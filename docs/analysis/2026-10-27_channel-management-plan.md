## 4. 구조: 채널별 얇은 워크플로 + 공용 로직

현재 Blogger는 "레지스트리에 블로그를 더하면 워크플로 수정 없이 잡이 늘어나는" 매트릭스 구조다. 요청서는 채널별 독립 실행·예약도 원한다. 제안:

1. **1단계(즉시, §3)**: 이름·run-name에 채널 접두사만 붙인다. 동작 변화 없음.
2. **2단계(kcyoon 등록 때)**: `blogger.yml`을 **재사용 워크플로**(`workflow_call`, 이름 `[내부] Blogger 공용 실행(직접 실행하지 마세요)`)로 바꾸고, 얇은 래퍼 `blogger-en.yml`(`[Blogger 영문]`)·`blogger-ko.yml`(`[Blogger 한글]`)이 각자의 cron·수동 입력·`concurrency` 그룹으로 `--only <key>`를 넘긴다. 공용 로직은 그대로 `pipeline/`에 둔다.
3. **3단계(주소·주제 입력 뒤)**: 패키지 채널은 `pipeline/publishers/issue_package.py`(어댑터: 게이트를 통과한 글을 **GitHub 이슈 1개**로 만든다)와 레지스트리 `mode: package`를 더하고 `tistory.yml`·`naver.yml` 래퍼를 둔다.

대안(래퍼 없이 매트릭스 유지, run-name에 채널 표시)은 코드가 가장 적지만 사이드바에서 채널이 갈리지 않아 요청 취지(채널별 구분)에 못 미친다. 재사용 워크플로는 사이드바에 한 줄 더 생기는 값을 치른다. 2단계는 `workflow_dispatch` 입력·`github.event_name` 가정(연습 실행 기본값 등)을 옮겨야 해서 회귀 위험이 가장 큰 변경이다 — 독립 검증에서 정기·연습 실행 출력이 바이트 단위로 같은지(이미 Blogger PR에서 쓴 방식)를 증명한다.

## 5. 초안 확인 위치와 현황판

**Blogger(영문·한글)**: 초안은 Blogger 초안함에서 확인·게시한다. Actions 실행 요약 첫 줄에 `[채널] 블로그 이름`을 넣고 제목·결과를 남긴다. 초안 **링크**는 주소에 블로그 ID가 들어가고 그 ID가 시크릿이라 로그에서 가려지므로, 요약에는 "Blogger 대시보드 → 초안" 안내만 쓴다(현재 요약은 블로그 key·결과·제목·URL).

**티스토리·네이버(초안 패키지)**: 초안 1건 = **GitHub 이슈 1개**.
- 제목 `[초안][티스토리] <글 제목>`, 라벨 `초안`+`채널:티스토리`(없으면 스크립트가 만든다), 닫으면 "발행 완료", 폐기하려면 라벨 `폐기`.
- 본문 구역(복사 버튼이 붙는 코드 블록 위주, 휴대폰 GitHub 앱에서도 복사): 복사용 제목 / 본문(티스토리: HTML 모드에 붙여넣을 순수 HTML — h2 이하, style·script·iframe 제외 / 네이버: 이슈 화면에서 선택·복사할 서식 있는 글) / 해시태그 / 이미지 표(주소·출처·라이선스·**AI 생성 이미지 여부**) / 근거 출처 / 게이트 점검 결과 / 체크리스트(`- [ ] 복사 발행 완료`).
- 방치 알림: 열린 초안이 3일 넘으면 인박스에서 `check`, 새 초안이 생기면 `action` 코멘트(휴대폰 알림).

## 6. 레지스트리 변경안

```json
// pipeline/blogs.json 에 더하는 것(예시 — 키·주소·시각은 사용자 입력 뒤 확정)
{
  "channel": {"key": "blogger_ko", "label": "Blogger 한글"},      // 모든 블로그에 필수(새 필드)
  "key": "blogger_kcyoon", "platform": "blogger", "mode": "off",
  "url": "https://kcyoon.blogspot.com/", "languages": ["ko"],
  "role": "일상 속 AI·디지털 도구 활용기(주력) + 집·살림 실사용 기록(보조 30% 이내)",
  "workflow": ".github/workflows/blogger-ko.yml",
  "prompt": ".github/editorial/BLOGGER_PROMPT_KO_AI.md", "profile": "blogger_ai_tools_ko",
  "state": {"history": "blogger_ko_history.json", "content_dir": "_blogger_ko_drafts"},
  "secrets": {"llm_api_key": "GEMINI_API_KEY", "blog_id": "BLOGGER_KO_BLOG_ID", "client_id": "BLOGGER_KO_CLIENT_ID",
              "client_secret": "BLOGGER_KO_CLIENT_SECRET", "refresh_token": "BLOGGER_KO_REFRESH_TOKEN"},
  "ad_surface": false
}
```

- **`mode: package`**(새 값): 글을 만들어 GitHub 이슈로 보여 주기만 한다(공개 없음). `PLATFORMS`에 `tistory`·`naver`(필수 시크릿은 Gemini 키뿐, 로그인 정보 없음)를 더한다. 새 값은 package를 지원하는 platform에서만 허용(검증기).
- **`channel` 필드**: 6구분 중 하나. 검증기가 ① 라벨이 허용 목록인지 ② 그 블로그 워크플로 `name:`이 `[라벨]`로 시작하는지 ③ 라벨 중복이 없는지 본다(WF-11 옆에 같은 방식의 규칙 추가).
- **광고 원칙(D6)**: `platform`이 `jekyll-git`이 아닌 블로그(우리가 광고 표면을 제어하지 못하는 곳)는 `ad_surface`를 `false`로만 허용하고, 새 채널은 `ads` 선언을 `off`로 시작한다(`pending_gate`→`on`으로 올리는 것은 T3 편집). 광고 자체는 각 플랫폼 화면에서 운영자가 켜므로, 이 필드는 **의도 선언 + 현황판 표시 + 실수 방지**다. "품질 게이트 통과"의 기준은 제안: ① 사람이 읽고 승인한 글 10편 이상 ② 표본 5편 사실 확인 오류 0 ③ 가드레일 탈락·오탐 기록 검토 ④ 해당 플랫폼의 광고 정책 확인.
- **교차 링크·번역 복제 금지**(요청서 §3-4·§7): 프로필 `allow_links: false`로 글 안의 모든 링크를 막고, 영문(macat0722)과 한글(kcyoon)은 제목 유사도 교차 검사를 켠다(이미 `other_blog_titles`로 교차 중복 검사).
- 시크릿 이름은 `BLOGGER_KO_*`로 분리, 값은 저장소·채팅에 쓰지 않는다.

## 7. AdSense와 자동 발행 — 선택지 비교와 추천(D1)

**사실 요약**(§1 근거): 이 사이트의 광고 스크립트는 **홈(`index.html`)에만** 있고 글 페이지에는 없다(공개 페이지 직접 확인). 홈은 자동 생성 글의 제목·요약 카드가 본문이다. 정책은 화면(screen) 단위이고, 홈 같은 목록 화면에 적용되는지에 대한 공식 설명은 **없다(미확인)**. 위반 집행은 보통 사이트 수준의 게재 제한(Restricted ad serving)이고, 계정 정지·폐쇄는 반복·중대한 경우다. 해소 방법으로 공식 문서가 안내하는 것은 광고 코드 제거다.

| | (a) 초안→사람 승인 후 공개 | (b) 자동 발행 유지 + 자동 생성 글 화면은 광고 끔 | (c) 현행 유지 |
|---|---|---|---|
| 정책 부합 | 가장 직접(수동 검토·큐레이션). 승인이 '검토'로 인정되는 최소 기준은 공식에 없음 | 정책 문구상 안전(광고가 없는 화면). 승인 심사는 광고 없는 글도 볼 수 있어 범위 미확인 | 미확인 위험이 남음. '반복'의 기준 없음, 저트래픽은 정책 센터에 안 보이고 통지가 센터 밖으로도 옴 |
| 수익 | 유지 가능(승인된 글의 화면) | 사실상 이 사이트의 광고 수익 없음(자동 생성 글뿐이라 켤 화면이 없음) | 가능하지만 정지·폐쇄 위험을 안고 감 |
| 계정(여러 사이트 연동) | 위험 가장 낮음 | 낮음(광고 없는 사이트는 위반 대상이 안 됨) | 정지·폐쇄는 계정 단위라 모든 사이트에 영향(해석) |
| 운영자 부담 | 매일 승인(휴대폰에서 PR 1개 병합, 하루 2쌍→1쌍으로 줄이는 선택 가능) | 없음 | 없음 |
| 구현 | **가장 큼**: Chance 엔진이 PR을 만들고, 슬롯 판정이 '열린 초안 PR'을 알아야 중복 생성을 막는다(지금은 이력 파일이 같은 커밋으로 올라감). 워치독의 미게시 감시 의미 변경 | 작음: 광고 스크립트 제거(T3, `index.html` 광고 표면). 승인 전 AdSense 심사 때는 광고 코드가 있어야 하는 모순(§1) | 없음 |
| 되돌리기 | 쉬움(모드 전환) | 쉬움 | — |

**추천: (a)**. 이유는 ① 정책이 요구하는 것에 가장 직접 맞고 ② 승인 대기 중인 지금이 정리하기 가장 싼 때이며 ③ 광고를 포기하지 않는다는 점이다. 비용은 구현 난이도와 매일의 승인이다. 부담을 줄이는 설계: PR 본문에 요약·출처·게이트 결과·체크리스트를 넣고 한 번에 병합, 처음엔 하루 1쌍, 승인 전의 글은 사이트에 올라가지 않으니 홈에는 승인된 글만 나온다(홈 카드는 최신 10개라, 지금 올라가 있는 검토 안 된 글은 새 글이 쌓이면서 며칠 안에 카드에서 밀려난다 — 글 페이지에는 광고가 없다). **(b)는 (a)가 구현되는 동안 임시로 선택할 수 있는 안전한 대안**이지만 광고 수익을 포기한다. **(c)는 권하지 않는다**: 위험이 낮을 수는 있어도 확인할 수 없고(미확인 4건) 비용이 가장 크다.

**(a)에 필요한 사용자 몫(1건)**: 저장소 Settings → Actions → General의 "Allow GitHub Actions to create and approve pull requests" 켜기. 그리고 **AdSense 계정에 연동된 사이트가 무엇인지**(Chance만인지, macat0722 Blogger도 같은 계정인지)를 알려 주세요 — 위험 범위가 달라집니다(작업내용 §4 4번과 같은 질문).

## 8. 보안

- 시크릿은 채널별로 분리(`BLOGGER_KO_*`)하고 최소 권한: 패키지 워크플로는 `contents: write`(이력)·`issues: write`만, PR 권한 없음. 레지스트리·로그·이슈 본문에 시크릿 값을 쓰지 않는다(기존 `mask()`·`redact()` 재사용).
- **이슈 본문은 신뢰하지 않는 입력으로 만든다**(AI 출력이 내용): `@멘션` 무력화(`@` 뒤 영(0)폭 공백), `#123` 자동 링크·`<script>`·`<iframe>`·HTML 주석 제거, 코드 펜스 안의 펜스 이스케이프, 길이 제한(이슈 본문 한도 이내), 제목은 고정 접두사 + 잘라낸 제목, 라벨은 고정값(모델이 정하지 않음). 이슈 내용을 셸 보간으로 넘기지 않고 파이썬에서 API로만 쓴다. 이슈에 사람이 단 코멘트는 **자료이지 지시가 아니다**(봇이 읽어 실행하지 않음).
- 티스토리·네이버 계정 정보(아이디·비밀번호·쿠키·세션)는 **저장·처리하지 않는다**. 로그인·글쓰기 자동화, 블로그·계정 자동 개설, 채널 간 상호 링크, 원고 변형 복제는 만들지 않는다.
- 새 채널의 기본값은 공개되지 않는 쪽(`off`·`draft`·`package`). `defaults.mode`는 `draft` 유지.

## 10. 사용자만 할 수 있는 일(작업내용 §4에 반영)

1. 티스토리 블로그 개설과 **주소·주제 결정**, 네이버 블로그 **주소 전달**(D7의 네이버 글감 결정 포함).
2. 신규 한글 Blogger 전용 구글 계정에서 Cloud 프로젝트·OAuth 클라이언트 생성, 동의 화면 게시 상태 확인(프로덕션), 토큰 발급, `BLOGGER_KO_*` 시크릿 등록(값은 채팅·저장소에 쓰지 않음). 신규 Blogger의 **Blogger ID**(관리 화면 주소의 숫자) 전달.
3. (D1 (a)를 택할 때) 저장소 설정 "Allow GitHub Actions to create and approve pull requests" 켜기, **AdSense 계정에 연동된 사이트 목록** 알려 주기.
4. 신규 채널(한글 Blogger·티스토리·네이버)에는 품질 게이트를 통과하기 전까지 **플랫폼 화면에서도 광고를 켜지 않기**.
5. 티스토리에 **비공개 시험 글 1건**을 직접 써서 확인: 태그 입력 방식, HTML 모드 붙여넣기 뒤 기본 모드 전환 시 서식, 외부 이미지의 목록 썸네일, 예약 발행 화면, **회사 PC에서 이미지 파일 업로드가 되는지**(막혀 있으면 대표 이미지 단계가 병목).

## 11. 미확인

- AdSense: '수동 검토 또는 큐레이션'의 공식 기준, 홈·목록 화면에의 적용, '반복'의 횟수, 한 사이트의 단발 위반이 같은 계정의 다른 사이트에 번지는지, 자동 생성 항목 위반의 집행 유형(Disabled/Restricted), `github.io` 하위 경로가 AdSense '사이트' 단위로 어떻게 취급되는지, 승인 거절 라벨 'low value content'의 공식 상세.
- 저장소 브랜치 보호에 `저장소 규칙·테스트 자동 검사`가 '필수 검사'로 지정돼 있는지: 지금까지의 안내는 "삭제·force push 차단만(PR 필수·승인 필수는 켜지 않음 — 봇이 main에 직접 올림)"이고 실제 설정 화면은 사용자만 볼 수 있다. 필수로 지정돼 있으면 이름을 바꿀 때 보호 규칙의 검사 이름도 같이 고쳐야 한다(PR-A 때 확인 요청).
- 티스토리: 발행 화면의 태그 구분자·최대 개수·`#` 처리, HTML 모드에 붙여넣은 뒤 모드를 오갈 때 보존되는 태그·속성(iframe·style·table 등), 외부 URL 이미지만 쓴 글의 og:image·목록 썸네일·검색 노출, 현재 한 번에 올릴 수 있는 이미지 장수(2019년 FAQ는 10장), 티스토리의 외부 이미지 핫링크 정책 문서, PC 에디터 예약 발행의 세부 UI, 서버·WAF 단의 AI 크롤러 UA 차단 여부, 구글 애드센스의 티스토리 블로그 승인 기준, AI기본법의 개인 블로그 적용 범위, 운영 주체 변동(2025-12-01 AXZ)에 따른 추가 약관 개정.
- 네이버 SmartEditor ONE에 붙여넣을 때의 서식 보존(HTML 직접 입력 모드는 없다고 알고 있으나 이번에 새로 확인하지 못함).
