## 한 줄 결론

**약관을 지키면서 프로그램이 티스토리·네이버 블로그에 "임시저장"을 넣어 주는 공식 방법은 지금 없다.**

비공식 방법(브라우저 자동화, 로그인 쿠키로 비공개 내부 기능 호출)은 기술적으로 존재하고, 티스토리에는 임시저장까지 해 주는 도구도 있다. 그러나

1. 프로젝트 규칙(비밀번호·쿠키 저장 금지, 로그인·세션 자동화 금지)에 어긋나고,
2. 네이버는 약관에 자동화 수단 금지 문구가 있다는 보도가 있으며,
3. 티스토리는 약관이 불명확해서 "불명확하면 하지 않는다"는 규칙에 걸린다.

**권고: 자동 업로드는 하지 않는다. 대신 "사람이 붙여넣고 발행하는 마지막 한 걸음"을 더 쉽게 만드는 쪽(복사 편의 개선)으로 간다.**

임시저장만 한다고 약관 위험이 줄지는 않는다. 약관이 문제 삼는 것은 "어떤 방식으로 접근했는가"이지 "공개했는가, 임시저장했는가"가 아니다(해석). 줄어드는 것은 "검수 없이 공개되는 글"의 위험뿐이다.

## 0. 먼저 알아둘 한계

1. **네이버 계열 사이트는 이 조사 도구로 열리지 않았다.** policy·help·developers·www.naver.com은 도구가 "가져올 수 없음"을 돌려줬고, 검색 도구는 naver.com 도메인을 "접근 불가"로 처리했다. navercorp.com은 403 오류였다. 접근을 막아 둔 사이트를 우회하지 않는다는 프로젝트 원칙(약관·robots.txt 준수)에 따라 우회하지 않았다. 그래서 **네이버 약관의 조항 번호와 현행 문구는 직접 확인하지 못했고**, 언론·개인 자료로 대신했다.
2. 조사 도구가 페이지를 요약해서 돌려주므로 **조항 번호가 한두 칸 어긋났을 수 있다.** 문서에 번호를 옮겨 쓰기 전에 원문과 대조하길 권한다.
3. 약관이 최근 개정됐다(다음 이용약관 시행 2026-09-22, 카카오 약관 시행 2026-09-30). 분기마다 다시 확인해야 한다.
4. 로그인하지 않았으므로 **에디터의 실제 동작**(붙여넣기 결과, 임시저장 버튼, 하루 발행 한도)은 시험하지 못했다.
5. 자동화 때문에 제재받았다는 **확인된 사례(공식 발표·통계)는 못 찾았다.** "걸린다"도 "안 걸린다"도 근거가 없다.

## 1. 티스토리

### 1-1. 공식 경로: 프로그램으로 글·임시저장을 넣는 길은 없다

- **공식 공지** "[안내] 티스토리 Open API가 종료됩니다."(2023-12-22 게시) ◎ [T1]
  - 2023년 말부터 단계적으로 닫는다. 순서는 파일 첨부 → 글 관련 → 댓글 관련 → 기타이고, 끝은 2024년 2월 말이다.
  - API로 하던 글 작성·수정, 이미지·파일 첨부, 댓글 작성·수정은 이후 에디터와 사이트에서 직접 하라고 안내한다. 종료 이유는 공지에 없다.
- **개발자 문서**도 같은 내용이다. 첫 화면 배너에 "2024년 2월까지 순차 종료"(https://tistory.github.io/document-tistory-apis/) ◎ [T2], 글쓰기 문서에는 "아래 API는 종료되었습니다"(https://tistory.github.io/document-tistory-apis/apis/v1/post/write.html) ◎ [T3]라고 표시돼 있다.
- **옛 API에도 진짜 '임시저장'은 없었다.** 글쓰기 문서의 공개 설정은 0=비공개(기본), 1=보호, 3=발행이었다 [T3]. 즉 예전에도 "프로그램 → 비공개로 저장"이 가장 가까운 방식이었다.
- **재개·신규 공식 경로 근거 없음.** 티스토리 공지 목록(2026년 공지들) ◎ [T9]과 검색에서 글쓰기 API 재개 소식은 없었다. 카카오 MCP 플랫폼 PlayMCP(2025-08 베타)의 공식 소개 자료에도 티스토리 글쓰기 도구는 없다. 다만 그 뒤 추가된 서버까지는 확인하지 못했다 ◎ [K5].
- **같은 계열의 선례**: 카카오스토리 API도 2023-11-15에 종료됐다 ◎ [K4]. 글쓰기 API를 닫는 흐름이므로 재개 가능성은 낮다고 본다(추론).
- 이메일로 글 올리기, 외부 에디터 연동: 공식 근거를 못 찾았다 ✕.
- **날짜가 엇갈리는 자료**
  - 공식: 2024-02 말 종료 ◎ [T1].
  - 판매 페이지는 2024-11-26에 티스토리 API가 중단됐다고 적는다 △ [C8]. 판매자 자신의 프로그램이 막힌 날일 가능성이 크다(추론). 공식 날짜로 쓰지 않는다.
  - 인프런 답변(2025-02)은 종료됐다는 점만 확인하고 날짜는 없다 △ [C7].
  - 오래된 튜토리얼은 아직 write 주소 사용법을 소개하지만 현재는 종료 상태다. 검색에 걸려도 믿지 않는다.

**해석**

- 티스토리 운영 주체는 주식회사 다음이고 [T4], 티스토리 홈페이지 하단의 이용약관 링크는 다음 이용약관을 가리킨다 ◎ [T11]. 로그인은 카카오계정으로 하는 것으로 알려져 있다(자료마다 표현이 달라 △ [C1][C6]).
- **"자동화된 글쓰기를 금지한다"고 콕 집은 조항은 못 찾았다.** 그러나 "허용한다"는 뜻도 아니다. 포괄 조항(운영정책 2.⑳, 다음 이용약관 12①22호)이 있고, 회사가 약관을 바꿀 수 있다. 프로젝트 규칙("불명확하면 하지 않는다")에 따르면 **하지 않는 쪽**이다.
- 질문별로 가장 가까운 조항
  - 스크래핑(내용 수집): 운영정책 2.②, 다음 이용약관 12①2호(허락 없는 서비스 정보 복제·상업 이용). "크롤링"이라는 단어는 없다.
  - 비공식 API·우회 접근: 직접 언급 없음. 가장 가까운 것은 역공학 금지(운영정책 2.⑭, 다음 이용약관 12①11호, 카카오계정 약관 12①8호)와 포괄 조항이다.
  - 자동 게시·매크로·봇: 직접 언급 없음. 가장 가까운 것은 동일 내용 반복 게시 금지(다음 운영정책 3-2 (19))와 허용하지 않은 악의적 방법으로 이용해 정상 운영을 방해하는 행위의 금지(3-2 (24))이다.
  - AI 생성 콘텐츠: 이용자 글에 대한 조항 없음(아래 AI 항목 참고).
- 언론은 티스토리·구글 블로거가 약관에 크롤링 금지를 명시하지 않았다고 비교 보도했다 ○ [M3]. 이는 글 수집(크롤링)에 관한 말이고, 글쓰기 자동화에 대해서는 아무것도 말해 주지 않는다.
- **robots.txt**(검색 로봇에게 "여기는 들어오지 마세요"라고 적어 둔 안내문): 내 블로그의 robots.txt는 모든 로봇에게 `/manage`, `/owner`, `/admin`, `/guestbook`, `/search`를 막아 둔다 ◎ [T7]. 글쓰기 화면은 `/manage` 아래에 있다(자동화 예제가 `/manage/post/write`를 쓰고 △ [C1], 다른 자료는 `/manage/newpost`를 쓴다는 검색 요약이 있다). robots.txt는 원래 로봇용 약속이라 사람이 브라우저로 글을 쓰는 것과는 무관하다. 그러나 **프로그램이 같은 주소에 들어가면** 프로젝트의 "robots.txt 준수" 원칙과 부딪친다.
- **AI 생성 콘텐츠**: 약관·운영정책에 금지·표기 조항은 없다 ◎ [T4][T5][T6]. 다만 2026-10-12 공지는 크리에이터 선정에서 "AI가 쓴 글을 거의 그대로 발행해"(https://notice.tistory.com/2705)를 아쉬운 점으로 꼽았다 ◎ [T8]. 금지가 아니라 평가 요소이며, 사람이 검수·가필하는 지금 흐름과 방향이 맞는다.

- **임시저장이 기술적으로 가능하다는 것과 약관상 허용된다는 것은 별개다.**

| A4 | **고객센터에 서면 문의**: "본인 계정에서 본인이 직접 실행하는 입력 보조(클릭 1회로 에디터에 본문 채움, 발행은 본인이 누름)가 약관상 허용되는가" | 문의 자체는 위험 없음 | 문안 초안 | **발송은 운영자 본인**(승인 필요) | 서면 답변이 있어야 B1을 검토할 수 있다. 약관만으로는 "자동화"의 범위가 정해지지 않는다 |

### B. 보류(문의 결과가 "허용"일 때만 검토)

| # | 대안 | 규정 위험 | AI 작업 | 운영자 작업 | 근거·주의 |
|---|---|---|---|---|---|
| B1 | **북마클릿·유저스크립트**: 운영자가 로그인한 자기 에디터에서 클릭하면 준비된 본문이 채워짐 | 티스토리 **중간**(불명확) / 네이버 **중간~높음**(자동화 수단 금지 문구, 매크로로 해석될 여지) | 중 | 중. 확장 프로그램 설치가 필요하고 **회사 PC는 보안정책으로 막혔을 수 있음**(확인 필요) | "내가 직접 실행"이라는 점이 약관상 면책 사유로 적혀 있지 않다. 사람이 1건씩 클릭하므로 어뷰징으로 보일 가능성은 낮지만 규정 판단은 별개다. 로그인해야만 시험할 수 있어 **AI가 사전 검증 불가**. 에디터가 스크립트를 막거나 구조가 바뀌면 깨진다. 티스토리용 공개 유저스크립트(Greasy Fork 'Tistory HTML Cleaner')가 있으나 에디터를 HTML 모드로 바꿔 내용을 정리하는 도구일 뿐이고, 존재가 허용을 뜻하지 않는다 △ [C19] |

### C. 하지 않는 것

- 로그인 자동화, 로그인 쿠키·세션 사용, 내부 API 호출(브라우저 에이전트·RPA 포함)
- 제3자 확장 프로그램, 상용 자동 발행 프로그램
- 죽은 API 되살리기(티스토리 Open API 토큰, 네이버 XML-RPC 연결 암호)

### D. 해당 없음·근거 없음

| 항목 | 상태 |
|---|---|
| 이메일로 글 올리기 | 티스토리·네이버 모두 근거 없음 ✕ |
| 모바일 앱 공유 메뉴로 보내기 | 근거 없음 ✕. 티스토리 iOS 앱 설명에는 사진·영상 첨부 글쓰기만 있고 공유 수신·임시저장 언급 없음 ◎ [T10] |
| 에디터 가져오기(Import) | 티스토리는 백업 내보내기 위주(△ [C20]), 네이버는 공식 가져오기·내보내기 근거 없음. 다른 곳→티스토리/네이버로 들여오는 기능은 못 찾음 |
| 외부 에디터 연동(워드 등) | 네이버는 2020 종료 [M1], 티스토리는 Open API 종료로 불가 |

### E. 전략 선택지(운영자 결정)

- **공식 API가 임시저장을 지원하는 채널을 병행**: Blogger는 글 생성 시 `isDraft` 옵션이 있고 ◎ [G1], 워드프레스 REST API는 `status=draft`를 받는다 ◎ [G2]. 지금의 블로거(Blogger) 흐름과 같은 방식이다. 다만 독자·수익 구조가 달라지므로 운영자 판단이 필요하다.
- 참고: 자동 대량 발행 자체는 구글 검색 스팸 정책의 "scaled content abuse"와도 닿는다 ◎ [G3]. 사람 검수 단계를 유지하는 현재 설계가 맞는 방향이다.

## 4. 추천과 승인이 필요한 결정

### 4-1. 추천(진행 순서)

1. **지금 구조를 유지한다.** AI가 초안 패키지를 만들고, 운영자가 붙여넣고 발행한다. 두 블로그의 약관 위험이 가장 낮은 방식이다.
2. **A1(티스토리)·A3(점검표)**: 바로 적용할 수 있다.
3. **A2 0단계(네이버)**: 운영자가 1건만 붙여넣어 보고 깨진 서식을 알려 주면, 그 결과로 네이버용 템플릿을 고정한다. 이후 필요하면 1단계(복사 버튼 페이지)를 검토한다.
4. **A4**: 운영자가 원하면 문의 문안을 AI가 쓰고, 발송은 운영자가 한다. 답이 올 때까지 B1은 하지 않는다.
5. **E 전략**은 운영자가 원할 때만 검토한다.

### 4-2. 절대 하지 말 것

- 두 블로그에 대한 로그인·세션·쿠키·내부 API 자동화(임시저장 전용이라도)
- 블로그 계정의 비밀번호·쿠키·토큰을 저장소·GitHub Secrets·PC 파일 어디에든 보관
- CAPTCHA·2단계 인증을 우회하려는 시도, 다중 계정, IP 바꾸기
- 제3자 자동 발행 도구·확장 프로그램 설치
- 같은 글을 짧은 간격으로 여러 건 일괄 발행(어뷰징·저품질 위험, 티스토리가 꼽은 약점과도 겹침)
- 네이버 쪽 원문을 우회 경로(보관 사이트 등)로 읽어 오기: 접근 차단을 우회하지 않는다는 원칙에 어긋난다

## 5. 확인 못 한 것과 자료 충돌

**확인 못 한 것 (✕)**

1. 네이버 이용약관·블로그 운영원칙의 조항 이름·번호·현행 문구(도구 차단, 우회하지 않음).
2. 네이버 블로그의 robots.txt 내용.
3. 네이버 글쓰기 API 종료 공지 원문(블로그피플), 개발자센터 공지 원문. 2018년 약관 개정 문구가 지금도 있는지와 시행일.
4. 티스토리 운영정책의 시행일, 임시저장에 대한 공식 도움말, 하루 발행 한도(2018년 15·30개, 2025년 5개 같은 주장이 있으나 모두 비공식), 임시저장이 한도에 포함되는지.
5. 두 블로그의 이메일 글쓰기, 모바일 공유 수신 기능.
6. 두 에디터의 붙여넣기 결과, 외부 이미지 처리(로그인이 필요해 시험하지 못함).
7. 자동화로 인한 실제 제재 사례·통계. 임시저장 전용 자동화가 제재 대상인지.
8. 'mcp-tistory' npm 패키지의 실제 기능(페이지 열람 실패, 검색 요약만 봄).
9. "운영자가 직접 실행하는 입력 보조 스크립트"가 약관상 자동화인지: 플랫폼만 답할 수 있다.
10. AI 기본법(2026-01-22 시행)이 개인 블로거에 직접 적용되는지: 투명성 의무(제31조)는 AI 사업자 중심으로 서술돼 개인 이용자는 불명확하다 ○ [M8]. **법률 자문이 아니다.**
11. PlayMCP에 그 뒤 추가된 서버 중 티스토리 글쓰기 도구가 있는지.

**자료가 엇갈리거나 오래된 곳**

- 티스토리 API 종료일: 공식은 2024-02 말 [T1], 판매 페이지는 2024-11-26 [C8]. 공식을 따른다.
- 검색 엔진 요약 중에는 티스토리 글쓰기 API가 아직 문서에 있다는 취지의 것이 있었다. 모두 종료 전 튜토리얼이고, 공식 문서는 종료로 표시한다 [T3].
- 네이버 XML-RPC 패키지 페이지의 최신 갱신일(2026-10-20)은 자동 갱신일이다. 서비스가 살아 있다는 뜻이 아니다 [C4].
- 네이버 블로그 AI 표기: 기사마다 표시 필요인지 권장인지 표현이 다르다 [M4][M5].
- 연합뉴스 2018 기사: 전재 페이지 한글이 깨져 시행일이 4월 5일/5월 1일로 갈린다 [M2].
- 다음·카카오 약관은 2026-08~09에 개정됐다. 2025년 이전 설명 글은 지금 문구와 다를 수 있다.
