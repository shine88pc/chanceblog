# 저장소 감시·알림에 무료 AI 를 쓸 수 있나 — 조사와 권고 (2026-10-30)

> 운영자 요청(2026-10-30, 채팅): "저장소 감시에 대한 무료 AI 활용 방안 검토(현재 작업하는 방식, 메시지 발송, 알림 등)". 조사 에이전트 한 명이 2026-10-30 에 공식 문서·가격 페이지·공개 REST 를 읽은 보고를 이 저장소의 사정에 맞춰 줄인 것이다. **표의 세부 수치는 요약 도구를 거쳐 읽은 것이라 인용·시행 전에 원문과 대조한다.** 표기: ◎ 공식 원문을 직접 읽음 / ○ 언론·해설 / △ 개인 글·계산 / ✕ 미확인. T3 = 새 시크릿·계정이 필요해 운영자 승인이 드는 것.
>
> **개정 2026-10-30(오후):** 운영자의 방향 정리에 따라 이 조사는 '후보 비교와 근거'로만 남긴다. 초기 범위는 선택 보조 AI(기본 꺼짐) 네 가지 — 감시 결과 한 줄 요약·긴 오류 로그의 간단한 설명·사용자가 확인할 조치 추천·주간 운영 결과 요약 — 이고, AI Router·여러 공급자 자동 전환·GitHub Models 는 후보와 설계에서 제외한다. 아래 표의 Groq·OpenRouter·Cloudflare 는 필요성이 확인된 뒤에 다시 볼 참고 자료다. 기존 AI 없는 Actions 감시·알림은 그대로 둔다.

## 한 줄 결론

1. **무료 AI 는 코드를 읽고 고치는 '세션형 일'(지금 Claude 세션이 하는 요청 이해·계획·수정·독립 검증·병합 부탁)을 대신할 수 없다.** 한도·품질·도구 사용 어느 쪽으로도 안 되고, 무료 에이전트 도구 대부분이 2026년 상반기에 무료 경로를 닫거나 줄였다.
2. **감시·판정·알림은 이미 AI 없이 GitHub Actions 위에서 돈다**(발행 중단 감시·확인 필요 모음·요청 알림·접수 코멘트). 비용 0, PC 가 꺼져 있어도 돈다. 이 부분은 AI 로 바꿀 이유가 없다.
3. 무료 AI 가 보탤 수 있는 것은 **짧은 입력 → 검증된 짧은 출력**(알림 한두 문장 요약, 미분류 실패의 3줄 요약)뿐이다. 필요가 입증될 때만 넣는다(1단계는 승인 없이 측정, 2단계는 T3).
4. **GitHub Models 는 2026-07-30 에 완전히 종료**됐다 ◎. 이 저장소에서 `GITHUB_TOKEN` 만으로 쓰던 '새 시크릿 없는 무료 AI' 길은 없다.

## 권장 구조 — 필요가 입증되면 이렇게

- **하는 일**: 기존 확인 필요 모음(2시간마다)에 '(AI 요약·미검증)' 한 줄을 더하는 것뿐. 입력은 소유자가 쓴 이슈와 미분류 실패만, 출력은 항목당 {분류(고정 목록), 120자 이내 요약, 세션 필요 여부}. **AI 출력으로 단독 푸시·라벨 변경·push·요청 파일 생성을 일으키지 않는다.**
- **워크플로 모양**(`ops-inbox.yml` 에 잡 둘 추가, 새 트리거 없음): `collect`(결정적, 예약·수동에서만 — 외부인이 이슈로 AI 한도를 소진시키지 못하게) → `summarize`(AI 호출, **쓰기 토큰·텔레그램 시크릿 없음**, `continue-on-error`, 5분 제한) → 기존 `ops-inbox`(AI 결과가 스키마·길이·URL 검사를 통과하면 한 줄 첨부, 아니면 지금과 똑같이 동작).
- **입력 소독·주입 방어**: 소유자(OWNER) 이슈만 보내고 제3자는 건수만. 기존 소독 함수(비밀값 마스킹·제어문자·`@`·링크 무력화) 재사용 + 길이 상한. 이슈 제목·본문은 YAML 에서 셸에 끼우지 않고 환경변수로만 전달. 지시와 데이터를 분리하고 AI 에는 도구·웹·쓰기 권한을 주지 않는다. 출력은 스키마·고정 목록·길이·URL 금지 검사를 통과해야 하고, 어긋나면 폐기하고 템플릿을 쓴다.
- **한도 분리·실패 시**: 벤더를 나눠 블로그 생성(Gemini)과 섞지 않는다. 실행당 1회 배치, 하루 24회 하드캡, 429·5xx 가 3연속이면 6시간 AI 를 건너뛴다. 결제수단이 없으므로 초과는 과금이 아니라 오류로 끝난다. AI 잡이 실패해도 기존 알림은 그대로 나간다. 공급자는 2단(Cloudflare → 별도 프로젝트 Gemini)을 넘기지 않는다.
- **알림 폭주 방지**: AI 요약은 별도 푸시 없이 기존 묶음에만 포함, 기존 본문 해시 마커로 변경이 없으면 AI 호출·알림을 생략, 기존 건수 상한 유지.
- **단계**: 1단계(승인 불필요) 알림 템플릿·규칙 분류 보강과 '미분류 실패 건수' 측정. 2단계(선택, T3) 건수가 많을 때만 키 발급·연결.

## 승인(T3)

- 필요: 새 시크릿 등록(Cloudflare 2개, 또는 별도 프로젝트 Gemini 키 1개), 계정 생성·약관 동의·키 발급(운영자가 직접), Copilot Free·Antigravity 로그인과 학습 옵트아웃 설정, 외부 서비스로 텍스트가 나가는 워크플로 병합.
- 승인 없이 가능: 결정적 템플릿·규칙 분류·중복 제거, 검증 모듈과 시험, 키가 없으면 건너뛰는 AI 호출 코드(기존 STUB 방식), 호출 카운터. 기존 Gemini 키 재사용은 새 시크릿이 아니라 승인은 필요 없지만 한도가 섞여 권장하지 않는다.
- 회사 PC 에 새 도구를 설치·로그인하는 일은 사내 보안 정책 확인이 먼저다(✕).

## 확인하지 못한 것·점검 시점

- Gemini 무료 분당·일일·토큰 한도 수치(운영자가 현재 키의 한도 화면을 확인해야 함), Groq 무료 표의 귀속, Cloudflare 가입 시 카드 요구, Copilot Free 크레딧 수치·소진 시 동작, Antigravity 주간 한도 수치, 한국어 품질(공식 근거 없음 — 이슈 20건 샘플로 실측 권장), Ollama 사내 PC 사양·설치 정책.
- 자료 충돌: Gemini CLI 무료 API 키 가능 여부, 일부 매체의 'Gemini CLI 전 등급 종료' 대 구글의 'Standard/Enterprise 유지'.
- 다음 점검: 2026-11-30 한 번, 그 전에도 알림에 429·model-not-found 가 뜨면 즉시. 블로그 생성의 모델 목록(`pipeline/blogs.json` `defaults.llm.models`)은 현재 무료 목록과 일치하지만 약 2개월마다 바뀐다.
