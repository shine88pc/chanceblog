## 2. 현황 진단

### 2-1 스킵 로직의 위치와 기준 (Chance, `generator.py`)

슬롯 판단은 `slot_state`(KST 9·18시, 이력만 본다) → `generate_blog_posts` → `collect_candidates`(분야 추첨 순서대로 소스를 읽고 게이트를 거침) 순서입니다. "할 일 없음"의 결과 코드는 `ALREADY_PUBLISHED`(그 슬롯 글이 이미 있음)·`OUT_OF_WINDOW`(첫 슬롯 전)·`ALL_LANES_EMPTY`(모든 분야가 비어 빨강)·`SOURCES_UNREACHABLE`·`ALL_DUPLICATES`·`NO_CANDIDATES`·`ALL_REJECTED`·`NO_MATCH`이고, 후보가 탈락하는 관문은 코드로 구분해 센다(`NO_TITLE`·`EXCLUDED`·`OFF_TOPIC`·`NOT_TECH`·`AGE`·`UNTRUSTED`·`UNCHECKED`·`UNRESOLVED`·`HOST_MISMATCH`·`SHORT_SUMMARY`·`DUPLICATE`). 요청서가 말한 "스킵 사유 분포"는 이제 Actions 요약의 분야 표와 `[SKIP] code=… lane=…` 줄에서 읽을 수 있습니다.

### 2-2 사유 분포 (실측)

- 소스 개편 전(10-20~10-25, 슬롯 창 11개): 글이 나온 창 2개, 나머지 9개는 첫 분야가 비기술이라 후보 0 — 원인은 신뢰 목록 밖 게시자(구글 뉴스 링크가 원문으로 안 풀림, 통과율 0.42%)와 36시간 신선도 창이었다(`2026-10-25_publish-readiness.md` §3-1).
- 소스 개편 뒤(10-26): 9시 슬롯 정기 실행 #71 이 글 1쌍을 발행했고(분야는 기술), 15:18 실행 #73 은 `ALREADY_PUBLISHED` 로 정상 건너뜀. 해외 소스(집행위원회 5·통계청 3)와 GOV.UK 2개가 들어간 뒤 첫 슬롯은 10-26 18시인데, 그 슬롯의 분야 추첨 순서가 문화→과학→사회→일상→경제→기술이라 문화(Pew)에 후보가 있으면 거기서 멈춰 새 소스는 읽히지 않을 수 있다(`collect_candidates`가 후보가 나온 분야에서 멈춘다). 새 소스의 첫 실제 관측은 분야 순서에 따라 이후 슬롯이 된다.
- 월요일 낮 피드 사본으로 모의한 분야별 후보(72시간 창): 과학 7·경제 2·문화 1, 사회·기술·일상 0 — 주말 직후라 공공기관 발표가 적은 탓이고 모든 분야가 비지는 않는다. 평일 공급은 병합 뒤 관측해야 한다.

### 2-3 주제 선정 방식과 데이터 구조

- **Chance**: 백로그 파일 없이 "소스 피드 + 필터"가 후보 풀이다. 분야(6개)는 최근 발행 편중을 줄이는 확률 추첨 순서(`editorial_lane_order`)로 시도하고, 분야가 비면 다음 분야로 넘어간다. 후보는 신뢰 도메인·72시간·요약 100자·소스별 제외 규칙·제목 유사도 중복(0.6)을 통과해야 하고 슬롯당 최대 3개를 시도한다.
- **이력**: `history.json`(Chance, 글 쌍마다 `date`·`slot`·`lane`·`source`·`source_url`·제목·이미지)과 `blogger_history.json`. 한·영은 한 번의 생성에서 쌍으로 나온다(번역이 아니라 같은 근거의 두 언어 글). 지금 이력 11건 가운데 옛 문자열 5건을 빼고 `lane`이 적힌 4건은 모두 `technology` 분야다 — 앞으로 분야 분포는 이력의 `lane`으로 측정한다(홈 정규식 분류는 쓰지 않는다).
- **Blogger**: 시드 32개 + LLM 주제 확장, 쿨다운 60일, 금지 주제 필터 → 이제 제목·라벨·본문 가드레일(PR #40 병합, 후속 보강 진행 중).

## 3. 요청서 3-2·3-3 설계를 실제 구조에 맞춘 수정안

| 요청서 설계 | 실제 구조 | 수정안 |
|---|---|---|
| 주제 백로그(큐) 파일 `topics/backlog.json` | 큐 없음, 소스 피드가 큐 역할 | **만들지 않는다.** 피드는 이미 20~30건 창이고 72시간이면 비는 분야가 있을 뿐이다. 큐가 필요해지는 경우(기존 글 확장 후보, 주말 이월)만 Phase 1 후반에 작은 파일로 검토 |
| 후보 공급 ① 수동 지정 | 없음(수동 작성 없을 예정) | 보류 |
| ② 자동 발굴(블로그별 핵심 주제 범위 설정 파일) | `EDITORIAL_LANES`·`NEWS_SOURCES`·`TRUSTED_SOURCE_DOMAINS`가 사실상 설정 | 설정 파일로 분리하려면 레지스트리(`pipeline/blogs.json`)에 `topics` 항목을 두는 안이 자연스럽다(Phase 6B와 합침) |
| ③ 기존 글 확장 | 없음 | 허브-클러스터는 글이 20편을 넘은 뒤. 지금은 중복 방지(유사도)가 먼저 |
| 선정 조건(3-3) 7개 | 일부 구현 | 아래 표 |

선정 조건 ↔ 현 코드:

| 3-3 조건 | 현 코드 | 빈틈 |
|---|---|---|
| 핵심 주제 적합도 | 분야·소스·`topic_regex`(제목·분류 태그) | 사이트 소개문(광고 표면)은 아직 옛 서술 — **T3, 기본값 변경 없음** |
| 독자 질문 명확성 | 편집 템플릿이 요구, 코드 검사 없음 | 작성 단계에서 `skip` 규칙으로 처리 |
| 근거 확보(출처 3개 이상) | 원문 주소 1개 + 피드 요약만(본문을 가져오지 않는 약관 정책) | **3개 이상은 불가능한 구조** — 공공 자료 글은 "원 자료 1개 + 해설"이고, 추가 출처는 Phase 1 에서 같은 기관의 관련 문서 링크로 대체하는 안을 제안 |
| 부가가치 | 편집 템플릿("원문 요약을 넘는 설명·맥락") | 코드 검사 없음 |
| 중복도 | 이력·`_posts` 제목 유사도 0.6, 월별 반복 발표는 제목이 비슷해 막힘(통계청) | 월별 지표는 같은 제목이 매달 오므로 **지표명+기준월**을 키로 하는 완화 필요(Phase 1 후보) |
| 신선도·수요 | 72시간 창(감점이 아니라 컷) | 점수제로 바꾸는 것은 품질 기준 변경(T3) |
| 위험도(YMYL) | 소스별 `HEALTH_RULE`, Blogger 가드레일, 소스 제외어 | Chance 건강 글은 통계·정책 사실만(의학 조언 금지) |
