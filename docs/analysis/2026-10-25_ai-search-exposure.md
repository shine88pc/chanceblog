## 1) 한눈에 결론

- 사실: 블로그·지도는 AI 봇을, 검색·플레이스는 모든 봇을, 카페는 구글·빙까지 막는다(높음·IDX-2). 막혀도 링크·제목만 출처로 보일 수 있으나 본문이 쓰였다는 뜻은 아니다(OpenAI 문서; 높음·ENG-2).

- ④ 쓰기 API 2020 종료·무허가 자동 게재는 약관 금지 → 초안만 자동, 발행은 사람. 체험 없는 AI 대량 글은 노출 제한(높음·API-1, 2, POL-1). ①의 한국어 각색본/독립 체험 글 중 택일은 미결(계획서 11-2). 복제 금지, 원문 안내는 단방향 링크 1개만. 성공 기준은 네이버 안 지표+구글 색인.
- 주제는 블로그마다 주력 1개+클러스터로 분리(구글·네이버 모두 주제 집중을 봄; 중간·MON-16)하고 구체 주제는 다음 단계에서 제안한다.
- 지역 글: 장소 질의는 지도·장소 DB가 뼈대, 블로그는 보조일 가능성(추정; 중간·LOC-04). 파일럿은 열린 웹인 ③이 후보이며 사람이 현장 확인한 글만 쓴다. 최대 위험은 지어낸 장소·낡은 정보(LOC-05, 10).

## 2. 운영자 결정 항목(추천 기본값 포함)

### 결정 1. AI 앱 노출의 1차 목표 질의를 무엇으로 둘까?

1) 주변 맛집·마트 같은 지역 질의
2) 설명형 질의(정의·절차·조건·비교). 예시로 든 소비기한 표기는 계획서 5-1의 축소 범위 밖일 수 있어 주제 확정 뒤 교체
3) 설명형 중심 + 지역 소규모 파일럿

**추천**: 셋째를 권장. 장소 질의는 지도·장소 DB가 뼈대이고 한국 장소 데이터의 중심(네이버·카카오)이 AI 봇에 닫혀 있어 블로그가 인용될 여지가 작을 수 있다(추정, LOC-04, 06, 01). 설명형 질의는 질문과 맞는 제목·문단, 구체 수치·조건, 1차 출처가 일관된 요인이고(GEO-06) 10/18~10/20 글 11편은 이미 이 형태에 가깝지만 최근 4편은 퇴행했다(SIT-08, 재검증 전). 다만 서식만 손보는 것으로는 부족하다. 구글이 AI 노출의 핵심으로 꼽는 것은 직접 경험·고유 자료 같은 '비범용' 콘텐츠이므로(GEO-02, MON-06) 설명형 글도 글마다 '이 글만의 가치'를 1개 이상(실제 구축 기록·직접 확인한 수치·비교표·날짜별 변경점) 갖춘다. 계획서 8-4는 이것이 없으면 발행을 보류하도록 정했다. 이 프로젝트의 실제 구축 기록(계획서 A형 구축기)이 가장 확실한 고유 자산이다. 계획서 5-1은 GitHub 주력 주제를 좁히되 주제명을 확정 대기로 두었으므로, 지금의 일반 해설(소비기한·우주날씨 등)과 옵션의 예시는 확정 범위 밖일 수 있다. 그래서 이 결정은 바로 아래의 '블로그별 주제' 결정과 함께 본다. 하지 않을 것: llms.txt·AI 전용 파일·글 쪼개기·질문 변형 양산(GEO-11, 계획서 8-4). 신규·소규모 사이트는 외부 언급이 적어 구조적으로 불리하다(GEO-09, 중간).

### 결정 2. 네 블로그의 주제를 어떻게 나눌까?

1) 블로그당 주력 1개+클러스터로 분리하고, 구체 주제는 다음 단계(콘텐츠 전략)에서 후보를 받아 고른다
2) 계획서의 기존 제안을 그대로 확정(① 자동화 입문 ② 생활 습관·예방 ③ 일상 AI·디지털 도구+집·살림 ④ ①의 한국어 각색)
3) 주제를 나누지 않고 폭넓게 운영

**추천**: 첫째를 권장. 구글('주된 목적·초점')과 네이버(관심사 집중도, C-Rank)는 주제 집중을 본다(MON-16, RANK-1; 중간). 계획서 9-2도 '1블로그=주력 1주제+클러스터 2~3개'다. 운영자가 10/25에 '네 곳의 주제를 분리해 전문화'하고 구체 주제는 콘텐츠 전략 단계에서 제안받겠다고 했으므로, 계획서의 기존 제안(① 5-1 확정 대기, ② 5-2, ③ 11-9, ④ 11-2 확정 대기)을 후보로 다시 놓고 고른다. 이 결정에서 함께 정할 것: (가) ④가 ①의 한국어 각색본인지 독립 체험 글인지, (나) 지역 파일럿의 대상 블로그(열린 웹인 ③이 후보이며 ③ 주제와 맞는지 확인), (다) 블로그 간 동일 글 복제·상호 링크 금지(네이버의 원문 안내 단방향 링크 1개만 예외, 계획서 9-6). 새 주제·정책 변경이라 T3 승인(사용자 승인 필요, 묶음 다).

2) 사람이 직접 방문·확인한 글 3~5편만 반자동 파일럿(8주)
3) 공공데이터·공식 자료 기반 자동 생성(데이터셋·라이선스는 확인 필요)

**추천**: 둘째를 권장. AI가 지어낸 장소로 실제 피해가 난 사례가 있고(LOC-10), 지도 API 결과 저장·외부 AI 전송과 장소·리뷰 수집은 약관·권리 위험이 크다(LOC-11, 12). 사람 확인 없는 자동 게시는 '의심스러우면 게시하지 않는다'(fail-closed) 원칙과 충돌하므로, 풀오토 원칙과는 어긋나도 범위를 작게 한정하고 8주 뒤 인용 여부로 확대를 판단한다. 대상 블로그는 외부 AI에 열린 ③(한글 Blogger)이 후보다. ④(네이버)는 외부 AI 봇에 닫혀 있고 ①②는 주제·언어가 다르기 때문이다. 다만 ③은 비활성 상태이고 '1블로그=주력 1주제'(계획서 9-2)와 맞아야 하므로, 시작 시점과 보조 클러스터 여부는 블로그별 주제 결정에서 정한다. 입력 단계 전제(위치정보 제거·타인 얼굴과 회사 정보 비투입·초안은 비공개 경로로 배달)와 '[확인 필요]' 규칙은 실험 항목에 있다. 새 주제·정책 변경이라 T3 승인 필요(묶음 다). 셋째는 약국·마트 공공데이터의 라이선스·필드를 확인하지 못해(근거 못 찾음) 보류.

### 결정 4. 네이버 블로그(④)를 어떻게 운영할까?

1) 초안만 자동 생성·배달하고 휴대폰에서 사람이 직접 발행(반자동, 주 1~2편)
2) ①②③ 안정화 후로 보류
3) 운영하지 않음

**추천**: 첫째를 소규모로 시험하되, 시작은 ①에 원문이 쌓이고 개설 게이트(계획서 9-3)를 통과하고 T3 승인을 받은 뒤다(계획서 11-3 #3·11-4: ④는 비활성으로 시작). 쓰기 API는 2020년에 종료됐고 허락 없는 자동 게재는 약관상 금지라 풀오토가 불가능하며(API-1, 2), 체험 없는 AI 대량 글은 노출이 제한된다(POL-1). 직접 체험·사진이 있는 글만 올리고 대가성은 모두 표시한다. AI 활용 표시는 네이버 규정상 권장일 뿐 의무는 아니지만(POL-2) 우리 원칙상 표시한다('AI 사용 사실 숨기기'는 헌장의 비목표이고 문구·위치는 계획서 6장 5번 미결). AI가 메모·사진에 없는 맛·분위기·날짜를 채우지 않게 '[확인 필요]'로 표시하고 협찬 여부는 사람이 판단한다. ④가 ①의 한국어 각색본일지 독립 체험 글일지는 미결(계획서 11-2)이며 어느 쪽이든 복제 금지, 원문 안내는 단방향 링크 1개만 둔다. 평가는 네이버 안 지표(블로그 통계·AI 브리핑 인용 수)와 구글 색인으로 하고 외부 AI 앱 노출은 기대하지 않는다(ENG-1, LOC-01). 메이트 후보는 전전월 인용 수 기준이라 신규 블로그는 최소 2개월 뒤다(NAV-MON-1). 운영자의 반복 수작업이 생기므로 시간 부담이 크면 둘째로. 새 플랫폼 경로라 T3 승인 필요(묶음 다).

3) ③은 비활성(paused)을 유지하고, 활성화할 때 광고 없이 시작

**추천**: 첫째를 권장하되, 가능 여부가 확인될 때까지 ③은 광고 없이 둔다(셋째). ③은 지금 개설만 된 비활성 상태이고 활성화는 개설 게이트 통과 뒤이므로(계획서 11-6) 그때까지 그대로 두고, 활성화할 때 광고 없이 시작해 가능 여부가 확인되면 연결한다. 애드센스는 게시자당 계정 1개 원칙이고 중복 계정은 미승인 사유다(MON-10). 다른 Google 계정의 Blogger를 기존 계정에 붙일 수 있는지는 확인 안 됨이므로 확인 전 새 계정 신청은 피한다.

### 결정 7. 운영 문서 19개(AGENTS·CLAUDE·GEMINI·WORKLOG·보안 가드레일 등)를 공개 사이트에서 뺄까?

1) 1단계만 지금: _config.yml의 exclude로 사이트·사이트맵·내비에서 빼기(저장소에는 그대로 둠)
2) 1단계는 지금, 2단계(저장소 공개 여부)는 요금제·Pages·Actions 영향을 확인한 뒤 나중에 별도 결정
3) 현행 유지

**추천**: 둘째를 권장한다. 1단계(지금)는 사이트에서 빼기(T3, 묶음 가), 2단계(나중)는 저장소 공개 여부 검토다. 사이트맵의 46%, 글 내비 링크의 83%가 운영 문서라 주제 신호·심사 인상·보안에 불리하다(SIT-03). 사이트에서 빼도 공개 저장소·이력에는 남는다. 저장소를 비공개로 바꾸면 요금제에 따라 GitHub Pages·Actions 조건이 달라져 사이트와 자동 발행이 멈출 수 있고(확인 필요) 이미 공개된 이력은 되돌릴 수 없으므로, 지금은 공개 여부를 바꾸지 않는다. 지금 할 일은 사이트에서 빼기(T3)와 비밀값 유출 자동 탐지 확인으로 한정한다. 검증 메모에 따르면 2026-10-18 구글 API 키 형식 파일이 공개 저장소에 올라갔다 삭제된 기록이 있고 이력에 남아 있다. 옛 키는 운영자가 10/25에 삭제·재발급하고 GitHub 시크릿을 교체했다(작업 기록, 저장소로는 검증 불가). 남은 일은 GitHub의 비밀값 유출 자동 탐지(secret scanning·push protection) 켜짐 확인이며 사용자가 직접 한다. 저장소 결함 목록의 D-08은 이 문제를 '낮음'으로 등록했으므로 범위(19개)를 반영해 등급을 다시 정한다.

2) 별도 프로젝트·유료 전환으로 소규모 자동 점검(월 약 $1~2, 약관 확인 필요)

### 결정 9. 홈에서 이미 광고 요청이 나가는데 방침은 '광고 미게시'라고 적혀 있다. 어떻게 맞출까?

1) 방침을 실제 동작에 맞게 개정(광고·쿠키 고지, 영문 방문자용 동의 관리 도구 검토)
2) 애드센스 심사 결과가 나올 때까지 변경하지 않고 기다림
3) 애드센스 승인 전까지 홈의 광고 로더 제거

**추천**: 첫째를 권장하되 변경 범위를 방침 문구로 한정한다. 저장소 기록상 애드센스는 심사 대기이고 심사 중에는 광고 표면(홈·방침)을 함부로 바꾸지 말라는 규칙이 있다(HANDLER·REQUEST_BRIEFING, 분석 계획서 4-2). 그러나 지금은 방침과 실제 동작이 어긋나는 정합성 문제이고(SIT-04) 애드센스 게시자 정책은 데이터 수집·제3자 쿠키 고지가 든 방침을 요구하므로, 승인 상태를 애드센스 화면에서 먼저 확인한 뒤 문구만 고치는 쪽이 낫다(공개 페이지로는 승인 여부를 알 수 없다). 광고 로더 제거는 심사 중 코드 변경이라 더 신중해야 한다. 루트 저장소에 ads.txt도 없다. 영문 블로그는 EEA·UK 방문자를 위한 동의 관리가 없으면 개인화 광고가 제한될 수 있다(MON-09). 모두 광고 표면이라 T3 승인 필요(묶음 나, 심사 상태 확인 후).

## 3. 승인(T3)이 필요한 항목 — 묶음별

- [진행 방식] T3는 위험이 다른 항목을 한꺼번에 묻지 않고 아래 3묶음(가: 심사에 유리·저위험 / 나: 광고 표면·방침 / 다: 계정·비용·새 플랫폼·정책)으로 나눠 채팅에서 따로 승인받는다. 승인은 채팅 메시지로만 유효하고, 승인 날짜와 항목 요지를 WORKLOG(작업 기록)에 남긴다(헌장 §5).
- [묶음 가 · 즉시·작업량 작음] _config.yml: 운영 문서 19개(AGENTS·CLAUDE·GEMINI·AI_COLLAB·HANDLER·WORKLOG·docs/·인수인계)를 사이트 발행·사이트맵·글 내비에서 빼기(Jekyll exclude, SIT-03). 저장소에는 그대로 남는다.
- [묶음 가] index.html(홈): 글 목록을 Jekyll 반복문으로 서버에서 미리 그려 JS(자바스크립트) 없이도 글 링크가 보이게 하기(SIT-02). 홈은 광고 코드가 있는 광고 표면이므로 변경 범위를 글 목록 영역으로 한정한다.
- [묶음 가 · 사이트 인증 파일(정적 파일 추가, 페이지 내용·광고 코드·루트 저장소는 건드리지 않음)] Bing 인증 파일(Search Console 가져오기 방식이면 불필요할 수 있음)과 IndexNow(새 글 알림) 키 파일(/chanceblog/ 하위에 두면 루트 저장소를 건드리지 않음, TEC-05). IndexNow는 키 파일이 T3 승인 대상이고 호출 워크플로 추가·수정은 T2(총괄 승인+독립 검증)다.
- [묶음 나 · 광고 표면·방침 · 애드센스 심사 상태 확인 후] privacy 방침 개정(실제 광고 요청 발생 현황에 맞춘 광고·쿠키·GA 고지, 영문 방문자용 동의 관리 도구 검토; SIT-04, MON-09)과 ads.txt(광고 계정 인증 파일, 루트 저장소 shine88pc.github.io에 신규). 저장소 기록상 애드센스는 심사 대기이고 심사 중 변경은 위험하므로(분석 계획서 4-2) 변경 범위를 좁히고 승인 상태를 먼저 확인한다.
- [묶음 나] 방문 분석 태그: GA4(방문통계)는 분석 계획서 7-2에서 이미 결정 대기 중인 같은 결정이다(페이지 머리 부분 변경+방침 문구+심사 중 변경). Clarity(화면 분석)는 태그 설치 없이 Search Console·Bing 인증만으로 연결되는지 확인되기 전까지 이 묶음에 올린다(MEA-06). 수치는 공개 저장소·Pages·Actions 로그에 올리지 않는다(분석 계획서 4-1).
- [묶음 나] _layouts·_includes: 글 바이라인과 author 마크업, 수정일 표시·사이트맵 수정일(lastmod) 연동, 피드 선언 정리, 한·영 짝 연결 표시(hreflang)와 대표 언어 지정(x-default), 짝 없는 글 3편 처리(SIT-06, 09, 10, 12, TEC-12, 13). 사이트 전체 페이지에 영향이 가는 광고 표면이라 심사 상태 확인 후 진행한다.
- [묶음 나] robots.txt(출입 규칙 파일, 루트 저장소만 유효): 현행 전체 허용 유지를 권장한다. AI 학습 봇 차단을 원하면 승인이 필요하고, /chanceblog/robots.txt는 무효이므로 정리한다(ENG-4, TEC-02, 14).
- [묶음 나 · 루트 저장소 인증 파일] 네이버 서치어드바이저는 호스트(루트) 단위 등록이라 루트 쪽에 인증 파일이 필요한지 확인한다(추정, SIT-15). 루트 저장소(shine88pc.github.io)에는 구글 광고 스크립트가 있어 애드센스 관련 변경 금지 규칙이 적용되므로 심사 상태 확인 후 진행한다.
- [묶음 다 · 계정·비용·새 플랫폼] 신규 한글 Blogger(③)의 계정·애드센스 연결 구조(비활성 유지, 활성화는 개설 게이트 뒤), 네이버 반자동 초안 배달 경로 신설(시작은 ①에 원문이 쌓이고 게이트를 통과한 뒤), Blogger 계정 연결 동의(OAuth)·시크릿 보관: 초안 저장 모드 구현 뒤에만 등록하고 동의 화면은 프로덕션으로 전환(TEC-08, D-11).
- [묶음 다 · 정책·톤·주제 변경] 블로그별 주제 분리, 지역(장소) 글 파일럿(대상 블로그 포함), 글 템플릿 강제 규칙(소제목·1차 출처·확인일·한계 문구·'이 글만의 가치' 1개 이상), 협찬·AI 활용 표시 문구(문구·위치는 계획서 6장 5번 미결), 한·영 쌍 정책 조정.
- [묶음 다 · 게시 빈도·모델 호출 증가] 지역 글·네이버 초안을 기존 슬롯에 추가할 때 Gemini 무료 한도(프로젝트 단위, 숫자는 AI Studio에서만 확인) 예비 약 15% 유지 여부를 먼저 계산.
- [묶음 다 · 만들게 될 경우의 신규 T3] Gemini 점검용 예약 워크플로·시크릿·결제 프로젝트(MEA-08, 만들지 않기를 권장).

## 4. 측정 실험(모두 방향 확인용)

### 폰 수동 점검(기준선 + 월 1회, 방향 확인용)

- 비용: 0원. 운영자 시간 월 약 1~2시간(제안 추정). 앱 사용이라 파이프라인의 Gemini API 무료 한도(프로젝트 단위)와 별개로 영향 0. 사람이 보는 개별 결과를 확인하는 방식이라 약관 부담이 가장 작다(MEA-07).
- 성공 기준: (제안치, 방향 확인용) ① 양성 대조 2개 중 1개 이상에서 우리 도메인이 출처로 나오면 그 앱의 검색 경로에 글이 들어와 있다고 본다. ② 일반 질문의 적중 비율이 기준선보다 4주 이상 꾸준히 오르면 '긍정 신호'로만 기록한다(월 1회·질문당 2~3회 표본에서 1건 증가는 우연과 구분되지 않는다; GEO-15). ③ 양성 대조도 0이면 색인·접근 문제로 보고, 양성 대조는 통과했는데 8주 이상 연속 0이며 Search Console에서 색인·노출이 확인될 때만 콘텐츠 경쟁력 문제로 해석한다(MEA-08). 신규·소형 사이트는 구조적으로 불리하므로(GEO-09) 0이라는 이유만으로 중단하지 않는다.
- 방법: 방향 확인용(정성) 점검이다. 질문 10~12개를 만든다: 설명형 질문(정의·절차·조건·비교) + 지명(역·동 이름)을 문장에 넣은 지역 질문('근처' 대신, 앱은 IP 기반 대략 위치를 쓸 수 있음) + 대조 질문 2~4개(우리 글 제목을 그대로 묻는 양성 대조, 존재하지 않는 고유명사를 묻는 음성 대조). ChatGPT·Gemini 앱(한국 AI 챗봇 유입의 약 94%, ENG-6)에서 질문당 2~3회 묻고, Claude·Perplexity·네이버 검색의 AI 브리핑은 선택 점검한다. ChatGPT는 검색을 켠 상태에서 묻고(계획서 8-5) 출처 표시 여부도 함께 기록하며, 무료 사용 한도로 모델·검색 사용이 바뀌지 않게 질문을 며칠에 나눠 묻는다. 질문별로 3회 중 몇 회 우리 도메인이 출처에 나왔는지(적중 비율)와 출처 수만 비공개 시트에 기록하고 답변·링크 원문은 저장하지 않는다. 같은 질문도 실행마다 출처가 바뀌므로(GEO-15) 4주 이상 같은 질문 세트로 본다. 기기·위치 허용 여부·앱 버전을 함께 적는다.

### 무료 도구 3종 연결·월 확인(Search Console·Bing·Clarity, 방향 확인용)

- 비용: 0원. 사용자 1회 설정 약 30~60분(제안 추정). Gemini 한도 영향 0.
- 성공 기준: (제안치, 방향 확인용) 새 글의 80% 이상이 7일 안에 색인된다. Search Console 생성형 AI 보고서는 노출이 적으면 보고서 자체가 안 보일 수 있으므로(MEA-04) '노출수 0 초과'를 기준으로 삼지 않고 '보고서가 보이는지(표시 여부)'를 별도 지표로 기록하며, 안 보이는 것은 실패가 아니다. Bing·Clarity 인용은 신규·소형 사이트에서 0일 수 있어(추정) 실패로 보지 않고 추세만 기록한다.
- 방법: 먼저 사전 확인 2가지를 한다. (가) Bing Webmaster Tools가 경로(/chanceblog/) 단위 등록을 받는지(TEC-04 미확인, 안 되면 Search Console 가져오기 방식 등 대안을 본다). (나) Clarity의 AI Visibility 연결이 태그 설치(추가 T3·방침·쿠키 고지)를 요구하는지, Search Console·Bing 인증만으로 되는지(MEA-06 미확인). 확인 전에는 Clarity를 T3 묶음 나에 올린다. 그 뒤 사용자가 1회 Search Console(속성 등록·사이트맵 제출·생성형 AI 보고서), Bing Webmaster Tools(Search Console 가져오기·AI Performance), Microsoft Clarity(AI Visibility)를 연결하고 월 1~2회 화면 수치를 캡처해 보존한다(보존기간·API 제공은 확인 안 됨). 새 글 색인은 색인 확인 도구(URL Inspection API)로 자동 확인할 수 있다. 사용자가 계정 연결 동의(OAuth)를 1회 해야 하고, 동의 화면이 '테스트' 상태이면 토큰이 7일 뒤 만료되므로(TEC-08, D-11) 읽기 전용 범위와 프로덕션 상태를 전제로 한다(분석 계획서 4-3). 사이트당 하루 2,000건 한도. 주의: Search Console 보고서는 AI 개요·AI 모드의 노출수만(클릭·검색어 없음), Bing은 인용 횟수만(순위·클릭 아님)이며, 둘 다 Gemini 앱·ChatGPT 노출은 보여 주지 않는다(MEA-04~06).

### GA4 AI Assistant 채널로 AI 유입 클릭 계측(방향 확인용)

- 비용: 0원. Gemini 한도 영향 0. 사용자 승인(T3, 묶음 나)과 방침 개정 필요.
- 성공 기준: (제안치, 방향 확인용) 전체 세션이 500 이상일 때만 비율을 본다(1%가 5세션이 되는 최소선). 그 전에는 AI 어시스턴트 세션 수만 기록하고 판정을 보류한다. 4~8주 누적에서 AI 어시스턴트 유입이 전체 세션의 1% 이상이면 '노출→클릭→수익' 가설 검증을 계속하고, 미만이면 AI 유입을 수익 근거로 삼지 않고 검색 유입 개선에 집중한다(Conductor 1.08%를 참고치로 둔 기준, MON-02). 애드센스 승인 후에는 AI 유입 세션의 광고 수익을 비공개로 따로 비교한다.
- 방법: Blogger는 설정에서 GA4 측정 ID(G-로 시작하는 추적 번호)를 입력한다(레이아웃 테마만, 반영 최대 24시간). Jekyll(Chance_Blog)은 페이지 머리 부분(head)에 태그를 넣어야 하는데, 이는 분석 계획서 7-2에서 이미 결정 대기 중인 같은 결정이다(T3: head 변경+개인정보처리방침에 GA·쿠키 고지+애드센스 심사 중 변경). 결정 전에는 설치하지 않는다. 방문·수익 수치는 공개 저장소·Pages·Actions 로그에 올리지 않고 비공개 채널(Looker Studio 비공개 공유·비공개 저장소·메일)로만 다룬다(분석 계획서 4-1). GA4 기본 채널의 AI Assistant(ChatGPT·Gemini·Copilot·Deepseek·Grok)에서 월별 세션을 본다. 구글 AI 개요·AI 모드 클릭은 이 채널에 잡히지 않고 Search Console 웹 합계에 포함되므로 두 도구를 함께 본다(MEA-11).

### 지역 글 파일럿(3~5편, 8주, 방향 확인용)

- 비용: 운영자의 현장 방문·확인 시간(글당). 모델 호출은 기존 게시 슬롯을 대체하면 증가 0이라 Gemini 무료 한도·예비 약 15%에 영향 없음. 슬롯을 추가하면 호출 증가이므로 T3에서 예비분 유지 여부를 먼저 계산한다.
- 성공 기준: (제안치, 방향 확인용) 8주 안에 ChatGPT·Gemini 중 한 곳 이상에서 지명 질문에 해당 글이 출처로 1회 이상 표시되면 '지역 글도 열린 웹으로 노출될 가능성이 있다'고 보고 확대를 검토한다. 0이어도 곧바로 중단하지 않는다. 양성 대조는 통과했는데 8주 이상 연속 0이고 색인이 확인될 때만 지역 글 확대를 보류하고 설명형 중심을 유지한다. 신규·소형 사이트는 구조적으로 불리해(GEO-09) 0이 중단 근거가 되지 못한다. 단발 결과로 판단하지 않고 같은 질문을 반복 측정한다(GEO-15).
- 방법: T3 승인 후 한 지역(동 단위)의 장소 글 3~5편을 사람이 직접 방문·확인해 작성한다. 대상 블로그는 외부 AI에 열린 ③(한글 Blogger)이 후보다. ③은 비활성이므로 활성화 뒤에 시작하고, 대상은 블로그별 주제 결정에서 확정한다('1블로그=주력 1주제'와 충돌하면 보조 클러스터로 두며, 이때 계획서 11-9의 30% 이내·라벨 분리 규칙을 따른다). 글 요건: 상호·지점·주소·방문일·확인일, 직접 촬영 사진(얼굴·번호판 비식별), 선정 기준, 지명(역·동) 문장 포함, 지도는 링크나 공식 임베드(지도 API 결과 저장·LLM 입력 금지), 협찬이면 제목·첫 부분에 표시, 확인 안 된 부정 평가는 제외. 영업시간 같은 변동값은 확인일과 함께 쓰거나 링크로 대체. 사실 규칙: 메모·사진으로 확인되지 않은 사실(맛·분위기·날짜·영업정보)은 쓰지 않고 '[확인 필요]'로 표시하며(계획서 7-4) 협찬 여부는 사람이 판단한다. AI 활용은 우리 원칙상 표시한다. 개인정보·위치 전제: 사진은 위치정보(EXIF)를 제거하고, 타인 얼굴·번호판·회사 관련 정보(사내 장비·문서·화면 등)는 AI에 넣지 않는다(계획서 7-4, 11-8 #5). 무료 Gemini 키는 입력이 제품 개선에 쓰이고 사람이 검토할 수 있어 민감정보 제출이 금지된다(MEA-02). 초안 전달은 본인 메일 또는 비공개 저장소로 하고, 공개 저장소 이슈에는 사진 없는 텍스트만 올린다(공개 저장소로 배달하면 초안·사진이 발행 전에 공개된다; 계획서 3-10 B). 동 단위 글은 운영자의 생활권이 드러날 수 있어 범위를 정할 때 고려한다. 발행 후 폰 점검(지명 질문)과 무료 도구 3종으로 8주 추적하고 같은 기간 설명형 글과 비교한다.

### 네이버 반자동 시험(주 1~2편, 8주)

- 비용: 운영자 시간 편당 약 10~15분(제안 추정, 체험 입력 제외). 모델 호출은 기존 슬롯을 대체하면 증가 0, 추가하면 T3에서 Gemini 무료 한도 예비 약 15% 유지 여부를 계산.
- 성공 기준: (제안치, 방향 확인용) 8주 뒤 (가) 운영자가 편당 15분 이하로 지속 가능하고 (나) 네이버 검색 유입·AI 브리핑 인용 수 또는 구글 색인 중 하나 이상이 확인되면 계속한다. 초반에는 인용 수가 0일 수 있다(메이트 후보도 최소 2개월 뒤, NAV-MON-1). 둘 다 못 맞추면 보류한다. 외부 AI 앱 노출은 성공 기준에 넣지 않는다(ENG-1, LOC-01).
- 방법: 시작 조건(셋 모두 충족): (가) ①(GitHub)에 원문이 쌓임(계획서 11-3 #3: 각색본은 원문이 발행된 뒤, 11-4: ④는 비활성으로 시작), (나) 개설 게이트(계획서 9-3) 통과, (다) T3 승인(새 플랫폼 경로, 묶음 다). 방식: 운영자가 직접 경험·사진·방문 메모를 입력 → AI가 초안 작성 → 초안 배달 → 운영자가 휴대폰에서 복사해 직접 발행(예약 발행은 PC 스마트에디터 ONE에서만). ④가 ①의 한국어 각색본인지 독립 체험 글인지는 계획서 11-2에서 미결이며, 어느 쪽이든 동일 본문 복제 금지·원문 안내는 글당 단방향 링크 1개(계획서 9-6). 대가성은 모두 표시(제목 또는 첫 부분)하고 협찬 여부는 사람이 판단한다. AI 활용 표시는 네이버 규정상 권장일 뿐 의무는 아니지만(POL-2) 우리 원칙상 표시한다(헌장 비목표 'AI 사용 사실 숨기기', 문구·위치는 계획서 6장 5번 미결). 메모·사진으로 확인되지 않은 사실(맛·분위기·날짜 등)은 쓰지 않고 '[확인 필요]'로 표시한다(계획서 7-4, 가짜 경험 금지 원칙). 개인정보·위치 전제: 사진 위치정보(EXIF) 제거, 타인 얼굴·번호판·회사 정보는 AI에 넣지 않고(무료 Gemini 키는 민감정보 제출 금지, MEA-02), 초안은 본인 메일 또는 비공개 저장소로 배달한다(공개 저장소 이슈에는 사진 없는 텍스트만). 평가는 네이버 안 지표(블로그 통계·검색 유입·AI 브리핑 인용 수)와 구글 색인(계획서 11-3 #6)으로 한다.

### (보류·비권장) Gemini 자동 인용 점검

- 비용: 월 약 $1~2(가정). 3.x 모델은 무료 키로 검색 연동이 안 되어 유료 전환이 필요하다(MEA-01). 별도 프로젝트면 파이프라인의 무료 한도·예비분 영향은 0이나, 같은 결제 계정의 크레딧이 0이 되면 그 계정의 모든 프로젝트 키가 멈출 수 있다(MEA-08).
- 성공 기준: 보류. 약관이 결과 분석·캐시·모니터링을 금지하므로(MEA-02) Google 확인 전에는 실행하지 않는다. 실행하더라도 양성·음성 대조가 정상일 때만 유효하고 Gemini 한 엔진이라 폰 앱 노출을 대표하지 못한다(MEA-09).
- 방법: MEA-08 설계 초안: 질의 20개(대표 질문 12·Search Console 상위 질의 4·양성/음성 대조 각 2), 주 1회·질의당 3회, 불리언만 기록(답변 원문·링크 저장 안 함), 비공개 저장소, 프로브 전용 결제 프로젝트(파이프라인 프로젝트와 분리), 월 약 260요청.

## 6. 한계와 주의

- 운영자의 관찰(AI 앱에서 네이버가 적게 보임)에 대한 설명은 '가능한 원인'일 뿐이다. robots.txt 차단은 직접 확인됐지만(IDX-1, 2) 앱별 실제 동작은 실측하지 않았고, 사용자 요청형 에이전트(ChatGPT-User 등)는 robots를 무시할 수 있으며 구글·빙 색인 경로는 열려 있다. OpenAI 문서상 검색용 봇이 막혀도 링크·제목만 출처로 보일 수 있어 '출처로 표시됨'과 '본문을 읽어 인용함'은 다르다(ENG-2). 그래서 '네이버 출처가 가끔 보이는' 현상은 설명할 수 있어도 확정할 수 없다.
- 인용 수치(구글 AI 개요 7.7%, ChatGPT·Gemini 0건)는 GEO 판매사 보고서이고 맛집·마트가 아닌 비로컬 질의(브랜드·치과) 표본이며 인과가 아니라 동시 발생이다(LOC-02). 한국어 맛집·마트·약국 질의 자체를 측정한 공개 연구는 찾지 못했고, 지역 근거 대부분은 미국·영어·API 기반 벤더 자료이며 자료마다 출처 구성이 달라 전략의 근거로는 불안정하다(GEO-03, LOC-04).
- '노출→수익' 가설은 반증된 것이 아니라 직접 근거가 없는 상태이고, 있는 자료의 방향은 AI 요약이 붙으면 클릭이 줄고 AI 유입이 1% 안팎이라는 쪽이다(MON-01, 02). Pew(미국·구글, 2025-03)·Conductor(미국 대형 사이트)·한국 B2B 블로그 표본은 소규모 블로그의 애드센스와 직접 연결되지 않고, 구글의 '품질 높은 클릭'은 수치가 없으며 Semrush 4.4배는 자사 추정이다(GEO-16, MON-03). 협찬 쪽도 네이버 자체 지표 중심이고 AI 노출이 기준인지는 확인하지 못했다(NAV-MON-3, 읽은 체험단 플랫폼 1곳·2차 자료 한계).
- 엔진별 인용 도메인은 거의 겹치지 않고(GEO-10) 같은 질문도 실행마다 출처가 바뀐다(GEO-15). 한 번의 검색 결과로 판단하지 말고 반복 측정해야 한다. 통계·인용문 삽입 같은 GEO 기법의 '최대 +40%' 주장은 일반 규칙으로 쓸 수 없고(GEO-08), 신규·소규모 사이트는 외부 언급이 적어 구조적으로 불리하다(GEO-09, 상관·판매사 자료). 출처 선정 공식은 어느 엔진도 공개하지 않았다(ENG-11).
- 측정 실험은 모두 방향 확인용(정성)이다. 월 1회·질문당 2~3회 표본은 우연과 구분되지 않고(반복 측정에는 하루 7회 이상·2~4주가 권고됨, GEO-15, 재검증 전), 신규·소형 사이트는 구조적으로 불리해 0이 중단 근거가 되지 못한다. 중단·확대 판단은 양성 대조(우리 글 제목을 그대로 묻는 질문)는 통과했는데 8주 이상 연속 0일 때만 한다.
- 시점 의존: 네이버 robots.txt는 자주 바뀌고(파일 수정 시각 2025-10~2026-10-25), 네이버 메이트는 2026-12까지 베타라 변경·종료될 수 있으며, 공정위 AI 광고 가이드라인은 초안(의견 제출 2026-11-11까지)이고, Gemini 가격·한도 문서는 2026-09~10 기준이다. 2026-10-25 이후 달라질 수 있다.
- 법·약관 항목은 법률 자문이 아니다. 개인 블로거 단독 제재 사례는 찾지 못했으나 위험이 없다는 뜻은 아니다. 카카오·네이버 지도 약관은 원문이 아니라 포럼 답변·2차 자료에 근거한다(LOC-11, 12). AI기본법상 자동 게시 블로그 운영자의 법적 지위는 확인하지 못했다.
- 일부 항목은 검증자가 재확인하지 못했다(SIT-05~09 일부, GEO-15, TEC-11 등). 네이버 도움말의 AI 브리핑 출처 서술 등 도구 차단으로 열람하지 못한 항목(검증자 판정 '확인 불가')은 메모에서 제외했다. 'Gemini 무료 키로 검색 연동 불가'는 현재 쓰는 3.x 텍스트 모델 기준이며(MEA-01) 실시간(Live) 모델 등 예외와 2.5 모델 접근(과거 사용자 한정, MEA-03)은 확인이 필요하다.
- 우리 사이트 점검은 2026-10-25 단일 시점이다. 색인 여부, 속도 지표(Core Web Vitals), AI 크롤러 실제 방문은 확인하지 못했다. 애드센스 승인 상태는 공개 페이지로 알 수 없고 저장소 기록(REQUEST_BRIEFING·HANDLER)상 심사 대기다. 조사 중 WebSearch 한도 소진으로 독립 교차검증이 제한됐으므로 이 메모는 주어진 검증 근거 모음과 비판 검토 지적, 저장소 기록만으로 작성했다.
- 보안(SIT-03 검증 메모, 사이트 페이지 밖 정보): 공개 사이트의 운영 문서에 2026-10-18 구글 API 키 형식 파일이 공개 저장소에 올라갔다가 약 70초 뒤 삭제됐고 이력에는 남아 있다는 기록이 있다. 옛 키는 운영자가 10/25에 삭제·재발급하고 시크릿을 교체했다(작업 기록이며 저장소로는 검증 불가). 사이트 페이지의 키·토큰 패턴 검색은 0건이었고, 남은 확인은 비밀값 유출 자동 탐지(secret scanning·push protection) 켜짐 여부다.
- 계획서와의 관계: 이 메모는 블로그별 주제를 확정하지 않는다. 계획서 5-1(GitHub 주력 주제명)과 11-2(네이버를 ①의 각색 채널로 연결)는 확정 대기이고 11-9(③ 주제)는 확정으로 적혀 있으나, 운영자가 10/25에 네 곳의 주제 분리·전문화를 콘텐츠 전략 단계에서 다시 제안받겠다고 했다. 이 메모의 주제 관련 문장은 그 결정의 입력이다.
- 메모 분량 제한(3,500자)으로 세부를 user_decisions·experiments·t3_items·automation에 나눠 담았다. 메모의 괄호 표기는 (근거 수준·근거 번호)이며, 'NAV-MON-n'은 네이버 조사 주제의 수익 항목(MON-1 메이트, MON-3 협찬 기준)이고 'MON-0n'은 수익 조사 주제의 다른 항목이다. 추정 표기가 붙은 문장은 근거에서 도출한 해석이다.
- 임계값(80%·1%·8주·500세션·시간 추정 등)과 수작업 합계(월 약 2~4시간 이상, 무료 도구 1회 설정 30~60분과 현장·체험 시간은 제외)는 근거가 있는 기준이 아니라 제안치이며 첫 달 측정 후 조정해야 한다. 근거 수준 표기는 각 발견의 신뢰도와 검증자 메모의 한계를 함께 반영한 보수적 값이다.

[확인일 2026-10-25]
1) 운영자가 본 '출처는 네이버인데 노출이 한정적'인 현상은 네이버의 AI 봇 차단으로 가장 잘 설명된다. 네이버는 블로그·카페·지식iN·검색·뉴스·쇼핑에서 외부 AI 봇을 robots.txt로 막고 있고(전자신문 2025-07, 네이버 관계자 확인), 민간 조사(2026-10)에서 네이버 블로그는 ChatGPT·Gemini 인용 0건, Google AI 개요 7.7%, 네이버 AI 브리핑 46.5%였다. robots.txt 원문은 도구 차단으로 직접 열람하지 못했다.
2) 네이버 글이 AI에 노출되는 곳은 사실상 네이버 자체 AI(AI 브리핑·AI탭)다. 클로바X·Cue:는 2026-04-09 종료됐고, AI 브리핑이 인용하는 콘텐츠의 약 70%가 UGC이며, 2026-06 출범한 '네이버 메이트'는 AI 브리핑 인용 수를 핵심 지표로 창작자를 선정해 지원금을 준다.
3) 외부 AI 앱에서 비-네이버 사이트(GitHub Pages·Blogger)가 노출되려면 엔진별 검색용 봇과 색인에 걸려야 한다. ChatGPT는 OAI-SearchBot과 제3자 공급자(Microsoft가 공식 페이지에서 OpenAI를 Bing 색인 기반 Web IQ 사용처로 명시, 비율은 비공개), Gemini·AI 개요·AI 모드는 Google 색인(특수 최적화·AI 전용 파일 불필요), Claude는 Brave Search 기반(Brave는 Googlebot이 못 긁는 곳은 안 긁음), Perplexity는 자체 색인(PerplexityBot), Copilot은 Bing이다. 학습용(GPTBot·ClaudeBot·Google-Extended)과 검색용은 분리되지만 Google-Extended 차단은 Gemini 앱 노출까지 끈다.
4) robots.txt는 호스트 루트에서만 유효하므로 github.io 프로젝트 페이지(/chanceblog/)는 자체 robots.txt로 AI 봇을 제어할 수 없다(기본 허용, Google 규격에서 도출한 추론). 노출이 목적이면 검색용 봇을 막지 않는 것이 기본이다.
5) 출처 선정 가중치는 어떤 엔진도 공개하지 않았다. 공식적으로 확인되는 것은 접근·색인 자격뿐이고 그 위는 제3자 역공학·연구다(AI 검색은 제3자 매체 편향 보고, 한국어는 미검증).
6) '주변 밥집·마트' 같은 장소 질의는 지도·장소 데이터가 주 공급원이라(Gemini 앱은 Google 지도, ChatGPT는 제3자 장소 제공자와 IP 위치, 네이버는 플레이스·지도) 일반 블로그 글이 1차 출처가 될 여지는 작다[추론]. Gemini 앱의 확장 장소 기능은 영어 질문 조건이 명시돼 있다.
7) 인용 대비 클릭은 작다. Pew 기준 AI 요약이 있으면 링크 클릭 8%(없으면 15%), 요약 속 링크 1%이며, 한국의 AI 챗봇 유입은 ChatGPT 64.6%·Gemini 29.0%·Perplexity 3.6%·Copilot 2.0%·Claude 0.8%(Statcounter 2026-09), 한국 기업 블로그의 AI 검색 유입은 방문의 0.7%였다. 'AI 노출이 늘면 애드센스가 자동으로 늘 것'이라는 가설은 AI 노출만으로는 뒷받침되지 않는다.
8) 측정 수단: Search Console(AI 개요·AI 모드는 '웹'에 합산), Bing Webmaster Tools AI Performance(2026-02 프리뷰), GA의 utm_source=chatgpt.com과 Gemini UTM(미문서화), 서버 로그의 봇 UA.
참고: Perplexity 도움말 페이지 fetch 결과에 AI 에이전트를 겨냥한 지시문(인용 형식·로케일 관련)이 있다고 도구가 알렸으나 따르지 않았다. OpenAI Help Center, navercorp 보도자료, 네이버 도메인, Search Engine Land 등은 403/차단으로 원문을 열람하지 못해 검색 발췌·언론 보도에 의존한 항목은 confidence를 낮췄다.

### NAV: 네이버 블로그와 외부 검색·AI 노출, 네이버 정책

핵심 결론(2026-10-25 직접 확인). (1) 네이버는 blog·m.blog·search·place·map·cafe·news 등 거의 모든 호스트의 robots.txt에서 AI 학습·RAG 목적 봇을 명시 차단한다. 블로그 글 보기는 Googlebot·Bingbot에는 열려 있지만 GPTBot·OAI-SearchBot·PerplexityBot·ClaudeBot·Claude-SearchBot·Google-Extended는 막혀 있고, 장소(플레이스)·지도·검색결과·카페는 모든 봇에게 막혀 있다. 각 AI 회사의 공식 문서상 이 토큰들을 막으면 ChatGPT 검색·Perplexity·Claude 검색·Gemini 그라운딩의 출처에서 빠진다. 사용자가 관찰한 '앱 안에서 네이버 출처가 한정적'이라는 현상은 이 설계와 부합하며, 외부 측정(GEO 업체 표본)에서도 ChatGPT·Gemini의 네이버 블로그 인용은 0건, 구글 AI Overviews는 7.7%였다. 다만 그 측정은 맛집·마트 같은 로컬 질의가 아니고 앱별 실제 동작은 검증하지 못했다(추정과 확인은 각 finding에 구분). (2) 네이버 블로그의 'AI 노출'은 네이버 자체 AI(AI 브리핑·AI탭) 안에서 일어난다. 공식 인용 기준은 경험·일관성·진정성(협찬 표시)·가독성·최신성의 5원칙이고, 네이버 메이트(2026-06~12 베타)는 AI 브리핑 인용수를 기준으로 월 30만~1,000만 원대 현금을 지급한다. 이는 ChatGPT·Gemini 같은 외부 AI 노출과 무관하다. (3) 블로그 글쓰기 공식 API(Open API·XML-RPC)는 2020-05-06 종료됐고 지금 호출해도 존재하지 않는 API로 응답한다. 공식 경로는 PC 스마트에디터(예약 발행 포함)와 앱뿐이라 네이버 블로그는 반자동(초안은 자동, 발행은 사람)이 현실적이다. (4) AI 사용은 허용되나 기계적 대량 생성·비체험 원고는 노출 제한 대상이다. 협찬·원고료 표시는 모든 글에 필수이고 AI 표시는 UGC에서 자율로 보도됐다. (5) 애드포스트 승인 수치는 공식 비공개이며, 블로그 지수는 네이버가 만든 개념이 아니다. 체험단·협찬은 네이버 자체 지표 중심이며 외부 AI 노출은 기준으로 확인되지 않았다. (6) 서치어드바이저는 비네이버 사이트를 지원(소유확인·사이트맵·RSS·수집요청·IndexNow)하나 등록은 호스트 단위만 가능하다. 운영자의 shine88pc.github.io는 인증 메타가 /chanceblog/ 페이지에만 있고 루트 페이지에는 없다. 시사점(판단이며 사실 발견 아님): 운영자의 목표(외부 AI 앱 노출)에는 AI 봇을 막지 않는 열린 웹(운영자의 github.io·blogspot robots.txt는 AI 봇을 막지 않음)이 유리하고, 네이버 블로그는 네이버 내부 노출·협찬·메이트 수익 용도로 분리해 보는 것이 근거에 부합한다. 방법상 메모: WebFetch가 naver.com 계열을 거부해 이 PC에서 직접 HTTP GET으로 읽었다. robots.txt가 막는 경로는 이후 호출하지 않았고, 초기 점검에서 PostList.naver를 3회, rss.blog.naver.com을 1회 잘못 호출했으나 게시글 번호 확인 외에는 근거로 쓰지 않았다. WebSearch 한도(200회)가 소진되어 체험단 플랫폼 공식 기준, 인공지능기본법·공정위 지침 원문 등은 추가 검색을 못 했으며, 필요하면 후속 요청으로 이어서 조사할 수 있다.

### GEO: 생성형 엔진 최적화(GEO)의 실증 근거

결론 요약(2026-10-25 기준). [효과가 비교적 일관되게 실증된 것] (1) 먼저 해당 AI의 검색 단계에 잡혀야 한다. ChatGPT가 인용한 페이지는 전부 자체 검색이 돌려준 페이지였고, 사이트 내 인용 변동의 약 32%가 검색 노출로 설명된 반면 페이지 속성 14개는 합쳐 2.8%였다. (2) 그 안에서는 질문과 직접 맞는 제목·문단, 가격·조건 같은 구체 사실, 실제로 갱신된 날짜가 유리하다(독립 연구 여러 건이 수렴). (3) Google은 공식 가이드에서 AI 검색 최적화도 결국 SEO라고 밝힌다. [상충하는 것] Aggarwal 외 GEO 논문의 인용문·통계·출처 표기 효과(약 27~41%, 보도상 최대 40%)는 이미 검색된 5개 문서 맥락의 실험실 결과이고, 현실적 파이프라인을 재현한 C-SEO Bench·SAGEO Arena·E-GEO에서는 중립 또는 음의 결과가 다수다. 스키마·FAQ·소제목·글 길이·답 먼저 구조도 사이트 간 상관은 있으나 사이트 내 비교와 사전사후 실험에서는 사라지거나 음이며, Google(불필요)과 Microsoft(권장)의 공식 입장도 갈린다. 엔진별 인용 도메인 겹침이 매우 낮고(Jaccard 약 0.12~0.24, 네 엔진 공통 3.8%) 같은 질문도 실행마다 출처가 크게 바뀐다. [근거 없음·과장] llms.txt(Google 불사용 명시, Ahrefs 로그에서 97% 미요청, 주요 AI 업체의 읽는다는 공식 확인 없음), 보장식 +40% 주장과 2차 글의 오인용 수치, 도구가 Google 내부 지표를 안다는 주장. [한국어·로컬] 한국어 동료심사 연구는 못 찾았다. 업체 보고서(2026-10)는 네이버 블로그가 네이버 AI 브리핑 출처의 46.5%이지만 ChatGPT·Gemini에서는 0건이라 하며, 네이버의 외부 AI 봇 차단 보도(2025-07)와 부합한다. 맛집·마트 같은 로컬 질의는 공식 사이트·리스팅·리뷰 플랫폼·지역 best-of 글·Reddit이 중심이고 개인 블로그 몫은 작다. 운영자의 노출이 늘면 광고·애드센스가 늘 것이라는 가설은 직접 근거가 약하다(Pew: AI 요약 안 링크 클릭 약 1%). 마케팅·판매업체 자료와 프리프린트 비중이 커서 상당수 발견은 confidence를 medium 이하로 표시했다.

### LOC: 지역·장소 질의(주변 맛집·마트 위치)를 AI가 처리하는 방식

결론: 운영자가 본 현상은 우연이 아니라 구조 때문이다. (1) 네이버 블로그·카페·지도·플레이스와 카카오맵·플레이스는 robots.txt에서 OAI-SearchBot, Claude-SearchBot, PerplexityBot, Google-Extended 같은 AI 크롤러를 명시적으로 막고 있다(2026-10-25 원문 직접 확인). 실제 인용 조사에서도 네이버 블로그는 네이버 AI 브리핑 인용의 46.5%인데 ChatGPT와 Gemini에서는 0건이었다. 반면 운영자의 GitHub Pages와 Blogger 사이트는 크롤러에 열려 있다. (2) '지금 위치 주변' 질의의 뼈대는 블로그 글이 아니라 지도·장소 DB(영업시간, 거리, 평점, 리뷰 요약, 예약 가능 여부)와 위치 신호이고, 블로그와 리뷰 글은 보조 근거다. 위치는 기본이 IP 기반 대략 위치이며 정밀 위치는 사용자가 허용해야 쓰인다. (3) 한국은 장소 데이터와 리뷰의 중심이 AI 크롤러에 닫힌 네이버와 카카오에 있고(네이버지도 월 3,054만 대 구글지도 1,019만), 구글의 Maps 그라운딩 API는 영어만 지원한다고 명시돼 있어, 외부 AI의 한국어 장소 답변은 구글 지도 데이터와 열린 웹 문서에 기댈 가능성이 크다(추론). (4) 출처로 올라올 만한 글은 열린 도메인에서, 상호·주소·방문일이 명확하고, 지도 DB가 못 주는 직접 경험과 선정 기준이 드러나는 후기·비교·지역 정리에 확인일을 붙인 형태다. DB 사실만 되풀이하거나 기계적으로 생성한 글은 불리하다(근거는 혼합이며 일부는 추론). 구글은 별도 마크업 없이 색인과 스니펫 자격만 요구한다. (5) 네이버 블로그의 가치는 외부 AI가 아니라 네이버 자체 AI(AI 브리핑, AI탭, 플레이스 에이전트) 안에 있다. (6) 노출이 곧 클릭이나 애드센스 수익은 아니다(Pew: AI 요약이 뜨면 링크 클릭 8% 대 15%). 운영자의 '노출 증가 시 수익 증가' 가설은 장소 질의에서 검증되지 않았다. (7) 법·약관: 지도 API 결과의 저장·재사용 금지(카카오 운영진은 외부 LLM 전송도 불허로 답변), 네이버·카카오 장소·리뷰 크롤링의 약관·DB권·리뷰 저작권 위험, 협찬은 공정위 지침상 제목 또는 첫 부분에 명확히 표시, 초상권과 진실 적시 명예훼손 위험을 지켜야 한다. (8) 자동 생성 글의 가짜 장소는 실제 피해 사례(태즈메이니아의 존재하지 않는 온천 기사)가 있으므로, 현장 확인·공식 출처·확인일·사람 검수 없이 장소 사실을 자동 게시하지 않는 원칙이 필요하다. 한계: 한국어 맛집·마트·약국 질의 자체를 측정한 공개 연구는 찾지 못했고, 인용 수치 상당수는 GEO·로컬 SEO 벤더 자료다.

### TEC: 기술 구현: GitHub Pages(Jekyll)·Blogger에서의 노출 최적화와 등록

핵심 결론 6가지. (1) 구글은 AI Overviews·AI Mode 노출에 '색인되고 스니펫이 가능한 페이지' 외 조건이 없고 특수 마크업·llms.txt가 필요 없다고 공식 명시했으며, FAQ 리치 결과는 2026-05-07부로 사라졌다(문서도 06-15 삭제). 따라서 JSON-LD는 AI 앱 노출 레버가 아니다. (2) 현재 글 페이지는 jekyll-seo-tag로 BlogPosting JSON-LD·canonical·OG와 한·영 상호 hreflang을 이미 내보낸다(2026-10-25 직접 확인). 남은 보강점은 author(보이는 바이라인과 함께), 홈 WebSite JSON-LD, 그리고 홈 글 목록이 posts.json을 JS로 그려서 서버 HTML에 글 링크가 0개라는 점이다. (3) 실제 레버는 색인과 크롤 허용이다. Search Console·Bing Webmaster Tools 등록(소유 확인은 사용자 1회), sitemap, IndexNow(Bing·Naver 등 참여, Google 미참여), robots.txt 기본 allow-all 유지가 해당하며, Google-Extended는 차단하지 않는 것이 안전하다. 성과 측정은 Search Console 'Generative AI performance'와 Bing 'AI Performance'로 할 수 있다.
