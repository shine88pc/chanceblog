# 데스크톱 콘텐츠 운영 프로그램 요구서(v0.2.0) 정합 분석 — 저장소 실제 상태 기준

> 운영자 지시(2026-10-30, 채팅): 요구서 `blog_publisher_claude_handoff_v0.2.0.md` 는 이 작업을 100% 이해하고 쓴 것이 아니라 **전체를 간략히 설명한 개요**이고, 주 작업을 관리하는 이 세션이 전체 내용을 알고 있으니 **그 이해를 기준으로 맞춰서** 진행한다. 이 문서는 요구서의 문장을 저장소의 실제 모습과 하나씩 대조한 결과와, 운영자가 정해야 할 것의 목록이다. 요구서 원문은 공개 저장소에 올리지 않았다(결정 11).
>
> 사실 확인 방법: 저장소 파일·워크플로·레지스트리를 읽고, 전체 이력(모든 브랜치 585개 커밋)을 검색했다. 확인하지 못한 것은 '미확인'으로 적었다.

## 한 줄 결론

**요구서가 그리는 '플랫폼별 자동·반자동 발행 + 무료 AI + 사람 검수'의 대부분은 이미 GitHub Actions 위에서 돌아가고 있다.** 새로 필요한 것은 ① 개인 PC 에서 쓰는 **데스크톱 작업대**(원고 작성·미리보기·승인), ② **무료 AI 공급자 라우터**, ③ **GitHub Releases 설치·자동 업데이트**, ④ **네이버 두 번째 블로그** 정도다. 그래서 요구서의 '새 저장소·새 폴더 구조·전면 재구성'이 아니라, **지금 파이프라인을 핵심(core)으로 두고 그 위에 데스크톱 작업대를 얹는** 구조로 맞춘다. 정상 동작은 시험(4,272개)으로 이미 고정돼 있으니 갈아엎지 않는다.

## 2. 보안 확인 (요구서 §3 — 가장 먼저)

운영자가 "Gemini API 키를 GitHub 에 넣어둔 상태"라고 한 것은 **GitHub Actions 시크릿(§3.2 경우)** 이 맞다.
- 저장소 전체 이력(모든 브랜치 585개 커밋)에서 키 모양 문자열을 9가지 형태로 찾았다 — 구글/Gemini(`AIza…`), GitHub 토큰, 텔레그램 봇 토큰, 구글 OAuth 클라이언트 비밀·refresh token, 비공개 키 블록, `sk-`·Groq·OpenRouter 키: **모두 0건**. 값은 출력하지 않고 개수만 봤다.
- 워크플로가 읽는 시크릿은 이름만 코드에 있다: `GEMINI_API_KEY`·`UNSPLASH_ACCESS_KEY`·Blogger 영문/한글 각 4개·`TELEGRAM_BOT_TOKEN`·`TELEGRAM_CHAT_ID`·`GITHUB_TOKEN`(실행마다 자동 발급).
- `.gitignore` 가 `.env*`·`client_secret*`·`token*.json`·`*.pem`·`*.key` 등을 막고, 검증기(SEC)·로그 마스킹(`llm.mask`/`scrub`)·가드레일 G-S1~S8 이 같은 일을 한다.
- 개인 PC 이관에서 빼야 할 '로컬 절대경로·회사 식별자'(사용자 폴더 이름·사내 도메인)도 저장소 파일·모든 브랜치·전체 이력에 **0건**이다.
- 사내 PC 쪽 미커밋 변경: 작업 clone(`KCY/chanceblog`)은 깨끗하고 stash 도 없다. 이관할 로컬 전용 작업물은 없다(세션 임시 폴더 제외).
- **권고**: 키를 폐기할 필요는 없다(노출 정황 없음). 다만 요구서 §3.2 의 권고대로 **데스크톱 앱용 키와 Actions 용 키를 분리**하는 것이 좋다(결정 7). 앱은 키 없이도 수동 모드로 돌아가야 한다.

## 3. 요구서와 어긋나거나 정정이 필요한 곳

1. **티스토리**: 요구서의 이유('공식 Open API 종료로 안정적인 연동 수단이 없다')는 맞지만(2024-02 종료, R-025 조사로 확인), 이 저장소의 티스토리 채널은 API 를 쓰지 않고 **네이버와 같은 복사 패키지**다. 요구서가 네이버에 허용한 방식과 같아 이유가 해당하지 않는다. 그리고 이미 운영자 승인(R-024)·구현·독립 검증을 마쳤다. → 결정 1.
2. **저장소 구조(§9)**: 요구서의 `apps/·packages/`(TypeScript 식 모노레포)는 예시다. 이 저장소는 Python(`pipeline/`·`scripts/`·`tests/`)이고 8,850줄 코어와 4,272개 시험이 있어 TypeScript 로 옮기면 전부 다시 만들어야 한다. → 파이썬 코어 재사용을 기본으로 한다(결정 3·4).
3. **'기존 구현을 모르는 상태'(§6.1, §14)**: 이 세션은 구현을 안다. 요구서의 '현황 분석 먼저'는 이 문서로 대신한다.
4. **Phase 0~3(§12)**: 현황 동결·보안 정리·재현 환경·회귀 시험은 대부분 이미 있다(작업내용.md·SECURITY_GUARDRAILS·`requirements-dev.txt`·SESSION_START·4,272개 시험). 없는 것은 **개인 PC 이관 가이드**뿐이다.
5. **Blogger 앱 연동(§6.2)**: 지금 refresh token 은 Actions 시크릿이라 데스크톱 앱이 쓸 수 없다. 앱에는 **데스크톱 유형 OAuth 클라이언트**(구글 Cloud 에서 운영자가 발급, 로컬 loopback 로그인)가 따로 필요하다. 블로그마다 구글 계정이 다르다(G-S8). → 결정 8.
6. **'자동 발행' 용어**: 요구서의 GitHub Pages '자동 Commit/Push/Deploy' 는 앱이 저장소에 push 하는 것인데, 이 저장소는 봇이 같은 `main` 에 직접 커밋한다(`🤖 자동 포스팅`). 앱의 push 는 충돌 방지(최신 main 에서 시작)와 승인 후 실행이 필요하다.
7. **공개 저장소 주의(§2.3 '비공개 원고 이관 제외')**: 이 저장소는 공개라 앱의 '게시 전 원고'는 저장소에 넣으면 안 된다. 앱은 원고를 PC 의 사용자 데이터 폴더(SQLite·파일)에 두고, **승인한 결과만** 저장소로 보낸다.
8. **새 폴더를 이 저장소에 두면** 사이트(Jekyll)가 그 폴더를 공개 파일로 내보낼 수 있다. 사이트 빌드에서 빼는 `_config.yml` 의 `exclude` 한 줄은 광고 표면 파일 수정(T3)이라 승인이 필요하다(R-025 가 이력 파일에 한 것과 같은 방식). → 결정 3.

## 4. 맞춘 구조 — 클라우드 파이프라인은 그대로, 개인 PC 작업대를 더한다

```text
[클라우드: GitHub Actions — 지금 그대로, PC 가 꺼져 있어도 돈다]
  정기 실행 → pipeline(생성·게이트·발행) → GitHub Pages · Blogger 초안 · 초안 이슈(네이버·티스토리)
  감시: 발행 중단 감시 · 확인 필요 모음 · 요청 알림(텔레그램)
        │  같은 저장소(git)가 단일 진실원천
[개인 PC: 데스크톱 작업대 — 새로 만든다]
  원고 작성(직접 / 무료 AI 라우터) → 검사(pipeline/gates 재사용) → 플랫폼별 렌더링 → 미리보기·승인
     → Pages: 승인 후 저장소에 커밋·푸시   → Blogger: 초안 API(앱용 OAuth)   → 네이버 A/B: 복사 패키지
  설치·업데이트: GitHub Releases(초안 릴리스 → 운영자 공개) → 앱이 확인·백업·검증·적용·롤백
```

원칙: ① 파이프라인 코드가 공통 핵심이다(데스크톱이 가져다 쓴다) ② 클라우드 자동 발행은 앱이 없어도 계속된다 ③ 앱은 사람이 검수하는 경로를 편하게 하는 도구다 ④ 승인(T0~T3)·독립 검증·텔레그램 요청 규칙은 그대로다 ⑤ 로그인·쿠키·탐지 회피 자동화 없음 ⑥ 유료 호출 없음.

요구서의 패키지 이름과 저장소의 대응: `core` → `pipeline/{run,plan,state,topics,drafts,draft_flow}.py` · `validators` → `pipeline/gates.py` + 프로필 가드레일 · `publishers` → `pipeline/publishers/{blogger,issue_package,base}.py` · `providers/ai-router` → `pipeline/llm.py`(Gemini 전용 — 공통 인터페이스를 새로 만들고 Gemini 를 그 아래로 감쌈) · `renderers` → 없음(복사 패키지 렌더는 `issue_package.py` 안, 새로 분리) · `shared` → `pipeline/{registry,console,secret_patterns}.py`.
