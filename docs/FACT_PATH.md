# 구조화 Fact 경로 — 1단계(핵심 부품)

> 대상: 블로그 저장소의 글 자동 작성에서 **외부 기사 요약 대신 구조화 데이터로 글을 만드는 길**을 만드는 AI와 사람. 상위 규칙: [`CHARTER.md`](./CHARTER.md)(등급)·[`SECURITY_GUARDRAILS.md`](./SECURITY_GUARDRAILS.md)(보안). 구조: [`ARCHITECTURE.md`](./ARCHITECTURE.md) §4-10.
> 상태(2026-11-09): **새 모듈·새 시험·문서만 있고 생성기와 워크플로에는 연결하지 않았다**(연결은 2단계 — 아래 §11). 등급 T2(`pipeline/` 새 코어 모듈). 이 경로를 켜는 설정은 아직 없다.
> 운영자 결정(2026-11-09): 자동으로 쓰는 외부 자료는 권리·약관·상업·AI 이용이 분명한 **구조화 데이터**뿐이다. 외부 본문·기사 문단·해설문·홍보문·검색 스니펫·외부 결론·제3자 차트·외부 사진·외부 사례 서술은 자동화에 쓰지 않는다. 규칙 기반 초안은 **AI 없이** 돌고, AI 는 선택이며 입력은 내부 Signal·검증된 최소 Fact·Source ID 뿐이다. 제한 재개 필수 16항목 중 6번('구조화 Fact 와 자체 계산만 초안에 전달')의 1단계다.

## 1. 한눈에

| 무엇 | 어디 | 한 줄 |
|------|------|-------|
| Fact·출처 기록·참조 표시 | `pipeline/facts.py` | 값 객체(불변)·검증기·결정적 JSON·`⟦F:id⟧` 참조와 렌더러·숫자 정책 |
| 결정적 계산기 | `pipeline/calc.py` | 계산식 F01–F14 와 비교 가능성 판정. AI 는 계산하지 않는다 |
| 어댑터 계약 | `pipeline/adapters/base.py` | 구조화 응답(JSON·CSV)만 읽고 네트워크는 주입된 `opener` 로만 쓴다 |
| 시험용 가짜 Provider | `pipeline/adapters/mock_stats.py` | 오프라인 고정 데이터, 실제 기관 이름·주소 없음 |
| 주제 허용 목록 | `pipeline/fact_topics.py` | 범주별 키·라벨·단위·지역 낱말 **허용 목록**과 차단 낱말(공백·중점을 지워서도 찾음) — 허용 목록 밖이면 글이 되지 않는다 |
| Recipe(틀) | `pipeline/recipes.py` | 시계열 변화·지역 비교·임계값(기록) 3개. 문장 틀·금지 표현·허용 범주 |
| 조립기 | `pipeline/fact_assembler.py` | `assemble(recipe, facts, today, …)` 순수 함수. 스스로 검사하고 못 맞추면 `Insufficient` |

**기본 성질**: 같은 입력이면 바이트까지 같은 글(입력 순서·해시 시드와 무관) · 모든 숫자는 Fact 에서 옴 · 값이 없으면 `None`(0 이 아님) · 단위·기준일·정의·지역 수준이 다르면 계산하지 않음 · **글에 보이는 값끼리 모순이 없음**(표시 소수 자리는 단위 표와 자료의 정밀도 중 큰 쪽) · 허용 목록에 있는 낱말·단위만 글이 됨 · 어떤 입력에서도 예외 없이 글 또는 `Insufficient` · 표준 라이브러리만 · 시계·난수·네트워크·파일 입출력이 코드에 없음(시각은 인자).

## 2. 흐름

```
 [Provider 어댑터]  fetch(access, params, opener) → bytes      ← 네트워크는 주입된 opener 만(SRC 관문이 나중에 감쌈)
        │           parse(raw, access, retrieved_at) → (SourceRecord, [Fact])
        ▼
 [Fact·SourceRecord]  불변 · 내용 해시 id · Provider·수집 기록·단위·기준일·지역을 달고 다님
        ▼
 [calc]  결정적 계산식 F01–F14 → DerivedFact(식 번호 + 입력 id)  /  Skipped(이유)
        ▼
 [fact_topics]  키·라벨·단위·지역 낱말이 허용 범주의 허용 목록 안인가(밖이면 UNKNOWN_TOPIC·차단 낱말이면 TOPIC_NOT_ALLOWED)
        ▼
 [Recipe.plan]  어떤 Fact 를 쓰고 어떤 계산을 하고 어떤 문장을 만들지(비교 불가면 그 문장을 만들지 않음) → 표시 소수 자리(display_context) 정하기 → Draft(칸 이름으로 적은 틀)
        ▼
 [fact_assembler]  칸 → id(bind) → 글(render) → 스스로 검사(post_problems) → AssembledPost  또는  Insufficient
```

## 3. 객체

### SourceRecord (한 번의 수집 기록)

`record_id`(내용 해시, `s`+16자리 16진수)·`provider_id`·`access_kind`(`api`·`csv`·`dataset` 뿐 — RSS·HTML·이미지는 거부)·`request_url`(비밀 없는 https 주소만: 사용자 정보·조각·키/토큰/비밀번호/서명 이름의 질의 거부)·`retrieved_at`(시간대 포함 ISO 시각, **코드가 시계를 읽지 않고 인자로 받는다**)·`response_hash`(응답 바이트 sha256)·`license_snapshot`(그때의 이용 조건 요약 글, 600자 이하)·`retention_days`(없으면 기한 없음). 보관 기한이 지난 기록의 Fact 는 조립기가 쓰지 않는다(`RETENTION_EXPIRED`).

### Fact (정규화한 값 하나)

`fact_id`(내용 해시, `f`+16자리)·`provider_id`·`source_record_id`·`kind`·`key`·`value`·`unit`·`as_of`·`region`·`region_level`·`region_label_ko/en`·`label_ko/en`. 라벨·지역 이름은 **우리가 정한 낱말**(어댑터의 낱말 표)이고 제공처의 설명 문장이 아니다 — 검증기가 숫자·문장 부호·표시 문자·25자 넘는 글을 거부한다.

| 종류(`kind`) | 뜻 | 값 | 단위 | 기준일 `as_of` |
|---|---|---|---|---|
| `NUMBER` | 수치 | Decimal | 필수 | 필수 |
| `OBSERVATION` | 관측값 | Decimal | 필수 | 필수 |
| `PRICE` | 가격 | Decimal | 필수 | 필수 |
| `DATE` | 날짜 | `YYYY-MM-DD` | 없음 | 선택 |
| `EVENT_START` · `EVENT_END` | 행사 시작일·종료일 | `YYYY-MM-DD` | 없음 | 선택 |
| `LAW_EFFECTIVE` | 법령 시행일 | `YYYY-MM-DD` | 없음 | 선택 |
| `DATETIME` | 시각 | 시간대 포함 ISO | 없음 | 선택 |
| `REGION` | 지역 | 글자(코드) | 없음 | 선택 |
| `OFFICIAL_STATUS` | 공식 상태 | 글자 | 없음 | 선택 |
| `CLASS_CODE` | 분류코드 | 글자 | 없음 | 선택 |
| `API_VERSION` | API 버전 | 글자 | 없음 | 선택 |

- **모름은 0 이 아니다**: 값이 없으면 `None` 이다. `None` 은 글자로 바뀌지 않고(`MissingValue`), 계산은 `Skipped("MISSING_VALUE")` 이며, 비교·순위·평균에서 빠진다.
- 기준일 형식: 연(`2026`)·분기(`2026-Q1`)·월(`2026-03`)·일·시각. 같은 형식끼리만 견준다. 없는 날짜(2월 30일)나 시간대 없는 시각은 거부한다.
- `key` 는 `<범주>.<지표>` 꼴(예: `labour.unemployment_rate`)이고 범주가 건강·의료·약·금융 투자·증권·암호화폐·법률이면 이 경로가 글로 만들지 않는다(`BLOCKED_TOPICS`). Recipe 의 `allowed_domains` 안의 범주이고 키·라벨·단위·지역 낱말이 그 범주의 허용 목록에 모두 있어야 글이 되며(아래 '주제 허용 목록') 범주가 분류(경제·일 같은 생성기의 한국어 분류)로 이어진다.

### DerivedFact (계산 결과)

`fact_id`(`d`+16자리)·`formula_id`(계산식 번호)·`input_fact_ids`(입력 Fact 또는 다른 계산 결과의 id — 순서가 뜻을 가진다)·`value`·`unit`·`as_of`·`region`·`key`·`region_level`·`provider_id`(입력에서 이어받음). 값은 정밀값(Decimal, 12자리)이고 반올림은 글로 쓸 때만 한다.

### 해시·직렬화

`fact_id` 는 출처 기록 id 를 포함한 내용의 sha256 앞 16자리다 — 같은 내용이면 같은 id, 다시 수집하면(수집 시각이 다르면) 새 Fact 다. 정렬된 JSON(`sort_keys`, 한 줄)을 쓰고 숫자 값은 문자열로 적는다(실수 변환 오차 없음). `dumps_bundle`/`loads_bundle` 이 출처 기록·Fact·계산 결과 묶음을 쓰고 읽으며, 읽을 때 필수 칸 누락·모르는 칸·형식 오류·id 불일치·참조 끊김을 `FactFormatError(problems)` 로 거부한다(문제 문장에 값을 싣지 않는다). 시험이 `PYTHONHASHSEED` 를 바꿔 같은 바이트가 나옴을 확인한다.

## 4. 참조 표시와 렌더링

본문 틀의 숫자·날짜·값은 모두 **참조 표시**다. 중괄호 두 개·중괄호-퍼센트는 쓰지 않는다(Liquid 오염 방지).

| 표시 | 뜻 | 예 |
|---|---|---|
| `⟦F:칸⟧` | 값 + 단위(날짜·글자 종류는 그 값) | `3.5%` · `1,235명` · `3위` |
| `⟦S:칸⟧` | 부호 있는 값 + 단위 | `+0.3%p` · `−0.1%p` |
| `⟦A:칸⟧` | 크기(부호 없음) + 단위 | `0.3%p` |
| `⟦V:칸⟧` | 값만 | `3` |
| `⟦U:칸⟧` | 단위 | `개월` |
| `⟦D:칸⟧` | 기준일 | `2026년 3월` |
| `⟦L:칸⟧` · `⟦R:칸⟧` | 낱말 라벨 · 지역 이름 | `실업률` · `가상 지역 가` |
| `⟦T:칸⟧` | 수집일(출처 기록) | `2026년 4월 18일` |

Recipe 의 틀은 칸 이름(`⟦F:main⟧`)으로 적고, 조립기가 `bind` 로 칸을 실제 id 로 바꾼 틀(`template_markdown` — 감사에 쓴다)을 `render` 로 글로 바꾼다. **렌더링 결과에는 표시 문자가 남지 않는다**(남으면 `TemplateError`).

- **숫자 정책은 `facts.NUMBER_POLICY` 한 곳**: 표시 소수는 **단위 표(`UNIT_TABLE`)의 최소 자리와 자료의 소수 자리 중 큰 쪽**이고(`display_context` — 명·건·위·원·개월 등은 최소 정수, 달러·유로는 둘째 자리, 그 밖은 첫째 자리) 한 글 안에서 같은 단위는 같은 자리다. 그래서 자료의 값은 반올림 없이 그대로 보이고(3.44 와 3.46 이 둘 다 `3.5` 로 보여 '달라지지 않았다'와 모순되는 일이 없다) 두 값의 차이도 정확히 보인다. 자료의 소수 자리가 4자리를 넘으면 값을 깎지 않고 글로 쓰지 않는다(`PRECISION_LIMIT`). 반올림은 **0 에서 먼 쪽**(2.25 → 2.3, −2.25 → −2.3), 천 단위 쉼표, 음수는 `−`(U+2212), 반올림해 0 이 되면 부호를 붙이지 않는다(`0.0%p`). 내부 계산은 Decimal 12자리 정밀값이고 반올림은 보여 줄 때만 한다. `fact_id`·표시 자리 계산은 호출한 쪽의 decimal 전역 문맥에 의존하지 않고 유효 숫자가 40자리를 넘는 값은 받지 않는다.
- **같음·높음·낮음은 보이는 값으로**: '같아·달라지지 않은·높은·낮은' 은 글에 보이는 두 값과 그 차이의 표시값이 모두 받쳐 줄 때만 쓴다(`recipes.verdict`). 어긋나게 되면 글을 만들지 않는다(`DISPLAY_INCONSISTENT`) — 소수 자리 규칙이 바뀌어도 거짓 문장이 나가지 않는 두 번째 방어선이다.
- **참조 없는 숫자는 거부**: `untraced_numbers(틀)` 이 틀 속의 아라비아·전각·원·분수·한자 숫자와 우리말 수 표현을 찾고(두 배·세 곳 같은 순우리말 수 관형사+세는 말, 열두 곳·스물세 개, 절반·곱절·반 토막, 두세 곳·한두 개·서너 곳, 첫째·둘째·첫 번째, 수십·수백·몇 곳, 삼 분기·삼십 퍼센트·백 퍼센트·이분의 일·영 이하 같은 한자어 수+세는 말), `render` 는 있으면 `UntracedNumber` 를 던진다. 예외는 숫자가 들었지만 주장이 아닌 굳은 말('제3자'·'제1유형'–'제4유형')뿐이다. 한자어 수 한 글자(일·이·삼…)는 흔한 낱말에 들어 있어 세는 말과 붙은 꼴만 본다 — 그 밖의 표현은 새 틀을 쓸 때 사람이 검토한다(한계). 숫자는 아라비아 숫자만 받는다(전각·인도 숫자 값·기준일은 거부).
- **조사 규칙**: 앞말의 받침에 따라 달라지는 조사(은·는·이·가·을·를·과·와·(으)로)를 참조 표시나 닫는 괄호 바로 뒤에 붙이지 않는다(`의`·`에`·`에서`·`보다`·`입니다` 같은 안 변하는 말만). 받침 판정 코드를 두지 않고 틀을 '라벨 + 고정 낱말 + 조사'로 짜서 피한다. 시험이 틀과 렌더링 결과를 모두 검사한다.

### 주제 허용 목록

`pipeline/fact_topics.py` 가 범주(Domain)마다 **키 낱말·라벨 낱말·단위**를 명시하고, 모든 범주가 같이 쓰는 지역 낱말(전체 이름이 한 낱말 — 시도 이름·전국·몇몇 나라)과 시험용 가상 지역 이름 모양을 둔다. Fact 의 키·라벨·단위·지역 이름이 Recipe 의 `allowed_domains` 안 범주의 허용 목록에 **모두** 있을 때만 글이 된다. 지금 범주는 8개다: `labour`(노동·고용)·`economy`(경제)·`price`(물가)·`population`(인구)·`education`(교육)·`environment`(환경·기상)·`energy`(에너지)·`space_weather`(우주날씨).

- 막힌 주제 접두사(`BLOCKED_TOPICS`)이거나 차단 낱말(건강·의료·금융 투자·법률·과장·단정)이 어느 칸에든 있으면 `TOPIC_NOT_ALLOWED`, 허용 목록에 없는 범주·낱말·단위·지역이면 `UNKNOWN_TOPIC` 이다(서로 다른 사유 코드라 한쪽이 다른 쪽을 가려 주지 못한다).
- 차단 낱말은 공백·가운뎃점·하이픈·문장 부호·보이지 않는 글자를 지운 글에서도 찾는다(`무 조건`·`효 능`·`무·조·건`). 낱말을 가로질러 우연히 생긴 글자는 세지 않는다 — 낱말 하나 안에 있거나 낱말의 첫머리에서 시작하는 것만 본다(`최고 소비` 의 `고소`·`판매 수` 의 `매수` 는 세지 않는다). 한 글자 낱말 `암`·`약`·`병` 은 낱말 전체일 때만 본다(암호·암모니아는 과탐하지 않는다). 허용한 낱말 쌍을 모두 이어 붙여 차단 낱말이 우연히 생기지 않음을 시험이 대조한다.
- 키·라벨·단위·지역 이름·영문 라벨·Provider 이름·독자용 안내 문장 모든 칸에 적용한다. 같은 묶음(지역 비교)에 허용 목록 밖 지역이 하나라도 있으면 그 지역만 빼고 비교하지 않고 묶음 전체를 쓰지 않는다 — 한 곳을 빼면 '가장 높은 곳'이 거짓이 될 수 있다.
- 같은 계열의 라벨은 하나여야 한다(`INCONSISTENT_LABELS`).

**비교 가능성 `comparable(a, b)`**: 단위·정의(`key`)·기간(기준일)·지역 수준(·제공처)이 같아야 `COMPARABLE`. 단위가 다르거나 값이 없거나 숫자가 아니면 `DISCARD`, 정의·기간·지역 수준·제공처만 다르면 `CONTEXT_ONLY`(참고로만 언급할 수 있고 같은 줄에 놓고 견주지 않는다). 시계열 식은 `same_period=False` 로 서로 다른 기간을 견주되 기간 단위(월·분기·연)는 같아야 한다. 모든 식이 이 판정을 거치고, 단위 불일치는 한 번 더 `UnitMismatch`(산술 방어선)로 막는다.

**단위 표와 변화율**: `facts.UNIT_TABLE` 의 한 칸은 (표시 소수 자리의 최소, `ratio_ok`) 다. 섭씨(℃)처럼 0 이 임의인 구간척도와 순위(위)·퍼센트포인트(%p)·지자기 지수(Kp)·자기장(nT)은 `ratio_ok` 가 거짓이라 F02·F03·F05 가 `NOT_A_RATIO_SCALE` 로 값을 만들지 않는다(0.5℃ 에서 3.3℃ 가 '560% 증가'가 되지 않는다) — Recipe 는 그 단위의 글에서 변화율 열·문장을 만들지 않는다. 표에 없는 단위는 비율 가능으로 보지만 주제 허용 목록의 단위는 모두 이 표에 명시한다(시험). 계산 결과의 절댓값이 1e15 이상이면 예외가 아니라 `VALUE_OUT_OF_RANGE` 로 값을 만들지 않는다. 근거 텍스트에는 계산식 번호 대신 숫자 없는 이름(`calc.FORMULA_LABELS` — 증감·변화율·평균…)을 쓴다.

## 6. 어댑터 계약

`pipeline/adapters/base.py` 의 `Adapter`(`fetch`·`parse` 두 메서드의 프로토콜)와 그 공통 구현 `StructuredAdapter`:

- `build_url(access, params)`: 비밀 없는 https 주소(호스트·경로는 Registry 의 접근 항목에서, 변수 이름은 어댑터의 허용 목록 안·값은 안전한 글자뿐, 키 이름 거부, 정렬해 붙임).
- `fetch(access, params, opener) -> bytes`: 네트워크는 **주입된 `opener(url, timeout=…, max_bytes=…)`** 로만 쓴다 — 어댑터는 `urlopen` 을 부르지 않고 `urllib`·`socket` 같은 네트워크 모듈을 import 하지 않는다(시험이 AST 로 확인). SRC 의 외부 호출 관문이 나중에 `opener` 를 감싸 허용 목록 밖 호스트를 거부한다. 어떤 예외든 `AdapterError("OPENER_FAILED")` 하나로 바꾸고 원래 예외 문구(주소·토큰이 실려 있을 수 있다)는 버린다.
- `parse(raw, access, retrieved_at, params=None) -> (SourceRecord, [Fact])`: **구조화 응답(JSON·CSV)만** 읽는다. HTML·RSS 본문 파서는 두지 않는다(HTML·XML 응답은 `BAD_JSON`/`BAD_CSV`). 응답 크기·행 수 상한과 형식 오류(깨진 JSON·NaN·같은 키 두 번·칸 누락·모르는 칸·알 수 없는 계열·지역·같은 행 중복)는 `AdapterError` 로 거부한다. **오류 메시지에는 요청 주소·질의 문자열·토큰·응답 본문을 넣지 않는다**(고정 문장과 행 번호 같은 우리 낱말뿐).
- Provider 가 SRC 의 Registry 에서 `자동화 가능` 상태이고 `strict_tier` 가 2 이하가 아니면 어댑터를 만들 수 없다(`BAD_PROVIDER` — 관문 ① 뒤의 방어선). Provider 에 선택 필드 `enabled` 가 있고 True 가 아니면 라벨이 '자동화 가능'이어도 꺼진 것으로 본다.
- **요청 경로**: SRC 의 `access.paths` 는 허용 **접두어**(비면 호스트 전체)다. 요청 경로는 `paths[0] + endpoint_suffix`(어댑터 클래스가 정하는 끝 경로, 기본 빈 글자)이고 접두어도 끝 경로도 없으면 `BAD_ACCESS` 다. 접근 항목에 호스트가 여럿이면 첫째를 쓴다(허용 안의 호스트).
- **관문의 거부**: SRC 의 외부 호출 관문(`check_url`)이 허용 목록 밖 주소를 거부하면 연결 코드가 `opener` 안에서 `AdapterError("EGRESS_DENIED")` 를 올린다. `fetch` 는 `AdapterError` 를 그대로 올리므로 '허용 목록 밖이라 거부함'이 `OPENER_FAILED` 에 뭉개지지 않는다.

`mock_stats`: 가짜 Provider(`provider_id = "mock_stats"`). 여섯 가상 지역 × 열다섯 달(2025년 1월–2026년 3월) 두 계열(실업률 %, 취업자 수 명)을 JSON·CSV 로 돌려주는 가짜 `opener` 와 어댑터. 호스트는 예약된 `.invalid` 도메인이라 어디에도 연결되지 않는다. 최신 달에 자료 기간 최고인 지역(R01)·최저인 지역(R02)·직전 달과 같은 지역(R03)·한 달이 비어 있는(모름) 지역(R06)을 일부러 넣었다.

## 7. 어댑터 작성 체크리스트 (실제 Provider 를 켜기 전)

실제 Provider 어댑터는 이 일에서 만들지 않았다 — 어떤 Provider 를 켤지는 운영자 해석 1건 대기이고(후보: NOAA 우주기상센터 JSON·캐나다 통계청 WDS·Eurostat), 켜기 전에 이용 조건 7칸이 모두 확인돼야 한다(지금은 `UNKNOWN`). 새 어댑터를 만들 때 아래를 모두 채운다.

1. **7칸 증거**: 상업 이용·자동 접근·2차 저작·저장·AI 입력·출처 표시·라이선스가 모두 `ALLOWED`/`CONDITIONAL`/`DENIED` 이고 근거가 `EXPLICIT`·`STANDARD_LICENSE`·`STATUTE` 다(`IMPLIED`·`NOT_ADDRESSED`·`NOT_READ`·`UNKNOWN` 은 하나라도 있으면 켜지 않는다). Registry 항목의 `strict_tier` 가 2 이하이고 `effective_status` 가 `자동화 가능`이다.
2. **robots**: 호스트의 robots 점검일이 있고 API 경로가 막혀 있지 않다(막혀 있으면 감사자 결정으로 남기고 켜지 않는다).
3. **호출 한도**: Registry 의 호출 한도 안으로 정한 하루 호출 수·재시도 규칙(실패 3회면 그날 건너뜀)이 있고 `opener` 쪽(관문)이 지킨다. 어댑터는 재시도 루프를 갖지 않는다.
4. **구조화 경로**: 접근 경로 종류가 `api`·`csv`·`dataset` 이다(RSS·HTML 본문·검색 스니펫·외부 사진·제3자 차트는 유형만으로 제외). 응답 크기·행 수 상한을 정한다.
5. **낱말 표**: 계열·지역 코드 → (키, 한국어·영어 라벨, 단위)를 **우리 낱말**로 적는다. 라벨은 숫자·문장 부호 없이 짧은 낱말이어야 하고(검증기 규칙), 표에 없는 코드는 거부한다. 제공처의 설명 문장을 복사하지 않는다. **주제 허용 목록(`pipeline/fact_topics.py`)에 지표의 키 낱말·라벨 낱말·단위·지역 이름을 올리고 시험한다** — 허용 목록에 없는 낱말·단위·지역은 글이 되지 않고(`UNKNOWN_TOPIC`), 건강·의료·금융 투자·법률·과장·단정 낱말은 올릴 수 없다. 새 단위는 `UNIT_TABLE` 에 소수 자리 최소와 `ratio_ok` 를 명시한다.
6. **시험 고정 데이터**: 실제 기관의 응답을 저장소에 넣지 않고 우리가 만든 가짜 응답(성공·형식 오류·크기 상한·모르는 코드·빈 칸=모름)으로 시험한다. 시험은 오프라인이고 `opener` 는 가짜다.
7. **`strict_tier`·`attribution`**: `attribution_template`(출처 표시 문구 — `{title}`·`{date}`·`{url}` 만 바꿔 쓴다)을 Registry 에 두고, 독자에게 보일 안내가 필요하면 선택 필드 `reader_notes`(운영자가 독자용으로 승인한 숫자 없는 한 줄 문장)에 둔다. SRC 의 `exceptions` 는 약관 감사 메모(`확인 못 함…`·날짜·개수가 든다)라 이 경로가 읽지 않는다. 출처 표시가 조건부(`CONDITIONAL`)면 `attribution_template` 이 있어야 한다.
8. **비밀**: 키·토큰은 요청 주소에 넣지 않는다(헤더 — 관문이 붙인다). 수집 기록의 `request_url` 검증기가 키 이름 질의를 거부한다.
9. **단위·기준일**: 숫자 Fact 는 단위와 기준일이 필수다. 제공처가 단위를 주지 않으면 낱말 표에서 정한다. 값이 비어 있으면 `None`(모름)으로 읽고 0 으로 채우지 않는다.
10. **연결 금지**: 어댑터 모듈이 `urlopen`·HTML 파서·시계·난수·환경 변수를 부르지 않는다는 구조 시험(`tests/test_fact_adapters.py`)이 새 어댑터에도 적용된다.

글의 뼈대(모든 Recipe 공통): **첫 문단**(= `description`, 한 문장 60–155자, 생성기가 본문 첫 문단에서 뽑는 설명과 같다) → 자료 안내(공식 자료 링크·수집일·'증감·변화율·평균·순위는 이 글이 직접 계산했다') → `## 한눈에`(핵심 수치 3–5개, 기준일 명시) → `## 숫자로 보기`(표 1–2개, 자체 계산 표시) → `## 비교·해석`(**'이 글의 해석'**으로 표시하고 원인을 단정하지 않는다 — 이 글이 아는 것은 숫자뿐) → `## 이 숫자를 읽을 때 주의`(정의·단위·잠정치·개정·비교 한계, Recipe 별 주의, Provider 의 `reader_notes`) → `## 출처`(공식 데이터 이름·주소·열람일·`attribution_template`) → 안내 줄(사람이 쓴 글이 아니라 규칙으로 자동 정리한 일반 정보·최신 값은 출처에서 확인). 글 머리말(`title`·`category`·`tags` 등)은 만들지 않는다 — 생성기가 쓴다(§11).

**비교 불가면 그 문장을 만들지 않는다**: 바로 앞 기간이 없으면 '바로 앞 기간 대비'를 쓰지 않고(첫 문단도 다른 틀을 쓴다), 같은 기준일이 아니거나 단위·정의·지역 수준이 다른 값은 지역 비교에서 빠지며(허용 목록 밖 낱말이 든 지역이 하나라도 있으면 그 묶음 전체를 쓰지 않는다), 값이 없는(모름) 기간은 표에 '자료 없음'으로 두고 그 앞뒤 증감은 '해당 없음'으로 두며, 기간 자체가 자료에 없으면 표에서 건너뛴다고 글이 말한다. 최신 기간의 값이 비었으면 표 머리 문장의 범위를 표의 첫·끝 줄에서 가져오고 '값이 있는 마지막 기간을 기준으로 정했다'고 적는다. 지역이 12곳을 넘으면 '표에는 값이 높은 12곳만 적었다'고 밝히고 이름 목록을 표의 곳으로 한정한다. 변주는 입력에서 계산되는 규칙(부호·같음·동률·기록 여부·자료 유무)뿐이다 — 난수 없음.

**문장 오류를 막는 규칙**(독립 검증 V-01·V-04·V-05·V-06·V-13): ① 같음·높음·낮음은 글에 보이는 값 기준이다(§4). ② 개수는 기간이 빠짐없이 이어질 때만 '개월·분기·년'으로 말하고, 아니면 '관측 N개'로 쓴다. ③ 변화율은 비율 가능한 단위에만 만든다(§5). ④ 동률인 최고·최저는 '같은 값 N곳'(지역)·'같은 값이 N번'(기간)으로 쓰고 한 곳·한 기간으로 단정하지 않으며, 모든 지역 값이 같으면 지역 비교 글을 만들지 않는다(`NO_VARIATION`) · 시계열 표의 값이 모두 같으면 최고·최저 문장과 범위 줄을 만들지 않는다. ⑤ 지역이 없는 계열은 R01·R03 틀이 지역 이름을 쓰므로 `NO_REGION_SERIES` 로 이유를 말한다 — 지역 없는 틀은 2단계 후보다(NOAA 우주기상 같은 지역 없는 계열이 첫 Provider 가 되면 먼저 필요하다).

**글에 쓰지 않는 표현**(`recipes.FORBIDDEN_PHRASES`, 시험이 합의한 전체 목록을 따로 적어 두고 낱말마다 확인한다): 건강(치료·완치·처방·환자·질환…)·단정(보장·반드시·확실히·무조건…)·즉시 효과·과장(역대급·폭등·급락·충격…)·원인 단정(때문에·원인은·영향으로…)·투자·권유(매수·매도·추천합니다·주식·코인…)·법률(위법입니다·처벌·소송…)·예측(전망됩니다·오를 것…)·번역투(에 의해·를 통해·에 대한…). 부분 문자열로 찾고 공백·가운뎃점·하이픈을 지운 글에서도 찾는다(낱말 첫머리에서 시작하는 것만 — 아래 '주제 허용 목록'). 제공처 이용 조건 줄(법적 출처 표시 문구)만 이 목록으로 검사하지 않고, 독자용 안내 문장(`reader_notes`)은 우리 글과 같이 검사한다.

### 조립기 결과

`AssembledPost`: `title`·`description`·`body_markdown`·`category`·`tags`·`facts_used`·`derived`·`evidence_text`(렌더링한 Fact 표를 평문으로 — 2단계에서 Gate 의 근거 텍스트가 된다. **값·단위·기준일·지역 이름만** 싣고 id·출처 기록 id·Provider id·계산식 번호는 싣지 않는다 — 실리면 그 숫자가 '근거 숫자'로 세어져 본문에 끼워 넣은 숫자를 못 잡는다. 본문의 숫자는 모두 이 글 안에 같은 글자 모양으로 있다)·`source_name`·`source_url`·`source_domain`·`lang = "ko"`·`recipe_id`·`as_of` 와, 추가로 `template_markdown`(렌더링 전 틀)·`source_records`·`dedupe_key`(`recipe|key|region|as_of`)·`skipped`(만들지 못한 계산과 사유)·`formulas`·`recipe_version`·`decimals`(글의 숫자를 보인 소수 자리 [(단위, 자리)]).

`Insufficient(code, detail)` 가 돌아오면 글을 만들지 않는다. 사유 코드: `NO_FACTS`·`TOO_FEW_POINTS`·`TOO_FEW_REGIONS`·`NOT_COMPARABLE`·`STALE`(최신 기준일이 450일을 넘음)·`FUTURE_DATA`(기준일이 오늘보다 뒤)·`TOPIC_NOT_ALLOWED`(막힌 주제·차단 낱말)·`UNKNOWN_TOPIC`(허용 목록에 없는 범주·낱말·단위·지역)·`MIXED_PERIOD_KIND`·`DUPLICATE_PERIOD`·`DUPLICATE_REGION`·`TOO_SHORT`(분량 하한 미달)·`NO_ANALYSIS`(서로 다른 계산식 둘 미만)·`PROVIDER_NOT_ACTIVE`·`SOURCE_INFO_INVALID`·`INVALID_FACTS`·`MISSING_RECORD`·`RETENTION_EXPIRED`·`READER_NOTE_UNSAFE`(독자용 안내 문장이 규칙을 못 지킴)·`ATTRIBUTION_TEMPLATE_INVALID`·`TEMPLATE_UNTRACED`·`RENDER_ERROR`·`TITLE_LENGTH`·`DESCRIPTION_LENGTH`·`BAD_TODAY`·`QUALITY_CHECK_FAILED`·`NO_REGION_SERIES`(지역 없는 계열)·`INCONSISTENT_LABELS`(같은 계열인데 라벨이 다름)·`NO_VARIATION`(모든 지역의 값이 같음)·`DISPLAY_INCONSISTENT`(보이는 값과 어긋나는 표현이 나오게 됨)·`PRECISION_LIMIT`(자료의 소수 자리가 표시 한도 넘음)·`VALUE_OUT_OF_RANGE`(값이나 계산 결과가 범위 밖)·`FUTURE_RECORD`(수집일이 오늘보다 뒤)·`PLAN_ERROR`·`INTERNAL_ERROR`(예상 밖 오류 — 글을 내보내지 않는 쪽으로 닫는다. 퍼징 시험이 0 임을 확인한다).

**분량 하한**: 국문 1,000자(공백·표시 기호 제외, 출처 목록 제외)는 생성기 방식으로 세되 표의 구분줄을 뺀 보수적 측정이다(생성기가 세는 수보다 같거나 작다). 하한을 맞추려고 근거 없는 문장을 채우지 않는다 — Recipe 별 최소 입력을 넘는 모든 입력이 하한을 넘고, 모자라면 `TOO_SHORT`.

**스스로 검사(`post_problems`)**: 표시 문자·중괄호·물결표·금지 표현·제목 길이·설명(한 문장·길이·첫 문단과 같음)·절 순서·표·분량·본문 숫자가 모두 근거 텍스트에 있음·틀에 참조 없는 숫자 없음·글자 체계(영문 낱말은 라벨·단위로 온 것만, 한자·가나 없음)·같은 문장 반복·조사 규칙. 걸리면 글 대신 `QUALITY_CHECK_FAILED` — 조용히 내보내지 않는다.

## 9. SRC(허용 목록)와의 인터페이스 약속

SRC 가 `pipeline/source_registry.py` 에서 `Registry.get(provider_id) -> Provider|None`(읽기 전용 필드 `provider_id`·`strict_tier`·`effective_status`·`access`(종류·호스트·경로)·`attribution_template`·`snapshot`·`policy`·`retention_days`)와 `Registry.active_providers()`·`is_url_allowed(url, purpose)` 를 만든다. 이 경로는 그 모양과 같은 **최소 프로토콜**(`facts.ProviderLike`·`RegistryLike`·`Opener`, `typing.Protocol`)을 `pipeline/facts.py` 안에 두어 어댑터·조립기가 '그 필드를 가진 아무 객체나' 받게 한다 — **SRC 의 모듈을 import 하지 않는다**(시험은 가짜 객체를 쓰고, 사전 모양의 Provider 도 받는다). 병합 뒤 연결은 2단계다.

**선택 필드**(없어도 글이 된다 — 프로토콜에는 올리지 않는다): `name`, `enabled`(있고 True 가 아니면 쓰지 않는다), `reader_notes`(독자에게 보일 수 있게 승인된 숫자 없는 한 줄 문장 목록, 기본 비어 있음). SRC 의 `exceptions` 는 약관 감사 메모(`확인 못 함…`·날짜·개수가 든다)라 독자용 문장이 아니므로 **읽지 않는다**.

독립 검증(V-08, SRC 머리 기준 읽기 전용)이 짚은 의미 불일치와 처리:

| 불일치 | 처리 |
|---|---|
| `exceptions` 가 독자용 문구가 아니라 감사 메모 — 구조화 접근 Provider 18곳 중 10곳이 숫자·수 표현 때문에 글이 안 됐다 | `exceptions` 를 읽지 않고 독자용 안내는 `reader_notes` 만(D-138) — 이 일에서 고쳤다 |
| `paths` 는 허용 접두어(비면 호스트 전체)인데 어댑터가 첫 경로를 그대로 요청 주소로 쓰고 빈 `paths` 는 `BAD_ACCESS` | 요청 경로 = `paths[0] + endpoint_suffix`(어댑터의 끝 경로)(D-139) — 이 일에서 고쳤다 |
| 활성 판정이 저장된 라벨·tier 만 본다(`enabled`·`Registry.is_active`·`snapshot.expires_at` 은 안 봄) | `enabled` 가 있고 True 가 아니면 거절(D-139). `Registry.is_active`·`snapshot.expires_at`·`is_url_allowed` 사전 확인은 2단계 연결 코드가 한다(이 경로가 SRC 모듈을 import 하지 않으므로) |
| 외부 호출 관문의 거부가 `OPENER_FAILED` 에 뭉개져 '허용 목록 밖'이라는 사유가 사라진다 | 연결 코드가 `opener` 안에서 `AdapterError("EGRESS_DENIED")` 를 올리고 `fetch` 가 그대로 올린다(D-139) |
| 지금 `active_providers()` 가 0곳이라 이 경로를 켤 Provider 가 없다 | 운영자 해석 1건 대기(§7) |

## 11. 이미지 문제와 2단계 연결 계획

### 이미지 문제(조사 결과 — 이 일에서 코드는 바꾸지 않았다)

지금 생성기는 Unsplash 사진 두 장을 못 얻으면 글을 저장하지 않는다(`generate_blog_posts` 의 `pick_images` 뒤 `len(images) < 2` 검사)와 사진의 작가 출처를 모르면 저장하지 않는다(`credit_line_for` 검사). 구조화 Fact 글은 외부 사진을 쓰지 않는다(운영자 방침: 자체 생성 표·차트·사용자가 고른 이미지, 없으면 이미지 없음). 머리말 `image` 가 없을 때 저장소가 어떻게 반응하는지 읽은 결과:

| 곳 | 반응 |
|---|---|
| `generator.front_matter_problems` | 필수 키에 `image` 가 있어 `image` 줄이 없으면 **오류**(글을 거절한다) |
| `tests/test_posts_front_matter.py` | `_posts` 의 **모든 글**의 `image` 가 `https` 주소(글자가 `https` 로 시작)여야 한다 — 없으면 PR 검사가 빨갛다 |
| `_layouts/post.html` | `page.image` 를 쓰지 않는다 — 글 쪽은 이미지 없이 정상 |
| `index.html` 서버가 미리 그린 카드 | `post.image` 가 없으면 이미지 없이 어두운 상자와 분류 표지만 보인다(깨지지 않음) |
| `index.html` 스크립트가 `posts.json` 으로 다시 그린 카드 | `post.image` 가 비면 **고정 Unsplash 사진 네 장 중 하나**(`getDefaultThumbnail`)를 제목 해시로 골라 보여 주고, 불러오기 실패 때도 첫 번째로 되돌린다 — 이미지 없는 글도 홈에서는 출처 표시 없는 Unsplash 사진이 뜬다 |
| `posts.json` | `image` 가 없으면 빈 글자(`""`) |
| `pipeline/drafts.py` | 승인 PR 이 올릴 수 있는 경로는 `_posts/…md` 뿐이다(`_POST_PATH_RE`) — 글마다 따로 이미지 파일을 올리려면 이 규칙과 `draft_flow` 를 바꿔야 한다(T2) |

**후보 해결**

1. **이미지 없음 허용 + 홈 카드 대체**: `index.html`(광고 표면, T3)의 기본 썸네일 네 장을 빼거나 바꿔야 하고, `front_matter_problems`(T2)와 `test_posts_front_matter`(기존 시험 완화)·사진 출처 검사를 모두 Fact 글에서만 풀어야 한다. 손댈 곳이 가장 많고 보호 영역(광고 표면)이 들어 있다.
2. **자체 이미지**: (a) 글마다 만드는 자체 SVG 차트(순수 함수 — 입력은 Fact 시계열, 출력은 결정적 SVG 글자) 또는 (b) 모든 Fact 글이 같이 쓰는 자체 디자인 카드 이미지 한 장(사진 아님·출처 표시 불필요). `image` 가 `https` 주소로 남아 위의 검사들이 모두 그대로 통과하고, 홈의 기본 Unsplash 사진도 뜨지 않는다.

**권고: 2번 — 먼저 (b), 이어서 (a)**. 근거: ① 보호 영역(`index.html`)과 기존 시험을 건드리지 않는다. ② 외부 사진을 쓰지 않아 운영자 방침과 맞고 사진 출처 검사는 '자체 이미지는 작가 출처가 없다'는 한 줄 예외로 풀린다. ③ (b)는 글마다 파일을 올리지 않아 승인 PR 의 경로 규칙을 바꿀 필요가 없다(정적 이미지 한 장을 한 번 저장소에 넣는 변경이고 `assets/` 는 광고 표면이 아니다). ④ (a)는 정보가 있는 이미지지만 SVG 는 소셜 미리보기(`og:image`)에 잘 안 쓰이고, 글마다 파일을 올리려면 `drafts.py`·`draft_flow.py`·`ARCHITECTURE` §4-4 와 G-L3 을 같이 고쳐야 해서 2단계 뒤 별도 작업이 맞다. (a)의 설계: `chart_svg(points, title, unit_label) -> str` 순수 함수(표준 라이브러리만)·고정 크기·좌표를 정수로 반올림해 결정적·`<title>`·`<desc>` 로 접근성·값 라벨은 `facts.format_*` 만 쓰고·스크립트·외부 참조·`style` 없음 — 아직 만들지 않았다.

**보완(독립 검증 I-02)**: 홈 카드는 `image` 가 `https` 절대 주소여야 `test_posts_front_matter` 를 통과하므로 저장소 안의 공용 카드 이미지를 쓰려면 사이트의 절대 주소가 필요하다. 글 레이아웃(`_layouts/post.html`)은 `page.image` 를 쓰지 않아 '벡터 그림은 소셜 미리보기에 잘 안 쓰인다'는 위의 근거는 지금은 무관하다. 공용 이미지 한 장을 모든 Fact 글에 쓰면 글마다 같은 그림이 되어 반복감이 커지므로 (a) 글마다 자체 차트를 만드는 쪽이 장기적으로 낫다.

### 2단계 연결 계획(한 군데 호출)

1. **스위치**: 레지스트리 `chance.content_source`(`feed` 기본·`facts`). 켜는 것은 T3(게시 방식·소스 변경)다. `facts` 에서는 `fetch_news_items`·기사 발췌·구글 뉴스 해석기를 부르지 않는다(SRC 의 `source_policy: allowlist` 와 같은 자리).
2. **생성기 호출 한 군데**: `generate_blog_posts` 의 후보 만들기 자리에서 `content_source == "facts"` 이면 Gemini 호출·피드 후보 대신 `fact_assembler.assemble(...)` 의 `AssembledPost` 를 후보로 쓴다. 어댑터 `fetch`→`parse` 는 이 호출의 앞에서 한 번(수집 시각은 생성기가 읽어 인자로 넘김 — 이 모듈들은 시계를 읽지 않는다). `languages` 는 `["ko"]` 만 허용한다(영문은 이 경로가 만들지 않는다).
3. **Gate 의 두 함수만 Fact 기반으로**: `quality_gate.evidence_text(source)` 가 `AssembledPost.evidence_text` 를, `source_ref(source)` 가 `source_url`·`source_domain`·`source_name` 을 돌려준다(규칙 함수는 그 두 함수만 읽는다 — `EvidenceBoundaryTest` 가 지킨다). 근거 텍스트에는 값·단위·기준일·지역 이름만 있고 id·계산식 번호가 없으므로(D-131) QG1-NUMBER 는 본문 숫자가 모두 근거 텍스트에 있으면 통과하고, 본문에 끼워 넣은 숫자는 정확히 잡힌다(id 의 숫자가 '근거 숫자'로 세어지던 예전 모양에서는 `5곳`·`17곳` 이 통과했다).
4. **Gate `QG5-COMPANY`(출처 도메인 허용 목록)**: Gate 는 출처 도메인이 공공·연구기관 목록(`PUBLIC_SOURCE_DOMAINS`)에 없으면 글을 보류한다. 골든 3편(가짜 도메인)은 물론 실제 후보 호스트 가운데 `kosis.kr` 도 목록 밖이라, 호스트가 목록에 없는 Provider 의 Fact 글은 **모두 보류된다**(같은 검증에서 `services.swpc.noaa.gov`·`www150.statcan.gc.ca`·`ec.europa.eu`·`ecos.bok.or.kr`·`apihub.kma.go.kr`·`open.law.go.kr` 와 공공데이터포털(`data.go.kr` 의 `www` 호스트)은 통과했다). 연결 방법: Fact 글에서 `source_ref(source)` 가 `source_domain`(= Provider 의 `access.hosts` 첫째 호스트 — SRC 허용 목록을 통과한 공식 호스트)을 돌려주고, Gate 의 도메인 판정이 Registry 가 허용한 `access.hosts` 를 같은 근거로 인정하게 한다 — 호스트를 SRC 허용 목록 한 곳에만 올리면 Gate 도 통과하도록. 켜기 전 순서(아래 11항)의 그림자 실행에서 `QG5-COMPANY` 통과를 확인한다.
5. **이미지**: 위 §11 권고에 따라 `chance.content_source: "facts"` 에서는 사진 선택·사진 사용 알림·작가 출처 검사를 건너뛰고 자체 이미지 주소를 머리말 `image` 로 쓴다(`front_matter_problems` 는 그대로 통과).
6. **이력 `topic`**: 외부 제목 대신 `AssembledPost.title`(자체 제목)을 쓴다. 공개 주석·실행 요약·탈락 사유에도 외부 제목이 없다(이 경로에는 외부 제목이 없다).
7. **중복 방지**: 지금의 제목 유사도(0.7)와 QG7-REUSE(같은 출처 주소 재사용 보류)는 **달마다 반복되는 통계 글을 중복으로 거부한다**(같은 Provider 의 같은 공식 페이지·같은 틀의 제목). Fact 글은 `AssembledPost.dedupe_key`(Recipe·키·지역·기준일)가 같은 글이 이미 있을 때만 중복으로 보고, 제목 유사도·출처 주소 재사용 검사는 `facts` 글에서 이 키로 바꾼다(이력에 `dedupe_key` 칸을 더한다).
8. **SHADOW_RUN 호환**: 그림자 실행은 후보를 일반 실행과 같은 함수로 만들고 쓰지 않으므로, Fact 후보도 같은 함수에서 나오면 호환된다(조립기는 파일을 쓰지 않는다). 외부 호출이 없는 경로라 `SHADOW_RUN` 중에도 어댑터는 가짜 opener 나 허용 목록 안 호스트로만 돈다.
9. **머리말·파일**: 머리말(`layout`·`title`·`category`·`tags`·`lang`·`image`·`description`·출처 세 줄)은 생성기의 기존 함수가 `AssembledPost` 의 칸으로 쓴다. 시험(`tests/test_fact_assembler.py`)이 생성기 함수를 읽기 전용으로 불러 같은 규칙을 이미 통과함을 확인한다.
10. **승인 흐름**: 하루 최대 1편·`publish_flow: pr`·사람 승인은 LOCK·R2 가 만든 것을 그대로 쓴다. 이 경로는 자동 공개 경로를 만들지 않는다.
11. **켜기 전 순서**: Provider 의 7칸 증거(운영자 해석 1건) → 주제 허용 목록에 지표 낱말·단위·지역 올리기 → Registry 에 켜기 PR → 그림자 실행 ≥3회(QG5 통과 확인 포함)·초안 ≥10건 평가 → 2단계 PR(`content_source` 값 추가 — 기본 `feed`, 꺼진 상태에서 출력이 이전과 바이트까지 같음을 시험) → T3 승인 뒤 값 변경.

## 13. 한계와 남은 일

- **글이 얼마나 자연스러운가(솔직한 평가)**: 문장은 짧고 구체적이며 틀에서 나온 티가 난다. 같은 Recipe 의 글은 같은 뼈대와 같은 주의 줄을 쓰고, 변주는 부호·같음·동률·기록 여부·자료 유무·기간 규칙뿐이다. 글에 '왜'가 없다 — 이 글이 아는 것은 숫자뿐이라는 원칙의 대가다.
- **분량과 틀 고정 글자(독립 검증의 글 품질 평가를 숫자로 잰 것)**: 골든 세 편의 본문 분량·'이 숫자를 읽을 때 주의' 절·그 절을 뺀 분량·틀의 고정 글자 비율을 잰다(`tests/fact_helpers.py` 의 `quality_metrics` — 글자 수는 생성기 방식으로 공백·표시 기호·표 구분줄·출처 목록을 뺀 것이고 '고정 글자'는 틀에서 참조 표시를 지운 나머지다). 이 표는 시험(`tests/test_fact_docs.py`)이 코드가 잰 값과 같은지 확인한다.

- **이 조립기 글의 쓰임(D-146)**: 하루 1편 상한·사람 승인을 전제로 한 **초안 보조**로는 쓸 만하다(숫자가 틀리지 않고 출처가 붙고 사람이 해석·맥락을 덧붙일 틈이 있다). 지금 3개 Recipe 그대로 공개 글을 계속 내는 것은 **보류가 맞다** — 새 정보가 제공처 페이지의 요약 수준(자체 계산한 증감·평균·순위뿐)이고, 같은 뼈대·같은 고정 문장이 글마다 반복되며, 월마다 같은 틀의 글이 쌓이면 대량 생산 패턴으로 읽힐 수 있다(`CHARTER.md` 비목표 '복제·대량 양산'). 2단계에서 Recipe 를 늘려 주제·구성·문장 틀의 변주를 키우거나 AI 서술을 더하되 모든 숫자를 Fact 검증으로 다시 거르는 방식(완성형 단계)으로 풍부하게 만든 뒤에 공개 글로 내는 것이 순서다. 이번 수정은 Recipe 를 늘리지 않았다.
