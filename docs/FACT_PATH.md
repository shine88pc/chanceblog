# 구조화 Fact 경로 — 1단계(핵심 부품)

> 대상: 블로그 저장소의 글 자동 작성에서 **외부 기사 요약 대신 구조화 데이터로 글을 만드는 길**을 만드는 AI와 사람. 상위 규칙: [`CHARTER.md`](./CHARTER.md)(등급)·[`SECURITY_GUARDRAILS.md`](./SECURITY_GUARDRAILS.md)(보안). 구조: [`ARCHITECTURE.md`](./ARCHITECTURE.md) §4-10.
> 상태(2026-11-09, 1단계 시점 — 이후 S2a·S2b 가 이어졌다): **새 모듈·새 시험·문서만 있고 생성기와 워크플로에는 연결하지 않았다**(연결은 2단계 — 아래 §11). 등급 T2(`pipeline/` 새 코어 모듈). 이 경로를 켜는 설정은 아직 없다.
> 2026-11-10 S2a(2단계 중 생성기에 연결하지 않는 순수 부분 — §14): 첫 제공처 NOAA 우주날씨의 어댑터(`pipeline/adapters/noaa_swpc.py`)·지역 없는 틀 R04–R06(`pipeline/recipes_noregion.py`)·후보 순서(`pipeline/fact_candidates.py`)·**제목에 값을 넣지 않는 정책**·출처 문구 자동 첨부 검사를 더했다. 연결(생성기 분기·후보 공급 한 함수·AI 키 미전달·잠금 규칙·워크플로)은 S2b 의 일이었다(S2a 시점에는 연결하지 않았다).
> 2026-11-11 S2b(2단계의 연결 부분 — §15): 레지스트리 `chance.content_source`(`feed` 기본·`facts`)와 생성기·그림자 실행의 Fact 분기, 후보 공급 함수(`pipeline/fact_supply.py`), 허용 목록 관문·호출 예산에 거는 연결 코드, 자체 카드 이미지, 출처 표식과 이력 칸, 이력의 발행일로 차례를 정하는 후보 선택을 이었다. **켜지는 값은 하나도 없다**: `pipeline/blogs.json` 에 값이 없고(기본 `feed`) 제공처는 모두 꺼져 있으며 워크플로·광고 표면은 바뀌지 않았다. 꺼진 상태의 출력은 이전과 바이트까지 같다. 워크플로의 AI 키 식(AF7)은 T3 라 패치 초안만 만들었다.
> 운영자 결정(2026-11-09): 자동으로 쓰는 외부 자료는 권리·약관·상업·AI 이용이 분명한 **구조화 데이터**뿐이다. 외부 본문·기사 문단·해설문·홍보문·검색 스니펫·외부 결론·제3자 차트·외부 사진·외부 사례 서술은 자동화에 쓰지 않는다. 규칙 기반 초안은 **AI 없이** 돌고, AI 는 선택이며 입력은 내부 Signal·검증된 최소 Fact·Source ID 뿐이다. 제한 재개 필수 16항목 중 6번('구조화 Fact 와 자체 계산만 초안에 전달')의 1단계다.

## 2. 흐름

```
 [Provider 어댑터]  fetch(access, params, opener) → bytes      ← 네트워크는 주입된 opener 만(SRC 관문이 나중에 감쌈)
        │           parse(raw, access, retrieved_at) → (SourceRecord, [Fact])
        ▼
 [Fact·SourceRecord]  불변 · 내용 해시 id · Provider·수집 기록·단위·기준일·지역을 달고 다님
        ▼
 [calc]  결정적 계산식 F01–F14 → DerivedFact(식 번호 + 입력 id)  /  Skipped(이유)
        ▼
 [fact_topics]  키·라벨·단위·지역 낱말이 허용 범주의 허용 목록 안인가(밖이면 UNKNOWN_TOPIC·차단 낱말이면 TOPIC_NOT_ALLOWED)
        ▼
 [Recipe.plan]  어떤 Fact 를 쓰고 어떤 계산을 하고 어떤 문장을 만들지(비교 불가면 그 문장을 만들지 않음) → 표시 소수 자리(display_context) 정하기 → Draft(칸 이름으로 적은 틀)
        ▼
 [fact_assembler]  칸 → id(bind) → 글(render) → 스스로 검사(post_problems) → AssembledPost  또는  Insufficient
```

## 3. 객체

### SourceRecord (한 번의 수집 기록)

`record_id`(내용 해시, `s`+16자리 16진수)·`provider_id`·`access_kind`(`api`·`csv`·`dataset` 뿐 — RSS·HTML·이미지는 거부)·`request_url`(비밀 없는 https 주소만: 사용자 정보·조각·키/토큰/비밀번호/서명 이름의 질의 거부)·`retrieved_at`(시간대 포함 ISO 시각, **코드가 시계를 읽지 않고 인자로 받는다**)·`response_hash`(응답 바이트 sha256)·`license_snapshot`(그때의 이용 조건 요약 글, 600자 이하)·`retention_days`(없으면 기한 없음). 보관 기한이 지난 기록의 Fact 는 조립기가 쓰지 않는다(`RETENTION_EXPIRED`).

### Fact (정규화한 값 하나)

`fact_id`(내용 해시, `f`+16자리)·`provider_id`·`source_record_id`·`kind`·`key`·`value`·`unit`·`as_of`·`region`·`region_level`·`region_label_ko/en`·`label_ko/en`·`meta`. 라벨·지역 이름은 **우리가 정한 낱말**(어댑터의 낱말 표)이고 제공처의 설명 문장이 아니다 — 검증기가 숫자·문장 부호·표시 문자·25자 넘는 글을 거부한다.

`meta`(S2a)는 값이 어디서 왔고 어떤 상태인지를 Fact 에 붙이는 **꼬리표**다 — 이름순으로 정렬한 (이름, 값) 글자쌍(여덟 개까지, 이름은 영문 소문자·밑줄, 값은 영문·숫자·`_.:-` 32자까지): `producer`(값을 만든 기관)·`status`(`observed` 관측·`estimated` 추정·`predicted` 예보·`reference` 기준값)·`quality`(`provisional` 잠정치)·`satellite`·`stations`. 해시에 들어가 꼬리표가 다르면 다른 Fact 다. **없으면 `None` 이고 그때의 `fact_id`·JSON 은 꼬리표가 생기기 전과 바이트까지 같다**(칸 자체를 해시와 JSON 에 넣지 않는다 — R01–R03 의 출력이 같은 까닭). `Fact.meta_value(이름)` 으로 읽는다.

| 종류(`kind`) | 뜻 | 값 | 단위 | 기준일 `as_of` |
|---|---|---|---|---|
| `NUMBER` | 수치 | Decimal | 필수 | 필수 |
| `OBSERVATION` | 관측값 | Decimal | 필수 | 필수 |
| `PRICE` | 가격 | Decimal | 필수 | 필수 |
| `DATE` | 날짜 | `YYYY-MM-DD` | 없음 | 선택 |
| `EVENT_START` · `EVENT_END` | 행사 시작일·종료일 | `YYYY-MM-DD` | 없음 | 선택 |
| `LAW_EFFECTIVE` | 법령 시행일 | `YYYY-MM-DD` | 없음 | 선택 |
| `DATETIME` | 시각 | 시간대 포함 ISO | 없음 | 선택 |
| `REGION` | 지역 | 글자(코드) | 없음 | 선택 |
| `OFFICIAL_STATUS` | 공식 상태 | 글자 | 없음 | 선택 |
| `CLASS_CODE` | 분류코드 | 글자 | 없음 | 선택 |
| `API_VERSION` | API 버전 | 글자 | 없음 | 선택 |

- **모름은 0 이 아니다**: 값이 없으면 `None` 이다. `None` 은 글자로 바뀌지 않고(`MissingValue`), 계산은 `Skipped("MISSING_VALUE")` 이며, 비교·순위·평균에서 빠진다.
- 기준일 형식: 연(`2026`)·분기(`2026-Q1`)·월(`2026-03`)·일·시각. 같은 형식끼리만 견준다. 없는 날짜(2월 30일)나 시간대 없는 시각은 거부한다.
- `key` 는 `<범주>.<지표>` 꼴(예: `labour.unemployment_rate`)이고 범주가 건강·의료·약·금융 투자·증권·암호화폐·법률이면 이 경로가 글로 만들지 않는다(`BLOCKED_TOPICS`). Recipe 의 `allowed_domains` 안의 범주이고 키·라벨·단위·지역 낱말이 그 범주의 허용 목록에 모두 있어야 글이 되며(아래 '주제 허용 목록') 범주가 분류(경제·일 같은 생성기의 한국어 분류)로 이어진다.

### DerivedFact (계산 결과)

`fact_id`(`d`+16자리)·`formula_id`(계산식 번호)·`input_fact_ids`(입력 Fact 또는 다른 계산 결과의 id — 순서가 뜻을 가진다)·`value`·`unit`·`as_of`·`region`·`key`·`region_level`·`provider_id`(입력에서 이어받음). 값은 정밀값(Decimal, 12자리)이고 반올림은 글로 쓸 때만 한다.

### 해시·직렬화

`fact_id` 는 출처 기록 id 를 포함한 내용의 sha256 앞 16자리다 — 같은 내용이면 같은 id, 다시 수집하면(수집 시각이 다르면) 새 Fact 다. 정렬된 JSON(`sort_keys`, 한 줄)을 쓰고 숫자 값은 문자열로 적는다(실수 변환 오차 없음). `dumps_bundle`/`loads_bundle` 이 출처 기록·Fact·계산 결과 묶음을 쓰고 읽으며, 읽을 때 필수 칸 누락·모르는 칸·형식 오류·id 불일치·참조 끊김을 `FactFormatError(problems)` 로 거부한다(문제 문장에 값을 싣지 않는다). 시험이 `PYTHONHASHSEED` 를 바꿔 같은 바이트가 나옴을 확인한다.

## 4. 참조 표시와 렌더링

본문 틀의 숫자·날짜·값은 모두 **참조 표시**다. 중괄호 두 개·중괄호-퍼센트는 쓰지 않는다(Liquid 오염 방지).

| 표시 | 뜻 | 예 |
|---|---|---|
| `⟦F:칸⟧` | 값 + 단위(날짜·글자 종류는 그 값) | `3.5%` · `1,235명` · `3위` |
| `⟦S:칸⟧` | 부호 있는 값 + 단위 | `+0.3%p` · `−0.1%p` |
| `⟦A:칸⟧` | 크기(부호 없음) + 단위 | `0.3%p` |
| `⟦V:칸⟧` | 값만 | `3` |
| `⟦U:칸⟧` | 단위 | `개월` |
| `⟦D:칸⟧` | 기준일 | `2026년 3월` |
| `⟦L:칸⟧` · `⟦R:칸⟧` | 낱말 라벨 · 지역 이름 | `실업률` · `가상 지역 가` |
| `⟦T:칸⟧` | 수집일(출처 기록) | `2026년 4월 18일` |

Recipe 의 틀은 칸 이름(`⟦F:main⟧`)으로 적고, 조립기가 `bind` 로 칸을 실제 id 로 바꾼 틀(`template_markdown` — 감사에 쓴다)을 `render` 로 글로 바꾼다. **렌더링 결과에는 표시 문자가 남지 않는다**(남으면 `TemplateError`).

- **숫자 정책은 `facts.NUMBER_POLICY` 한 곳**: 표시 소수는 **단위 표(`UNIT_TABLE`)의 최소 자리와 자료의 소수 자리 중 큰 쪽**이고(`display_context` — 명·건·위·원·개월 등은 최소 정수, 달러·유로는 둘째 자리, 그 밖은 첫째 자리) 한 글 안에서 같은 단위는 같은 자리다. 그래서 자료의 값은 반올림 없이 그대로 보이고(3.44 와 3.46 이 둘 다 `3.5` 로 보여 '달라지지 않았다'와 모순되는 일이 없다) 두 값의 차이도 정확히 보인다. 자료의 소수 자리가 4자리를 넘으면 값을 깎지 않고 글로 쓰지 않는다(`PRECISION_LIMIT`). 반올림은 **0 에서 먼 쪽**(2.25 → 2.3, −2.25 → −2.3), 천 단위 쉼표, 음수는 `−`(U+2212), 반올림해 0 이 되면 부호를 붙이지 않는다(`0.0%p`). 내부 계산은 Decimal 12자리 정밀값이고 반올림은 보여 줄 때만 한다. `fact_id`·계산·표시는 호출한 쪽의 decimal 전역 문맥(정밀도·반올림·지수 한계·함정)에 기대지 않는다 — 모든 진입점이 명시한 지역 문맥(`facts.exact` — 정밀도 60·짝수 쪽 반올림·넓은 지수 범위) 안에서 돌고 단항 `abs`·`-` 대신 `copy_abs`·`copy_negate` 를 쓴다(D-150 — 전역 정밀도 5 에서 `1,234,567.1` 이 `1,234,600.0` 이 되던 일을 고쳤다). 유효 숫자가 40자리를 넘는 값은 받지 않는다. **순위·개수 계산 결과는 자료의 단위 자리와 상관없이 정수**로 보인다(`INTEGER_FORMULAS`: F04·F12·F16 — 교육 범주의 `곳`·`개` 단위 소수 자료에서도 `6곳 비교`, D-153). 지역이 짝수 곳이라 **평균이 표시 자리의 반 칸에 정확히 걸치면**(값 3.4·3.4·3.5·3.5 의 평균 3.45) 그 단위의 표시 자리를 한 칸 늘려 반올림 없이 보인다(`settle_context` — 평균 `3.45%`, 차이 `+0.05%p`, D-152).
- **같음·높음·낮음은 보이는 값으로**: '같아·달라지지 않은·높은·낮은' 은 글에 보이는 두 값과 그 차이의 표시값이 모두 받쳐 줄 때만 쓴다(`recipes.verdict`). 어긋나게 되면 글을 만들지 않는다(`DISPLAY_INCONSISTENT`) — 소수 자리 규칙이 바뀌어도 거짓 문장이 나가지 않는 두 번째 방어선이다.
- **참조 없는 숫자는 거부**: `untraced_numbers(틀)` 이 틀 속의 아라비아·전각·원·분수·한자 숫자와 우리말 수 표현을 찾고(두 배·세 곳 같은 순우리말 수 관형사+세는 말, 열두 곳·스물세 개, 절반·곱절·반 토막, 두세 곳·한두 개·서너 곳, 첫째·둘째·첫 번째, 수십·수백·몇 곳, 삼 분기·삼십 퍼센트·백 퍼센트·이분의 일·영 이하 같은 한자어 수+세는 말), `render` 는 있으면 `UntracedNumber` 를 던진다. 예외는 숫자가 들었지만 주장이 아닌 굳은 말('제3자'·'제1유형'–'제4유형')뿐이다. 우리말 수 표현은 흔한 낱말(조건·이번·사건·세대·열대·일명·만원·프로그램·조사원 …)을 수로 잡지 않도록 **구조로** 가른다(D-154): ① 앞 글자가 한글·영문·숫자가 아닐 때만(낱말 첫머리), ② 세는 말 뒤에 한글이 더 이어지면 조사·어미로 시작할 때만(`세 곳이`·`두 배로` 는 잡고 `일 개선`·`한 프로그램`·`일일 건수` 는 놓친다), ③ 한 글자 수(한·두·세·네·열, 일·삼·사·오·십·백·천·만 …)는 띄어 쓴 꼴만 모든 세는 말과 이어 보고 붙여 쓴 꼴은 흔한 낱말과 겹치지 않는 세는 말(곳·개·번·명·가지·개월·퍼센트·시간 …)만 본다(세대·열대·두건·사건·조건·일개·오명·만원은 수가 아니다), ④ 두 글자 이상 수(열두·스물·다섯·이십·오륙·두어·두세 …)는 붙여 쓴 꼴도 보되 수 글자로만 된 흔한 낱말(사이·이사·일일·만일·조사·구조 …)은 뺀다, ⑤ 지시어 `이`(이 곳·이 점·이 번호)는 한 글자 수로 보지 않는다. 두어 곳·서넛·한둘·여럿·이삼 일·오륙 개·십중팔구·영하·반 이상과 영문 수 낱말(two·half·zero …)도 잡는다. 그 밖의 표현은 새 틀을 쓸 때 사람이 검토한다(한계, §13). 숫자는 아라비아 숫자만 받는다(전각·인도 숫자 값·기준일은 거부).
- **조사 규칙**: 앞말의 받침에 따라 달라지는 조사(은·는·이·가·을·를·과·와·(으)로)를 참조 표시나 닫는 괄호 바로 뒤에 붙이지 않는다(`의`·`에`·`에서`·`보다`·`입니다` 같은 안 변하는 말만). 받침 판정 코드를 두지 않고 틀을 '라벨 + 고정 낱말 + 조사'로 짜서 피한다. 시험이 틀과 렌더링 결과를 모두 검사한다.

### 주제 허용 목록

`pipeline/fact_topics.py` 가 범주(Domain)마다 **키 낱말·라벨 낱말·단위**를 명시하고, 모든 범주가 같이 쓰는 지역 낱말(전체 이름이 한 낱말 — 시도 이름·전국·몇몇 나라)과 시험용 가상 지역 이름 모양을 둔다. Fact 의 키·라벨·단위·지역 이름이 Recipe 의 `allowed_domains` 안 범주의 허용 목록에 **모두** 있을 때만 글이 된다. 지금 범주는 8개다: `labour`(노동·고용)·`economy`(경제)·`price`(물가)·`population`(인구)·`education`(교육)·`environment`(환경·기상)·`energy`(에너지)·`space_weather`(우주날씨).

- 막힌 주제 접두사(`BLOCKED_TOPICS`)이거나 차단 낱말(건강·의료·금융 투자·법률·과장·단정)이 어느 칸에든 있으면 `TOPIC_NOT_ALLOWED`, 허용 목록에 없는 범주·낱말·단위·지역이면 `UNKNOWN_TOPIC` 이다(서로 다른 사유 코드라 한쪽이 다른 쪽을 가려 주지 못한다).
- 차단 낱말은 공백·가운뎃점·하이픈·문장 부호·보이지 않는 글자를 지운 글에서도 찾는다(`무 조건`·`효 능`·`무·조·건`). 낱말을 가로질러 우연히 생긴 글자는 세지 않는다 — 낱말 하나 안에 있거나 낱말의 첫머리에서 시작하는 것만 본다(`최고 소비` 의 `고소`·`판매 수` 의 `매수` 는 세지 않는다). 한 글자 낱말 `암`·`약`·`병` 은 낱말 전체일 때만 본다(암호·암모니아는 과탐하지 않는다). 허용한 낱말 쌍을 모두 이어 붙여 차단 낱말이 우연히 생기지 않음을 시험이 대조한다.
- 키·라벨·단위·지역 이름·영문 라벨·Provider 이름·독자용 안내 문장 모든 칸에 적용한다. 같은 묶음(지역 비교)에 허용 목록 밖 지역이 하나라도 있으면 그 지역만 빼고 비교하지 않고 묶음 전체를 쓰지 않는다 — 한 곳을 빼면 '가장 높은 곳'이 거짓이 될 수 있다.
- 같은 계열의 라벨은 하나여야 한다(`INCONSISTENT_LABELS`).
- **허용 목록이 없는 자유 글 칸은 더 엄격하다(D-155)**: 공식 데이터 이름(`SourceInfo.name`)과 독자용 안내 문장(`reader_notes`)은 낱말을 나눠 쓴 우회(`국민환 자 통계`)를 낱말 첫머리 규칙으로는 못 잡으므로 **낱말 경계와 상관없이** 공백·부호를 지운 글에서 차단 낱말을 찾는다(`blocked_loose` — 이름 `최고 소비` 의 `고소` 같은 우연한 글자도 걸리는 오탐이 있으나 사람이 고쳐 쓸 수 있는 칸이라 놓치는 쪽의 값이 더 크다고 보았다). 두 칸은 제어·서식·방향 문자(`unicodedata` 범주 C, 줄·문단 구분)와 링크·HTML·마크다운 링크·코드·표를 만드는 기호(`<`·`>`·`[`·`]`·백틱·`|`·역슬래시·`@`)와 주소 조각(`http`·`://`·`www`)도 받지 않는다(`&` 는 막지 않는다 — HTML 엔티티는 영문자나 숫자가 있어야 만들어지고 그것은 글자 체계·숫자 검사가 막는다). Fact 의 라벨 같은 허용 목록 칸은 낱말 첫머리 규칙 그대로다(과탐 방지).

**비교 가능성 `comparable(a, b)`**: 단위·정의(`key`)·기간(기준일)·지역 수준(·제공처)이 같아야 `COMPARABLE`. 단위가 다르거나 값이 없거나 숫자가 아니면 `DISCARD`, 정의·기간·지역 수준·제공처만 다르면 `CONTEXT_ONLY`(참고로만 언급할 수 있고 같은 줄에 놓고 견주지 않는다). 시계열 식은 `same_period=False` 로 서로 다른 기간을 견주되 기간 단위(월·분기·연)는 같아야 한다. 모든 식이 이 판정을 거치고, 단위 불일치는 한 번 더 `UnitMismatch`(산술 방어선)로 막는다.

**단위 표와 변화율**: `facts.UNIT_TABLE` 의 한 칸은 (표시 소수 자리의 최소, `ratio_ok`) 다. 섭씨(℃)처럼 0 이 임의인 구간척도와 순위(위)·퍼센트포인트(%p)·지자기 지수(Kp)·자기장(nT)·등급 단계(단계)는 `ratio_ok` 가 거짓이라 F02·F03·F05 가 `NOT_A_RATIO_SCALE` 로 값을 만들지 않는다(0.5℃ 에서 3.3℃ 가 '560% 증가'가 되지 않는다) — Recipe 는 그 단위의 글에서 변화율 열·문장을 만들지 않는다. 표에 없는 단위는 비율 가능으로 보지만 주제 허용 목록의 단위는 모두 이 표에 명시한다(시험). 계산 결과의 절댓값이 1e15 이상이면 예외가 아니라 `VALUE_OUT_OF_RANGE` 로 값을 만들지 않는다. 근거 텍스트에는 계산식 번호 대신 숫자 없는 이름(`calc.FORMULA_LABELS` — 증감·변화율·평균…)을 쓴다.

## 6. 어댑터 계약

`pipeline/adapters/base.py` 의 `Adapter`(`fetch`·`parse` 두 메서드의 프로토콜)와 그 공통 구현 `StructuredAdapter`:

- `build_url(access, params)`: 비밀 없는 https 주소(호스트·경로는 Registry 의 접근 항목에서, 변수 이름은 어댑터의 허용 목록 안·값은 안전한 글자뿐, 키 이름 거부, 정렬해 붙임).
- `fetch(access, params, opener) -> bytes`: 네트워크는 **주입된 `opener(url, timeout=…, max_bytes=…)`** 로만 쓴다 — 어댑터는 `urlopen` 을 부르지 않고 `urllib`·`socket` 같은 네트워크 모듈을 import 하지 않는다(시험이 AST 로 확인). SRC 의 외부 호출 관문이 나중에 `opener` 를 감싸 허용 목록 밖 호스트를 거부한다. 어떤 예외든 `AdapterError("OPENER_FAILED")` 하나로 바꾸고 원래 예외 문구(주소·토큰이 실려 있을 수 있다)는 버린다.
- `parse(raw, access, retrieved_at, params=None) -> (SourceRecord, [Fact])`: **구조화 응답(JSON·CSV)만** 읽는다. HTML·RSS 본문 파서는 두지 않는다(HTML·XML 응답은 `BAD_JSON`/`BAD_CSV`). 응답 크기·행 수 상한과 형식 오류(깨진 JSON·NaN·같은 키 두 번·칸 누락·모르는 칸·알 수 없는 계열·지역·같은 행 중복)는 `AdapterError` 로 거부한다. **오류 메시지에는 요청 주소·질의 문자열·토큰·응답 본문을 넣지 않는다**(고정 문장과 행 번호 같은 우리 낱말뿐).
- Provider 가 SRC 의 Registry 에서 `자동화 가능` 상태이고 `strict_tier` 가 2 이하가 아니면 어댑터를 만들 수 없다(`BAD_PROVIDER` — 관문 ① 뒤의 방어선). Provider 에 선택 필드 `enabled` 가 있고 True 가 아니면 라벨이 '자동화 가능'이어도 꺼진 것으로 본다.
- **요청 경로**: SRC 의 `access.paths` 는 허용 **접두어**(비면 호스트 전체)다. 요청 경로는 `paths[0] + endpoint_suffix`(어댑터 클래스가 정하는 끝 경로, 기본 빈 글자)이고 접두어도 끝 경로도 없으면 `BAD_ACCESS` 다. 접근 항목에 호스트가 여럿이면 첫째를 쓴다(허용 안의 호스트).
- **관문의 거부**: SRC 의 외부 호출 관문(`check_url`)이 허용 목록 밖 주소를 거부하면 연결 코드가 `opener` 안에서 `AdapterError("EGRESS_DENIED")` 를 올린다. `fetch` 는 `AdapterError` 를 그대로 올리므로 '허용 목록 밖이라 거부함'이 `OPENER_FAILED` 에 뭉개지지 않는다.

`mock_stats`: 가짜 Provider(`provider_id = "mock_stats"`). 여섯 가상 지역 × 열다섯 달(2025년 1월–2026년 3월) 두 계열(실업률 %, 취업자 수 명)을 JSON·CSV 로 돌려주는 가짜 `opener` 와 어댑터. 호스트는 예약된 `.invalid` 도메인이라 어디에도 연결되지 않는다. 최신 달에 자료 기간 최고인 지역(R01)·최저인 지역(R02)·직전 달과 같은 지역(R03)·한 달이 비어 있는(모름) 지역(R06)을 일부러 넣었다.

## 7. 어댑터 작성 체크리스트 (실제 Provider 를 켜기 전)

실제 Provider 어댑터는 1단계에서 만들지 않았다 — 어떤 Provider 를 켤지는 운영자 해석 1건 대기였고(후보: NOAA 우주기상센터 JSON·캐나다 통계청 WDS·Eurostat), 켜기 전에 이용 조건 7칸이 모두 확인돼야 한다. 첫 후보 NOAA 우주날씨의 어댑터는 S2a 가 만들었고 이 체크리스트를 그 제공처에 대해 채운 표는 §14-8 이다. 새 어댑터를 만들 때 아래를 모두 채운다.

1. **7칸 증거**: 상업 이용·자동 접근·2차 저작·저장·AI 입력·출처 표시·라이선스가 모두 `ALLOWED`/`CONDITIONAL`/`DENIED` 이고 근거가 `EXPLICIT`·`STANDARD_LICENSE`·`STATUTE` 다(`IMPLIED`·`NOT_ADDRESSED`·`NOT_READ`·`UNKNOWN` 은 하나라도 있으면 켜지 않는다). Registry 항목의 `strict_tier` 가 2 이하이고 `effective_status` 가 `자동화 가능`이다.
2. **robots**: 호스트의 robots 점검일이 있고 API 경로가 막혀 있지 않다(막혀 있으면 감사자 결정으로 남기고 켜지 않는다).
3. **호출 한도**: Registry 의 호출 한도 안으로 정한 하루 호출 수·재시도 규칙(실패 3회면 그날 건너뜀)이 있고 `opener` 쪽(관문)이 지킨다. 어댑터는 재시도 루프를 갖지 않는다.
4. **구조화 경로**: 접근 경로 종류가 `api`·`csv`·`dataset` 이다(RSS·HTML 본문·검색 스니펫·외부 사진·제3자 차트는 유형만으로 제외). 응답 크기·행 수 상한을 정한다.
5. **낱말 표**: 계열·지역 코드 → (키, 한국어·영어 라벨, 단위)를 **우리 낱말**로 적는다. 라벨은 숫자·문장 부호 없이 짧은 낱말이어야 하고(검증기 규칙), 표에 없는 코드는 거부한다. 제공처의 설명 문장을 복사하지 않는다. **주제 허용 목록(`pipeline/fact_topics.py`)에 지표의 키 낱말·라벨 낱말·단위·지역 이름을 올리고 시험한다** — 허용 목록에 없는 낱말·단위·지역은 글이 되지 않고(`UNKNOWN_TOPIC`), 건강·의료·금융 투자·법률·과장·단정 낱말은 올릴 수 없다. 새 단위는 `UNIT_TABLE` 에 소수 자리 최소와 `ratio_ok` 를 명시한다.
6. **시험 고정 데이터**: 실제 기관의 응답을 저장소에 넣지 않고 우리가 만든 가짜 응답(성공·형식 오류·크기 상한·모르는 코드·빈 칸=모름)으로 시험한다. 시험은 오프라인이고 `opener` 는 가짜다.
7. **`strict_tier`·`attribution`**: `attribution_template`(출처 표시 문구 — `{title}`·`{date}`·`{url}` 만 바꿔 쓴다)을 Registry 에 두고, 독자에게 보일 안내가 필요하면 선택 필드 `reader_notes`(운영자가 독자용으로 승인한 숫자 없는 한 줄 문장)에 둔다. SRC 의 `exceptions` 는 약관 감사 메모(`확인 못 함…`·날짜·개수가 든다)라 이 경로가 읽지 않는다. 출처 표시가 조건부(`CONDITIONAL`)면 `attribution_template` 이 있어야 한다.
8. **비밀**: 키·토큰은 요청 주소에 넣지 않는다(헤더 — 관문이 붙인다). 수집 기록의 `request_url` 검증기가 키 이름 질의를 거부한다.
9. **단위·기준일**: 숫자 Fact 는 단위와 기준일이 필수다. 제공처가 단위를 주지 않으면 낱말 표에서 정한다. 값이 비어 있으면 `None`(모름)으로 읽고 0 으로 채우지 않는다.
10. **연결 금지**: 어댑터 모듈이 `urlopen`·HTML 파서·시계·난수·환경 변수를 부르지 않는다는 구조 시험(`tests/test_fact_adapters.py`)이 새 어댑터에도 적용된다.

**제목 정책(S2a, D-200)**: 모든 Fact 글의 **제목에는 측정값(숫자)을 넣지 않고 이름(`⟦L⟧`)·지역(`⟦R⟧`)·기준일(`⟦D⟧`·`⟦T⟧`)만 쓴다** — 값·변화량·순위·퍼센트·개수 같은 계산 결과는 제목에 없다. 예: `가상 지역 가 실업률, 2025년 4월부터 2026년 3월까지 — 숫자로 읽기`. 기준일 참조는 허용한 칸 이름에서만 쓴다(최신 기준일 `main`·`cur`·표의 처음·끝 줄 `first_row`·`last_row`·읽은 자료의 처음 `first`·수집일 `record`). 이유: 제목은 이력의 `topic`·태그·분류와 함께 AI 입력이 되는 길이 열려 있는 칸이다(AI 흐름 감사 R18·F1–F4) — 값이 제목에 있으면 값이 AI 로 새는 길이 된다. **설명(`description`)과 본문에는 값이 있어도 된다**: 감사 보고서 §4 의 `AssembledPost` 표에서 AI 가능 함수가 읽는 칸은 제목·태그·분류뿐이고 설명·본문은 읽지 않는다(`tags`·`category` 는 라벨·분류 낱말뿐이다). 지킴이는 세 겹이다 — 틀 단계(`recipes.title_template_problem` 이 값 참조를 거절 → 조립기 `TITLE_HAS_VALUE`)·`post_problems` 의 `TITLE` 검사·골든 글과 시험(제목에 값 참조·날짜 아닌 숫자 없음).

**비교 불가면 그 문장을 만들지 않는다**: 바로 앞 기간이 없으면 '바로 앞 기간 대비'를 쓰지 않고(첫 문단도 다른 틀을 쓴다), 같은 기준일이 아니거나 단위·정의·지역 수준이 다른 값은 지역 비교에서 빠지며(허용 목록 밖 낱말이 든 지역이 하나라도 있으면 그 묶음 전체를 쓰지 않는다), 값이 없는(모름) 기간은 표에 '자료 없음'으로 두고 그 앞뒤 증감은 '해당 없음'으로 두며, 기간 자체가 자료에 없으면 표에서 건너뛴다고 글이 말한다. 최신 기간의 값이 비었으면 표 머리 문장의 범위를 표의 첫·끝 줄에서 가져오고 '값이 있는 마지막 기간을 기준으로 정했다'고 적는다. 지역이 12곳을 넘으면 '표에는 값이 높은 12곳만 적었다'고 밝히고 이름 목록을 표의 곳으로 한정한다. 변주는 입력에서 계산되는 규칙(부호·같음·동률·기록 여부·자료 유무)뿐이다 — 난수 없음.

**문장 오류를 막는 규칙**(독립 검증 V-01·V-04·V-05·V-06·V-13): ① 같음·높음·낮음은 글에 보이는 값 기준이다(§4). ② 개수는 기간이 빠짐없이 이어질 때만 '개월·분기·년'으로 말하고, 아니면 '관측 N개'로 쓴다. ③ 변화율은 비율 가능한 단위에만 만든다(§5). ④ 동률인 최고·최저는 '같은 값 N곳'(지역)·'같은 값이 N번'(기간)으로 쓰고 한 곳·한 기간으로 단정하지 않으며, 모든 지역 값이 같으면 지역 비교 글을 만들지 않는다(`NO_VARIATION`) · 시계열 표의 값이 모두 같으면 최고·최저 문장과 범위 줄을 만들지 않는다. ⑤ 지역이 없는 계열은 R01·R03 틀이 지역 이름을 쓰므로 `NO_REGION_SERIES` 로 이유를 말한다 — 지역 없는 계열은 지역 없는 틀 R04–R06(§14)이 쓴다(R01–R03 은 그대로다).

**글에 쓰지 않는 표현**(`recipes.FORBIDDEN_PHRASES`, 시험이 합의한 전체 목록을 따로 적어 두고 낱말마다 확인한다): 건강(치료·완치·처방·환자·질환…)·단정(보장·반드시·확실히·무조건…)·즉시 효과·과장(역대급·폭등·급락·충격…)·원인 단정(때문에·원인은·영향으로…)·투자·권유(매수·매도·추천합니다·주식·코인…)·법률(위법입니다·처벌·소송…)·예측(전망됩니다·오를 것…)·번역투(에 의해·를 통해·에 대한…). 부분 문자열로 찾고 공백·가운뎃점·하이픈을 지운 글에서도 찾는다(낱말 첫머리에서 시작하는 것만 — 아래 '주제 허용 목록'). 제공처 이용 조건 줄(법적 출처 표시 문구)만 이 목록으로 검사하지 않고, 독자용 안내 문장(`reader_notes`)은 우리 글과 같이 검사한다.

### 조립기 결과

`AssembledPost`: `title`·`description`·`body_markdown`·`category`·`tags`·`facts_used`·`derived`·`evidence_text`(렌더링한 Fact 표를 평문으로 — 2단계에서 Gate 의 근거 텍스트가 된다. **값·단위·기준일·지역 이름만** 싣고 id·출처 기록 id·Provider id·계산식 번호는 싣지 않는다 — 실리면 그 숫자가 '근거 숫자'로 세어져 본문에 끼워 넣은 숫자를 못 잡는다. 본문의 숫자는 모두 이 글 안에 같은 글자 모양으로 있다)·`source_name`·`source_url`·`source_domain`·`lang = "ko"`·`recipe_id`·`as_of` 와, 추가로 `template_markdown`(렌더링 전 틀)·`source_records`·`dedupe_key`(`recipe|key|region|as_of`)·`skipped`(만들지 못한 계산과 사유)·`formulas`·`recipe_version`·`decimals`(글의 숫자를 보인 소수 자리 [(단위, 자리)]).

`Insufficient(code, detail)` 가 돌아오면 글을 만들지 않는다. 사유 코드: `NO_FACTS`·`TOO_FEW_POINTS`·`TOO_FEW_REGIONS`·`NOT_COMPARABLE`·`STALE`(최신 기준일이 450일을 넘음)·`FUTURE_DATA`(기준일이 오늘보다 뒤)·`TOPIC_NOT_ALLOWED`(막힌 주제·차단 낱말)·`UNKNOWN_TOPIC`(허용 목록에 없는 범주·낱말·단위·지역)·`MIXED_PERIOD_KIND`·`DUPLICATE_PERIOD`·`DUPLICATE_REGION`·`TOO_SHORT`(분량 하한 미달)·`NO_ANALYSIS`(서로 다른 계산식 둘 미만)·`PROVIDER_NOT_ACTIVE`·`SOURCE_INFO_INVALID`·`INVALID_FACTS`·`MISSING_RECORD`·`RETENTION_EXPIRED`·`READER_NOTE_UNSAFE`(독자용 안내 문장이 규칙을 못 지킴)·`ATTRIBUTION_TEMPLATE_INVALID`·`ATTRIBUTION_REQUIRED`(출처 표시가 조건부인데 템플릿이 비어 있음 — D-206)·`ATTRIBUTION_SCOPE_MISMATCH`(공공영역 주장이 든 문구에 그 기관이 만들지 않은 값이 섞임)·`TITLE_HAS_VALUE`(제목 틀에 값 참조 — D-200)·`TEMPLATE_UNTRACED`·`RENDER_ERROR`·`TITLE_LENGTH`·`DESCRIPTION_LENGTH`·`BAD_TODAY`·`QUALITY_CHECK_FAILED`·`NO_REGION_SERIES`(지역 없는 계열)·`INCONSISTENT_LABELS`(같은 계열인데 라벨이 다름)·`NO_VARIATION`(모든 지역의 값이 같음)·`DISPLAY_INCONSISTENT`(보이는 값과 어긋나는 표현이 나오게 됨)·`PRECISION_LIMIT`(자료의 소수 자리가 표시 한도 넘음)·`VALUE_OUT_OF_RANGE`(값이나 계산 결과가 범위 밖)·`FUTURE_RECORD`(수집일이 오늘보다 뒤)·`PLAN_ERROR`·`INTERNAL_ERROR`(예상 밖 오류 — 글을 내보내지 않는 쪽으로 닫는다. 퍼징 시험이 0 임을 확인한다).

**분량 하한**: 국문 1,000자(공백·표시 기호 제외, 출처 목록 제외)는 생성기 방식으로 세되 표의 구분줄을 뺀 보수적 측정이다(생성기가 세는 수보다 같거나 작다). 하한을 맞추려고 근거 없는 문장을 채우지 않는다 — Recipe 별 최소 입력을 넘는 모든 입력이 하한을 넘고, 모자라면 `TOO_SHORT`.

**스스로 검사(`post_problems`)**: 표시 문자·중괄호·물결표·금지 표현·제목 길이·설명(한 문장·길이·첫 문단과 같음)·절 순서·표·분량·본문 숫자가 모두 근거 텍스트에 있음·틀에 참조 없는 숫자 없음·글자 체계(영문 낱말은 라벨·단위로 온 것만, 한자·가나 없음)·같은 문장 반복·조사 규칙. 걸리면 글 대신 `QUALITY_CHECK_FAILED` — 조용히 내보내지 않는다.

## 9. SRC(허용 목록)와의 인터페이스 약속

SRC 가 `pipeline/source_registry.py` 에서 `Registry.get(provider_id) -> Provider|None`(읽기 전용 필드 `provider_id`·`strict_tier`·`effective_status`·`access`(종류·호스트·경로)·`attribution_template`·`snapshot`·`policy`·`retention_days`)와 `Registry.active_providers()`·`is_url_allowed(url, purpose)` 를 만든다. 이 경로는 그 모양과 같은 **최소 프로토콜**(`facts.ProviderLike`·`RegistryLike`·`Opener`, `typing.Protocol`)을 `pipeline/facts.py` 안에 두어 어댑터·조립기가 '그 필드를 가진 아무 객체나' 받게 한다 — **SRC 의 모듈을 import 하지 않는다**(시험은 가짜 객체를 쓰고, 사전 모양의 Provider 도 받는다). 병합 뒤 연결은 2단계다.

**선택 필드**(없어도 글이 된다 — 프로토콜에는 올리지 않는다): `name`, `enabled`(있고 True 가 아니면 쓰지 않는다), `reader_notes`(독자에게 보일 수 있게 승인된 숫자 없는 한 줄 문장 목록, 기본 비어 있음). SRC 의 `exceptions` 는 약관 감사 메모(`확인 못 함…`·날짜·개수가 든다)라 독자용 문장이 아니므로 **읽지 않는다**.

독립 검증(V-08, SRC 머리 기준 읽기 전용)이 짚은 의미 불일치와 처리:

| 불일치 | 처리 |
|---|---|
| `exceptions` 가 독자용 문구가 아니라 감사 메모 — 구조화 접근 Provider 18곳 중 10곳이 숫자·수 표현 때문에 글이 안 됐다 | `exceptions` 를 읽지 않고 독자용 안내는 `reader_notes` 만(D-138) — 이 일에서 고쳤다 |
| `paths` 는 허용 접두어(비면 호스트 전체)인데 어댑터가 첫 경로를 그대로 요청 주소로 쓰고 빈 `paths` 는 `BAD_ACCESS` | 요청 경로 = `paths[0] + endpoint_suffix`(어댑터의 끝 경로)(D-139) — 이 일에서 고쳤다 |
| 활성 판정이 저장된 라벨·tier 만 본다(`enabled`·`Registry.is_active`·`snapshot.expires_at` 은 안 봄) | `enabled` 가 있고 True 가 아니면 거절(D-139). `Registry.is_active`·`snapshot.expires_at`·`is_url_allowed` 사전 확인은 2단계 연결 코드가 한다(이 경로가 SRC 모듈을 import 하지 않으므로) |
| 외부 호출 관문의 거부가 `OPENER_FAILED` 에 뭉개져 '허용 목록 밖'이라는 사유가 사라진다 | 연결 코드가 `opener` 안에서 `AdapterError("EGRESS_DENIED")` 를 올리고 `fetch` 가 그대로 올린다(D-139) |
| 지금 `active_providers()` 가 0곳이라 이 경로를 켤 Provider 가 없다 | 운영자 해석 1건 대기(§7) |

## 11. 이미지 문제와 2단계 연결 계획

### 이미지 문제(조사 결과 — 이 일에서 코드는 바꾸지 않았다)

지금 생성기는 Unsplash 사진 두 장을 못 얻으면 글을 저장하지 않는다(`generate_blog_posts` 의 `pick_images` 뒤 `len(images) < 2` 검사)와 사진의 작가 출처를 모르면 저장하지 않는다(`credit_line_for` 검사). 구조화 Fact 글은 외부 사진을 쓰지 않는다(운영자 방침: 자체 생성 표·차트·사용자가 고른 이미지, 없으면 이미지 없음). 머리말 `image` 가 없을 때 저장소가 어떻게 반응하는지 읽은 결과:

| 곳 | 반응 |
|---|---|
| `generator.front_matter_problems` | 필수 키에 `image` 가 있어 `image` 줄이 없으면 **오류**(글을 거절한다) |
| `tests/test_posts_front_matter.py` | `_posts` 의 **모든 글**의 `image` 가 `https` 주소(글자가 `https` 로 시작)여야 한다 — 없으면 PR 검사가 빨갛다 |
| `_layouts/post.html` | `page.image` 를 쓰지 않는다 — 글 쪽은 이미지 없이 정상 |
| `index.html` 서버가 미리 그린 카드 | `post.image` 가 없으면 이미지 없이 어두운 상자와 분류 표지만 보인다(깨지지 않음) |
| `index.html` 스크립트가 `posts.json` 으로 다시 그린 카드 | `post.image` 가 비면 **고정 Unsplash 사진 네 장 중 하나**(`getDefaultThumbnail`)를 제목 해시로 골라 보여 주고, 불러오기 실패 때도 첫 번째로 되돌린다 — 이미지 없는 글도 홈에서는 출처 표시 없는 Unsplash 사진이 뜬다 |
| `posts.json` | `image` 가 없으면 빈 글자(`""`) |
| `pipeline/drafts.py` | 승인 PR 이 올릴 수 있는 경로는 `_posts/…md` 뿐이다(`_POST_PATH_RE`) — 글마다 따로 이미지 파일을 올리려면 이 규칙과 `draft_flow` 를 바꿔야 한다(T2) |

**후보 해결**

1. **이미지 없음 허용 + 홈 카드 대체**: `index.html`(광고 표면, T3)의 기본 썸네일 네 장을 빼거나 바꿔야 하고, `front_matter_problems`(T2)와 `test_posts_front_matter`(기존 시험 완화)·사진 출처 검사를 모두 Fact 글에서만 풀어야 한다. 손댈 곳이 가장 많고 보호 영역(광고 표면)이 들어 있다.
2. **자체 이미지**: (a) 글마다 만드는 자체 SVG 차트(순수 함수 — 입력은 Fact 시계열, 출력은 결정적 SVG 글자) 또는 (b) 모든 Fact 글이 같이 쓰는 자체 디자인 카드 이미지 한 장(사진 아님·출처 표시 불필요). `image` 가 `https` 주소로 남아 위의 검사들이 모두 그대로 통과하고, 홈의 기본 Unsplash 사진도 뜨지 않는다.

**권고: 2번 — 먼저 (b), 이어서 (a)**. 근거: ① 보호 영역(`index.html`)과 기존 시험을 건드리지 않는다. ② 외부 사진을 쓰지 않아 운영자 방침과 맞고 사진 출처 검사는 '자체 이미지는 작가 출처가 없다'는 한 줄 예외로 풀린다. ③ (b)는 글마다 파일을 올리지 않아 승인 PR 의 경로 규칙을 바꿀 필요가 없다(정적 이미지 한 장을 한 번 저장소에 넣는 변경이고 `assets/` 는 광고 표면이 아니다). ④ (a)는 정보가 있는 이미지지만 SVG 는 소셜 미리보기(`og:image`)에 잘 안 쓰이고, 글마다 파일을 올리려면 `drafts.py`·`draft_flow.py`·`ARCHITECTURE` §4-4 와 G-L3 을 같이 고쳐야 해서 2단계 뒤 별도 작업이 맞다. (a)의 설계: `chart_svg(points, title, unit_label) -> str` 순수 함수(표준 라이브러리만)·고정 크기·좌표를 정수로 반올림해 결정적·`<title>`·`<desc>` 로 접근성·값 라벨은 `facts.format_*` 만 쓰고·스크립트·외부 참조·`style` 없음 — 아직 만들지 않았다.

**보완(독립 검증 I-02)**: 홈 카드는 `image` 가 `https` 절대 주소여야 `test_posts_front_matter` 를 통과하므로 저장소 안의 공용 카드 이미지를 쓰려면 사이트의 절대 주소가 필요하다. 글 레이아웃(`_layouts/post.html`)은 `page.image` 를 쓰지 않아 '벡터 그림은 소셜 미리보기에 잘 안 쓰인다'는 위의 근거는 지금은 무관하다. 공용 이미지 한 장을 모든 Fact 글에 쓰면 글마다 같은 그림이 되어 반복감이 커지므로 (a) 글마다 자체 차트를 만드는 쪽이 장기적으로 낫다.

> S2b(2026-11-11)가 아래 1·2·5·6·8·9·10·12항을 이었고 7항은 일부(이력의 `dedupe_key` 로 건너뜀)를 이었다. 3·4항과 7항의 Gate 쪽은 S2BG 의 몫이고 11항(켜기 전 순서)은 §15-8 의 '켜기 전 T3 패치 목록' 으로 옮겼다. 항목별 위치는 §15-1 의 표.

1. **스위치**: 레지스트리 `chance.content_source`(`feed` 기본·`facts`). 켜는 것은 T3(게시 방식·소스 변경)다. `facts` 에서는 `fetch_news_items`·기사 발췌·구글 뉴스 해석기를 부르지 않는다(SRC 의 `source_policy: allowlist` 와 같은 자리).
2. **생성기 호출 한 군데**: `generate_blog_posts` 의 후보 만들기 자리에서 `content_source == "facts"` 이면 Gemini 호출·피드 후보 대신 `fact_assembler.assemble(...)` 의 `AssembledPost` 를 후보로 쓴다. 어댑터 `fetch`→`parse` 는 이 호출의 앞에서 한 번(수집 시각은 생성기가 읽어 인자로 넘김 — 이 모듈들은 시계를 읽지 않는다). `languages` 는 `["ko"]` 만 허용한다(영문은 이 경로가 만들지 않는다).
3. **Gate 의 두 함수만 Fact 기반으로**: `quality_gate.evidence_text(source)` 가 `AssembledPost.evidence_text` 를, `source_ref(source)` 가 `source_url`·`source_domain`·`source_name` 을 돌려준다(규칙 함수는 그 두 함수만 읽는다 — `EvidenceBoundaryTest` 가 지킨다). 근거 텍스트에는 값·단위·기준일·지역 이름만 있고 id·계산식 번호가 없으므로(D-131) QG1-NUMBER 는 본문 숫자가 모두 근거 텍스트에 있으면 통과한다. 본문에 끼워 넣은 숫자는 **32 이상의 정수는 모두 잡힌다**(정수 32–399 를 다섯 모양으로 끼운 시험에서 옛 근거는 21–40개가 통과했고 새 근거는 0개) — 그러나 Gate 는 **32 미만의 정수를 주장으로 읽지 않으므로** `5곳`·`17곳` 은 새 근거에서도 통과한다(옛 근거에서 그것들이 통과한 원인은 id 의 숫자가 아니라 이 하한이었다). 조립기의 값 집합 검사도 달 번호(1–12)·수집일의 일자와 겹치는 작은 정수(`5곳`)는 구별하지 못한다(`17곳` 은 거절). 진짜 방어선은 '틀의 모든 숫자는 참조 표시'라는 틀 단계 규칙(`untraced_numbers`)이고 그것은 온전하다(D-144 와 D-150 이 이 서술을 바로잡았다). **구현됨(S2BG)**: `quality_gate.py` 의 `_fact_source`·`evidence_text`·`source_ref` 가 올바른 Fact 사전(`fact_post` 가 정확히 True 이고 근거·주소·도메인·이름이 모두 글)일 때 근거 텍스트와 출처를 돌려준다 — 인터페이스와 위조된 반쪽 사전 처리는 [`QUALITY_GATE.md`](./QUALITY_GATE.md) §11-2·§11-3(D-260·D-261).
4. **Gate `QG5-COMPANY`(출처 도메인 허용 목록)**: Gate 는 출처 도메인이 공공·연구기관 목록(`PUBLIC_SOURCE_DOMAINS`)에 없으면 글을 보류한다. 골든 3편(가짜 도메인)은 물론 실제 후보 호스트 가운데 `kosis.kr` 도 목록 밖이라, 호스트가 목록에 없는 Provider 의 Fact 글은 **모두 보류된다**(같은 검증에서 `services.swpc.noaa.gov`·`www150.statcan.gc.ca`·`ec.europa.eu`·`ecos.bok.or.kr`·`apihub.kma.go.kr`·`open.law.go.kr` 와 공공데이터포털(`data.go.kr` 의 `www` 호스트)은 통과했다). 연결 방법: Fact 글에서 `source_ref(source)` 가 `source_domain`(= Provider 의 `access.hosts` 첫째 호스트 — SRC 허용 목록을 통과한 공식 호스트)을 돌려주고, Gate 의 도메인 판정이 Registry 가 허용한 `access.hosts` 를 같은 근거로 인정하게 한다 — 호스트를 SRC 허용 목록 한 곳에만 올리면 Gate 도 통과하도록. 켜기 전 순서(아래 11항)의 그림자 실행에서 `QG5-COMPANY` 통과를 확인한다. **구현됨(S2BG)**: `rule_company_fact` 가 공공 목록에 Provider 의 `provider_hosts`(레지스트리 `access.hosts` 전체)를 **정확히 같은 호스트일 때만** 더한다 — 하위 도메인·접미사 일치 없음, 이상한 항목은 무시, 자동화 제외 도메인이 이긴다([`QUALITY_GATE.md`](./QUALITY_GATE.md) §11-4, D-262). `provider_hosts` 는 레지스트리에서만 채운다(S2b).
5. **이미지**: 위 §11 권고에 따라 `chance.content_source: "facts"` 에서는 사진 선택·사진 사용 알림·작가 출처 검사를 건너뛰고 자체 이미지 주소를 머리말 `image` 로 쓴다(`front_matter_problems` 는 그대로 통과).
6. **이력 `topic`**: 외부 제목 대신 `AssembledPost.title`(자체 제목)을 쓴다. 공개 주석·실행 요약·탈락 사유에도 외부 제목이 없다(이 경로에는 외부 제목이 없다).
7. **중복 방지**: 지금의 제목 유사도(0.7)와 QG7-REUSE(같은 출처 주소 재사용 보류)는 **달마다 반복되는 통계 글을 중복으로 거부한다**(같은 Provider 의 같은 공식 페이지·같은 틀의 제목). Fact 글은 `AssembledPost.dedupe_key`(Recipe·키·지역·기준일)가 같은 글이 이미 있을 때만 중복으로 보고, 제목 유사도·출처 주소 재사용 검사는 `facts` 글에서 이 키로 바꾼다(이력에 `dedupe_key` 칸을 더한다). **Gate 쪽 구현됨(S2BG)**: Fact 글은 `rule_reuse_fact` 가 이력 항목의 `dedupe_key` 가 정확히 같을 때만 `QG7-REUSE` 로 보류하고(키 없는 옛 항목은 건너뜀, 키가 비었거나 글이 아니면 `QG0-DEDUPE-KEY`) 출처 주소 재사용 검사는 피드 글에만 남았다([`QUALITY_GATE.md`](./QUALITY_GATE.md) §11-5, D-263·D-264). 이력에 `dedupe_key` 칸을 쓰는 일과 제목 유사도 검사를 Fact 글에서 빼는 일은 S2b 의 몫이다.
8. **SHADOW_RUN 호환**: 이 문서는 처음에 '그림자 실행은 후보를 일반 실행과 같은 함수로 만든다'고 적었지만 **코드와 달랐다** — `pipeline/shadow_run.py` 의 `_evaluate` 는 자기 반복문으로 피드 후보를 모아 `build_post_prompt`·`call_gemini_with_fallback` 을 직접 부르고, 생성기를 가져오지 않고 인자 `g` 로 받아 임포트 그래프에 보이지 않는다(전수 확인 F6·F14, D-159). 그래서 Fact 후보는 그림자 실행에서도 `assemble` 로만 만들어야 하고(AI 호출 없음 — 조립기는 파일을 쓰지 않는다), 2단계는 후보를 만드는 함수를 `generate_blog_posts` 와 하나로 합치거나 `_evaluate` 앞에 같은 `content_source` 분기를 둔다. 어느 쪽이든 Fact 분기에서 닿는 곳에 AI 호출이 없어야 하고(AF4) 그림자 실행의 새 호출 지점은 호출 지점 등록(AF5)에 이유와 함께 올린다. 외부 호출이 없는 경로라 `SHADOW_RUN` 중에도 어댑터는 가짜 opener 나 허용 목록 안 호스트로만 돈다.
9. **머리말·파일**: 머리말(`layout`·`title`·`category`·`tags`·`lang`·`image`·`description`·출처 세 줄)은 생성기의 기존 함수가 `AssembledPost` 의 칸으로 쓴다. 시험(`tests/test_fact_assembler.py`)이 생성기 함수를 읽기 전용으로 불러 같은 규칙을 이미 통과함을 확인한다.
10. **승인 흐름**: 하루 최대 1편·`publish_flow: pr`·사람 승인은 LOCK·R2 가 만든 것을 그대로 쓴다. 이 경로는 자동 공개 경로를 만들지 않는다.
11. **켜기 전 순서**: Provider 의 7칸 증거(운영자 해석 1건) → 주제 허용 목록에 지표 낱말·단위·지역 올리기 → Registry 에 켜기 PR → 그림자 실행 ≥3회(QG5 통과 확인 포함)·초안 ≥10건 평가 → 2단계 PR(`content_source` 값 추가 — 기본 `feed`, 꺼진 상태에서 출력이 이전과 바이트까지 같음을 시험) → T3 승인 뒤 값 변경.
12. **AI 호출 없음(방어 묶음, 2026-11-10)**: **이 분기는 AI 를 부르지 않는다**: 분기에서 호출·참조로 닿는 곳에 AI 가능 함수가 없어야 하고(정적 규칙 AF4·AF8 — `tests/ai_flow_scan.py` 의 진입 함수 목록에 이 분기를 올린다), `facts` 실행에는 AI 키를 주지 않으며(워크플로 키 식 — AF7, 2단계), 영문은 국문 단독이고 AI 번역은 금지다(D-158). 이 글과 이력 항목에는 출처 표식(`provenance: facts`)을 붙여 AI 입력을 만드는 읽기(최근 제목·이미지 검색어·재작성 사유·이슈 수정)가 건너뛰게 한다([`AI_FLOW.md`](./AI_FLOW.md)).

### AI 흐름 방어 결정 (방어 묶음, 2026-11-10)

번호는 결정 표의 D-150–D-157(Fact 후속)과 이어지게 D-158 부터다. 결정 표의 번호 점검(빠짐없이 늘어나는지)과 부딪히지 않게 표 밖의 목록으로 적었다 — Fact 후속이 병합된 뒤 표의 마지막 행으로 옮겨도 된다.

- **D-158** 구조화 Fact 글은 **국문 단독**이고 AI 번역은 금지다. 글 제목에는 숫자·값을 넣지 않고(라벨·지역·기준일만), 사진 교체·보강 대상에서 제외한다(출처 표식으로 거른다). 이유(전수 확인 조건 ①): 영문판을 AI 번역으로 만들면 값 전부가 AI 로 가고, 제목에 값이 있으면 기존 코드가 `_posts` 제목을 AI 입력으로 보내는 네 자리가 곧 값이 새는 자리가 된다 — 방어 장치가 있어도 제목에 값을 넣지 않는 것이 첫 방어선이다([`AI_FLOW.md`](./AI_FLOW.md) §2).
- **D-159** 이 세 곳(`statcan`·`uk_govuk`·`noaa_swpc`) 자료에는 AI 서술·번역·요약·다듬기·이미지 설명 단계를 만들지 않는다. Fact 분기는 호출·참조로 닿는 곳에 AI 호출이 없고(AF4) `facts` 실행에는 AI 키를 주지 않는다(AF7, 2단계). 이 문서 §11 의 8항(그림자 실행)과 §13 을 이 한 가지 말로 고쳤다. 이유(전수 확인 F7·F9·F14): 허용 목록 문서의 '자체 제목은 프롬프트로', 이 문서의 '그림자 실행은 같은 함수', 완성형 'AI 서술(선택)' 이 서로 달랐다.

- **주제 허용 목록은 8개 범주의 기본 낱말뿐**이다 — 실제 어댑터를 켤 때 지표·라벨·단위·지역 이름을 올리고 시험해야 하고 시군구·외국 지역·세부 지표는 아직 없다.
- **허용 목록은 낱말 단위 완전 일치**라 공식 지표명을 그대로(`소비자물가지수`·`수출액`·`산업생산지수`) 쓰면 `UNKNOWN_TOPIC` 이다 — 낱말을 띄어 쓰거나(`소비자 물가 지수`) 표에 올려야 글이 된다(재검증이 현실 이름 30개 중 8개가 거절됨을 보였다). 지역 코드는 있고 지역 라벨이 없는 Fact 는 `RENDER_ERROR` 로 끝나 사유 코드가 불투명하다. `위`(순위) 단위는 어느 범주의 단위 목록에도 없어 순위 자료로는 글이 되지 않는다(순위는 이 경로가 계산해 만든다). 자료에 소수 5자리 이상 값이 하나만 있어도 글이 없다(`PRECISION_LIMIT`, §4).
- **우리말 수 표현 검사는 어휘 목록과 구조 규칙**이다(D-154): 흔한 낱말을 수로 잡던 오탐은 크게 줄었고(조건·이번·사건·세대·열대·만원·프로그램·조사원 등을 시험이 목록으로 고정한다) 두어 곳·서넛·이삼 일·오륙 개·영하 같은 표현도 잡지만 규칙이 단순해 몇 가지가 남는다. **오탐**: '어떤'의 뜻으로 쓴 `한 곳`·`하나`, 세는 말 바로 뒤에 조사로 시작하는 낱말이 붙은 꼴(`한 대가`·`한 대도시`·`한 개나리`), `하나로마트` 같은 이름. **미탐**: 한 글자 수 + 붙여 쓴 모호한 세는 말(`한주`·`한해`·`삼건`·`일년`·`천원` — 띄어 쓰면 잡힌다)·세는 말 목록 밖 낱말(`두 사람`은 잡지만 `두 개발자`·`두 권`은 아님)·지시어와 겹치는 꼴(`이 퍼센트`·`이분기`)·로마 숫자(`III`)·막연한 양('여러'·'다수'·'소수'). **서술격 어미 꼴(N2, S2a)**: 세는 말 바로 뒤의 `이다` 꼴도 센다 — 받침 있는 세는 말 뒤는 `이다`·`입니다`·`였다`·`일 때`·`인데`(`세 곳이다`·`열두 곳일 때`·`세 곳인데`), 받침 없는 세는 말(가지·개·해·배·마리·군데·나라·자리·대·호·주·위·차례·단계·분기·가구·학교·퍼센트·포인트·프로·달러·세·이하·초과·초) 뒤는 `이` 가 줄어 `다·면·며·죠·든·예요·요·고·지·야` 가 바로 붙은 꼴(`두 가지다`·`한 해다`·`세 가지면`·`두 가지예요`)을 센다 — 줄어든 꼴은 받침 없는 세는 말 뒤에서만 세므로 `한 번지`·`한 살다`·`한 분야` 는 수가 아니다. '세는 말 + 어미' 가 흔한 낱말인 짝은 뺐다: `한 개인`·`한 주인`·`한 살인 사건`·`한 달인`·`한 위인`·`그 일 원인은`(`인` 은 `인데`·`인지`·`인가`·`인걸`·`인즉` 일 때만 센다), `한 해고`·`한 배고픈`(`고`), `한 해지`·`한 대지`·`한 주지`·`한 배지`(`지`), `한 해야`·`한 대야`·`한 주야`(`야`), `한 개요`·`한 주요`·`한 해요`(`요`). 그 대가로 같은 짝에 쓴 진짜 수(`두 주요 지표`·`세 대지`·`두 개요`·`세 개인 경우`)는 놓친다 — 기준선(F2 이전)은 잡았으나 일반 낱말을 크게 오탐했던 곳이다. 남는 오탐: `열 가지고 있는 병`('열'이 발열)·`한 대면 조사`·`한 개고기`·`일 년도 말`(`도` 때문에 F2 이전부터). **구간·줄·열·날(S2AFIX D12)**: 세는 말 목록에 더했다 — `네 구간인데`·`두 줄이다`·`두 열은`·`세 날이다` 도 센다(검증자의 자연 문장 70개 중 잡은 수: F2 50·S2a 첫 검증 66·지금 70, 흔한 말 92개의 오탐은 7 그대로이고 새 오탐 0). 띄어 쓴 꼴만 센다. `한 날` 은 하다 의 관형형('게시를 한 날')이라 수가 아니어서 뺐고(`열한 날`·`스물한 날` 은 센다) `한 줄`·`열 줄` 처럼 개수일 때는 센다 — 문서 말뭉치에서 새로 걸린 낱말은 모두 진짜 센 말이다. 새 틀은 사람이 한 번 읽어 확인한다.
- **자유 글 칸의 엄격한 차단 낱말 검사는 오탐이 있다**(D-155): 낱말 경계를 가로질러 우연히 생긴 글자도 잡으므로 공식 데이터 이름이나 안내 문장에 `최고 소비` 같은 말이 있으면(`고소`) 글이 막힌다 — 그런 이름·문장은 사람이 고쳐 써야 한다. 이 엄격한 검사는 그 두 칸에만 쓴다.
- **평균이 반 칸에 걸리는 지역 비교는 표시 자리가 하나 늘어**(D-152) 값이 `3.40%` 처럼 보인다 — 자료보다 한 자리 더 보이지만 값은 정확하다. 중앙값(짝수 곳이면 가운데 두 값의 평균)과 평균·중앙값의 차이도 같은 규칙을 따른다(N3, S2a — 값 3.3·3.3·3.4·3.6 은 `평균 3.40%`·`중앙값 3.35%`·차이 `0.05%p` 로 보인다). 지역 없는 시계열(R04)의 창 평균과 평균과의 차이에도 같은 규칙을 건다(정수 자료의 30일 평균이 100.5 이면 `100.5개` 로 보인다). 그 밖의 반올림 어긋남은 남는다: 평균이 반 칸에 걸리지 않아도 보이는 두 값의 뺄셈과 보이는 차이가 끝 자리에서 다를 수 있다 — 주의 문장('보이는 값끼리 다시 계산하면 끝자리가 다를 수 있습니다')이 알린다.
- 조사 회피는 틀 규칙이다 — 새 틀을 쓸 때 시험이 거절하지만, 자연스러운 한국어를 위해 어쩔 수 없이 '라벨 + 고정 낱말' 꼴로 돌려 쓴 곳이 있다.
- 이미지·머리말·이력·중복 방지는 S2b 가 이었다(§15). Gate 규칙의 Fact 글 판정(출처 도메인·출처 주소 재사용)은 S2BG 의 몫이고 켜는 것은 모두 따로 승인이다.
- 영문 글(`label_en`)은 값만 실어 두고 이 경로는 쓰지 않는다 — 구조화 Fact 글은 **국문 단독**이고 AI 번역은 금지다(D-158). **이 세 곳(캐나다 통계청 `statcan`·영국 정부 콘텐츠 API `uk_govuk`·미국 NOAA 우주날씨 `noaa_swpc`) 자료에는 AI 서술·번역·요약·다듬기·이미지 설명 단계를 만들지 않는다**(D-159). 완성형 단계의 'AI 서술(선택)'은 이 세 곳에 적용하지 않고, 다른 제공처에 쓰려면 별도 승인과 출력 검증이 먼저다.
- **낮은 심각도로 남긴 것**: 같은 계열에 여러 수집 기록이 섞이면 글은 가장 늦은 수집일 하나를 '받아 옮긴 날'로 쓴다(L-02) · 계산 층이 키가 다른 두 `%` 의 비중(F05)을 막지 않는다(부분과 전체는 정의가 다를 수 있어 의도) · `AdapterError` 의 `__context__` 에 원 예외가 남는다(로거가 `__suppress_context__` 를 지키는 한 노출 없음, L-08) · 이중 반올림의 5e-13 경계(L-09) · 한국어 어색함('높은'을 명·원 단위에도 씀, 연 자료의 '바로 앞 기간'과 '전년 같은 기간'이 같은 줄 두 번 — L-07).
- **F2 독립 검증의 정보 항목(N5–N9)은 고치지 않고 적어 둔다**: 공식 데이터 이름의 합성어 쪼개기 검사는 숫자·영문을 끼워 넣은 이름(`국민환1자 통계`)을 통과시킨다(사람이 승인한 칸이라 위험이 작다) · 수 표현 검사는 ASCII 공백 한 칸만 본다(`두  곳`·NBSP 는 통과해 이후 `TEMPLATE_UNTRACED` 로 막힌다) · 정수 자료에서 평균이 .5 이면 모든 값이 소수 한 자리로 보인다(값은 정확) · 결정·결함 번호 메모(D-157·D-180 의 SRC 번호)는 SRC 가지의 실제 번호와 다를 수 있다 · 시험 파일에 숨은 글자가 글자 그대로 들어 있다(저장소의 관례).

## 14. S2a — NOAA 우주날씨 어댑터·지역 없는 틀·제목 정책·출처 문구(2026-11-10, 생성기에 연결하지 않았다)

운영자 승인(확인 요청 008, 2026-11-10): 제한 재개 조건 10가지 — **우리 계산이 값을 더하는 글만**(구조화 Fact 와 규칙 기반 틀, AI 미사용)·국문 단독·**Fact 글 제목에 값 없음**(이름·지역·기준일만)·세 제공처의 자료는 AI 에 한 글자도 넘기지 않음·제공처 켜기는 따로. 첫 제공처는 NOAA 우주날씨(확인 요청 007, 규칙 기반 경로 전용). S2a 는 2단계 가운데 **생성기·워크플로·레지스트리 값·`blogs.json` 을 건드리지 않는 순수 부분**이다. 연결은 S2b 이고 방어 묶음(AG)·허용 목록(SRC2)이 병합된 뒤에 한다. 모든 새 모듈은 AI 클라이언트·생성기·`pipeline.llm` 을 import 하지 않고 네트워크·파일 쓰기·시계·난수를 부르지 않는다(구조 시험).

**배경 문장·Kp 증감 칸·R05 동률(S2AFIX D2·D5·D6·D9)**: ① 글마다 '이 값은 무엇인가·어떻게 읽나·무엇을 말해 주지 않나' 고정 문장이 둘에서 넷 있다 — 숫자 칸 맨 앞의 배경 문단(`KP_ABOUT`·`KP_STORM_ABOUT`·`SSN_ABOUT_DAILY`·`SSN_ABOUT_MONTHLY`·`FLARE_ABOUT`·`SCALE_ABOUT`)과 해석 끝의 한계 문장(`KP_LIMIT`·`SSN_LIMIT`·`FLARE_LIMIT`, R06 은 해석의 일반 문장이 그 몫). 우리 말로 쓴 고정 문장이고 숫자·수 낱말이 없으며 기준값은 참조 표시로만 쓴다. 정의는 조사 보고서 4절의 해석 줄(Kp 척도·G 등급·R·S 등급·플레어 시작·최대·종료)과 맞췄고, 보고서에 없는 일반 상식은 둘이다 — 흑점이 태양 표면의 어두운 점이라는 설명과 플레어 등급 글자(A·B·C·M·X)의 순서 — 검증 때 확인할 항목이다. 고정 문장이 늘어 고정 글자 비율은 줄지 않았다(Kp 72에서 77%·흑점수 62에서 66·65%·R05 Kp 76에서 78%·플레어 83에서 85%·R06 81에서 82%) — 더한 것은 변하는 값이 아니라 읽는 법이다. ② 흑점수 두 글은 표 소개 문장에 제목어 `추이` 가 들어가 Gate QG6 의 약속어 검사를 지난다(`tests/test_space_gate.py` 가 현재 Gate 에 모든 틀의 글을 넣어 본다). ③ **Kp 표에는 증감 칸·줄이 없다** — Kp 는 3분의 1 단위 값을 제공처가 소수 둘째 자리로 줄여 적어 두 값의 차이가 한 끝자리 어긋난다(5.33 에서 2.67 이 −2.66, 실제 −2.67). 3분의 1 격자로 다시 계산하면 표에 보이는 두 값의 차이와 맞지 않아 '보이는 값끼리 맞는다'는 규칙(D-152)을 깨므로 칸을 뺐고 바로 앞 날의 값과 높낮이 말만 쓴다(`F01` 은 흑점수 글이 쓴다). 평균·범위는 적힌 값으로 계산하고 주의 줄이 그렇다고 밝힌다. ④ R05 Kp 글은 하루 최대값이 모두 같으면 가장 높은·낮은 날을 가르지 않고, 최저가 여러 날이면 '같은 값 N번, 가장 나중'으로 쓴다(R04 의 `flat_table`·`n_lo` 와 같은 규칙). ⑤ **공통 안내 두 곳**(첫 문단 뒤 자료 안내와 주의 줄 '계산한 값')은 지역 없는 틀(R04–R06)에서 이 글이 실제로 쓴 계산식의 낱말만 말한다(`Recipe.calc_from_formulas`·`CALC_WORDS`, S2AFIX2 N5) — 이전에는 모든 글이 '증감·변화율·평균·순위' 를 나열해 증감·변화율·순위를 계산하지 않는 Kp 글이 같은 글의 주의 줄('날짜 사이의 증감은 계산하지 않았고')과 어긋났다. 낱말 목록은 글의 `formulas` 에서 표시 순서대로 만들고(Kp R04 는 하루 최대값·평균·평균과의 차이·최고값·최저값·개수), 모르는 계산식이 섞이면 옛 고정 문장으로 돌아간다. 기존 틀 R01–R03 은 고정 문장 그대로라 출력이 바뀌지 않는다.

### 14-4. 출처 문구 자동 첨부(R14)

`fact_assembler.attribution_line(template, title=, date=, url=)` 는 레지스트리의 `attribution_template` 을 **입력으로 받는** 순수 함수다 — `{title}`(공식 데이터 이름)·`{date}`(열람일)·`{url}` 만 바꾸고 모르는 자리 표시·표시 괄호·물결표가 남으면 `None`(글을 만들지 않는다: `ATTRIBUTION_TEMPLATE_INVALID`), 비었으면 빈 문자열이다. 조립기는 그 한 줄을 `## 출처` 끝에 `- 이용 조건: ` 로 붙인다. 달라진 점(D-206): ① **출처 표시 칸(`policy.attribution`)이 명시적으로 `ALLOWED`(표시 의무 없음)가 아니면 템플릿이 비었을 때 글을 만들지 않는다**(`ATTRIBUTION_REQUIRED` — 조건부·모름(`UNKNOWN`)·거절·칸 없음·정책을 읽을 수 없음 모두 막는다. 모르면 막는다(S2AFIX D8). 이전에는 비어도 글이 나갔다) ② **공공영역·연방정부 저작물 주장이 든 문구는 쓴 Fact 가 모두 문구에 이름이 든 기관이 만든 값일 때만** 붙는다 — 꼬리표 `producer` 가 없거나 문구에 그 이름이 없으면(제3자 필드를 읽은 Fact) `ATTRIBUTION_SCOPE_MISMATCH`, Provider 가 제공처가 만든 값만 읽는다는 약속(`own_data_only`)이 명시적으로 참이 아니면(거짓·값 없음 포함) 거절한다. 공공영역 주장은 글자·숫자만 남겨(NFKC) 낱말 목록과 견주므로 하이픈·가운뎃점·전각으로 나눠 쓴 꼴과 '저작권이 없다'·'자유롭게 쓸 수 있다' 도 잡는다. 시험은 NOAA 조사 보고서의 B안 문구(저작권 보호 대상이 아니라는 고지 포함)를 입력으로 써서 한 줄이 정확히 붙음을 확인한다. 로고·이미지·NWS 명칭 상표는 글에 쓰지 않는다. **레지스트리의 문구 값을 채우는 일은 허용 목록(SRC2)의 몫**이라 여기서는 하지 않았다.

### 14-5. 중복 방지와 후보 순서(`pipeline/fact_candidates.py`)

`candidate_key(spec, today)` 는 `space_weather.kp_weekly:2026-W45` 꼴 — 글감 이름과 **글을 내는 날이 속한 기간**(ISO 주·달)으로 결정적이다. `plan_candidates(today, done_keys)` 는 오늘 대기 중이고 키가 이미 낸 것에 없는 글감을 순서대로 돌려주는 순수 함수이며(오늘은 인자, 시계 없음) 순서는 글감 순서를 ISO 주 번호만큼 돌려 정한다. 글감은 여섯: `kp_weekly`·`kp_storm_weekly`·`flares_weekly`·`scales_weekly`(주)·`sunspot_daily_monthly`·`sunspot_monthly_monthly`(달). 글 하나가 읽는 제품은 3개 이하다. 조립기의 `AssembledPost.dedupe_key` 는 그대로(`recipe|key|region|as_of`)이고 이력과의 연결은 S2b 다.

**같은 제품을 읽는 글감은 한 기간에 하나만**(S2AFIX D4, D-208): `kp_weekly`(R04)와 `kp_storm_weekly`(R05)는 둘 다 `kp_estimated` 를 읽어, 같은 주에 둘이 나가면 같은 7일 자료의 표가 같은 글 둘이 된다(검증: 표의 (날짜, 값) 이 모두 같고 숫자 72% 가 겹침). 같은 기간 종류에서 읽는 제품이 겹치는 글감은 한 묶음(`conflict_groups` — 제품이 이어지는 것끼리)이고, 한 기간에는 묶음마다 **대표 글감 하나**만 후보가 된다. 대표는 묶음 안에서 기간 번호(ISO 주 번호·달 번호)만큼 돌려 정해 두 글감이 주마다 번갈아 나온다(수정 전에는 한 해 모든 주에 Kp 후보가 둘, 후에는 하나). 묶음 안 어느 글감이든 같은 기간의 키가 `done_keys` 에 있으면(손으로 낸 글 포함) 묶음이 닫힌다. **이웃 기간의 겹침은 막지 못한다**: 키는 날짜가 아니라 기간 이름이라, 일요일(46주)에 낸 글과 이틀 뒤 화요일(47주)에 낼 글은 자료 창이 거의 겹쳐도 키로는 구별되지 않는다(`tests/test_space_candidates.py` 가 이 한계를 못박는다). S2b 가 이력에 글을 낸 날짜를 함께 남기고 같은 제품의 다음 글을 자료 창 길이(Kp 는 7일)만큼 띄우는 일을 맡는다.

### 14-7. S2b 에 넘기는 것

생성기 한 군데가 부를 함수: `noaa_swpc.NoaaSwpcAdapter(provider, product_id).fetch(access, {}, opener)` → 바이트 · `.parse(raw, access, retrieved_at)` → `(SourceRecord, [Fact])` · `noaa_swpc.product_source_name(product_id)`·`product_url(product_id)` → `SourceInfo` 의 이름·주소 · `fact_candidates.plan_candidates(today, done_keys)`·`get_recipe(recipe_id)` → 후보와 Recipe · `fact_assembler.assemble(recipe, facts, today, records=, source=, params=)` → `AssembledPost` 또는 `Insufficient`. 이 함수들은 AI 가능 함수를 호출·참조하지 않아야 한다(AF4 진입 함수 후보). 이력에는 `candidate_key` 를 남기고, `reader_notes` 에는 라벨·공식 데이터 이름에 없는 영문 낱말을 쓰지 않는다.

**S2b 가 연결하기 전에 정해야 하는 것 넷**(S2a 두 번째 독립 검증 N6 — 코드는 바꾸지 않았다. 근거는 검증자의 재현 도구 `gate_history`·`d4_sim`·`rc_probe_noanalysis`):

1. **같은 출처 주소 재사용 보류(Gate QG7)**: NOAA 글의 `source_url` 은 제품마다 고정이라(`product_url`) 지난주 같은 제품의 글이 이력에 있으면 새 글이 `QG7-REUSE` 로 보류된다(현재 main 의 Gate 에 골든 글 여섯 편을 넣어 6/6 보류를 다시 확인했다). Kp 두 글(R04·R05)은 같은 제품 주소를 써서 서로 막기도 한다. S2b 가 이력에 남기는 `source_url` 을 글 단위 값으로 정하거나 Fact 경로 글의 QG7 처리를 정해야 하고, Gate 규칙을 바꾸는 것은 별도 승인이다. → **Gate 쪽은 S2BG 가 구현했다**([`QUALITY_GATE.md`](./QUALITY_GATE.md) §11-5): Fact 글은 같은 출처 주소 대신 `dedupe_key` 같음으로 보므로 S2b 는 이력에 `dedupe_key` 를 남기면 된다(Gate 는 켜지 않았다).
2. **후보를 고르는 정책(부르는 요일·주 상한)**: 글감마다 대기 시작 요일이 달라(월·화·수·목) 먼저 대기하는 글감이 이긴다. 하루 한 번 `plan_candidates` 를 부르고 첫 후보를 낸다고 두면 2026년에 주 상한 1 에서는 `flares_weekly`·`scales_weekly` 가 한 번도, 주 상한 2 에서는 `scales_weekly` 가 한 번도 나오지 않는다(주 상한 3 에서 모두 나온다 — 옛 코드도 같은 현상이었다). 순서 회전이 있어도 부르는 날이 정해져 있지 않으면 굶는 글감이 생긴다.
3. **대표 글감이 실패하면 그 묶음은 그 주를 건너뛴다(폴백 없음)**: 대표가 `Insufficient` 여도 같은 묶음의 다른 글감은 후보에 없다. 평평한 Kp 에 빠진 날이 있는 경우(§14-8)와 겹치면 일어난다 — 대표가 R04 인 짝수 주에 R04 는 `NO_ANALYSIS` 인데 같은 자료로 R05 는 글이 만들어져, 그 주에는 Kp 글이 하나도 없다.
4. **53주 해와 홀수 주 월요일**: 53주 해(2009·2015·2020·2026·2032·2037)에는 W53 과 이듬해 W01 이 모두 홀수라 같은 대표(`kp_storm_weekly`)가 두 주 연속이다(1,619주 중 6번 — '번갈아' 가 한 해 한 번 깨진다). 그리고 홀수 주 월요일에는 Kp 후보가 없다(대표 `kp_storm_weekly` 의 대기 시작이 화요일 — 시험이 못박는다).

## 15. S2b — 생성기·레지스트리·그림자 실행에 이은 구조화 Fact 분기(2026-11-11, 켜지는 값은 하나도 없다)

S2a 의 순수 부품(§14)을 생성기·레지스트리·그림자 실행에 이었다. 레지스트리 `chance.content_source`(`feed` 기본·`facts`)가 스위치이고, 값이 `facts` 일 때만 생성기가 별도 함수 `generate_fact_post` 로 가서 후보를 만든다 — 피드·기사 발췌·구글 뉴스 해석기·Gemini·프롬프트·사진 선택을 한 번도 부르지 않는다. **켜지는 값은 하나도 없다**: `pipeline/blogs.json` 에 `content_source` 값이 없고(기본 `feed`) 허용 목록의 제공처는 모두 꺼져 있으며(2026-11-11 기준 62곳 가운데 켜진 곳 0) `.github/` 워크플로·광고 표면·`_config.yml` 은 바뀌지 않았다. 꺼진 상태(`content_source` 없음·`feed`)에서 생성기·그림자 실행의 출력은 이전과 바이트까지 같다(§15-9). 등급 T2(`pipeline/`·`generator.py`) — 켜는 값 변경·워크플로(AF7)·제공처 켜기는 T3 이고 §15-8 에 목록을 적었다. 결정은 §12 의 D-230–D-246, 결함 레지스터는 D-250–D-256, 방어 쪽 설명은 [`AI_FLOW.md`](./AI_FLOW.md) §12-3 이다. 병합 뒤 독립 검증이 짚은 것(낮음 넷·정보 다섯)은 후속 묶음 **S2BFIX** 가 고쳤다 — 결정 D-290–D-299·D-308·D-309, 결함 레지스터 D-300–D-307(코드·시험·문서만, 켜지는 값은 여전히 하나도 없다). 아래 §15-4·§15-5·§15-8·§15-10 이 그 결과를 적는다.

### 15-2. 스위치와 시작 안전장치(D-230·D-232)

**스위치**: 레지스트리 Chance 항목의 `content_source`. 값은 `feed`(기본 — 적지 않아도 같다)·`facts` 둘뿐이고 읽는 곳은 `source_policy.content_source_of` 한 함수다(`chance_content_source` 가 레지스트리를 읽어 부르고, 값이 이상하면 `RegistryError` 로 멈춘다 — 조용히 `feed` 로 떨어지지 않는다). 검증은 `registry_errors` 안의 `content_source_errors` 가 한다: 모르는 값과 `jekyll-git` 이 아닌 항목은 거절하고 `facts` 는 `source_policy: allowlist`·`languages: ["ko"]`·`publish_flow: pr` 셋이 모두 맞을 때만 받는다. 생성기는 `generate_blog_posts` 안에서 값을 한 번 읽어 `facts` 면 `generate_fact_post` 로 가고(주제 입력·승인 흐름 인자를 그대로 넘긴다) 아니면 이전과 같은 코드로 내려간다. 워크플로가 같은 값을 읽을 수 있게 명령줄 `python -m pipeline.source_policy content-source` 가 값을 한 줄로 낸다 — 읽지 못하면 출력 없이 종료 1 이다(AF7 패치 초안의 읽기 단계, §15-8).

**시작 안전장치**: `facts` 분기는 시작할 때 아래 여섯이 모두 맞아야 한다(`generator.fact_context` → 순수 판정 `source_policy.fact_start_problems`·파일 읽기 `fact_start`). 하나라도 아니면 요청을 한 번도 보내지 않고 이유를 한 줄로 남긴 뒤 결과 코드 `FACT_NOT_READY` 로 정상 종료한다 — 예외 없음·파일·이력 변경 0·피드 경로로 되돌아가지 않음. 이유 문장은 고정 문구와 제공처 식별자뿐이다.

| 조건 | 못 채우면 |
|---|---|
| 1 `content_source` 가 `facts` | 이 분기를 시작하지 않는다(일반 실행은 애초에 이 분기로 오지 않는다) |
| 2 `source_policy` 가 `allowlist` | 허용 목록 모드가 아니라는 이유 |
| 3 레지스트리 검증 오류 0 | 오류 건수와 `python -m pipeline.registry` 로 확인하라는 안내 |
| 4 제공처 `noaa_swpc_json` 이 허용 목록에서 ACTIVE | `enabled`·`strict_tier`·상태·기한·접근 경로·호출 한도 가운데 못 채운 것(허용 목록 파일을 읽지 못하거나 제공처가 없으면 그 이유) |
| 5 자체 카드 이미지 파일 | `assets/fact-card.svg` 가 없다는 이유 |
| 6 사이트 주소를 읽을 수 있음 | `_config.yml` 의 `url`·`baseurl` 을 읽을 수 없거나 모양이 올바르지 않다는 이유 |

지금 저장소의 값(제공처 모두 꺼짐)에서는 레지스트리의 스위치를 `facts` 로 잘못 바꿔도 조건 4 가 막아 새 글이 나올 수 없다. 수동 실행의 주제 입력은 받지 않는다(D-245). 시작 점검을 통과한 뒤에도 승인 흐름이 아니면(D-293 — 요청 앞에서) 또는 이력 파일을 읽을 수 없으면(D-292 — 요청을 보내기 전에) 같은 방식(`FACT_NOT_READY`·이유 한 줄·파일·이력 변경 0·요청 0)으로 멈춘다.

### 15-3. 후보 공급과 선택(D-231·D-237·D-238)

**공급 함수 `fact_supply.supply`**(순수 오케스트레이터 — 시계·파일·SRC 모듈 없음): 입력은 오늘 날짜·수집 시각(생성기가 읽어 넘긴다)·이력·제공처 객체·주입된 opener·`accept` 검사·`limit`(기본 1)이고 출력은 `SupplyResult`(`posts`·`candidates`·`skipped`·`waiting`·`considered`)다. 흐름: ① 이력에서 지난 Fact 글을 읽어 오늘 낼 수 있는 글감을 먼저 낼 차례 순서로 받는다 ② 차례대로 글감이 읽는 제품마다 어댑터 `fetch`→`parse` 를 한 실행에 한 번씩만 한다(성공·실패를 모두 기억) → 조립기 `assemble` ③ 어댑터 오류·`Insufficient`·중복·`accept` 거절은 그 글감만 `skipped` 에 적고 다음 글감으로 넘어간다 ④ 한 편이 나오면 멈추고 같은 묶음의 나머지는 시도하지 않는다 ⑤ 차례인 글감이 시각 때문에 읽을 수 없으면 기다린다(`waiting`).

| 건너뜀 사유(`skipped` 의 둘째 칸 — 고정 글자뿐) | 뜻 |
|---|---|
| `ADAPTER:<코드>` | 어댑터 오류 — `EGRESS_DENIED`(허용 목록 관문이 막음)·`BUDGET_DENIED`(호출 예산이 막음)·`BAD_SHAPE`(응답 모양)·`BAD_ACCESS`(접근 경로 없음)·`UNEXPECTED_ERROR` 등 |
| `INSUFFICIENT:<코드>` | 조립기가 글을 만들지 않음(`NO_ANALYSIS`·`TOO_FEW_POINTS`·`STALE` 등, §8) |
| `DUPLICATE:DEDUPE_KEY` | 같은 `dedupe_key` 가 이력에 있음 |
| `REJECTED:<코드>` | `accept` 가 거절 — `FRONT_MATTER`(최종 머리말 검사)·`MARKER_ERROR`·`GATE:<보류 코드>` |
| `BAD_INPUT:TODAY`·`BAD_INPUT:RETRIEVED_AT` | 오늘·수집 시각 인자가 이상함(글 대신 사유를 돌려주고 예외는 없다) |

**선택 정책 `select_candidates`**(순수 — 오늘과 협정 세계시 분은 인자): 글감은 여섯(`kp_weekly`·`kp_storm_weekly`·`flares_weekly`·`scales_weekly`·`sunspot_daily_monthly`·`sunspot_monthly_monthly`)이고 같은 제품을 읽는 글감은 묶음이다(Kp 두 글감이 한 묶음 — 묶음은 다섯). 오늘 후보가 되는 글감은 ① 이번 기간에 같은 묶음에서 아직 내지 않았고 ② 자료가 준비됐고(월 글감은 달의 `due` 일부터, 주 글감은 그 주 어느 요일에나) ③ 같은 제품을 읽은 지난 글과 자료 창만큼 떨어진 것이다. 순서는 이력에서 **가장 오래 전에 낸 글감이 먼저**(한 번도 안 낸 글감이 맨 앞, 같으면 글감 순서)이고 같은 묶음의 글감은 묶음에서 가장 앞선 글감의 자리에 이어 붙는다 — 대표가 실패하면 같은 묶음의 다음 글감이 같은 응답으로 이어서 시도된다. 자료 창은 제품별 `WINDOW_DAYS` 다.

| 제품 | 같은 제품을 읽은 두 글 사이 최소 간격 | 읽는 시각 하한(협정 세계시) |
|---|---|---|
| `kp_estimated`·`xray_flares`·`scales` | 7일 | 없음 |
| `ssn_daily` | 28일 | 0시 30분 이후 — 이전이면 `waiting` |
| `ssn_monthly` | 28일 | 없음 |

### 15-4. 연결 코드 — 허용 목록 관문과 호출 예산(D-233)

`generator.fact_opener(sources, provider, access, transport)` 가 어댑터에 주입하는 opener 와 호출 예산을 만든다. 실제 호출 한 번을 하는 transport(`make_fact_transport` — 검사된 opener·리다이렉트 0번·gzip 요청·풀린 크기를 상한까지만 푼다, 시험은 이 함수를 가짜로 바꾼다)를 ① 허용 목록 관문 ② 호출 예산으로 차례로 감싼다. 응답은 64KiB 이하의 조각으로 읽고 요청을 시작한 때부터 60초(`FACT_READ_DEADLINE_SECONDS`)를 넘기면 `TimeoutError` 로 닫는다(D-290). 관문·예산이 막으면 요청은 나가지 않고 어댑터 오류로 바뀌어 그 글감만 건너뛴다(다른 글감은 계속).

| 상황 | 어댑터 오류 | 이후 |
|---|---|---|
| 허용 밖 호스트·허용 밖 경로·허용 밖 목적, 제공처가 ACTIVE 아님 | `EGRESS_DENIED` | 요청 0, 호출 수에 세지 않음 |
| 한 실행의 호출 상한 소진(`RUN_CAP`)·같은 주소 재시도 상한(`RETRY_CAP`) | `BUDGET_DENIED`(코드가 따라온다) | 이 실행에서 더 부르지 않음 |
| 403·429 | 그 호출은 `OPENER_FAILED`, 이후 호출은 `BUDGET_DENIED`(`STOPPED_BY_STATUS`) | 이 실행의 나머지 호출 0(차단 가능성 — 문의는 사람이 정한다) |
| 404 | 그 호출은 `OPENER_FAILED`, 같은 주소를 다시 부르면 `BUDGET_DENIED`(`STOPPED_URL`) | 그 주소만 중지, 다른 제품은 계속 |
| 실패 3회 | 실패한 호출은 `OPENER_FAILED`, 세 번째 실패 뒤 호출은 `BUDGET_DENIED`(`SKIPPED_AFTER_FAILURES`) | 이 실행의 나머지 호출 0 |
| 응답 모양이 다름·너무 큼 | 어댑터가 닫음(`BAD_SHAPE`·`TOO_LARGE` 등) | 그 제품은 건너뜀, 글 없음(거짓 글 없음) |
| 응답을 60초 안에 다 받지 못함(천천히 흘리는 응답) | `OPENER_FAILED`(호출 예산은 실패로 센다) | 그 제품은 건너뜀, 실패가 3번이면 이 실행의 나머지 호출 0 |
| 같은 주소의 성공 응답 | — | 이 실행 안에서 재사용(호출 0) |

한 실행의 호출 상한은 레지스트리 호출 한도에서 계산한다(`egress.budget_for`) — NOAA 는 공식 수치 한도가 없어 자체 상한(제품 3개 × 제품당 1회 × (1 + 재시도 1회), 하루 8회)에서 6 이고(2026-11-11 의 허용 목록 값 기준) 한도를 모르는 제공처는 0 이라 호출이 하나도 나가지 않는다. 어댑터에는 재시도 루프가 없고 공급 함수는 한 제품을 한 실행에 한 번만 부른다(D-237).

### 15-5. 글·표식·이력·이미지(D-235·D-236·D-243·D-245)

- **파일**: `generator.fact_file_text` 가 머리말(`layout`·`title`·`category`·`tags`·`lang`·`image`)을 생성기의 기존 함수로 쓰고 조립기의 본문과 설명·출처 세 줄을 붙인다. 파일 이름은 `날짜-KR-시각.md`, 폴더는 분류별 국문 폴더(기존 규칙 그대로)이고 **같은 이름의 파일이 있으면 덮어쓰지 않고** `FILE_EXISTS` 로 건너뛴다(`FACT_ALL_SKIPPED`). 영문 짝 글은 없다.
- **표식**: `fact_check_post` 가 글에 `with_marker` 를 한 번 쓰고 `fact_history_entry` 가 이력에 `entry_with_marker` 를 한 번 쓴다. Gate 에는 표식 전의 글을 넘긴다(머리말 한 줄이 본문 규칙에 쓰이지 않게).
- **이력 항목**: `date`·`topic`·`kr_title`(자체 제목)·`kr_image`·`slot`·`source`·`source_url`·`languages`·`candidate_key`·`dedupe_key`·`recipe_id`·`as_of`·`content_source` 와 표식. 승인 흐름에서는 `drafts.entry_fields` 의 `flow`·`branch`·`paths` 가 더해진다. 이력은 글과 같은 커밋이 아니라 생성 시점에 main 에 따로 올라가므로(`drafts` 설계) 승인 PR 을 닫아 폐기해도 그 글감은 '낸 것' 으로 센다.
- **이미지**: 모든 Fact 글이 `assets/fact-card.svg` 의 https 절대 주소를 `image` 로 쓴다(D-236). 사진 선택·사진 사용 알림·작가 출처 검사는 없다.
- **이력 읽기**: 진입에서 이력을 엄격히 읽는다(`read_history_strict` — 잠금 가드의 같은 이름 함수와 같은 규칙) — 파일이 없으면 빈 이력이고 깨졌거나 목록이 아니면 요청을 보내기 전에 `FACT_NOT_READY` 로 멈춰 이력·파일을 그대로 둔다(D-292). 읽을 수 있는 이력의 옛 항목은 하나도 잃지 않고 새 항목만 더한다.
- **승인 PR 본문**: 글 머리말과 이력 항목에 표식이 둘 다 있으면 `drafts.build_pr_body` 가 '계산으로 만든 초안(AI 미사용)' 으로 안내하고 AI 고지문 점검 줄을 뺀다 — 피드 글의 본문은 바이트까지 그대로다(D-294).
- **승인 흐름**: `draft_flow` 가 참이 아니면 이 함수는 글·이력을 쓰지 않고 `FACT_NOT_READY` 로 멈춘다(D-293). 결과 코드는 `DRAFT_CREATED`(공개는 PR 병합)뿐이고 연습 실행(`DRY_RUN`)이면 파일·이력을 쓰지 않는다. 하루 1편·주간 상한·열린 초안 상한·일시정지는 기존 잠금 가드가 이 분기 앞에서 맡는다(D-243).

### 15-6. Gate 인터페이스(D-234)

Fact 후보를 Gate 에 넘길 때 `source` 는 아래 아홉 키의 사전이다(`fact_supply.GATE_SOURCE_KEYS`·`gate_source`). Gate 쪽이 이 모양을 읽게 고치는 일은 S2BG 가 한다 — S2b 는 사전을 만들어 넘기기만 한다.

| 키 | 값의 출처 |
|---|---|
| `fact_post` | 정확히 `True` |
| `evidence_text` | `AssembledPost.evidence_text`(값·단위·기준일·지역 이름뿐 — id·계산식 번호 없음, D-131) |

| `dedupe_key`·`recipe_id`·`as_of` | `AssembledPost` |

### 15-7. 그림자 실행(D-239)

`shadow_run.run` 은 레지스트리 값이 `facts` 일 때만 읽기 전용 구간 안에서 `run_facts` 로 간다. 후보는 일반 실행과 같은 함수 `generator.fact_prepare`(공급 함수 → 어댑터 → 조립기)로 만들고 Gemini·피드·사진을 부르지 않으며 Gemini 키가 필요 없다. 후보마다 최소 품질 Gate 를 **항상** 돌려 `PASSED`·`HELD` 와 보류 코드를 결과 폴더(`SHADOW_OUT`, 저장소 밖 임시 폴더)에 일반 그림자 실행과 같은 모양으로 쓴다: 번호 폴더의 글 파일·`result.json`(`model` 은 `rule`, `lane` 은 `facts`)과 맨 위 `run.json`. 시작 안전장치를 못 채우면 후보 0건으로 정상 종료하고 이유를 `run.json` 의 `notes` 에 남긴다. 저장소 작업 폴더의 바이트는 그대로이고 쓰기·git 차단 방어 코드도 그대로 감시한다. 네트워크 읽기는 허용 목록 관문·호출 예산을 거친다(§15-4).

### 15-8. AI 호출 0 과 켜기 전 T3 패치 목록(D-240·D-241)

**AI 호출 0**: `generate_fact_post` 와 `run_facts` 는 AI 이름을 한 번도 쓰지 않는 별도 함수이고 정적 규칙 AF4·AF8 의 진입 함수로 올라 있다(위반 0). 시험은 SDK 가짜 호출 횟수·`GEMINI_CALLS` 가 0 이고 피드·기사 발췌·해석기·프롬프트·사진·검색어 함수를 부르면 실패하는 감시자가 한 번도 울리지 않음을 확인한다(생성기·그림자 실행 모두). 런타임 방벽(`ai_guard`)은 그대로이고 이 분기에서는 AI 입력이 만들어지지 않는다. Fact 구역은 이름 있는 안쪽 함수를 두지 않는다(사각지대 B16 — D-255).

**켜기 전 T3 패치 목록**(이 묶음에서는 하나도 적용하지 않았다):

**AF7 패치 초안**: 두 워크플로에 읽기 단계를 더한다 — `python -m pipeline.source_policy content-source` 의 한 줄 출력을 단계 출력으로 남기고, 읽지 못하면 단계가 실패해 생성기 전에 멈춘다. 키 식은 닫힌 쪽(허용 목록)이다: `기존 조건 && 읽기 단계 출력 == 'feed' && 비밀 || ''` 꼴로 새 조건은 기존 조건의 괄호 밖에 잇는다(괄호 안에 붙이면 `&&` 가 `||` 보다 먼저 묶여 `facts` 실행에도 키가 샌다). 출력이 비거나 `facts` 이면 키는 빈 글자다. 지금 두 워크플로는 `content_source` 를 모르고(그래서 `facts` 로 켜면 키가 실행 환경에 간다 — D-252) `tests/test_fact_branch_docs.py` 가 이 현재 상태와 패치 뒤 상태를 모두 시험한다: 패치 식을 이벤트 종류·`dry_run`·`real_ai`·출력 값(`feed`·`facts`·빈 값·모르는 값·출력 없음)·비밀 유무의 모든 조합으로 평가해 `feed` 가 아니면 키가 비는지와 `feed` 일 때 옛 식과 같은 값인지를 확인한다.

### 15-10. 한계와 남은 일(S2c)

- **실제 네트워크 호출은 한 번도 하지 않았다**: 시험은 가짜 transport 와 고정 표본(`tests/fixtures/noaa_swpc/`)만 썼다. 실제 응답의 모양·압축·응답 시간·개정은 그림자 실행에서 처음 확인된다(§15-8 의 권고 순서 ④). `make_fact_transport` 는 응답 객체 대역으로만 시험했다. 응답 읽기 마감(D-290)이 실제 소켓 위에서도 도는지는 시험이 아니라 저장소 밖 일회용 확인으로 한 번 봤다 — 루프백 서버가 본문을 0.3초에 1바이트씩 흘릴 때 마감 1.5초에 1.58초 만에 `TimeoutError` 로 닫혔고 마감 없이 `read` 한 번으로 읽던 옛 방식은 63초가 걸렸다(외부 접속 없음).
- **Gate 는 S2BG 가 병합되기 전에는 Fact 글을 모두 보류한다**(D-253). 그림자 실행의 결과는 그 전에는 평가에 쓸 수 없다.
- **승인 PR 본문**은 S2BFIX 가 고쳤다(D-254 → D-294): 표식이 글·이력 둘 다 있으면 '계산으로 만든 초안(AI 미사용)' 으로 안내한다.
- **사각지대 B16**(D-255): 정적 규칙은 값으로만 쓰인 안쪽 함수의 몸통을 읽지 않는다. Fact 구역은 람다·최상위 함수로 쓰고 시험이 지킨다.
- **이력의 한계**(D-256 → D-295): `write_history` 가 마지막 200개만 남기므로 그보다 오래된 Fact 글은 '낸 적 없음' 으로 읽혀 먼저 차례가 온다 — 글감마다 마지막 글은 늘 마지막 열 편 안팎에 있어 닿지 않고(주 1–2편이면 2년 이상, 시험이 200개로 자르며 2년을 시뮬레이션해 고른 글감·날짜가 하나도 달라지지 않음을 확인한다) 닿아도 그 글감이 가장 오래 전에 낸 것이었으므로 순서가 달라지지 않는다. 읽을 수 없는 `date` 는 그 제품을 이력 항목을 고칠 때까지 막는다(막는 쪽 — 잠금이 켜져 있으면 잠금 가드가 먼저 `HISTORY_DATE_UNREADABLE` 로 멈춘다). 미래 날짜는 창 길이(제품별 7일·28일)가 지날 때까지 그 제품을 막는다. 깨진 이력 파일 자체는 이제 Fact 경로가 읽는 즉시 멈춘다(D-292).
- **호출 합계·간격은 지키지 못한다**(D-298 — 처음 실제 호출을 연결한 묶음의 한계): 허용 목록의 NOAA 자체 상한(하루·월 호출 합계, 같은 파일 60초·다른 파일 5초 간격)을 연결 코드가 지키지 못한다. 연결 코드가 지키는 것은 한 실행의 호출 상한(`run_call_cap`)·같은 주소 응답 재사용·403·429·404·실패 3회 뒤 중지·gzip 요청·일별 제품 시각뿐이다. 독립 검증의 측정(가짜 transport, 실행당 NOAA 요청 수): 글이 정상으로 나오는 날 1회·오늘 낼 글감이 없는 날 0회·**후보를 모두 건너뛰는 날**(옛 Gate 보류·NOAA 장애·검사 탈락)은 실행당 3–5회(장애 때는 실패 3회 상한으로 3회). 글이 안 나온 실행은 다음 정기 실행(하루 최대 24–30번)에서 처음부터 다시 부르고 403·429 중지는 한 실행 안에서만이다. 같은 실행 안의 중복 호출은 이미 없다(한 제품 한 번 — D-237).
- **켜기 전 결정 항목(새로 더함)**: 글이 안 나온 날의 재호출을 줄일지 — 예: 실행 사이에 날짜별 호출 횟수를 기록한다(Actions 캐시 — `SOURCE_POLICY.md` §7 의 설계안). 상태를 쓰는 변경이라 이 묶음은 구현하지 않았다. 켜기 전에 그림자 실행을 도는 동안의 실제 호출 수를 보고 정한다.
- **홈 미리보기 이미지(검증 D6)**: 대표 글이 Fact 글인 동안 홈 첫 화면의 공유 미리보기 이미지가 글의 `image`(SVG 카드)가 되어 대부분의 소셜 미리보기가 비게 된다 — 홈 파일은 광고 표면이라 이 묶음이 건드리지 않았고 S2c(PNG 카드·글별 차트)와 함께 본다.
- **글 품질은 S2a 그대로다**: 틀·고정 문장 비율·같은 카드 이미지의 반복감·값이 달라지지 않는 설명 문단(§13·§14-8 의 품질 개선 후보 ①–⑤)은 이 묶음이 바꾸지 않았다 — 켜기 전에 운영자가 받아들일지 정한다. S2c 후보: 글마다 다른 차트(`chart_svg` — 승인 PR 의 경로 규칙을 같이 고쳐야 한다)·지난주 대비 같은 이력 기반 계산 문단(이력에 값을 남기면 AI 입력 방어와 겹치는 새 면이 생기므로 별도 설계)·'지표 설명' 페이지·여러 글을 묶는 주간 정리.
- **켜기 전 운영자 결정은 그대로다**(§14-8): 제목·태그·라벨의 기관명(NOAA) 사용 범위, 얇은 글 위험의 수용, 제공처 켜기와 값 변경 순서.
