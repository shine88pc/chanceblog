# 신규 글 최소 품질 Gate와 그림자 실행(SHADOW_RUN)

> 대상: Chance 엔진(`generator.py`)이 새로 만드는 글. 상위 규칙: [`CHARTER.md`](./CHARTER.md)(등급)·[`SECURITY_GUARDRAILS.md`](./SECURITY_GUARDRAILS.md)(보안). 구조: [`ARCHITECTURE.md`](./ARCHITECTURE.md) §4-1-1.
> 상태(2026-11-09): **코드는 있고 꺼져 있다.** 레지스트리 값(`pipeline/blogs.json`)은 바꾸지 않았다 — `quality_gate` 필드가 없으면 `off`와 같고, `languages`는 이미 있던 `["ko","en"]`이다.
> 켜는 것(`quality_gate: hold`, `languages: ["ko"]`)은 **T3(게시 기준·방식 변경)** 이라 운영자 채팅 승인이 필요하다.
> 같은 날 독립 검증이 지적한 17건(건강 C 미탐·출처 표지 뒤가 검사 밖·정규식 멈춤·인용 사각·숫자 종류·그림자 쓰기 길·병합 충돌 …)을 고쳤다. 고친 내용은 §10.
> 같은 날 두 번째 독립 재검증(판정: 조건부 통과 — 꺼진 채 병합 가능, 켜기 전에 건강 C 미탐 해소)이 남긴 높음 1건(건강 C 미탐이 구조적으로 남음)과 중간·낮음 정리를 다시 고쳤다(§10-2). **낱말 규칙으로 건강 C 의 '누락 0'을 보증할 수는 없다** — 한계와 켜기 전 사람 검토 절차는 §9-1.
> 2026-11-10 세 번째 독립 재검증(판정: 조건부 통과 — 꺼진 채 병합은 안전하고, 켜기 전에 새 D1·D2 를 고치거나 한계로 받아들이고 사람 검토를 채택할 것)이 남긴 중간 2건·낮음 7건·정보 3건을 낱말 하나씩이 아니라 구조로 고쳤다(§10-3). Gate 는 그 사이 M037 로 병합됐고 레지스트리 값은 그대로라 **여전히 꺼져 있다**.

## 1. 한눈에

| 무엇 | 어디 | 기본값 |
|------|------|--------|
| 최소 품질 Gate — 후보 글이 규칙 8가지에 걸리면 그 후보를 버리고 다음 후보로(전부 탈락하면 그 실행은 글 없이 경고로 끝남) | `pipeline/quality_gate.py`(순수 규칙) + `generator.py` 한 곳 | **꺼짐** |
| 글 언어 설정 — `["ko"]`이면 영문은 만들지도 검증하지도 게시하지도 않는다 | `pipeline/blogs.json` chance 항목의 `languages` | `["ko","en"]`(지금과 같음) |
| 그림자 실행 — 정지(`PIPELINE_PAUSE`)를 건드리지 않고 후보 글을 **읽기 전용**으로 만들어 평가 | `pipeline/shadow_run.py` + 환경 변수 `SHADOW_RUN` | 없음(변수가 없으면 이전과 같음) |

운영자가 정한 제한 재개 순서(2026-11-09): `PIPELINE_PAUSE` 유지 → **최소 품질 Gate 적용** → **그림자 모드 검증** → `publish_flow: pr` 검증 → 하루 최대 1편 PR → 사람 승인 후 공개. 자동 공개는 재개하지 않는다.

## 2. 설정값과 켜는 법

| 설정(레지스트리 chance 항목) | 값 | 뜻 |
|------------------------------|----|----|
| `quality_gate` | 없음 또는 `off` | Gate 를 부르지 않는다(이전과 출력이 같다) |
| | `hold` | 후보 글이 규칙에 걸리면 버리고 다음 후보로 간다 |
| `languages` | `["ko","en"]` | 국문·영문 한 쌍(지금 동작). `["en","ko"]` 도 같은 뜻이다(순서는 가리지 않는다) |
| | `["ko"]` | 국문 글 하나. 프롬프트에서 영어를 빼고, 영문 검증·이미지·파일·이력·승인 초안도 모두 뺀다 |

- 값 검증: 레지스트리 검증기(`python -m pipeline.registry`, REG-1)가 위 값 밖의 `quality_gate`·`languages`(`jekyll-git`)를 오류로 막는다. 실행기는 값을 읽지 못하거나 틀리면 **약한 설정으로 조용히 떨어지지 않고** 모델을 부르기 전에 멈춘다(`registry.chance_settings`).
- `languages` 값의 **단일 정의처**는 `quality_gate.normalize_languages` 한 함수다 — 레지스트리 검증기·`chance_settings`·Gate 설정이 모두 이 함수를 쓰고, 정규 튜플(`("ko","en")` 또는 `("ko",)`)을 돌려준다. 허용하는 집합은 제한 재개 잠금(LOCK)의 L6 규칙과 같다(`ko` 를 포함하고 ko·en 만 겹침 없이 든 목록).
- 되돌리는 법: 두 값을 지우거나 `off`·`["ko","en"]`으로 되돌리면 된다(코드를 되돌릴 필요 없음). 전체를 멈추는 길은 그대로 `PIPELINE_PAUSE`다.
- 국문 전용을 켜면 승인 PR 도 글 파일 하나짜리가 된다(`draft_flow`가 글 경로 1개 또는 2개를 받는다). 두 파일 초안의 PR 제목·본문은 옛 코드와 글자 하나 다르지 않다.

## 3. 규칙 8가지

모두 규칙 기반·오프라인·결정적이다(같은 입력이면 같은 결과). 입출력·시계·환경변수를 읽지 않는다. 보류 사유 하나하나에 코드가 붙고, 문장은 한 줄이며 모델이 쓴 글이 섞이면 소독한다(`::`·`##[` 무력화, 제어 문자 제거).

|------|-----------|-----------|
| **QG1-NUMBER** | 본문(출처 목록의 링크 글자·주소·머리말은 제외하고, 이미지 대체글·HTML 속성·마크다운 링크 제목 같은 숨은 글은 포함)의 숫자·퍼센트·금액·연도·날짜가 **모델에 준 근거 텍스트**에 없다. **같은 종류끼리만** 맞춘다: 퍼센트는 근거의 퍼센트, 금액은 근거의 같은 통화 금액, 연도는 근거의 연도, 그 밖의 수(건수·측정값)는 근거의 수 — 근거의 `45명`이 본문 `45%`를, 근거의 `2,000명`이 본문 `2000년`을 받쳐 주지 않는다. 표기를 맞춰 견준다: 쉼표·전각, `4,975만` = `49.75 million`, `3조 4천억`, 영어 숫자 낱말(`twenty-five percent`), 소수점 쉼표(`3,5%` = `3.5%`), `11월 4일` = `November 4`, 숫자 날짜 `11/05/2026`은 월/일과 일/월 두 해석 중 하나라도 근거에 있으면 받는다, 한국 날짜 = UTC 날짜 + 한국 날짜 | 작은 정수(31 이하)는 단위·퍼센트·통화가 붙은 것만 센다(목록 번호·몇 가지·날짜의 일). 연도처럼 생긴 정수(1900–2100)에 세는 말(`명`·`건`·`개`·`people`·`cases` …)이 붙으면 연도가 아니라 건수다. 영어 숫자 낱말은 값이 32 이상이거나 hundred·thousand·million 이 붙은 것만 센다. 영문자가 붙은 식별자(5G·H5N1·21st)는 숫자 주장이 아니다. 파생값(2%포인트)·반올림값(약 70%)은 근거에 없으면 보류다 |

### 3-1. 본문 쪼개기: 출처 목록과 꼬리

Gate 는 본문을 **진짜 본문(story)·출처 목록(block)·꼬리(tail)** 셋으로 쪼갠다(`quality_gate.split_story`). 분량(QG3-LENGTH)·링크(QG3-LINK)·구조(QG8)는 진짜 본문만 재고, 숫자·인용·건강·행사·제목 규칙은 **진짜 본문 + 출처 목록의 링크 밖 글 + 꼬리**를 읽는다(`scan_text_of`). 링크 제목의 숫자·기관 이름은 주장이 아니므로 링크 글자·주소·글머리는 뗀다.

- **출처 표지**: 제목 줄(`#`–`######`)·굵은 글씨 한 줄(`**출처**`)·`출처:` 줄·표지 이름만 있는 줄(앞에 `>`·`-`·`※`가 붙어도)이고 이름이 목록 이름(출처·참고 자료·Sources·References·원문 링크 …)일 때. '관련 자료'처럼 본문 소제목으로도 쓰는 말은 표지가 아니다.
- **자르는 조건**: 표지 뒤가 '링크 항목(또는 짧은 기관 이름 항목)들 + **짧은 꼬리**(읽기 글자 600자 이하)'일 때만 자른다. 글 중간에 `출처: 통계청` 같은 표 캡션이 있고 그 뒤에 서술이 길게 이어지면 그 표지는 출처 목록이 아니라 캡션이므로 **글 전체를 본문으로 본다**(이전에는 한 줄 표지 하나가 그 뒤 글 전체를 모든 규칙의 검사 밖으로 보냈다). 뒤에서부터 표지 후보를 스무 개까지 살피고, 가장 뒤의 유효한 표지가 이긴다.
- **라벨 없는 끝쪽 링크 목록**: 표지가 없어도 글 맨 끝에 링크 항목이 둘 이상 이어지면 출처 목록으로 본다(바로 위의 짧은 라벨 줄 포함).
- **꼬리**(대표 사진 줄·사진 출처 줄, 모델이 목록 뒤에 덧붙인 글 등)는 규칙이 읽는다 — 꼬리에 숨긴 숫자·인용·단정도 걸린다. Gate 가 보는 글은 모델이 쓴 글에 사진 줄이 붙은 것이다(설명·출처 세 줄·라이선스 표시·고지문은 글을 파일로 만들 때 더해지므로 아직 없다). 꼬리 상한 600자는 그 입력에 넉넉하다 — 공개된 완성본에서 잰 꼬리는 최대 590자이지만 거기에는 그렇게 나중에 더해진 줄이 들어 있다.

### 3-2. 건강 규칙(QG4)의 구조

운영자 판정(확인 요청 002, 2026-11-06)을 규칙으로 옮겼다: 증상에 **즉각·단정 효과**를 붙이거나(C), 질환에 단정을 붙이면 보류한다. 반면 **행동 순서**를 꾸미는 `즉시`·`바로`(`통증이 있을 때 즉시 쉬는 시간을 기록한다`)와 정보 제목(`영양제 바로 알기` 같은 A·B 문장)은 보류하지 않는 것이 원칙이다 — 그래서 한국어 CLAIM 은 부사와 효과 동사 사이의 **구조**(행동 서술어·다른 대상이 끼는가)로 행동 순서와 결과 수식을 가르고, ASSERT 단정 낱말에는 `즉시`·`바로`가 없다.

| 단계 | 검사 | 면제 |
|------|------|------|
| ① | 프로필 본문 위험 규칙(`body_risk_hit`) | 전문가 상담·면책 절 건너뜀(프로필 규칙대로) |
| ② | 프로필 `banned_patterns` 를 제목·본문 전체에 | **없음** |
| ③ | 상담을 부정하는 문장에서 프로필 위험 낱말·증상 단정 | **없음** |
| ④ | QG4-ASSERT: 건강 신호 + 단정 낱말(문단) | 없음(면책 절 안이어도) |
| ⑤ | QG4-CLAIM: 증상 + 즉각·단정 부사 + 효과 동사(조각 하나, 제목 포함), 증상이 없어진다는 문구, 이 제품·방법이 낫게 한다는 단정 | 없음 |
| ⑥ | QG4-TITLE: 제목의 금지 주제 낱말 | 없음 |

위 단계는 본문에 더해 **숨은 글**(이미지 대체글·HTML 속성 값·링크 글자, `hidden_health_text`)도 읽는다. 코드 블록은 읽지 않는다.

**효과 단정(⑤)이 글을 읽는 방법** — 2차 재검증이 보인 미탐 구조 다섯을 이렇게 막았다.

1. **조각 나누기**(`_claim_units`): 쉼표·느낌표·물음표가 증상과 즉각 효과를 갈라놓던 것을 고쳤다. 제목처럼 **짧은 글**(120자 이하, 줄바꿈 없음)은 어떤 문장 부호가 있어도 **통째로 한 조각**이다(`허리 통증, 즉시 줄이는 방법`·`피곤하세요? 즉시 회복시켜 드립니다`). 긴 글은 마침표·줄바꿈을 늘 문장 경계로 보고, 문장이 120자를 넘으면 쉼표·느낌표·물음표·쌍점 사이의 **절 하나씩과 이웃한 두 절을 이은 것**을 조각으로 본다(물음표는 40자 이하의 짧은 질문 뒤에서만 이어 본다 — 긴 문장 끝의 물음표는 경계다). 마침표는 바로 뒤에 영문자·숫자가 붙지 않을 때만 문장 끝이다 — 소수점(`99.9%`·`3.5배`)·약어(`U.S.`)·주소(`example.com`)와 `Dr.`·`Mr.` 같은 호칭의 점은 경계가 아니다(경계를 덜 자를수록 단정을 더 잘 찾는다. 3차 검증 전에는 `통증이 99.9% 즉시 사라집니다` 가 제목 위치에서는 보류되고 본문 위치에서는 점에서 갈려 통과했다).
2. **부사와 효과 동사 사이**(`_ko_gap_modifies_result`): 예전의 글자 수 상한(8자)을 구조 규칙으로 바꿨다. 사이에 행동 서술어(가서·받·드세요·하고·먹·바르·쉬·찜질·중단 …)나 증상이 아닌 다른 대상(…을·를)이 끼면 부사는 그 행동의 순서를 꾸미는 말이라 C 가 아니고, 명사구·부사만 끼면 효과 결과를 꾸미는 말이라 C 다(`피로를 완전히 하루 한 번 이 방법만으로 없앨 수 있다`). 멀리 떨어진 말을 잇지 않는 느슨한 안전선만 40자로 둔다. `치료를 받`·`치료를 위해`처럼 효과 동사가 목적어로 쓰인 말은 효과 동사가 아니다. 시간 부사 + 명령형은 행동을 재촉하는 말이고 단정 부사(완전히·확실히 …)는 명령형이어도 단정이다(`이 샴푸로 완전히 해결하세요`). `…하고·…하며·…하면서·…하여·…해서` 는 앞 낱말이 **행동 낱말 목록**(`_DO_VERB_STEMS` — 확인·기록·휴식·운동·상담 …)에 있을 때만 행동 서술어다 — `안전하고 부드럽게`·`편안하며 확실하게` 같은 형용사 나열은 행동 순서가 아니라 결과를 꾸미는 말이다(전에는 `하고` 앞이 아무 낱말이어도 행동으로 읽어 이 모양이 통과했다). 형용사를 가르는 목록을 두지 않고 행동 낱말만 적은 것은 목록에 없는 쪽이 보류(안전한 쪽)로 떨어지게 하려는 것이다. 사이의 대상이 몸 낱말(몸·팔·눈 …)이고 그 뒤에 부사·형용사 나열뿐이면(`즉시 몸을 가볍게 풀어 주는`·`즉시 몸을 편안하고 가볍게 풀어 주는`) 그 대상은 효과 동사의 대상이라 C 다 — 대상 뒤에 다른 서술어가 이어지면(`즉시 눈을 감고 …`) 행동이다. 효과 동사가 `…는지·…은지·…을지` 로 이어지거나(`통증이 줄어드는지 확인하세요`) `…지 않·못·말·마` 로 부정되면 효과를 묻거나 부정하는 말이라 단정이 아니다.
3. **증상·질환 어휘**(`_SYMPTOM_KO`): 닫힌 낱말 목록을 넓히고 **접미 규칙**(…염·…증·…증후군·…장애·…병)을 더했다(`가나염`·`과민증`·`협착증`·`수면 장애`·`당뇨병`). 일반어는 최소 예외 목록으로 뺀다(화염·방염·식염·탄산염·저염·감염·전염·오염, 영수증·보험증·신분증·저작권증·자격증·안전인증·품질보증·예약증·교환증·계약증·수강증·사원증·급증, 시스템 장애·서비스 장애). 체중 감량을 숫자로 말하는 문구(`5kg 감량`)도 몸 상태 낱말로 읽는다. `디스크` 는 컴퓨터 맥락(하드·SSD·`디스크 공간`)을, `공황` 은 `공황 발작` 밖의 쓰임을, `이명` 은 `이명박` 을, `스트레스` 는 `스트레스 테스트` 를 뺀다. 모호한 낱말 다섯(기미·주름·틱·땀·쥐)은 **일부러 증상으로 세지 않는다**(일반어이거나 뜻이 여럿이라 오탐이 많다) — 이 다섯 낱말만으로는 이 규칙이 보류하지 않는다(§9-1). 3차 수정은 목록 밖 낱말 몇 개(잇몸·혈액순환·화병·`눈 떨림`·`손 떨림`·`다리 쥐`·`땀 냄새`·부기)를 더하고(`떨림`·`쥐` 한 낱말은 뜻이 여럿이라 몸 낱말과 합친 말로만 읽는다), 비유로 쓰는 `X의 고질병`·`근시안적`·`탈염`·`디스크 어레이`·`복식부기` 는 증상에서 뺐다.
4. **긴 조각**(`_claim_windows`): 400자를 넘는 조각은 앞 400자만 보지 않고 **400자 창을 200자씩 밀며 겹쳐** 훑는다(200자 안의 단정은 반드시 한 창에 들어간다). 시간은 글 길이에 비례한다.
5. **효과 동사·활용·시간 낱말·어순·영문**: 효과 동사를 낱말마다 활용형을 손으로 적는 대신 **어간 × 활용 끝 묶음**(`_stems` — 이다형 줄이·줄여·줄였·줄인·줄일·줄임·줄입, 지다형 사라지·사라져·사라졌·사라진·사라질·사라짐·사라집 …)으로 만든다. 묶음 하나를 고치면 그 묶음의 모든 낱말이 함께 바뀌고, 새 낱말은 어간만 더하면 -ㄴ다·-었다·-ㄹ 수 있다·해요체·합쇼 꼴이 따라온다(검증자의 활용 행렬 동사 38 × 6꼴 228꼴에서 미탐 104 → 2 — 남은 꼴은 `멈추다` 의 관형·가능 꼴로, `작업을 즉시 멈추는 방법` 같은 행동 때문에 일부러 읽지 않는다). 동의어(고치다·억제·진정시키다·경감·잠재우다·누그러지다·잦아들다·감소·시원해지다·괜찮아지다·벗어나다·해방·리셋·박멸·안정시키다·낮아지다·내려가다·물러가다·달아나다·사그라들다·다스리다·달래다 …)와 풀리다·가라앉다·멎다·날아가다·뚫리다·펴지다·떨어지다·되찾다·되살리다·되돌리다·젊어지다·재생하다·치유·극복·퇴치·정상화도 읽는다. **시간 낱말**은 낱말 하나씩이 아니라 구조로 읽는다: 즉효·곧·직후, 동작 + `자마자`(`먹자마자`)·동작 + `는 순간`(`바르는 순간`), 기간 단위(초·분·시간·일·주·개월·한/두/세/네 시간·주·하루·이틀·열흘·보름 …) + 끝말(만에·이내·이면·안에·내에·동안·후면·뒤면·만·컷), `단 하루에`·`단 한 번`, `100퍼`. **효과 명사가 부사 앞에 오는 어순**(`통증 해소 효과가 즉시 나타납니다`·`두통 해결 당장 가능합니다`·`허리 통증 완화 지금 바로`)은 부사 바로 앞이 효과 명사(+ 효과·조사·쉼표·지금)이고 뒤가 결과 서술어(가능·나타·느낄 수·체감·경험 …)이거나 글 끝일 때 읽는다 — 뒤가 행동·안내(`바로 알기`·`바로 시작하세요`)이거나 부정·묻는 절이면 읽지 않는다. 영어는 부사(overnight·for good·in two days·within a week …)와 동사(gone·goodbye·beat·soothe·lose·burn·shed·drop·alleviate·reverse …)를 넓혔고, 교통·네트워크·경제·소프트웨어에서 같은 낱말이 다른 뜻으로 흔한 것(`congestion` 은 nasal·chest·sinus 처럼 몸 낱말이 붙을 때만, `stress test`·`market stress`·`pain points`·`index weight`·`Great Depression`·`memory bloating`·`pandemic hangover`·`security posture`·`cold start` 는 제외)은 증상으로 읽지 않는다. 증상이 없어진다는 문구(`제로`·`걱정 끝`·`이제 안녕`·`굿바이`·`작별`·`해방되다`·`즉효`)는 효과 동사가 없어도 같은 규칙이다.

**제품·방법이 낫게 한다는 단정**(`_PRODUCT_CURE`): 지시어(이·그·저·해당) + 제품·방법 낱말(영양제·보충제·약·식단·차·방법·의자 …) + 같은 문장의 낫는다·치료한다·고쳐 준다·해결한다 …가 건강 낱말과 함께 있으면 QG4-CLAIM 으로 보류한다 — 상담 문구가 붙어도 면제하지 않는다(`의사와 상담하세요(이 약은 암을 치료합니다)`). 부정·반박·정보 문장(`못합니다`·`근거는 없다`·`입증되지 않았다`·`치료하는 데 쓰입니다`)은 건너뛴다. 지시어 없는 일반 서술(`약은 암을 치료합니다`)은 보지 않는다(§9-1).

**허용 방향 오탐을 숫자로**(아래 '새로 걸린 문장은 없다'는 **3차 검증자의 문장에 한정된 사실**이다 — 4차 검증자의 일상·기술·경제 45문장에서는 `곧`·`직후`·몸 낱말 규칙 때문에 6개에서 9개로 늘었다. 실제 글(공개 62편·문서 35,993문장)에서는 새로 걸린 것이 0이다): 구조 규칙으로 넓힌 만큼 오탐이 늘 수 있어 측정으로 적는다. **구현자가 고른 대조 문장**(건강과 무관한 일반·기술·경제 27문장과 행동 순서 20문장, 검증자의 A·B·일반 대조 42문장 중 이상적으로는 통과인데 보류되는 2개 — `스마트폰 배터리 발열을 즉시 줄이는 설계가 공개됐다`·`로봇 관절의 마찰을 완전히 없애는 신소재가 개발됐다`)에서는 새 효과 단정에 걸린 것이 0개였다. 그러나 이것은 **구현자 문장에 한정된 사실**이다 — **3차 검증자가 새로 지은 문장**에서는 행동 순서 44문장 중 QG4-CLAIM 이 옛 4 → 9, 일상·기술·경제 45문장 중 7 → 20, 영문 25문장 중 10 → 23 으로 늘었다. 3차 수정은 결과를 묻는 절·부정·`고질병`·`근시안적`·`탈염`·`디스크 어레이`와 영문 모호어를 줄여 같은 문장들에서 행동 순서 5(수정 직전 9), 일상·기술·경제 15(수정 직전 20), 영문 3(수정 직전 23)이 되었고 새로 걸린 문장은 없다. 남은 오탐은 몸 낱말이 기계·경제에 쓰인 문장(`발열`·`관절`·`스트레스 지수`·`시장 불안감`·`가격이 떨어졌다`)과 효과 동사가 명사로 쓰인 행동 문장(`치료 방향을 정하세요`)이다 — 보류 쪽 오류라 비용이 낮다고 보고 줄이지 않았다. 공개 62편(국문·영문)과 저장소 한국어 문서 35,785문장·줄에서 새로 걸린 것은 0이다(§7).

### 3-3. 입력 상한과 시간

- 글이 **30,000자**를 넘으면 정규식을 돌리기 전에 QG0-INPUT 으로 보류한다(지금 글은 2–6천 자). 근거 글은 앞 20,000자만 읽는다.
- 건강 규칙에 넘기기 전에 공백 연속(탭·폼 피드·CR·U+2028 …)을 한 칸으로, 숫자 연속을 15자리로 접는다(기존 위험 규칙의 숫자+단위·절 나누기 패턴이 이런 입력에서 제곱 시간이 되기 때문 — `pipeline/gates.py` 는 고치지 않고 Gate 쪽에서 입력을 줄여 부른다). 머리말 제목 줄은 정규식이 아니라 문자열로 처리한다.
- 출처 표지 판정은 줄 하나(300자 이하)씩, 제목 줄은 여는 부분만 정규식으로 보고 나머지는 문자열 메서드로 뗀다(꼬리를 정규식으로 받으면 공백이 긴 줄에서 3차 시간).
- 3만 자 입력의 최악 모양 77종(앞의 63종에 효과 단정의 최악 모양 — 쉼표·느낌표·물음표·마침표 연속, 부사·효과 동사·증상 낱말·접미 낱말·목적어가 잇달아 오는 글 — 을 더했다)을 규칙 함수마다 시간을 재 보았다: 한 모양을 규칙 전체로 돌려도 3.3초 이내이고 함수 하나는 최대 1.1초다. 시간 초과·예외는 없었다. 3차 수정 뒤에는 검증자의 적대적 모양 377개에 이번 수정의 정규식(자마자·는 순간·마크다운 링크 제목·소수점·약어·효과 명사 어순·몸 낱말 대상)을 겨냥한 81개를 더한 458개를 29,900자로 국문·영문 쌍으로 돌렸고 시간 초과·예외는 없었으며 가장 느린 모양이 9.3초였다(다른 작업이 같은 PC 에서 한창 돌던 때의 값 — 가장 느렸던 모양 네 가지를 한가할 때 세 번씩 다시 재면 이번 코드는 2.2–4.7초, 같은 조건의 옛 머리(`ed3fea1`)는 1.5–3.6초로 시간은 느는 쪽이지만 같은 자릿수다). 효과 단정 검색은 겹치는 창으로 글 길이에 비례하고(§3-2) 시험이 모양 11가지의 시간 상한을 못박는다.
- **4차 독립 검증이 찾은 한 모양(정규식 제곱 시간)**: 위 458모양에 없던 `](` 뒤에 공백이 수만 자 이어지는 입력에서 마크다운 링크 제목 정규식(`_MD_TITLE_TEXT`)이 제곱 시간이었다(한 함수가 29,000자에서 7.5초, `check_candidate` 가 15–22초 — 위의 '시간 초과·예외 없음'은 이 모양을 포함하지 않았다). 주소 자리를 1자 이상으로 바꿔 선형으로 고쳤고(`[a]( "제목")` 처럼 주소가 빈 것은 더는 링크 제목으로 읽지 않는다) 공백·줄바꿈·탭 28,000자가 각각 2초 안에 끝나는 것을 시험이 못박는다. 켜기 전에 이 시간 측정은 한가한 PC 에서 최종 코드로 한 번 더 한다.

### 3-4. 근거 텍스트 경계 — 나중에 근거를 바꿔 끼우는 자리

**근거 텍스트**란 `generator.build_post_prompt`가 모델에 싣는 것(제목·출처 이름·게시 시각·기사 요약)이다. Gate 는 그것만 근거로 본다 — 지금 입력은 피드 요약(최대 1,800자, 소스별 `summary_max_chars`)이라 **요약이 짧으면 근거에 있는 숫자가 적어 통과율이 낮을 수 있다**(입력 보강은 운영자 결정 대기 — 이 일에서 하지 않았다).

Gate 가 근거를 읽는 곳은 `pipeline/quality_gate.py`의 **`evidence_text(source)` 한 함수**(근거 글과 요약 글자 수)와 **`source_ref(source)` 한 함수**(검증된 원문 주소·게시자 도메인·출처 이름)뿐이다. 규칙 함수는 그 두 함수가 돌려준 값만 본다. 근거를 다른 모양(구조화 자료와 출처 기록)으로 바꿀 때는 이 두 함수만 고치면 되고, 시험(`EvidenceBoundaryTest`)이 후보 항목의 키(`summary`·`published`·`title`·`link`·`publisher_domain`)를 이 두 함수만 읽는다는 것을 소스 구조로 확인한다.

## 4. 연결 위치와 탈락 표시

- `generator.generate_blog_posts`의 후보 검증 칸, **같은 `try` 안, 머리말 최종 검사(`check_final_front_matter`) 바로 뒤** 한 곳에서만 부른다(`quality_gate.require_pass(quality_gate.check_candidate(...))`, `quality_gate: hold`일 때만). 걸리면 `QualityHold`(`ValueError` 하위)가 올라와 기존 `except ValueError`가 받아 **'본문 검증 탈락'과 같은 길**로 이 후보를 버린다 — 탈락 기록(`rejects`)·공개 주석 한 줄·실행 요약에 `품질 Gate 보류 [코드, …]: 사유`로 한 줄씩 남는다.
- 모델 호출·이미지 검색은 탈락한 후보에 더 쓰지 않는다(Gate 는 이미지 고르기 전에 돈다). 전부 탈락하면 `ALL_REJECTED`(정기 실행은 글 없이 경고·초록, 수동 실행은 지금처럼 예외).
- Blogger·이슈 수정·승인 흐름·알림 코드는 Gate 를 읽지 않는다(시험이 소스를 확인한다).
- 건강 프로필을 읽지 못하면 Gate 를 켠 채 약한 검사로 떨어지지 않고 모델을 부르기 전에 멈춘다.

## 5. 국문 전용(`languages: ["ko"]`)이 바꾸는 것

기본에서는 프롬프트·검증·이미지·파일·이력·승인 PR 이 옛 코드와 바이트까지 같다(기본 프롬프트 14개의 해시와 두 파일 PR 본문의 해시를 시험이 못박는다). `["ko"]`이면:

1. 프롬프트가 '한국어로 작성'이고 응답 틀에서 `en_*` 칸이 빠진다(편집 템플릿 문서의 'bilingual' 한 낱말은 그대로 둔다 — 편집 지침 변경은 T3).
2. 영문 응답이 오더라도 읽지도 검증하지도 쓰지도 않는다.
3. 대표 이미지는 1장만 고르고 사진 사용 알림도 한 번이다.
4. 글 파일은 국문 하나, 이력 항목에는 `en_title`·`en_image`가 없고 `languages: ["ko"]`가 적힌다. `generate_blog_posts`는 `(국문 경로, None)`을 돌려준다.
5. 승인 흐름이면 이력의 `paths`가 1개다 — PR 제목은 `[초안][Chance] 한국어 제목`, 본문에서 영어 칸이 빠진다.

## 6. 그림자 실행(SHADOW_RUN) 인터페이스

PIPELINE_PAUSE 가 켜져 있으면 모든 실행이 건너뛴다. 제한 재개 조건(그림자 3회·초안 10개 이상 평가)을 정지를 유지한 채 얻으려고, **쓰기 권한이 없는 읽기 전용 실행**을 따로 둔다. 워크플로(`.github/workflows/chance-shadow.yml`)는 다른 담당이 만든다 — 이 문서가 그 워크플로가 부르는 인터페이스다.

### 환경 변수

| 변수 | 뜻 |
|------|----|
| `SHADOW_RUN` | 앞뒤 공백·대소문자는 무시한다. **켜짐**: `1`·`true`·`yes`·`on`·`enabled`. **꺼짐**: 비어 있거나 없음·`0`·`false`·`no`·`off`·`disabled`. **그 밖의 값**(오타·`2`·`garbage`)은 **실행을 거절한다**(`::error::` 한 줄, 종료 코드 2 — 모르는 값을 꺼짐으로 읽으면 정지가 풀린 상태에서 일반 쓰기 실행으로 내려가기 때문이다). 켜짐이면 정지 변수(`PIPELINE_PAUSE`)를 보지 않고 읽기 전용 경로로 간다(변수 자체는 건드리지 않는다). **이 변수가 없으면 이전과 동작이 같다** — 정지에 그대로 멈춘다 |
| `SHADOW_OUT=<폴더>` | 결과를 쓸 폴더. **저장소 작업 폴더 밖의 로컬 절대 경로**이고 비어 있거나 없는 폴더여야 한다. 실경로(심볼릭 링크·정션·8.3 짧은 이름을 푼 것)로 견주어 저장소 안이거나 그 위 폴더면 거절하고, Windows 확장 경로 접두사(역슬래시 둘 뒤에 물음표나 점이 오는 모양)와 UNC 공유 경로는 통째로 거절한다. 파일, 비어 있지 않은 폴더, 상대 경로도 종료 코드 2. 러너의 임시 폴더 아래를 권한다 |
| `SHADOW_COUNT` | 시도할 후보 수. 기본 3, 상한 5(넘으면 5로 줄이고, 숫자가 아니거나 1 미만이면 3) |
| `GEMINI_API_KEY` | 일반 실행과 같다(없으면 종료 1). `DRY_RUN=1`이면 가짜 응답(`model: stub`)으로 인터페이스만 연습한다 |

하루 상한·슬롯 규칙은 보지 않고 정해진 수의 후보만 시도한다. 후보는 일반 실행과 같은 함수(수집·프롬프트·검증)로 만들고 같은 기사는 한 번만 평가한다. 레지스트리의 `quality_gate` 값과 상관없이 Gate 는 **항상 적용**하고(보류 사유를 파일로 낼 뿐 버리지 않는다), `languages`는 레지스트리를 따른다.

### 출력 파일

글 파일 이름은 **측정 도구가 읽는 이름**(`날짜-KR|EN-시각6자리.md`)이다 — 측정 도구는 폴더 아래의 `.md`를 모두 읽어 파일 이름의 날짜와 시각으로 국문·영문을 한 쌍으로 묶는다. 한 번의 실행 안에서 쌍 키가 겹치지 않도록 시도 번호마다 시각을 1초씩 늦춘다(시작 시각 + 번호 − 1초).

```
SHADOW_OUT/
  run.json                              전체 요약(요청 수·시도 수·통과 수·시도한 분야·후보별 한 줄)
  01/
    2026-11-09-KR-103000.md             파일이 될 모양의 국문 글(머리말·설명·출처 세 줄·출처 목록·고지문 포함, 자리표시 대표 사진은 뺌)
    2026-11-09-EN-103000.md             영문 글(languages 가 ko 뿐이거나 모델이 영문을 못 만들었으면 없음)
    result.json                         아래 형식
  02/                                   시도 번호 두 자리(01–05), 글 파일 시각은 한 시도마다 1초 늦다
```

검증에 실패한 후보도 모델이 쓴 글 그대로 남는다(건너뜀·응답 형식 오류·제목 중복은 글이 없어 `result.json`만 남는다).

### `main()` 의 순서

`main()` 은 **모르는 `SHADOW_RUN` 값 거절 → 정지 검사(`_pause_on`) → 그림자 분기(`SHADOW_RUN` 켜짐이면 읽기 전용으로 처리하고 끝) → (제한 재개 잠금 가드가 있으면 그 아래) → 일반 실행** 순서다. 그림자 분기는 잠금 가드보다 **앞**에 있어야 한다 — 그림자 실행은 읽기 전용이라 잠금 대상이 아니고, 가드가 앞서면 레지스트리 규칙 위반·하루 상한이 그림자 실행까지 멈춘다. 이 순서는 병합할 때 지켜야 한다(§10).

### 읽기 전용은 코드로 강제된다

1. `pipeline/shadow_run.py`는 저장소 파일을 쓰는 함수와 승인 흐름 실행부(`git` 을 부르는 모듈)를 부르지도 읽지도 않고, `subprocess` 는 부르지 않는다(`git`·`gh` 를 막으려고 `Popen` 을 바꿔 끼울 뿐이며, 소스 구조 시험이 `subprocess.<함수>(…)` 호출이 하나도 없음을 확인한다). 결과를 쓰는 길은 `ShadowWriter` 하나이고 경로가 `SHADOW_OUT` 밖이면 거절한다.
2. 실행하는 동안 `read_only()`가 `generator`의 쓰기 함수(`write_text_atomic`·`write_history`·`write_step_summary`·`trigger_download`·`fix_images`·`pick_images`)를 부르면 `ShadowViolation`이 나게 바꾸고, 프로세스 만들기(`subprocess.Popen`·`os.system`·`os.popen`)가 `git`·`gh` 를 부르면 같은 예외로 막는다. 프로그램 이름은 **명령의 모든 낱말**에서 찾는다(`cmd /c git …`·셸 한 줄 안의 `echo x && git …`도 막는다).
3. **파이썬 감사 훅**(`sys.addaudithook`)이 `SHADOW_OUT` 밖의 파일을 만들거나 바꾸거나 지우는 일을 어느 길로 하든(`open`·`pathlib`·`os`·`shutil`·`tempfile`) 같은 예외로 막는다. 경로는 실경로로 풀어 견주고, 읽을 수 없는 경로는 밖으로 본다(fail closed).
   - **하드링크**(`os.link`)는 원본과 새 경로를 **모두** 검사한다 — 저장소 파일에 `SHADOW_OUT` 안의 이름을 붙인 뒤 쓰면 저장소 파일이 바뀌기 때문이다(하드링크는 같은 파일의 다른 이름이라 실경로 비교로는 알 수 없다).
   - `sqlite3.connect` 는 데이터베이스 파일을 검사한다(`:memory:`·빈 이름은 파일이 아니므로 허용).
   - 막지 않는 것은 **파이썬이 모듈을 처음 읽을 때 스스로 하는 일 네 가지**뿐이다: `__pycache__` 폴더 새로 만들기, 그 안에 `.pyc`(또는 임시 `.pyc.숫자`) 파일 쓰기, 임시 파일을 `.pyc` 로 바꾸기, 쓰다 만 임시 `.pyc.숫자` 파일 지우기. 폴더 삭제·다른 이름의 파일·캐시 밖의 `.pyc` 는 막는다. 그리고 그 플랫폼의 널 장치(Windows `nul`, 그 밖은 `/dev/null`).
   - 프로세스를 만드는 감사 이벤트(`subprocess.Popen`·`os.system`·`os.exec`·`os.posix_spawn`·`os.spawn`)도 훅이 판정해서 `from subprocess import Popen` 으로 미리 쥔 `Popen` 도 `git`·`gh` 이면 막힌다.
   - **쓰기로 보는 열기 깃발**: `O_WRONLY`·`O_RDWR`·`O_APPEND`·`O_CREAT`·`O_TRUNC`·`O_EXCL` 과 Windows 에만 있는 `O_TEMPORARY`(읽기로 열어도 닫을 때 파일이 지워진다)가 든 `open` 은 쓰기로 보고 판정한다(`O_TEMPORARY` 시험은 그 깃발이 있는 플랫폼에서만 돈다).
   - **폴더 번호(dir_fd)**: 리눅스의 `shutil.rmtree` 는 `os.rmdir(이름, dir_fd=번호)`·`os.remove(이름, dir_fd=번호)` 처럼 열린 폴더 번호와 짧은 이름으로 지운다. 훅은 `os.rmdir`·`os.remove`·`os.mkdir`·`os.rename` 등 11개 이벤트의 짧은 이름을 `/proc/self/fd/번호` 가 가리키는 폴더 뒤에 붙여 판정하고, 폴더를 풀 수 없으면 막는다(fail closed). 열기 이벤트(`open`)에는 폴더 번호가 실리지 않아 상대 경로를 dir_fd 로 여는 쓰기는 이 방식으로 알 수 없다(생성기·그림자 실행 코드는 dir_fd 를 쓰지 않는다).  `os.spawnv` 는 리눅스·맥에서 파이썬 코드가 fork 한 자식에서 실행하므로 막힌 자식이 127 로 끝날 뿐 부모에 예외가 오지 않는다(git·gh 는 실행되지 않는다).
   - 함수를 바꿔 끼우는 방식은 함수를 미리 쥐고 있는 코드를 놓쳐서 쓰지 않았다(Python 3.10 의 `Path.write_text` 가 `io.open` 을 미리 쥐고 있어 빠져나갔고, 시험이 잡았다). 훅은 구간 안에서만 켜지고(한 번 달면 뗄 수 없어 구간이 끝나면 아무 일도 하지 않는다) 위반하면 실행이 빨강으로 끝난다.
   - Windows 의 Python 3.12 에서 `shutil.copy2` 는 감사 이벤트를 내지 않는 지름길(`CopyFile2`)을 써서, 같은 이벤트를 대신 내도록 바꿔 끼운다.
   한계: 감사 이벤트를 내지 않는 길(`ctypes`·확장 모듈이 운영체제 함수를 바로 부르는 것)과 자식 프로세스가 하는 일은 이 방식으로 막지 못한다. 구체적으로 읽기 전용 구간 안에서 `subprocess` 로 부른 셸 한 줄(`echo x > 파일`)·자식 파이썬·`os.system`·`os.popen`·`ctypes`(`CreateFileW`) 다섯 길이 저장소에 파일을 만들 수 있다 — 3차 검증이 확인한 문서화한 한계이고, 읽기 전용 구간에서 자식 프로세스 만들기를 일괄 거절하는 하드닝은 하지 않았다(실제 방어선은 워크플로 권한 `contents: read`). `__pycache__` 폴더 안의 `.pyc` 쓰기는 이름이 무엇이든 허용된다(파이썬이 스스로 하는 일과 구별할 수 없다 — 추적되지 않는 캐시 파일이지만 가짜 바이트코드를 심는 길은 남는다). `git`·`gh` 차단은 **이름 기반의 근사**라 다른 이름으로 복사한 실행 파일이나 파이썬 `-c` 를 거친 호출은 모른다 — 그래서 위의 쓰기 함수 차단과 이 모듈이 쓰기 함수를 부르지 않는다는 구조 시험이 함께 있고, 실제 방어선은 워크플로 권한(`contents: read`)이다.
4. `generator.py`의 `write_text_atomic`·`write_step_summary`·`trigger_download`는 `SHADOW_RUN` 이 켜짐이면 `DRY_RUN`과 같이 스스로 막힌다(이중 방어).
5. 정지 우회는 이 모드 안에서만이다: `_pause_on()`이 `SHADOW_RUN` 켜짐 값(`1`·`true`·`yes`·`on`·`enabled`)일 때만 False 를 돌려주고 `main()`이 곧바로 읽기 전용 경로로 넘긴다. `0`·`false`·`off` 같은 꺼짐 값은 우회하지 않는다. 일반 실행 경로(쓰기·게시)로는 내려가지 않는다.
6. 이 경로는 오프라인 측정 도구에 연결하지 않는다 — 측정은 워크플로가 두 번째 단계에서 별도 프로세스로 한다(시험이 소스를 읽어 확인한다).

### 워크플로가 지킬 것(권고)

수동 실행(`workflow_dispatch`)만, 권한은 `contents: read`만, 정지 변수는 건드리지 않는다(그림자 경로는 그 값을 보지 않는다), `SHADOW_OUT`은 러너 임시 폴더 아래로 하고 결과는 실행 요약·아티팩트로만 낸다(커밋·푸시 단계 없음), 비밀은 단계 `env`로만 넘긴다. 이 변수·형식을 바꿀 때는 이 문서와 `tests/test_shadow_run.py`를 함께 고친다.

## 9. 알려진 한계와 남은 위험

- 규칙은 글자 모양을 읽는 근사다. 사실이 맞는지·분석이 있는지는 판정하지 못한다(Gate 는 사람 검토를 대신하지 않는다 — [`SECURITY_GUARDRAILS.md`](./SECURITY_GUARDRAILS.md) G-C11).
- 근거가 피드 요약뿐이라 요약이 얇은 소스는 통과가 어렵다. 입력 보강(같은 피드의 본문 칸 사용)은 별도 T3 결정이다. 근거를 구조화 Fact 로 바꾸는 일은 별도 작업(FACT)이며 이 Gate 는 §3-4 의 두 함수 경계만 고치면 된다.
- 영어 근거를 국문으로 옮긴 인용·이름은 글자를 맞춰 볼 수 없어 개수로만 제한한다. 국문 글에 섞인 번역 인용의 개수는 근거의 인용 개수에 기대므로, 근거에 따옴표로 감싼 말이 많으면 번역 인용 몇 개가 더 지나갈 수 있다.
- 숫자: 한자어 숫자(삼십오 퍼센트), 공백으로 천 단위를 끊은 숫자(1 234 567), 날짜 범위(5–7일의 7)는 읽지 못한다. 연도처럼 생긴 정수가 근거의 같은 연도로 받쳐질 때 건수로 쓰였다면 놓칠 수 있다.
- QG4 는 보류 쪽으로 기울어 있어 건강 인접 글(공학의 진단, 사망 통계)이 걸리고, `영양제 바로 알기`처럼 운영자 기준으로는 통과해야 하는 정보 제목도 걸린다(알려진 한계). 몸 낱말이 기계에 쓰인 기술 문장(`스마트폰 배터리 발열을 즉시 줄이는 설계`·`로봇 관절의 마찰을 완전히 없애는 신소재`)도 효과 단정으로 걸린다(측정한 대조 42문장 중 2건 — 허용 방향 오탐). QG8 은 구조가 다른 번역 복제를 못 잡는다. 건강 규칙의 미탐 한계는 §9-1.
- 숨은 글(이미지 대체글·HTML 속성·마크다운 링크 제목·링크 글자): 건강 규칙(QG4)은 링크 글자까지 읽고, 숫자·인용·이름(QG1·QG2)은 링크 글자를 뺀 나머지를 읽는다 — 출처 목록 링크 제목 속의 숫자·기관 이름은 주장이 아니라는 규칙(§3-1)이라 읽지 않는다. 코드 블록·인라인 코드·HTML 주석·그림 속 글자는 어느 규칙도 읽지 않는다. 실제 글에서는 대체글이 `Thumbnail` 같은 짧은 말이라 영향이 없다(공개 글 62편 중 52편이 숨은 글을 갖지만 숫자·인용·직함 이름이 든 글은 0편).
- 그림자 훅은 감사 이벤트를 내지 않는 길(`ctypes`·확장 모듈)과 자식 프로세스가 하는 일을 막지 못하고, `git`·`gh` 차단은 이름 기반이다(§6). 실제 방어선은 워크플로 권한이다.
- 켠 뒤 보류가 늘면 모델 호출이 늘 수 있다(후보 3건 상한은 그대로, 전부 탈락한 실행은 다음 정기 실행이 다시 시도). 호출 수 증가는 G-L5(T3)와 이어진다 — 켜기 전에 운영자가 정한다.
- 근거에 통화 표시가 하나도 없고 같은 값이 있으면 금액을 환산이 아니라 표기 차이로 받아 준다(통화 없는 근거 숫자가 다른 통화 금액을 받쳐 줄 수 있다 — 시험이 이 동작을 못박는다). 31 이하의 단위 없는 정수는 주장으로 세지 않는다.
- 원문 주소 비교는 계정 정보(`user@`)와 기본(80·443)이 아닌 포트를 남긴다(다른 서비스일 수 있다). 읽을 수 없는 포트는 읽을 수 없는 주소다.

### 9-1. 건강 규칙: 보증할 수 없는 것과 켜기 전 사람 검토 절차

**'누락 0'은 낱말 규칙으로 보증할 수 없다.** 제한 재개 최소 조건 7(건강 C 누락 0건)을 이 규칙의 통과로 '증명'할 수는 없다. 증상·질환 이름이 어휘에 없거나 같은 뜻을 새 표현으로 쓰면 지나간다. 2차 수정은 검증자가 지은 새 C 문장 105개 중 41개가 통과하던 것을 0개로(도구로 다시 돌릴 수 있는 88개는 그대로 돌렸고, 구두점 구조 17개는 같은 모양의 우리 문장 24개로 확인했다), 증상·질환 낱말 91개의 보류를 22개에서 86개로 올렸지만, 이것은 **본 문장에 맞춘 측정이지 일반 보증이 아니다** — 다음 검증자가 같은 방식으로 새 문장을 지으면 새는 곳이 또 나올 수 있다 — **3차 검증이 이것을 실증했다**: 검증자가 새로 지은 B·C 모양 60문장(같은 뜻의 흔한 광고 말투·드문 동의어) 중 48문장이 통과했고(운영자 글자 그대로의 문장 45개와 질환·약 + 단정 10개는 모두 보류), 3차 수정이 구조 하나씩(`…하고` 행동 낱말 목록·어간 × 활용 끝 묶음·효과 명사 어순·시간 낱말 구조·소수점)으로 닫아 48 → 3 으로 줄였다. 구현자가 따로 새로 지은 홀드아웃 50문장은 39 → 2 이 미탐이다. 그래도 새 표현은 또 지나갈 수 있다. 알려진 구멍:

- **일반화의 한계(4차 독립 검증의 측정)**: 검증자가 새로 지은 흔한 광고 낱말 30문장 중 24개가 본문·제목 모두 통과했고 3차 수정이 새로 잡은 것은 0개였다 — 닫힌 목록은 구현자가 3차 문장에 맞춰 닫은 만큼만 닫혔다(운영자 기준 그대로의 모양은 72/72 보류). 빠진 곳은 부사 목록·시간 끝말(`뒤`·`후`·`1주일`)·받침 어간 활용(`빼는`·`풀 수`·`줄도록`)이다. 이것이 사람 검토 절차(아래)가 켜기 전 조건인 이유다.
- **이중 부정의 후퇴**: `이 방법으로 허리 통증이 즉시 사라지지 않을 이유가 없습니다`(이중 부정 = 단정)는 3차 수정 전에는 보류였고 지금은 통과한다(`…지 않` 면제가 효과 동사 바로 뒤의 `…지 않` 을 부정으로만 읽는다). 같은 면제의 반대편 `…사라지지 않으면 전액 환불해 드립니다` 와 함께 알려진 한계다.
- **효과 명사 어순 규칙의 우회**: `피로 회복에 즉시 도움이 됩니다`(조사 `에`)·`허리 통증 완화 — 즉시 체감`(구분 기호 `—`·`:`·`→`)·`허리 통증 해소 효과가 즉시 나타나며 번거로움이 없습니다`(부사 뒤 24자 안의 `없` 한 글자)가 지나간다. 이 `없` 면제를 시험이 못박지 않는다(독립 검증의 변이 MN09 생존).
- **문서에 없던 우회 모양**: 영문·한자 혼용(`허리 통증을 instantly 해소합니다`·`Back pain을 즉시 해소하는 방법`)·말줄임표·세 절 이상 떨어진 긴 문장·40자 넘는 질문 뒤 답.
- 어휘 밖 이름: 목록에도 접미 규칙(…염·…증·…증후군·…장애·…병)에도 안 걸리는 증상·질환 이름. 3차 수정이 몇 개(잇몸·혈액순환·화병·`눈 떨림`·`손 떨림`·`다리 쥐`·`땀 냄새`·부기)를 더했지만 모호한 낱말(기미·주름·틱·땀·쥐·멍과 단독 `눈`·`떨림`)은 일부러 세지 않는다.
- 문장이 둘로 갈린 단정: 긴 글에서 마침표·줄바꿈 앞뒤로 갈린 증상과 즉각 효과(`요즘 허리 통증이 심합니다. 즉시 줄이는 방법을 소개합니다.`)는 잇지 않는다(문장 둘). 120자 이하의 짧은 글은 마침표가 있어도 통째로 본다. 소수점·주소·약어의 점은 경계가 아니다(3차 수정 — 영어 호칭 약어는 `Dr.`·`Mr.`·`Mrs.`·`Ms.`·`Prof.`·`St.` 만 문장 끝으로 읽지 않는다).
- 시간 낱말 뒤에 행동 낱말이 낀 조건절: `하루만 먹어도 변비가 해결됩니다`처럼 부사(`하루만`)와 효과 동사 사이에 행동 낱말(`먹어`)이 끼면 행동 순서로 읽혀 통과한다(구조 규칙의 알려진 한계 — `먹으면 즉시 …` 와 같은 모양이라 둘을 가를 수 없다).
- 시간 부사 + 명령형 면제(설계 선택): `이 차를 마시고 두통을 즉시 해소하세요`처럼 광고가 명령형으로 쓰면 행동을 재촉하는 말로 읽혀 통과한다 — 운영자 원칙(`바로 자세를 교정하세요`는 C 가 아니다)과 같은 취급이다.
- 묻거나 부정하는 절 면제의 반대편: 효과 동사가 `…는지`·`…지 않·못` 으로 이어지면 단정으로 읽지 않으므로 `통증이 즉시 사라지지 않으면 전액 환불해 드립니다` 같은 조건부 약속은 지나간다(보장·환불 약속을 따로 보는 규칙은 없다).
- 효과를 가리키는 새 표현: 어간 목록 밖 동사(`꺼지다`·`쪼그라들다` …)·결과 서술어 목록(`가능·나타·느낄 수·체감·경험 …`) 밖의 어순·`두통 끝` 처럼 효과 동사 없이 끝나는 말·`가시다`(`가시는 비밀`처럼 정해진 쓰임에서만 효과 동사)·지시어 없는 제품 단정(`약은 암을 치료합니다`)·코드 블록 안의 글과 그림 속 글자.
- 행동 낱말 목록: `…하고·…하며` 앞 낱말이 목록(`_DO_VERB_STEMS`)에 없는 행동이면 행동 순서 문장이 보류된다(허용 방향 오탐 — 안전한 쪽이라 이렇게 두었다).
- 영문: `congestion` 은 nasal·chest·sinus·head·lung 이 붙을 때만 읽으므로 `Clears congestion instantly` 는 통과하고, `Pain-free in minutes`·`No more headaches, guaranteed` 처럼 효과 동사 없는 문구는 영문 규칙이 읽지 않는다.
- 허용 방향 오탐(건강과 무관한 글이 걸림)은 보류 쪽 오류라 비용이 낮다고 보고 줄이지 않았다 — 늘어난 만큼은 §3-2 에 숫자로 적었다.

**켜기 전 건강 인접 글을 사람 검토로 보내는 절차**(운영으로 닫는다 — 코드는 바꾸지 않는다. 제한 재개 순서의 '하루 최대 1편 PR → 사람 검토·승인 후 공개'와 같은 길이다):

1. **범위**: 제목·본문에 환자·진단·치료·약·보충제·질환 이름·증상 낱말이 있는 후보(`_HEALTH_TOPIC`·`_SYMPTOM_KO`·`_SYMPTOM_EN` 이 읽는 낱말)가 건강 인접 글이다. 그러나 이 분류는 Gate 가 읽는 닫힌 낱말 목록에 기대므로 목록 밖 증상 이름(`잇몸 출혈`·`멍` 같은 말)을 쓴 글은 분류에서 빠질 수 있다 — **그래서 이 절차는 건강 인접 분류가 아니라 모든 글의 승인(`publish_flow: pr` 의 사람 검토·승인 후 공개)으로 닫는다.**
2. **보류**: 제목에 건강 프로필의 금지 주제 낱말(환자·진단·치료·약·당뇨·암·고혈압 …, 영어는 cancer·diabetes …, 정확한 목록은 프로필의 `banned_topic_patterns`)이 있으면 **QG4-TITLE 로 늘 보류**한다. 어휘(`_SYMPTOM_KO`·`_SYMPTOM_EN`)에만 있는 낱말(비염·통증, 영어 `patient`)은 제목만으로는 보류하지 않고 본문에 단정·효과 표현이 있을 때 QG4-ASSERT·CLAIM·HEALTH 로 보류한다 — 그래서 아래 4·5 의 사람 검토가 필요하다. 보류된 후보는 글로 올라가지 않고 실행 요약과 `result.json` 의 `hold_codes` 에 코드와 한 줄 사유만 남는다.
3. **운영자 확인**: 그 주제를 다뤄도 되는지는 보류 기록(QG4-TITLE 포함)을 본 운영자가 정한다. 허용하려면 사람이 글을 쓰거나 고쳐 승인 PR 로 올린다 — Gate 를 끄거나 낱말을 빼서 통과시키지 않는다.
4. **자동 공개 금지**: Gate 를 통과한 건강 인접 후보도 '누락 0'을 보증할 수 없으므로 `publish_flow: pr`(사람 검토·승인 후 공개) 밖으로 나가지 않는다. 승인 PR 을 열 때 사람이 '효능·즉각 효과 단정이 없는지' 한 번 더 읽는다(PR 본문에 점검 문구를 넣는 일은 `draft_flow` 쪽 변경이라 이 묶음에서 하지 않았다).
5. **켜기 전 확인**(그림자 실행 3회·10편 평가 안에서): 건강 인접 낱말이 있는 후보를 운영자가 모두 눈으로 대조한다 — 보류된 것은 오탐인지, 통과한 것은 미탐인지. 통과한 건강 인접 후보가 있으면 그 글을 사람 검토 목록에 올리고 그 글의 낱말을 어휘에 더한다.
6. **어휘 목록 관리**: 증상·질환 어휘는 `quality_gate._SYMPTOM_KO`·`_SYMPTOM_EN` 한 곳, 시험 목록은 `tests/test_quality_gate_health.py` 다. 새 미탐 낱말이 드러나면 어휘와 시험 목록에 함께 더한다. **관리 책임자는 운영자가 정한다**(켜기 전 결정, §10-2).

| `pipeline/registry.py` | 가져오기 줄은 `from pipeline.gates import …` 바로 아래에 둔다(잠금 쪽 가져오기 줄과 한 줄씩 나란히 들어가 충돌하지 않는다) |
| `docs/DEFECT_REGISTER.md` | 이 Gate 의 행은 D-90 이다(그림자 측정 도구가 D-89 를 쓴다). 두 행을 모두 남긴다 |
| `docs/ACTIONS_GUIDE.md` | 그림자 워크플로 안내에 옛 글 파일 이름(`<번호>/post_ko.md`·`post_en.md`)이 있으면 §6 의 새 이름(`<번호>/날짜-KR-시각.md`·`날짜-EN-시각.md`)으로 고친다 |
| 측정 도구의 연결 금지 시험 | 그림자 워크플로가 측정 도구를 두 번째 단계에서 별도 프로세스로 부르므로 `.github/` 전체를 훑는 연결 금지 시험은 그 워크플로 한 파일을 예외로 두어야 한다 — 측정 도구 묶음이 이미 조건부 예외로 고쳐 두었고 합친 트리에서 통과한다(이 Gate 쪽 조치 없음) |

**남은 일(이 묶음 밖)**: 근거를 구조화 Fact 로 바꾸는 일(FACT 작업 — 병합 뒤, §3-4 경계), `languages` 를 `["ko"]` 로 바꾸는 일과 `quality_gate: hold` 를 켜는 일(T3), `pipeline/gates.py` 의 숫자+단위·절 나누기 정규식을 근본적으로 고치는 일(이 묶음은 읽기 전용 재사용), Pew `NEWS_SOURCES` 항목과 `TRUSTED_SOURCE_DOMAINS` 의 `pewresearch.org` 삭제(소스 담당 — Gate 쪽은 이미 통과시키지 않는다).

### 10-2. 2차 수정(GATEFIX2) — 재검증 '조건부 통과'가 남긴 것

두 번째 독립 재검증은 '꺼진 채 병합 가능, 켜기 전 D1 해소'로 끝났다. 남은 것을 이렇게 처리했다.

| 번호 | 내용 | 처리 |
|------|------|------|
| D1 (높음) | 건강 C 미탐이 구조적으로 남음(검증자의 새 C 문장 105개 중 41개 통과) — ① 쉼표·느낌표·물음표가 조각을 가름 ② 부사와 효과 동사 사이 8자 상한 ③ 닫힌 증상 어휘 ④ 긴 절 앞 400자만 봄 ⑤ 효과 동사·활용 | **반영**(§3-2): 조각 나누기·구조 규칙·접미 규칙·겹치는 창·동사 확장. 105문장 미탐 41 → 0, 낱말 91개 중 86개(모호한 다섯 제외) |
| D2 | 허용 방향 오탐(몸 낱말이 기계·기술에 쓰인 문장 — 발열·관절) | **부분**: 줄이지 않고 숫자로 적었다(대조 42문장 중 2건 그대로) |
| D3 | Windows `O_TEMPORARY` 로 읽기 전용 열기 + 닫을 때 삭제를 훅이 못 막음 | **반영**: 쓰기 깃발에 `O_TEMPORARY` 추가, Windows 조건부 시험 |
| D4 | 한 낱말 외국 이름 + `대통령은`, 영어 `Name CEO` 어순을 직함 붙은 사람으로 못 읽음 | **반영**(§3 QG2-PERSON), 기관 이름·수식어·문장 첫머리 낱말은 제외 |
| D5 | 이미지 대체글·HTML 속성·링크 글자 속 단정 | **반영**(건강 규칙만 읽는다, §3 QG4-HEALTH), 코드 블록은 읽지 않는 한계를 적음 |
| D6 | (가) 통화 없는 근거 숫자가 금액을 받쳐 줌 (나) 포트·계정이 다른 주소를 같게 봄 | (나) **반영**, (가) **미반영**: 환산이 아닌 표기 차이를 살리려는 의도된 동작이라 한계로 적고 시험이 못박음(§9) |
| D7–D9 | 켜기 전 운영자 결정 6가지, 병합 메모 | 아래 목록과 병합 메모 |
| D10 | 시험이 못 잡은 변이 11개(U02·U03·U05·U06·U10·U13·U14·U15·U27, 동등 U22·U25) | **반영**: U05 는 결과를 바꾸지 않는 시간 방어(상수·호출 횟수로 고정, 모든 모양에서 결과 불변을 확인), 나머지는 입력 시험 추가 |

**켜기 전 운영자가 정할 것 6가지**

1. `quality_gate: hold`·`languages: ["ko"]`를 켜는 순서와 시점(T3). 권고는 국문 전용으로 먼저, Gate 는 그림자 실행 결과를 본 뒤.
2. 건강: ① 낱말 규칙의 '누락 0 보증 불가' 한계를 받아들일지 ② §9-1 의 사람 검토 절차를 채택할지 ③ 증상·질환 어휘 목록의 관리 책임자.
3. 근거 입력 보강(같은 피드의 본문 칸 사용)과 구조화 Fact 로 바꾸는 시점(FACT) — 요약이 얇으면 숫자·인용 규칙의 통과율이 낮다.
4. 켠 뒤 늘 수 있는 모델 호출의 한도(G-L5, T3) — 보류가 늘면 같은 실행 안에서 다음 후보를 더 시도한다.
5. 허용 도메인 목록(`PUBLIC_SOURCE_DOMAINS`)을 새 Source Allowlist·Tier 구조와 맞추는 일.
6. 그림자 실행 3회·평가 10편 계획(언제·누가 돌리고 누가 결과를 보나, 건강 인접 후보는 §9-1 절차로).

**병합 메모**: 이 묶음의 `docs/DEFECT_REGISTER.md` 행은 D-90(원래 행)과 D-150 이후다(D-140–D-148 은 소스 담당의 행). `docs/ACTIONS_GUIDE.md` 의 옛 글 파일 이름 패치(그림자 워크플로 안내의 `<번호>/post_ko.md`·`post_en.md` → `<번호>/날짜-KR-시각.md`·`날짜-EN-시각.md`)는 그 절이 이 가지에 없어 여기서는 적용할 수 없다 — 그림자 워크플로 묶음과 합칠 때 적용한다.

### 10-3. 3차 수정(GATEFIX3) — 세 번째 재검증 '조건부 통과'가 남긴 것

세 번째 독립 재검증(2026-11-10)은 '꺼진 채 병합은 안전, 켜기 전에 새 D1·D2(중간)를 고치거나 한계로 받아들이고 사람 검토를 채택'으로 끝났다. 이 수정은 '고치는' 쪽이다 — 낱말을 하나씩 더하는 대신 어간·어순·단위·목록 방향 하나로 한꺼번에 닫았고, 닫히지 않은 것은 §9-1 에 구체적으로 적었다. 새 D3(리눅스 CI 에서 실패할 시험)는 M037 병합 가지에서 이미 고쳤다.

| 번호 | 내용 | 처리 |
|------|------|------|
| 새 D1 (중간) | `…하고` 형용사 나열(`안전하고 부드럽게 줄여 줍니다`)을 행동 순서로 읽어 C 가 통과 | **해결**: `…하고·…하며·…하면서·…하여·…해서` 는 행동 낱말 목록에 있는 낱말 뒤에서만 행동. 검증자의 600문장 행렬에서 이 모양 미탐 120 → 0 |
| 새 D2 (중간) | 닫힌 목록 틈(활용 -ㄴ다·-었다·-ㄹ 수 있다·진 꼴, 효과 명사 뒤 부사, 시간 낱말, 동의어, 목록 밖 증상) — 검증자의 B·C 60문장 중 48 통과 | **완화(구조로 닫았으나 목록은 닫힌 채)·목록 밖 이름은 한계**: 어간 × 활용 끝 묶음, 효과 명사 어순, 시간 낱말 구조, 동의어. 60문장 중 통과 48 → 3, 활용 행렬 미탐 104 → 2 |
| 새 D4 (낮음) | 소수점·약어의 마침표가 본문 위치에서 문장 경계로 읽혀 단정이 갈림(`통증이 99.9% 즉시 사라집니다`) | **해결**: 마침표는 바로 뒤에 영문자·숫자가 붙지 않을 때만 문장 끝(`Dr.`·`Mr.` 호칭 제외) — 문장 단위 검사 두 곳과 제품 단정 정규식도 같은 경계 |
| 새 D5 (낮음) | 객체 낱말 판정의 후퇴(`허리 통증이 즉시 몸을 가볍게 풀어 주는 방석`), 시간 부사 + 명령형 면제 | **해결(후퇴)·설계 선택(면제)**: 사이의 대상이 몸 낱말이고 뒤에 부사뿐이면 효과 동사의 대상. 면제는 그대로 두고 §9-1 에 적음 |
| 새 D6 (낮음) | 허용 방향 오탐(한국어): `고질병`·`근시안적`·`탈염`·`디스크 어레이`·`…는지 확인` | **해결(일부)**: 예외와 묻는 절·부정 절. 몸 낱말이 기계·경제에 쓰인 문장은 한계(§3-2 숫자) |
| 새 D7 (낮음) | 허용 방향 오탐(영문): `congestion`·`depression`·`stress test`·`pain points` … | **해결(일부)**: 다른 뜻으로 흔한 낱말은 건강 맥락이 있거나 예외 앞말이 없을 때만 증상. 영문 25문장 중 걸림 23 → 3 |
| 새 D8 (낮음) | 대문자 약어 + 직함(`IMF 총재는`)을 인물로 읽어 QG2-PERSON 오탐 | **해결**: 대문자 2–5자로만 된 이름은 인물이 아니다(이름의 일부가 대문자인 `Kim Jong UN` 은 그대로 인물) |
| 새 D9 (낮음) | 숨은 글(대체글·`title` 속성·링크 제목)을 건강 규칙만 읽음 | **해결(일부)**: 숫자·인용·이름 규칙도 이미지 대체글·HTML 속성·마크다운 링크 제목을 읽는다(링크 글자는 제외 — §3-1). 코드 블록·그림 속 글자는 한계(§9) |
| 새 D13 (낮음) | 새 줄의 상수·경계·규칙 삭제를 시험이 못박지 않음(검증자 변이 N01·N02·N03·N06·N07·N09·N16·N21 생존) | **해결**: 정확히 120자·40자 경계, `하라`, `…하고` 행동 낱말 목록, `…염` 낱말 끝, 제품 단정 예외 낱말 하나하나, 전각 물음표를 시험이 못박는다 |
| 정보 D10·D11·D12 | 문서의 정직성(§3-2 '0개' 문구는 구현자 문장에 한정, §9-1 구체 구조, §6 의 `O_TEMPORARY`·자식 프로세스 한계), 제목 위치 정규화 | **반영**: 본문대로 고쳤고, 제목에도 본문과 같은 정규화(NFKC·보이지 않는 서식 문자 제거)를 쓴다 |

**켜기 전 운영자가 정할 것은 6가지에 하나가 더해져 7가지다**(1–6 은 §10-2 와 같다). **7번 보류 알림 경로**: 보류는 실행 요약과 `result.json` 에만 남고 운영자는 텔레그램 요청만 처리하므로 보류가 쌓이는 것을 알려면 정보 알림·확인 요청 중 어떤 길로 전할지 정해야 한다. 또 지금 `chance` 의 `publish_flow` 는 `direct` 라 '모든 글의 승인'은 `publish_flow: pr` 를 켜는 별개의 변경이므로, **일시정지를 풀기 전에 이 값이 `pr` 인 것이 켜기 조건**이다(제한 재개 순서: 정지 유지 → Gate → 그림자 검증 → `publish_flow: pr` 검증).

켜기 전 운영자가 정할 것 6가지는 §10-2 와 같다. 2번(건강)이 구체화된다 — 새 D1·D2 를 구조로 고쳤어도 '누락 0' 은 보증할 수 없으므로(§9-1) ① 그 한계를 받아들일지 ② §9-1 의 사람 검토 절차(**건강 인접 분류가 아니라 모든 글의 승인으로 닫는다**)를 채택할지 ③ 어휘·행동 낱말 목록(`_SYMPTOM_KO`·`_SYMPTOM_EN`·`_DO_VERB_STEMS`, 시험 목록 `tests/test_quality_gate_health.py`)의 관리 책임자를 정하는 것이다.

**병합 메모**: 이 묶음의 `docs/DEFECT_REGISTER.md` 행은 D-186–D-189 다(다른 묶음의 D-160–D-178·D-180·D-190–D-199 와 겹치지 않는다). 꺼진 상태(`quality_gate` 값이 없음)의 출력은 이 수정 앞뒤로 바이트까지 같다(§8 의 52쌍 비교를 다시 돌려 확인했다).
