# Copilot(과 다른 AI)을 정확하게 쓰는 방법 — 개발 지식 없이

> 이 문서는 개발자가 아닌 사용자를 위한 안내입니다. 기술 설명은 [`ISSUE_EDITS.md`](./ISSUE_EDITS.md)에 있습니다.
> Actions 탭에서 무엇을 언제 누르는지(수동 실행·빨간 ✗·자동 발행 멈추기)는 [`ACTIONS_GUIDE.md`](./ACTIONS_GUIDE.md)에 있습니다.

## 1. 무슨 일이 일어나고 있나

"앞부분만 읽고 뒤를 추정해서 반영한다"는 느낌은 AI 도구에서 실제로 일어날 수 있는 현상입니다. 도구가 긴 파일을 조각으로 읽거나 일부만 보고, **요청이 모호하면 빈칸을 추정으로 채우기** 때문입니다. 정확한 조각 크기(500자 등)는 도구 내부 사정이라 저희가 확인할 수 없지만, 그럴 수 있다는 전제로 구조를 만들었습니다.

그래서 해법은 "Copilot에게 더 자세히 말하기"가 아니라 **AI가 추정할 여지를 없애는 구조**입니다.

| 원칙 | 의미 |
|------|------|
| ① 요청을 정형화 | 위치(대상 페이지)·원문(변경 전)·결과(변경 후)를 양식으로 받는다. 개발 지식은 필요 없고 화면에서 복사해 붙이면 된다 |
| ② 정확해야 하는 일은 기계가 문자 그대로 | 변경 전/후를 알면 AI 없이 그대로 교체한다. 추정이 끼어들 수 없다 |
| ③ AI가 한 일은 자동 검증 후 사람이 병합 | 요청 밖 변경을 자동으로 찾아 PR에 알려 준다. diff를 읽을 필요가 없다 |

## 2. 사용 방법 (복사해서 붙이기만 하면 됩니다)

저장소 → **Issues → New issue → "고정 페이지 수정"** (또는 "기존 게시글 이미지 변경")을 고릅니다.

### 문구를 바꾸고 싶을 때 — 가장 정확한 방법
1. 블로그 화면에서 바꿀 문장을 **복사**해 `변경 전`에 붙여 넣습니다.
2. 바뀔 문장을 `변경 후`에 적습니다(**그대로 교체**됩니다).
3. 제출하면 잠시 뒤 이슈에 PR 링크가 달립니다. 내용을 보고 **Merge** 하면 반영됩니다.

예) 변경 전 `문의는 old@example.com 으로 보내 주세요.` → 변경 후 `문의는 new@example.com 으로 보내 주세요.` → AI 없이 이 한 문장만 바뀝니다.

### 그 밖의 경우
| 하고 싶은 일 | 양식에서 | 쓰는 방법 |
|--------------|----------|-----------|
| 링크 주소 바꾸기 | 수정 항목 `링크 변경` | 변경 전 = 현재 URL, 변경 후 = 새 URL |
| 페이지 제목·설명(SEO) | 수정 항목 `SEO 메타 수정` | 변경 후에 `title: 새 제목` / `description: 새 설명` 줄 |
| 글의 대표 이미지 | 양식 `기존 게시글 이미지 변경` | 글 주소(또는 정확한 제목) + 원하는 장면 설명 |
| 문장을 자연스럽게 / 구조 변경 | `문구 수정`(변경 전 비움) 또는 `섹션/레이아웃 변경` | 어느 문단의 무엇을 어떻게 — 한두 문장으로 |

`변경 전`을 비우면 AI가 파일 **전체**를 읽고 최소 수정안을 만듭니다. 그래도 범위(대상 파일 하나, 광고 코드·front matter 불변)는 자동으로 지켜지고, 내용이 맞는지는 PR에서 직접 확인하세요.

## 3. Copilot에게 직접 일을 시키고 싶을 때

이슈에서 오른쪽 **Assignees → Copilot** 으로 지정하면 Copilot 코딩 에이전트가 PR을 만듭니다. 이때:

1. 이슈를 **위의 양식으로 작성**하세요. 양식 내용이 가장 정확한 지시서입니다. Copilot은 [저장소 지침 파일](https://docs.github.com/en/copilot/reference/custom-instructions-support)(`.github/copilot-instructions.md`, `.github/instructions/*.instructions.md`)과 [`AGENTS.md`](https://github.blog/changelog/2025-08-28-copilot-coding-agent-now-supports-agents-md-custom-instructions/)를 읽으며, 우리는 거기에 "파일 전체를 읽고, 요청한 부분만 고치고, 모르면 멈춘다"를 적어 두었습니다.
2. Copilot이 올린 PR은 [사람이 **Approve and run workflows** 를 눌러야 검증이 돕니다](https://github.blog/changelog/2026-03-13-optionally-skip-approval-for-copilot-coding-agent-actions-workflows/) (기본 설정, 보안 때문). 눌러 주세요.
3. 잠시 뒤 PR에 **"요청 범위 검증"** 코멘트가 달립니다.
   - ✅ 통과 → 요청한 교체와 정확히 일치. 안심하고 병합하세요.
   - ⚠️ 확인 필요 → 범위 안이지만 AI가 쓴 문장이라 직접 읽어 보세요.
   - ❌ 요청 범위 밖 → 병합하지 말고 PR에 이렇게 답글을 다세요: **"요청한 부분만 바꾸고 나머지는 되돌려 주세요."**
4. 병합은 항상 사람이 합니다(에이전트는 자기 브랜치로만 push하고 승인·병합을 하지 못합니다).

## 4. Copilot Chat이나 다른 AI에 직접 말할 때 쓰는 문장 틀

> `about.md` 파일 **전체를 읽고**, "문의는 old@example.com 으로 보내 주세요." 문장만 "문의는 new@example.com 으로 보내 주세요."로 바꿔 줘. 다른 부분은 건드리지 마. 바꾼 줄 번호를 알려 주고, 문장을 못 찾으면 고치지 말고 알려 줘.

핵심은 세 가지입니다: **파일 이름 + 원문 그대로 + "다른 곳은 건드리지 마"**.

## 5. 저장소에 들어 있는 장치

| 장치 | 역할 |
|------|------|
| 이슈 양식(`page-edit.yml`, `blog_control.yml`) | 요청을 정형화. 대상 페이지 목록은 새 페이지가 생기면 자동 갱신 |
| `issue-edit.yml` | 양식으로 접수된 요청을 해석·검증·수정해 **PR로** 올림 (main 직접 반영 없음) |
| `pr-scope-check.yml` | 사람·Copilot이 만든 PR이 요청 범위를 지켰는지 자동 검증 후 코멘트 (`issue-edit`이 만든 PR은 만들기 전에 같은 검사를 이미 통과한다) |
| Copilot 지침 파일 | Copilot이 읽는 규칙(파일 전체 읽기, 최소 수정, 모르면 멈춤) |
| 사후 검증 | 광고 코드(`adsbygoogle`)·front matter·위험한 코드(`<script>` 등)·비밀 값이 바뀌지 않았는지 기계가 확인 |

## 6. 한계와 장기 개선

- 자동으로 **증명**할 수 있는 건 문자 그대로 교체·링크·SEO·이미지 교체입니다. AI가 문장을 쓰는 경우는 "범위 안인지"만 보장하고 내용은 사람이 확인해야 합니다.
- 장기적으로는 페이지 문구를 작은 데이터 파일(`_data/*.yml`)과 이름 있는 섹션으로 나누면 어떤 AI든 정확한 위치를 이름으로 찾을 수 있습니다. 광고 심사 페이지를 고치는 일이라 **사용자 승인 후** 진행해야 하며, 필요하면 말씀해 주세요.
- 큰 개편·새 기능은 이슈 양식이 아니라 작업 요청서를 AI에게 주고, 결과는 PR로 받아 검토하세요.
