# 품질 측정 그림자 모드 (`pipeline/quality_shadow.py`)

> **이 도구는 게시와 무관하다.** 글을 만들거나 올리거나 초안으로 보내는 어떤 흐름(`generator.py`·`pipeline/run.py`·워크플로·레지스트리)도 이 모듈을 **연결하지 않는다**(불러오지 않는다). **유일한 예외: 수동 그림자 워크플로의 별도 프로세스 호출** — `.github/workflows/chance-shadow.yml` 한 파일이 그림자 실행 뒤에 `python -m pipeline.quality_shadow …` 로 이 도구를 따로 띄우는 것만 허용한다(그 파일은 수동 실행 전용이고 모듈을 불러오지 않는다). 측정 결과가 발행·보류·탈락을 정하지 않는다. 연결하는 것은 별도의 T3 변경이며 운영자 채팅 승인이 필요하다. 연결 금지와 이 예외의 조건은 `tests/test_quality_shadow_guards.py` 의 소스 규칙 시험이 지킨다.
>
> **이 도구는 신호를 낼 뿐 제한 재개 조건을 단독으로 판정하지 못한다.** 무엇을 판정할 수 있고 무엇을 못 하는지는 §9 표에 있다(그림자 실행 횟수 기록·서로 다른 초안 증명·건강 C 누락 0·가짜 인용 0·결함 등급은 이 도구 밖의 일이다).

운영자 결정(2026-11-09, 확인 요청 006 항목 10 답 A): 게시 결과에 영향을 주지 않는 **그림자 모드**부터 진행하고, 독립 검증 뒤 결과만 보고한다. 설계 출처는 [`11_generator_improvement_plan.md`](./analysis/chance-content-2026-11-04/11_generator_improvement_plan.md) §1–§5(그림자 모드·검사 S1–S20·영향 시뮬레이션)와 [`12_quality_checklist.md`](./analysis/chance-content-2026-11-04/12_quality_checklist.md)이고, **한 가지가 다르다: 이번에는 실행 요약·설정 필드·생성기에 연결하지 않는 측정 전용 오프라인 도구**다. 변경 등급은 T2(`pipeline/` 코어)이며 구현자와 다른 주체의 독립 검증을 받는다(검증은 조건부 통과였고 지적 P1–P12 를 이 문서와 코드에 반영했다).

## 1. 한눈에

| 보장 | 어떻게 지키나 |
|---|---|
| 게시·초안 흐름에 연결하지 않는다 | `generator.py`·`blogger_generator.py`·`pipeline/`·`scripts/`·`.github/` 전체(워크플로·액션·양식)가 `quality_shadow` 를 한 글자도 담지 않는다는 시험 + 파이썬 소스를 AST 로 읽어 문자열을 이어 붙여 그 이름을 만들거나(`'quality_' + 'shadow'`) 동적 import·`eval`·`exec` 를 부르는 모양이 없다는 시험(사고 방지용 경보선이며 의도적 은폐까지 막지는 못한다). **유일한 예외: 수동 그림자 워크플로의 별도 프로세스 호출** — `.github/workflows/chance-shadow.yml` 한 파일만, 모듈을 불러오지 않고 `python -m pipeline.quality_shadow …`(또는 `python pipeline/quality_shadow.py …`)로 별도 프로세스에서 부를 때에 한해 이름이 나와도 연결로 읽지 않는다(주석·파일 존재 확인·`echo` 안내 문구의 이름도 허용). 그 파일이 수동 실행(`workflow_dispatch`) 하나만 트리거로 쓰는지도 같이 본다. 조건을 어기거나 다른 파일이 같은 일을 하면 연결로 읽혀 시험이 빨강이 되고, 그 파일이 없는 저장소에서는 예외 검사를 건너뛴다 |
| 네트워크를 쓰지 않는다 | 이 모듈이 불러오는 모듈이 표준 라이브러리 일부와 `pipeline.console`·`pipeline.gates` 뿐이라는 AST 시험(`from pipeline import llm` 같은 하위 모듈도 허용 목록과 견준다) + 동적 import·`eval`·`exec` 호출이 없다는 시험 + 깨끗한 프로세스에서 불러 봐도 네트워크·프로세스 모듈이나 다른 `pipeline.*` 모듈이 로드되지 않는다는 시험 + 분석을 도는 동안 소켓·`urlopen` 호출이 0회라는 시험 |
| 파일 쓰기는 `--out` 하나뿐 | 쓰는 호출이 `write_report` 한 함수에만 있다는 소스 시험. 입력 글 폴더 안·원문 폴더 안·입력 파일(글·원문, 링크 포함) 자체로는 쓰지 않는다(§2 `--out` 행) |
| 제한 재개 조건을 단독으로 판정하지 않는다 | 이 도구는 신호를 낸다. 12개 조건 가운데 끝까지 판정해 주는 것은 없다(§9) |
| 측정 불가는 0 이 아니라 `null` + 이유 | 모든 측정 묶음에 `null_reasons` 가 있고, 보고서의 `null` 값마다 이유가 있다는 시험 |
| 같은 입력에는 같은 출력 | 시각·난수·절대 경로를 쓰지 않는다. 날짜 기준은 `--as-of` 필수 인자 |
| 판정이 아니라 신호 | 하나의 점수로 합치지 않고 신호를 나눠 낸다. 신호를 판정에 쓰면 거의 모든 글이 걸려 게시가 멈춘다(11-04 개선안 §5-4) |

## 2. 사용법

```
python -m pipeline.quality_shadow --posts _posts --as-of 2026-11-09 --own-domain example.github.io --out 보고서.json
python -m pipeline.quality_shadow --posts _posts --as-of 2026-11-09 --own-domain example.github.io --out 보고서.md --sources-dir 원문폴더
python -m pipeline.quality_shadow --posts 후보글.md --as-of 2026-11-09 --source-text 후보원문.txt --detail
```

**권장 호출 인자**: 사이트의 글을 재는 호출(`--posts` 가 글 폴더)에는 **`--own-domain` 에 사이트 자신의 호스트 이름**(`_config.yml` 의 `url` 값에서 앞의 프로토콜 표시를 뺀 이름)을 항상 준다. 주지 않으면 사이트 자체 링크(내부 링크)가 **외부 출처 수**에 섞인다 — 되돌려보기에서 64편 중 2편의 도메인 수가 1개씩 늘었다. 이 도구는 `_config.yml` 을 읽어 기본값으로 쓰지 않는다(읽는 파일을 늘리지 않으려는 선택이므로 호출하는 쪽이 값을 준다). `--as-of` 는 항상 직접 준다. 보고서는 입력 폴더 밖에 쓴다(`--out` 행).

| 인자 | 뜻 |
|---|---|
| `--posts` | 글 폴더(`*.md` 를 재귀로 읽는다) 또는 글 파일 하나. 머리말(`---`)이 없는 파일은 글이 아니라서 `read_problems` 에 적고 건너뛴다 |
| `--as-of YYYY-MM-DD` | **필수.** 항목 7(행사)의 '아직 열리지 않았나/지났나' 기준일. 오늘 날짜를 기본으로 쓰지 않는다(재현성) |
| `--out` | 보고서를 쓸 파일. 없으면 표준 출력. **입력을 덮어쓰거나 입력 폴더에 섞이면 거절(종료 2)**: 글 폴더 안, 글 파일 하나를 줬을 때 그 파일이 든 폴더 안(글이 `_posts` 아래에 있으면 `_posts` 전체 — `.md` 보고서가 거기 생기면 글로 발행될 수 있다), 원문 폴더(`--sources-dir`) 안, 원문 파일(`--source-text`) 자체, 이름이 달라도 입력과 같은 파일(하드 링크), 이미 있는 폴더. 상위 폴더를 만들지 않으며 쓸 수 없는 위치도 트레이스백 대신 종료 2 로 알린다 |
| `--format` | `json` 또는 `md`. 기본은 `--out` 확장자가 `.md` 면 md, 아니면 json |
| `--sources-dir` | 원문 텍스트 폴더. 글마다 `<글 이름>.txt`·`<날짜>-<6자리>.txt`·`<6자리>.txt`(각각 `.md` 도 가능) 순서로 찾는다 |
| `--source-text` | 글 파일 하나를 잴 때 쓰는 원문 텍스트 파일 |
| `--detail` | 글마다 주장 문장 목록도 싣는다 |
| `--own-domain DOMAIN` | 자기 사이트 도메인(여러 번 쓸 수 있다). 이 도메인으로 가는 링크(내부 링크)는 **외부** 출처로 세지 않는다. **주지 않으면 내부 링크도 외부 출처 수에 섞인다(경고)** — 권장 호출 인자는 위 상자를 본다. 값은 도메인 이름이어야 하고(주소·경로는 거절, 종료 2) 보고서에는 개수만 남는다(`options.own_domain_count`) |

종료 코드: 0 정상 · 1 읽거나 분석하지 못한 글이 있거나 측정한 글이 하나도 없다(보고서는 만들었고 `read_problems` 에 적었으며 빈 폴더는 경고를 낸다) · 2 인자·설정 오류(쓸 수 없는 `--out` 포함). 글 하나를 준비·비교·분석하다 예외가 나면 그 글(또는 그 짝)만 `read_problems` 에 `분석 중 예외(예외 종류)` 로 적고 나머지는 계속 잰다(예외 문구는 입력 내용이 섞일 수 있어 싣지 않는다). 글은 UTF-8, 한 파일 2 MB 까지, 본문 한 줄은 5,000자까지만 읽는다(더 긴 줄은 잘라 읽고 글마다 `body.long_lines_truncated` 로 알린다). 이 도구의 정규식은 입력 길이에 비례해서만 느려지게 짜 두었고 줄 상한은 그 위의 보험이다 — 공백이 4,000칸 이어진 줄(모양 8가지)·공백이 길게 이어진 줄 250개·날짜가 16,000개 든 112 KB 단락·550 KB 원문 텍스트·5,000자리 숫자 줄 40개의 시간 시험이 지키고, 모듈의 컴파일된 정규식 212개를 모양 1,664가지로 키워 가며 재고(남은 의심은 `{1,20}`·`{0,300}` 같은 상한이 있는 반복, 15밀리초 문턱 근처의 측정 잡음, 그리고 `search` 로 재면 제곱이지만 코드가 `fullmatch` 로만 쓰는 `--own-domain` 패턴뿐이었고, 확인한 것들은 길이를 4배로 하면 시간도 4배였다) 글 전체 분석을 한 줄 모양 5,264가지(반복 조각 47종 × 앞 표지 16종 × 뒤 표지 7종)와 여러 줄 17가지로 길이를 두 배로 재어 제곱 이상으로 느려지는 곳이 없음을 확인했다(재탐색에서 숫자 연속·크레딧 줄·표 구분선·인용 줄·점이 수천 개인 호스트의 제곱 시간을 찾아 고쳤다). **예외 하나**: 빌려 쓰는 프로필 규칙 가운데 국문 용량 규칙(`\d+ … mg`)은 숫자가 길게 이어지면 연속 길이의 제곱 시간이다(4,000자리 한 줄에 0.74초). 이 도구는 그 규칙에 **20자리를 넘는 숫자 연속을 20자리로 줄여서** 넘기고(`숫자 + 단위`는 그대로 찾힌다) 규칙 파일(`pipeline/gates.py`·프로필)은 고치지 않는다 — 실제 게시 흐름의 게이트도 같은 규칙을 쓰므로 그쪽은 별도로 점검할 일이다.

### 보고서 모양

최상위 `tool`·`schema_version`·`as_of`·`note`(게시와 무관 선언)·`thresholds`(이 실행이 쓴 임계값)·`options`(`own_domain_count`·`detail`)·`posts`(글별)·`pairs`(한·영 짝별)·`read_problems`·`summary`. 글 하나는 `path`(입력 폴더 기준 상대 경로)·`date`·`lang`·`pair_key`·`published`·`title` 과 측정 묶음 여덟 개(`claims`·`grounding`·`sources`·`added_value`·`press_release_summary`·`event_focus`·`health_risk`·`topic_fit`), 짝 요약 `pair` 를 가진다. 항목 5는 `pairs` 와 글의 `pair` 에 있다.

**`null` 규약**: 측정할 수 없으면 값은 `null` 이고 같은 묶음의 `null_reasons` 사전에 `{키: 이유}` 가 있다. 0 은 '측정했더니 0'이다. 예) 원문도 링크도 없는 글의 `grounding.supported` 는 `null`, 원문 주소는 있으나 본문 링크가 없는 글은 `0`. 목록 값(`profile_body_rule_hits`)은 빈 목록이 '측정했고 걸린 것 없음', `null` 이 '프로필을 못 읽어 측정 못 함'이다.

## 3. 아홉 항목의 정의

(운영자 지정 9가지. 규칙 기반이라 오탐·누락이 있고, 판정이 아니라 '사람이 먼저 볼 순서'를 정하는 신호다.)

### 항목 1 — 핵심 사실 주장 수

**주장 문장** = 본문의 서술 문장 가운데 **숫자·날짜·퍼센트·금액·고유명사(기관·인물·지명)가 하나라도 든 것**. `claims.total`(전체)·`numeric`(숫자·날짜·퍼센트·금액이 든 것 — 더 믿을 만한 수)·`entity_only`(고유명사만 든 것 — 오탐이 가장 많은 쪽)·`by_anchor`(앵커 종류별 문장 수)·`claim_ratio`(주장 문장 ÷ 전체 문장).

세지 않는 것: 제목·소제목, 출처 목록, 이미지·크레딧·인용 줄(`“제목.” Source: …`·`Adapted from …`)·AI 고지 줄, 블록 인용(`>`), 따옴표로 시작해 따옴표로 끝나는 문장(인용문 자체), 물음표로 끝나는 문장, 12자 미만 조각, 주소 속 숫자, 단위 목록에 없는 영문자가 붙은 식별자(`G1`·`COP31`·`5G`·`21st`)·통화 기호 없는 `3M`(회사 이름)·`4K`(해상도)·이름에 붙은 수(`코로나19`)·`제10조`·소수점 아래가 15자리를 넘는 수와 천 단위 쉼표 묶음에 목록에 없는 글자가 붙은 수(`1,000x`·`10,000s` — 앞부분 1·10 만 잘라 읽어 틀린 값을 내지 않으려고 읽지 않는다. `2026,2027`·`1,2,3` 처럼 쉼표로 이은 목록은 따로 읽는다). 표는 머리 행을 빼고 **행마다 한 문장**으로 센다. 목록 항목 맨 앞의 굵은 소제목(`**허위 광고:**`)은 고유명사 후보에서 뺀다.

숫자는 값으로 바꿔 둔다: `4,975만 달러` = `$49.75 million`, `4조 2천억 원` = 4.2조(이어 붙은 한국어 단위를 합친다), `1.2 trillion`, `3.2bn`. 영문 단위가 **바로 붙은** 수는 쓴 그대로의 값으로 읽는다(`3.5GHz`=3.5·`12.5km`=12.5·`100MW`=100·`155mm`=155 — 단위 환산은 하지 않는다). 통화 기호 뒤의 규모 약어는 값이다(`$5M`·`€3M`=백만, `$2.5B`=십억, `$300K`=천). 한글에 붙여 쓴 수는(`약5%`·`총3명`·`연2회`·`월10만원`·`전년대비12%`·`올해12월`·`약3억원`) 단위·퍼센트·개수 낱말이 따라올 때만 읽는다. 날짜는 국문(`2026년 11월 3일부터 5일까지`·`11월 3–5일`)·영문(`November 3 to November 5, 2026`·`3 November 2026`)·ISO 를 읽고, 일 없이 월만 적은 `2026년 11월`·`November 2026` 은 월 단위 날짜로 읽으며, 연도가 없으면 **글 날짜에서 가장 가까운 해**로 본다. 연도 없는 **기간**(`1월 1일–10월 24일`)은 끝 날짜의 해를 먼저 정하고 시작은 같은 해(끝보다 늦으면 그 전해)로 둔다. 월 뒤의 수가 일(日) 표시 없이 개수·퍼센트 낱말을 달면(`3월 20개 사업`·`5월 15명`·`6월 30% 증가`·`9월 10건`) 날짜가 아니라 숫자다.

**오탐·누락 가능성**: 고유명사는 영문은 대문자로 시작하는 낱말열·약어(문장 첫 낱말 하나만 대문자인 것·`AI` 같은 일반 약어는 제외), 국문은 기관 접미사(…위원회·…연구소·…통계청 등)와 나라·지역 이름표뿐이다 — **한글로 적은 인명은 못 찾고**, 제목체 소제목이 문장 속에 섞이면 오탐한다. 일상어와 겹치는 지명('이란'·'인도')은 오탐이 잦아 이름표에서 뺐다(못 찾는 쪽을 택함). 그래서 `numeric` 이 `total` 보다 안정적이다. **`claims.total` 은 사실 진술의 수가 아니다** — 고유명사(약어·영문 이름) 한 낱말이면 세므로 사실을 말하지 않는 문장이 많이 섞인다(되돌려보기에서 `entity_only` 가 `total` 의 절반 안팎이었다). 믿을 값은 `numeric` 이다. 한계: 영문 단위는 쓴 그대로 읽을 뿐 환산하지 않아(`0.1GW` 와 `100MW` 는 다른 값) 단위가 다른 표기는 원문과 맞춰 볼 때 어긋남으로 나올 수 있고, `3월` 처럼 월만 적은 수는 숫자 3 으로 읽혀 원문의 `March` 와 맞춰지지 않는다.

### 항목 2 — 공식 근거로 지원되는 주장 수

- **원문 텍스트가 주어진 경우**(`--sources-dir`·`--source-text`, `mode: source_text`, `approximate: false`): 주장마다 핵심 토큰이 원문에 있는지 본다. **숫자·날짜는 모두 원문에 있어야** 하고(값으로 비교 — 국문 `4,975만` 과 영문 `$49.75 million` 이 같다. 1–12 의 정수는 영어 낱말 `four` 같은 것도 인정), 숫자·날짜 없이 고유명사만 든 문장은 낱말 하나(앞 6글자)라도 원문에 있으면 지지로 본다(느슨한 확인). 결과는 `supported`·`unsupported`·`unverifiable`(한글 고유명사만 있어 영문 원문과 맞출 수 없는 문장). 원문에 없는 환산·반올림·파생 수치(예: 원문에 없는 `4조 2천억 원`)가 `unsupported` 로 잡힌다. **한계**: 숫자는 값만 비교하므로 단위·대상이 바뀐 수치(같은 3 인데 GHz 가 아니라 GB)는 통과하고, 숫자 없는 주장은 기관 이름만 원문에 있으면 지지로 보며, **따옴표 인용문은 검사하지 않는다** — 지어낸 인용·지어낸 기능 설명도 지지로 나올 수 있다(§9).
- **원문이 없는 경우**(과거 글 되돌려보기, `mode: inline_link_approx`, `approximate: true`): **같은 문단에 공식 기관·연구기관 본문 링크가 붙은 주장 수**를 근사치로 낸다(`supported`). `linked_in_sentence`(같은 문장)·`linked_in_paragraph`(같은 문단, 아무 외부 링크)·`linked_official_in_paragraph`(=`supported`)도 함께 낸다. 이미지 크레딧·라이선스 링크는 근거로 세지 않는다. **링크가 있다고 그 주장을 뒷받침하는 것은 아니다** — 되돌려보기에서 감사의 근거 판정(충실·경미한 문제·근거 없는 주장)과 이 비율은 거의 무관했다(§6). 사실 정확성의 지표로 쓰지 않는다. 출처를 글 끝 출처 목록에만 모아 적고 본문에는 링크를 달지 않은 글은 도메인이 있어도 0 이 된다 — 이름은 지원되는 주장 수이지만 실제로는 '같은 문단에 공식 링크가 붙은 주장 수'다.
- **원문이 전혀 없는 경우**(원문 텍스트·머리말 `source_url`·본문 링크가 모두 없음, `mode: unavailable`): 값은 모두 `null` 과 이유.

### 항목 3 — 출처 수

`sources`: `distinct_domains`(서로 다른 외부 출처 **등록 도메인** 수 — `science.nasa.gov` 와 `www.nasa.gov` 는 하나, `statcan.gc.ca`·`mfds.go.kr` 처럼 `gc.ca`·`go.kr` 등 두 칸 공공 접미사를 인식)·`distinct_hosts`·`domains`·`body_links`·`body_links_unique`·`front_matter_source_url`·`source_url_in_text`(머리말 주소가 본문·출처 목록에 있나)·`sources_section_present`·`sources_list_items`·`citation_line`. 도메인 집계는 머리말 `source_url` + 본문 링크 + 출처 목록 링크 + 인용 줄 링크의 합이다. **세지 않는 것**: Unsplash 작가·사이트 같은 이미지 크레딧 링크, 마크다운 이미지 문법으로 넣은 이미지 주소, CC BY·OGL 같은 라이선스 본문 링크(인용 줄에 붙는다), 이미지 크레딧 링크뿐인 출처 목록 항목, `--own-domain` 으로 준 자기 사이트 링크. 빼 버린 링크 수는 `image_credit_links_excluded`·`license_links_excluded`·`own_site_links_excluded` 로 알린다. **`--own-domain` 을 주지 않으면 사이트 자체 링크가 출처 수에 섞인다**(§2 권장 호출 인자). 주소를 견주는 곳(`source_url_in_text`·`body_links_unique`·`shared_links`·한·영 `same_source_url`)은 소문자 호스트·앞의 `www.`·`http`/`https`·끝 슬래시·fragment·추적 쿼리(`utm_*`·`ref`·`fbclid` 등)·쿼리 순서 차이를 같게 본다. 깨진 모양의 주소(`[`·`]` 가 짝이 안 맞는 IPv6 표기 등)는 라이선스 본문으로도 도메인으로도 세지 않고 링크 하나로만 센다(분석을 멈추지 않는다). 분류(`categories`·`official_domains`)는 **호스트** 기준이다 — 같은 등록 도메인 안에도 학회(`ieee.org`)와 그 매거진(`spectrum.ieee.org`, 언론)처럼 성격이 다른 호스트가 있다.

출처 목록 제목은 `## 출처`·`### Sources`·`**Source**`·`**출처 및 참고자료**`·`### 참고 자료` 등 열여섯 가지 모양을 읽는다(`## 이미지 출처` 는 출처 절이 아니다). 출처 절 뒤에 새 소제목이 나오면 본문으로 돌아가고, 출처 목록 뒤의 소제목 없는 문단은 본문으로 세지 않는다.

### 항목 4 — 원문 대비 추가 가치(신호를 나눠 낸다 — 점수 하나로 합치지 않는다)

- 나쁜 신호: `unsupported_addition_ratio` = 원문과 대조할 수 있는 주장 중 원문에 없는 주장의 비율(항목 2 의 원문 모드). **원문이 없으면 `null`** 과 이유.
- 직접 작업 신호: `table_data_rows`(표 데이터 행 수)·`own_calculation_markers`(글쓴이가 직접 계산했다고 밝히는 표현 — `직접 계산`·`계산하면`·`we calculated`·`our analysis` 등. '통계청이 산출한'처럼 출처의 계산이나 `환산`이라는 낱말 자체는 세지 않는다 — 원문에 없는 환산은 가치가 아니라 근거 없는 추가다)·`comparison_markers`(`비교`·`대비`·`차이`·`compared` 등 — 흔한 낱말이라 보고만 하고 판정에 쓰지 않는다)·`distinct_domains`·`distinct_official_domains`.
- `own_work_signals_present` = 표 행이 있거나 직접 계산 표현이 있거나 **공식 도메인이 둘 이상**. (항목 6·9 가 '추가 가치 신호가 약함'을 이 값으로 읽는다.) 한계: 같은 발표를 두 공식 사이트에 함께 올린 경우(연구원과 상위 연구회 등)도 둘로 센다. 표는 모양일 뿐 분석인지 알 수 없다.

### 항목 5 — 한·영 유사도

같은 **날짜 + 파일 이름 끝 6자리**(`pair_key`)의 국문·영문 글을 짝으로 묶는다. 6자리(시각)만으로는 날짜가 다른 글이 겹친다(10-26 과 10-29 에 같은 키가 있다). 짝마다: `structure`(소제목·문단·불릿 수 — 정확히 같은 항목 수 `matched`, 차이가 ±`CLONE_STRUCTURE_TOLERANCE` 이내인 항목 수 `within_tolerance`)·`number_jaccard`(**의미 있는 숫자** 집합의 자카드 — 연도와 31 이하 정수는 뺀다)·`shared_links`·`length_ratio_en_per_ko`(본문 글자 수, 공백 제외)·`same_source_url`.

`translation_clone_suspected` 는 아래 셋을 **모두** 만족할 때 참이다: ① 세 개수의 차이가 모두 ±1 이내 ② 숫자 자카드 ≥ 0.5 이거나 양쪽에 의미 있는 숫자가 없음(`null`) ③ 길이 비율이 1.2–3.0 안. **출처 주소가 서로 다르면(표기 차이를 정규화한 뒤에도 `same_source_url` 이 거짓) 번역 짝인지 판정하지 않는다** — 값은 거짓이 아니라 `null` 이고 `null_reasons` 에 이유 코드 `source_url_differs` 가 적힌다(파일 이름 끝 6자리만 같은 전혀 다른 글일 수도 있고, 같은 글을 다른 주소로 가리킨 번역일 수도 있어 단정하지 않는다). 이때도 구조·숫자·길이는 참고로 적고, 요약에는 `translation_clone_undetermined`(보류한 쌍 수)가 따로 있다. 한쪽 주소가 없으면 `same_source_url` 이 `null` 이고 구조·숫자·길이로만 본다. 임계값은 §5 표에 있다.

**참고 신호(판정에 쓰지 않는다)**: 구조 하나에만 기대지 않도록 두 글이 나누는 내용을 따로 적는다 — `ref_numbers_jaccard`(본문의 **모든** 숫자 값과 날짜의 자카드 — 연도·31 이하 정수도 포함하므로 판정용 `number_jaccard` 보다 넓다)·`ref_names_jaccard`(영문 고유명사의 자카드 — 한글 이름은 못 찾는다)·각각의 공유 개수 `ref_shared_numbers`·`ref_shared_names`. 합집합이 비면 `null` 과 이유다. 시험이 이 신호를 비워도 모든 판정이 같음을 확인한다.

한계: 구조 일치는 '번역 복제'의 필요조건에 가깝지 충분조건은 아니다(같은 틀로 쓴 서로 다른 글도 걸린다). 합성 독립 각색 8쌍(같은 틀·다른 문장) 시험에서는 5쌍이 걸러지고(숫자·길이 규칙) 1쌍은 주소가 달라 보류되며 **2쌍이 걸린다** — 같은 틀·같은 주소(또는 주소 없음)·숫자 없음·길이 비율 범위 안인 독립 글은 못 거른다. 이때 참고 신호(영문 이름 겹침 0)가 사람에게 단서를 준다. 의미 없는 번역인지(독자 가치)는 보지 않는다. 국문만 재개하면 짝이 없어 번역 복제는 항상 0쌍이라 '통과 0'은 공허하게 참이다(§9).

### 항목 6 — 보도자료·회사 발표 단순 요약 여부

`press_release_summary.flag`(참·거짓·`null`)와 `kind`:
- `company_release_summary`: 첫째 근거(머리말 `source_url`, 없으면 본문 첫 링크)가 **회사 도메인**이고, 출처가 그 도메인 하나이거나 공식 출처 없이 회사 도메인뿐이며, 직접 작업 신호가 없다.
- `official_press_release_summary`: 첫째 근거가 **공식 도메인**인데 주소가 **강한 보도자료 형식**(`press`·`release(s)`·`newsroom`·`보도자료` 조각)이고, 출처가 하나이며, 직접 작업 신호가 없다. (1차 자료이긴 하나 보도자료를 다시 쓴 데 그친 글.)
- `press_format_summary`: 분류표에 없거나 언론·기타 도메인인데 **보도자료·공지 형식 주소**이고 위 조건을 모두 만족. 형식 주소 = 강한 조각(`press`·`release(s)`·`newsroom`·`보도자료`) 또는 `announcement`·`notice`·`pr` 같은 약한 조각. **`/news/` 조각 하나만으로는 켜지지 않는다**(언론 기사 주소에 흔한 낱말이라 보도자료가 아닌 기사가 걸리던 것을 고쳤다 — 이름 '보도자료 형식 요약'과 정의를 맞췄다).
- `none`: 위에 해당 없음. 근거 주소가 전혀 없으면 `flag`·`kind` 는 `null` 과 이유.

공식 기관의 `/news/` 경로는 보도자료가 아니라 소식·기사인 경우가 많아 강한 조각만 센다. 분류표에 없는 회사 도메인은 회사로 짐작하지 않는다(`unknown`) — 누락이 오탐보다 낫다는 선택이다. **커버리지 한계**: 회사로 분류하는 도메인은 표에 이름이 있는 16개뿐이라 표에 없는 회사(예: 현대·SK하이닉스·TSMC·네이버·카카오·IBM·보잉)는 `unknown` 이 되어 회사 발표 요약을 판정하지 못하고 주제는 `borderline` 이 된다. 표에 없는 정부·통계·학술 사이트(여러 나라 정부·통계청·학술지)도 마찬가지다.

### 항목 7 — 행사 안내 중심 여부

본문 문장 가운데 **행사 신호어**(행사·개최·참가·참석·접수·박람회·엑스포·컨퍼런스·부스·설명회·공청회·간담회·토론회·`event`·`expo`·`conference`·`seminar`·`forum`·`hearing`·`briefing`·`town hall`·`open house`·`roundtable`·`will take place`·`attend`·`register` 등 `EVENT_TERMS`)가 든 문장의 비율과 서로 다른 신호어 종류 수, 제목의 신호어를 본다. **행사 안내 중심(`flag`)** = (신호어 문장 비율 ≥ `EVENT_SENTENCE_RATIO_MIN` 이고 서로 다른 신호어 ≥ `EVENT_DISTINCT_TERMS_MIN`) 이거나 (제목에 신호어가 있고 비율 ≥ `EVENT_TITLE_RATIO_MIN`). `부스트`(boost)·`참가국` 같은 다른 뜻의 낱말은 신호어에서 뺐다. **한계**: 낱말 기반이라 행사를 *해설하는* 정상 분석 글(정상회의 결과 해설·포럼 보고서 해설 같은 합성 글에서 확인)도 걸릴 수 있고, 사전에 없는 말로 쓴 행사 안내는 놓친다. 행사가 아닌 실제 글의 최고 비율(0.176)과 임계값(0.2)의 간격이 좁아 경계 양쪽(0.19 는 아니고 0.20 은 맞다, 제목 규칙의 0.14·0.15)을 시험으로 못박았다.

날짜: 본문의 날짜(일 단위)를 읽어 `dates_after_post_date`·`dates_after_as_of`(기준일 이후)를 낸다. `date_status` 는 행사 여부와 별개로 글에 적힌 날짜의 상태다 — `upcoming`(기준일 이후 날짜가 있음 = 아직 열리지 않은 행사 가능성), `past_event_dates`(글 날짜 이후이고 모두 기준일 이전 = **지난 행사 안내, 낡은 글**), `no_event_dates`. 날짜 기준이 필수 인자라 같은 글도 기준일에 따라 상태가 바뀐다. 본문이 비면 `flag` 는 `null`.

### 항목 8 — 건강 위험 판정

`health_risk.level` = `none` · `caution`(주의) · `high`(높음), `reasons` 에 이유.
- **강한 의료어**(질환·질병·치료·약물·복용·보충제·영양제·체중 감량·임신·영유아·증상·감염·환자·수술·당뇨·혈압·우울증·자살 …, 영문은 낱말 경계를 지킨다 — `diagnostics` 는 의료 진단이 아니다): 하나만 있어도 `caution`.
- **약한 의료어**(진단·부작용·처방·중독·접종·의료·병원·건강·의사 …)·**안전 인접어**(사망·사고·부상·유통기한·소비기한·섭취·독성·식품 안전·폭력·학대 …): **서로 다른 종류가 둘 이상**이어야 `caution`(같은 낱말을 여러 번 써도 하나로 센다). 소비기한·사망 통계 같은 건강·안전 인접 글을 잡으려는 것이다.
- `high`: ① 강한 의료어와 **단정 표현**(반드시·확실히·입증·완치·보장·`definitely`·`proves`·`cures` …)이 **한 문장**에 있다 ② 강한 의료어와 **행동 지시**(`복용하세요`·`끊으세요`·`you should take` …)가 한 문장에 있고 같은 문장에 상담 안내(의사·전문가와 상담 등)가 없다 ③ 효능 단정 규칙(완치·만병통치·특효·`부작용 없음` …)에 걸린다.
- **`pipeline/gates.py` 재사용(읽기 전용)**: Chance 에는 자체 프로필이 없어 같은 위험 영역을 막는 Blogger 실용 프로필(`pipeline/profiles/blogger_practical_ko.json`·`…_en.json`)의 본문 규칙(`body_risk_hit`)과 효능 단정 규칙(`banned_patterns`)을 빌려 증거로 낸다(`profile_body_rule_hits`·`profile_banned_hits`). 본문 규칙에 걸린 것은 약한 신호 **하나**로만 센다(그 규칙은 '증상·진단·의료' 낱말 하나만 있어도 걸리게 엄격해 단독으로 `caution` 을 만들면 노이즈가 크다). **같은 낱말을 둘로 세지 않는다**: 프로필 규칙이 맞춘 낱말이 이 도구의 의료어 사전(강·약·안전)에 이미 있으면(`진단`·`처방`·`접종`·`의료`·`medical`·`drug`·`treatment` …) 서로 다른 신호로 더하지 않고, 사전에 없는 낱말(`비만`·`항생제`·`임상`·`pills`·`insulin` …)일 때만 약한 신호 하나로 더한다(`profile_adds_signal`). 그래서 설비 '진단'이나 비유로 쓴 'medical' 한 낱말만 든 평범한 글은 `none` 이다. 프로필이 맞춘 낱말은 첫 번째 것만 본다. 프로필을 못 읽으면 두 값은 `null` + 이유이고 자체 사전만으로 판정한다.

이 항목은 **건강 낱말 검출기**이지 일반 위험 검출기가 아니다. 감사가 지적한 위험(원문에 없는 환산, 출범일 오류, 과학 단정 오류 같은 사실 정확성 문제)은 이 항목으로 못 본다(§6).

**건강 판정의 한계(중요)**: 이 항목의 신호는 운영자의 **A/B/C 규칙이 아니라 낱말 기반 신호**다. 운영자의 건강 C 예시 9개에 이 도구를 돌려 보면 6개를 놓친다(독립 검증 §6 ⑦ — A/B/C 와 `none`/`caution`/`high` 의 대응은 C 를 `high` 로 가정): `high` 로 잡는 것은 `영양제로 불면이 바로 치료됩니다`·`당뇨 100% 보장`·`암 완치 보장` 셋이고, `이 영양제는 피로를 즉시 없애줍니다`·`당뇨를 무조건 개선하는 식품` 은 `caution` 에 그치며, `수면제 바로 끊어도 될까`·`피로를 즉시 줄이는 방법`·`자세를 바로 교정하는 책상 설정`·`통증을 완전히 없애는 의자 선택법` 은 `none` 이다. 즉시·바로·완전히·무조건 같은 단정어와 효과 동사의 짝, 통증·피로·수면제 같은 낱말이 사전에 없기 때문이다. **실제 건강 C 자동 중단은 Gate 쪽 규칙의 몫이며 이 도구가 대신하지 않는다.** 이 도구의 사전을 고쳐 C 를 잡게 만들려고 하지도 않는다(범위 밖 — 한계를 정직하게 적는 것까지). `caution` 은 인접 주제(소비기한·사망 통계)까지 넓게 잡는 '사람이 먼저 볼 순서'일 뿐이다.

### 항목 9 — 주제 적합성

운영자 기준(결정 12): Chance 중심 주제 = 공공기관 1차 자료·연구기관 자료·공식 통계·정부 정책·법령·국제기구 자료·공식 관측자료. 회사 발표 단순 요약·행사 일정 안내·한 줄 인용을 늘린 글·보도자료 재작성·의미 없는 한·영 번역 쌍은 독립 분석·추가 가치가 부족하면 비공개·통합 후보이고, 회사 자료를 완전히 금지하지는 않지만 **회사 발표만 근거인 글은 핵심 주제가 아니다**.

`topic_fit.fit` = `core` / `borderline` / `off` / `null`:
- `core`: 첫째 근거가 **공식 도메인**(공공기관·연구기관)이고 행사 안내 중심(항목 7)도, 보도자료를 요약만 한 글(항목 6)도 아니다.
- `borderline`: 첫째 근거가 공식인데 위 둘 중 하나에 걸린다 / 첫째 근거는 회사·언론이지만 다른 출처에 공식 도메인이 있다 / 첫째 근거 도메인이 분류표에 없다(사람이 확인).
- `off`: 공식 기관·연구기관 출처가 없고 첫째 근거가 회사·언론·기타다.
- `null`: 근거 주소(머리말 `source_url`·본문 링크)가 없어 출처를 분류할 수 없다.

주제 적합성은 **출처 종류**를 보는 것이다. 공식 사이트가 낸 인물·미담 기사처럼 도메인은 공식이지만 주제가 자료 해설이 아닌 글은 `core` 로 나온다(한계, §6). 한 줄 인용을 늘린 글과 의미 없는 번역 쌍은 이 항목이 아니라 항목 1(주장 밀도)·항목 5가 각각 단서를 줄 뿐이다.

## 4. 도메인 분류표

`DOMAIN_RULES`(도메인 끝부분 → 분류)가 정본이다. 분류: `public_agency`(정부·공공기관·공식 통계·국제기구·공식 관측)·`research`(연구기관·대학·학회·여론조사 연구소·학술지)·`company`·`news_media`·`other`(이미지 제공처·SNS·위키)·`unknown`(분류 못 함). 공식 = `public_agency` + `research`. 가장 긴 끝부분이 이기고(`spectrum.ieee.org` 는 언론, `ieee.org` 는 연구, `nst.re.kr` 은 공공, `re.kr` 은 연구), 표에 없을 때는 `.gov`·`.mil`·`.int`·`.edu`·`.ac.kr` 같은 모양 규칙만 쓴다. **회사는 표에 이름이 있는 것만 회사다.**

표의 근거: 운영자 기준(결정 12)의 예시와 `generator.py` 의 `NEWS_SOURCES`·`TRUSTED_SOURCE_DOMAINS`·`TERMS_BLOCKED_DOMAINS`. 예) `nasa.gov`·`europa.eu`·`statcan.gc.ca`·`ftc.gov`·`federalreserve.gov`·`nsf.gov`·`gov.uk` 는 공공, `pewresearch.org` 는 연구기관, `openai.com`·`onepredict.ai` 는 회사. **표가 낡지 않게**: 시험(`test_quality_shadow_guards.py`)이 `generator.py` 의 모든 소스·신뢰·약관 차단 도메인이 `unknown` 이 아닌지, 읽는 소스(약관 허용·보류)가 모두 공식으로 분류되는지 대조한다. 소스를 더하면 이 표도 같은 변경에서 고친다.

(되돌려보기 산출물 자체는 저장소에 올리지 않는다. 재현: **같은 코드**로 같은 글 스냅샷에 같은 `--as-of`·`--own-domain` 을 주면 바이트까지 같은 보고서가 나온다. 코드를 고치면 값이 바뀌므로 산출물은 코드 판별 값(`quality_shadow.py` 의 sha256 앞 12자 또는 커밋 해시)과 짝지어 따로 보관한다 — 보고서 JSON 에 그 값을 넣지는 않는다(결정성·기존 소비자 호환).)

- **번역 복제**: 감사가 번역 복제로 본 22쌍 중 **21쌍을 잡았고**, 독립 각색 2쌍과 파일 이름 끝 6자리만 같은 서로 다른 글의 짝(영문 JAXA 글 ↔ 국문 다른 글)을 옳게 걸렀다. **'오탐 0'은 이 음성 표본 3쌍에서의 값이라 근거가 약하다** — 같은 틀로 따로 쓴 합성 독립 각색 8쌍에서는 5쌍이 걸러지고 1쌍이 보류되며 2쌍이 걸렸다(§3 항목 5). 놓친 것은 직접 손질한 초기 쌍(식품 날짜 쌍: 문단 수가 둘 다르고 영문에 숫자가 없다) 하나다. 번역이 구조를 ±1 넘게 바꾸거나(문단 둘 합침·불릿 추가) 길이 비율이 범위를 벗어나면 풀린다 — 이 판정은 번역 복제의 필요조건 신호이지 증명이 아니다. 주소 표기만 다른 번역 쌍은 이제 풀리지 않는다(주소 정규화). 되돌려보기 31쌍에는 출처 주소가 서로 다른 쌍이 없어(주소가 없는 쌍 3쌍) 보류로 바뀐 쌍은 0이다. 참고 신호는 의심 아님 7쌍에서 모두 0.2 이하였고 의심 24쌍에서는 0.0–1.0 으로 넓게 퍼졌다 — 한글로 적은 이름·다른 날짜 표기 때문에 진짜 번역 쌍도 낮게 나올 수 있어 단독 판정에는 못 쓴다. 이 임계값은 감사 라벨을 본 뒤에 맞춘 것이다.
- **행사 안내**: 감사가 행사로 본 두 이야기(한·영 4편)를 모두 잡았고 다른 글은 걸리지 않았다. 표본이 둘뿐이다. 독립 검증의 합성 글 시험에서는 행사를 해설하는 정상 분석 글이 걸리고(오탐) 공청회·브리핑·타운홀·오픈하우스 안내가 걸리지 않았다(미탐) — 미탐은 신호어를 더해 고쳤고 오탐은 낱말 기반 한계로 남는다.
- **회사 발표·주제**: 회사 도메인 글(회사 구상 쌍·AI 쇼핑 글)을 `company_release_summary`·`off` 로 잡았다. 감사는 AI 쇼핑 글에 고유 가치 2점을 줬다 — **같은 회사 문서 세 건을 시점별로 대조한 분석의 질은 도메인으로 못 본다.** 반대로 공식 사이트의 인물 기사(멘토링)는 도메인이 공식이라 `core` 로 나오고 감사의 '주제 약함'과 어긋난다.
- **보도자료 형식**: FTC 보도자료 쌍은 `official_press_release_summary`·`borderline` 으로 나온다. 감사는 이 쌍을 '주제 적합'으로 보았다 — 운영자 기준이 '보도자료 재작성'을 비공개·통합 후보에 넣은 것과 감사의 '주제' 기준이 다르다. 되돌려보기에서 언론 기사 주소의 `/news/` 조각만으로 '보도자료 형식 요약'이 켜지던 비공개 글 2편(한·영 한 쌍)은 이제 `none` 이다.
- **건강**: 소비기한 글·출소자 사망 통계 글을 `caution` 으로 잡았다. 수정 전에는 `caution` 이 10편이었는데 그중 3편(설비 '진단'·비유로 쓴 '진단'·`medical support`)은 한 낱말이 사전과 프로필 규칙에서 두 번 세어져 걸린 것이라 수정 뒤 `none`(7편)이 되었다. 감사의 `risk` 항목 대부분은 건강이 아니라 **사실 정확성·단정 과장**이라 이 항목으로는 보이지 않는다. 운영자 건강 C 예시는 9개 중 6개를 놓친다(§3 항목 8 한계).
- **숫자 읽기**: 수정 전에는 소수·천 단위가 붙은 단위를 정수 앞부분으로 읽어 `12,246kg` 을 12, `4,261km` 를 4, `1,450kg` 을 1, `1.8m` 를 1 로 낸 글이 있었다(실제 글 1편에서 확인). 지금은 쓴 그대로의 값으로 읽는다. 한글에 붙여 쓴 수(`약5%` 같은 것)는 실제 글에 아직 없다(`코로나19` 한 건은 식별자라 계속 제외) — 생성기가 숫자 앞을 띄어 쓰는 습관 때문에 가려져 있던 잠복 결함이라 미리 고쳤다.
- **날짜 읽기**: 2026-10-30 KR-224001(Pew 광고 분석)에서 표의 `1월 | 31%` 가 1월 31일로, 분석 기간 `1월 1일–10월 24일` 이 2027년으로 읽혀 `date_status` 가 `upcoming` 이던 것을 고쳤다 — 가짜 날짜 둘(2027-01-31·2027-10-24)이 사라졌다. 남은 `past_event_dates` 는 국문 글에 실제로 적힌 자료 기준일(2026년 11월 4일) 때문이고 영문 글에는 그 날짜가 없어 두 글의 상태는 여전히 다르다(오독이 아니라 글 내용의 차이다).
- **근거 근사치**: 같은 문단 링크 비율은 감사의 근거 판정과 상관이 거의 없다. 원문 텍스트가 이력에 남지 않아 과거 글은 원문 모드로 잴 수 없다(11-04 개선안 §5-6 의 한계 그대로) — 원문 모드는 후보 글 단계(요약 텍스트를 가진 시점)에서만 의미가 있다.
- **직접 작업 신호**: 감사의 고유 가치 점수와 일치하는 쪽이 많지만, 표만 있는 글(원문 수치를 표로 옮긴 글)과 같은 발표를 두 사이트에 올린 글은 신호가 있다고 나온다.
- **주장 수의 교차 확인**: 같은 국문 글 25편에서 항목 1 의 숫자 주장 수는 데스크톱 저장소의 별도 규칙 기반 검사기(날짜·통계·가격·시각 확인 권장 항목)와 피어슨 0.99·순위 상관 0.82 로 같은 방향이었다(수정 전 값이며 독립 검증은 이 입력이 없어 재현하지 못했고 이번 수정 뒤에도 다시 재지 않았다). 둘은 다른 것을 센다 — 그림자는 숫자가 든 **문장 수**, 검사기는 표기 **하나하나** — 라서 절대값은 다르다.
- **출처 수의 교차 확인**: 감사 인벤토리의 본문 링크 호스트(이미지 크레딧 제외)와 64편 중 62편이 같았다. 차이 2편은 인벤토리가 자기 사이트 링크·이미지 주소의 호스트까지 센 것이다(그림자는 `--own-domain` 과 이미지 제외 규칙으로 뺀다). 인벤토리는 출처 절을 `##` 제목만 읽어 43편을 놓쳤다(그림자는 열여섯 모양을 읽는다).
- **한국어 사전 기반 검사는 어미·표기 변형을 놓칠 수 있다.** 임계값은 이번 64편(감사 50편) 눈대중이다.

## 7. 연결하려면(이 문서의 범위 밖)

연결은 하지 않았다(**유일한 예외: 수동 그림자 워크플로의 별도 프로세스 호출** — 조건은 §1). 훗날 연결한다면 11-04 개선안 §3·§4 의 단계(`off` → `shadow` → `hold`)와 승인 경로(T3)를 따른다: 검사별 설정 한 줄로 되돌릴 수 있게 하고, 처음에는 결과를 실행 요약·로그에만 남겨 동작을 바꾸지 않으며, 신호를 판정에 쓰지 않는다. 그때 `tests/test_quality_shadow_guards.py` 의 연결 금지 시험과 이 문서의 선언을 같은 변경에서 고친다.

## 9. 이 도구로 판정할 수 있는 것·없는 것

**이 도구는 신호를 낼 뿐 제한 재개 조건을 단독으로 판정하지 못한다.** 아홉 측정은 모두 구현돼 있지만 대부분 **대리 지표**(진짜 값을 재는 것이 아니라 그와 닮은 것을 센다)이고, 12개 제한 재개 조건 가운데 이 도구 하나로 끝까지 판정되는 것은 없다. 그림자 실행 횟수 기록·서로 다른 초안 증명·건강 C 누락 0·가짜 인용 0·결함 등급은 **이 도구 밖의 일**이다. 결과는 '사람이 먼저 볼 글의 순서'를 정하는 데 쓴다.

### 하지 않는 것(범위 밖 — 이 도구를 고쳐서 메우려 하지 않는다)

- 그림자 실행 기록부 만들기(날짜·입력 해시·결과 해시) — 그림자 3회·초안 10개 평가의 운영 절차로 따로 한다.
- 원문 텍스트를 파이프라인에서 `--sources-dir` 로 넘기는 연결 — T3 이며 운영자 채팅 승인이 필요하다.
- 건강 사전 확장·A/B/C 규칙 이식·평범한 문장 과탐 시험 — 데스크톱 WP-B2 와 Gate 의 몫이다.
- 지어낸 인용 탐지(인용문 대조) — 한계로만 문서화한다.
