# 이슈 기반 게시글 이미지 수정 인수인계

## 작업 요약

GitHub 이슈로 기존 블로그 게시글의 이미지를 변경할 때, AI가 요청과 무관한 `generator.py`를 고르고 전체 파일을 다시 작성해 버렸던 문제를 개선했습니다. 현재 자동 이슈 처리는 **기존 게시글 이미지 변경만 지원**하도록 범위를 제한했습니다.

## 문제 원인

- 이전 이슈 처리 코드는 저장소 파일 앞부분만 AI에 보여주고, AI가 수정할 파일과 전체 파일 내용을 선택·작성하도록 했습니다.
- 그 결과 이미지 변경 요청이 게시글이 아니라 `generator.py` 변경으로 이어질 수 있었습니다. 이슈 #15 실행 로그에서도 `generator.py` 한 파일만 커밋된 것이 확인됐습니다.
- 작업 성공 댓글이 실제 의도한 수정의 성공을 보장하지 않는 문제도 있었습니다.

## 반영한 개선

- 이슈 양식을 이미지 변경 전용으로 바꾸고, 사용자가 **게시글 공개 주소 또는 제목**과 **원하는 이미지 설명**을 입력하도록 했습니다.
- 게시글 경로는 AI가 선택하지 않습니다. 자동화 코드가 `_posts` 안에서 파일명, 게시글 제목, URL 슬러그를 기준으로 대상을 찾습니다.
- 대상이 없거나 여러 글과 일치하면 파일을 수정하지 않고 이슈 댓글로 다시 지정하는 방법을 안내합니다.
- AI는 이미지 검색어만 제안합니다. 수정 대상 파일이나 전체 파일 내용은 생성할 수 없습니다.
- 선택된 게시글의 front matter 대표 이미지와 본문 첫 이미지 URL만 교체하며 나머지 본문은 유지합니다.
- 처리 결과 댓글에 수정 파일, 변경 항목, 이전 URL과 새 URL을 기록합니다. 오류는 성공으로 처리하지 않습니다.
- 소유자·멤버·협업자가 연 이슈만 workflow를 실행하고, 댓글 등록에 필요한 `issues: write` 권한을 추가했습니다.
- 커밋 대상은 계속 `_posts`와 `history.json`으로 제한됩니다.

## 사용자 사용 방법

1. GitHub 저장소에서 **Issues → New issue**를 선택합니다.
2. **기존 게시글 이미지 변경** 양식을 선택합니다.
3. 바꿀 글을 블로그에서 열고 주소창의 공개 URL을 복사해 넣습니다. URL 대신 게시글 제목을 그대로 넣어도 됩니다.
4. 원하는 이미지에 담길 장면을 구체적으로 적습니다. 예: “소방관이 화재 현장에서 구조 활동을 하는 모습과 안전 장비가 보이는 사진”.
5. 이슈를 생성하고 봇 댓글에서 대상 파일과 이미지 변경 결과를 확인합니다.

대상 글을 찾지 못하거나 여러 글이 일치한다는 댓글을 받으면, 해당 글의 공개 URL이나 정확한 제목을 확인해 새 이슈로 다시 요청합니다.

## 지원 범위와 제한

- 현재 이슈 자동화는 **기존 게시글 이미지 변경 전용**입니다. 글 내용, 제목, 레이아웃, 디자인, 코드, 설정 변경은 자동으로 수정하지 않습니다.
- 이슈 작성자는 저장소 소유자, 멤버 또는 협업자여야 합니다.
- Gemini 및 Unsplash API 키가 Actions Secrets에 설정되어 있어야 합니다. 이미지 후보를 찾지 못하면 게시글을 바꾸지 않고 안내합니다.
- 이미지 변경이 공개 페이지에 보이기까지 GitHub Pages 빌드·배포 시간이 걸릴 수 있습니다.

## 확인 결과

- `python -m py_compile generator.py`: 통과
- `git diff --check`: 통과
- 제목과 게시글 URL을 통한 대상 매칭, 대표 이미지와 본문 이미지 동시 변경, 존재하지 않는 대상의 변경 거부를 확인했습니다.
- PyYAML 파서로 `.github/workflows/chanceblog.yml`과 `.github/ISSUE_TEMPLATE/blog_control.yml`을 파싱했습니다. 모두 파싱에 성공했고, 이슈 양식의 필드 ID 중복과 필수 입력도 확인했습니다.
- 실제 GitHub Actions의 Gemini·Unsplash 네트워크 실행은 별도로 수행하지 않았습니다.
