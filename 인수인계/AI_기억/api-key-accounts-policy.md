**운영자 채팅(2026-11-03 20:5x):** "API Key 발급은 지금 **휴대폰 번호 1개**로 전부 받아 둔 상태(구글 계정도 전부 같은 번호). 추가로 번호 2개(업무용 서브폰(개인)·배우자 명의)가 있고 가입·키 발급 여력이 남아 있다. **문제가 없다면 부족한 부분을 다른 번호로 새로 발급받아 적용**하면 될 것 같다." — '부족한 부분'이 정확히 어느 서비스·어느 한도인지는 말씀이 없다(모름).

**내 답(채팅):** **한도를 늘릴 목적의 새 계정·키는 권하지 않는다.** 이유 — ① 약관: Google API 약관 §2(d) '문서에 정한 한도를 우회하려 시도하지 않는다'·§2(c) 신원을 가리거나 속이지 않는다·§3(a) 통지 없이 접근 정지 가능(2026-11-03 확인); Gemini 추가 약관(aistudio.google.com/docs/terms)은 다중 계정·다중 키를 직접 말하지 않지만 위 API 약관을 따로 적용하고, 무료 등급은 입력을 구글이 검토·개선에 쓸 수 있어 민감·개인 정보를 넣지 말라고 함; **Unsplash API 약관 §12 는 쿼터를 넘기거나 우회하려는 시도를 명시 금지**(§2: 자격 증명을 제3자와 공유 금지·API 계정은 본인 앱에만 연결); 네이버 약관은 이 도구로 열 수 없어 **미확인**; Gemini 한도는 키가 아니라 **프로젝트** 단위(그래서 같은 프로젝트의 키를 늘려도 소용없고, 늘리려면 프로젝트=계정을 늘리는 길뿐 → 우회로 보이기 쉬움). ② 위험: 지금 잘 도는 키가 모두 한 번호·한 계정 묶음에 있어 우회로 판단돼 정지되면 함께 막힐 수 있음(번짐 방식은 비공개 — 추측이라 '가능성'으로만). ③ 배우자 명의 번호는 인증 문자·계정 복구 수단이 배우자에게 묶이고 본인 정보 정확성 요구에 걸릴 수 있어 권하지 않음. ④ 운영자 본인 명세도 같은 방향(최종 요구 9번·Unsplash 명세 §14: 한도 우회용 키 순환 금지).
**정식 대안(= '한도에 막혀 멈추는' 문제를 실제로 푸는 길):** 호출을 줄이는 구조(캐시·절약 모드·사람이 고를 때만 호출 — 앱에 이미 설계됨, 한도 도달은 '데이터 없음'으로 계속 진행) / Unsplash: 데스크톱용 앱을 같은 계정에 따로 등록(개수 제한 없음·명세가 인정하는 '개발용/운영용 구분') + 출처 표시를 고친 뒤 정식(Production) 신청(시간당 50→1,000) / 다른 제공자 추가(이미지는 Pexels·Pixabay 등 — 서비스마다 정식 계정 1개, 명세 7번의 '다음 제공자') / Gemini: 어디서 막히는지 먼저 확인(호출 줄이기·모델·분산), 정식으로 한도를 올리는 길은 유료 등급인데 운영자가 '결제수단·월 소액 결제 하지 않음'으로 정했으므로 권하지 않고 요청 시에만 안내 / **새 키가 '다른 용도'(네이버 검색 키 미발급·데스크톱 전용 Unsplash 앱·Blogger 데스크톱 OAuth)이면 지금 계정에서 새 앱·키를 만들면 되고 새 번호는 필요 없다**(D-08: 구글 Cloud 에서 영문·한글 각각 '데스크톱 앱' OAuth 클라이언트).
**내가 하지 않는 것:** 계정 생성·인증 번호 입력(AI 는 못 함 — 운영자 몫), 한도 우회용 자동 순환. **앱에 이미 있는 장치(k):** 용도마다 키 최대 3개, 같은 한도 묶음은 한도 오류 때 건너뜀, Unsplash 는 자동 순환 없음, 둘째 키 추가 때 약관 경고 1회, 401·403 등은 전환 없이 조치 안내. 운영자가 그래도 합법적인 별개 용도의 키(다른 앱·교체)를 넣는 것은 막지 않는다(앱은 키 출처를 알 수 없고 경고만).
**다음 결정 요청에 넣을 항목(기본값 있음):** K1 '부족한 부분'이 어느 서비스·어느 한도인지 알려 달라(예: 'Gemini 하루 한도에 자주 막힘') — 기본: 새 계정·번호는 쓰지 않고 위 정식 대안으로 진행. 운영자가 답하면 그에 맞는 정식 방법을 먼저 찾는다. 감지 회피 방법(계정이 묶이지 않게 하는 법 등)은 도와주지 않는다.
