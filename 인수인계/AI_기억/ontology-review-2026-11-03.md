**우리 쪽 현황(확인한 사실):** 이미 비슷하게 하고 있는 것 — 저장소가 진실(AGENTS.md·docs/ARCHITECTURE·DECISIONS·SECURITY_GUARDRAILS)·블로그 레지스트리(`pipeline/blogs.json`: 블로그·채널·플랫폼·mode·시크릿 이름)·오류 코드 카탈로그(코드 ↔ 쉬운 한국어)·예문 목록 시험('지어내지 않기')·사람 승인(병합·T3·독립 검증)·확인 필요 모음. **없는 것:** 용어집·관계 사전(`GLOSSARY`/`ONTOLOGY` 문서 없음 — 2026-11-03 22:45 grep), 규칙 개선 전용 Day-2 피드백 루프, 클라우드↔데스크톱 식별자 대응표. **같은 낱말이 다른 뜻인 실제 사례:** `key`(블로그 key·API 키·entry_id)·'키'(API 키 vs 핵심 키워드)·'번호'(후보 순번 — 지울 때마다 당겨짐 / 번호 앞 8자 / 요청 R-nnn / 이슈·PR·실행 번호 — `candidates delete 3` 반복이 다른 후보를 지우던 사고가 이 종류)·'프로필'(네이버 블로그 프로필 / 콘텐츠 프로필 JSON / Unsplash 작가 프로필 URL)·'상태'(후보·연결·이미지·글·실행 상태가 모두 다름)·'채널/플랫폼/블로그/모드'(Chance·Blogger 영문·네이버 …)·네이버 블로그 식별자가 클라우드(`naver_life_tips`)와 데스크톱(`naver_a`·`naver_b`)에서 다름('데이터 없음 ≠ 0' 같은 의미 규칙도 한 곳에 없음).

**적용할 것(작고 점진적, 새 인프라 없음):**
1. **O1 용어·관계 사전(자연어 온톨로지) 한 파일** — 블로그 저장소 `docs/GLOSSARY.md`(AI 지침 `AGENTS.md`·`CLAUDE.md` 등이 가리킴)와 데스크톱 `docs/` 의 대응 문서: 핵심 개념 정의·관계 문장('A 는 B 와 이럴 때 결합')·**같은 낱말 다른 뜻 표**·'데이터 없음 ≠ 0'·변경 시 갱신 규칙, 문서의 코드 이름이 실제와 같은지 지키는 시험 1개(doc-sync). T0~T1, 새 의존성 없음 → 내가 기본값으로 진행(운영자 승인 항목 아님 — 말씀하시면 멈춤).
2. **O2 '자연어 규칙 → 예문 표 → 시험' 형식 공식화** — 이미 'c'(지어내지 않기)·'e'(제안 관문)가 하는 방식을 규칙 문서(`docs/RULES.md` 또는 각 모듈 문서)에 같은 틀로: 규칙 한 줄 + 통과/위반 예문 + 담당 시험. LLM 은 **작성 시점**에 규칙을 코드·시험으로 옮기는 데 쓰고 사람이 승인(실행 시점에 LLM 이 판정하지 않음 — 키 없이도 되는 핵심 흐름·'지어내지 않기' 안전 때문). 'c2' 에 적용.
3. **O3 Day-2 규칙 피드백 루프** — 운영 중 오탐·미탐·실패·용어 변경을 한 곳(`docs/RULE_FEEDBACK.md`)에 쌓고 정기 점검(알림에 한 줄)에서 규칙·예문·시험으로 반영. 지금의 '확인 필요 모음'·TROUBLESHOOTING 과 역할이 겹치지 않게 '규칙 개선' 전용.
4. **O4 이관 매핑표** — 데스크톱 이관(클라우드 자산 → 데스크톱 저장소: `naver_history.json`·`_naver_drafts`·블로그 기록·블로그 key 대응)을 자연어 매핑 규칙 + 사람 승인 가져오기로(식별자 다중 의미 사고 예방). 설치 마무리·이관 단계의 입력.
