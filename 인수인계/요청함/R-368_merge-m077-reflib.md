# 병합 요청 M077 — 참고 글 보관함을 앱에 넣습니다

> **병합 방식**: 지금은 AI 병합 기능이 **꺼져 있어** 운영자께서 직접 병합해 주세요. (`M077 승인` 이라고 답하셔도 아직 AI 가 병합하지 않습니다 — 켜지는 변경이 운영자 병합으로 들어온 뒤에만.) 이 요청은 앱 저장소 `chanceblog-desktop` 의 것이고, PR 제목 맨 앞이 `[M077]` 인 것 하나만 병합합니다. 검사는 이미 끝나 초록입니다. 이슈 #205 가 '급함'이라 급함으로 보냅니다.

## 1. 무엇을 바꾸는지
'내 글 문체 참고값 보기' 대화상자 안에 단추 하나(`참고 글 보관함 열기`)가 생기고, 그것이 여는 새 화면에서 **참고 글을 보관**합니다. 글을 붙여 넣거나 파일(.txt 등)에서 올리면 이 PC 의 사용자 데이터 폴더(`references/`)에 글 하나당 파일 하나로 남아 프로그램을 닫아도 유지되고, 목록(제목·글자 수·고친 때)에서 열어 고쳐 저장하고 두 단계 확인으로 지울 수 있습니다. 한도는 최대 50편·제목 80자·본문 100,000자·파일 1MB 입니다. 글은 AI 나 인터넷으로 보내지 않고, 새 외부 접속·키·의존성은 없습니다.

## 2. 왜 필요한지
운영자님이 이슈 #174(11-11)에서 요청하신 '래퍼런스 글을 올려 두고 다시 열어 고쳐 쓰는' 기능이고, 이슈 #205(11-15)에서 개인 PC 에서 쓸 수 있게 우선 진행해 달라고 하셨습니다.

## 3. 사용자가 체감하는 변화
설정 화면에서 '내 글 문체 참고값 보기'를 열면 그 안에 `참고 글 보관함 열기` 단추가 생겼고, 보관함에서 글을 올리고 고치고 지울 수 있습니다. 그 밖의 화면·글쓰기·발행 흐름은 그대로입니다. 저장할 때 줄 바꿈(CRLF·CR)은 LF 로 통일하고 맨 앞 BOM 은 빼며 NBSP 는 공백으로 바꿔, 화면에 보이는 글과 저장되는 글이 같습니다(윈도 메모장 글을 올려도 열자마자 '저장하지 않은 변경'이 뜨지 않게). 키·토큰 모양(구글·깃허브·AWS·Bearer·PEM·OAuth 여섯 모양)이 든 글은 저장을 거절하고 위치와 종류만 알립니다.

## 4. 위험과 기존 기능에 미치는 영향
- **기존 기능**: 영향이 없습니다. 새 파일 10개(코드 5·시험 5)가 더해지고 기존 파일 17개가 바뀝니다 — 코드 6곳(`service/context.py` 의 `write_json` 에 키워드 인자 하나(기본 끔, 쓰는 곳은 보관함뿐)·`security/backup_note.py` 의 백업 카드 한 문장·`ui/adapters.py`·`ui/core/text.py`·`ui/qt/shell.py` 연결·`ui/qt/style_dialog.py` 단추 하나), 시험 2곳, 문서 9곳. `vendor`·`.github`·의존성·백업 형식은 그대로입니다.
- **솔직하게 알려 드릴 점 ① — 데이터 폴더에 새로 쓰고 지웁니다**: 보관함이 `references/` 에 파일을 쓰고, 글을 지울 때 그 파일을 지웁니다. 저장소 안전 시험의 '파일을 직접 지우는 곳' 허용 목록에 `(references.py, delete_reference)` 의 `unlink` **한 줄을 더했습니다**(이유가 주석·결정 D-489·SECURITY 에 공개). 이 변경을 되돌려도 이미 보관한 글 파일은 PC 에 남습니다.
- **② 전체 백업·복원에는 들어가지 않습니다**(첫 판). 백업 카드 '담지 않는 것'의 한 문장을 사실대로 고쳐 그렇게 알렸고(줄 수·백업 형식은 그대로), PC 를 바꿀 때는 `references/` 폴더를 직접 옮겨야 합니다. 백업·복원이 보관함을 건드리지 않는다는 것은 진짜 백업·복원으로 시험했습니다.
- **③ 키·토큰 검사는 여섯 모양뿐입니다.** OpenAI·Anthropic 키처럼 그 여섯 모양이 아닌 것은 못 막고, 쪼개 쓴 토큰도 못 막습니다 — 문서에 한계로 적었습니다(본문이 로그·오류에 새는 길은 없음을 확인).
- **④ 서비스는 화면 스레드에서 곧바로 불립니다**(작업 스레드가 아님). 50편·10만 자 글에서 구현자가 0.3초에서 0.7초로 쟀고(검증자는 PC 가 바쁠 때 더 오래 걸린 값을 봄), 문서도 그렇게 고쳤습니다.
- **⑤ 화면 확인의 한계**: Qt 화면은 이 PC 에서 offscreen 으로만 띄워 확인했습니다(스크린샷 64장·화면 시험 84개). **실제 윈도 125%·150% 렌더·한글 입력기·화면 읽기 프로그램은 운영자 PC 에서 확인해야 합니다.** 저장소 CI 에는 PySide6 가 없어 그 Qt 시험 82개는 CI 에서 건너뛰어 초록으로 보이며, 이 PC 와 운영자 PC 에서만 돕니다.
- **⑥ 알려 둔 작은 한계**(결정 D-490 ⑥·D-491 ④·D-492 ⑩ 에 적음): 다른 대화상자가 프로그램 코드로 보관함을 덮을 때 편집 칸이 확인 없이 비워짐(사용자가 누를 수 있는 길은 못 찾음)·거절·안내를 화면 읽기 프로그램에 알리는 호출 없음·바깥에서 지운 글을 열면 낡은 줄이 목록에 남음·유니코드 비문자 두세 개는 편집 칸에서 바뀜 등.
- **⑦ 검사 한 번 빨갰던 일**: 이 가지의 첫 저장소 검사에서 시험 한 개(한글 120자짜리 파일 이름 — 리눅스는 파일 이름이 255바이트까지)가 리눅스에서만 빨갰고, 이 PC(윈도)에서는 못 잡았습니다. 시험의 파일 이름 길이만 줄여 고쳤고 서비스 코드는 바꾸지 않았습니다.
- **이번에 하지 않는 것**: 글을 쓸 때 보관함의 글을 가져다 쓰는 연결과 사진 연동은 다음 묶음입니다.

## 5. 시험·독립 검증 결과
- 전체 검사 초록(저장소 검사 두 칸 — 파이썬 3.10·3.12, 조각 셋씩): 병합 가지의 자동 검사 실행 2건이 모두 성공했습니다(시험 16분 39초·병합 부탁 PR 자동 만들기 17분 3초). 같은 내용의 작업 가지에서도 시험이 14분 31초에 초록이었습니다. 새 시험 277개 — 서비스 110·화면 규칙 68·어댑터 15·Qt 화면 84(이 중 Qt 82개는 PySide6 없는 환경에서 건너뜀).
- 규칙을 일부러 망가뜨린 변이 시험: 구현자의 서비스 25개·화면 규칙과 Qt 37개·Qt 15개를 모두 시험이 잡았습니다. 두 독립 검증자가 직접 만든 변이로 1차에서 시험 구멍 11곳이 드러나 모두 시험을 더해 닫았고, 2차 변이 55개 중 남은 것은 넷입니다(변이를 잘못 만든 것 하나·동등 변이 하나·시험이 안 지키는 줄 둘 — 임시 파일 지우기의 링크 건너뜀과 '다시 읽기' 단추의 Tab 위치).
- 독립 검증(구현자와 다른 AI 두 명, 서로 다른 관점): ⓐ 안전·자료 손실·개인정보 — 1차 fix_required(필수 4·권고 7)에서 시작해 델타 확인에서 **최종 통과(필수 0·권고 0)**, ⓑ 화면 규칙·Qt 동작·시험 품질·UI 문서 — 1차 fix_required(필수 2·권고 6)에서 시작해 델타 확인에서 **최종 통과(필수 0)**. 무작위 걷기 약 1만 판에서 '확인 없이 글이 사라지거나 엉뚱한 글이 지워지는' 경우는 0(좁은 한 길은 고침).
- 직접 확인: 변경에 비밀 모양 0·새 네트워크·하위 프로세스 코드 0(시험의 두 프로세스 쓰기 도우미 제외)·`vendor`·`.github`·의존성 변경 0, 저장소 안전 시험 통과.
