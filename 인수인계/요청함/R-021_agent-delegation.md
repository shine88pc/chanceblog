## 한 줄 (일 위임 설계)
"지금 하는 모든 작업을 다른 봇이나 GitHub Copilot 에게도 위임할 수 있게 하라"는 지시대로, **지금까지 Claude 가 하던 일 12가지를 저장소 절차서로 옮기고**, Copilot·다른 AI·GitHub 봇이 같은 절차로 이어받을 수 있게 지침과 도구를 만들었습니다. 병합해 주세요(블로그 글 만드는 방식·광고·시크릿·워크플로·모델은 바뀌지 않고, **새 알림 경로나 시크릿도 없어 T3 승인이 필요한 항목이 없습니다**). 확인 3가지는 아래에 있고 **답이 없어도 기본값으로 진행**합니다.

## 하실 일 (병합, 2분 — R-020 과 같은 방법)
1. 저장소 첫 화면(https://github.com/shine88pc/chanceblog) 맨 위 노란 **"ai/claude/agent-delegation had recent pushes" — Compare & pull request** 배너를 누릅니다. 배너가 여러 개면 이름에 `agent-delegation` 이 든 것입니다. 배너가 안 보이면 이 주소를 엽니다: https://github.com/shine88pc/chanceblog/compare/main...ai/claude/agent-delegation?quick_pull=1
2. **제목은 그대로 두고** 초록 **Create pull request**.
3. 화면 맨 아래 검사가 모두 초록(All checks have passed)이 될 때까지 기다린 뒤(보통 5~10분) **Squash and merge → Confirm squash and merge**. **Delete branch 는 누르지 않습니다.**

병합하셨는지는 제가 직접 확인합니다.

## 무엇이 들어 있나 (쉬운 설명)
- **절차서**(`docs/AGENT_RUNBOOK.md`): 제가 해 온 일 12가지(현황 읽기·운영자 응답 처리·요청 보내기·변경 전달·실행 점검·문서 갱신 등)를 누가 읽어도 같은 결과가 나오게 단계별로 적었습니다. 워크플로 17개의 역할 표도 있습니다.
- **설계서**(`docs/AGENT_DELEGATION.md`): 어느 일을 Claude·Copilot·GitHub 봇·사람이 할 수 있는지, 어떻게 맡기는지, 안전 장치(광고·비밀·승인이 필요한 일은 맡기지 않음, 만든 쪽과 검증하는 쪽을 다르게), 운영자에게 알림이 닿는 길.
- **Copilot 지침**: 소유자가 이슈에서 직접 지정한 일만 하고, 위험한 곳(광고 표면·비밀·`.github/` 전체·검증기·`pipeline/blogs.json`·규칙 문서)은 건드리지 않게 못 박았습니다.
- **검증기 보강**: 'Copilot 이 쓴 승인 표시는 인정하지 않는다'(AD-2)를 더했고, 독립 검증이 찾아낸 우회 길도 막았습니다 — 같은 변경에서 광고 표면 보호 목록에서 파일을 빼고 그 파일을 고쳐도 걸립니다. 승인은 운영자만 합니다.
- **읽기 도구 2개**: GitHub 실행·PR·이슈 상태를 로그인 없이 읽는 도구, 검증을 한 번에 돌리는 도구(시험 포함).

## 공식 문서로 확인한 사실 (설계에 반영함 — 이 저장소에서 직접 시험한 것은 아닙니다)
- **Copilot 이 일하는 길**: 유료 Copilot 요금제에서, 소유자가 이슈의 담당자(Assignees)에 Copilot 을 지정하면 `copilot/…` 브랜치에 **초안 PR** 을 만듭니다. Copilot 은 PR 을 승인·병합하지 못하고, 검사는 사람이 **Approve and run workflows** 를 눌러야 돕니다(그대로 두기를 권합니다 — 끄면 비밀에 닿는 작업이 사람 확인 없이 돌 수 있습니다). **그 클릭은 Claude 가 PR 내용을 먼저 읽고 '눌러도 된다'고 알린 뒤에만** 눌러 주세요.
- **쓸 수 없는 것**: Copilot **자동화**(이벤트·예약 실행)는 비공개 저장소만 됩니다 — 이 저장소는 공개라서 불가. 일을 자동으로 배정하려면 별도 접근 토큰(PAT — 비밀번호 같은 열쇠)을 저장소에 등록해야 하고 그것은 T3(운영자 승인이 꼭 필요한 일)라서 하지 않습니다. 이슈에서 한 번 눌러 배정하시면 됩니다.
- **알림**: 운영자는 텔레그램만 보시는데, **`[공통] 확인 필요 모음` 이 이미 '새로 해야 할 일'(승인 대기 포함)을 텔레그램으로 보냅니다**(몇 시간 늦을 수 있음). 그래서 Copilot PR 이 승인을 기다리면 알림이 갑니다. 세션이 켜져 있으면 Claude 가 먼저 읽고 더 빨리 알립니다.

## 확인 3가지 (답이 없으면 기본값)
| 번호 | 질문 | 기본값(답이 없을 때) |
|---|---|---|
| **D1** | 이슈 하나를 열어 오른쪽 **Assignees** 를 눌렀을 때 **Copilot** 이 목록에 **보입니까?**(GitHub 앱이든 웹이든 이슈 화면의 Assignees 에서 같은 이름을 찾으시면 됩니다. 메모에 `있음` / `안 보임` / `모름`) | `안 보임`으로 보고 Copilot 길은 보류 — 나머지(다른 AI·봇·절차서)는 그대로 동작 |
| **D2** | 쓰시는 **다른 AI·봇**이 있습니까?(예: ChatGPT Codex, Gemini CLI. 메모에 이름 또는 `없음`) | `없음` — 모든 AI 공통 규칙(`AGENTS.md`)만 지원 |
| **D3** | 앞으로 **진행 사항**을 어떻게 받으시겠습니까?(이슈 #76) — **A**: 일을 마무리할 때 한 번(지금처럼) / **B**: 하루 한 번 요약(세션이 켜져 있는 날) / **C**: 받지 않음(병합 부탁 같은 꼭 필요한 요청만) | **A** |

설명만 드리는 것(결정 불필요): Copilot PR 의 **'워크플로 자동 실행(승인 건너뛰기)' 설정은 끄고 둡니다.** **자동 병합은 하지 않습니다**(모든 병합은 운영자). 첫 시험은 문서 한 줄 같은 작은 일 하나를 Copilot 에게 맡겨 흐름을 점검합니다(D1 이 '있음'일 때).
