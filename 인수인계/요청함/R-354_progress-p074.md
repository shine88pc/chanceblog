# 진행 현황 P074 — 이슈 #207 답(논의·준비) (본문 — 폰에는 싣지 않고 요청 열기로 읽습니다)

## 1. 제가 이해한 요청
1. 블로그 관리 메뉴가 GitHub Pages·Blogger 영문/한글·네이버 A/B 로 **특정된 카드**로 되어 있는데, 사용자가 필요에 따라 **어느 사이트의 블로그든 연결**할 수 있게 한다.
2. 카드는 단순하게 **'+ 블로그 추가'** 형태로 보여 준다.
3. 직접 입력(키인)보다 **프로그램이 제안하고 사용자가 고르는** 방식으로 — 예: 협찬 가능 분야처럼. 주제 설정의 우선·제외 키워드는 무슨 낱말을 넣어야 할지 알 수 없으니 **제안 키워드나 프로그램이 구현할 수 있는 주제 목록**에서 고르게 한다.
4. 그 밖에 직접 입력하는 항목도 가능한 한 **보기를 고르는 형태**로 바꾼다.

## 2. 지금 앱 상태(직접 확인)
- 블로그 관리는 **고정 슬롯 다섯**(GitHub Pages·Blogger 영문·Blogger 한글·네이버 A·네이버 B)입니다. 앱 안의 글 만들기·후보·초안·게시 준비·백업이 모두 이 다섯 이름을 기준으로 움직입니다.
- 칸은 네 묶음(기본 정보·자세한 정보·주제 설정·모양)입니다. **고르는 칸**: 글 언어·후보 만들기 켬/끔·협찬 가능 분야(칩 여섯)·선호 글 유형(칩 다섯)·색 프리셋. **직접 입력하는 칸**: 블로그 이름·블로그 주소(또는 아이디)·별명·채널 역할·주요 주제·대상 독자·문체·카테고리·소개글·우선 키워드·제외 키워드·프로필·커버 이미지 경로.
- 앱이 이미 가진 목록: 협찬 가능 분야 6(소형가전·PC 주변기기·숙박·여행·AI 서비스·PC 부품·업무 자동화), 글 유형 5(정보형·비교형·문제 해결형·제품·서비스 소개형·장소·업체 정보형), 주제 묶음 이름 약 25개(생활 문제 해결·API 한도·로컬 AI·디지털 정리·일정 관리·가계부·시간 관리 등).

## 3. 제안
### 3-1. '+ 블로그 추가' 카드 — 두 단계로 나눕니다
- **A 단계(표현만 바꿈 — 안전)**: 카드 목록에 **등록한 블로그만** 보여 주고 맨 끝에 '+ 블로그 추가' 카드를 둡니다. 누르면 **블로그 종류**(네이버·Blogger·GitHub Pages 중 선택)를 고르고 이름·주소를 적습니다. 속에서는 지금의 다섯 슬롯 중 같은 종류의 빈 자리를 씁니다(사용자 눈에는 '슬롯 이름' 대신 블로그 별명만 보임). 저장 형식·엔진은 그대로라 위험이 작고 기존 저장 파일이 그대로 읽힙니다. 한계: 같은 종류는 지금처럼 최대 2개(네이버 2·Blogger 2·GitHub 1).
- **B 단계(구조 변경 — 큰 묶음)**: 종류별로 원하는 수만큼 블로그를 추가하고 '어느 사이트든'(티스토리·브런치 같은 새 종류 포함) 연결하게 하려면 저장 형식(판 3)·글 만들기/후보/초안/게시 준비/백업의 '다섯 이름' 기준을 일반화해야 합니다. 새 사이트 종류는 게시 방식이 달라 복사 패키지(손으로 붙여 넣기) 수준으로만 시작하는 안이 안전합니다. 이 단계는 별도 설계·승인 항목으로 따로 여쭙겠습니다(새 게시 연결은 T3).

### 3-2. 직접 입력을 선택형으로
| 칸 | 지금 | 제안(고르기 + '직접 추가'는 보조로 유지) |
|---|---|---|
| 우선·제외 키워드 | 낱말을 직접 적음 | 앱이 아는 주제 묶음·협찬 분야·글 유형에서 **제안 칩**을 보여 주고 여러 개 선택(자주 쓴 것 먼저) |
| 주요 주제·카테고리 | 낱말 직접 입력 | 같은 제안 칩 + 글 유형 기준 기본 카테고리 제안 |
| 대상 독자 | 한 줄 직접 입력 | 짧은 보기 목록(예: 20–30대 직장인·대학생·주부·여행자·개발 입문자·자영업자 …) 중 선택 |
| 문체 | 한 줄 직접 입력 | 보기(친근한 말투·정중한 설명체·간결한 정보체·생생한 후기체) 중 선택 |
| 채널 역할 | 한 줄 직접 입력 | 보기(정보 공유·후기 기록·제품 비교·브랜드 소개·일상 기록) 중 선택 |
| 소개글 | 직접 입력 | 위 선택값으로 만든 문장을 제안, 사용자가 고쳐 저장 |
| 별명 | 직접 입력 | 블로그 종류 + 번호로 제안(고칠 수 있음) |
| 블로그 주소 | 직접 입력 | **제안 불가**(주소는 사용자만 앎) — 예시와 모양 검사 도움말 |
| 이미지 경로 | 경로 직접 입력 | '파일 고르기' 창(경로를 적지 않음) |
- 보기 목록은 앱 안에 두고(제가 처음 목록을 제안) 사용자가 항목을 추가·삭제할 수 있게 합니다. 목록 밖의 값은 직접 추가로 남겨 둡니다.
- 모두 **AI·네트워크 없이** 앱 안의 규칙만으로 되고 새 외부 연결·비용이 없습니다.

| 키워드·주제 칸 | 제안 칩 선택이 기본, 직접 추가는 보조로 유지 |
