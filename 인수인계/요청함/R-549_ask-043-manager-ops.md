# 확인 요청 043 — 매니저 프로젝트 독립 운영 체계 설계안 (결정은 한 가지)

> 이 글은 **질문**입니다. 이슈 양식 '[답변] AI 확인 요청에 답하기' 에 **대상번호 043**(앞의 0 을 빼고 써도 됩니다)와 고른 보기(1·2·3)를 적어 주세요. **답이 없으면 3(보류)** 입니다 — 아무것도 바뀌지 않습니다.
> 이슈 #279 의 진행 범위는 '논의·준비까지만' 이라 지금까지는 **조사와 설계만** 했습니다. 코드·설정·시크릿은 어느 저장소에도 올리거나 바꾸지 않았습니다.

## 쉽게 말해
- 운영자님이 "블로그가 쓰는 GitHub 이슈 + 텔레그램 알림 방식을 신규 포트폴리오 매니저 프로젝트에도 같은 모양으로 만들어 달라"고 하셨습니다.
- 블로그 방식의 뼈대는 이렇습니다. AI 는 (규칙상) **요청 파일만 올립니다** → GitHub 의 자동 실행이 대신 텔레그램을 보냅니다(AI 는 봇 토큰이 없습니다) → 운영자님은 폰에서 읽고 **이슈 양식으로 답**합니다 → **병합은 운영자님만** 합니다.
- 매니저는 이 모양을 그대로 쓰되 **저장소·봇·시크릿·양식·번호·작업 기록을 전부 따로** 둡니다. 그리고 **비공개·금융 저장소**에 맞게 고칩니다(알림에 금액·수량·종목 같은 값을 코드로 못 싣게 막는 것 등).
- 승인하시면 매니저 세션이 portfolio-manager 저장소에서 직접 구현합니다. 병합·시크릿 등록·설정 변경은 계속 운영자님 몫입니다.

## 조사 결과 한눈에 — 블로그는 실제로 이렇게 합니다
(블로그 저장소의 코드·워크플로·문서를 직접 읽어 확인했습니다. 확인하지 못한 것은 맨 아래에 따로 적었습니다.)
1. **AI → 운영자 알림**: AI 가 요청 파일(.md)을 정해진 가지에 올리면 워크플로 `AI 요청 텔레그램 알림` 이 새 파일만 골라 텔레그램으로 보냅니다. 종류는 진행 현황(📊 P번호)·병합 요청(🔀 M번호)·확인 요청(🔔 숫자 번호)·병합완료 확인. 제목 80자·요약 300자 같은 한도가 있고, AI 가 쓴 글은 비밀 모양 가리기·링크 무력화·멘션 방지 소독을 거쳐 나갑니다. 버튼 주소는 허용 목록만 됩니다.
2. **운영자 → AI 답**: 폰에서 이슈 양식 `[답변]`(대상번호·선택)·`[요청]`(새 일)을 올리면, **저장소 소유자 계정만** 접수되고 접수 코멘트와 텔레그램 ✅ 가 갑니다. 승인은 번호가 AI 가 보낸 확인 요청과 같고 선택이 그 요청의 승인 보기와 같을 때만, 그 요청에 적힌 항목에 한해서 인정합니다. 대상번호만 올린 답과 `[요청]` 은 '접수'일 뿐 승인이 아닙니다.
3. **진행 보고**: AI 세션의 정기 실행이 2시간마다(변화가 없어도) 5항목(현재 진행·직전 이후·다음 계획·예상 완료·확인 대기)을 보냅니다. 진행 글에는 병합을 암시하는 문장을 쓰지 않는 규칙이 있습니다(진행 문구를 병합 신호로 읽은 사고 뒤에 생김).
4. **PR·병합**: AI 가 한 커밋짜리 병합 가지(제목 `[M번호]`)를 올림 → 자동 검사 → 초록이면 자동으로 **PR 만** 만듦(병합은 안 함) → AI 가 병합 부탁 알림 → **운영자님만** Squash and merge. 알림이 나간 PR 하나만 병합합니다.
5. **완료·오류**: 병합 뒤 AI 가 확인하고 '병합완료 확인 - 정상/이상' 을 보냅니다. main 검사 실패는 텔레그램 🚨, 발행 정체는 `[Watchdog]` 이슈, 운영자 확인거리는 `[운영] 확인 필요 모음` 이슈입니다. 운영자님은 GitHub 기본 알림은 무시하고 텔레그램에 적힌 일만 합니다.
6. **알게 된 한계**: 코드 수천 줄·문서 1 MB 로 커졌고 번호가 두 겹(R/P/M/숫자)이라 헷갈립니다. 10분 간격으로 건 예약 실행이 실제로는 7시간 간격이었습니다. 공개 저장소 전제가 곳곳에 있습니다(로그인 없는 읽기, '이슈는 공개' 안내, 무료 러너). AI 가 push 용 자격증명으로 이슈를 쓰는 것은 **기술로는 못 막고 규칙에 기댑니다**. 시크릿은 push 한 가지의 워크플로로도 닿을 수 있습니다 — 블로그 문서도 '알려진 한계'로 적었습니다.

## 매니저 적용 설계 요약
1. **세 길을 그대로**: AI→운영자 알림 / 운영자→AI 이슈 답 / 변경 전달(PR). AI 는 파일만 올리고 텔레그램 토큰은 GitHub 쪽에만 있습니다.
2. **번호**: `PM-` 접두 + 종류 글자 `S`(진행)·`Q`(확인)·`B`(병합)·`C`(완료)·`E`(오류) + 세 자리. 블로그의 R·P·M 글자와 겹치지 않고 번호를 한 겹으로 줄입니다.
3. **알림**: 진행 S(무음)·확인 Q·병합 B·완료 C·오류 E, 그리고 접수·수정·검사 실패 같은 고정 문장. 모든 글 머리에 `[PM]` 표지, 버튼은 매니저 저장소로만 열립니다.
4. **금융 규칙(새로 추가)**: 알림·이슈·PR·커밋·로그에 금액·수량·종목·계좌·수익률을 쓰지 않습니다. 코드가 숫자는 **허용 모양(번호·날짜·시각·작은 건수)만** 통과시키고 나머지는 보내지 않고 거절합니다. 오류 알림은 로그 원문 없이 고정 문장만 보냅니다.
5. **열쇠로 막기(새로 추가)**: AI 의 GitHub 열쇠는 '올리기'만 되고 이슈·PR·워크플로·시크릿·설정은 쓰지 못하게 만듭니다. 그러면 AI 가 스스로 승인하거나 병합하거나 시크릿을 읽는 길이 막힙니다(블로그는 규칙으로만 막았음). 요금제 때문에 못 막는 곳(main 에 직접 올리기)은 탐지 알림으로 메웁니다.
6. **시크릿**: 텔레그램 두 개뿐이고 새 봇·별개 값입니다. 시크릿을 쓰는 단계는 main 의 코드만 실행하고, 등록은 구축 병합이 끝난 **뒤**에 합니다.
7. **비공개 대응**: AI 읽기용 읽기 전용 열쇠, 안내 문구 교체('이슈는 공개' 삭제), 예약 실행 없음, PR 만들기 대기 0(러너 분 한도 때문).
8. **작게 시작**: 파이썬 약 1,000줄·워크플로 4개·문서 4–5개. 블로그의 글 발행·Pages·광고·감시·텔레그램 수신·AI 병합 정책은 가져오지 않습니다.

## 만들 파일 한눈에 (portfolio-manager 저장소를 처음부터 만듭니다 — 블로그 저장소는 한 줄도 바꾸지 않습니다)
- **이슈 양식**(`.github/ISSUE_TEMPLATE/`): 답변 양식·새 일 양식·설정(빈 이슈 막음).
- **워크플로 4개**(`.github/workflows/`): `pm-notify`(알림 보내기)·`pm-ack`(운영자 답 접수)·`pm-ci`(검사 + PR 만들기 + 실패 알림)·`pm-telegram-test`(연결 시험, 수동). 소유자 지정 파일(`CODEOWNERS`)과 PR 양식도 함께.
- **알림·접수 코드**(`ops/`): 알림 보내기·알림 파일 고르기·접수·금융 값 검사·실패 감지·비밀 모양 가리기 — 블로그 코드를 줄여 복사하고 글 발행 같은 블로그 전용 부분은 뺍니다. 알림 전용 가지 `ai/pm/NO-MERGE-outbox` 하나.
- **검증·도구**(`scripts/`·`tools/`): 저장소 검증기·최종 검사·이슈 상태 읽기·알림 파일 만들기·번호 채우기·병합 가지 만들기·알림 확인.
- **시험**(`tests/`): 남긴 함수마다 네트워크 없이 도는 시험 + 금융 값 검사 시험 벡터. **문서**: `AGENTS.md`·`CLAUDE.md`·`docs/` 네다섯 개(운영자 사용법·보안·구조·현황)·`WORKLOG.md`.
- 합쳐서 새 파일 30개 안팎·파이썬 약 1,000줄. 전체 표(경로·블로그 출처·변경 등급)는 총괄 폴더의 `design.md` 3절입니다.

## 시크릿·Actions 설정 한눈에 (이름만 — 값은 어디에도 쓰지 않습니다)
- **시크릿 둘**: `TELEGRAM_BOT_TOKEN`·`TELEGRAM_CHAT_ID` — 새 봇의 값을 매니저 저장소 설정 화면에 운영자님이 직접 입력합니다(블로그 시크릿과 별개). 부트스트랩 병합이 끝난 **뒤**에 등록합니다.
- **자동 제공 토큰**(`GITHUB_TOKEN`): 접수 코멘트(`pm-ack`)와 PR 만들기(`pm-ci` 의 마지막 job)에만, 워크플로 파일에 최소 권한으로 적습니다.
- **저장소 설정(운영자 몫)**: Actions 기본 권한은 읽기 · 자동 병합 끔 · PR 만들기 허용은 마지막 단계에서 켬 · main 보호 규칙은 요금제가 되면 켬 · 지출 한도 0 · 2단계 인증. 워크플로별 트리거·권한·시크릿 표는 `design.md` 4-3절입니다.

## 테스트·텔레그램 수신 확인 방법
- **자동 시험(AI, 네트워크 없이)**: 남긴 함수의 성공·실패 경로·알림 글자 견본 대조·검증기가 일부러 망가뜨린 워크플로를 모두 잡는지·금융 값 거절 벡터·핵심 규칙 변이 시험. 전송 없이 폰에 갈 글을 화면에 미리 보는 연습 출력도 있습니다.
- **연결 시험(운영자 1회)**: 시크릿을 GitHub 설정 화면에 직접 입력한 뒤 `PM 텔레그램 시험` 을 main 에서 실행 → 폰에 `✅ [PM] 알림 연결 확인` 이 오는지 확인(요약에는 시크릿이 '등록됨/없음' 으로만 나오고 값·길이는 없음). 실패하면 원인 분류 코드로 찾습니다.
- **종단 시험(AI + 운영자)**: 진행·확인 요청과 접수·수정 알림·완료·오류·금융 값 거절·PR 만들기와 병합·열쇠 제한·직접 푸시 탐지를 한 번씩 돌려 폰에서 눈으로 확인합니다.
- **수신 확인 체크리스트(운영자)**: 머리의 `[PM]` 표지와 번호 모양 · 새 봇 대화방에 왔는가(블로그 봇 방이 아닌가) · 버튼이 매니저 저장소로만 열리는가 · 글에 금액·수량·종목·계좌가 없는가 · 접수 코멘트가 이슈마다 한 번만 달리는가 · 올린 적 없는 접수 알림이 오면 바로 알리기.

## 할 일 — 승인하시면
**AI 가 합니다(매니저 저장소, 모두 PR 로 올리고 병합은 운영자님):**
1. 부트스트랩 PR 하나: 규칙 문서·검증기·시험·검사 워크플로.
2. 부트스트랩 PR 둘: 알림·접수 코드, 워크플로, 이슈 양식 둘, AI 도구, 시험, 알림 전용 가지. 다른 세션의 독립 검증을 거칩니다.
3. 병합 뒤 시험: 진행·확인·완료 알림과 병합 흐름을 한 번씩 돌려 폰에서 확인합니다.
4. 단계마다 알림으로 보고합니다. **값(토큰·채팅 번호)은 절대 묻지 않습니다.**

**운영자님이 손으로 하셔야 합니다(AI 는 못 합니다):**
1. 텔레그램에서 새 봇 'Portfolio Manager Bot' 만들기, 봇에 `/start`, 채팅 번호 확인. 값은 채팅·문서에 쓰지 않고 GitHub 설정 화면에만 직접 입력합니다.
2. 저장소 설정: Actions 기본 권한을 읽기로, 자동 병합 끔, 요금제가 되면 main 보호 규칙, 결제 화면 지출 한도 0. 요금제와 저장소 소유자가 개인 계정인지도 확인해 주셔야 합니다.
3. AI 열쇠 만들기(저장소 한 곳 전용, 권한은 올리기와 읽기만)와 AI PC 에 직접 입력. 구축 때만 임시 열쇠(7일).
4. 부트스트랩 병합 뒤 시크릿 두 개 등록 → `PM 텔레그램 시험` 실행 → 폰에 `✅ [PM] 알림 연결 확인` 이 오는지 확인.
5. PR 병합(알림이 나간 PR 하나만).

각 손 작업은 승인 뒤에 번호 있는 확인 요청으로 쉬운 순서와 함께 보냅니다.

## 위험과 되돌리기
- 알림이 안 오면: 시험 워크플로 요약의 원인 코드(토큰·채팅·`/start` 등)를 봅니다. 시크릿을 지우면 알림이 꺼집니다.
- 토큰이 노출되면: BotFather 에서 폐기하고 새 값으로 시크릿만 바꿉니다.
- **확인하지 못한 가정**: '워크플로 변경 권한이 없는 열쇠는 워크플로 파일을 못 올린다', '읽기 권한 열쇠로 비공개 저장소 이슈를 읽는다', 요금제별 기능(main 보호·지출 한도·분 한도). 첫 시험 항목으로 확인하고, 맞지 않으면 열쇠 방식을 블로그식(규칙만)으로 바꾸는 선택지가 있습니다.
- 러너 분: 추정 월 650–920분(무료 한도의 3분의 1에서 절반, 요금제 확인 필요). 예약 실행이 없고 지출 한도 0 이면 넘어도 과금 없이 멈춥니다.
- 금융 값이 새는 글: 숫자 모양은 코드가 거절하고, 종목·계좌 이름처럼 숫자 없는 정보는 규칙으로 금지합니다. 새면 해당 글을 정리하고 값이 실제면 계정·키를 교체합니다.
