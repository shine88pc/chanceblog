## 1. 무엇을 바꾸는지
11-24 2차 독립 감사가 보여 준 — 기존 검증기를 통과하면서 안전 장치를 약하게 만드는 워크플로·설치 줄 모양들을 막습니다. **모든 새 규칙은 '더 엄격한 쪽'이고, 지금 저장소의 진짜 워크플로·문서를 하나도 새로 거절하지 않습니다**(검증기 결과 오류 0·경고 3 그대로).
① **재사용 워크플로·컨테이너 이미지(결함 D-490)**: 다른 저장소의 재사용 워크플로(SHA 고정이어도)·`docker://` 단계·job 의 `container`·`services` 이미지·읽지 못하는 `uses`(앞뒤 공백 포함)는 오류입니다(이미지 안의 코드가 시크릿과 함께 job 의 모든 단계를 돌리기 때문).
② **복합 액션 파일(D-491)**: `action.yml`/`action.yaml`(워크플로 폴더 바로 아래 파일만 제외)도 신뢰 못 할 입력 보간·외부 액션 고정 검사를 받고, 읽지 못하면 오류입니다.
③ **시크릿 허용표 WF-17(D-492)**: '워크플로 × 쓸 수 있는 시크릿 이름' 표 — 표 밖 이름·`toJSON(secrets)` 류 통째 읽기·동적 색인·`secrets: inherit` 는 오류입니다. 표는 진짜 워크플로가 실제로 쓰는 것을 그대로 적었습니다. **새 시크릿을 쓰는 워크플로를 더할 때는 허용표를 같이 고쳐야 합니다(운영자 검토).**
④ **신뢰 못 할 칸 확장(D-493)**: shell·working-directory·defaults.run·runs-on·container·services·checkout ref/repository 에 PR 제목·이슈 글 같은 입력이 직접 들어가면 오류입니다.
⑤ **setup-python 키 제한(D-494)**: 운영자 루프 두 워크플로의 `with` 는 `python-version` 하나뿐이어야 합니다.
⑥ **pip 설치 줄(D-495)**: 색인·주소 옵션(`--index-url`·`--extra-index-url`·`-f`·`--find-links`·`--trusted-host` 등)·주소/VCS 직접 참조·`-e`·셸이 `<<<`·파이프로 입력을 받는 줄은 오류입니다.
⑦ **검사 취소 한 줄(D-496)**: `guardrails.yml` 의 `cancel-in-progress` 를 main 이 아닐 때만 켜게 바꿨습니다 — main 푸시의 검사는 뒤따르는 푸시로 취소되지 않고(대기열에 섬), 다른 가지는 이전처럼 취소됩니다.
시험: 새 모듈 셋(`test_validate_wf_shapes`·`test_validate_secret_table`·`test_dependency_sources`)과 강화한 기존 시험, 허용표 시험 동기화 `tests/unit_test_weights.json` 새 모듈 행, 문서 `docs/SECURITY_GUARDRAILS.md`·`ENGINEERING_GUIDE.md`·`DEPENDENCY_PINNING.md`·`ACTIONS_GUIDE.md`·결함 대장 D-490–D-496.

## 3. 위험과 알려 둔 한계
- 새 규칙은 **미래의 정상 워크플로를 거절할 수 있습니다** — 예: 데이터베이스 컨테이너가 필요해지면(`container`·`services` 는 항상 오류) 검증기를 고치는 변경을 운영자가 검토해야 합니다. 시크릿 허용표도 새 시크릿 사용 때 같이 고쳐야 합니다.
- 한계(문서에 적음): 시크릿 허용표는 파일 단위입니다. 설치 줄 검사는 줄의 옵션 낱말만 봅니다(`PIP_*` 환경 변수·pip 설정 파일·`pip download`·`pip wheel`·해석기 코드 안의 pip·**코드의 이름 목록 밖의 셸 입력 모양**(`| (bash)`·`while read` 루프·`flock`·`su -c`·`pwsh` 등)은 못 잡음). 복합 액션의 node 자바스크립트·docker 액션이 짓는 파일은 안 읽습니다. setup-python 키 제한은 운영자 루프 두 워크플로에만 걸립니다.
- 진짜 pip 파서와 견주는 시험은 새 pip 가 별칭을 더해 구조가 달라지면 거짓 빨강 대신 **경고 후 건너뜁니다**(검증기가 아는 오래된 철자를 놓치면 여전히 빨강 — 새 별칭을 놓친 경우의 알림이 경고뿐이라는 약화를 문서에 적었습니다).
- 검사 취소 한 줄은 GitHub 의 '대기 중 실행은 더 새 실행으로 대체될 수 있다' 동작이 남아 병합 직후 검사가 항상 끝까지 도는 것은 아닙니다 — 문서에 한계로 적었고 **병합 뒤 첫 관측으로 확인**하겠습니다.
- 이 PC 에서 `actionlint`·Linux CI 를 못 돌렸습니다(블로그 검사가 대신 돕니다).
- **운영자께 여쭐 것(급하지 않음, 기본값으로 진행해 두었습니다)**: ① setup-python `with` 제한을 모든 워크플로로 넓힐지 ② 설치 줄 검사를 환경 변수·설정 파일·`pip download` 까지 넓힐지 ③ 다른 저장소 재사용 워크플로를 SHA 고정이어도 오류로 둔 더 엄격한 선택 확정 ④ naver·tistory 의 동적 색인 한 식 허용을 계속할지 ⑤ 셸이 파이프·here-string 입력을 받는 줄을 pip 가 있든 없든 모두 오류로 둔 것(지금 저장소 0줄) ⑥ pip 파서 시험의 '경고 후 건너뜀' 완화 확정 — **모두 추천: 지금 기본값 그대로**.
