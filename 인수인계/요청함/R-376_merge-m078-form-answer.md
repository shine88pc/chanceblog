## 1. 무엇을 바꾸는지
- **확인 021(이슈 #217, 선택 ②)** — 옛 답변 양식 `AI 요청에 답하기(결정·확인) (이전 R 번호용)`(파일 `ai-reply.yml`)을 없앱니다. New issue 화면의 양식이 `AI 확인 요청에 답하기(대상번호)`·`AI 에게 새 일 맡기기(작업 요청)`(그 밖의 고정 페이지·이미지 양식은 그대로)만 남습니다. 그 양식을 가리키던 안내 문장(새 양식·작업 요청 양식의 안내 글·접수 봇의 거절 안내·폰 알림 문구·문서·검증기)을 새 현실에 맞췄습니다.
- **확인 022(이슈 #218, 선택 ②)** — 새 답변 양식의 `대상번호` 칸에 **`19` 만 써도 `019` 로 읽습니다**(`1`→`001`, `19`→`019`, `135`→`135`, 1000 이상은 그대로). 접수 답글에 '입력한 대상번호를 019 로 읽었습니다(앞의 0 은 자리 채움입니다)' 줄이 붙고, 폰 알림에는 읽은 번호(`✅ 답변 접수 019 → 선택 ②`)가 보입니다. 양식의 예시도 `001` 에서 `019` 로 바꿨습니다.
- **계속 거절하는 것**: 번호가 `0`·`00`·`000`(새 사유 '0 입니다'), 앞에 0 이 더 붙은 `0019`, 전각·다른 문자 체계의 숫자, 부호·소수점·16진수, 글자가 낀 `19번`, 번호 둘(`19 20`), `P`·`M` 으로 시작하는 알림 번호, 빈 값. 양식 칸·선택 칸·승인 보기는 바뀌지 않았습니다.

## 2. 왜 필요한지
운영자님이 이슈 #215 에서 '옛 r000 꼴 답변 방식을 없애 달라', 이슈 #216 에서 '019 를 19 로 써도 되게' 요청하셨습니다. 확인 019·020 의 답이 옛 양식에 올라가 자동 접수가 거절한 일(P080)이 있었고, 옛 양식이 첫 화면에 남아 새 양식 대신 쓰이는 것이 원인이었습니다.

## 3. 사용자가 체감하는 변화
- 병합 뒤 New issue 에서 답변 양식이 하나뿐입니다(`AI 확인 요청에 답하기(대상번호)`). 텔레그램 확인 요청의 `답하기` 주소는 처음부터 이 양식을 바로 엽니다(바뀐 것 없음).
- 대상번호는 텔레그램 확인 요청 맨 위의 숫자 그대로 쓰시거나 앞의 0 을 빼고 쓰셔도 됩니다. 선택은 '그 요청의 승인 보기 번호'를 직접 고르는 것은 그대로이고, 대상번호만 올린 답은 '확인함'일 뿐 승인이 아닙니다.
- 이미 올라온 옛 형식 이슈(#213·#214 등)는 지우지 않으며, 접수 코드가 예전처럼 읽어 '양식 모양이 달라 처리하지 못했습니다 — 새 양식으로 다시 올려 주세요' 로 답합니다.

  - ① **목록 밖이라 일부러 안 고친 두 곳**(승인 목록에 없어서 되돌렸습니다): `.github/workflows/operator-reply.yml` 머리 주석 4행이 이미 낡은 메뉴 이름을 가리키는 것(주석뿐, 동작 같음)과 `pipeline/telegram_inbox.py` 안내 문장의 '옛 요청은 r001 같은 번호' 한 구절(봇에 `/start` 를 보내면 나오는 글). 시험이 이 두 곳만 정확히 예외로 못박고 있어 누가 고치면 시험도 같이 고치면 됩니다. 고쳐도 되는지는 다음 확인 요청으로 여쭙겠습니다.
  - ② `01` 처럼 앞에 0 이 하나 붙은 두 자리도 `001` 로 받습니다('앞을 0 으로 채워 세 자리로' 를 그대로 읽은 결과이고 번호가 두 가지로 읽히지는 않습니다). 거절을 원하시면 한 줄 고치면 됩니다.
