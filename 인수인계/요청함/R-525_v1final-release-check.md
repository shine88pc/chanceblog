# 병합 요청 M126 — 릴리스 후보 점검 스크립트 (앱, T1)

> **병합 방식**: 지금은 AI 병합 기능이 **꺼져 있어** 운영자께서 직접 병합해 주세요. (`M126 승인` 이라고 답하셔도 아직 AI 가 병합하지 않습니다.) 이 요청은 앱 저장소 `chanceblog-desktop` 의 것이고, PR 제목 맨 앞이 `[M126]` 인 것 하나만 병합합니다. 검사는 이미 끝나 초록입니다. 급하지 않습니다(보통).

## 1. 무엇을 바꾸는지
앱 v1.0 완료 기준(열두 항목)이 채워졌는지를 **한 번에 보여 주는 점검 스크립트**를 더합니다. **스크립트·시험·문서뿐이고 제품 코드·`.github/`·`vendor/`·의존성·`capabilities.py` 스위치·`service/external.py`·VERSION 은 0줄입니다.** 스크립트는 표준 라이브러리만 쓰고 읽기만 하며 네트워크를 쓰지 않고, **'선언'은 하지 않습니다**(결과를 보여 줄 뿐 선언은 운영자 몫).
① **`scripts/release_check.py`**: 열두 항목마다 `PASS`·`FAIL`·`수동(운영자)`·`아직(미구현)` 중 하나와 근거 한 줄을 표로 냅니다(지금 이 저장소: PASS 2·FAIL 0·수동 3·아직 7 — 대부분 '아직'·'수동' 이 정상입니다).
② **후보 산출물 키 모양 훑기**(`--scan-dir 폴더`): 설치 파일을 풀어 놓은 폴더·로그·백업·진단 복사본을 기존 `security/scan.py` 의 여섯 모양(새 검사 규칙은 만들지 않음)으로 덩어리째 훑어 **발견 0·읽지 못함 0 일 때만** 10번 PASS 로 냅니다. 큰 파일·zip·압축을 읽고, 읽지 못한 파일은 숨기지 않고 세며, 링크는 따라가지 않고, 출력에는 키 글자가 없습니다.
③ 시험 새 모듈 둘(257개)과 시험 도구 하나, 문서(결정 D-670–D-675·구조 문서·변경 이력).

## 2. 왜 필요한지
v1.0 선언 전에 '무엇이 됐고 무엇이 남았는지'를 사람이 일일이 읽지 않고 같은 기준으로 확인하고, 설치 파일·로그에 비밀이 남지 않았는지 기계로 한 번 더 보는 안전 장치입니다.

## 3. 사용자가 체감하는 변화
**없습니다.** 앱 화면·기능·동작은 그대로이고 개발 도구(운영자·AI 가 명령줄로 돌리는 점검)만 늘어납니다.

## 4. 위험과 알려 둔 한계
- **알려 둔 한계**: ① 길이 상한이 없는 토큰(JWT·Bearer 값)이 **32,768 글자보다 길고** 덩어리 경계(1MiB)에 걸리면 놓칠 수 있습니다(숫자를 문서·주석에 적었고 '읽지 못함' 으로도 세지 않음 — 실제 JWT·Bearer 값은 보통 몇 KB). ② 읽음으로 세지만 못 보는 것(표지 없는 UTF-16·UTF-32 일부·NTFS 대체 스트림·목록 밖 압축·PyInstaller 묶음 안쪽)은 문서에 이름으로 적었습니다. ③ 구현 흔적을 찾는 판독(7·9·11번)은 이름 어림짐작이라 구현이 있는데 '아직' 에 머무는 경우가 있을 수 있습니다(문서에 적음). ④ 4번(기본 설정에서 유료 호출 불가)은 소스의 상수·용도 기본값을 읽는 정적 확인이고 실제 0 호출은 기본 설정 시험(네트워크 갈래)이 봅니다. ⑤ 윈도에서만 돌려 봤고 리눅스는 앱 검사(CI)가 첫 확인입니다.
- **운영자께 여쭐 것(급하지 않음, 이번 병합과 별개)**: ① 32,768 글자 한도로 충분한지 — **추천: 충분**(더 키우려면 상수 하나) ② 11번(설치 파일 코드) 판독이 보는 설치 정의 파일 확장자(`.iss`·`.nsi`·`.wxs`·`.nuspec`)는 설치 도구를 정한 뒤 맞춥니다 — **추천: 설치 도구 시험 갈래 뒤에 맞추기**.

## 5. 시험·독립 검증 결과
- 시험 13,505 → 13,762개(+257, 3.12·3.10·PySide6 있는 3.12 모두 같음 — 앞선 병합 두 개를 합친 값), 사라진 시험 0, 변이 88개 모두 시험이 잡음(앞 구현의 변이 21개도 새 시험으로 다시 잡음).
- 독립 확인(구현자와 다른 AI): 1차 안전 S·시험 Q 둘 다 **수정 필요**(필수 1씩 — 긴 토큰이 덩어리 경계에서 새던 것, 건너뜀 문구가 Qt 칸 갈래와 합치면 빨개지는 것) → 재작업 → **재확인 통과**(필수 0·권고 1·참고 8) — 긴 토큰 재현 4/4 닫힘·내 생성기 8,600회에서 '32,768 글자 이하 놓침 0'·바꾼 기존 시험 16개 중 종료 코드 단언 한 곳만 의도해서 느슨(진짜 저장소의 FAIL 줄을 허용 — 권고로 기록)·새 변이 65개 중 58개 잡음. 못 한 것: 우분투 실제 실행(아래 검사가 확인).
- **병합 맞춤(앞선 병합과 겹친 곳)**: 결정 행 D-670–D-675 를 앞선 병합의 행 앞에 번호순으로 끼웠고, D-675 위치 시험을 '다음 줄이 빈 줄이거나 다른 결정 행' 으로 맞췄습니다(같은 큰 표 안이라는 점은 그대로).
- 검사(CI): 앱 12칸이 모두 초록입니다(Windows·Ubuntu × 파이썬 3.10·3.12 × 시험 조각 3개, 17분 31초, 가지 머리 `8e105e9`) — 앞선 병합 두 개(M123·M124)가 들어간 나무에서 돈 값입니다. 앱 검사는 화면(Qt) 시험을 건너뜁니다(이 갈래는 Qt 시험이 없음).
