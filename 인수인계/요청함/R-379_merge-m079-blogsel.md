# 병합 요청 M079 — 블로그 관리 화면을 '등록한 블로그 + 블로그 추가' 와 고르는 입력으로 바꿉니다

> **병합 방식**: 지금은 AI 병합 기능이 **꺼져 있어** 운영자께서 직접 병합해 주세요. (`M079 승인` 이라고 답하셔도 아직 AI 가 병합하지 않습니다.) 이 요청은 앱 저장소 `chanceblog-desktop` 의 것이고, PR 제목 맨 앞이 `[M079]` 인 것 하나만 병합합니다. 검사는 이미 끝나 초록입니다. **병합 시점 안내**: 시험지(`docs/PERSONAL_PC_TEST.md`)의 블로그 등록 단계가 새 화면 기준이라 **지금 시험 중이신 옛 Package 와는 화면이 달라 맞지 않습니다 — 다음 Package 를 만드시기 직전에 병합하시길 권합니다.** 급하지 않습니다(보통).

## 1. 무엇을 바꾸는지
- **카드**: 블로그 관리 목록에 **등록한 블로그만** 별명으로 보이고(별명이 없으면 `네이버 블로그 1` 같은 종류+번호), `네이버 A`·`Blogger 영문` 같은 **슬롯 이름은 화면 어디에도 없습니다.** 목록 맨 끝에 점선 **`블로그 추가`** 카드가 생겨, 누르면 종류(네이버 블로그·Blogger·GitHub Pages)를 고르고 같은 종류의 빈 자리가 속에서 쓰입니다(`연결 N개 · 남은 자리 N개`, 자리가 없으면 이유가 보임).
- **새 블로그 폼**: 이름 칸은 비어 있고 별명은 제안해 미리 넣으며 `저장`·`취소` 둘입니다(저장 전에도 `등록 전` 카드로 남아 다른 카드를 열었다 돌아와도 입력이 안 지워집니다).
- **고르는 입력**: 주요 주제(26)·카테고리(11)·우선/제외 키워드(27)는 제안 칩을 먼저 보이고(직접 추가는 보조·한도와 우선/제외 겹침은 칩이 못 만듦), 채널 역할·대상 독자·문체는 보기 칩 + `직접 입력`, 별명·소개글은 제안 문장 + `쓰기`, 이미지는 읽기 전용 칸 + 파일 고르기. 저장되는 값은 기존과 같은 글입니다.
- **앱 창을 닫을 때**: 저장하지 않은 블로그 입력이 있으면 확인창이 뜹니다(초안 화면의 확인과 겹쳐도 블로그 확인이 이어서 뜸).

## 2. 왜 필요한지
운영자님이 이슈 #207(11-15)에서 '카드를 깃허브 페이지·Blogger 영문/한글·네이버 A/B 로 특정해 보이지 말고 사용자가 필요한 사이트의 블로그를 연결할 수 있게, 키인 입력은 프로그램이 제안하고 선택하게' 요청하셨습니다.

## 3. 사용자가 체감하는 변화
블로그 관리 화면 하나만 달라집니다. 글쓰기·후보·초안·발행 흐름과 다른 화면은 그대로입니다(다른 화면의 `네이버 A·B` 이름은 아래 4 의 한계와 후속).

## 4. 위험과 기존 기능에 미치는 영향
- **기존 기능**: 영향이 없습니다. 서비스·저장 형식(판 2)·백업 형식·엔진·`vendor`·`.github`·의존성은 한 줄도 바꾸지 않았습니다(변경 28개 파일 — 새 4(코드 1·시험 3)·수정 24). 저장되는 값은 기존과 같은 글이고, 화면으로 저장한 파일이 서비스 함수로 직접 저장한 파일과 바이트까지 같다는 것을 시험이 견줍니다.
- **솔직하게 알려 드릴 점**
  - ① **슬롯 다섯·종류 셋(네이버 둘·Blogger 둘·GitHub Pages 하나)이 한계입니다.** 운영자님 요구 '어느 사이트든' 과 직접 부딪히고, 풀려면 저장 형식 판 3 과 새 채널이 필요한 **대규모 작업(T3)** 이라 이번에 하지 않았고 따로 여쭙겠습니다.
  - ② **다른 화면(Seed·후보·초안·홈)은 아직 `네이버 A·B` 이름을 씁니다** — 별명으로 바꾸는 후속(BLOGSEL-2)을 추천대로 이어서 진행 중입니다.
  - ③ 칩 Tab 이동이 깁니다(이름 칸에서 저장까지 134번)·복제하면 두 카드 제목이 같음·목록 순서가 슬롯 순서라 `Blogger 2` 가 `Blogger 1` 위에 보일 수 있음·꺼진 칩의 이유가 툴팁에만 있음 — 문서에 한계로 적었고 후속(BLOGSEL-2)에 들어 있습니다.
  - ④ 쓰는 중이거나 읽기에 실패한 상태에서는 창 닫기 확인을 묻지 않습니다(영영 안 닫히는 길을 만들지 않으려는 의도 — 그동안 저장 전 입력은 확인 없이 사라질 수 있음).
  - ⑤ 새 블로그 폼으로 옮겨 온 입력은 옛 슬롯의 기본값(협찬 가능 분야·Blogger 언어)을 '사용자가 본 값' 그대로 가져갑니다.
  - ⑥ **화면 확인의 한계**: Qt 화면은 이 PC 에서 오프스크린으로만 띄워 확인했습니다(스크린샷과 화면 시험 87개). **실제 윈도 125%·150% 렌더·한글 입력기·화면 읽기 프로그램·파일 고르기 창·`취소` 뒤 키보드 포커스·창 닫기 확인창·실제 마우스 더블클릭은 운영자 PC 에서 확인해야 합니다.** 저장소 CI 에는 PySide6 가 없어 Qt 시험은 CI 에서 건너뛰어 초록으로 보이며 이 PC 와 운영자 PC 에서만 돕니다.
  - ⑦ 이 가지의 앞선 커밋 저장소 검사에서 파이썬 3.10 윈도 한 칸이 한 번 빨갛다 같은 커밋 재실행에서 초록이었습니다(불안정으로 봄).
