# 병합 요청 M128 — 설치 도구 시험 준비물 (앱, T3)

> **병합 방식**: 지금은 AI 병합 기능이 **꺼져 있어** 운영자께서 직접 병합해 주세요. (`M128 승인` 이라고 답하셔도 아직 AI 가 병합하지 않습니다.) 이 요청은 앱 저장소 `chanceblog-desktop` 의 것이고, PR 제목 맨 앞이 `[M128]` 인 것 하나만 병합합니다. 검사는 이미 끝나 초록입니다. 급하지 않습니다(보통).

## 1. 무엇을 바꾸는지
앱 v1.0 의 정식 설치 파일을 만들 도구(Velopack 의 두 방식과 Inno Setup)를 문서가 아니라 **측정**으로 고르기 위한 시험 준비물입니다(운영자 확인 037 ①). **앱 코드·`vendor/`·의존성·`capabilities.py` 스위치·`service/external.py`·VERSION 은 0줄이고, 기존 워크플로(`ci.yml`·`package.yml` 등)는 한 글자도 안 바뀝니다.**
① **새 워크플로 `.github/workflows/installer-spike.yml` 한 개** — **수동 실행(workflow_dispatch) 전용**·입력칸 0·`contents: read`·시크릿 0·`windows-latest`·액션은 `package.yml` 과 같은 승인된 세 SHA·보고서 둘만 14일 올림. **병합만으로는 아무 일도 일어나지 않습니다** — Actions 화면에서 Run workflow 를 눌러야 돌고, 그 실행은 따로 번호 있는 부탁으로 여쭙겠습니다.
② `packaging/spike/`: 도구 잠금 표(`tools.lock.json` — 고정 해시의 내려받기만)·`fetch_tools.py`·단계 실행기 `run_spike.py`(설치 도구 설치 → 번들 → 포장 → 측정 → 보고서 다섯 단계)·측정 M01–M22 `measure.py`·시험용 작은 앱 둘·`ChanceBlogSpike.iss`.
③ 시험 여섯 파일과 가짜 바깥 세계 도우미 둘(설치 도구·윈도·네트워크 없이 흐름 전체를 돌림), 그리고 `tests/test_workflow_artifacts.py` 의 허용 모양을 넷에서 여섯으로 강화.
④ 문서: 운영자 실행 안내 `docs/INSTALLER_SPIKE_RUN.md`·결정 D-700–D-708·SECURITY·PACKAGE·PACKAGE_OCR·RELEASE·CHANGELOG 문장과 결정 색인(다시 만든 생성물).

## 2. 왜 필요한지
설치·갱신 도구는 한 번 고르면 바꾸기 어렵습니다. 이 시험은 세 갈래(A·B·C)를 같은 조건에서 만들어 보고 **측정 22항목**(설치 크기·시간·바로가기·삭제 시 데이터 보존·갱신·백신 검사·권한 등)으로 점수를 매겨 근거 있게 고르려는 것입니다(설계서 INSTALLER 3-1).

## 3. 사용자가 체감하는 변화
**없습니다.** 앱 화면·기능은 그대로이고, 병합만으로는 워크플로가 돌지도 않습니다.

## 4. 위험과 알려 둔 한계
- **이 스크립트는 진짜 도구와 한 번도 돌려 보지 않았습니다.** 가짜 바깥 세계 시험으로만 흐름을 확인했고, 진짜 Velopack·Inno Setup·방화벽·Defender 동작은 운영자의 수동 실행 한 번이 알려 줍니다(항목마다 오류를 가둬 첫 실행에서 값을 최대한 얻도록 했습니다).
- **실행하면 일어나는 일(병합과 별개, 실행 부탁에서 따로 여쭙니다)**: GitHub 가 빌려 주는 **일회용 윈도 가상 머신 안에서만** 방화벽 규칙·가짜 자격 증명·임시 사용자를 만들었다 치우고, 고정 해시 도구(GitHub 릴리스 호스트·PyPI)를 내려받습니다. 개인 PC 에서 실수로 돌지 않게 시작 전에 거절하는 장치(종료 코드 2)가 있으나 **환경 변수를 일부러 맞추면 통과하는 실수 방지 장치이지 보안 장치가 아닙니다**(D-708).
- 임시 비밀번호는 보고서에서 가리지만 일부 변형(다른 글자가 낀 글·거꾸로·base64)은 못 가립니다 — 일회용 가상 머신의 임시 사용자용 값이라 위험은 작습니다.
- Inno Setup 은 러너에 깔린 판이 6.7 줄이 아니면 갈래 C 를 '없음'으로 기록합니다.
- 윈도 러너에서 한 시험(`…a_missing_inno_is_unavailable_not_failed`)이 처음에 빨갰던 것은 **러너 이미지에 Inno Setup 이 이미 깔려 있어 '없음' 시험에 보였기 때문**이고 고쳤습니다(검사 진단으로 원인을 찾음).
- 새 결정 D-700–D-708 의 상태 칸은 이번 병합으로 '독립 검증 통과' 로 갱신했습니다.
- **운영자께 여쭐 것(급하지 않음, 이번 병합과 별개)**: 병합 뒤 실행 부탁(수동 실행 한 번 — 약 40–60분, 결과 블록을 이슈 양식에 붙임)을 보낼 때 운영자 PC 에서 하실 일은 Actions 화면의 Run workflow 한 번뿐입니다.
