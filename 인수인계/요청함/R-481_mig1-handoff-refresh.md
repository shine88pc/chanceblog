# 병합 요청 M113 — 새 PC 이어받기 보강 (MIG1)

> **병합 방식**: 지금은 AI 병합 기능이 **꺼져 있어** 운영자께서 직접 병합해 주세요. (`M113 승인` 이라고 답하셔도 아직 AI 가 병합하지 않습니다.) 이 요청은 블로그 저장소 `chanceblog` 의 것이고, PR 제목 맨 앞이 `[M113]` 인 것 하나만 병합합니다. 검사는 이미 끝나 초록입니다. 급하지 않습니다(보통).

## 1. 무엇을 바꾸는지
운영자께서 PC 를 옮기실 때(개인 PC·무료 AI 한도) 이 PC 의 로컬 파일 없이도 새 세션이 첫 보고·병합 부탁·병합 확인·검사 확인·감시를 이어받도록 **문서·도구·기억을 저장소로 올린** 묶음입니다. **기능 코드·워크플로·광고·레지스트리 값은 바꾸지 않았습니다.**
① **입구**: `CLAUDE.md`·`AGENTS.md` 읽는 순서에 '최신 한 장'(요청 가지의 마지막 진행 현황 알림) 단계를 더하고, `인수인계/작업내용.md` 의 30초 카드를 줄여 불변 규칙·승인 목록을 현행으로 고쳤습니다. 작업내용 21곳을 현행화하고 11-24 아침 덧붙임(밤사이 병합·알림 워크플로 수정)을 더했습니다.
② **개인 PC 운영 계약·이관 절차**: `docs/AGENT_RUNBOOK.md` §8(미정 항목은 지어내지 않고 '미정' 으로 표시)과 `docs/SESSION_START.md` §8(옛 PC 5단계·새 PC 7단계 — 한 PC 라 **실제로 해 보지는 못했다**고 적음).
③ **도구 사본 33개**: 작업 폴더의 현행 도구·규칙 문서를 일반형으로(윈도 계정 이름·고정 작업 폴더·개인 메일·키 없음) `인수인계/도구/work/` 에. 감시기 사본은 자기 종료(약 29분)를 더해 고아가 GitHub 조회 한도를 갉아먹은 사고를 새 PC 로 옮기지 않습니다. Qt 윈도 러너 도구 셋은 승인 근거 문제로 일부러 뺐습니다.
④ **기억 사본 10개**: 운영자 상시 지시·정책·운영 교훈을 개인 값을 가려 `인수인계/AI_기억/` 에(사진 가지 이름·해시·계정 사용량 수치 등도 말로 바꿈).
⑤ **외부 접속 등록 장부 한 파일**: `pipeline/egress.py` 에 운영 도구 사본 14곳의 예외를 등록했습니다 — 모두 사람이나 AI 세션이 직접 실행하는 도구이고 워크플로·예약이 부르지 않으며 접속 대상은 자기 저장소의 GitHub 공개 REST 와 로컬 git 뿐입니다(시험이 요구하는 등록).

## 2. 왜 필요한지
PC 이전 때 로컬에만 있던 도구·규칙·기억이 사라지면 새 세션이 처음부터 다시 배워야 합니다. 이 묶음이 그 간격을 메웁니다.

## 3. 사용자가 체감하는 변화
**지금은 없습니다**(문서·도구 사본·등록 장부뿐 — 사이트 화면·공개 글·알림 동작 그대로).

## 4. 위험과 기존 기능에 미치는 영향
- **기존 기능**: `.github/`·광고 표면·`ads.txt`·레지스트리 값·시크릿·의존성은 바뀌지 않았습니다. 검증기 출력은 시작점과 같습니다(오류 0·경고 3).
- **공개 저장소라 개인정보를 특히 점검했습니다**: 독립 검증이 추가된 줄 전부를 정규식 14종과 눈으로 훑어 윈도 계정 이름·개인 메일·사진 파일 이름·비밀 모양이 없음을 확인했고, 기억 사본 셋은 원본과 대조했습니다.
- **알려 둔 한계**: 이관 절차(SESSION_START §8)는 한 PC 라 실제로 해 보지 못했습니다 — 첫 실제 이관 때 어긋난 곳을 고칩니다. 옛 11-04 기억 사본 넷에는 세션 번호가 가려지지 않은 채 남아 있습니다(이미 main 에 있음, 후속 정리 대상).
- **운영자께 여쭐 것(이번 병합과 별개)**: 개인 PC 에서 AI 상주 여부·크론과 감시기를 켤지·'프로그램 완성' 의 기준·다음 PC 가 개인 PC 인지 빈 공용 PC 인지는 문서에 '미정' 으로 두었고 번호 있는 확인 요청(032 와 이후)·이슈로 여쭙니다.
