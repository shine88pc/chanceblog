# R-020 · Gemini 멈춤 방지 수정 PR 병합 부탁

## 한 줄
오늘 낮 한글 Blogger 수동 실행이 **15분 제한으로 취소**됐습니다(같은 때 영문도 10분이나 걸렸습니다). 글을 쓰는 AI(Gemini) 호출이 **응답 없이 멈춘 것으로 보이는데**, 멈춘 호출을 기다리는 시간에 상한이 없었습니다. **호출 하나가 120초를 넘기면 포기하고 다음 모델로 넘어가게** 고쳤습니다. 병합해 주세요.

## 하실 일 (2분)
1. 저장소 첫 화면(https://github.com/shine88pc/chanceblog) 맨 위 노란 **"ai/claude/llm-call-timeout had recent pushes" — Compare & pull request** 배너를 누릅니다. 배너가 여러 개면 이름에 `llm-call-timeout` 이 든 것입니다. 배너가 안 보이면 이 주소를 엽니다: https://github.com/shine88pc/chanceblog/compare/main...ai/claude/llm-call-timeout?quick_pull=1
2. **제목은 그대로 두고** 초록 **Create pull request**.
3. 화면 맨 아래 검사가 모두 초록(All checks have passed)이 될 때까지 기다린 뒤(보통 5~10분) **Squash and merge → Confirm squash and merge**. **Delete branch 는 누르지 않습니다.**

병합하셨는지는 제가 직접 확인합니다.

## 무슨 일이 있었나 (쉬운 설명)
- 12시쯤 R-019 안내대로 영문·한글을 수동 실행하셨습니다. 글을 만드는 단계는 평소 **21초**면 끝나는데, 영문은 **10분 36초** 걸려 겨우 성공했고(첫 번째 AI 모델이 멈췄다가 두 번째 모델로 넘어간 것으로 보입니다), 한글은 **15분 제한(GitHub 이 실행 하나에 주는 최대 시간)을 넘겨 취소**돼 글이 올라오지 않았습니다.
- 멈춘 위치는 실행 상세 로그가 로그인 없이는 안 보여 **추정**입니다. 다만 AI 호출에 시간 상한이 없던 것은 코드로 확인했습니다. 사진 기능이 글마다 AI 호출을 1회 늘려 멈춤을 만날 확률도 늘었습니다.

## 바뀌는 것 / 안 바뀌는 것
- **바뀜**: 블로그 글 자동 작성(Blogger 영문·한글, 티스토리·네이버 초안 패키지)과 이슈 수정 요청 처리가 쓰는 AI 호출 하나마다 **120초 상한**(이슈 수정은 짧은 일이라 영향이 거의 없습니다). 넘으면 같은 모델을 다시 부르지 않고 바로 다음 모델로 넘어가며, 멈춘 모델은 같은 실행의 다음 호출에서 맨 뒤로 보냅니다(글 만들기 → 사진 검색어 만들기가 같은 모델에서 두 번 멈추지 않게). 일시적 오류(과부하 등)의 재시도는 그대로입니다.
- **안 바뀜**: 모델 목록·프롬프트·글 검사 규칙·AI 고지문·시크릿·광고·`mode`·워크플로 파일. **Chance 블로그의 글 생성기는 이번에 안 바뀝니다**(같은 문제가 남아 있어 따로 다룹니다 — 결함 대장 D-66).
