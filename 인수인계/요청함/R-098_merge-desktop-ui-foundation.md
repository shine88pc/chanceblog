## 무엇이 바뀌나 (쉬운 설명)
운영자님이 11월 3일 저녁에 주신 화면 디자인 명세(승인하신 목업)를 만드는 **첫 묶음**입니다. 화면은 **내 데이터를 읽기만 하고 아무것도 쓰거나 보내지 않습니다**(키 보관·발행·파일 저장 없음).

1. **화면 도구는 PySide6 로 확정**합니다(결정 D-32 — 처음 설계의 '또는' 을 닫음). 선택 설치라서, PySide6 가 없으면 화면 명령은 쉬운 한국어 안내 뒤 끝나고 **명령줄 기능은 그대로** 동작합니다.
2. **실행**: `python -m chanceblog_desktop gui` — 내 데이터 폴더를 읽기 전용으로 보여 주고, `--sample` 을 붙이면 예시 데이터로 보여 줍니다(`--data-dir 폴더` 로 폴더 지정).
3. **들어간 화면**: 홈(요약 카드 4개·맞춤 주제 추천·내 블로그 현황·빠른 작업·활용 팁), 상태 화면 다섯(불러오는 중·빈 화면·오류·일부만·오프라인), 앱 틀(상단바·왼쪽 메뉴 6개·본문·서랍·대화상자). **홈 말고 메뉴 5개는 '아직 만들고 있어요' 안내 화면**입니다(다음 묶음).
4. **디자인 기준**: 밝은 테마만, 글자 색 5단계, 글꼴은 윈도 시스템 글꼴, 선 모양 아이콘 한 벌, 누르는 칸 크기·키보드 포커스 표시를 값(토큰)으로 한곳에서 관리합니다.
5. **사진 규칙**: Unsplash 사진 출처 두 줄 복사 규칙과 내 사진(JPG·PNG·WebP, 20MB 이하, 실제 이미지인지 검사) 규칙이 들어 있지만 **아직 실제 Unsplash 를 부르지 않고** 예시 데이터로만 보입니다.
6. **비밀이 화면에 나가지 않게**: 블로그 이름·오류 문구는 키 모양을 가린 **뒤에** 잘라 보여 주고, 화면 명령의 사용법 오류도 친 값을 되풀이하지 않습니다.

**바뀌지 않는 것:** 기존 명령(후보·글·네이버·Pages 올리기·`keys`)의 동작과 서비스 층·키 보관 코드입니다. 화면을 직접 띄워 보시기 전에도 `docs/images/ui/` 의 확인용 캡처 13장(예시 데이터)으로 모양을 보실 수 있습니다.

## 확인한 것
- 독립 검증 2회(구현자와 다른 AI 가 새 복사본에서, 진짜 창은 각 회 두 번만 띄우고 나머지는 창 없이). 1차는 **'조건부 병합 가능'**(높음 0·중간 6)으로, 병합 전에 고칠 것 2건 — 블로그 이름에 키 모양이 있으면 앞 24~26자가 화면 오른쪽에 보이던 것, 화면 명령의 사용법 오류가 친 값을 되풀이하던 것 — 과 결정 번호·문서 정정을 짚었습니다. 그 2건과 권장 3건(긴 이름이 잘리던 것·진짜 창에서 단추마다 검은 포커스 사각형이 겹치던 것·화면 처리 중 예외와 취소 처리)을 모두 고쳤고, 일부러 어겨 본 변이 71곳을 시험이 모두 잡도록 보강했습니다. 2차(재확인)는 **'병합 가능(조건 없음)'**입니다 — 화면용 값에 키 앞부분이 남는 경우는 블로그 이름 1,276건 중 188건→0건, 오류 문구 15,312건 중 588건→0건이 되었고(가린 뒤에 자르는 것을 29.9만 가지 조합과 진짜 화면 글 6.1만 건으로 점검), 사용법 오류가 친 값을 되풀이한 건수는 형태 46가지×가짜 키 5종을 진짜 프로세스로 195~230건씩(파이썬 3.12+PySide6·3.10.11·3.12) 돌려 0건, 진짜 창에서 Tab 으로 닿는 단추 23개 모두 검은 포커스 사각형이 없고(고치기 전엔 단추마다 있었음) 글자 잘림은 2건→0건입니다. 시험: 화면 시험 205개가 파이썬 3.12+PySide6 에서 모두 OK, 진짜 3.10.11 과 PySide6 없는 3.12 에서도 모두 OK(Qt 시험 81개만 건너뜀), 기존 명령줄 회귀 121개 OK, 지역·글자 인코딩을 바꾼 환경 4종에서도 같은 결과입니다. 내 데이터를 읽기만 하는지도 확인했습니다(진짜 데이터 폴더에 눌러 본 뒤 파일·크기·시각·목록 변화 0, 네트워크·자식 프로세스 0, 없는 폴더를 줘도 폴더 생성 0). 검증자가 새 main(889b1c6) 위에 직접 합쳐 본 트리에서도 화면 205개와 키 보관·한도·제안 핵심 25개 모듈(1,173개)이 3.12·3.10 모두 통과했습니다 — 이 브랜치는 그 합침과 문서 충돌 풀이·결정 번호(D-32)만 다릅니다. 합친 뒤 문서를 읽는 시험 3개 모듈(저장소 구조·원고 모델·점수 계산 — 89개)은 제가 다시 돌려 통과했습니다. 남은 것은 낮은 지적 6건뿐이며 아래 한계에 적었습니다.
- 이 브랜치의 자동 검사: 4칸(Windows·Ubuntu × 파이썬 3.10·3.12) 모두 초록 — 11:08 에 시작해 11:25 에 끝났고 17분 36초 걸렸습니다. PR 화면의 검사도 이 결과를 그대로 보여 줍니다. 자동 검사에는 PySide6 가 없어 화면(Qt) 시험 81개는 건너뛰며, 그 시험은 아래 독립 검증과 개발 PC 에서 돌렸습니다.
- 변경 범위: 파일 56개(고친 6·새 50 — 화면 코드 21·시험 6·점검 도구 4·문서 6·확인용 캡처 13), 줄 수로는 거의 새로 추가한 것입니다(+7077 −6). 기존 파일은 `__main__.py`(화면 명령 등록)·README·문서 4개에 조금씩입니다.

## 솔직한 한계 (병합을 막지 않음)
- **자동 검사는 화면 코드를 검증하지 않습니다.** 자동 검사 환경에는 PySide6 가 없어 새 시험 205개 중 화면(Qt) 시험 81개는 건너뜁니다(나머지 124개는 돕니다). 화면 코드는 개발 PC 와 독립 검증자가 직접 돌려 확인했습니다. 병합 뒤 별도 묶음으로 자동 검사에 화면 칸을 더하겠습니다(검사 설정 변경이라 따로 다룹니다).
- **진짜 윈도에서의 확인이 남았습니다.** 화면 배율 125·150%, 한글 입력기, 화면 읽기 프로그램은 이 개발 PC 에서 시험하지 못했습니다. 진짜 창은 독립 검증자가 두 번만 띄워 포커스 사각형·글자 잘림을 확인했고 나머지는 창 없이 환경별로 재는 도구로 점검했습니다. 운영자님 PC 에서 보실 때 어색한 곳이 있으면 알려 주세요.
- **일부 키 모양(`sk-proj-`·`sk-ant-` 등)은 가려지지 않습니다** — 키 가리개 규칙 자체의 기존 한계이고 'c3' 묶음이 보강합니다. 화면에 키가 나올 경로는 막아 두었지만 마지막 방어선이 약한 부분입니다.
- **PySide6 는 LGPL 입니다.** 개발·시험에는 문제가 없지만 설치 파일에 넣어 배포할 때는 고지와 재배포 조건 검토가 필요합니다(`RELEASE.md` 에 적었고 설치 파일 묶음 때 다룹니다).
- 독립 검증이 찾은 낮은 지적 6건(공백이 든 경로 지우기·표준 오류가 없는 실행의 한 줄 기록·취소 뒤 안내 중복·문서 정정 2건·시험 공백)은 병합 뒤 후속 묶음에서 고칩니다. 현재 동작은 모두 맞고 회귀를 막는 보강입니다.

## 위험과 대비
- 새 코드가 대부분이고 **기존 동작은 바뀌지 않습니다.** PySide6 가 없는 환경(자동 검사 포함)에서도 명령줄은 그대로 돕니다. 되돌려야 하면 병합 한 건을 되돌리는 요청을 드립니다.
