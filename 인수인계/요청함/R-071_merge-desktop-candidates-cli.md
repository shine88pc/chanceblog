# [R-071] 병합 부탁 — 후보 명령줄·CSV 가져오기·프로필 옵션

## 병합할 제목 (이것 하나만)
> **[R-071] 후보 명령줄(candidates)·CSV 가져오기·네이버 프로필 옵션 — 요구서 v0.3.1 1순위 b [대상: 데스크톱]**

- 맨 앞이 `[R-071]` 인 이 제목 하나만 병합합니다. 다른 번호나 다른 제목은 병합하지 않습니다.
- 이번에도 **데스크톱 프로그램 저장소 `chanceblog-desktop`** 입니다(병합 화면 맨 위 저장소 이름 확인). 앞의 후보 데이터 모델 묶음(R-062)이 병합된 뒤의 두 번째 묶음입니다.
- 첫 화면에 노란 배너가 여러 개 보여도(작업 중인 다른 브랜치) 위 제목 하나만 고릅니다.

## 무엇이 들어 있나 (쉬운 설명)
앞 묶음(R-062)이 만든 '주제 후보 그릇'을 **명령으로 쓸 수 있게** 하는 묶음입니다. 화면은 아직 없고, 후보를 밖에서 모아 오는 일(수집)과 초안 문장 만들기도 이번에 없습니다. **병합해도 블로그·네이버에는 아무 일도 일어나지 않습니다.**
1. **후보 명령 `candidates`** — 목록(`list`)·추가(`add`)·보기(`show`)·선택(`select`)·보류(`hold`)·제외(`reject`)·되살리기(`restore`)·검토(`review`)·삭제(`delete`, `--yes` 가 있어야 지움)·글과 연결(`link`/`unlink`). 후보는 목록의 순번이나 번호 앞 4자 이상으로 고르고, 겹치면 어느 후보인지 보여 줍니다. 같은 키워드를 같은 블로그에서 90일 안에 다시 고르면 막지는 않고 경고만 합니다. `list`·`show` 는 보기만 하므로 보관함 파일을 만들거나 옛 구조를 올리지 않습니다.
2. **CSV 가져오기** — 표 파일(CSV)로 후보를 한꺼번에 넣습니다(UTF-8·BOM·한글 Windows 인코딩 자동 판별, 5MB·2000줄까지). 잘못된 줄만 줄 번호와 이유로 건너뛰고 나머지는 저장하며(건너뛴 줄이 있으면 종료 코드 1), **같은 파일을 다시 넣어도 중복되지 않습니다.**
3. **네이버 프로필 선택 항목 명령** — 앞 묶음에서 만든 7개 항목(도입부 스타일·소제목 수·설명 난이도·마무리 방식·제외 주제·같은 주제 재사용 기준·기본 글 유형)을 `naver-profile set` 으로 정하고 `show` 로 봅니다. 새 항목을 안 쓴 프로필의 출력은 예전과 한 글자도 다르지 않습니다.
4. **프로필 항목을 읽는 점검** — 소제목 수가 정한 범위를 벗어나거나 제외 주제 낱말이 글에 있으면 경고만 보여 줍니다(막지 않음).

## 확인한 것
- 독립 검증 2회(구현자와 다른 AI 가 새 복사본에서): 1차에서 **중간 4건**(번호로 후보를 지울 때 뒤 번호가 당겨져 같은 명령을 반복하면 다른 후보가 지워짐·후보 1000개 초과 순번·같은 CSV 를 두 창이 동시에 가져오면 전부 중복·시험 구멍)과 낮음이 나와 모두 고쳤고, 재검증은 **'병합 가능'**(높음·중간 0·낮음 7)이었습니다. 보관함 손상·분실, 비밀 노출, 읽기 전용 위반은 찾지 못했고 강제 종료 75회·동시 명령 240개·후보 4000개 규모도 버텼습니다.
- 일부러 코드를 망가뜨려 보는 점검(변이): 구현자 190곳은 모두, 검증자가 새로 설계한 84곳 중 80곳을 시험이 잡았습니다(못 잡은 것은 시험 공백 2곳과 결과가 같은 변경 1곳 — 실제 코드는 정상).
- **서비스 다듬기(R-068) 위로 옮겨 합쳤습니다.** 겹친 문서 6곳(변경 이력·README·구조 문서·결정 기록·오류 안내 표·오류 카탈로그)을 글자 단위로 합쳐 양쪽 내용을 모두 살렸고, 결정 기록 번호는 D-23·D-24 입니다(D-22 는 다듬기가 먼저 썼습니다).
- **병합 전 사전 점검까지 했습니다.** 이 브랜치의 자동 검사(Windows·Ubuntu × 파이썬 3.10·3.12)를 보내기 전에 먼저 돌려 봤고, 첫 사전 검사에서 시험 1개(콘솔이 없는 검사 환경에서 `CON` 같은 장치 이름의 문구가 달라짐 — 제품은 정상 거절)가 Windows·3.10 칸에서 실패해 시험을 고친 뒤 다시 돌려 **4칸이 모두 초록임을 확인했습니다**(약 16분 — 20분 한도 안). 병합 화면의 검사도 같은 시간이 걸립니다.
- 시험: 새 시험 326개(후보 명령줄·CSV·프로필 옵션·점검·진짜 프로세스 18개), 합친 뒤 전체 시험은 위 자동 검사가 Windows·Ubuntu 에서 모두 돌립니다(약 2000개).
- 변경 범위: 파일 19개(추가 약 4,300줄 — 대부분 새 코드와 시험). 기존 시험은 새 명령 한 줄을 표에 더한 것 하나만 바뀌었습니다. `vendor`·`.github`·`publish`·`render`·발행 코드는 바뀌지 않았습니다.
- **병합 전에 꼭 볼 것:** 이 브랜치의 자동 검사 4칸(Windows·Ubuntu × 파이썬 3.10·3.12)이 모두 초록인지 확인해 주세요. 독립 검증자 PC 에는 파이썬 3.10 이 없어 3.10 은 이 자동 검사로만 확인합니다. 빨간 칸이 있으면 병합하지 말고 아래 '안 될 때'를 따라 주세요.
