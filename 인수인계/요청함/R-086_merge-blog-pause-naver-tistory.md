## 무엇이 바뀌나 (쉬운 설명)
채팅으로 주신 결정 — **"네이버와 티스토리는 잠정 중단하고 데스크톱 이관을 마친 시점부터 발행, 티스토리는 접근성 문제로 최종 중단"** — 을 그대로 반영합니다.

1. **네이버 = 잠정 중단.** 블로그 목록 파일(`pipeline/blogs.json`)에서 네이버 블로그의 상태를 `package`(초안 이슈 만들기)에서 `off`(정지)로 바꾸고 이유를 적었습니다. 정기 실행은 계속 돌지만 **"대상 0개"로 10초 안에 초록으로 끝나고 새 초안 이슈를 만들지 않습니다.** 감시·'확인 필요 모음'에는 '네이버: 정지 중'이 참고로만 보이고 경고는 나오지 않습니다. 데스크톱 이관을 마친 뒤 데스크톱에서 발행하고, 클라우드 쪽을 되살리고 싶으면 상태 한 줄(`off` → `package`)만 바꾸면 됩니다.
2. **티스토리 = 최종 중단.** 티스토리 워크플로의 **정기 실행을 껐고 수동 실행만 남겼습니다.** 블로그 목록에는 2026-10-30 부터 티스토리가 없어서(제외·격리) 수동으로 돌려도 대상 0개입니다. 다시 쓰려면 운영자님의 새 결정이 필요합니다.
3. 플랫폼 코드·시험·워크플로 파일은 **지우지 않았습니다**(삭제는 원하실 때 따로 알려 주세요). 열려 있는 네이버 초안 이슈는 그대로 두었으니 필요 없으면 직접 닫으셔도 됩니다.
4. 시험과 안내 문서도 이 결정에 맞춰 고쳤습니다(실제 레지스트리의 네이버 상태·정기 실행 대상 수 1→0·티스토리 정기 실행 없음이 시험으로 고정됩니다).

**바뀌지 않는 것:** Chance·Blogger 영문·Blogger 한글의 발행, 사이트 모양과 광고 관련 파일, 시크릿, 발행 중단 감시 — 모두 그대로입니다.

## 확인한 것
- 이 브랜치의 자동 검사: 블로그 저장소 자동 검사(저장소 규칙·전체 시험, 파이썬 3.10·3.12) 모두 초록 — 21:59 에 시작해 22:01 에 끝났고 1분 58초 걸렸습니다. PR 을 만들면 2분 안팎의 같은 검사가 한 번 더 돌 수 있습니다.
- 직접 확인: 독립 검증 AI 는 쓰지 않았습니다(코드 로직 변경 없음 — 정지 설정·정기 실행 줄 삭제·문서·시험 기대값). 제가 직접 확인한 것: 저장소 검증기 오류 0건, 이 결정에 맞춰 고친 시험과 레지스트리·일정·초안 현황 관련 시험 모듈이 모두 통과, 계획 도구가 네이버 0개·티스토리 0개·나머지 블로그는 그대로 나오는 것. 첫 자동 검사에서는 워크플로 일정·초안 현황 표를 지키던 시험 5개가 이 결정과 맞지 않아 빨갛게 나왔고, 그 기대값을 고쳐 새 브랜치로 다시 올려 초록이 됐습니다(이 요청의 브랜치가 그 최종본).
