# 확인 요청 049 — 새 액션 하나의 고정 코드 대조 (결정은 한 가지)

> 이 글은 **질문**입니다. 이슈 양식 '[답변] AI 확인 요청에 답하기' 에 **대상번호 049**(`49` 처럼 써도 됩니다)와 고른 보기(1·2)를 적어 주세요. **답이 없으면 2(첫 실행 미룸)** 입니다. 이 답은 병합 승인이 아니고, 병합은 따로 부탁드립니다.

## 쉽게 말해
- 릴리스 올리는 흐름(`release.yml`)은 GitHub 가 만든 작은 프로그램(액션) 네 개를 씁니다. 세 개는 이미 병합된 다른 흐름과 같은 값이고, **새 것 하나**(`actions/download-artifact`)만 처음 쓰입니다.
- 액션은 '이름 + 40자리 고정 코드' 로 묶어 두었습니다. 그 40자리가 **공식 저장소의 v4.3.0 태그와 같은 값인지** 사람 눈으로 한 번 맞춰 보는 일입니다. AI 는 이 값을 2026-11-24 에 읽은 뒤 다시 읽지 못했고(접속이 금지), 독립 검증이 2026-11-26 에 다시 읽어 같음을 확인했지만, 서명 키를 다루는 흐름이라 사람이 한 번 더 맞춰 보길 부탁드립니다.
- 이 대조는 값을 **승인**하는 것이 아니라 '표와 공식 태그가 같다' 를 확인하는 것입니다. 병합만으로는 아무것도 실행되지 않으니, **첫 실행 전에만** 끝내시면 됩니다.

## 확인할 값

| 액션 | 태그 | 전체 고정 코드(SHA) |
|---|---|---|
| `actions/checkout` | v4.4.0 | `11d5960a326750d5838078e36cf38b85af677262` |
| `actions/setup-python` | v5.6.0 | `a26af69be951a213d495a4c3e4e4022e16d87065` |
| `actions/upload-artifact` | v4.6.2 | `ea165f8d65b6e75b540449e92b4886f43607fa02` |
| `actions/download-artifact` | **v4.3.0 (새 액션)** | `d3f86a106a0bac45b974a628896c90dbdf5c8093` |

앞의 셋은 이미 병합돼 도는 다른 흐름과 같은 값이라 **새 액션 하나만** 대조하시면 됩니다.

## 대조하는 방법(약 3분, 새 액션 하나)
1. 브라우저에서 GitHub 를 열고 검색창에 `actions/download-artifact` 를 써서 저장소를 엽니다.
2. 맨 위 저장소 이름의 주인이 **`actions`** 인지 봅니다. 다른 사람 이름이 앞에 붙은 포크라면 멈추고 '다르다(2)' 로 답해 주세요.
3. 오른쪽 또는 `Tags` 화면에서 **`v4.3.0`** 태그를 찾고, 그 옆에 보이는 커밋 SHA 의 **앞 7자리가 `d3f86a1`, 끝 4자리가 `8093`** 인지 봅니다.
4. 하나라도 다르면 승인하지 말고 '다르다(2)' 와 화면에 보이는 값을 답해 주세요.
5. 같으면 **'대조함(1)'** 으로 답해 주세요.

## 같이 알려 드리는 것(첫 실행 전에 운영자가 해 둘 일)
- **환경 `release` 만들기**: 저장소 설정에서 환경 `release` 를 만들고 필수 검토자(본인 한 명)·배포 가지 제한(main 만)·본인 승인 막기는 끔을 먼저 해 두세요. 환경이 없는 채로 실행하면 GitHub 가 보호 규칙 없는 환경을 자동으로 만들어, 서명 비밀이 없어 서명은 실패하지만 승인 없이 서명 단계가 시작됩니다.
- **서명 키**: 운영자가 오프라인에서 만듭니다(AI 는 키를 만들지도 다루지도 않습니다). 공개키를 앱에 넣는 변경이 병합되기 전의 첫 실행은 '매니페스트 만들기' 단계에서 멈추는 것이 정상입니다.
- 병합과 첫 실행(`Run workflow` 한 번 + 환경 승인 한 번)은 운영자만 합니다.
