# [R-109] 레퍼런스 스타일 학습 글 생성 — 설계안과 결정 4가지

> **지금 하실 일은 없습니다.** 12:31 에 올리신 이슈 #122(첨부 '추가 기능 설계 요청서')에 대한 논의·준비 단계의 답이라 **코드는 만들지 않았고**, 아래 결정 4가지는 모두 기본값이 있어 답이 없으면 기본값으로 설계를 굳힙니다.
> 답하는 방법: 텔레그램의 **[답하기]** → 요청 번호 `r-109`(지금은 하이픈 포함) → 답변 **승인** → **선택** 칸에 `A=1 B=1 C=1 D=0` 처럼 적기(안 적은 항목은 기본값). 채팅으로 말씀해 주셔도 됩니다.

## 한눈에
- **가능합니다.** 레퍼런스(선택)가 비어 있으면 지금의 가이드라인 기반 생성 그대로, 있으면 **스타일 분석 → 프로필 → 생성 프롬프트에 합성**의 두 단계로 갑니다. 기존 화면·입력·파이프라인은 그대로 두고 **입력 하나와 함수 하나가 늘어나는 모양**으로 설계했습니다.
- **어디에 넣나**: 데스크톱 프로그램에서 AI 로 본문 초안을 만드는 묶음('d')은 **아직 시작 전**이라 뜯어고칠 코드가 없습니다. 그래서 **'d' 와 함께** 설계·구현하는 것이 가장 쉽고 안전합니다(AI 호출을 어디까지 켜는지는 'd' 묶음의 승인 범위를 따르고, 키·무료 한도는 r091 의 안전장치 안에서만 씁니다).
- 입력 화면은 이미 병합된 화면 기초(r098)에 홈만 있어서, **'참고 레퍼런스(선택)' 입력 칸과 '레퍼런스 스타일 반영' 체크박스는 글 작성 화면을 만드는 화면 묶음에 들어갑니다**(그 전에는 명령줄 입력 옵션으로 같은 기능을 시험할 수 있게 만듭니다).

## 설계 요약
| 부분 | 내용 |
|---|---|
| 입력 | 주제·기본 가이드라인(지금 그대로) + **레퍼런스 글(선택)**. 비어 있으면 기존 로직, 있고 체크박스가 켜져 있으면 스타일 반영 |
| ① 스타일 분석 `ReferenceAnalyzer` | **규칙 기반(키 없이 동작)**: 문장 끝(합니다체·해요체·평어 비율)·문장 길이 분포·문단 길이·소제목·목록·표 사용 습관·자주 쓰는 접속어·글 마무리 방식을 세어 **스타일 프로필**(숫자와 짧은 설명)로 만듭니다. 선택으로 **모델 보강**(키가 있을 때 프로필을 말로 다듬기) |
| ② 프롬프트 합성 | 주제 + 가이드라인 + 스타일 프로필을 합쳐 시스템 프롬프트를 동적으로 조립(레퍼런스가 없으면 프로필 부분이 빠짐). 요청서의 예시 구조를 그대로 쓰되 아래 안전 문구를 더합니다 |
| 연동 | 생성 함수에 `style_profile=None` 매개변수로 자연스럽게 연결 — 기존 API·로컬 모델 연동 구조는 안 깨집니다. 한도 안전장치(r091)를 그대로 거칩니다 |
| 변경 범위 | 새 모듈 하나(분석·프롬프트 합성) + 생성 함수의 매개변수 하나 + 입력 칸·체크박스 + 시험. 메인 루틴·전체 화면 구조는 다시 쓰지 않습니다 |

## 꼭 같이 정해야 하는 주의점 셋
1. **'지어내지 않기' 규칙이 스타일에 눌리면 안 됩니다.** 레퍼런스가 '제가 직접 써 보니…' 같은 체험담 문체이면 그 말투를 따라 하다 **겪지 않은 일을 겪은 것처럼 쓰는** 글이 나올 수 있습니다. 그래서 프로필에는 **사실·고유명사·숫자·경험 서술을 담지 않고**(말투·구조·호흡만), 생성 지시에 '레퍼런스가 경험담이어도 경험하지 않은 일을 쓰지 않는다'를 넣고, 결과는 지금의 '지어내지 않기' 검사(r099)를 똑같이 거칩니다.
2. **URL 로 레퍼런스를 가져오는 것은 새 위험이 큽니다.** 남의 글을 프로그램이 대신 열면 그 사이트의 약관·robots 규칙·저작권, 그리고 내부 주소로 유도되는 위험(서버 요청 위조)을 따져야 하고, 지금 프로그램에는 '글 안의 주소를 열어 보는' 기능이 일부러 없습니다. 그래서 **1차는 글 붙여넣기만** 받고, URL 가져오기는 허용 범위를 정해 따로 승인받는 것을 권합니다.
3. **저작권·복사 방지**: 스타일은 따라 하되 레퍼런스 문장을 베끼지 않게(요청서의 4번 지침 그대로) 하고, 결과에 레퍼런스와 같은 문장이 길게 겹치면 확인 권장을 띄웁니다(기존 유사도 검사 재사용). 레퍼런스 원문은 **저장하지 않고 분석 결과(프로필)만** 남기는 것이 기본입니다.
- 참고: 분석+생성을 모델로 두 번 부르면 무료 한도를 두 배로 쓰므로, **분석은 규칙 기반으로 먼저**(무료·키 불필요) 하고 모델 보강은 선택으로 두었습니다.

## 결정해 주세요 (기본값 있음)
- **A 구현 시점**: `1` 본문 초안('d') 묶음에 **함께**(기본) / `2` 'd' 가 끝난 뒤 별도 묶음
- **B 레퍼런스 입력**: `1` **글 붙여넣기만**(기본) / `2` URL 가져오기도(약관·robots·저작권·주소 안전 확인 뒤 별도 승인)
- **C 분석 방식**: `1` **규칙 기반 + 선택적 모델 보강**(기본) / `2` 모델 분석만
- **D 레퍼런스 원문 보관**: `0` **보관 안 함, 분석 결과(프로필)만 저장**(기본) / `1` 내 컴퓨터에 원문도 저장

## 다음
- 승인하시면('A=1' 이든 기본값이든) 'd' 구현 지시서에 이 설계를 넣고, 구현·독립 검증 뒤 병합 부탁을 드립니다. 'd' 는 이미 대기 중이던 일이라 이 요청 때문에 일정이 늘지는 않지만, 화면 묶음이 필요한 부분은 그 묶음에 맞춰 들어갑니다.
- 요청서의 프롬프트 예시는 거의 그대로 쓰고, 위 안전 문구와 '결과를 기존 검사에 통과시키는 단계'만 더합니다.
