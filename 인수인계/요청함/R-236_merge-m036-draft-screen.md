# [M036] 병합 부탁 — 데스크톱 '초안 작성' 화면 (P4e)

> **검사는 이미 끝났습니다 — PR 47 를 열어서 병합하셔도 됩니다.** 가지를 올린 때 데스크톱 저장소의 검사(Windows·Ubuntu × 파이썬 3.10·3.12 시험, 12칸)가 돌아 모두 초록으로 끝났습니다. **이 병합 부탁은 데스크톱 프로그램 저장소 `chanceblog-desktop` 의 것입니다**(블로그 저장소가 아닙니다).

- 병합 화면 맨 위의 저장소 이름이 **`chanceblog-desktop`** 이고 변경된 파일이 **72개**(화면 코드 18·서비스 새 파일 1·시험 19·문서와 화면 사진 31·그 밖 3, +6,841/−108줄)인지 봅니다. `.github`·의존성 파일·저장·보안·발행 모듈은 **없습니다.** 다른 노란 배너(작업 중인 다른 가지)는 무시하셔도 됩니다.

## 이번 묶음이 하는 일
앱 왼쪽 메뉴에 **'초안 작성'** 화면이 생깁니다. 지금까지는 '주제 후보' 화면에서 후보를 고르는 데까지였고, 이번에 그 다음 단계가 이어집니다.
1. **만들기**: '주제 후보' 에서 후보 하나를 골라 `이 주제로 만들기` 를 누르면, **AI 를 쓰지 않는** 규칙 기반 초안(제목 후보·본문·태그·확인 권장)이 나옵니다(이미 병합된 규칙 기반 초안 서비스를 씁니다).
2. **고치기**: 제목·본문을 화면에서 직접 고치고, 검사하기 단추로 점검 카드(키·토큰 모양·건강 효과 단정·확인이 필요한 곳·거의 안 고침)를 봅니다.
3. **복사**: 항목별 복사 단추는 **클립보드에만** 씁니다. 게시·전송·저장은 없고, `네이버 글쓰기 열기` 는 글쓰기 주소만 엽니다. 초안은 메모리에만 있어 앱을 닫으면 사라집니다(고친 내용이 있으면 닫기 전에 확인창).
4. **복사 전 안전 관문**: 키·토큰 모양(편집기에 직접 친 주소 안의 이름 있는 비밀 인자·웹훅·`sk-` 키 포함)과 **건강 효과 단정**(건강 C — M035 의 판정기를 그대로 씀)이면 복사를 막습니다. 건강 단정 막음은 문장을 고쳐 쓰면 풀리고 건너뛰는 단추가 없습니다. 관문을 지나도 '거의 고치지 않음' 이면 한 번 더 묻습니다.

## 눈에 보이는 변화
- 앱을 쓸 때: 사이드바에 '초안 작성' 메뉴가 하나 늘고, 주제 후보 상세에서 `이 주제로 만들기` 로 새 화면으로 넘어갑니다. 창 폭이 1280 이상이면 두 칸(본문|도움말), 미만이면 한 칸입니다. 다른 화면(주제 후보·블로그 관리·설정)의 기능은 바뀌지 않습니다.
- 블로그·공개 글·설정·키는 바뀌지 않습니다.

## 단계 보고
1. **변경 파일**: 72개(+6,841/−108). 화면 코드(`ui/core`·`ui/qt` 16·어댑터 2), 서비스 새 파일 `service/draft_engine.py` 1(후보 보관함을 읽기 전용으로 열어 초안 본문을 규칙으로 만듦 — AI·네트워크·파일 쓰기 없음), 시험 19, 화면 사진·문서 31, 그 밖 3.
2. **시험**: 새 시험 모듈 4개(서비스 23·초안 화면 순수 108·서비스 연결 16·Qt 화면 57 = 204개)가 파이썬 3.12·3.10 모두 통과합니다. 변이 점검(코드를 일부러 틀리게 해서 시험이 빨개지는지)은 구현자 149곳 모두 잡혔고, 검증자가 직접 고른 56곳은 52곳이 잡혔습니다(직전 생존 10곳 10/10·구현자 표 무작위 20곳 20/20, 새로 고른 26곳 중 22곳 — 살아남은 4곳은 동치 1·시험 틈 3, 낮음). 합치면서 건강 판정기(M035)의 문서 시험 하나가 'D-290–D-319 에서 다른 묶음 번호는 D-297 뿐' 이라고 못박고 있어 이 묶음의 D-312–D-314 에서 빨개져, 허용 집합을 넓혔습니다(3줄 — 두 묶음이 각자 초록이어도 합치면 빨개지는 종류라 합친 검사가 잡았습니다). 검사는 12칸 모두 초록입니다.
3. **독립 검증**: 구현자와 다른 AI 가 읽기 전용으로 3회 검증했습니다 — 1차 조건부 통과 → 2차 조건부 통과(주소 안 이름 있는 비밀 인자 미탐 등) → 3차 수정 반영 뒤 **통과**(병합 가능, 고칠 조건 없음). 마지막 검증은 **합친 트리 그대로**를 봤습니다: 충돌 문서 세 곳 풀이에서 줄이 하나도 빠지지 않았고(결정 번호 D-278–D-314 37개 빠짐·중복 0), 나머지 파일 548개가 합성 결과와 바이트까지 같고, 주소 안 비밀 키 모양 68개가 68/68 막히며(직전 52/68), 정상 주소·글 116개 중 오탐은 긴 파일 이름 2개(옛 규칙 그대로)뿐이고, 건강 단정(운영자 C 의도 문장 52개)은 후보 경로·편집기·제목·선택 입력 4칸 모두 52/52 중지되며 기준보다 더 막은 것도 덜 막은 것도 0 입니다. 새 문제 6건(낮음 1·정보 5)은 병합을 막지 않고 병합 뒤 문서 정리·시험 보강 때 닫습니다(예: D-313 의 숫자 17/25 가 합친 판정기에서는 18/25 가 된 것).
4. **기존 기능 영향**: 서비스는 새 파일 하나뿐이고 기존 서비스·저장·보안·발행 코드는 바뀌지 않습니다(보호 경로 바이트 같음). 명령줄(28시나리오)과 기존 화면은 그대로입니다.
5. **데이터 이관**: 없음(초안은 저장하지 않음). **원복 방법**: 이 PR 을 되돌리는(Revert) 커밋 하나를 병합하면 됩니다.
