# [R-085] 이미지(Unsplash) 기능 — 만들기 전 사전 보고

> **지금 꼭 하실 일은 없습니다.** 아래 확인 5건(U1~U4·K1)에는 모두 기본값이 있어서, 답이 없으면 기본값으로 진행합니다. 바꾸고 싶은 것만 알려 주세요.
> 답하는 방법: 텔레그램의 **[답하기]** → 요청 번호 `R-085` → 답변 **승인** → **선택** 칸에 `U1=B U2=B` 처럼 적기(안 적은 항목은 기본값). 채팅으로 말씀해 주셔도 됩니다.

## 한눈에
- **같은 방향으로 만드는 데 문제 없습니다.** 올려 주신 명세(UNSPLASH-INTEGRATION v1.0.0)가 Unsplash 공식 규칙(사진 주소 그대로 쓰기·사용 알림·작가와 Unsplash 출처·키 비밀·한도 우회 금지)을 모두 담고 있어, 방향을 바꿀 곳은 없습니다.
- **블로그의 지금 코드는 두 갈래이고 수준이 다릅니다.** Blogger 영문·한글 글은 규칙을 거의 지키고 있고, Chance(GitHub Pages) 글은 사진은 잘 붙이지만 **작가·Unsplash 출처 표시가 없습니다.** 명세의 지시대로 이 부족한 쪽을 데스크톱에 그대로 복사하지 않고, 새로 쓰면서 고칠 점을 아래에 적었습니다.
- Unsplash 는 사진을 **검색해 보여 주는** 서비스이고 새로 만들어 주지 않습니다. 화면 글자에도 '이미지 생성'이란 말을 쓰지 않습니다.

## 명세 §24 의 13항목
1. **기존 Unsplash 연동 위치:** 두 곳입니다. ① Chance 글: 글 생성기(`generator.py`)와 수정 요청 처리(`pipeline/edits`) ② Blogger 영문·한글 글: 대표 사진 모듈(`pipeline/main_image.py`, 글을 올리는 실행에서 호출). 티스토리·네이버 초안 묶음(`pipeline/publishers/issue_package.py`)은 사진을 새로 찾지 않고, 받은 사진 정보로 출처 안내 줄만 만듭니다.
2. **쓰는 주소와 응답 값:** 검색 `search/photos`(가로 사진·`content_filter=high`, 한 번에 Chance 15장·Blogger 10장), 사진을 쓰기로 하면 `download_location` 호출. 쓰는 값은 Chance = 사진 주소(`urls.raw`)·`download_location`, Blogger = 사진 번호·주소·설명(`alt_description`)·작가 이름·작가 프로필 링크·`download_location`.
3. **사진 주소 그대로 쓰기(핫링크):** 예 — 두 갈래 모두 `images.unsplash.com` 주소를 글에 그대로 씁니다. 다만 **주소를 다시 만들면서 `?` 뒤의 추적 값(`ixid`)을 버립니다.** 공식 안내는 크기 값을 바꿀 때도 `ixid` 를 남기라고 하므로 고칠 점입니다(요약 도구를 거친 문장이라 실제 구현 전에 원문과 대조합니다).
4. **사용 알림(`download_location` 호출):** 예 — 두 갈래 모두 사진을 쓰기로 했을 때 한 번 부르고, 실패해도 글을 막지 않습니다.
5. **작가·Unsplash 출처 표시:** **Blogger 글 = 있음**(글 맨 위에 작가 이름+프로필 링크+Unsplash 링크), **티스토리·네이버 초안 안내 줄 = 있음**, **Chance 글 = 없음.** Chance 의 고정 사진 목록(키가 없거나 검색이 안 될 때 쓰는 대체 사진)과 홈페이지 기본 썸네일 4장도 출처가 없습니다.
6. **UTM(출처 링크의 앱 표시):** 있음(`utm_source=chanceblog&utm_medium=referral`). 데스크톱은 명세대로 `utm_source=chanceblog_desktop` 을 씁니다.
7. **키 저장 방식과 노출 위험:** GitHub 시크릿 `UNSPLASH_ACCESS_KEY` 를 실행 환경 변수로 읽어 요청 머리글에만 씁니다(Blogger 쪽은 주소가 바뀌어도 키가 따라가지 않는 방식 + 주소 호스트 검사). 코드에서 키를 출력·기록하는 곳은 찾지 못했습니다. 위험은 키 노출보다 **한도**입니다(데모 앱이라 시간당 50회, 모든 자동 실행이 같은 키를 공유).
8. **데스크톱으로 가져올 것:** 코드는 복사하지 않고 새로 씁니다(블로그 모듈은 GitHub 실행 환경 전제). **생각만 가져옵니다:** 주소 호스트 허용 목록(사진·작가·사용 알림), 작가 이름 정리(보이지 않는 글자 제거·길이 제한), 한글 제목일 때 영어 검색어 만들기(AI 가 없을 때의 대체 규칙 포함), 최근에 쓴 사진 제외, 실패 이유를 고정 코드로만 남기기, 실패해도 글을 막지 않기, 응답 머리글로 남은 호출 수 읽기.
9. **새로 만들 것:** 이미지 제공자(공통 틀·Unsplash·오류 종류·한도 상태), 이미지 저장소(썸네일·메타데이터·정리), 화면 부품(주제 썸네일·이미지 카드·이미지 선택 창·출처 표시·Placeholder), 설정 화면(설정 → 연결 관리 → 이미지 서비스 → Unsplash), 이미지 정보 저장 칸(저장 구조 버전이 오르며 마이그레이션 포함), 문서 5개(명세 §20 의 이름대로).
10. **한도와 오류 처리:** 지금 블로그는 한 번 실행에 검색 최대 3회 + 사용 알림 1회(Blogger), 429·403·5xx·시간 초과를 고정 코드로 남기고 Blogger 는 사진 없이 / Chance 는 고정 사진 목록으로 대신합니다. 데스크톱은 명세대로: 같은 검색어 반복 금지·저장된 결과 우선·남은 호출 수와 초기화 시각 표시·429 는 기다리라는 시간 준수·5xx·시간 초과는 짧게 기다렸다 **최대 1회** 재시도·**키 자동 순환 없음**·실패하면 Placeholder 로 계속 진행.
11. **시험 계획:** 실제 Unsplash 를 부르지 않고 가짜 응답으로 — 단위(검색어 만들기·응답 변환·출처 문장·UTM 링크·한도 값 읽기·중복 제거·선택 시 사용 알림·키 가림·저장 만료) + 통합(정상·결과 없음·401·403·429·5xx·시간 초과·오프라인·선택·이미지 없이 진행·내 사진 선택) + 화면(Skeleton·Placeholder·선택 표시·출처·Tooltip·125% 배율). 키·보안 코드이므로 **다른 에이전트의 독립 검증**을 한 번 거칩니다.
12. **기존 기능 영향:** GitHub Pages·Blogger·네이버 초안 기능은 건드리지 않고 **추가만** 합니다. 후보·초안 정보에 '이미지' 칸이 생겨 데이터 저장 구조 버전이 오르며, 올리기 전 자동 백업이 들어갑니다(키는 어디에도 저장되지 않음).
13. **운영자 확인이 필요한 사항:** 아래 U1~U4(이미지)와 K1(키 한도).

## 확인 5건 (모두 기본값 있음)
**U1. 썸네일을 30일 저장하는 것(명세)과 사진 주소 그대로 쓰기(공식 안내)의 균형.** 공식 문서는 사진 파일 저장에 대해 허용도 금지도 말하지 않습니다.
- **A (기본) 명세대로 30일 저장** — 단 인터넷이 될 때는 항상 Unsplash 가 준 주소에서 먼저 불러오고, 저장본은 오프라인·한도 도달·느릴 때의 보조로만 씁니다(고른 사진 외 원본은 저장하지 않음, 저장을 지워도 출처 정보는 남음).
- B 더 보수적으로 **7일만** 저장(같은 방식).

**U2. 데스크톱용 Unsplash 앱을 따로 만들지.** 지금 키(데모 앱)는 시간당 50회이고 블로그 자동 발행과 함께 씁니다(사진 파일을 화면에 띄우는 것은 세지 않고 검색·알림 호출만 셉니다).
- **A (기본) 같은 키를 쓰되 호출을 예약·절약**(운영자 작업 없음).
- B 데스크톱 전용 앱을 따로 만들어 한도를 분리(Unsplash 개발자 계정에서 새 앱을 만들고 키를 안전한 곳에 직접 입력하는 계정 작업이라 요청이 따로 갑니다).

**U3. 블로그 Chance 글의 출처 표시·`ixid` 고치기.** 글 끝에 'Photo by 작가 on Unsplash'(UTM 링크 포함)를 넣고 사진 주소의 추적 값을 남기는 수정입니다.
- **A (기본) 수정안을 만든다** — 실제 사이트 빌드를 공개 사이트와 견줘 달라지는 곳을 확인한 뒤 별도 병합 부탁으로 올립니다(승인은 그때 따로).
- B 하지 않는다(규칙에 못 미치는 상태가 유지되고 정식 승인 신청은 못 합니다).

**U4. 정식(Production) 한도 신청 시점.** 시간당 호출을 1,000회로 올리려면 Unsplash 에 신청해야 하고, 출처 표시 등 가이드라인을 갖춰야 합니다.
- **A (기본) U3 수정이 병합되고 데스크톱 이미지 기능이 만들어진 뒤** 신청 방법을 안내드립니다(운영자 작업).
- B 지금은 신청하지 않음.

**K1. 키 한도에서 '부족한 부분'이 어디인지.** 채팅으로 말씀하신 '다른 번호로 계정·키를 더 만들어 적용' 대신 정식 방법으로 풀기 위해 필요합니다(약관 때문에 한도를 늘릴 목적의 새 계정은 권하지 않는다고 채팅에 적었습니다 — Google API 약관은 문서에 정한 한도를 우회하려 시도하지 않겠다는 조항이 있고, Unsplash API 약관은 쿼터 우회를 직접 금지합니다).
- **A (기본) 새 계정·번호는 쓰지 않고** 정식 방법으로 진행 — 호출 줄이기(저장된 결과 우선·사람이 고를 때만 호출), 데스크톱 전용 Unsplash 앱 따로 등록(U2-B), 다른 이미지 제공자 추가(Pexels·Pixabay 등, 서비스마다 정식 계정 1개), 정식 한도 신청(U4).
- B 막히는 곳을 알려 주시면(예: 'Gemini 하루 한도에 자주 막힘', 어느 블로그 실행에서·언제) 그 서비스의 정식 해결책을 먼저 찾아 보고드립니다. 선택 칸에 `K1=B` 와 메모, 또는 채팅으로 알려 주세요.
- 어느 쪽이든 새 키가 **다른 용도**(네이버 검색 키·데스크톱 전용 앱·Blogger 데스크톱용 인증)라면 지금 계정에서 새 앱·키를 만들면 되고 새 번호는 필요 없습니다.

## 명세에서 제가 해석한 점 (아니라고 하시기 전에는 이대로)
- 자동으로 제안된 사진은 '제안' 상태이고, 사용자가 **`이 이미지 사용`을 눌러야** 사용 알림이 갑니다(같은 사진을 다시 눌러도 다시 부르지 않음). 초안 복사·출처 복사만으로는 부르지 않습니다.
- 사진 주소는 Unsplash 가 준 것을 그대로(추적 값 유지) 씁니다.
- 이 프로그램은 키를 환경 변수로 읽지 않으므로(보안 저장소에서만 읽음) 명세의 `.env.example` 은 만들지 않습니다.
- 화면 시제품과 시험 사진에는 실제 Unsplash 사진·실제 작가 이름을 쓰지 않습니다(자체 견본·가상 이름).
- Unsplash 키 자동 순환은 두지 않고, Secret Key 입력 칸도 만들지 않습니다(검색·사진·사용 알림에는 Access Key 만 필요).

## 일정
키 연결 설정 구현이 병합된 뒤 이미지 기능을 단계별(명세 §22 의 5단계)로 시작하며, 설치 마무리(요구하신 마지막 단계)보다 앞입니다. 단계마다 독립 검증과 병합 부탁이 따로 갑니다.
