# 병합 요청 M137 — 앱 업데이트 장치(확인·서명 검증·상태·복구) (앱, T3)

> **병합 방식**: 지금은 AI 병합 기능이 **꺼져 있어** 운영자께서 직접 병합해 주세요. (`M137 승인` 이라고 답하셔도 아직 AI 가 병합하지 않습니다.) 이 요청은 앱 저장소 `chanceblog-desktop` 의 것이고, PR 제목 맨 앞이 `[M137]` 인 것 하나만 병합합니다. 검사는 이미 끝나 초록입니다. 급하지 않습니다(보통).

## 1. 무엇을 바꾸는지
운영자께서 확인 038 ①(이슈 #265)로 승인하신 '앱 업데이트 확인(읽기, 사용자가 단추를 누를 때만)의 설계와 구현 준비' 를 구현했습니다. 새 판이 있는지 확인 → 내려받기 → 서명 확인 → 상태 기록 → 실패하면 복구 안내까지의 장치이고, **모든 스위치가 꺼진 채** 들어갑니다.
- **서명 확인**: 릴리스에 붙는 서명된 목록(매니페스트)을 앱이 외부 부품 없이 직접 확인하는 코드(파이썬 표준 라이브러리만)입니다. 서명 방식 표준(RFC 8032)의 시험 값·OpenSSL·cryptography 와 교차해 같은 결과가 나옴을 확인했습니다.
- **내장 공개키·폐기 목록**: 출하 목록은 **비어 있습니다**(서명 비밀키는 어디에도 만들지 않았습니다).
- **상태·복구**: 열아홉 상태의 상태 기계, 업데이트 뒤 시작 점검과 복구 안내(자동으로 되돌리지는 않음), 폴더에서 업데이트(오프라인 적용), 설정 화면 '업데이트' 카드의 화면용 데이터(화면 연결은 다음 갈래), 오류 표 12행.
- **새 스위치** `UPDATE_APPLY`(적용·복구·시작 후크)를 더해 외부 접속·적용 스위치 아홉 개가 **모두 꺼진 채** 출하됩니다.
- 바뀐 곳(57개 파일): 새 `update/` 패키지(12 파일)·서비스 `update_flow`·화면용 데이터 둘·`capabilities.py`·`service/external.py`·`service/wiring.py`·`net/endpoints.py`·`net/client.py`·`errors/catalog.py`·꺼진 시작 후크 한 줄(`packaging/gui_entry.py`)·시험 25 파일·문서 7과 `CHANGELOG.md`.

## 2. 왜 필요한지
앱 v1.0 의 업데이트 기능을 켜기 전 상태까지 만들어 두면, 설치 도구가 정해진 지금(결정 D-811 — 병합 부탁은 따로)부터 적용 부분(U-4)을 이어 만들 수 있습니다. 서명 확인과 복구는 틀리면 안 되는 부분이라 켜기 전에 독립 검증을 두 번 거쳤습니다.

## 3. 사용자가 체감하는 변화
**없습니다.** 스위치가 모두 꺼져 있어 앱은 업데이트를 확인하지도 내려받지도 적용하지도 않고 외부 접속은 0 입니다. 시작 후크도 꺼져 있어 데이터 폴더를 읽지도 쓰지도 않습니다. 설정 화면의 '업데이트' 카드는 아직 화면에 연결하지 않았습니다.

## 4. 위험과 알려 둔 한계
- **켜는 일은 이 병합에 없습니다.** `NET_UPDATE_CHECK`·`UPDATE_APPLY` 를 켜는 것은 독립 검증 뒤 새 번호로 따로 승인받습니다.
- 켜기 전에 반드시 고칠 것 셋(같은 릴리스 재시도 막힘·시계 되감기 방어·시작 후크가 단일 실행 판정보다 앞서는 문제)과 화면 연결 전에 고칠 것 둘(적용이 받은 파일과 확인 결과의 일치를 안 봄·폴더 출처 확인 결과를 받기가 거절하지 않음)은 `docs/SECURITY.md` 표에 기한과 함께 적었고 코드는 아직 고치지 않았습니다(D-804·D-806).
- 출하 공개키 자리가 비어 있고 설치 도구 어댑터(U-4)가 없어서 켜더라도 아무것도 설치되지 않습니다.
- 서명 시험 값 하나(`RFC_VECTOR_1023`)는 표준 원문과 글자 대조를 하지 못했습니다(접속 금지) — 같은 서명을 서로 다른 네 구현이 같은 값으로 냅니다.
- 재확인 권고 둘(후속, 병합을 막지 않음): 문서 표를 세는 시험이 `SECURITY.md` 끝 덧붙임에 약함·오류 삼킴 허용 목록 일부.
- 운영자께 여쭐 것은 없습니다.
