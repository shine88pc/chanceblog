# 병합 요청 M074 — 앱이 처리하지 못한 오류의 이름과 코드 위치만 작은 파일에 남깁니다

> **병합 방식**: 지금은 AI 병합 기능이 **꺼져 있어** 운영자께서 직접 병합해 주세요. (`M074 승인` 이라고 답하셔도 아직 AI 가 병합하지 않습니다 — 켜지는 변경이 운영자 병합으로 들어온 뒤에만.) 이 요청은 데스크톱 저장소 `chanceblog-desktop` 의 것이고, PR 제목 맨 앞이 `[M074]` 인 것 하나만 병합합니다. 검사는 이미 끝나 초록입니다.

## 1. 무엇을 바꾸는지
앱이 **처리하지 못한 오류**가 났을 때, 그 **오류의 이름과 코드 위치만** 데이터 폴더의 작은 기록 파일(`logs/errors.log`)에 한 줄 남깁니다. 시각·어느 길로 들어왔는지·오류 이름·코드 위치(파일 이름과 줄 번호, 가장 안쪽 여섯 곳까지)뿐이고, 오류 메시지 글·값·키·토큰·글 본문·폴더 경로(사용자 이름 포함)는 읽지도 담지도 않습니다. (확인 015 승인 9번, 결정 D-488)

## 2. 왜 필요한지
창 없는 실행 파일(더블클릭)에는 오류를 보여 줄 표준 오류 화면이 없어서, 앱이 처리하지 못한 오류가 났을 때 나중에 원인을 찾을 단서가 어디에도 남지 않았습니다. 사용자가 '앱이 이상해요' 라고만 알릴 수 있었습니다.

## 3. 사용자가 체감하는 변화
평소에는 달라지는 것이 없습니다. 앱을 켜기만 해서는 폴더도 파일도 생기지 않고, **처리하지 못한 오류가 처음 났을 때** `%LOCALAPPDATA%\ChanceblogDesktop\logs\errors.log`(데이터 폴더를 바꿨다면 그 폴더 안 `logs`)가 만들어집니다. 화면 문구는 두 곳이 바뀝니다:
1. 예상하지 못한 오류 안내의 '로그 파일·내보내기 기능은 아직 없습니다'가 '로그를 내보내는 기능은 아직 없습니다. 처리하지 못한 오류가 났다면 데이터 폴더의 `logs/errors.log` 마지막 몇 줄(오류 이름과 코드 위치뿐)도 함께 알려 주세요'로 바뀝니다.
2. 백업·복원 카드의 '담지 않는 것' 아홉째 줄이 '로그·디버그 기록 — 이 앱은 로그 파일을 만들지 않고, 있어도 담지 않아요'에서 'logs/ — 앱이 처리하지 못한 오류가 났을 때만 처음 만들어지는 작은 기록이에요(오류 이름과 코드 위치뿐)…'로 바뀌고 길어집니다(새로 만드는 백업의 목록 파일에도 같은 글이 들어갑니다. 옛 백업은 그대로 복원됩니다 — 복원이 이 칸을 모양만 확인한다는 것을 코드로 확인했고 옛 목록으로 직접 복원해 보지는 않았습니다).

## 4. 위험과 기존 기능에 미치는 영향
- **기존 기능**: 영향이 없습니다. 네트워크·외부 쓰기·하위 프로세스는 쓰지 않고, 화면 실행에서만 켜집니다(예시 화면 `--sample` 과 명령줄은 켜지 않음). 충돌 덤프는 만들지 않고 백업에도 넣지 않습니다. 파일 쓰기가 실패해도(디스크 가득·권한 등) 그 줄만 버리고 앱은 그대로 돕니다. 1분에 30줄까지만 씁니다.
- **솔직하게 알려 드릴 점 ① — 파일을 새로 씁니다**: 데이터 폴더에 `errors.log`·`errors.log.1`·`errors.log.2` 세 개(각 256 KB 이하, 합쳐 최대 약 768 KB)가 생길 수 있습니다. 앱은 이 파일을 다시 읽지 않고 지워도 됩니다(다음 오류가 나면 다시 생깁니다). **이 병합을 되돌려도 이미 만들어진 파일은 사용자 PC 에 남습니다**(코드만 사라짐).
- **② 화면(Qt) 시험을 못 돌렸습니다**: 백업 카드의 줄이 길어져서 최소 창에서도 맞게 보이는지 확인하는 화면 시험을 포함해 화면 도구(PySide6)가 필요한 시험은 이 PC 에 그 도구가 없어 못 돌렸고 앱 저장소의 자동 검사도 건너뜁니다. 대신 화면 도구 없이 도는 시험으로 지켰습니다. 병합하신 뒤 앱의 백업·복원 카드 '담지 않는 것' 줄이 잘리지 않는지 한 번 봐 주시면 가장 확실합니다.
- **③ 기록이 닿지 않는 길이 있습니다**(문서에 한계로 적었고 후속 항목): 묶음 실행 파일이 시작하다 실패하는 경우(메시지 상자에 오류 종류 이름만 나옴), 작업 스레드가 삼키는 오류, 프로그램이 갑자기 꺼지는 네이티브 충돌, 앱이 거절한 데이터 폴더. 가장 흔한 실패 길 둘(작업 스레드·시작 실패)이 빠져 있어 이 기록이 모든 오류를 잡아 주지는 않습니다.
- **④ 돌려쓰기 한계**: 다른 프로그램이 `errors.log` 를 연 채로 크기가 꽉 차면 그 줄은 버려지고 가장 오래된 조각(`.2`)이 먼저 사라질 수 있습니다.
- **⑤ 문서 사진은 다시 찍지 않았습니다**(백업 카드 사진 등에 옛 글이 남아 있음 — UI_VISUAL_QA 15절).
- **⑥ 개발 중 한 번 있었던 일**: 구현자의 첫 시험 실행이 이 PC 의 실제 데이터 폴더에 `logs/errors.log` 를 한 번 만들었다가 지웠습니다. 시험이 임시 폴더로만 풀리게 고쳤고 독립 검증자가 다시 확인했습니다(지금 그 폴더에는 `logs` 가 없습니다).

## 5. 시험·독립 검증 결과
- 앱 저장소 자동 검사 초록(환경 4개 × 조각 3개): CI — 시험 성공(11분 35초)과 병합 부탁 PR 자동 만들기 성공. 새 시험 파일 102개(`tests/test_security_errorlog.py` — 파일·클래스 이름 글자표를 전체 유니코드로 훑기·깊은 추적·돌려쓰기 한도 경계·속도 제한·문서가 말한 한계 길을 동작으로 확인). 시험 모듈이 약 5초 더 걸립니다.
- 독립 검증(구현자와 다른 AI): AP14 관점이 2차·3차를 재검증해 최종 **통과**(필수 0). 앞서 나온 권고(돌려쓰기 문구가 막힌 단계에 따라 다름·한계를 낱말이 아니라 동작으로 확인·문서의 거짓 문장 고침 등)는 3차 수정으로 반영했습니다. 직접 확인: 네트워크·하위 프로세스·`.github`·`vendor`·의존성 변경 0, 이 가지가 먼저 병합된 AP15(M073) 위에서 충돌 없이 만들어졌고 결과가 검증한 작업 가지와 같음.
- 변이 시험(규칙을 일부러 망가뜨려 시험이 빨개지는지): 구현자의 111개를 모두 시험이 잡았고, 검증자가 직접 만든 69개 중 67개를 잡았습니다(못 잡은 둘은 앱 동작에 영향이 없는 방어 가지).

## 6. 원복 방법(문제가 생겼을 때)
M074 병합 하나만 되돌리면(Revert) 코드와 문서가 이전으로 돌아갑니다. 이미 만들어진 `logs/errors.log*` 는 남으니(최대 약 768 KB, 이름·위치뿐) 필요하면 `%LOCALAPPDATA%\ChanceblogDesktop\logs` 폴더를 지우시면 됩니다.
