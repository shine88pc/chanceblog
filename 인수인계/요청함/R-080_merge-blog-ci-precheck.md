# [R-080] 병합 부탁 — 블로그도 검사를 미리 끝내 두기

## 무엇이 바뀌나 (쉬운 설명)
**배경:** 데스크톱 저장소는 R-075 로 '검사를 미리 끝내 두기'를 마쳤습니다(R-075 때 PR 을 만드시고 2분 44초 만에 병합하셨습니다). 블로그 저장소는 PR 을 만든 뒤에야 검사(약 2분)가 돌아서, 검사가 빨갛게 나와도 제가 미리 알 수 없었습니다.

**고치는 법:**
1. 제가 올리는 브랜치(`ai/claude/…`)에서도 **같은 검사**(저장소 규칙·전체 시험·워크플로 점검)가 먼저 돌게 합니다. 저는 그 결과가 초록인 것을 확인한 **뒤에만** 병합 부탁을 보냅니다. 빨간 칸은 제가 먼저 고치므로 이슈로 '문제' 답을 쓰실 일이 없어집니다.
2. 이 사전 검사의 광고 표면 검사는 PR 검사와 같은 범위(main 과 갈라진 곳부터)를 봅니다. 그 범위를 못 구하면 조용히 넘어가지 않고 **실패**로 멈춥니다.
3. 텔레그램의 '검사 실패' 알림은 **main 에서만** 갑니다 — 제 브랜치의 사전 검사가 실패해도 운영자님께 알림이 가지 않습니다(바뀌지 않는 규칙을 시험으로 고정했습니다).
4. 절차서의 병합 부탁 규칙 문장도 지금 방식에 맞췄습니다(요청 파일은 병합 브랜치의 같은 커밋이 아니라, 검사가 초록이 된 뒤 요청 전용 브랜치로 보냅니다).

**바뀌지 않는 것:** 블로그 발행·사이트·네이버·Blogger 는 그대로입니다(검사 설정·시험·문서만 바뀝니다). **PR 을 만들 때 도는 검사(약 2분)도 그대로입니다** — 블로그에는 봇이 글을 계속 올려서, 병합 직전의 '합친 결과'를 한 번 더 확인하는 것이 의미가 있기 때문입니다. 그래서 데스크톱과 달리 블로그 PR 은 만든 뒤 2~3분을 기다리시는 점은 같습니다.

## 확인한 것
- 독립 검증 2회(구현자와 다른 AI 가 새 복사본에서 — 1회차 '병합 가능'·낮음 6건 → 보완 → 2회차 '병합 가능'·새 지적 0): 전체 시험 4470개를 파이썬 3.12 와 **진짜 파이썬 3.10** 으로 모두 통과(3.10 은 설계상 3.12 전용 시험 5개만 건너뜀), 새 검사 단계를 진짜 bash·git 으로 54가지 경우에 돌려(main push·PR 은 옛 동작 그대로, AI 브랜치만 새 기준, 기준을 못 구하면 실패) 확인, 텔레그램 알림 조건 13가지 조합(main 에서만 알림), 일부러 코드를 틀리게 바꿔 보는 점검(구현자 42곳 모두 적발, 검증자 70곳 중 놓친 것은 문서 설명 문장 일부뿐), 운영자님께 새로 새는 길이 없음을 코드로 확인했습니다.
- 이 브랜치의 사전 검사: **처음으로 실제 GitHub 에서 돌려 확인했습니다** — 19:03 에 이 브랜치를 올리자 가드레일 검사(저장소 규칙·전체 시험·워크플로 점검, 파이썬 3.10·3.12)가 바로 돌았고 2분 25초 만에 초록으로 끝났습니다. 새로 넣은 '광고 표면 검사 기준(main 과 갈라진 지점)' 기록도 의도대로 남았습니다. 병합 화면에서는 PR 을 만들면 합친 결과의 검사가 2분쯤 한 번 더 돕니다.
- 변경 범위: 파일 11개(검사 설정 1개·시험 3개(새 파일 1)·문서 6곳·작업 기록 1곳). 설정 파일은 '언제 도는지'·'검사 기준'·'알림은 main 에서만' 세 곳과 설명 주석뿐이고 권한(읽기 전용)·액션 버전·시험 명령은 그대로입니다.

## 솔직한 한계 (병합을 막지 않음)
- 사전 검사와 PR 검사가 같은 코드라 결과가 같지만, 가끔 흔들리는 시험이 있으면 실패할 기회가 두 번이 됩니다(그럴 때 빨간 칸은 제가 먼저 보고 고치거나 다시 돌립니다).
- GitHub 이 사전 검사 실패 때 계정 메일·앱 알림을 보낼 수 있습니다(저장소 코드로 막을 수 없는 GitHub 설정 — 평소처럼 무시하셔도 됩니다).
- 이 변경 자체의 첫 실제 실행은 제 브랜치를 올릴 때 확인했고, 병합 뒤 첫 AI 브랜치 push 에서 한 번 더 확인합니다.
