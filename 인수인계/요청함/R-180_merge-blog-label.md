# [M005] 병합 부탁 — 병합 표기 규칙(M 번호·NO-MERGE)을 도구·안내 문서·시험에 반영

> **검사는 이미 끝났습니다 — PR 을 만들자마자 병합하셔도 됩니다.** 제가 브랜치를 올린 때 검사가 돌아 초록으로 끝났고, PR 화면에는 그 끝난 결과만 보입니다. **이 병합 부탁은 블로그 저장소 `chanceblog` 것입니다**(데스크톱 저장소 `chanceblog-desktop` 이 아닙니다). 방금 병합해 주신 M004(건강 판정 보완)와는 **다른 묶음**이고, 이번에는 **사이트·글 발행·알림 전송 코드가 바뀌지 않습니다** — AI 가 쓰는 도구 사본·안내 문서·시험뿐입니다.

## 병합할 제목 (이것 하나만)
> **[M005] 병합 표기 규칙 — 병합 PR 제목 [M###]·가지 이름 M###-…·병합 금지 NO-MERGE (도구·안내 문서·시험) [대상: 공통]**

- **제목 맨 앞이 `[M…]` 인 것만 병합하는 것입니다.** 이번 것은 `[M005]` 이고 가지 이름은 `ai/claude/M005-merge-label-docs-2` 입니다(제목·가지 이름의 `M005` 가 위 알림의 번호와 같습니다). `M` 이 없는 제목·가지는 병합하지 않습니다.
- 병합 화면 맨 위의 저장소 이름이 **`chanceblog`** 이고 변경된 파일이 **6개**인지 봅니다.
- 이 병합에는 사이트(`index.html`·`_config.yml`·글)·`pipeline/`·`.github/`(워크플로)·광고 표면 변경이 **없습니다.** 다른 노란 배너(요청 파일을 올리는 `NO-MERGE-…` 가지 등)는 병합하는 것이 아니니 누르지 마세요.

## 이번 묶음이 하는 일 (운영자 지시 2026-11-06 의 반영)
말씀하신 대로 **병합 화면에서 `M` 번호로 '병합해도 되는 것'을 알아보게** 하는 표기를 도구와 안내 문서에 못박았습니다.
1. 병합할 PR 의 **제목은 `[M004] …` 처럼 알림 번호로 시작**하고 **가지 이름은 `ai/claude/M004-…`** 입니다(텔레그램 `🔀 M004 · 병합 요청` 의 번호와 같습니다). 요청 번호(`R-nnn`)는 AI 의 작업 번호라 병합 화면에는 나오지 않습니다.
2. **병합하면 안 되는 가지는 이름에 `NO-MERGE`** 를 넣습니다(요청 파일을 올리는 가지는 `ai/claude/NO-MERGE-operator-requests` 로 이름을 이미 바꿨습니다).
3. AI 도구(`make_request.py`)가 요청 번호 기준 지정한 번호 이후의 병합 부탁에서 **제목·가지 이름의 번호가 알림 번호와 다르면 요청 파일을 아예 만들지 않습니다**(실수 방지). 이미 보낸 병합 부탁(R-175 까지)은 옛 표기 그대로입니다.
