# 확인 011 답 접수 — Package 빌드 실패 원인 분석·수정 시작 (08:00 기준)

## 받은 것
- 확인 011 에 선택 없이 붙여 주신 Actions 실행 로그(이슈 #186)를 읽었습니다. 'Package — 개인 PC 제한 시험용 빌드(수동)' 가 **[3/8] 배치 단계 직후의 묶음 점검**에서 멈췄습니다.

## 원인(분석)
- 묶음 점검은 '빌드한 PC 의 가상환경·기본 Python·Windows 폴더 밖에서 온 DLL 이 묶음에 들어가면 거절한다'는 규칙입니다. 로그에는 GitHub 실행 PC 의 자바(Temurin JDK 17) 폴더의 `api-ms-win-core-*.dll` 들이 걸렸습니다.
- 실행 PC 의 PATH 에서 자바 폴더가 Windows 폴더보다 앞에 있어, 묶음을 만드는 도구가 그 폴더의 DLL 을 모은 것으로 보입니다. 이 PC 에서는 PATH 에 그런 폴더가 없어 같은 빌드가 통과했습니다. **점검은 설계대로 작동한 것이고 묶음은 만들어지지 않았습니다**(키·개인 데이터가 새는 일은 없었습니다).

## 하는 일
- 빌드가 묶음 도구를 부를 때 PATH 를 결정적으로 좁히도록 고치고, 같은 실패가 다시 나면 한 번에 원인을 알 수 있게 실패 문구에 건수·출처 폴더 요약을 더합니다. 허용 폴더 규칙은 완화하지 않습니다. 독립 검증과 앱 검사(12칸)를 거친 뒤 병합 부탁을 따로 보내고, 병합하시면 Actions 에서 'Run workflow' 를 한 번 더 눌러 주세요(그때 안내를 다시 드립니다).
- 모르는 것: 로그에 보인 6개 너머의 문제가 더 있는지, 수정 뒤 [4/8] 이후가 러너에서 통과하는지는 다시 돌려 봐야 압니다. 첫 실행 실패는 안내 문서에 미리 적어 둔 가능성이었습니다.
- 개인 PC 시험은 '나중에' 로 두신 그대로이며 재촉하지 않습니다.
