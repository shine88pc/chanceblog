# 병합 요청 M103 — 검사 규칙의 남은 틈 닫기(블로그 L6b)

> **병합 방식**: 지금은 AI 병합 기능이 **꺼져 있어** 운영자께서 직접 병합해 주세요. (`M103 승인` 이라고 답하셔도 아직 AI 가 병합하지 않습니다.) 이 요청은 블로그 저장소 `chanceblog` 의 것이고, PR 제목 맨 앞이 `[M103]` 인 것 하나만 병합합니다. 검사는 이미 끝나 초록입니다. 급하지 않습니다(보통).

## 1. 무엇을 바꾸는지
앞서 병합된 검사 규칙 보강(M095, L6)의 독립 검증이 권고·참고로 남긴 틈을 마무리합니다. **검사를 약하게 만들거나 오탐을 늘리지 않는 것**이 최우선이고, 워크플로·정책·광고 표면 파일은 건드리지 않았습니다.
① **슬래시 없는 앱 스킴 링크(D-365)**: AI 가 고친 글에 `bitcoin:`·`tg:`·`ms-settings:` 같은 앱 스킴 링크를 넣는 것이 새 외부 링크 검사를 통과하던 것을, 앱 스킴 80개와 접두사 `ms-`·`web+` 를 눌리는 링크 자리(링크 대상·꺾쇠 대상·참조식 정의)에서 읽어 막습니다(콜론 뒤 공백·줄바꿈이 오는 꼴 포함). 각주 정의 본문에서는 읽지 않아 영문 글머리 오탐이 되살아나지 않습니다. 각주 예외는 라벨이 kramdown 각주 ID 꼴일 때만이라 `[^]`·`[^.]`·`[^a b]` 같은 라벨 우회가 닫힙니다(2차 검증이 찾은 시작점보다 약해진 회귀 하나 포함).
② **워크플로 식 공백(D-366)**: 워크플로 규칙(WF-4)이 `github [ … ]`·`toJSON (github)` 처럼 `(`·`[` 앞에 공백을 끼우면 피하던 것을 공백(탭·줄바꿈·유니코드 공백 포함)을 지운 이름으로 읽어 막습니다. 저장소 워크플로 전부에서 새 오류 0 입니다.
③ **image-set(D-367)**: 따옴표 안 `)` 를 읽고, 글을 한 번만 훑는 방식으로 바꿔 닫는 괄호 없는 `image-set(` 반복 8만 자의 제곱 시간(3.5초)을 0.02초로 줄였습니다.
④ **일부러 안 한 것(D-368)**: 글 속 주소 끝의 밑줄·물결 글자 떼기(정상 수정은 기존 호스트 검사가 이미 거절), 시작점부터 있던 틈(CR 단독 줄바꿈 등)은 범위 밖으로 '열림' 에 기록했습니다.

## 2. 왜 필요한지
운영자 방침(세부는 추천안으로 진행하고 알리기만 함)으로 진행하는 검사 마무리입니다. 이 검사들은 AI 가 고친 글이 새 외부 링크·위험한 워크플로 식을 몰래 넣지 못하게 하는 마지막 문 가운데 하나이고, 검증자가 재현한 우회 길을 닫는 것입니다.

## 3. 사용자가 체감하는 변화
**지금은 없습니다**(검사만 더 단단해짐, 발행 정지 중). 앞으로 AI 가 글을 고칠 때 앱 스킴 링크나 각주 라벨 우회 같은 입력이 있으면 그 수정이 거절됩니다.

## 4. 위험과 기존 기능에 미치는 영향
- **기존 기능**: 워크플로 파일·정책 파일·광고 표면·레지스트리·의존성은 안 바뀌었습니다(검사 코드 2개와 시험·문서뿐). 시작점에서 막히던 입력이 지금 통과로 바뀐 것은 없음을 안전 검증자가 구조 차분 4만 7천여 건과 무작위 6만 건으로 확인했습니다. 저장소 글 269편·정상 수정 수천 건에서 새 거절 0, `validate_repo.py` 출력은 시작점과 같습니다(오류 0·경고 3). 바뀐 기존 시험은 보강뿐이고 약화 0 입니다.
- **알려 둔 한계(열림 — 안전 검증자의 권고라 병합을 막지 않는다고 판정, 결함 D-369 ⑧·⑨)**: ⑧ **이 묶음이 만든 오탐 면** — 꺾쇠 없는 참조식 정의 줄(`[1]: News: BBC 2020`·`[Update]: Line: 12` 같은 줄)을 앱 스킴으로 읽어 새 외부 링크로 거절합니다(막는 쪽이라 안전하지만 드문 정상 수정이 거절될 수 있음 — 정의의 콜론 뒤 공백 읽기를 꺾쇠가 있을 때만으로 좁히면 닫힘). ⑨ 시작점과 같은 틈 — 빈 `[a]:` 줄 뒤의 다음 정의 `[r]: //evil.example/a` 가 통과합니다. 둘 다 같은 정규식을 좁히는 다음 묶음 몫입니다. 그 밖에 CR 단독 줄바꿈이 참조식 정의를 숨기는 시작점부터의 틈은 AI 병합을 켜기 전에 닫기를 권합니다.
- **운영자께 여쭐 것(급하지 않음, 이번 병합과 별개 — 두 독립 검증 모두 '지금은 목록 방식 유지' 권고)**: 앱 스킴을 목록(80개+접두사)으로 읽는 대신 눌리는 링크 자리에서는 **모든 스킴을 외부로 보는 방식**으로 바꿀까요? **추천: 지금은 목록 방식 유지**(바꾸면 기존 시험 두 곳의 기대값이 바뀌고 영문 글머리 오탐이 늘 수 있습니다).
