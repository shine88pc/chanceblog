# R-041 · 새 저장소 — 다섯 번째 코드(Chance 글 만들기) 병합 부탁

R-039 병합을 확인했습니다(새 저장소 PR #5, 12:32 — 병합된 내용이 올린 것과 같고 병합 뒤 검사가 초록입니다).

## 무엇인가
프로그램이 **원고 하나를 Chance 블로그의 글 파일로 만드는 부분**입니다. 아직 파일을 쓰거나 올리지는 않고, "이 경로에 이 내용의 파일"을 계산만 합니다(미리보기와 다음 단계인 발행의 바탕입니다).
- **파일 이름과 위치**는 지금 Chance 와 같습니다: `_posts/<분야>/날짜-KR(또는 EN)-시각.md`, 시각은 한국 시각. 머리말도 같은 순서·같은 한 줄 형식입니다.
- **실제 Chance 글 두 편(한글·영어)으로 형식을 못 박았습니다.** 그 글의 원고와 정보를 넣으면 **글자 하나까지 똑같은 파일**이 나오는지 시험합니다. 형식이 어긋나면 사이트 빌드가 깨지거나 글이 이상하게 보일 수 있어서, 실제 글로 고정해 두는 것이 가장 안전합니다.
- 잘못된 입력은 파일을 만들지 않고 쉬운 말의 오류 안내로 거절합니다(없는 언어·시각 정보 없는 시각·제어 문자·머리말을 흉내 낸 본문·로그인 정보가 든 주소 등). 분야 이름에서 Windows 에서 못 쓰는 글자는 정리하고, 설명이 없으면 본문 첫 문단에서 자동으로 만듭니다.
- 만든 글의 머리말을 **마지막으로 한 번 더 검사**하는 함수도 있어서, 사이트에 올리기 전에 형식 문제를 막습니다.

- **끝난 것**: 시험 158개 통과(앞 128 + 이번 30), 검사 4개(Windows·Ubuntu × Python 3.10·3.12) 초록. 코드·문서를 일부러 34곳 망가뜨려 봐도 시험이 모두 잡았습니다.
- **들어 있는 것**: 코드 1개(`render/pages.py`), 시험, 실제 Chance 글 표본 2편(이미 공개된 글), 문서 몇 줄. 외부 연결·시크릿·새 설치 항목은 없습니다.
- **곧**: 별도 검토자가 지적한 보안·견고성 고칠 것(코드 묶음)도 곧 병합을 부탁드립니다. 그다음은 '승인된 글을 연결한 chanceblog 에 쓰고 올리는' 발행 부분입니다(올리는 일이라 독립 검증을 거친 뒤에만 보냅니다).
