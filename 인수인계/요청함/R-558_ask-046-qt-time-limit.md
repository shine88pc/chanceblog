# 확인 요청 046 — 화면 시험 칸의 시간과 한도 (결정은 한 가지)

> 이 글은 **질문**입니다. 이슈 양식 '[답변] AI 확인 요청에 답하기' 에 **대상번호 046**(앞의 0 을 빼고 써도 됩니다)과 고른 보기(1·2·3)를 적어 주세요. **답이 없으면 3(보류)** 입니다 — 아무것도 바뀌지 않고, 화면 칸 병합 부탁은 다른 갈래를 모두 병합한 뒤 맨 마지막에 다시 여쭙니다.
> 검사 정의 파일의 숫자를 바꾸는 일이라 승인이 필요한 사안(T3)입니다.

## 쉽게 말해
- 확인 042 ①(이슈 #277)로 승인하신 '병합 가지·main 마다 화면(Qt) 시험을 윈도 열두 칸으로 돌리기(시간 한도 40분, 검사 약 33분)'를 마무리해 독립 검증을 받던 중, 열두 칸을 실제 러너에서 세 번 돌려 본 결과가 예상과 달랐습니다.
- **가장 느린 칸이 설치까지 약 33분**(한도 40분의 82%)이었고 가장 빠른 칸은 약 4분이었습니다. 화면 시험 자체의 실패는 한 번도 없었습니다.
- **같은 시험의 시간이 실행마다 최대 5배 달라졌습니다**(예: 한 시험 310초 → 1,002초). 같은 프로세스에서 앞서 돈 화면 시험이 많을수록 뒤의 시험이 느려지는 것으로 보여(앞선 작업량 변화와 시간 변화의 상관 0.77), 시간표만 다시 맞춰서는 고르게 나눌 수 없습니다.
- 그래서 최악의 경우 한 칸이 40분을 넘겨 **'시간 초과' 빨강**이 날 수 있습니다(독립 검증이 교차 확인으로 계산한 최악이 약 39분 + 설치 1.5분). 병합 가지는 한 커밋이라 빨간 칸만 다시 돌릴 수 없어서, 시간 초과는 그 병합 부탁을 막습니다.

## 보기
1. **병합 가지·main 에서 그대로 돌리되 화면 칸의 시간 한도를 40분에서 60분으로 올립니다(추천).** 숫자 하나(와 그것을 못박는 시험·문서)만 바뀝니다. 검사 시간은 보통 약 33분, 가끔 40분 안팎까지 늘 수 있습니다(지금 약 19분에서 약 33분을 받아들이신 것의 연장입니다).
2. **main 푸시와 수동 실행에서만 돌립니다.** 병합 가지의 검사는 지금처럼 약 19분이고, 화면 시험은 병합된 뒤 main 에서 돌아 빨강이면 뒤따라 고칩니다(확인 042 의 둘째 보기와 같습니다).
3. **보류 — 아직 정하지 않음(기본).** 화면 칸 병합 부탁을 보내지 않고 다른 갈래의 병합을 먼저 합니다. 화면 칸은 맨 마지막에 다시 여쭙니다.

## 후속 (따로 확인)
- 시간이 흔들리는 근본 원인을 없애려면 화면 시험 파일마다 새 프로세스로 돌리게 검사 도구를 고쳐야 합니다(T3, 별도 갈래). 안정되면 한도를 40분으로 되돌릴 수 있습니다. 이 제안은 위 선택과 별개로 따로 여쭙겠습니다.
- 어느 보기를 고르셔도 시간표(무게 표)는 3차·4차 측정의 평균으로 다시 맞춰 독립 검증을 다시 받은 뒤에 병합 부탁을 보냅니다.
