# 확인 요청 034 — AP7 변경안: 요구 파일은 그대로, 파이썬별 constraints 로 설치 버전 묶기 (결정은 한 가지)

> 이 글은 **질문**입니다. 이슈 양식 '[답변] AI 확인 요청에 답하기' 에 **대상번호 034**(`34` 처럼 써도 됩니다)와 고른 보기(1·2)를 적어 주세요. **답이 없으면 2(보류)** 입니다. 승인하셔도 구현은 진행 중인 패키지 병합 순서 **뒤**이고, 병합 부탁은 독립 검증 뒤 따로 보내 운영자님이 직접 병합합니다.

## 조사 결과(확인 033 ① 승인 범위 안에서 — 두 호스트 읽기·인증서 검증 켬·미리 만든 설치 파일만)
| 직접 요구 | 요구 파일의 범위(그대로) | 파이썬 3.10 에서 실제 설치 | 파이썬 3.12 에서 실제 설치 |
|---|---|---|---|
| pyyaml | `>=6,<7` | 6.0.4 | 6.0.4 |
| google-genai | `>=2,<3` | **2.33.0** | **2.34.0** |
| google-auth | `>=2,<3` | 2.63.1 | 2.63.1 |
| google-api-python-client | `>=2,<3` | 2.202.0 | 2.202.0 |
- 하위 의존성까지 합쳐 3.10 은 37개·3.12 는 36개. 다른 것은 `google-genai`·`websockets`(16.1.1/17.4)·`pycparser`·`exceptiongroup` 넷.
- **전체 시험 10,463개: 3.10·3.12 모두 실패 0·오류 0**(건너뜀 9·3 — 3.12 이상 전용 시험 6개 차이), 외부 접속 시도 0, `pip check` 통과, **캐시 없이 한 번 더 설치해도 버전·파일·해시가 같음**. 다만 시험이 대부분 가짜 SDK 를 쓰므로 호출 모양(`generate_content(model, contents, config)`·`response_mime_type`)은 따로 접속 없이 읽어 두 버전 모두 있음을 확인했습니다.
- 이유: `google-genai` 2.34.0 과 `websockets` 17.4 는 파이썬 3.11 이상 전용이라 3.10 은 못 받습니다. 그래서 발행 경로(Chance, 3.10)와 나머지(3.12)가 이미 다른 SDK 를 쓰고 있고, 고정 목록은 **파이썬마다 하나씩** 필요합니다.
- 알림: `actionlint-py==1.7.12.25` 는 미리 만든 설치 파일이 없고 설치 중 깃허브에서 실행 파일을 받아 승인 범위(두 호스트·미리 만든 설치 파일) 밖이라 설치하지 않았습니다(이미 정확 고정이라 이번 질문과 무관 — 확인 032 #9 와 함께 다룸).
- 조사 중 보안: 이 PC 의 pip 설정(인증서 검사를 끄는 신뢰 호스트)은 쓰지 않고 이 PC 신뢰 저장소의 인증서로 **검증을 켠 채** 받았습니다.

## 변경안(지시하신 '범위 유지·통과 버전만 constraints')
| 번호 | 바뀌는 곳 | 내용 |
|---|---|---|
| 1 | 새 파일 둘 | `constraints-py310.txt`(37줄)·`constraints-py312.txt`(36줄) — 위 실측 한 벌을 `이름==버전` 으로. **요구 파일 3개는 한 글자도 안 바꿈** |
| 2 | 설치 줄 10곳(`.github` T3) | `blogger/naver/tistory`(3.12)·`issue-edit/pr-scope-check/sync-issue-form`(3.12)·`guardrails`(3.10·3.12)·`chanceblog/chance-fix-images/chance-shadow`(3.10 인라인 설치)의 `pip install` 에 `-c constraints-pyNN.txt` 만 더함(권한·시크릿·트리거·다른 줄 그대로) |
| 3 | 검증기 새 규칙 `DEP-3` | 요구 파일·패키지를 설치하는 줄에 `-c` 가 없으면 오류, constraints 줄 꼴(`==` 만)·누락·요구 범위 밖 버전 검사(요구 파일에서 이미 `==` 인 `actionlint-py` 줄은 제외) |
| 4 | 시험·문서 | 규칙 변이 시험, G-A5·D-10 상태 갱신, 갱신 절차 문서 |
- **갱신**: 월 1회와 필요할 때, 이번과 같은 격리 설치·전체 시험으로 새 목록을 만들어 constraints 만 바꾸는 작은 T3 병합 부탁으로(외부 접속이 필요하면 그때 다시 번호 있는 확인).
- **대안**: B 요구 파일을 `==` 로 바꾸기(범위 유지 지시와 충돌·하위 의존성은 계속 떠다님·3.10 에서 파이썬마다 요구 파일이 갈라짐) — 비추천. C 해시까지 담은 lock(`--require-hashes`) — 더 강하지만 큼(확인 032 #15 계열, 보류), 이 변경 위에 나중에 얹을 수 있음.

## 승인받으려는 것(이것이 전부)
1. **변경안 구현**(위 표 1–4). 병합은 진행 중인 패키지·블로그 병합 순서 **뒤**, 독립 검증(안전·시험) 뒤 병합 부탁, 운영자 직접 병합.
2. **병합 전 임시 가지 검증 한 번**: `NO-MERGE-` 임시 가지에 검증용 워크플로 한 개를 올려 GitHub 러너(리눅스·파이썬 3.10.22/3.12.16)에서 `pip install -c … -r …`·`pip check`·가져오기·접속 없는 SDK 호출 모양 점검만 돌립니다. 이유: 이번 조사는 윈도에서 했고 리눅스 설치 파일이 같은 버전을 푸는지는 아직 확인 못 했습니다. 시크릿·쓰기 권한 없음, 끝나면 가지를 지웁니다.

## 위험과 되돌리기
- 리눅스 러너에서 같은 버전이 안 풀리면 위 2번 검증이 병합 전에 잡습니다(그러면 목록을 고쳐 다시).
- 보안 패치를 자동으로 못 받음 → 월 1회 점검 절차.
- 되돌리기: `-c` 줄 10곳과 새 파일 둘·`DEP-3` 을 한 커밋으로 되돌리면 지금과 같습니다.

## 선택지
1. **승인(변경안 구현과 병합 전 임시 가지 검증 한 번)** — 위 범위대로 진행합니다.
2. **보류(기본)** — 요구 파일 범위만 유지하고 아무것도 바꾸지 않습니다(지금처럼).

## 1 을 추천하는 이유
- 어느 날 예약 실행이 갑자기 다른 버전으로 도는 것을 막고, 파이썬 3.10/3.12 의 실제 차이를 코드에 못박는 가장 작은 방법입니다(요구 파일·권한·시크릿은 안 바뀜).
- 전체 문서(조사 보고서·변경안 전문·후보 파일)는 작업 폴더 `audit6/improve/ap7/` 에 있고 승인되면 저장소 문서로 올립니다. 이 알림에는 운영자님 사진의 이름이나 읽은 글을 쓰지 않았습니다.
