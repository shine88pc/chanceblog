# 확인 요청 — 승인이 필요한 개선 12가지

> 이 글은 **질문**입니다. 텔레그램에서 `015/1/` (추천대로 전부) 또는 `015/2/3 예 5 아니오` 처럼 **직접 답하셔야** 승인이고, **답이 없으면 전부 보류**(아무것도 바꾸지 않음)입니다. 승인은 아래 **번호 항목에만** 유효합니다. 승인하셔도 코드·설정·자동화 파일의 변경은 독립 검증을 거친 뒤 **병합 부탁으로 한 번 더 확인**드립니다.

## 왜 묻나
AI 가 '프로그램 성능 향상을 위한 개선'을 스스로 진행하며 조사한 결과(125건) 중, 문서·시험·작은 코드 변경은 이미 승인 없이 진행 중입니다. 아래는 **광고 표면 파일·자동화 파일(.github)·설정·결정 변경**이라 운영자 승인이 필요한 것들입니다. 위험이 큰 것은 이 글에 넣지 않았고(맨 아래 '아직 묻지 않는 것'), 12가지는 모두 **되돌리기 쉽고 한 번에 하나씩** 올라갑니다.

**근거의 확인 정도**: 조사 결과를 독립 검증으로 사실 확인한 것은 1번(네 가지 모두)·12번, 일부만 맞다고 확인된 것은 2·3·4(나)·8·9번, 아직 한 번 더 확인하지 못한 것은 4(가)·5·6·7·10·11번입니다. 어느 것이든 구현 전에 코드로 다시 확인하고, 사실이 아니면 하지 않고 알려 드립니다.

## 승인 요청 12가지 (추천은 모두 '예')
1. **공개 사이트 화면 파일 네 가지 손보기(광고 표면 파일 — 광고 줄은 한 바이트도 안 바꿈)**: 글 안 표가 어두운 카드에서 일부 줄이 안 보이고 휴대폰에서 넘침 · 글 사진을 열자마자 다 받음 · 홈 카드 제목·태그에 따옴표나 꺾쇠가 있으면 화면이 깨질 수 있음 · 홈이 1분마다 본문이 든 큰 글 목록을 다시 받음. 승인 표시가 든 한 커밋 PR 로 올리고 **병합 전에 임시 가지에서 실제 사이트를 만들어 전후를 비교**하며 광고 줄이 그대로인지 확인합니다. 되돌리기: PR 되돌림 한 번.
2. **출처 링크 안내 한 줄**: 글의 '공식 자료' 링크가 제공처의 원자료 파일이라 눌러도 읽을 화면이 아닙니다. 출처 목록에 '원자료 파일입니다' 한 줄만 더합니다(글 틀 변경).
3. **'계산이 값을 더하는 글' 판정 기준을 문서로 정하기**: 더하는 것은 큰 단위로 모으기·앞 기간과 비교·기준 대비 개수·순위, 더하지 않는 것은 표에 보이는 서너 값의 최대·최소·평균뿐. 이 기준을 문서에 쓰고 제공처 등급 표를 옮기기만 한 글은 '지금 등급 대비 예보 등급' 비교를 더하거나 후보에서 뺍니다.
4. **자동화 파일 두 곳 한 줄씩**: (가) 계산 글 실행에서 쓰지 않는 Unsplash 키를 넘기지 않기 (나) 사이트 배포를 main 가지에서만 하게 막기(먼저 GitHub 설정의 배포 가지 규칙 화면을 확인하는 단계가 있습니다). 각각 따로 병합합니다.
5. **패키지 요구 파일을 정확한 버전으로 고정(1단계만)**: 지금은 버전 범위라 새 버전 하나나 패키지 서버 장애가 자동 실행을 빨갛게 만들 수 있습니다. 공개 14일 지난 버전만 고릅니다. 자동화 파일(워크플로)은 이 항목에서 바꾸지 않습니다.
6. **텔레그램 수신 읽기 예약 시간 실험**: 지금은 답장이 이슈로 들어오기까지 몇 시간 걸립니다. 정각을 피한 시간당 두 번(7분·37분)으로 바꿔 3일 동안 실제 간격을 재 봅니다(한 줄, 되돌리기 쉬움).
7. **검사(CI) 속도 측정**: 병합 부탁마다 기다리는 검사가 약 14분 35초입니다. 임시 가지에서 검사 조각 수를 바꿔 12칸을 3번 돌려 시간을 **재 보기만** 하고, 값을 붙여 다시 묻습니다(병합 부탁 아님).
8. **홈 추천 줄 서랍의 막다른 길 고치기(앱, 결정)**: 서랍 단추가 모두 '다음 단계에서 열려요' 안내만 띄웁니다. 서랍 모양은 그대로 두고 주 단추를 '주제 후보에서 열기'로 바꿔, 눌렀을 때 그 후보가 골라진 주제 후보 화면으로 가게 합니다(결정 D-201 '기존 서랍 유지'와 달라지는 점을 기록).
9. **작은 로그 파일 허용(앱, 결정)**: 앱이 갑자기 닫혀도 남는 기록이 없어 알리기 어렵습니다. 데이터 폴더 안에 오류 이름과 코드 위치만 가려서 남기는 작은 로그(256KB 3개 돌려쓰기, 첫 오류 때 처음 만듦)를 허용합니다. 가림을 걸 수 없는 충돌 덤프는 만들지 않고 백업에 넣지 않는 규칙은 그대로입니다.
10. **안내 문장의 흐린 글 색(앱, 결정)**: 흰 바탕의 흐린 안내·결과 문장(대비 3.2:1)을 기존의 진한 보조색(5.4:1)으로 바꿉니다. **입력 칸 테두리의 새 색은 더하지 않습니다**(승인한 목업 색 유지).
11. **발행 정지를 풀 때의 절차 한 줄(결정)**: 정지를 풀면 '마지막 활동이 8.5일 넘게 지났다'는 이유로 첫 감시가 심각 알림과 빨간 실행을 만들 수 있습니다. 정지를 풀 때 AI 가 같은 시각에 설정 파일의 일시정지 표시 한 줄(`planned_pause.active` 를 false 로)도 함께 바꾸는 절차를 해제 점검표에 적습니다. **정지 변수 자체는 운영자만 풉니다.**
12. **개인 정보 표현 정리**: 문서·시험 값·AI 기억 사본 여러 곳에 개인을 알아볼 수 있는 표현이 남아 있습니다. 표현을 중립 말로 바꿉니다(약관 근거·정식 대안·결정 항목은 유지, 공개 이력의 과거분은 못 지웁니다).

## 아직 묻지 않는 것 (위험이 크거나 운영자 판단이 필요해서)
- 홈의 외부 스크립트·큰 글 목록 파일을 가볍게 바꾸는 큰 작업 · 사이트 이름 표기 통일(이름은 운영자가 고르는 일) · PR 검사에 main 의 검사기를 한 번 더 돌리기 · NOAA 호출 한도 장부 · 저장 안 한 초안의 복구용 임시본 · AI 가 조용할 때 알림 · PR 재시도(자동화 파일) · 커밋 작성자 정보와 '회사 PC' 서술 정리. 필요해지면 따로 묻겠습니다.

## 승인하신 뒤
- 항목마다 구현 → 독립 검증 → 병합 부탁(운영자가 병합) → 제가 직접 확인 순서로 진행하고, 진행은 진행 현황 알림으로 알립니다. 광고 표면·자동화 파일 변경은 병합 전에 실제 사이트 전후 비교나 연습 실행 결과를 붙입니다.
- 각 항목은 구현 전에 코드로 다시 확인합니다. 조사 내용이 사실이 아니거나 위험이 커 보이면 그 항목은 하지 않고 알려 드립니다.
- 제가 이어지지 못하는 날(23시 재부팅 뒤 앱이 안 열리는 경우)에는 승인이 기록으로만 남고, 앱이 다시 열려 이어지는 때에 시작합니다.
