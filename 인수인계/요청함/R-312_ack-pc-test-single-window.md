# 접수 — 개인 PC 시험 결과와 '창이 한 개만 뜨게' 요청 (본문 — 폰에는 싣지 않고 요청 열기로 읽습니다)

## 1. 받은 내용
- 이슈 #190(확인 012 답, 16:23): **6-4 까지 진행한 결과 정상적으로 통과**, 앱 빌드 `83722d6`, Windows 10 Pro 22H2(OS 빌드 19045.7807), 화면 배율 100%.
- 추가 요청: **프로그램 창이 한 개만 뜨도록 수정**.

## 2. 시험 결과를 어떻게 기록했나
- 표준 사용자 계정에서 관리자 권한 없이 실행되고(1단계), 다른 일반 계정에서 첫 계정의 데이터 폴더·키에 닿지 않으며 빈 상태로 시작하고(6-1–6-3), 시험용 가짜 키를 지우면 처음 상태로 돌아오는 것(6-4)을 **Package 제한 사용 Gate 의 '표준 사용자 실행·다른 계정 접근 차단·키 범위' 세 항목이 통과한 것**으로 기록합니다. 7단계 표의 세부 칸은 요약만으로 충분해 더 여쭙지 않습니다.
- **8단계(시험 계정·압축 푼 폴더 지우기)는 편하실 때 하시면 됩니다.** 창 수정을 확인하려고 같은 PC 에서 한 번 더 열어 보실 거라면 그 뒤에 지우셔도 됩니다.

## 3. '창이 한 개만' — 제가 이해한 것과 계획
- **코드를 확인해 보니** 앱에는 같은 계정에서 두 번 열리는 것을 막는 장치가 없습니다. 실행 파일을 두 번 누르거나(처음 뜨는 데 몇 초 걸려 다시 누르기 쉽습니다) 열려 있는 줄 모르고 다시 열면 창이 두 개 뜹니다. 두 창이 같은 데이터 폴더를 함께 쓰면 저장이 엇갈릴 수도 있습니다.
- **고치는 방법**: 두 번째로 열면 새 창을 만들지 않고, 이미 열려 있는 창을 앞으로 가져온 뒤 조용히 끝납니다. 열려 있는 창이 멈춰 있어 응답이 없으면 그 사실을 쉬운 말로 알리고 끝냅니다. 같은 계정·같은 데이터 폴더일 때만 하나로 막고, 다른 계정이나 다른 데이터 폴더(개발용 `--data-dir`)는 따로 열 수 있습니다. 네트워크·비밀·설정은 건드리지 않고, 앱 코드와 시험만 바꿉니다.
- **다른 상황이었다면**(예: 한 번만 눌렀는데 창이 둘 떴다면) 이슈로 어느 단계에서 어떻게 보였는지 한 줄만 알려 주세요. 그때는 원인을 따로 찾겠습니다.
- 순서: 구현 → 독립 검증 3명 → 병합 부탁(운영자 병합) → 병합 뒤 Actions 에서 시험용 Package 를 다시 만들어(Run workflow) 같은 PC 에서 두 번 열어 보는 확인. 그 안내는 병합 부탁 때 함께 드립니다.
