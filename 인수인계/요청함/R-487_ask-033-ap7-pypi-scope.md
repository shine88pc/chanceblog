# 확인 요청 033 — AP7 의존성 정확 버전 조사의 외부 접속 범위 (결정은 한 가지)

> 이 글은 **질문**입니다. 이슈 양식 '[답변] AI 확인 요청에 답하기' 에 **대상번호 033**(`33` 처럼 써도 됩니다)과 고른 보기(1·2)를 적어 주세요. **답이 없으면 2(보류)** 입니다. 승인하셔도 이 조사가 하는 일은 아래 범위뿐이고, 고정 변경안은 따로 번호 있는 확인과 병합 부탁으로 올립니다.

## 정리한 운영자 지시(11-24 채팅, 확인 015 의 미완료 AP7)
- 지금의 범위 지정(`>=2,<3` 같은 표기)은 그대로 둡니다. 임의로 최신 버전을 골라 고정하지 않습니다. 운영자님이 버전 여섯 개를 손으로 알려 주는 방식도 쓰지 않습니다.
- 깨끗한 격리 가상환경에서 **기존 범위 조건 그대로** 설치하고, **실제 설치된 버전을 기록**하고, **전체 시험을 통과한 버전만** constraints(또는 lock) 파일에 고정하는 **별도 변경안**을 제안합니다.
- 외부 PyPI 조회나 패키지 내려받기가 필요하면 그 조사·검증 범위를 별도 승인 대상으로 올립니다 → **이 요청이 그것입니다.**

## 승인받으려는 범위(이것이 전부입니다)
| 항목 | 내용 |
|---|---|
| 접속 대상 | `pypi.org` 와 `files.pythonhosted.org` 두 호스트, 보안 연결로 **읽기만**(pip 의 기본 색인). 다른 호스트·추가 색인·깃허브·개인 서버는 쓰지 않습니다 |
| 받는 것 | 요구 파일 3개(`requirements-dev/edits/pipeline.txt`)의 패키지와 그 하위 의존성의 설치 파일. **환경당 약 30MB 안팎, 두 환경 합쳐 최대 약 60MB**(큰 것은 `google-api-python-client`) |
| 하는 일 | 이 PC 의 작업 폴더(저장소 밖)에 새 가상환경 둘(CPython 3.10·3.12) → 요구 파일을 **지금 범위 그대로** 설치(고정 없음) → 설치된 버전 전부(직접·하위)와 내려받은 파일의 해시를 기록 → 두 환경에서 **전체 시험 약 10,500개**를 외부 접속을 막는 러너(루프백만 허용)로 돌려 통과 여부 확인 → 같은 설치를 한 번 더 해서 같은 버전으로 풀리는지(재현성) 확인 |
| 산출물 | 조사 보고서(설치 버전 표·시험 결과·재현성)와 **별도 변경안**(T3 제안): constraints 파일을 새로 두고 검사·예약 워크플로가 그것으로 설치하게 하는 안, 또는 요구 파일을 `==` 로 바꾸는 안 중 시험을 통과한 쪽과 장단점. 변경안 자체는 이번 승인에 포함되지 **않고** 따로 확인·병합 부탁을 거칩니다 |
| 하지 않는 것 | 저장소 파일 변경·푸시·워크플로 실행, 요구 파일 값 변경, 비밀·사진·개인 값 사용, 위 두 호스트 밖 접속 |
| 안전 장치 | 기본 인증서 검증 유지(`--trusted-host` 없음)·색인 주소 변경 없음·추가 색인 없음, **미리 만든 설치 파일(wheel)만** 쓰고 소스 빌드가 필요해 보이면 멈춰 보고, 내려받은 파일 해시 기록, 조사가 끝나면 가상환경을 지우고 보고서만 남깁니다 |
| 걸리는 시간 | 설치 약 10분, 전체 시험 두 번(낮은 우선순위, 병렬) 약 1–2시간, 이 PC 에서만 |

## AI 의 추천: 1 (승인)
- 틀린 버전을 고정해서 예약 발행·이슈 목록 갱신이 의존성 설치에서 빨개지는 위험을 **실제 설치와 시험으로** 걸러 낼 수 있는 유일한 방법입니다(로그인해야 보이는 CI 설치 로그를 읽을 수 없고, 이 PC 와 옛 기록의 버전은 낡았을 수 있습니다).
- 접속은 읽기 전용이고 두 호스트·약 30MB 로 작으며, 저장소는 바뀌지 않습니다.
- 하위 의존성까지 고정하는 constraints 방식이 직접 의존성만 `==` 로 고정하는 것보다 재현성이 높은지도 같은 조사로 비교합니다.
