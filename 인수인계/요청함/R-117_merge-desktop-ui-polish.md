## 확인한 것
- 독립 검증 1회(구현자와 다른 AI 가 새 복사본에서 새로 만든 예문으로, 진짜 `pythonw` 포함)를 받았고 판정은 **'병합 가능(조건 없음)'** 이었습니다 — 이전에 남긴 '낮음' 6건은 모두 닫혔고 새로 생긴 위험은 낮음뿐입니다. 경로 지우기는 새 예문 720건·무작위 글 6만 건·이름 조각 퍼즈 3만 건에서 알아본다고 한 모양의 누출이 없고(예외는 `file:///유닉스경로` 하나) 정상 글 60개는 하나도 지워지지 않았으며 30만 자 병적 입력은 최대 0.083초(글 길이에 선형)입니다. 창 없는 실행은 진짜 `pythonw`(표준 핸들 없음)로 확인했고 취소 신호는 진짜 스레드·시그널로 8가지 순서와 실제 클릭 흐름을 확인했습니다. 가림 규칙 64종을 새 main 으로 직접 확인했고 문서 목록은 Slack `xapp-` 하나만 실제와 달랐습니다(후속). 시험은 3.12+PySide6 `Ran 344 … OK`·진짜 3.10.11 `Ran 344 … OK (skipped=87)`·PySide6 없는 3.12 같음·문서 읽는 7모듈 OK·환경 변주 OK 이고, 변이는 구현자 64곳 중 63(남은 1은 동작이 같은 변이)·검증자가 새로 설계한 54곳 중 51(남은 3은 UI 로 닿지 않는 경로 1·문서 낱말은 두고 뜻만 뒤집은 편집 2)을 잡았습니다.
- 이 브랜치의 자동 검사: 4칸(Windows·Ubuntu × 파이썬 3.10·3.12) 모두 초록 — 15:28 에 시작해 15:44 에 끝났고 15분 9초 걸렸습니다. PR 화면의 검사도 이 결과를 그대로 보여 줍니다.
- 변경 범위: 파일 15개(코드 5·시험 3·문서 7), 줄 수는 +463 −21 입니다.

## 솔직한 한계 (병합을 막지 않음)
- 경로 지우기는 절대 경로 모양(드라이브·네트워크·유닉스·`~/`)만 알아봅니다. 상대 경로·`%USERPROFILE%`·`$HOME`·`scheme://서버/…` 는 못 알아보고, 따옴표 없는 경로는 줄 끝까지 지워 뒤 설명도 같이 사라집니다. `file:///home/…`(유닉스식 파일 주소)는 한 가지 모양이 아직 이름 조각을 남깁니다(윈도 `file:///C:/…` 는 지워짐).
- 이론상 경주 하나: 이전 작업의 끝 신호가 처리되기 전에 새 작업에 취소를 누르면 그 한 번이 삼켜집니다(다시 누르면 됨, 사람 손으로는 맞추기 어려운 시간대).
- 가림 한계 시험은 '안 가려짐' 7가지를 못박아, 가림 규칙이 더 많은 모양을 알아보게 되면 의도적으로 실패하며 문서 목록을 같이 고치라고 알립니다.
- 실제 윈도 창·배율·한글 입력기는 이 PC 에서 보지 못했습니다(offscreen 시험만).
