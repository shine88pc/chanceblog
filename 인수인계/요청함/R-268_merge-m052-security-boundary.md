## 이번 묶음이 하는 일 (운영자 보안 결정 9항목 — 11-11)
개인 PC 제한 Package 로 가기 전에 닫아야 하는 보안 결함(보안 조사: 높음 3·중간 3·낮음 2·정보 3)을 고칩니다. **필수·높음 결함이 하나라도 남으면 Package 를 중지**한다는 운영자 지시의 해당 부분입니다.
- **출력의 비밀을 한 경계에서 가리기(H1)**: 화면·명령줄·로그·오류·진단·연결 시험 결과·시험 실패 출력 등 **글이 나가는 모든 곳**에서 Authorization·api_key·serviceKey·access/refresh_token·client_secret·password·Cookie·Set-Cookie·X-API-Key 같은 값을 가립니다(기능마다 따로 가리지 않고 프로그램 시작 지점에서 한 번 깝니다). 조사 163건에서 새는 입력 62 → 5(남은 5건은 이름 표지가 없는 값이라 알려 둔 한계), 11곳 × 11이름 표에서 새는 칸 0.
- **키 일부 표시 제거(H2)**: 키의 끝 4자리·앞부분·길이를 어디에도 보이지 않습니다. 보이는 것은 용도 이름·번호·등록 여부·마지막 시험·등록 시각뿐입니다.
- **외부 게시 완전 비활성(H3)**: 이 시험 버전은 글을 GitHub 에 올리거나(push·PR)·Blogger 에 게시하거나·네이버에 자동으로 올리지 못합니다. 소스 상수 하나로 막혀 있고 설정·환경 변수·명령줄·화면 어느 쪽으로도 켤 수 없습니다(켜려면 소스를 고쳐야 함). 이 PC 에 Git 로그인이 있어도 앱이 push 하지 못합니다 — 실제 git 으로 한 실험에서 기준 코드는 git 49번에 원격 main 이 움직였고 이 가지는 git 0번·원격 그대로였습니다.
- **본문 속 비밀 모양 검사(M3)**: Google API Key·GitHub Token·Bearer·OAuth·AWS 키·PEM 개인 키 여섯 종류가 글(후보·프로필·원고·검토 칸·키 별칭 등)에 있으면 저장·백업을 멈추고 **위치와 종류만** 알립니다(비밀을 다시 보이지 않음·자동 삭제 없음·'무시하고 저장' 없음).
- **그 밖**: Blogger 로그인 정보 입력 칸 숨김, `doctor` 의 데이터 폴더 위치 경고, 백업 목록에 '키는 백업에 들어 있지 않아요' 표시, 시험 실패 출력 가리기, 워크플로 산출물 규칙 시험(읽기만).

## 눈에 보이는 변화
- **운영자 PC 의 블로그·자동 실행은 그대로입니다.** 이 변경은 데스크톱 앱 안의 동작이라 개인 PC 로 옮길 시험용 Package 에 들어가야 보입니다. 보이게 되는 것: 키 화면에 끝 4자리가 없고, 외부 게시 단추가 없거나 '이 시험 버전은 글을 GitHub 에 올리지 않아요' 안내로 막히고, 글에 키 모양이 있으면 저장이 멈추고 위치만 알려 줍니다.

## 솔직한 한계 (문서에 적음)
- 이름 표지가 없는 값(경로 속 키·라벨 없는 한 줄·64자 16진수 등)은 가리지 못합니다. 키 모양을 모르는 자유 글 속 비밀은 저장·백업이 못 막습니다(올리는 글을 눈으로 확인하는 규칙이 먼저). 스캐너는 여섯 종류만 봅니다. 의도적 우회(`__import__` 등)는 정적 규칙이 못 막고 실행되는 경로만 시험이 봅니다. 지우기·되돌리기 직전의 안전 사본에는 원문이 남습니다.
- **외부 게시 기능 자체가 없습니다**(PR 흐름은 제안만 — 켜려면 별도 설계·독립 검증·운영자 승인 뒤 소스 변경). 복사 관문 미리보기의 앞 문맥이 앞선 비밀의 꼬리를 일부 되풀이하는 낮은 지적(`.env` 짧은 변수 이름)과 헤더 줄 경계의 문서 보완은 병합 뒤 후속으로 고칩니다.
