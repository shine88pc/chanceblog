# 확인 요청 009 — 영상 분석문 방향 검토 8항목 (작업 요청서 7)

> 이 글은 **질문**입니다. 어느 문장도 승인이 아니며, 텔레그램에서 `009/1/` 처럼 **직접 답하셔야** 승인입니다. 답이 없으면 8개 모두 'A 채택하지 않음'으로 두고 아무것도 바꾸지 않습니다. 급하지 않습니다.

**한눈에**
- 운영자가 Gemini 에게 유튜브 영상을 분석시켜 쓰게 한 글을 **근거가 아니라 확인 대상**으로 보고, 실제 코드·시험·설정·문서와 대조했습니다. 읽기 전용이고 아무것도 구현하거나 바꾸지 않았습니다. 영상 자체는 자동 접근·자막 추출이 약관상 제한이라 열지 않았습니다(영상 쪽 주장은 모두 미확인).
- 분석문이 '현재 프로젝트'라고 적은 설명은 대부분 실제와 다릅니다. 프로젝트 주장 27줄 중 **맞음 10 · 틀림 15 · 미확인 2**(2절).
- 운영자가 의심하신 8개 후보는 모두 **방향에서 벗어남(보수적으로 분류)** 이고 **추천은 전부 A(채택하지 않음)** 입니다(3절). 어느 선택도 곧바로 코드·설정·공개 글·광고·일시정지 변수를 바꾸지 않습니다.

## 1. 한 줄 요청
영상 분석문의 아이디어 중 **방향에서 벗어난다고 본 8개**를 어떻게 할지, 그리고 **방향 안의 새 항목 후보 3개**(4절)를 할지 정해 주세요. 정하지 않으셔도 됩니다(기본값 = 전부 하지 않음).

## 2. 대조 결과 요약 — 분석문의 '현재 프로젝트' 열은 대부분 달랐습니다
- **화면 도구는 PyQt 가 아니라 PySide6** 입니다(운영자 채팅으로 확정한 결정). PyQt 는 소스에 0건입니다.
- **`reference_style` 이라는 파일·낱말은 어디에도 없습니다**(블로그·데스크톱·진행 중 작업·운영자 폴더 모두 0건). 레퍼런스 글에서 어조를 뽑는 기능도 없습니다. 스타일은 사람이 고르는 프로필·선택 입력(규칙)뿐입니다.
- **Ollama·Hermes3·DeepSeek 로 글을 쓰는 코드는 없습니다.** Ollama 는 문서 3곳에서 '후보·비추천'으로만, Hermes 는 0건, DeepSeek 은 코드 수정용 유료 API 후보로 문서에만 나옵니다. 데스크톱 프로그램은 **AI 호출 코드가 0**입니다(시험이 지킵니다). 실제 AI 는 클라우드 파이프라인의 Gemini(모델 3개)뿐입니다.
- 이 프로젝트는 '개인 데스크톱 하나'가 아니라 **두 갈래**입니다 — 자동 실행되는 클라우드 파이프라인(일시정지 중)과, 사람이 쓰고 승인하는 데스크톱 작업대.
- 분석문이 '없다'고 한 검수는 **이미 여러 겹**입니다(게시 전 검사·건강 판정기·복사 전 관문·지어내지 않기·최소 품질 관문 등). **실제로 없는 것은 '필수 키워드 포함 검사'와 '가비지 텍스트 검사' 둘뿐**이고, 이 둘이 아래 6번과 새 항목 N-2 입니다.

## 3. 방향 검토 8항목 — 각각 A(채택하지 않음)·B(변형)·C(나중에 재검토)

### 1) 웹 스크래핑식 사전 리서치 — 글 쓰기 전에 웹에서 최신 정보·통계를 긁어 와 AI 에 먹이기
- **이유**: 지금 방향은 '약관이 재가공을 허용한 공식·공공·개방 자료의 구조화된 값(Fact)만 쓴다'(허용 목록 방식, 11-09 결정)이고, 일반 웹페이지·RSS 요약·기사·검색 결과 조각은 정부 자료여도 **유형만으로 자동화 제외**입니다. AI 크롤러를 막는 곳에는 접근하지 않는다는 방침과도 부딪힙니다.
- **영향**: 채택하면 허용 목록·외부 호출 관문·품질 관문 설계가 우회되고 권리·복제 위험이 생기며, 구현 중인 묶음의 병합 순서가 흔들립니다.
- **선택지**: A 채택하지 않음 / B 사람이 읽고 고른 공식 자료의 숫자·날짜를 직접 입력하는 수동 칸(앱의 '참고 주소' 칸이 이미 주소를 열지도 가져오지도 않고 글자 그대로만 보여 주므로 새로 만들 것 없음) / C 허용 목록의 구조화 제공처가 가동된 뒤 '허용된 API 를 늘리는 방식'으로만 재검토
- **추천: A**

### 2) Gemini 검색 연동(Search Grounding) — AI 가 구글 검색을 직접 해서 답의 근거로 쓰기
- **이유**: AI 처리기 정책이 'AI 에는 신호와 검증된 최소 Fact 만, 원문 외부 텍스트는 금지'로 고정돼 있고, 검색 연동은 AI 가 검색 결과 본문을 직접 읽는 방식이라 같은 종류의 입력입니다. 구글 공식 약관(시행 2026-03-23, 요약 도구를 거쳐 읽음 — 원문 확인 권장): **무료 서비스의 입력·출력은 제품 개선에 쓰일 수 있고 사람 검토자가 읽을 수 있으며**, 검색 근거 결과는 질문한 사용자에게만 검색 제안과 함께 보여 주어야 하고 **캐시·재배포·분석을 금지**합니다 — 공개 블로그에 올리고 저장소에 저장하는 우리 흐름과 문구상 충돌 소지가 큽니다. 코드에 검색 도구 사용은 0건이고, 제한 재개 조건(008)이 새 글을 AI 미사용으로 한정해 쓰일 자리도 없습니다.
- **영향**: AI 입력 규칙·약관 조건·출처 표기·재가공 권리가 한꺼번에 열리고 비용이 생길 수 있으며, 고정 값을 푸는 T3 변경이 필요하고 구현 중인 묶음과 충돌합니다.
- **선택지**: A 채택하지 않음 / B 검색은 사람이 한다(직접 확인한 공식 자료의 숫자·날짜만 입력하고 AI 에는 현행 정책대로 최소 Fact 만) / C 유료 등급 전환(운영자 비용 결정)·약관 원문 재확인·정책 개정을 먼저 한 뒤 글 생성이 아닌 비공개 노출 점검용으로만 재검토
- **추천: A** (우리 Gemini 키가 무료인지 유료인지는 운영자만 확인할 수 있습니다 — 문서 기록은 무료)

### 3) 금지어를 대체어로 자동 변환 — 위험한 표현을 자동으로 순화된 낱말로 바꿔 주기
- **이유**: 지금 설계는 '**막고 사람이 고친다**'입니다. 게시 전 검사에 걸리면 사유를 AI 에게 돌려 다시 쓰게 하고 끝내 못 맞추면 게시하지 않으며, 건강 판정기는 표시·중지만 하고, 복사 전 관문은 막되 우회 단추를 만들지 않습니다. 판정기는 낱말이 아니라 **문맥**을 읽으므로 낱말만 바꾸면 뜻은 남은 채 판정만 피하는 **은폐 도구**가 됩니다. 건강·금융·법률은 사람 승인과 가드레일을 둔다는 원칙에도 맞지 않습니다. 자동 치환 코드는 0건입니다.
- **영향**: 단속 회피성 표현 바꾸기가 자동화되어 건강 판정 보강의 효과가 줄고, 협찬·경제적 이해관계 표시를 임의로 지우지 못하게 한 원칙과 어긋납니다.
- **선택지**: A 채택하지 않음(반려·중지·경고 유지) / B 바꿔 주는 대신 '왜 걸렸는지와 고치는 방향'을 사람에게 알려 주기(이미 일부 있음 — 검사 카드 문구, 게이트 안내, 경험을 전제한 후보를 정보형으로 돌리는 글 유형 전환) / C 나중에 재검토
- **추천: A** (B 는 이미 있는 장치를 다듬는 정도라 새 기능이 필요 없습니다)

### 4) 구매 전환(Conversion) 최적화 — 독자 구매 여정에 맞춰 전환이 잘 되게 글을 구성
- **이유**: 사이트 목표는 고유 가치·정보 제공이고 AdSense 사유가 '가치가 별로 없는 콘텐츠'이므로 전환을 겨냥한 구성·문구는 반대 방향입니다. 글쓰기 규칙이 이미 '특정 제품·서비스를 홍보하거나 순위를 매기거나 구매·가입을 권하지 않는다'·'광고·홍보 말투 금지'이고, 11-09 방침은 편집과 수익화를 분리하고 협찬 가능성을 주제 점수에 더하지 않는다고 정했습니다. 구분: **구매 결정에 쓰이는 정보**(구매 전 확인사항·비교·선택 기준)는 방향 안이고, 문제는 '전환'을 목표로 한 최적화입니다.
- **영향**: 정보 제공 목적과 충돌하고 광고·협찬 표시 규칙과 얽힙니다.
- **선택지**: A 채택하지 않음 / B 독자 질문 단계(알아보기·비교·결정 전 확인)에 맞춘 정보형 틀만 다듬기(비교형·제품·서비스 소개형 틀이 이미 있음) / C 수익 구조를 운영자가 따로 정한 뒤 재검토
- **추천: A** (B 는 기존 글 유형 틀로 충족)
- **확인 필요(이 조사는 판단하지 않았고 지금은 바꾸지 않습니다)**: 데스크톱 주제 엔진의 점수에 '수익화(협업 적합도)' 항목이 이미 있는데, 위 11-09 방침('협찬 가능성을 주제 점수에 더하지 않음')과 어떻게 맞는지는 별도 확인이 필요합니다.

### 5) 전문가·병원·법률 페르소나 주입 — 병원 '과잉진료 없는 정직함', 법률 '판례 중심' 같은 정체성을 미리 주입
- **이유**: 경험·전문성을 지어내지 않는다는 원칙과 건강·금융·법률은 사람 승인과 가드레일을 둔다는 원칙에 부딪힙니다. 글쓰기 규칙이 이미 '전문가의 말·연구 결과를 쓰지 않는다'·'지어낸 인간 저자의 경험·자격·감정 금지'이고, 확인 요청 006 결정으로 필명은 'ChanceBlog 편집부'이며 가상 인물·하지 않은 검수를 했다고 쓰는 것은 금지입니다. 새 글 방식(Fact 경로)은 건강·의료·금융 투자·법률을 자동 거절합니다. '전문가가 검수한 듯한 글'은 실제 검수가 없으면 **거짓 표기**가 됩니다.
- **영향**: 지어낸 전문성·하지 않은 검수가 글에 들어가 신뢰·정책 위험이 생기고, 건강·법률 글이 늘어 가드레일 부담이 커집니다.
- **선택지**: A 채택하지 않음 / B '문체(톤)'만 — 차분한 설명체·근거 중심 같은 말투 프리셋은 허용 범위(프로필 말투·초안 선택 입력이 이미 하는 일), 직함·자격·경력·병원·법률 정체성·가치 선언은 넣지 않음 / C 실제 자격 있는 검수자가 있고 그 사실을 증빙·표기할 수 있을 때만 별도 결정
- **추천: A** (B 는 이미 있음)

### 6) 필수 키워드 포함 여부 검수 — 정해 둔 키워드가 글에 들어갔는지 검사
- **이유**: 키워드 채우기를 부추길 위험이 있습니다('가치가 별로 없는 콘텐츠'). 우리 검사 기준은 출처·날짜·중복·지어낸 사실·번역 복제·'이 글만의 가치'이고, '낱말을 몇 번 넣어야 한다'는 기준은 코드·문서에 없습니다. 비슷해 보이는 장치는 방향이 다릅니다 — 주제 선정용 우선·제외 키워드(후보 거르기), 사용자가 적은 '반드시 포함할 문장'(초안 엔진이 끼워 넣는 입력), 제목의 약속어가 본문에 있어야 한다는 낚시 제목 방지 검사.
- **영향**: 글이 낱말 위주로 기울고 유사도·중복 검사와 충돌하며, 검사 카드가 초록을 만들려고 낱말을 끼워 넣게 하는 유인이 생깁니다.
- **선택지**: A 채택하지 않음 / B 뒤집은 검사 — '필수 포함'이 아니라 **같은 낱말·문장의 지나친 반복(채우기 모양)을 경고만 하고 막지 않기**, 직접 적은 '반드시 포함할 문장'이 고친 글에 남았는지만 확인(새 항목 N-2 와 묶음) / C 나중에 재검토

### 7) AI 크롤러 방문 추적 — GPTBot·ClaudeBot 등의 방문·인용을 추적
