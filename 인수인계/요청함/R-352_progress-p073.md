# 진행 현황 P073 — 이슈 #206 답(논의·준비) (본문 — 폰에는 싣지 않고 요청 열기로 읽습니다)

## 1. 제가 이해한 요청
1. 래퍼런스 글에 사진이 들어 있으면 **사진과 글의 관계**를 읽어 초안에 반영한다.
2. 사용자가 사진을 올려 글을 쓸 때 **올린 사진과 래퍼런스 글의 모양**을 보고 어떤 의도의 글인지 파악해 초안을 쓴다.
3. 사진을 파악하기 어렵다면 사용자가 **간단한 선택형**으로 사진 정보를 적을 수 있다(예: 맛집이면 간판·건물·메뉴·인테리어·메인 메뉴·밑반찬).
4. 같은 작성자는 비슷한 사진 구성과 사진 순서대로 글을 쓰므로, 래퍼런스의 **사진·글·지도 첨부 형태 그대로** 초안을 제안한다.
5. 래퍼런스보다 사진이 적거나 많아도 **올린 사진만으로** 초안을 쓸 수 있어야 한다.
6. 부족한 곳은 사용자가 최종 검토로 고치지만 **게시글 품질은 문제없게** 한다.

## 2. 지금 앱 상태(직접 확인)
- 앱의 초안은 규칙 기반(AI 없음)이고 사진은 '[이미지 N]' 자리 표시만 있으며 사진은 사용자가 직접 올립니다. 사진 내용을 읽거나 사진 순서에 맞춰 글을 짜는 기능은 없습니다.
- 래퍼런스 보관함 자체가 아직 없습니다(이슈 #205 로 지금 만드는 중).

## 3. 제안 — 1단계는 AI 없이 가능합니다
1. **래퍼런스 구성 읽기(규칙 기반)**: 보관함의 래퍼런스 글에서 사진 자리(그림 표시·'[이미지 N]')·지도 표시·소제목·문단을 읽어 '구성표'(예: 사진 → 문단 → 사진 → … → 지도 → 마무리)를 만듭니다. 글의 문장을 베끼지 않고 **구성만** 참고합니다.
2. **사진 종류 선택**: 올린 사진마다 종류를 하나 고르는 선택칸(글 종류별 기본 목록 — 맛집이면 간판·건물 외관·메뉴판·인테리어·대표 메뉴·반찬·음식 클로즈업·기타 — 사용자가 목록을 고칠 수 있음). 사진 순서는 올린 순서이고 끌어서 바꿀 수 있습니다.
3. **초안 틀 제안**: 구성표의 순서에 올린 사진(종류 표시 포함)을 맞춰 놓고, 사진 자리마다 그 종류에 맞는 문단 틀을 앱의 기존 초안 규칙(사실 근거 문장)과 사용자가 적은 간단한 정보(가게 이름·메뉴·가격 같은 칸)로 채워 제안합니다. 지도는 '지도 자리' 표시만 두고 실제 지도 넣기는 사용자가 합니다.
4. **사진 수가 다를 때**: 같은 종류끼리 먼저 맞추고, 래퍼런스에만 있는 종류는 건너뛰거나 '사진 없이 쓰는 문단'으로 제안하고, 래퍼런스에 없는 종류의 사진은 묶음 문단으로 붙입니다 — 미리보기에서 사용자가 고릅니다.
5. **품질**: 기존 글 모양 점검(금지 표현·글 길이·이미지 설명 누락 등)을 그대로 적용하고, 사용자 입력 칸이 비면 그 문단은 비워 두지 않고 '채워 주세요' 표시로 남겨 어색한 문장이 나가지 않게 합니다.

## 4. AI 가 사진을 읽는 방식은 따로 승인이 필요합니다(2단계, 지금은 하지 않음)
사진 내용을 AI 가 알아보게 하려면 사진을 외부 AI 서비스로 보내야 해서 새 외부 연결·비용·개인정보(사진 속 얼굴·가게 정보) 문제가 생깁니다. 이는 T3 에 해당해 번호 있는 확인 요청으로 따로 여쭙겠습니다(1단계가 쓸 만한지 보신 뒤).

## 5. 정할 것 다섯 가지 — 기본값으로 진행합니다(바꾸고 싶으시면 이슈로 알려 주세요)
| 정할 것 | 기본값 |
|---|---|
| 첫 판의 글 종류 | 맛집(식당) 글부터, 같은 틀로 다른 종류를 늘림 |
| 사진 종류 목록 | 글 종류별 기본 목록 + 사용자가 추가·삭제 |
| 지도 | '지도 자리' 표시만(실제 지도는 사용자가 넣음) |
| 사진 자동 판별(AI) | 2단계로 미룸(승인 필요) |
| 사진 저장 | 앱은 사진 파일을 복사·저장하지 않고 파일 이름·순서·종류만 기억(개인정보·용량) |

## 6. 순서와 한계
- 순서: ① 래퍼런스 보관함(#205, 진행 중) → ② 래퍼런스 구성 읽기 → ③ 사진 종류 선택 화면 → ④ 초안 틀 제안. 묶음마다 독립 검증·앱 저장소 검사·병합 부탁을 거칩니다(이번 요청은 '논의·준비까지만'이라 코드는 아직 바꾸지 않았습니다).
- 한계: 규칙 기반 문장은 AI 초안보다 단조로울 수 있어, 품질을 지키려고 사실 근거 중심 문장과 사용자 입력 칸을 둡니다. 래퍼런스의 문장을 그대로 따라 쓰는 일은 하지 않습니다(표절·저작권). 화면은 이 PC 에 화면 도구가 없어 실제로 띄워 보는 시험이 어렵습니다(설치 허락 대기).
