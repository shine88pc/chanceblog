# 확인 요청 041 — 설치 도구 시험 한 번 돌리기 (결정은 한 가지)

> 이 글은 **질문**입니다. 이슈 양식 '[답변] AI 확인 요청에 답하기' 에 **대상번호 041**(`41` 처럼 써도 됩니다)과 고른 보기(1·2)를 적어 주세요. **답이 없으면 2(나중에)** 입니다. 시험은 **운영자님만** 돌릴 수 있고(AI 는 워크플로를 실행하지 않습니다), 돌리신 뒤 결과를 붙이는 것은 이 답과 상관없이 바로 하셔도 됩니다.

## 쉽게 말해
- 앱 v1.0 의 정식 설치 파일을 만들려면 설치 도구를 골라야 합니다(후보: Velopack 의 두 방식과 Inno Setup). 문서로 고르지 않고 **같은 앱 묶음에 세 후보를 적용해 숫자로 재 보는 시험**을 준비해 방금 병합했습니다([M128]).
- 이 시험은 **GitHub 가 빌려 주는 일회용 Windows 컴퓨터 안에서만** 돕니다 — 운영자님 PC 에는 아무것도 설치하거나 받지 않고, 비밀 값(키·토큰)도 쓰지 않으며, 비용은 0 입니다. 끝나면 그 컴퓨터는 사라집니다.
- 그런데 이 시험은 **운영자님이 단추를 한 번 눌러야** 돕니다(수동 실행 전용). 다 돌면 약 40–60분이 걸리고 그동안 화면을 열어 둘 필요는 없습니다.

## 하는 법 (5분 + 기다림)
1. GitHub 의 앱 저장소(`chanceblog-desktop`)에서 **Actions** 탭을 엽니다.
2. 왼쪽 목록의 **Installer spike — 설치 도구 시험(수동, 병합 뒤 운영자 실행)** 을 누릅니다.
3. 오른쪽 **Run workflow** 를 누르고 가지는 **main** 그대로 둔 채 초록색 **Run workflow** 를 한 번 누릅니다(입력칸 없음).
4. 40–60분 뒤 실행이 끝나면(초록이든 빨강이든) 그 실행을 열어 **Summary 맨 아래의 '설치 도구 시험 결과 블록'** 회색 상자를 **통째로 복사**해, 이슈 양식 **'AI 에게 새 일 맡기기(작업 요청)'** 본문에 붙여 넣어 주세요(설명은 덧붙이지 않아도 됩니다. 첫 줄은 `INSTALLER_SPIKE_RESULT`, 마지막 줄은 `END`).
5. 빨갛게 끝나거나 상자가 없으면 **빨간 X 가 붙은 단계의 이름만** 알려 주세요. '도구 받기' 에서 빨간 것은 받은 파일의 크기·지문이 미리 적어 둔 값과 달라 **일부러 멈춘 안전 장치**이니 그 사실만 알려 주시면 됩니다.
- 자세한 안내는 저장소의 `docs/INSTALLER_SPIKE_RUN.md`(쉬운 글)에 있습니다.

## 그다음
- 결과를 받으면 AI 가 점수를 측정값으로 다시 매겨 어느 도구로 갈지 결정 기록에 적고 알려 드립니다(점수 차가 작으면 이미 승인하신 Velopack 을 따릅니다). **세 도구가 모두 탈락할 때만** 다시 여쭙니다(설치 파일을 1.1 로 미루고 휴대용만 1.0 에 내는 방안).
- 시험용 파일은 결정 뒤에 지우는 정리 가지를 따로 부탁드립니다.

## 위험과 되돌리기
- 일회용 컴퓨터 안의 일이라 되돌릴 것이 없습니다. 이 시험이 빨갛게 끝나도 앱·블로그·설정에는 영향이 없습니다.
- 안전 장치: 도구는 시작할 때 GitHub 의 일회용 Windows 컴퓨터 안인지 먼저 확인하고 아니면 아무것도 안 하고 멈춥니다.
- 하지 않으시면(기본 2) 설치 도구 선택이 멈춰 있고, 앱 v1.0 의 정식 설치 파일(확인 035 ③ 범위)이 그만큼 늦어집니다.

## 1 을 추천하는 이유 · 반대 의견
- 설치 파일 선택이 v1.0 일정의 선행 조건이고, 시험은 운영자님 몫이 단추 한 번과 붙여 넣기 한 번뿐입니다. **반대 의견**: 지금 바쁘시면 나중에 하셔도 되고, 시험 결과가 마음에 안 들면 다시 돌려야 할 수 있습니다.
- 이 알림에는 운영자님 사진의 이름이나 읽은 글을 쓰지 않았습니다.
