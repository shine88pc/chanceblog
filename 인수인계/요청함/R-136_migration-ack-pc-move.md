# [R-136] 접수 확인 — PC 이전 요청과 준비 계획

> **지금 꼭 하실 일은 없습니다.** 운영자님이 20:03 에 텔레그램으로 보내신 글("현재 사용중인 pc에서 다른 pc로 변경해 작업을 이어갈 예정이야 / 다른 pc에서 이어서 진행할수 있도록 준비해줘")을 확인했습니다. 접수일 뿐 승인이 아닌 글이지만 이번 요청은 제 쪽에서 바로 준비하는 일이라 그대로 진행합니다.

## 왜 확인이 늦었나
- 텔레그램으로 보내신 글은 **정기 읽기**(10분마다로 설정된 자동 실행)가 가져가야 하는데, GitHub 가 이 정기 실행을 병합 뒤 약 3시간이 지나도록 **한 번도 시작하지 않았습니다**(Chance 정기 실행이 자주 늦는 것과 같은 GitHub 쪽 지연으로 보입니다). 그동안은 제가 브랜치를 올릴 때만 읽어서, 20:03 의 글을 20:35 에 읽었습니다.
- **조치**: ① 지금부터 제가 점검할 때마다(현황 알림·요청을 보낼 때) 읽기 확인용 브랜치를 올려 즉시 읽습니다(해 없음, 검사 한 번이 돎). ② 정기 읽기를 GitHub 가 덜 바쁜 시각(분 단위)으로 옮기는 방안은 워크플로 변경이라 병합 부탁(R-번호)으로 따로 드리겠습니다. 급한 글은 채팅으로 주셔도 됩니다.

## 이전 준비 계획 (제가 하는 일)
| 순서 | 일 | 상태 |
|---|---|---|
| 1 | **이 PC 에만 있는 작업을 전부 저장소(GitHub)로 올립니다** — 진행 중인 데스크톱 작업(NAVER 안전 틀·5채널 전략 P0·P1)의 임시 커밋을 보관용 브랜치로 올림(수정이 끝나면 한 번 더) | 진행 |
| 2 | **이어가기 안내서**를 저장소의 `인수인계/작업내용.md` 맨 위 새 절로 씁니다 — 새 PC 에서 새 세션이 가장 먼저 읽을 곳: 운영자 상시 지시(조용히 일하기·매시간 현황 알림·병합 부탁 형식·승인 범위·금지 사항), 진행 중 작업 목록과 다음 순서, 첫 10분 절차, 도구 사용법 | 진행 |
| 3 | **도구 모음**(요청 파일 만들기·한 커밋 가지 만들기·검사 결과 읽기·감시 스크립트 등 제가 매일 쓰는 소형 스크립트 13개)을 저장소 `인수인계/도구/` 에 안내문과 함께 올립니다(비밀·내 PC 경로 없음) | 진행 |
| 4 | **새 PC 처럼 깨끗한 폴더에서 저장소를 새로 받아** 안내서대로 시험·검증기·도구가 도는지 확인합니다 | 3 번 뒤 |
| 5 | 진행 중인 병합 부탁(NAVER 안전 틀·5채널 P0)은 **오늘 밤 안에 보내는 것이 목표**이고, 이전 전에 못 끝나면 안내서에 '다음 순서'로 남깁니다 | 진행 |

## 운영자님이 하실 일 (새 PC 에서, 이전 날)
1. **Git·Python 설치와 GitHub 로그인**(저장소 push 권한이 있는 본인 계정) — 안내서에 설치 목록과 순서를 적습니다(제가 대신 비밀번호를 넣지 않습니다).
2. Claude 앱을 설치·로그인하고 **저장소 두 개**(블로그 `chanceblog`, 데스크톱 `chanceblog-desktop`)를 짧은 경로에 받습니다.
3. 새 세션에서 블로그 저장소 폴더를 열고 **"이어서 진행해줘"** 라고 입력하면 안내서를 따라 이어갑니다.
- **텔레그램 봇·Gemini·Blogger 키 등 비밀은 옮길 것이 없습니다**(GitHub 의 자동 실행 설정에 있음). 데스크톱 프로그램의 키는 윈도 자격 증명 관리자에 있어 새 PC 에서 다시 입력하셔야 합니다(아직 실제로 쓰는 키는 없습니다).
- 이 PC 의 파일(임시 작업 폴더·내 메모)은 옮기지 않습니다 — 필요한 내용은 위 1~3 으로 모두 저장소에 남깁니다.

## 하나만 알려 주세요
- **이전하실 날짜(또는 시점)**: 아직 모르시면 **언제든 이전해도 되는 상태**로 준비합니다(기본값). 날짜를 알려 주시면 그 전에 진행 중인 병합 부탁을 마무리하는 순서를 맞춥니다. 이 PC 는 매일 23:00 에 강제 재부팅되어 그때 제 작업 세션도 멈추므로, 이전 날 전에 한 번 더 '이어가기 시험'을 하겠습니다.
- 답은 채팅이나 텔레그램으로 편하게 주세요(텔레그램 글은 제가 확인할 때마다 읽습니다).
