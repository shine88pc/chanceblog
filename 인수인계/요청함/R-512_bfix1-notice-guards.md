# 병합 요청 M121 — 2차 독립 감사 지적 중 AI 가 직접 고친 것 (T2)

> **병합 방식**: 지금은 AI 병합 기능이 **꺼져 있어** 운영자께서 직접 병합해 주세요. (`M121 승인` 이라고 답하셔도 아직 AI 가 병합하지 않습니다.) 이 요청은 블로그 저장소 `chanceblog` 의 것이고, PR 제목 맨 앞이 `[M121]` 인 것 하나만 병합합니다. 검사는 이미 끝나 초록입니다. 급하지 않습니다(보통).
>
> ⚠ **이 PR 은 검사 정의를 바꿉니다**(`tests/` 와 `docs/SECURITY_GUARDRAILS.md` 변경) — 그래서 검사의 초록은 바뀐 규칙으로 낸 값이니 아래 독립 확인 결과와 함께 읽어 주세요. 병합 전에 PR 화면의 머리 커밋이 `926d0d3` 로 시작하는지 한 번 봐 주세요.

## 1. 무엇을 바꾸는지
11-24 2차 독립 감사(BA·BP)가 지적한 것 중 운영자 승인 없이 AI 가 고칠 수 있는 항목입니다. **`.github/`·검증기 `scripts/validate_repo.py`·`AGENTS.md`·`pipeline/auto_notice.json`·레지스트리 값·광고 표면·의존성은 한 글자도 안 바꿨습니다.**
① **접수 코멘트가 고쳐지면 승인으로 읽지 않기**(`scripts/github_status.py`): 운영자 답 이슈는 봇이 되풀이해 적은 접수 코멘트와 본문의 값이 같을 때만 승인으로 읽는데, 그 코멘트가 접수 뒤에 고쳐졌으면 값이 같아 보여도 믿지 않고 번호 있는 확인 요청으로 다시 묻는 새 상태 `ack_edited` 를 더했습니다(시각이 없거나 읽을 수 없으면 고쳐진 것으로 봄 — 닫힌 쪽).
② **병합 부탁 알림(꺼짐 그대로)**(`pipeline/auto_notice.py`): PR 이 `.github/`·`tests/`·`scripts/validate_repo.py`·`AGENTS.md`·`docs/SECURITY_GUARDRAILS.md` 를 바꾸면 알림에 '검사 정의가 바뀐 PR — 초록은 스스로 증명한 값입니다' 줄을, 모든 알림에 머리 커밋 7자리를 싣습니다(읽기 한 가지 — 변경 파일 목록 읽기이며 새 권한 없음, 읽기 실패·0건·300개 초과면 알리지 않음). 이 알림 기능은 지금 꺼져 있어 병합 직후 동작은 그대로입니다.
③ **닫힌 쪽 워크플로 줄 시험**: 워치독의 정지 변수 전달 줄과 Chance 두 워크플로의 '콘텐츠 출처 확인' 단계가 실패하면 닫히는 모양을 글자 그대로 못박는 시험(워크플로 파일은 안 고침).
④ **정지·킬 스위치 안내 정정**(문서·시험): `mode: off` 는 Blogger·네이버·티스토리에만 맞고 **Chance 는 `PIPELINE_PAUSE` 만 멈춤 수단**이라는 점, 멈추려면 `true` 이고 `off` 는 재개라는 점, 모르는 최상위 키가 실행도 멈추는 점 등을 코드 사실에 맞춰 바로잡고 그 사실을 코드로 읽는 시험을 더했습니다.
⑤ **연습 실행 스위치**(`generator.py`): `DRY_RUN` 의 켜짐 값을 정지 변수 등과 같은 한 집합(1·true·yes·on)으로 맞췄습니다 — `DRY_RUN=on` 이 연습으로 읽혀 글을 올리지 않는 쪽으로만 달라집니다. **쓰는 쪽 스위치 `FIX_IMAGES` 는 옛 켜짐 값(1·true·yes)을 그대로 둡니다**(독립 안전 확인이 쓰기 방향 스위치를 넓히지 말라고 지적해 반영).

## 3. 위험과 알려 둔 한계
- 이 PR 은 `tests/` 와 `docs/SECURITY_GUARDRAILS.md` 를 바꿔 **검사 정의를 바꾸는 PR** 입니다. 시험은 약해지지 않았고(기존 시험에서 약해진 단언 0 — 독립 확인이 기준과 머리의 차이를 줄 단위로 대조), 새 시험과 변이로 지켰습니다.
- 접수 코멘트에 이모지 반응이 달리면 `updated_at` 이 바뀌어 **정상 승인도 `ack_edited` 로 읽힐 수 있습니다**(안전한 쪽 — 다시 묻기만 함). 실제 GitHub 응답으로 첫 관측이 필요해서, 병합 직후 최근 정상 `[답변]` 이슈에 읽기 도구를 한 번 돌려 `접수대조=same` 인지 확인하겠습니다.
- 병합 부탁 알림의 새 표기(⚠ 줄·머리 커밋)는 알림 자동화가 켜진 뒤에는 자동이고, 그 전(지금)에는 제가 요청 파일 `verify` 칸에 직접 씁니다(요청 도구가 자동으로 붙이지 않음 — 후속 작은 개선 후보).
- **후속 T3 제안(이 병합 밖, 따로 묶어 여쭙겠습니다)**: `AGENTS.md` 의 승인 문장에 '고쳐진 접수 코멘트도 승인이 아님' 한 구절·검증기의 사각(재사용 워크플로·`docker://` 단계 등)·`guardrails.yml` 의 `cancel-in-progress` 를 main 에서 끄기·환경 시크릿 등. `[Watchdog]` 정지 알림 이슈를 AI 가 닫는 수단은 정하지 않았습니다(런북이 이슈 쓰기를 금지).
