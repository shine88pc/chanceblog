# 확인 요청 038 — 인터넷 접속을 어디까지 열까요 (결정은 한 가지)

> 이 글은 **질문**입니다. 이슈 양식 '[답변] AI 확인 요청에 답하기' 에 **대상번호 038**(`38` 처럼 써도 됩니다)과 고른 보기(1–3)를 적어 주세요(2 를 고르시면 내용 칸에 줄일 범위를). **답이 없으면 3(보류)** 입니다. 승인하셔도 **이 요청은 설계와 구현 준비까지**입니다 — 소스의 스위치를 실제로 켜는 일은 갈래마다 구현과 독립 검증이 끝난 뒤 **새 번호로 다시** 여쭙고, 병합은 운영자님만 합니다.

## 왜 묻는지
- 앱은 지금 인터넷으로 나가는 일이 **전부 꺼져 있습니다**(외부 쓰기·접속 완전 비활성, 2026-11-11 결정). 그런데 v1.0 완료 기준 5번(GitHub Pages 테스트 글을 만들고 승인 뒤 배포)·6번(Blogger 테스트 글 초안 저장)과 앱 스스로 업데이트 확인은 접속이 있어야 합니다. 그래서 어디까지 열지를 먼저 정해야 설계·구현을 시작할 수 있습니다.
- 설계서 셋을 마쳤습니다(네트워크 공통 틀·Pages 가지 올리기·Blogger 초안 저장 — 적대적 위협 66행·시험 계획·변이 60개 포함).

## 여는 세 가지 (모두 '표에 적힌 곳만·사용자가 누를 때만·기본 꺼짐')
| 번호 | 기능 | 하는 일 | 하지 않는 일 |
|---|---|---|---|
| ㉠ | 업데이트 확인(읽기) | 설정 화면의 '확인' 단추를 누를 때만 새 버전이 있는지 읽음 | 자동 확인·상시 백그라운드·버전 번호 외 아무것도 보내지 않음 |
| ㉡ | Pages 가지 올리기 | 만든 글을 **새 가지에만** 올리고 GitHub 에서 합칠 화면(PR 비교 링크)을 글자로 알려 줌 — 공개는 운영자님이 GitHub 에서 직접 병합 | **main 에 곧바로 올리기 금지**·앱이 Git 로그인 정보를 만지지 않음(이 PC 의 기존 로그인 사용) |
| ㉢ | Blogger 초안 저장 | 구글 로그인(앱 안 루프백) 뒤 **초안으로만** 저장 — 공개는 운영자님이 Blogger 에서 | 초안 아닌 즉시 공개 금지·키·토큰은 앱 입력 칸과 자격 증명 보관소에만 |

가장 위험한 두 가지('main 에 직접 올리기'·'초안이 아닌 공개')는 **네 겹씩** 막고, 사진·읽은 글·경로·사용자 이름은 어떤 요청에도 실리지 않는지를 시험으로 확인합니다.

## 승인(보기 1)하면 일어나는 일
1. AI 가 구현 갈래를 `NO-MERGE-` 가지에서 시작합니다 — 순서 **공통 틀 → Pages → 업데이트 → Blogger**, 스위치는 **모두 꺼진 채** 병합 부탁이 옵니다(약 60–70시간 AI 작업, 병렬이면 이틀 안팎·독립 검증 별도).
2. **안전 시험의 허용 목록이 4곳에서 6곳(+ Blogger 로그인용 컴퓨터 안 한 곳)으로 늘어납니다** — '아무것도 못 나감' 이 '정확히 이 곳들만' 으로 바뀌는 것이라 약해지는 것은 아니며, 약해지지 않았음을 변이 시험 60개로 보입니다.
3. 패키지 점검(`--selftest`·Package Gate 의 '외부 게시 0')의 기준이 '모두 꺼짐' 에서 '승인받은 스위치만 켜짐' 으로 바뀝니다(이것도 T3 변경이라 병합 부탁 때 따로 알립니다).
4. 보관함 판 번호가 2 에서 3 으로 한 번 올라갑니다(열 때 사본이 자동으로 남고, 옛 버전 앱은 새 데이터를 안전하게 거절).
5. 켜는 소스 변경(스위치 `True`)은 갈래마다 새 번호 있는 확인으로 다시 여쭙습니다. Pages 는 켠 뒤 시험 글 두 단계(① PR 만 만들어 보고 닫기 ② 시험 글 한 건 병합·공개 확인·삭제 요청 — 확인 036 의 시험 글 방식), Blogger 는 입력·로그인 단계 뒤 초안 저장 단계입니다.

## 운영자님 몫 (승인 뒤, 그때 다시 안내)
- **Pages**: 이 PC 의 Git 로그인이 이 저장소에 가지를 만들 수 있는지 확인(비밀은 GitHub·Git 화면에서 직접)·시험 글 실기 두 단계(공개 영향이 있는 ②는 따로 승인).
- **Blogger**: 구글 클라우드에서 영문용·한글용 '데스크톱 앱' OAuth 클라이언트 2개(클라우드 자동 발행이 쓰는 것과 다른 것)·Blogger API 사용 설정·동의 화면 프로덕션 전환·앱에서 로그인·시험 초안 1건 확인. 값은 앱 입력 칸에만 붙여 넣습니다.

## 보기와 선택
1. **승인(추천)** — ㉠㉡㉢ 셋 모두 구현 준비. 완료 기준 5·6번과 앱 스스로 업데이트 확인을 모두 유지합니다.
2. **범위 줄이기** — 내용 칸에 적어 주세요. 예: '㉠㉡ 만(Blogger 는 v1.0 뒤로 — 완료 기준 6번 제외)'·'㉠ 만(읽기 접속만 — 5·6번 제외)'. 받으면 번호 있는 확인으로 범위를 다시 확정합니다.
3. **보류(기본)** — 지금처럼 아무것도 열지 않습니다(5·6번과 앱 스스로 업데이트는 빠집니다).

## 1 을 추천하는 이유 · 반대 의견
- 새 접속은 모두 '표에 적힌 곳만·누를 때만·기본 꺼짐' 으로 만들 수 있고, 설계서가 위협 66행과 시험 계획을 이미 적었습니다. v1.0 완료 기준을 줄이지 않는 가장 짧은 길입니다.
- **반대 의견**: 한 번 열면 되돌리는 비용이 크고 구현·검증에 시간이 많이 듭니다. 위험을 줄이려면 2 로 시작할 수 있습니다(대가: 완료 기준 6번을 빼야 함).
- 이 알림에는 운영자님 사진의 이름이나 읽은 글을 쓰지 않았습니다.
