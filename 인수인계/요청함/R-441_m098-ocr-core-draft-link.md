# 병합 요청 M098 — 글자 읽기 b 단계 1·3 (앱)

> **병합 방식**: 지금은 AI 병합 기능이 **꺼져 있어** 운영자께서 직접 병합해 주세요. (`M098 승인` 이라고 답하셔도 아직 AI 가 병합하지 않습니다.) 이 요청은 앱 저장소 `chanceblog-desktop` 의 것이고, PR 제목 맨 앞이 `[M098]` 인 것 하나만 병합합니다. 검사는 이미 끝나 초록입니다. 급하지 않습니다(보통). 이 병합은 안전 시험의 허용 목록을 넓히는 줄이 있어 운영자만 병합하는 종류입니다.

## 1. 무엇을 바꾸는지
승인해 주신 '사진 속 글자 읽기'(확인 018 사진은 PC 밖으로 나가지 않음 · 026 앱 연동 승인 · 030 ② GEOS 고지문만 넣고 소스 압축 파일은 없음)의 **첫 병합**입니다. 눈에 보이는 기능은 없고 몸통만 들어갑니다.
① **추가 도구 소스(`ocr_addon/`)**: 읽기 작업자·앱과 주고받는 약속(프로토콜)·네트워크 차단 가드·빌드 도구·고정 목록·고지문. 앱 본체에는 설치되지 않는 별도 도구의 소스이고, 앱의 의존성은 늘지 않았습니다.
② **앱 쪽 몸통**: 읽기 어댑터(이 PC 안 계산 작업자 하나만 띄우고, 시간 초과·연속 실패·약속 위반이면 자식 프로세스까지 끝냄) · 추가 도구 폴더 점검(해시·크기·정보 파일) · 순수 규칙(상태 기계·대기열·세대 번호·시간 값·읽은 줄 확인·고침·빼기·합치기·'모두 맞아요' 두 단계) · 오류 코드 7개(문서 15절).
③ **초안 잇기**: 사용자가 확정한 글자 줄이 있으면 그 사진 문단 끝에 틀 문장(`사진에 적힌 글이에요.`)과 확정한 줄들을 이은 문단 하나를 더합니다. 글자가 없으면 옛 동작과 한 글자도 같습니다.
④ **기능 관문**: `LOCAL_OCR` 는 **False** 이고 화면 연결(다음 병합)도 없어서, 읽기 어댑터는 이 빌드에서 한 번도 뜨지 않습니다. 켜기는 따로 번호를 붙여 여쭙습니다.

## 2. 왜 필요한지
운영자 승인(026)대로 글자 읽기를 단계로 나눠 넣습니다. 몸통(이번)과 화면(다음), 도구 빌드 흐름(그다음)을 따로 병합해 한 번에 검토할 양을 줄였고, 켜기 전에 각 단계를 독립 검증으로 막아 둡니다.

## 3. 사용자가 체감하는 변화
없습니다. 앱에서는 켜지지 않아 어떤 화면도 달라지지 않습니다(사진 없는 글 1,092건·글자 없는 사진 2,016경우·컨트롤러 흐름 77행·사진 보드 흐름 380건이 병합 전 main 과 같음을 직접 견줌).

## 4. 위험과 기존 기능에 미치는 영향
- **기존 기능**: 저장 형식(초안·사진 정보·백업)·서비스 쓰기·설정·네트워크는 안 바뀌었습니다. 새 칸·새 의존성 0. 앱의 하위 프로세스는 '이 PC 안 계산 작업자 하나'뿐이고 네트워크 모듈은 어느 허용 목록에도 없습니다.
- **안전 시험의 허용 목록 변경(모두 강화 방향, 병합 전 직접 확인해 주세요)**: 하위 프로세스 허용 +1(어댑터 파일) · 하위 프로세스를 띄우는 곳 목록 +2(어댑터 첫 문장이 관문임을 시험이 확인) · 읽기 전용 열기 허용 +1(한 함수, 몸통이 `open(path, 'rb')` 한 줄뿐임을 소스에서 확인) · 임시 폴더 지우기 한 호출만 허용(그 함수 밖의 같은 호출은 그대로 걸린다는 시험이 따로 있음). 바뀐 기존 시험에 약화는 없습니다.
- **알려 둔 한계**: 네트워크 가드는 `sendmsg`(유닉스 전용)·`bind`·`listen` 을 감싸지 않습니다(작업자는 윈도 전용이라 이 빌드에서 닿지 않음 — 다른 운영체제로 옮기면 가드부터 넓혀야 함). 윈도 Job 개체는 프로세스를 띄운 뒤에 넣습니다(아주 짧은 틈, 입력 끝·유휴 종료가 따로 있음). 읽은 뒤 빈 임시 폴더(`cbd-ocr-` 로 시작)가 남을 수 있습니다. 진짜 추가 도구 빌드는 이 병합에서 돌리지 않았습니다(빌드 흐름은 별도 병합). 사진 대상·설명·메모 칸이 `Token:` 같은 이름 줄로 끝나는 틈은 기존 main 때부터이며 마지막 관문이 일반 실패 문장으로 막습니다.
- **운영자께 여쭐 것(급하지 않음, 이번 병합과 별개)**: 추가 도구에는 GEOS(LGPL-2.1) 부품이 들어 있어, 앱 이용 약관이 '디버깅을 위한 역설계'까지 금지하지 않는지 도구를 실제로 배포하기 전에 한 번 봐 주세요(AI 는 약관을 바꾸지 않습니다). **추천: 배포 전에 확인.**

## 5. 시험·독립 검증 결과
- 새 시험 478개(몸통 383 + 초안 잇기 95): 고치기 전 코드에서 빨강이고, 구현자 변이 350개 모두 시험이 잡았습니다(동등 변이 2개 제외). 3.12·3.10 바뀐 모듈 전체 통과.
- 독립 검증(구현자와 다른 AI 둘 이상): 몸통은 1차 필수(빌드 점검 실패 뒤에도 산출물을 만드는 틈·소켓 가드의 시험 틈 등)를 모두 고친 뒤 변경분 재확인 **둘 다 pass(필수 0·권고 0)**, 초안 잇기는 1차 필수 1(줄 하나씩은 통과하지만 이으면 비밀 모양이 되는 입력)을 고친 뒤 변경분 재확인 통과.
- 검사(CI) 앱 12칸 초록. 앱 검사에는 PySide6 가 없어 Qt 시험은 건너뛰므로, 이 병합 가지의 Qt 시험은 GitHub 윈도 러너에서 따로 돌렸습니다(네 조각 모두 통과).
