# 병합 요청 M102 — 후속 정리 둘째 묶음 POLISH-2 (앱)

> **병합 방식**: 지금은 AI 병합 기능이 **꺼져 있어** 운영자께서 직접 병합해 주세요. (`M102 승인` 이라고 답하셔도 아직 AI 가 병합하지 않습니다.) 이 요청은 앱 저장소 `chanceblog-desktop` 의 것이고, PR 제목 맨 앞이 `[M102]` 인 것 하나만 병합합니다. 검사는 이미 끝나 초록입니다. 급하지 않습니다(보통).

## 1. 무엇을 바꾸는지
앞 묶음(POLISH-1)의 독립 검증이 '병합은 막지 않지만 고칠 만하다' 고 남긴 작고 안전한 것들을 한 묶음으로 닫습니다(운영자 방침: 세부는 추천안으로 진행하고 알리기만 함).
① **네이버 복사 속도**: 마침표가 아주 길게 이어진 줄(예: 2만 개와 글자 하나)에서 문장 끝을 찾는 정규식이 제곱 시간이 걸리던 것을 앞 한 줄 추가로 선형으로 고쳤습니다. 옛·새 정규식이 걸린 자리를 1,400만 개가 넘는 글로 견줘 차이가 0 입니다.
② **툴팁**: 줄인 칩·요약 배지·카드·서랍의 '전체 이름' 툴팁이 별명 속 `<b>굵게</b>` 같은 글을 서식 글로 읽던 것을 한 곳에서 글자 그대로 보이게 했습니다(옛 서랍 툴팁도 같은 곳을 거침).
③ **확인창 바꿔 열기의 예약 예외**: 확인창이 같은 이벤트 차례에 지워질 때(앱을 닫을 때) 나던 예외를 없앴습니다.
④ **작은 어색함**: 개수가 붙는 칩은 늘 `이름 · 개수` 로, Seed 가져오기·일괄 바꾸기·후보 만들기 확인창의 채널 줄 앞머리는 쌍점 두 번 대신 줄표로, 주제 묶음 칩 접근 이름은 채널 칩과 같게 맞췄습니다.
⑤ **낮은 창의 확인창 높이**: 확인창이 창 높이보다 조금(16px 까지) 길면 위아래 여백을 8px 까지 줄여 막대 없이 엽니다(사진 3장 확인창이 낮은 창 1093×614 에서 막대가 생기던 것). **이 규칙은 모든 확인창에 닿습니다** — 아래 4절의 확인 결과를 봐 주세요.

## 2. 왜 필요한지
POLISH-1 검증이 남긴 목록 가운데 저장 형식·서비스·외부 접속을 건드리지 않는 것만 골랐습니다. 눈에 보이는 작은 거슬림(낮은 창의 막대·툴팁 서식 노출·칩 글 불일치)과 한 건의 느려짐(구두점 줄)을 정리합니다.

## 3. 사용자가 체감하는 변화
- 낮은 창(예: 1093×614)에서 사진 확인창·일부 확인창이 막대 없이 열립니다(여백이 위아래 8px 로 줄어듦). 보통·큰 창은 그대로입니다.
- 개수가 붙은 칩이 모두 `이름 · 개수` 모양입니다. 확인창의 채널 줄 앞머리가 줄표입니다.
- 별명에 꺾쇠 글이 들어 있어도 툴팁에 글자 그대로 보입니다.
- 네이버 복사가 구두점 줄이 아주 길어도 멈추지 않습니다.

## 4. 위험과 기존 기능에 미치는 영향
- **기존 기능**: 저장 형식·서비스 쓰기·백업·설정·`.github`·외부 접속·의존성은 안 바뀌었습니다. 안전 시험의 허용 목록 변경도 없습니다. 바뀐 기존 시험 8곳은 값·문턱을 새 규칙에 맞춘 것이며 약화는 없습니다(더 엄하게 바꾼 곳 하나 포함).
- **확인창 높이 규칙(모든 확인창에 닿는 부분)을 안전 검증자가 직접 확인**: 확인창 40장면을 병합 전 main 과 견줘 **같음 40·다름 0**(바이트 단위), 확인창 13종을 창 높이 1px 단위로 훑은 467줄 중 띠 밖 289줄은 main 과 같고 띠 안 178줄은 모두 막대 없이 열리며 위아래 여백이 8px 이상입니다(main 은 이 178줄 모두 막대가 있었음). 표준 창 크기에서 달라지는 것은 낮은 창의 사진 3장 확인창과 보통 확인창 일부뿐입니다. 150% 배율 흉내에서도 같았습니다.
- **알려 둔 한계**: offscreen 으로만 봤습니다 — 실제 윈도 125%·150% 렌더·한글 입력기·화면 읽기 프로그램·진짜 마우스 툴팁·낮은 창에서 8px 여백이 답답해 보이는지는 운영자 PC 확인 목록(`docs/UI_VISUAL_QA.md`)입니다. 툴팁 도우미가 줄바꿈 글(CRLF)을 두 번 그리는 경우·아직 원문을 그대로 쓰는 고정 글 자리 4곳은 병합을 막지 않는 참고로 남겼습니다.
- **운영자께 여쭐 것(급하지 않음, 이번 병합과 별개)**: 낮은 창에서 확인창 위아래 여백이 8px 만 남는 모양이 답답한지 운영자 PC(125%·150%)에서 한 번 봐 주세요 — **추천: 유지**(막대가 생겨 버튼이 가려지는 것보다 낫다고 판단).

- 독립 검증(구현자와 다른 AI 둘 — 안전·시험): 둘 다 **pass(필수 0·권고 0)**. 네이버 정규식은 새 도구로 395만 개 글(시험 렌즈)과 1,431만 개 글(안전 렌즈)에서 옛 정규식과 차이 0 이고 악성 입력이 선형 시간입니다. 병합 충돌은 문서뿐이며 두 쪽 절을 모두 남겼습니다.
- 검사(CI) 앱 12칸 초록. 앱 검사에는 PySide6 가 없어 Qt 시험은 건너뛰므로, 이 병합 가지의 Qt 시험은 GitHub 윈도 러너에서 따로 돌렸습니다(네 조각 모두 통과).
