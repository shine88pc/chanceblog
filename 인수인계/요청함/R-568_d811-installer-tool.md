# 병합 요청 M138 — 설치 도구 결정 기록 D-811 (앱, T0)

> **병합 방식**: 지금은 AI 병합 기능이 **꺼져 있어** 운영자께서 직접 병합해 주세요. (`M138 승인` 이라고 답하셔도 아직 AI 가 병합하지 않습니다.) 이 요청은 앱 저장소 `chanceblog-desktop` 의 것이고, PR 제목 맨 앞이 `[M138]` 인 것 하나만 병합합니다. 검사는 이미 끝나 초록입니다. 급하지 않습니다(보통).

## 1. 무엇을 바꾸는지
설치 도구 시험을 두 번째로 돌려 주신 결과(이슈 #288)를 읽고, 앱의 **설치 파일을 만드는 도구를 Inno Setup 으로 정한** 결정 기록입니다. 앱·코드·시험·설정은 그대로이고 문서 네 곳만 바뀝니다.
- 세 후보(Velopack 에 파이썬 부품을 더한 것·Velopack 만·Inno Setup)가 **관문 여덟 개를 모두 통과**했습니다. 표준 사용자 계정에서 설치해 보는 것만 일회용 컴퓨터에서 확인되지 않았고(세 후보 모두 같음) 운영자 PC 시험지로 남습니다.
- 점수는 Inno Setup 84·Velopack(파이썬 부품 없이) 68·Velopack(부품 더함) 63 입니다(다른 AI 가 이 점수를 보지 않고 따로 매긴 값 82·65·61 도 같은 결론). 점수 차가 5점을 넘으면 점수가 높은 쪽으로 가기로 한 규칙에 따라 Inno Setup 입니다. 이미 승인하신 틀(D-04)의 2순위로 가는 것이라 위임 규칙에 따라 새 승인 없이 정하고 알려 드립니다.
- 근거 숫자(일회용 컴퓨터 측정): 설치 파일 크기 29.1 MB(Velopack 49.4 MB)·조용한 설치 3.1초(Velopack 30.7초)·제거해도 글·설정·자격 증명이 남음·한국어 안내 글 있음.
- 약점과 대책: 앱을 켜 둔 채 새 설치 파일을 실행하면 새 판이 적용되지 않았습니다(깨지지는 않고 옛 판이 그대로 남음). 그래서 업데이트는 앱이 먼저 끝난 뒤 설치 파일을 실행하는 방식으로 하고, 켜 둔 앱이 있을 때의 결과는 실제 모양으로 나중에 다시 재서 확인합니다.
- 바뀐 곳: `docs/DECISIONS.md`(D-811 한 행)·`docs/DECISIONS_INDEX.md`(생성물)·`CHANGELOG.md`(한 줄)·`docs/INSTALLER_SPIKE_RUN.md`(끝에 짧은 절).

## 2. 왜 필요한지
설치 파일을 실제로 만드는 다음 갈래(설치 구현)가 이 결정을 기다립니다. 결정을 기록해 두어야 이어받는 작업이 같은 근거 위에서 갑니다. 설치 구현은 이미 병합하지 않는 작업 가지에서 이 결정을 근거로 준비를 시작했습니다.

## 3. 사용자가 체감하는 변화
**없습니다.** 문서만 바뀝니다.

## 4. 위험과 알려 둔 한계
- 이 결정은 설치 구현이 병합되기 전까지는 되돌릴 수 있습니다. 점수의 가중치는 AI 가 정한 값(보안·데이터 보존·수동 우선을 위에 둠)이라 다르게 보시면 알려 주세요.
- 일회용 컴퓨터는 실제 PC 와 달라서(Defender 실시간 보호가 꺼져 있음·표준 사용자 설치를 못 해 봄) 표준 사용자 설치(T-INST-04)와 SmartScreen 경고(무서명 — D-05)는 운영자 PC 시험지에서 확인합니다.
- 켜 둔 앱이 있을 때의 업데이트 결과는 시험이 생산과 호출이 달라 완전하지 않습니다 — 이 부분만 나중에 다시 잽니다(결정 기록에 적어 둠).
- 운영자께 여쭐 것은 없습니다(이의가 있을 때만 알려 주세요).
