# 병합 요청 M139 — Blogger 초안 저장 장치(앱, T3)

> **병합 방식**: 지금은 AI 병합 기능이 **꺼져 있어** 운영자께서 직접 병합해 주세요. (`M139 승인` 이라고 답하셔도 아직 AI 가 병합하지 않습니다.) 이 요청은 앱 저장소 `chanceblog-desktop` 의 것이고, PR 제목 맨 앞이 `[M139]` 인 것 하나만 병합합니다. 검사는 이미 끝나 초록입니다. 급하지 않습니다(보통).

## 1. 무엇을 바꾸는지
운영자께서 확인 038 ③(이슈 #265)로 승인하신 'Blogger 초안 저장' 의 설계와 구현 준비를 구현했습니다. 앱이 승인한 글을 **Blogger 에 초안으로만** 저장하는 길이고, **모든 스위치가 꺼진 채** 들어갑니다.
- **구글 로그인**: 이 PC 안에서만 열리는 한 번짜리 창구가 로그인 코드를 받습니다(표준 방식 PKCE). 로그인 주소는 앱이 열지 않고 사용자가 직접 엽니다.
- **초안 저장 한 가지**: 블로그 확인·초안 저장·같은 제목 초안 찾기·초안인지 확인 — 네 가지 요청뿐이고 **공개·수정·삭제 길은 없습니다**. 쓰기 자동 재시도 0, 저널을 먼저 쓰고 보내서 앱이 꺼져도 이어받습니다.
- **연결 해제**: 구글에 취소 요청을 먼저 보내고 이 PC 의 기록을 지웁니다.
- **글 변환**: 승인한 원고 → Blogger 초안 제목·HTML·라벨(이 PC 사진이 든 글은 안내하고 멈춤).
- **안전 장치**: 보내기 직전 비밀 검사 두 번·로그인 창구는 이 PC(127.0.0.1)에만 열리고 180초 제한·비밀 값은 오류 글·로그에 남기지 않음. 명령줄 `blogger` 부명령과 `doctor` 줄도 더해지지만 스위치가 꺼져 있으면 모두 거절됩니다.
- 바뀐 곳(55개 파일): 새 소스 6(`net/loopback.py`·`publish/blogger.py`·`publish/blogger_auth.py`·`render/blogger.py`·`service/blogger_flow.py`·`ui/core/open_url.py`)·바뀐 기존 소스 11(선언·등록·덧붙임 위주)·시험 31(새 12·바뀐 19)·문서 8(새 `docs/BLOGGER_SETUP.md` 포함).

## 2. 왜 필요한지
앱 v1.0 의 'Blogger 초안 저장' 을 켜기 전 상태까지 만들어 두면, 구현·독립 검증이 끝난 뒤 켜는 단계(① 입력·로그인 ② 초안 쓰기)를 새 번호로 따로 승인받아 켤 수 있습니다. 구글 로그인과 토큰을 다루는 부분이라 켜기 전에 독립 검증을 두 번 거쳤습니다.

## 3. 사용자가 체감하는 변화
**없습니다.** 스위치가 모두 꺼져 있어 앱은 Blogger 에 접속하지도 쓰지도 않습니다. 설정 화면의 모양은 그대로입니다.

## 4. 위험과 알려 둔 한계
- **켜는 일은 이 병합에 없습니다.** Blogger 스위치(`NET_BLOGGER_OAUTH`·`NET_BLOGGER_DRAFT` 등)는 독립 검증 뒤 새 번호로 두 단계로 따로 승인받습니다.
- 가짜 구글 서버로만 확인한 것(실기 확인이 필요): 실제 구글의 할당량·제목과 라벨 길이 상한·콜백 경로·갱신 토큰이 오는 조건·취소 응답·윈도 방화벽 질문. 켜기 전 실기 단계 항목으로 문서에 적었습니다.
- 같은 제목 초안이 둘일 때 어느 쪽이 내 것인지 못 가립니다(이어받기는 제목과 내용 해시가 모두 같을 때만, 아니면 새 초안 + 알림 — 옛 초안은 지우지도 덮어쓰지도 않음).
- 재확인 권고 일곱(병합을 막지 않음, 시험 한두 줄로 닫는 틈)은 시험 묶음 후속으로 미룹니다. 코드 결함은 찾지 못했습니다.
- 병합 가지를 만들 때 시험 오염 하나(같은 프로세스 안에서 한 시험 모듈이 끝난 뒤에도 Blogger 연결 자리를 남겨 뒤쪽 시험이 빨개지던 것)를 시험 파일 한 곳에서 바로잡았습니다. 코드는 0줄이고 시험 개수·단언은 그대로입니다.
- 운영자께 여쭐 것은 없습니다.
