# 병합 요청 M142 — 설치 파일(Inno Setup)을 만드는 도구와 규칙(앱, T2)

> **병합 방식**: 지금은 AI 병합 기능이 **꺼져 있어** 운영자께서 직접 병합해 주세요. (`M142 승인` 이라고 답하셔도 아직 AI 가 병합하지 않습니다.) 이 요청은 앱 저장소 `chanceblog-desktop` 의 것이고, PR 제목 맨 앞이 `[M142]` 인 것 하나만 병합합니다. 검사는 이미 끝나 초록입니다. 급하지 않습니다(보통).

## 1. 무엇을 바꾸는지
설치 도구를 Inno Setup 으로 정한 결정(이슈 #288)에 따라, **정식 설치 파일(`ChanceBlogDesktop-<버전>-Setup.exe`)을 만드는 도구**를 구현했습니다. 앱 코드(`src/`)·스위치(모두 꺼짐)·`.github`·서명·태그·릴리스·의존성은 0줄이고, 바뀐 곳은 `packaging/`·시험·문서뿐입니다.
- **설치 파일 만들기** `packaging/build_installer.py`: 묶음 폴더와 압축 파일을 확인한 뒤 Inno Setup 컴파일러로 설치 파일을 만들고, 컴파일러 판과 파일 SHA-256 을 바깥 정보에 남깁니다. 컴파일러를 못 찾거나 판을 읽지 못하면 만들지 않고 멈춥니다.
- **생산 스크립트** `packaging/ChanceBlogDesktop.iss`: 사용자 폴더에 설치(관리자 암호 없음)·제거해도 글·설정·백업·자격 증명은 남김·데이터를 지우는 구역이 없음을 시험이 지킵니다.
- **한 곳에 못박은 값** `packaging/pkgcommon.py`: 설치 파일 이름(버전 모양이 틀리면 거절)·영구 앱 ID·무음 설치·제거·업데이트 인자의 단일 출처·설치 폴더와 데이터 폴더가 겹치는지 보는 검사.
- **바깥 정보에 선택 칸** `installer`(도구 이름·판·컴파일러 SHA-256·만든 곳)와 `artifacts`(설치 파일·압축 파일별 이름·SHA-256·크기): `schema` 번호는 그대로입니다.
- 바뀐 곳(18개 파일): 코드 5(`packaging/{build_installer,pkgcommon,build_package,make_manifest}.py`·`ChanceBlogDesktop.iss`)·시험 새 셋(`installer_build_support`·`test_installer_build_rules`·`test_installer_ids`)과 바뀐 기존 시험 셋·문서 7(`CHANGELOG`·`docs/{DECISIONS,DECISIONS_INDEX,PACKAGE,RELEASE,SECURITY,PERSONAL_PC_TEST_V1_DRAFT}.md`).

## 2. 왜 필요한지
앱 v1.0 은 정식 설치 파일로 배포됩니다. 설치 파일을 만드는 도구가 있어야 릴리스 갈래가 설치 파일을 만들어 올릴 수 있고, 업데이트 적용(방금 병합된 설치 도구 연결)이 쓰는 무음 인자도 이 도구와 **같은 값**이어야 어긋나지 않습니다 — 이번 병합으로 두 값이 같음을 지키는 시험이 처음 켜집니다.

## 3. 사용자가 체감하는 변화
**없습니다.** 앱은 한 줄도 바뀌지 않았고, 설치 파일은 아직 어디에도 올라가지 않습니다.

## 4. 위험과 알려 둔 한계
- **릴리스·서명·태그는 이번에 하지 않았습니다.** 설치 파일도 코드 서명이 없어 처음 실행할 때 SmartScreen 경고가 뜰 수 있습니다(SHA-256 대조 안내를 릴리스 갈래가 맡습니다).
- 진짜 설치 파일로만 확인할 수 있는 것은 릴리스 갈래의 실기 단계로 남깁니다: `/CLOSEAPPLICATIONS` 의 실제 효과·무음 설치와 제거를 한 번 돌려 보는 러너 스모크.
- 진짜 컴파일은 앱 검사의 윈도 칸에서 처음 돌았고 **통과했습니다**(Inno Setup 6.7.1 로 컴파일된 설치 파일 약 2.1MB — 실행 요약의 안내 둘). 그래도 설치 파일을 실제로 깔아 보는 일(무음 설치·제거·`/CLOSEAPPLICATIONS` 실측)은 릴리스 갈래의 러너 스모크 몫입니다.
- 시험 묶음 후속으로 미룬 것: 러너 이미지 이름 값의 줄바꿈 한 글자 통과(러너 값이라 위험 낮음)·3.13 에서만 나는 기존 시험 하나(이 갈래와 무관, 검사는 3.10·3.12).
- 운영자께 여쭐 것은 없습니다.

## 5. 시험·독립 검증 결과
- 시험: 시험 id +205(이 갈래 기준 — 1차 +163·재작업 +42, 사라진 0·세 파이썬 같은 집합), 새 시험 모듈 셋, 구현자 변이(일부러 틀리게 해 보는 시험) 52개와 재작업 변이 47개가 모두 걸림, 파이썬 3.12·3.10 통과. 업데이트 적용과 합친 나무에서 INSTALL 시험 묶음 412개 통과(건너뜀 1 = 개발 PC 에 Inno 가 없어 건너뛴 진짜 컴파일 시험), 앱과 설치 쪽 무음 인자가 같음을 지키는 시험이 건너뛰지 않고 통과.
- 독립 검증(구현자와 다른 AI): 1차 안전(필수 0·권고 6)·시험(필수 2·권고 10) → 권고를 모두 닫는 재작업 → 변경분 재확인(안전·시험 겸임) **통과**(필수 0·권고 2·참고 13). 권고 하나(문서가 '릴리스 워크플로가 상대 경로로 부른다'고 적은 문장 — 지금 명령줄은 절대 경로)는 병합 가지에서 바로잡았고, 나머지 하나(시험 보강)는 시험 묶음 후속입니다.
- 검사(CI): 앱 검사(CI) 12칸이 모두 초록입니다(17분 19초, 가지 머리 `49d8c22`). 윈도 칸에서 진짜 컴파일 시험이 처음 돌아 'Inno 6.7.1 으로 컴파일'(설치 파일 2,142,558바이트·2,142,576바이트) 안내가 두 번 보입니다.
