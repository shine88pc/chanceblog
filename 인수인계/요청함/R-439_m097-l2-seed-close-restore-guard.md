# 병합 요청 M097 — 편집 중 Seed 닫기 질문과 복원 중 저장 겹침 막기(앱 L2)

> **병합 방식**: 지금은 AI 병합 기능이 **꺼져 있어** 운영자께서 직접 병합해 주세요. (`M097 승인` 이라고 답하셔도 아직 AI 가 병합하지 않습니다.) 이 요청은 앱 저장소 `chanceblog-desktop` 의 것이고, PR 제목 맨 앞이 `[M097]` 인 것 하나만 병합합니다. 검사는 이미 끝나 초록입니다. 급하지 않습니다(보통).

## 1. 무엇을 바꾸는지
① **편집 중 닫기 질문(F025)**: 앱을 닫을 때 입력이 있는 화면 가운데 Seed 관리만 묻지 않아 쓰던 입력이 소리 없이 사라졌습니다. 이제 Seed 관리의 고친 칸·'Seed 등록' 폼에 저장 안 한 입력이 있으면 닫기 전에 `저장 안 하고 닫기`/`계속 고치기` 두 갈래로 묻습니다(초안·블로그 확인이 먼저 있으면 이어서 Seed 확인이 뜸). 처음 포커스와 Esc 는 안전한 쪽(계속 고치기)입니다. ② **복원 중 저장 겹침(F030)**: 백업 복원이 보관함 파일을 바꾸는 동안 Seed·블로그 저장 등 쓰기를 시작하는 화면 길 열한 가지가 겹쳐 시작될 수 있었습니다 — 복원이 도는 동안은 화면 층에서 시작을 거절하고 한 줄 안내를 보입니다(입력은 남아 복원 뒤 다시 저장). ③ 같은 묶음에서 확인창을 취소하면 서랍 안 Tab 가둠이 풀려 키보드 포커스가 서랍 밖으로 새던 것을 한 줄로 막았습니다.

## 2. 왜 필요한지
운영자 방침(세부는 추천안으로 진행하고 알리기만 함)으로 진행하는 안전 묶음(L2)입니다. 입력이 소리 없이 사라지는 곳이 하나 남아 있었고, 복원과 저장이 같은 순간 겹치면(시작점에서 같은 코드로 재현) 복원 중 저장이 'started' 로 끼어들 수 있었습니다.

## 3. 사용자가 체감하는 변화
Seed 관리에서 입력을 고치다 앱을 닫으면 질문이 한 번 뜹니다(안전한 쪽이 기본). 백업을 복원하는 동안 다른 저장 단추를 누르면 '복원이 끝난 뒤에 다시 눌러 주세요' 한 줄 안내가 나옵니다. 큰 창·작은 창·150% 배율 흉내에서 확인창과 안내가 잘리지 않음을 검증자가 확인했습니다.

## 4. 위험과 기존 기능에 미치는 영향
- **기존 기능**: 저장 형식·서비스 쓰기·백업 형식·설정·네트워크는 안 바뀌었습니다(화면 규칙과 앱 틀만). 바뀐 기존 시험은 없습니다. 기존 Qt A–D조 462개는 검증자가 직접 돌려 통과했고, 서랍을 다루는 모듈은 한 줄 고침 뒤에도 통과를 확인했습니다. Qt 시험은 GitHub 윈도 러너(PySide6 포함)에서도 따로 돌려 네 조각 모두 통과했습니다(이 묶음 단독 머리와, 앞서 병합된 L3 뒤의 main 위에 합친 이 병합 가지 둘 다).
- **알려 둔 한계**: Seed 확인창은 `저장하고 닫기` 없이 두 갈래입니다(저장은 열린 씨앗 하나 단위라 여러 입력을 이어 저장하는 새 흐름이 필요 — 지시서의 세 갈래에서 이탈, 두 검증자 모두 '안전 쪽·타당' 의견). 서비스 층 잠금 통일은 안 했습니다(복원 직후의 낡은 판은 기존 '낡은 판' 규칙이 거절하고, 앱 밖 프로그램의 동시 쓰기는 열려 있음). 블로그 닫기 질문의 기존 구멍(읽기 오류 화면·쓰는 중이면 안 묻는 경우)과 질문 단추 낱말·모양 통일은 후속입니다.
- **운영자께 여쭐 것(급하지 않음, 이번 병합과 별개)**: ① Seed 닫기 질문에 `저장하고 닫기` 를 원하십니까? **추천: 지금은 두 갈래 유지**(원하시면 '고친 씨앗 하나이고 새 폼이 비어 있을 때만' 으로 좁혀 따로 요청) ② 복원이 `seeds.lock`·`blog-profiles.lock` 도 서비스 층에서 잡게 할까요? **추천: 지금은 안 함**(화면 층 막기는 시작만 미루고 파일을 쓰지 않으며 서비스 쓰기·잠금 통일은 T3 판단).

## 5. 시험·독립 검증 결과
- 새 시험 61개(순수 32·Qt 29): 고치기 전 코드에서 빨강(1차: 순수 28개 중 26·Qt 17개 중 14)이고 구현자 변이 58개가 모두 잡혔습니다.
- 독립 검증(구현자와 다른 AI 둘이 안전·시험 두 관점으로): 1차 판정의 필수(안전: 닫기 질문의 '쓰는 중' 규칙과 닫기 연쇄의 시험 틈, 시험: 서랍 Tab 이 새는 것)를 모두 고친 뒤 변경분 재확인 **둘 다 pass(필수 0)**.
- 검사(CI) 앱 12칸 초록. 앱 검사에는 PySide6 가 없어 Qt 시험은 건너뛰므로, Qt 시험은 GitHub 윈도 러너에서 따로 돌렸고(합친 병합 가지 네 조각 통과) 검증자도 로컬에서 직접 돌렸습니다.
- 합친 방식: 앞서 병합된 L3 와 같은 문서 두 곳(`UI_STATES`·`UI_COMPONENTS`)에 절을 더한 것이 겹쳐 두 쪽 절을 모두 남겼습니다(내용 손실 없음, 코드는 겹침 없음).
