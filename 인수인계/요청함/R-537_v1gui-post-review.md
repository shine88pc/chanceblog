# 병합 요청 M131 — 글 검토 화면 1a (앱, T2)

> **병합 방식**: 지금은 AI 병합 기능이 **꺼져 있어** 운영자께서 직접 병합해 주세요. (`M131 승인` 이라고 답하셔도 아직 AI 가 병합하지 않습니다.) 이 요청은 앱 저장소 `chanceblog-desktop` 의 것이고, PR 제목 맨 앞이 `[M131]` 인 것 하나만 병합합니다. 검사는 이미 끝나 초록입니다. 급하지 않습니다(보통).

## 1. 무엇을 바꾸는지
앱 v1.0 의 글 흐름 첫 단계입니다 — 운영자가 가져온 글을 앱 안에서 읽고, 발행 전 검사 결과와 미리보기를 보고, **승인 상태로 바꾸는** 화면입니다. **승인은 상태 전이일 뿐 게시가 아닙니다. 외부 쓰기 스위치는 모두 꺼져 있고 새 외부 접속·하위 프로세스는 0 이며 `service/`·`security/`·`.github/`·`vendor/`·의존성·`capabilities.py` 는 0줄입니다.**
① **순수 층 `ui/core/`**(`posts`·`post_rules`·`post_text`·`post_fake`·`posts_view`)과 **서비스 어댑터 `ui/posts_adapter.py`**(화면이 글 서비스를 부르는 한 곳 — 읽기 넷·쓰기 다섯 함수뿐).
② **Qt 화면 `ui/qt/`**(`post_parts`·`post_screen`·`post_flow`)와 새 메뉴 '글 검토'(사이드바 일곱 번째)·기존 파일의 작은 연결.
③ **미리보기의 개인 키 가리기**: 개인 키 블록(PEM·PGP)은 머리부터 꼬리까지 가리기 엔진에 물어 한 덩어리로 가립니다(눈에 안 보이는 글자·긴 라벨·변환기가 머리를 버리는 모양까지 엔진 판정을 따름). Pages 값 기억은 가리기 엔진이 가리는 모든 모양을 기억하지 않습니다.
④ **사이드바 간격**: 묶음 이름 아래 여백을 2px → 0 으로 줄였습니다(합 8px, 사이드바 최소 높이 496 → 488 — 메뉴 하나가 늘어도 최소 창 안에 들게 하려는 것, D-637·D-638).
⑤ 시험 새 모듈 넷(`test_ui_posts_core`·`test_ui_posts_adapter`·`test_ui_posts_matrix`·`test_ui_qt_posts`)과 바뀐 기존 시험 열세 파일(메뉴 개수·Tab 정거장 같은 의도적 갱신, 강화만).
⑥ 문서: `docs/UI_POST_FLOW.md`(새)·결정 D-620–D-641·TROUBLESHOOTING 17절·README·CHANGELOG·ARCHITECTURE 문장·결정 색인(다시 만든 생성물).

## 2. 왜 필요한지
글을 올리기 전에 '무엇이 올라갈지·막힌 이유가 무엇인지' 를 앱 안에서 보고 승인 상태로 바꾸는 단계가 없으면 이후 단계(공개 확인·갱신·Blogger 연결)를 켤 수 없습니다. 이 화면은 읽기·승인 상태 전이만 하며 게시는 하지 않습니다.

## 3. 사용자가 체감하는 변화
**있습니다.** ① 왼쪽 메뉴에 **'글 검토'** 가 하나 늘어(일곱 번째) 가져온 글을 읽고 검사 결과를 보고 승인 상태로 바꿀 수 있습니다(승인해도 게시되지 않습니다). ② **사이드바의 묶음 이름 아래 여백이 줄어** 모든 화면의 왼쪽 메뉴가 8px 촘촘해집니다 — **운영자 PC(윈도 125·150%)에서 한 번 봐 주세요.**

## 4. 위험과 알려 둔 한계
- 윈도 125·150% 렌더·한글 입력기·화면 읽기 프로그램은 오프스크린으로만 확인했습니다(운영자 PC 확인 필요 — 사이드바 보이는 변화 포함).
- 사이드바 높이 여유가 경보까지 4px(경보 492·한도 500)입니다 — 다음 갈래가 메뉴를 하나 더하면(약 44px) 접기·스크롤 같은 구조 변경이 필요합니다.
- 소스 규칙 시험(화면이 서비스를 어떻게 부르는지)은 **시험 코드일 뿐 실행 시 방어가 아닙니다**(이름 조립·다른 쓰기 도구는 못 잡음 — 한계를 문서에 적음). 실제 방어는 거절 실행기·로컬 전용 백엔드·꺼진 스위치·서비스의 승인 순간 재검사입니다.
- 엔진 자체가 못 알아보는 머리(전각·키릴 동형 문자·소문자)는 미리보기도 가리지 못합니다. **추가로 시험 렌즈가 찾은 앱 전체 한계: 키·토큰 모양이 줄 구분 글자(U+2028·U+2029·U+0085)로 쪼개지면 가져오기 검사와 가리기 엔진이 모두 못 알아봅니다** — 이 갈래의 범위 밖이라 **별도 보안 강화 갈래로 제안합니다**(서비스·`security/` 파일 수정, 외부 쓰기가 꺼져 있는 지금은 이 PC 화면에만 보임).
- 건강 효과 판정은 제목·본문에만 걸립니다(Pages 한 줄 설명·태그는 다음 갈래). 네이버 프로필 저장 위치 틈(블로그 관리 화면과 서비스가 다른 파일에 씀)은 안내만 합니다. 글 고치기·지우기는 다음 갈래입니다.
- 키 블록 5,000벌짜리 극단 글은 미리보기 만들기가 0.49초 → 3.1초로 느려졌습니다(보통 글은 같음).
- 앱 검사(CI)는 PySide6 가 없어 화면(Qt) 시험을 건너뜁니다 — 이 갈래의 Qt 시험은 PySide6 있는 3.12 오프스크린에서 직접 돌려 통과를 확인했습니다.
- **운영자께 여쭐 것(급하지 않음, 이번 병합과 별개)**: ① 사이드바 간격 제거(8px)를 받아들이실지 — **추천: 받아들이고 운영자 PC 에서 확인** ② Pages 값 대화(닫을 때 확인 줄 대신 이 앱을 연 동안 기억) — **추천: 그대로** ③ 다음 갈래 우선순위(글 고치기·지우기 vs 네이버 복사·발행 기록) — **추천: 글 고치기·지우기 먼저** ④ 네이버 프로필 저장 위치를 어느 쪽으로 합칠지 — **추천: 다음 갈래에서 서비스 쪽으로**.
