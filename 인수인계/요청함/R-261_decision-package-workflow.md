# 확인 요청 — 시험용 Package 빌드 워크플로 한 파일(T3, `.github` 변경)

> 이 글은 **질문**입니다. 어느 문장도 승인이 아니며, 텔레그램에서 번호에 맞춰 `대상번호/1/` 처럼 **직접 답하셔야** 승인입니다. 답이 없으면 보류(2번)로 두고 아무것도 바꾸지 않습니다.

**한눈에**
- 회사 PC 에서는 파일을 가져올 수 없으므로, 앱을 개인 PC 로 옮기려면 **GitHub 가 Windows 에서 압축 파일을 만들고 개인 PC 브라우저로 내려받는 길**이 필요합니다. 그 길을 여는 워크플로 파일 **한 개**(`.github/workflows/package.yml`, 데스크톱 저장소)입니다.
- 사람이 Actions 화면에서 `Run workflow` 를 누를 때만 돌아갑니다. 푸시·PR·예약으로는 돌지 않고, 입력칸도 비밀 값도 없습니다.
- 독립 검증을 통과했습니다(높음·중간 문제 0). 쓰는 외부 액션 세 개의 고정값(전체 커밋 번호)이 **공식 저장소의 릴리스 표시와 일치**함을 제가 직접 확인했습니다.
- 승인하셔도 **바로 병합되지는 않습니다.** 앱 보안 수정·초안 저장·백업이 병합된 뒤 이 파일 한 개만 든 병합 부탁을 따로 드립니다.

## 1. 무엇을 하는 파일인가
- Actions 화면에서 `Run workflow` 를 눌렀을 때만, GitHub 의 Windows 러너에서 앱 압축 파일(개인 PC 제한 시험용, **미서명**)을 만듭니다.
- 순서: 잠금 파일의 도구를 정확한 버전으로 설치 → 빌드(작업 트리가 깨끗한지·도구 버전이 같은지·자가 점검·외부 쓰기 잠금 확인 중 **하나라도 틀리면 실패하고 아무것도 올리지 않습니다**) → 압축 파일·SHA256SUMS·PACKAGE_INFO 둘, **네 가지만** 14일간 내려받을 수 있게 올림.
- 실행 기록에 압축 파일의 SHA-256 이 찍혀 개인 PC 에서 대조할 수 있습니다.

## 2. 하지 않는 일
- 비밀 값·토큰 사용 0(권한은 읽기 하나), 서명 없음, 릴리스·게시·외부 서비스 쓰기 없음, 로그·데이터 업로드 없음, 입력칸 없음, 예약·푸시·PR 로 자동 실행 없음.

## 3. 독립 검증 결과
- **1차 검증은 '보류'** 였습니다(빌드가 만든 PC 의 설정에 따라 압축 파일이 달라지는 문제 등). 모두 고친 뒤 **델타 검증에서 '통과'** 했습니다 — 같은 입력이면 PATH 가 다른 두 방식으로 빌드해도 같은 압축 파일이 나옵니다(SHA-256 일치).
- 워크플로 초안 검토: 수동 실행만·입력칸 없음·읽기 권한 하나·비밀 0·서명 단계 없음·올리는 파일 네 개·보존 14일·실패하면 올리지 않음(`if-no-files-found: error`)·앱 보안 수정 쪽의 '워크플로 산출물 규칙 시험' 17개와 충돌 없음.
- **액션 고정값 대조(제가 11-11 저녁에 공개 저장소의 태그를 직접 조회)**: `checkout` v4.4.0 · `setup-python` v5.6.0 · `upload-artifact` v4.6.2 — 세 고정값이 모두 공식 저장소의 그 릴리스 표시와 정확히 일치했고, 앞의 둘은 이미 병합된 `ci.yml` 의 고정값과도 같습니다.
- **첫 실행의 위험**: 새 안전 검사(묶음에 들어가는 DLL 이 어디서 왔는지 확인)가 GitHub 러너의 환경 때문에 거절할 수 있습니다. 그러면 실행이 빨갛게 끝나고 **아무것도 올라가지 않으며**, 거절 문장이 어느 파일인지 알려 줍니다 — 그때 제가 고쳐서 다시 올립니다.

## 4. 승인하시기 전에 알아 두실 점
1. **공개 저장소라 올린 파일을 14일 동안 GitHub 에 로그인한 누구나 내려받을 수 있습니다.** 비밀 값은 들어 있지 않고 '개인 PC 제한 시험용, 미서명 Package — 공개 배포용이 아닙니다' 표시가 맨 위에 있습니다.
2. **서명이 없어** 개인 PC 에서 SmartScreen 경고가 뜹니다(시험지에 '추가 정보 → 실행' 안내가 있습니다). 개인 PC 에 '스마트 앱 컨트롤' 이 켜져 있으면 미서명 앱 실행이 막힐 수 있습니다 — **그 보안 설정을 바꾸는 일은 권하지 않으며 제가 대신할 수도 없습니다.** 막히면 알려 주세요(서명 방법은 따로 의논합니다).
3. 지금 이 PC 에서 만든 시험 빌드는 외부 쓰기 잠금이 아직 병합 전이라 **`TESTBUILD` 로 표시되며 개인 PC 로 보내지 않습니다.** 개인 PC 용 최종 Package 는 앱 보안 수정·초안 저장·백업 화면이 병합된 **뒤에** 이 워크플로로 만듭니다(그 전에는 만들지 않습니다).
4. 독립 검증이 남긴 낮은 지적 셋(출력 폴더 이름 끝 공백 처리·깨끗함 검사의 숨은 변경·시험지에 둘째 계정 만들기에 관리자 권한이 필요하다는 안내 추가)은 최종 빌드 전에 고칩니다.

## 5. 선택
- **1 = 승인**: 이 파일 한 개만 든 병합 부탁(`[M###]`)을 앱 보안 수정 등이 병합된 뒤 따로 드립니다. 병합 뒤 Actions 에서 한 번 실행해 최종 Package 를 만들고 개인 PC 시험지 순서로 안내합니다.
- **2 = 보류**(기본값): 이 워크플로 없이 갑니다. 이 경우 개인 PC 로 앱을 옮기는 다른 길(예: 개인 PC 에서 직접 소스를 설치해 실행 — 파이썬 설치가 필요해 어렵습니다)을 따로 의논해야 하고 개인 PC 시험은 그만큼 늦어집니다.
