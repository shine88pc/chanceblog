# R-024 · 티스토리·네이버 연결 — 계획과 진행 (이슈 #81 답)

## 한 줄
글을 올려 주는 '기계'는 이미 있고(2026-10-27 병합), 빠진 것은 **블로그 주소 두 개와 켜기 승인**입니다. 아래 [답하기] 한 번이면 제가 프로필·프롬프트·등록을 만들고, 23시 전에 병합 부탁(R-025)까지 보냅니다. **23시 전에 답이 없으면** 준비물을 저장소에 남겨 다음 세션이 이어받습니다.

## 먼저 알아 둘 것 — '자동 업로드'가 안 되는 이유
- 티스토리는 공식 글쓰기 API 가 2024-02 에 종료됐고, 네이버도 2020 년에 종료됐습니다.
- 로그인·세션을 흉내 내는 자동화는 계정 보안·약관 위험이 커서 **만들지 않기로 2026-10-27 에 승인(D4)된 방식**입니다(두 사이트의 계정 정보는 저장·처리하지 않습니다).
- 그래서 **반자동**입니다: 하루 1편, AI 가 글을 완성해 **GitHub 이슈 1개(초안 패키지)** 로 보여 줍니다 → 이슈의 복사 상자(제목·본문·태그)를 복사해 블로그에 붙여 발행(2~3분) → 이슈를 닫습니다.

## 진행 상황 (지금)
| 부품 | 상태 |
|---|---|
| 초안 패키지 기계(코드·워크플로 `[티스토리] 초안 패키지 만들기`·`[네이버] 초안 패키지 만들기`·시험) | **완성·병합됨**(2026-10-27). 대상 블로그가 없어 정기 실행은 '대상 0개'로 초록 |
| 블로그 항목(주소·주제)·프로필(주제 가드레일·AI 고지)·프롬프트 | **없음 — 주소·주제 입력 대기** |
| 첫 실제 초안 이슈의 복사·붙여넣기 확인, 비공개 시험 글 | 켠 뒤 운영자 확인 몫 |

## 계획 (오늘 23시 전)
1. **지금**: 이 요청에 답(주소 두 개 + 기본 주제 승인 + 켜기 승인).
2. **답을 받으면 약 60~90분**: 프로필·프롬프트·블로그 항목·시험 → 독립 검증 → **병합 부탁 R-025**(운영자가 병합).
3. **병합 뒤**: 티스토리 매일 14:20·네이버 15:20(KST) 정기 실행이 첫 초안 이슈를 만듭니다(GitHub 가 늦출 수 있습니다). 운영자는 **비공개 시험 글 1건**으로 태그·서식·이미지 업로드(회사 PC 에서 되는지)를 확인한 뒤 복사해 발행합니다.
4. **23시까지 못 끝나면**: 준비물 브랜치와 남은 단계를 `인수인계/작업내용.md` 에 적어 다음 세션이 이어받습니다.

## 승인 항목 (아래 번호 항목에만 승인이 유효합니다)
1. 티스토리 블로그 **주소**(`이름.tistory.com`) — 아직 없으면 선택 C(네이버만).
2. 네이버 블로그 **주소**(`blog.naver.com/아이디`) — 아직 없으면 선택 B(티스토리만).
3. 두 블로그의 **주제·어조**를 아래 기본값으로 쓰기(T3: 정책·톤).
4. `pipeline/blogs.json` 에 두 블로그 항목을 더하고 `mode: package` 로 켜기(T3: 새 블로그). 이 모드는 **공개하지 않고** 이슈 초안만 만듭니다.
5. `_config.yml` 의 `exclude` 에 두 블로그의 이력 파일 이름을 더하기(T3: 광고 표면 파일 — 안 더하면 이력 파일이 사이트에 그대로 공개됩니다). 승인 표시와 함께 한 커밋으로 들어갑니다.
6. 광고(애드센스·애드포스트)는 켜지 않습니다 — 품질 게이트를 통과하기 전까지.

## 알아 둘 점
- 이 저장소는 공개라서 **초안 이슈도 공개 화면**에 보입니다 — 블로그에 올리기 전에 같은 글이 먼저 보일 수 있습니다(2026-10-27 승인된 D4 와 같은 수준).
- 하루 상한 1편이고, 같은 채널에 열린 초안 이슈가 3건 이상이면 새로 만들지 않습니다(쌓이면 알려 줍니다).
- 무료 AI 호출 한도: 글 1편에 호출 2~3회(추정) → 하루 +4~6회. 구현 때 기존 사용량과 합쳐 확인합니다.
- 켜도 블로그에는 아무 일도 일어나지 않습니다 — 발행은 운영자가 복사해 직접 합니다.
