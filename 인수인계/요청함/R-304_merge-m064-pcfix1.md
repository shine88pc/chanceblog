# [M064] 병합 부탁 — 시험용 Package 빌드 실패 수정 (PCFIX1)

> **검사는 이미 끝났습니다 — PR 을 열어서 병합하셔도 됩니다.** 가지를 올린 때 데스크톱 저장소의 검사(Windows·Ubuntu × 파이썬 3.10·3.12 시험)가 돌아 초록으로 끝났습니다. **이 병합 부탁은 데스크톱 프로그램 저장소 `chanceblog-desktop` 의 것입니다**(블로그 저장소가 아닙니다).

> **[M064] 시험용 Package 빌드가 GitHub 러너에서 실패한 것 고치기(PCFIX1) — 빌드가 PyInstaller 를 부를 때 PATH 를 좁히고 묶음 점검 실패 문구에 건수·출처 폴더 요약 추가 — 허용 폴더 규칙은 그대로, 워크플로 변경 없음**

## 이번 묶음이 하는 일
- **무슨 일이 있었나**: 운영자께서 'Package — 개인 PC 제한 시험용 빌드(수동)' 를 처음 돌렸을 때 `[3/8]` 직후 '묶음 점검에서 문제가 나왔어요' 로 멈췄습니다(확인 011 에 붙여 주신 로그). GitHub 실행 PC 의 PATH 에서 자바 폴더가 Windows 폴더보다 앞이라, 묶음 도구(PyInstaller)가 그 폴더의 DLL 을 모았고, 묶음 점검이 '가상환경·기본 Python·Windows 폴더 밖 DLL 은 거절' 규칙대로 막았습니다. **점검은 설계대로 일했고 묶음은 만들어지지 않았습니다**(로그인과 무관, 키·개인 데이터 유출 없음).
- **고친 것**: 빌드가 묶음 도구를 부를 때 PATH 를 결정적으로 좁힙니다(가상환경·기본 Python·Windows 폴더만). 다른 프로그램 폴더의 DLL 이 끼어들 길이 닫힙니다. 실패 문구에는 총 건수와 출처 폴더별 요약이 더해져 같은 실패가 다시 나도 한 번에 원인을 알 수 있습니다. 정보 파일에 'PATH 정책' 한 줄이 기록됩니다.
- **하지 않은 것**: 허용 폴더 규칙은 한 줄도 완화하지 않았습니다. 빌드 워크플로 파일은 건드리지 않았습니다.

## 눈에 보이는 변화
- **앱 화면·사용에는 변화가 없습니다.** 바뀌는 것은 Package 를 만드는 도구의 PATH 처리와 실패 문구뿐입니다.

## 솔직한 한계
- **러너에서는 아직 한 번도 돌려 보지 못했습니다.** 이 PC 에서 러너와 비슷한 상황(가짜 자바 폴더·가짜 Windows Kits 폴더가 PATH 맨 앞, 가상환경 없는 파이썬)을 만들어 같은 실패를 재현하고 고친 뒤 통과하는 것을 확인했지만, `[4/8]` 이후(정보 파일·자가 점검·압축·검사)는 러너에서 처음 도는 것이라 다른 문제가 나올 수 있습니다.
- 첫 로그가 앞 여섯 건만 보여 주었으므로 그 너머의 문제가 더 있었는지는 모릅니다(이제는 새 문구가 한 번에 알려 줍니다).
- 러너에서 PyInstaller 자체가 다른 이유로 실패하면 `build.log` 는 올라가지 않아 원인을 볼 수 없습니다(워크플로를 바꿔야 해서 이번 범위가 아닙니다 — 필요해지면 운영자 승인을 따로 받아 제안합니다).
