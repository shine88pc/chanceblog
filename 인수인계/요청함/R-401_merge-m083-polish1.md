# 병합 요청 M083 — 후속 정리 묶음(블로그 관리·사진 넣어 글쓰기 독립 검증이 남긴 작은 일 열두 가지)

> **병합 방식**: 지금은 AI 병합 기능이 **꺼져 있어** 운영자께서 직접 병합해 주세요. (`M083 승인` 이라고 답하셔도 아직 AI 가 병합하지 않습니다.) 이 요청은 앱 저장소 `chanceblog-desktop` 의 것이고, PR 제목 맨 앞이 `[M083]` 인 것 하나만 병합합니다. 검사는 이미 끝나 초록입니다. 앞선 `[M082]`(사진 3단계)가 병합된 main 위에서 만든 것이라 순서는 이미 맞습니다. 급하지 않습니다(보통).

## 1. 무엇을 바꾸는지
- **긴 별명 칩(주 화면)**: 후보·Seed·초안 작성 화면의 채널 칩·요약·거르기는 이름이 **스무 자를 넘으면 `…` 로 줄고** 전체 이름은 마우스를 올리거나 화면 읽기 프로그램이 읽을 때 나옵니다(서랍은 열두 자 그대로). 같은 서른 자 별명 둘이어도 좁은 창(900×560·배율 150%)에서 가로 스크롤이 생기지 않습니다.
- **글 읽기 편하게**: 이름 끝 번호와 개수가 붙어 읽기 어렵던 곳을 `네이버 블로그 1 · 6`·`이름 · 3개`·`이름: 3개` 꼴로, Seed 가져오기 확인창의 채널 줄은 카드 순서로, 한 자리뿐인 종류(GitHub Pages)는 `전체 (GitHub Pages)` 처럼 번호 없이 가릅니다. 칩 곁의 고정 글과 겹치는 별명을 가르는 목록에 Seed 요약의 상태 낱말(`사용 중`·`쉬는 중`·`승인 전`)을 문구 표에서 읽어 더했습니다.
- **글 검색 칸**: Seed·후보의 글 검색 칸에 한글을 치는 동안 늦게 끝난 이름 읽기가 화면을 다시 그려 **조합이 끊기던 것**을 막았습니다(입력 보호 범위에 검색 칸 추가).
- **사진 정리**: 종류를 고르면 '자리 정하기' 가 **저절로 펼쳐져 줄이 749px 가 되던 것**을, 종류가 정한 기본값은 한 줄 요약(`들어갈 곳: 도입 ▸`, 542px)으로 접어 두고 사용자가 직접 고른 값·설명 글이 있을 때만 펼치도록 고쳤습니다.
- **글 모양 점검**: 닫는 중괄호가 하나 더 붙은 `{{사진 1}}}` 를 통과시키던 틈(M082 의 정확한 사진 자리 예외가 만든 틈)을 막았고, 문장 끝 정규식의 제곱 시간(마침표 2만 개와 글자 하나에 약 9초)을 글자 수에 비례하게(몇 밀리초) 바꿨습니다 — 찾는 결과는 옛 정규식과 같음을 무작위 글로 견줬습니다.
- **작은 글·색**: 경고 문구에서 이유 문장이 물음 앞에 오고, 저장 알림이 `초안을 저장했어요 · 사진 정보는 저장하지 않았어요` 로 구분되며, 저장 안내 토스트에 기존 상태색 토큰의 줄이 생깁니다(새 색 없음).
- **열린 확인창 바꿔 열기**: 열린 확인창을 닫지 않고 다른 확인창으로 바꾸면 새 확인창이 **44px 로 접혀 글이 안 보이던 옛 문제**를 고쳤습니다(바꿔 열 때만 다음 이벤트 차례에 틀을 한 번 더 놓음).

## 2. 왜 필요한지
블로그 관리 후속(M080)과 사진 넣어 글쓰기(M081·M082)를 병합한 뒤 독립 검증자들이 '병합을 막지는 않지만 고칠 만하다' 고 남긴 작은 일들입니다. 운영자님의 방침(세부는 추천안으로 진행하고 알리기만)에 따라 한 묶음으로 모아 고쳤고, 저장 형식·서비스 쓰기·백업·설정·`.github`·`vendor`·의존성·외부 접속은 건드리지 않았습니다.

## 3. 사용자가 체감하는 변화
별명이 아주 긴 블로그가 있어도 후보·Seed 화면이 좁은 창에서 옆으로 밀리지 않고, 글 검색 칸에 한글을 칠 때 글자가 끊기지 않으며, 사진 정리에서 종류를 고를 때 줄이 갑자기 길어지지 않습니다. 확인창을 바꿔 열 때 글이 사라지던 일이 없어집니다. 그 밖의 평소 화면은 같습니다 — 사진 없는 글의 초안 만들기·저장·복사 흐름 77줄과 본문 생성기 1,092 조합이 main 과 같음을 검증자가 직접 비교했고, 앱의 확인창 40장면이 main 과 그림 지문·Tab 순서·처음 포커스까지 같음을 확인했습니다.

## 4. 위험과 기존 기능에 미치는 영향
- **기존 기능**: `.github`·`vendor`·의존성·**저장 형식·서비스 쓰기·백업**·설정 칸·오류 표는 한 줄도 바꾸지 않았습니다(변경 38개 파일 — src 21·시험 11(새 3)·문서 5·CHANGELOG 1, +1,289/−91). 바뀐 코드는 화면 글·화면 규칙(`ui/core`·`ui/qt`)과 순수 규칙 둘(`check/garbage.py`·`content/photo_flow.py`)뿐입니다.
- **솔직하게 알려 드릴 점**
  - ① **확인창 변경은 앱의 모든 확인창**에 닿는 코드(`Dialog.present` 의 바꿔 열기)입니다. 평소 글·평소 창 크기의 확인창 40장면을 main 과 같은 조건으로 견줘 모두 같음을 확인했고(바뀐 것은 바꿔 연 두 장면의 높이 44px → 322px 뿐), 새로 여는 확인창은 그대로입니다.
  - ② 칩 한도 스무 자는 추천안입니다. 주 화면의 다른 곳(카드 아래 이름·상세 줄)은 전체 이름 그대로라 같은 블로그가 칩과 카드에서 다르게 읽힐 수 있습니다(툴팁·화면 읽기 이름에 전체 이름이 있습니다).
  - ③ 줄인 칩의 전체 이름 툴팁은 Qt 가 `<b>…</b>` 같은 별명 글을 서식으로 읽을 수 있습니다(서랍 툴팁과 같은 옛 방식, 표시 전용).
  - ④ '사용자가 직접 고른 들어갈 곳' 은 그 종류의 기본값과 다른 값으로 가르므로, 기본값과 같은 값을 일부러 고른 줄은 다시 만들어질 때 접힌 한 줄 요약으로 보입니다.
  - ⑤ 같은 모양의 제곱 시간 정규식이 `render/naver.py` 에 남아 있고(main 에도 있음) 확인창이 같은 이벤트 차례에 지워질 때 앱을 닫는 순간의 예외 한 가지가 남아 있습니다 — 후속 묶음 후보입니다.
  - ⑥ **화면 확인의 한계**: Qt 화면은 이 PC 에서 오프스크린으로만 확인했습니다. 저장소 CI 에는 PySide6 가 없어 Qt 시험(새 21개 포함)은 건너뛰며 이 PC 와 운영자 PC 에서만 돕니다. **실제 윈도 125%·150% 렌더·한글 입력기·화면 읽기 프로그램·진짜 마우스 툴팁·토스트 안내 줄(4px)이 눈에 띄는지는 운영자 PC 에서 확인해야 합니다.**
