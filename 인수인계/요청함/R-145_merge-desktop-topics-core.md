## 왜 필요한가 (쉬운 설명)
운영자님이 R-131 답에서 승인하신 '5채널 주제 선정 전략'을 프로그램에 얹는 2번째 단계입니다. 화면·초안 만들기와 **떨어진 순수 계산 부품**으로 먼저 만들어 두면, 다음 단계(후보 만들기·저장·화면)가 이 위에 안전하게 쌓입니다. 이 부품이 하는 일: 채널 5개의 프로필(가중치·비율·상한)을 읽고, 후보 하나를 6가지 항목(채널 적합도·작성 가능성·차별성·시기·근거·수익화)으로 점수 내고, 점수를 구간(우선 추천 80+·일반 65~79·보류 50~64·제외)으로 나누고, 채널마다 상위 5개(같은 묶음 최대 2개)를 고릅니다. 데이터가 없는 항목은 0점이 아니라 **빼고 다시 나눕니다**('모름 ≠ 0').

R-131 에서 정하신 조건이 코드에 들어간 곳: 관심도(상대값 `trend_ratio` 등)와 실제 검색 횟수(`search_demand_count`, 출처 필수)를 **다른 칸**으로 분리하고 관심도 서비스를 횟수의 출처로 적으면 거절합니다 / 작업 상태(`work_status`)와 추천 구간(`recommendation_band`)을 **두 축**으로 분리 / 후보 연결·점수·출처 스냅샷(`CandidateLink`·`Provenance`) / 후보 생성은 네이버 A·B 만 켜짐(`generation_enabled`), 이력 읽기는 5채널 모두(`history_enabled`) / 사용자 데이터 파일 이름 네 개(`channel_profiles.json`·`seeds.json`·`calendar.json`·`topic_engine.db`)는 이름만 정함.
