## 무엇이 바뀌나 (쉬운 설명)
운영자님이 11월 3일 r085 에서 승인하신 **'Unsplash 규칙 지키기(A안)'** 의 수정안입니다. Unsplash 의 공식 규칙은 ① 사진 주소의 `ixid` 값을 크기를 바꿔 쓸 때도 남기고 ② 사진을 보여 줄 때 작가와 Unsplash 를 밝히며 프로필 링크를 걸고(링크에는 `utm_source` 표시) ③ 사진을 쓰기로 했을 때 사용 알림을 보내라는 것입니다. Blogger 쪽은 ②③을 이미 하고 있었고, **Chance 글(`generator.py`)은 ①②가 빠져 있었습니다.**

1. **Chance 새 글에 출처 한 줄**: 사진 바로 아래에 `Photo by 작가 on Unsplash` 한 줄(작가 프로필·Unsplash 링크에 `utm_source=chanceblog`)이 들어갑니다. 한국어·영어 글 모두 같은 영어 문구입니다. 작가 이름은 바깥(Unsplash)에서 오는 글이라 보이지 않는 글자·줄바꿈·마크다운 기호를 정리해 넣고, 길이도 80자로 제한합니다. **작가 출처를 알 수 없는 사진은 새 글에 쓰지 않습니다.**
2. **`ixid` 유지**: Chance·Blogger 모두 Unsplash 가 준 `ixid` 를 사진 주소에 남깁니다(올바른 모양일 때만, 아니면 지금처럼 빼고 글은 그대로 올라갑니다).
3. **사진을 바꾸는 두 경로**(생성기의 이미지 교체·이슈로 접수한 수정 요청)도 옛 출처 줄을 지우고 새 줄을 넣습니다.
4. **키가 엉뚱한 곳으로 가지 않게**(독립 검증이 짚어 고친 것): Unsplash 접속 키는 검색·사진 조회·사용 알림 요청 모두 '다른 주소로 안내되어도 따라가지 않는' 방식으로만 싣고, 사용 알림 주소는 `api.unsplash.com` 의 정해진 모양만 받으며, 새 글에 쓸 사진 주소도 `images.unsplash.com` 의 정해진 모양만 받습니다. 고정 사진 목록 조회는 한 번에 6번까지만 합니다(데모 키의 시간당 50회 한도를 아끼려고).
5. **PR 자동 점검(범위 검사)**: 사진 교체 PR 에서 출처 줄이 바뀌었으면 '✅ 통과' 가 아니라 **'⚠️ 확인 필요'** 로 표시하고 이전→이후 줄을 보여 줍니다. 작가 이름은 바깥에서 온 글이라 자동으로 '진짜 작가 이름'이라고 증명할 수 없기 때문입니다.

## 알아 두실 동작 변화 (꼭 읽어 주세요)
- **Unsplash 키가 만료되거나 시간당 한도를 넘으면 새 Chance 글이 멈추고 빨강으로 끝납니다.** 전에는 출처 없는 예비 사진으로 조용히 올라갔는데, 출처 없는 사진을 새 글에 쓰지 않기로 해서 생기는 변화입니다. 글·이력·초안은 아무것도 만들어지지 않고(깨진 글이 올라가지 않습니다), 연습 실행은 영향이 없습니다.
- 다만 **그 시간대의 슬롯이 열려 있는 동안 정기 실행(매시 17분·47분)이 뉴스 수집과 글 생성(Gemini 호출)을 한 뒤 사진에서 멈추는 일을 되풀이**합니다(하루 최대 약 30번, Gemini 무료 한도를 같이 씁니다). 실행 요약에는 '사진 문제'라는 말이 없고 로그에만 있습니다. 재시도 간격을 늘릴지는 운영자님이 정하실 일로 남겼습니다(아래 결정 항목). 키 문제는 보통 시간당 한도라 한 시간 안에 풀립니다.

**바뀌지 않는 것:** 광고 관련 파일(`index.html`·레이아웃·`_config.yml`·개인정보·소개·연락처·`robots.txt`)·워크플로 파일·시크릿·블로그 설정(`blogs.json`)·이미 올라간 글(`_posts/`)·글 이력 구조·티스토리·네이버 초안 패키지 — 모두 그대로입니다.

## 확인한 것
- 독립 검증 2회(구현자와 다른 AI 가 새 복사본에서 가짜 응답으로 — 진짜 Unsplash·Jekyll 은 쓰지 않았습니다). 1차는 **'조건부 병합 가능'**(높음 0·중간 5·낮음 8)이었습니다 — 사진 교체 PR 점검이 이름 칸의 아무 평문을 ✅ 로 표시하던 것·접속 키가 검사 없는 주소로 갈 수 있고 옛 검색·알림 요청은 다른 주소로 안내돼도 키를 따라 보내던 것·새 글 사진 주소를 검사하지 않던 것·고정 사진 목록 조회가 최악 32번이던 것·키 문제 때 매 틱 재시도(문서의 한계)와 시험 공백 15곳 — 모두 고쳤습니다. 수정분을 같은 검증자가 새로 쓴 예문 216건·키 경로 30시나리오·무작위 시험 6,000회로 다시 확인해 **'병합 가능'** 이라고 판정했습니다(막았어야 할 악성 주소 92건은 모두 막히고 정상 모양 20건은 통과했으며, 키가 다른 주소로 따라가는 길은 0). 근거(검증자 직접 실행): 전체 시험 4,751개를 3.10·3.12 에서(실패 5개는 이 PC 에 bash 가 없어서 나는 `test_manual_run_defaults` 5개로 이번 변경 전에도 같습니다), 새로 짠 변이 46개 중 43개 잡힘(나머지는 같은 동작 2개와 낮은 시험 공백 1개), 지난 시험 공백 15곳 모두 해결, 바뀐 줄은 전부 실행. 최종 병합 트리(r090 병합 뒤 main 위)는 검증자가 합쳐 본 결과 충돌이 인수인계 현황 문서 한 곳뿐이었고 새 시험과 용어 사전·AI 문서 시험 436개가 3.10·3.12 모두 통과했습니다.

## 솔직한 한계 (병합을 막지 않음)
- **기존 글 52편과 홈페이지 기본 썸네일 4장·글 카드·모달 이미지에는 출처 표시가 없습니다**(이미 올라간 글은 이번에 고치지 않았고, 홈페이지는 광고 표면이라 손대지 않았습니다). 기존 글 52편 중 본문에 사진 줄이 있는 글은 40편(나머지 12편은 줄 자리 자체가 없습니다)입니다.
- **실제 Unsplash 와 실제 Jekyll 사이트 빌드는 이번에도 직접 못 돌렸습니다.** 가짜 응답으로만 시험했고, 출처 줄이 사진 아래 한 줄로 보이는지는 다른 마크다운 해석기로만 확인했습니다. `GET /photos/photo-<번호>`(고정 사진 목록 조회)가 실제로 되는지는 공식 문서에 근거가 없어 첫 실제 실행에서 확인해야 합니다 — 안 되면 검색 결과가 모자란 날에만 글이 멈춥니다(출처 없는 사진을 몰래 쓰지 않음).
- 남은 낮은 한계: 모델이 코드 블록 안에 사진 줄을 쓰면 그 뒤에도 출처 줄이 들어갑니다(드묾)·`ixid` 에 `+`·`/` 가 들어 있으면 조용히 빠집니다(글은 올라갑니다)·이름의 `$$` 는 이스케이프하지 않습니다(사이트에 수식 도구 없음).
- **두 번째 독립 검증이 새로 찾은 낮은 것 4건(병합을 막지 않아 병합 뒤 작은 후속 묶음으로 손봅니다)**: ① Unsplash 접속 키 끝에 줄바꿈이 딸려 있으면 사진 검색 오류 줄에 키가 그대로 찍힐 수 있습니다(이번 변경 전 코드부터 같은 동작 — 키를 저장소 비밀 값에 넣을 때 끝에 줄바꿈이 없게 해 주세요) ② 사진 주소만 바꾸고 옛 출처 줄을 그대로 둔 손으로 만든 PR 은 '직접 확인하세요' 안내가 붙은 통과로 나옵니다(우리 코드가 만드는 PR 은 줄도 같이 바꿉니다) ③ 시험 한 곳이 비현실적인 경우(한 글에 출처 줄이 둘 이상)만 못 잡습니다 ④ 설명 문서의 한 문장이 '처음 판'의 키 전달 방식을 이번 변경 탓처럼 적었는데 실제로는 이전 코드부터 있던 방식입니다.

## 결정하실 것 (기본값은 '지금 구현대로' — 바꾸고 싶으실 때만 알려 주세요)
1. 홈페이지 기본 썸네일 4장에 출처를 달지·단색 틀로 바꿀지·그대로 둘지(광고 표면이라 따로 요청드려야 해서 **그대로**).
2. 기존 글 52편에 출처·`ixid` 를 소급해 채울지(작가 조회 API 를 시간당 50회 한도 안에서 나눠 불러야 해서 **하지 않음**).
3. 키 문제로 새 글이 멈추는 변화와 매 틱 재시도(위 '알아 두실 동작 변화')를 **받아들일지**(기본: 받아들임. 불편하시면 재시도 간격을 늘리는 작업을 따로 요청으로 드립니다).
4. `GET /photos/photo-<번호>` 가 실제로 되는지 — 병합 뒤 첫 실제 실행에서 제가 확인합니다.
5. 출처 링크의 `utm_source=chanceblog` 가 Unsplash 에 등록하신 앱 이름과 같은지(Unsplash 개발자 화면에서 운영자님만 확인 가능, 다르면 알려 주세요).
