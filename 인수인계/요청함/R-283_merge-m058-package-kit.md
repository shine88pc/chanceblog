# [M058] 병합 부탁 — 시험용 Package 만들기 도구 (PCKIT)

> **검사는 이미 끝났습니다 — PR 을 열어서 병합하셔도 됩니다.** 가지를 올린 때 데스크톱 저장소의 검사(Windows·Ubuntu × 파이썬 3.10·3.12 시험)가 돌아 초록으로 끝났습니다. **이 병합 부탁은 데스크톱 프로그램 저장소 `chanceblog-desktop` 의 것입니다**(블로그 저장소가 아닙니다).

## 병합할 제목 (이것 하나만)
> **[M058] 개인 PC 제한 사용 시험용 Package 만들기 도구(PCKIT) — 키·개인 데이터 비포함·SHA-256·시험지·자체 점검 — 외부 쓰기·네트워크·AI 0**

- **제목 맨 앞이 `[M…]` 인 것만 병합하는 것입니다.** 이번 것은 `[M058]` 이고 가지 이름은 `ai/claude/M058-package-kit` 입니다.
- 병합 화면 맨 위의 저장소 이름이 **`chanceblog-desktop`** 이고 변경된 파일이 **29개**(+7,405/−3줄)인지 봅니다. 새 폴더 `packaging/`(만드는 도구)와 많은 시험·문서입니다. **`.github`(빌드 워크플로)·`vendor`·의존성 파일·블로그 저장소는 없습니다.** 다른 노란 배너는 무시하셔도 됩니다.

## 이번 묶음이 하는 일
운영자 개인 PC 제한 사용을 위한 **시험용 Package(미서명)를 만드는 도구와 문서**입니다. 앱 안의 로컬 도구·문서·시험뿐이고 새 외부 호출·키·네트워크·AI·글 올리기는 없습니다. **이 병합만으로 Package 가 만들어지지는 않습니다** — 빌드는 따로 승인하신 워크플로(확인 010)를 사람이 실행할 때 돕니다. 이 병합 뒤에 그 워크플로 병합 부탁을 보냅니다.
- **만드는 도구**: 앱 실행 입구·묶음 목록과 SHA-256(내려받은 파일이 맞는지 대조하는 값)·빌드(도구 버전을 잠금 파일로 고정한 환경에서만)·정보 카드·라이선스 모음. 빌드는 작업 트리·도구 버전·자체 점검·외부 쓰기 관문 값 중 하나라도 틀리면 실패하고, 모든 조건을 통과한 빌드만 '정식'(`release_eligible`)이며 그 밖의 빌드는 이름과 정보 카드에 TESTBUILD 로 드러납니다.
- **묶음에 들어가지 않는 것**: **키**(자격 증명 관리자의 값)·키 모양 글·**개인 데이터**(보관함·백업 폴더·저장한 초안·사용자 설정·잠금·복원 표지와 그 `.bak`·`.tmp` 사본)·소스 저장소 파일. 앱이 쓰는 데이터 파일 이름을 코드에서 읽어 오는 시험이 있어 새 데이터 파일이 생기면 시험이 빨개집니다. 묶음에는 프로그램(exe·`_internal`·`vendor`)과 `VERSION`·`LICENSES`·정보 카드만 있고, 실행해도 데이터 폴더를 만들지 않습니다.
- **자체 점검과 시험지**: 내장 `--selftest`(외부 쓰기 관문 상수·보안 경계 설치·정보 파일 등 12항목)와 잘못된 인자 거절, 그리고 개인 PC 시험용 **시험지**(0단계 SHA-256 대조부터 표준 계정·다른 계정·초안 저장·백업·복원 시험 순서 — 문구는 실제 앱 화면 글자와 대조해 맞춤)가 들어갑니다. 설정 화면에는 버전과 commit 표시가 생깁니다.
- **병합 직전 점검에서 찾아 고친 둘**: 최신 앱(백업·복원·초안 저장 병합 뒤)에 합쳐 보니 시험지의 저장·복원 문구가 실제 화면과 달랐고, 묶음 금지 이름 규칙이 일부 데이터 파일 이름과 `.bak`·`.tmp` 사본을 빠뜨렸습니다. 둘 다 고쳤고 시험으로 못박았습니다.

## 눈에 보이는 변화
- **운영자 PC 의 블로그·자동 실행·앱 사용은 그대로입니다.** 앱에서 달라지는 것은 설정 화면의 버전·commit 표시뿐이고, Package 는 이 병합 다음 단계(빌드 워크플로 병합 → Actions 에서 `Run workflow`)에서 만들어집니다.

## 솔직한 한계 (문서에 적음)
- **서명 없는 Package** 라 Windows 스마트 앱 컨트롤·SmartScreen 경고가 뜰 수 있습니다(시험지에 대응 안내, 서명·설정 변경은 이번 범위가 아닙니다). Windows Defender 검사는 이 PC 의 서비스가 꺼져 있어 못 했고 정보 카드가 그렇게 적습니다.
- 이 PC 는 Windows 뿐이라 **검사(리눅스)가 PCKIT 시험을 처음 돌립니다**(이번 검사 12칸이 그것이고 초록입니다).
- 같은 빌드 재현은 같은 PC·같은 파이썬에서만 확인했습니다(다른 PC 는 못 함). 병합 뒤 첫 Package 는 병합 커밋에서 다시 빌드하므로 정보 카드의 SHA-256 은 그때 값입니다.
- 독립 검증의 정보 2건(후속): 금지 이름 규칙이 SQLite 임시 파일 둘·`MANIFEST.json`·시험용 가짜 보관소 파일 이름을 직접 막지 않습니다(입력 폴더 규칙과 `.db` 규칙이 먼저 막아 영향은 작습니다) / 문서에 적힌 SHA-256 은 특정 커밋의 값입니다.

## 단계 보고
1. **변경 파일**: 29개(+7,405/−3). 새 `packaging/`(입구·묶음 목록·빌드·정보 카드·잠금·라이선스)·`ui/core/version.py`·설정 화면 연결, 시험 8모듈, 문서(PACKAGE·시험지·결정·보안·구조)입니다. `.github`·`vendor`·의존성은 0줄입니다. 앞서 병합된 N-3a·보안 수정·백업·복원·초안 저장 위로 옮겼고 겹친 세 곳(설정 화면 가져오기 한 줄·보안 문서·결정 표)은 양쪽을 모두 살려 풀었습니다.
2. **시험**: PCKIT 새 시험 386개(합친 트리 10,212개 = 순수 main 9,826 + 386, 3.12·3.10 같음), 변이(코드를 일부러 틀리게 해서 시험이 빨개지는지)를 구현자 67개와 검증자 별도 25개 모두 잡았습니다.
3. **독립 검증 세 번**: 1차 조건부 통과 → 수정 → 2차 통과 → 최신 앱 위 재정렬 델타 점검 **통과**(필수·높음·중간·낮음 0, 정보 2). 검증자가 실제로 빌드를 세 번 해 구현자의 압축 파일 SHA-256 을 글자 하나까지 재현했고(3506b8c: 04f43966…), 최종 머리를 두 폴더·두 PATH 순서에서 빌드해 같은 값(8fc18b6f…)을 확인했습니다. 정식 빌드의 자체 점검 12/12·풀어서 `--selftest` 종료 0·잘못된 인자 거절 종료 2·10초 실행 유지·데이터 폴더 새 파일 0·자격 증명 관리자 항목 0→0·항목 172개·데이터·키 파일 0·이 PC 흔적 0 을 확인했습니다.
4. **기존 기능 영향**: 설정 화면의 버전·commit 표시 외 없음. 기존 시험은 약화 없이 그대로 통과합니다.
5. **데이터 이관**: 없습니다. **원복 방법**: 이 PR 을 되돌리는(Revert) 커밋 하나를 병합하면 됩니다.
