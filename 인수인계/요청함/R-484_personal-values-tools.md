# 병합 요청 M114 — 도구 사본의 고정 작성자 값 정리 (확인 032 승인 #13 도구 쪽)

> **병합 방식**: 지금은 AI 병합 기능이 **꺼져 있어** 운영자께서 직접 병합해 주세요. (`M114 승인` 이라고 답하셔도 아직 AI 가 병합하지 않습니다.) 이 요청은 블로그 저장소 `chanceblog` 의 것이고, PR 제목 맨 앞이 `[M114]` 인 것 하나만 병합합니다. 검사는 이미 끝나 초록입니다. 급하지 않습니다(보통).

## 1. 무엇을 바꾸는지
확인 032 ①(이슈 #254)로 승인하신 일곱 건 중 **'추적 파일에 하드코딩된 개인 값 정리'의 도구 쪽**입니다.
① 도구 사본 셋(`mk_merge_branch.py`·`mk_lane_merge.py`·`mk_lane_merge_desktop.py`)이 커밋 작성자 이름·메일을 각자 상수로 갖고 있어 개인 표현 시험의 면제 목록에 올라 있었습니다. 이제 셋 모두 `commit_as_author.py` 의 상수 한 곳에서 읽습니다(이미 그렇게 읽는 다른 사본 셋과 같은 방식).
② 작성자 파일이 곁에 없으면 커밋 전에 바로 실패합니다(조용히 다른 신원으로 커밋하는 길이 없음).
③ 개인 표현 시험의 면제 목록에서 세 줄을 뺐습니다 — 값이 다시 들어오면 시험이 빨개집니다. 새 시험 둘과 결함 기록 한 행(D-445)을 더했습니다.
**기능 코드·워크플로·광고·레지스트리 값은 바꾸지 않았습니다.**

## 2. 하지 않은 것(운영자께 여쭐 것)
같은 항목에 적힌 **공개 사이트 연락처(`_config.yml` 의 `email:`)** 는 이번에 하지 않았습니다. 사이트가 방문자에게 보여 주는 값(광고 표면과 맞닿음)이라, 바꾸려면 **어떤 주소를 공개로 보여 줄지** 운영자님의 값과 사이트 전후 비교가 필요합니다. 이 값은 병합 뒤 따로 여쭙겠습니다(급하지 않음).

## 3. 사용자가 체감하는 변화
**없습니다**(도구 사본·시험·문서뿐 — 사이트 화면·공개 글·알림 동작 그대로).

## 4. 위험과 기존 기능에 미치는 영향
- **기존 기능**: `.github/`·광고 표면·`ads.txt`·레지스트리 값·시크릿·의존성은 바뀌지 않았습니다. 검증기 출력은 시작점과 같습니다(오류 0·경고 3).
- **알려 둔 한계**: 이 PC 의 작업 폴더 원본 도구는 그대로라, 다음 도구 사본 새로 고침 때 원본이 저장소 판을 덮어쓰면 개인 표현 시험이 빨개집니다(그때는 저장소 판을 지키고 원본을 같은 방식으로 고칩니다).

## 5. 시험·독립 검증 결과
- `test_handoff_tools` 176개에서 178개로(새 시험 둘, 삭제 0). 세 도구를 각각 옛 상수판으로 되돌리면 새 시험이 빨강입니다. 합친 나무에서 검증기 오류 0, 관련 시험 4개 모듈 통과.
- 독립 확인(구현자와 다른 AI — 안전·개인정보·시험 렌즈 겸임): **pass(필수 0)** — 변이 19개(옛 상수판·경로 오타·이름·메일 뒤바뀜 등) 모두 빨강, 개인 정보 점검 통과. 권고 셋은 같은 날 반영.
