# 확인 요청 048 — 릴리스 올리는 흐름을 병합하지 않는 가지에 준비 (결정은 한 가지)

> 이 글은 **질문**입니다. 이슈 양식 '[답변] AI 확인 요청에 답하기' 에 **대상번호 048**(`48` 처럼 써도 됩니다)과 고른 보기(1·2)를 적어 주세요. **답이 없으면 2(나중에)** 입니다. 허락하셔도 병합·실행·공개는 하지 않고 따로 부탁드립니다.

## 쉽게 말해
- 앱 v1.0 의 마지막 큰 조각은 '설치 파일을 릴리스 화면에 올리는 흐름' 입니다. 설치 도구가 Inno Setup 으로 정해졌으니(결정 D-811) 이제 그 흐름을 만들 차례입니다: GitHub 의 일회용 Windows 컴퓨터에서 앱 묶음 만들기 → 자가 점검 → 설치 파일·휴대용 압축 파일·해시 목록 → 서명한 업데이트 목록 → **초안** 릴리스.
- 이 흐름은 GitHub 워크플로 파일(`.github/workflows/release.yml`) 하나로 만들고, 워크플로 파일은 규칙상 운영자 승인 항목(T3)입니다. 그래서 **병합하지 않는 작업 가지(NO-MERGE)에 초안만 준비하는 것** 을 허락해 달라는 질문입니다. 지난번 설치 도구 시험 워크플로(확인 037)와 같은 방식입니다.
- 허락하시면 AI 가 워크플로 초안과 그 구조를 지키는 시험을 만들고 독립 검증(안전·시험)까지 마친 뒤 **병합 부탁을 따로** 보냅니다. 서명 도구·릴리스 점검 스크립트처럼 워크플로 밖의 일반 코드는 허락과 관계없이 이미 승인하신 범위(앱 v1.0 완성)에서 먼저 만들기 시작합니다.

## 허락하시는 것(이 목록 안에서만 유효)
1. `release.yml` 새 파일 하나를 **병합하지 않는 가지** 에 준비: 수동 실행(입력칸 없음)만, 결과는 항상 **초안** 릴리스, 공개와 태그 만들기는 운영자의 'Publish release' 한 번.
2. 새 액션 한 개(`download-artifact`) 사용 — 기존 세 개와 같이 40자리 고정 코드로 묶습니다.
3. 그 구조(권한·실행 방식·시크릿 위치)를 지키는 시험.

## 허락하지 않는 것(그대로 막혀 있음)
병합·워크플로 실행·서명 키 만들기·시크릿 입력·저장소 설정 변경·태그·릴리스 공개 — 모두 **따로** 번호 있는 확인이나 운영자 몫입니다. AI 는 서명 키 값을 만들지도 보지도 않습니다.

## 추천값으로 진행하는 것(바꾸고 싶으시면 알려 주세요)
- 태그 이름 `vX.Y.Z`·채널은 `stable` 하나(후보는 `-rc.N` 사전판 표시)·산출물 이름 `ChanceBlogDesktop-<버전>-Setup.exe` 와 `-win64.zip`·시크릿은 서명 키 하나뿐.

## 그다음(나중에, 운영자 몫)
- 서명 키 만들기·저장소 설정·시크릿 입력은 운영자님만 할 수 있는 일이라 시점이 되면 순서표로 따로 드립니다. 지금 하실 일은 없습니다.

## 위험과 되돌리기
- 병합하지 않는 가지에 파일만 두는 일이라 되돌릴 것이 없고 앱·블로그·설정에는 영향이 없습니다.
- 하지 않으시면(기본 2) 릴리스 올리는 흐름이 멈춰 있어 앱 v1.0 의 정식 릴리스가 그만큼 늦어집니다.

## 하실 일
- 급한 일 없음. 허락하시면 `[답변]` 으로 대상번호 048 과 보기 1 을 적어 주세요.
