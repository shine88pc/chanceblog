# 병합 요청 M075 — 'AI 병합' 규칙을 설명 문서와 자동 시험으로만 넣습니다

> **병합 방식**: 지금은 AI 병합 기능이 **꺼져 있어** 운영자께서 직접 병합해 주세요. (`M075 승인` 이라고 답하셔도 아직 AI 가 병합하지 않습니다 — 켜지는 변경이 운영자 병합으로 들어온 뒤에만.) 이 요청은 블로그 저장소 `chanceblog` 의 것이고, PR 제목 맨 앞이 `[M075]` 인 것 하나만 병합합니다. 검사는 이미 끝나 초록입니다.

## 1. 무엇을 바꾸는지
운영자님이 11-15 아침 확인 016 에 `016/3` 으로 정해 주신 '조건부 승인형 AI 병합'(운영자님이 병합 번호를 적어 `M### 승인` 이라고 하시면 AI 가 **그 PR 한 건만** 병합하는 방식)의 **규칙을 글과 자동 시험으로 저장소에 넣습니다.** 넣는 것은 ① 규칙 설명서 `docs/AI_MERGE_POLICY.md`(어떤 변경은 AI 가 병합할 수 있고 어떤 변경은 승인하셔도 운영자만 병합하는지 12가지 목록, 승인 문장을 읽는 법, 병합 직전 8가지 확인, 쉬운 설명 양식) ② 그 규칙대로 변경을 나누는 판정 코드 `pipeline/merge_policy.py` ③ 판정이 규칙대로인지 지키는 자동 시험 두 파일 ④ 기존 시험 한 파일의 조정 한 곳(아래 4번) ⑤ 결함 대장 두 줄(D-346·D-347) ⑥ 상태 문서 세 곳(`AGENTS.md`·`인수인계/작업내용.md`·`WORKLOG.md`)의 낡은 문장 정정입니다. 판정 코드는 **어디서도 불러 쓰지 않으며**, 시험이 그 사실도 지킵니다.

## 2. 왜 필요한지
AI 병합을 켜는 변경을 보내 드리기 전에, 규칙이 말로만이 아니라 글과 시험으로 못박혀 있어야 합니다(말로만 있는 규칙은 세션이 바뀌면 달라질 수 있습니다). 이 묶음은 그 바닥만 놓고 **켜지는 않습니다.** 켜는 변경은 따로, 운영자님이 직접 병합하는 요청으로 보내 드립니다.

## 3. 사용자가 체감하는 변화
사용하는 분이 느끼는 변화는 없습니다 — 새 코드는 어디서도 실행되지 않고, 블로그·앱·발행 흐름은 그대로입니다. 병합 방식도 그대로입니다(지금은 운영자님만 병합).

## 4. 위험과 기존 기능에 미치는 영향
- **기존 기능**: 영향이 없습니다. 새 파일 4개(문서 1·코드 1·시험 2)와 결함 대장 두 줄이 더해지고, 기존 파일은 시험 한 곳과 상태 문서 세 곳의 낡은 문장만 바뀝니다.
- **조정한 기존 시험 한 곳**: `tests/test_generator_quality_gate.py` 의 '품질 Gate(`quality_gate.py`)를 이름으로 언급해도 되는 파일' 목록에 새 정책 파일 한 개를 더했습니다 — **목록을 넓힌 것이라 이 부분은 느슨해졌습니다.** 대신 정책 파일이 Gate 를 글자로만 적고 불러 쓰지 않는지 코드 구조까지 보는 시험을 새로 넣었습니다.
- **상태 문서 정정**: `AGENTS.md` 한 줄(규칙 2번)·작업내용 몇 곳에 적혀 있던 '정책 문서는 다음 묶음이 추가한다·정책 문서화·시험 중' 문장을 '들어왔고 꺼진 상태'로 바로잡았습니다(규칙 내용은 그대로, 직전 작업 기록이 시킨 일).
- **솔직하게 알려 드릴 점 ① — 켜기 전에 운영자님께 여쭐 것이 다섯 가지 있고, 정하기 전에는 켜지 않겠습니다**(문서 §1 요약과 §11-3 에도 같은 목록):
  1. 첫 3건을 코드·문서·시험 변경으로만 한정하는 것으로 읽은 것이 맞는지.
  2. 파일을 열자마자 저절로 실행되는 시작 파일(예: pipeline 폴더의 시작 파일)과 하위 폴더의 AI 지침 문서를 운영자 전용으로 둘지.
  3. 안전 장치(발행 잠금·품질 검사·인증 확인 등)를 지키는 시험 파일을 운영자 전용으로 둘지.
  4. 초안 승인 흐름 코드와 그림자 실행 코드를 운영자 전용으로 둘지.
  5. 영문 글자를 모양만 다른 글자(예: 전각 글자·위첨자)로 바꿔 써서 검사를 피하는 코드를 켜기 전에 막아 둘지(막는 방법은 AI 가 정하고 독립 검증자가 확인).
  검증자 의견은 2·3·4 는 운영자 전용으로 두고 5 는 켜기 전에 막는 쪽입니다. 지금은 AI 병합이 꺼져 있어 영향이 없습니다.
- **② 글자 검사의 한계**: 코드를 글자로 훑어 보는 자동 검사(정책 코드가 어디서도 쓰이지 않는지 보는 검사 포함)는 마음먹고 돌아가려는 시도(글자를 쪼개 붙이기·전각 글자 쓰기 등)를 모두 잡지는 못합니다. 이 검사는 실수와 무심한 변경을 잡는 장치이고, 마지막 방어선은 독립 검증자와 운영자님의 승인입니다. 이 한계도 문서에 정확히 적었습니다.
- **③ 확인을 기다리는 보수적 규칙**: AI 가 보수적으로 정해 두고 운영자님의 확인을 기다리는 규칙이 몇 가지 있습니다 — 안전 장치 파일과 새 외부 접속 코드를 운영자 전용으로 보는 것, 문서 변경에는 키·토큰 같은 낱말 규칙을 적용하지 않는 것, 블로그 저장소의 새 파일을 공개 파일로 보고 운영자 전용으로 두는 것. 급하지 않고 켜는 데 막히지 않으며, 문서 §7-5–§7-7 과 결함 대장 D-347 에 있습니다.
- **켜는 변경이 아닙니다**: 이 병합으로 AI 가 병합할 수 있게 되지 않습니다. 켜지기 전까지 모든 병합은 지금처럼 운영자님이 합니다.
