## 1. Source·Provider Tier 감사표

### 1-1. 읽는 법

- **실행에 쓰는 기준은 `strict_tier` 하나**입니다. `permissive_interpretation` 은 참고(표준 공개 라이선스가 목적 제한 없는 재사용을 허락하면 그 칸을 허용으로 인정하는 해석), `effective_status` 는 strict 기준의 실제 상태입니다.
- **7칸 기호** (상업 이용·자동 접근·가공·저장·AI 입력·출처 표시·라이선스 순): ✔ 허용(약관이 직접 말함·표준 라이선스 본문·법령 근거) · ✔* 허용으로 읽히나 **그 칸을 직접 말한 문장은 없음**(일반 재사용 허락뿐) · △ 조건부 허용(출처 표시·변경 표시 등 조건) · ✖ 금지 · ? 확인되지 않음(문장 없음 또는 못 읽음).
- **strict 규칙**: ✔*·? 가 하나라도 있으면 Tier 3, ✖ 가 하나라도 있으면 Tier 4, 7칸이 모두 ✔·△ 이면 Tier 1(표준 공개 라이선스·법령 근거) 또는 Tier 2(공식 API·약관 명시). permissive 는 ✔* 를 허용으로 칩니다.
- **경로 유형 규칙**(운영자 기준): 외부 RSS 요약·기사/페이지 본문·검색 스니펫은 발행자나 라이선스와 무관하게 **유형만으로 Tier 3(자동화 제외)**, 외부 사진도 자동화 제외입니다. 구조화 API·데이터셋만 권리 판독 결과(`strict_tier`)를 따릅니다. 그래서 권리가 분명한 출처(예: NASA 글 strict Tier 1)도 RSS·본문 경로로는 자동화되지 않습니다.
- **근거 수준**: 오늘(2026-11-09) 공식 약관·robots.txt 를 읽은 결과입니다(약 120쪽, 요약 도구 경유 — 중요한 칸은 사람이 원문을 한 번 읽는 것이 안전). 못 읽은 칸은 `?`(추정 안 함). Pew 는 열지 않았고 2026-10-26 기록을 썼습니다. 도구가 못 읽은 곳은 우회하지 않고 `?` 로 두었습니다.

**막힌 칸을 푸는 길**(비용 낮은 순):

1. **공공누리 `AI유형`(인공지능 학습용) 또는 제0유형(조건 없음)이 표시된 구조화 데이터셋을 Dataset 단위로 찾아 판정** — AI 입력 문장이 직접 생겨 strict 로 통과할 수 있는 유일한 현실적 경로입니다. 지금까지 읽은 데이터셋 3건(단기예보·에어코리아·TourAPI)은 AI유형이 아닙니다. 탐색 조사를 시작했습니다(TE, 진행 중).
2. **운영자 해석 1건**(기본값 strict 유지): 'AI 입력 칸만 `?` 이고 **AI 를 쓰지 않는 규칙 기반 경로**'를 자동화로 허용할지. 허용하면 위 표의 permissive Tier 1–2 후보(NOAA·통계청 WDS·Eurostat·단기예보 등)가 규칙 기반 초안 경로에서 바로 쓰입니다. Tier 1·2 정의에는 AI 입력 확인이 없는데 Policy Gate 는 AI 입력 UNKNOWN 도 제외한다는 정의 간 간극에서 나온 질문입니다.
3. 공급자에 문의하는 것은 기본 절차가 아니므로 하지 않습니다.
4. Tier 0 만으로 시작: 시드·발행 이력·사용자 입력·자체 계산만으로 만든 초안(예: 정정 기록·사용자가 확인한 경험 글)은 외부 Provider 없이도 파이프라인을 통과시킬 수 있지만, 독자에게 줄 가치가 큰 글이 되기는 어렵습니다.

**따라서 제한 재개용 최소 Allowlist 는 '지금은 Tier 0, 그리고 1번(AI유형·제0유형 Dataset)의 결과 또는 2번의 운영자 해석이 생기는 만큼 늘어난다'** 입니다. 이것이 10절에서 다루는 가장 큰 일정 위험입니다.


## 5. Desktop 과 Publication Pipeline 의 의존성 분석

데스크톱 저장소 코드를 읽고(import 그래프 포함) 복사본에서 소켓·HTTP·프로세스를 막은 채 후보 12개·초안 4개를 실제로 돌려 확인했습니다. 전체 분석은 운영자 폴더의 `Desktop_의존성_분석_2026-11-09.md` 에 있습니다.

**판정: 분리됨(호출 경로) · 안 됨(코드 경계) = '부분'**

- **로컬 작성 기능은 발행과 독립입니다**: 프로필·Seed·후보·초안·편집·복사·백업·복원·기존 게시 이력 읽기는 네트워크·git·`PIPELINE_PAUSE`·블로그 저장소를 부르지 않고, 없어도 돕니다(막은 호출 0건, `PIPELINE_PAUSE=true` 여도 초안 글자까지 같음). 앱에 GitHub 토큰이 없어 `PIPELINE_PAUSE` 변수를 읽지도 쓰지도 못하고, 그런 코드도 0건입니다. 네트워크 부품(`urllib`·`http.client`·`subprocess git`)은 CLI 전용 `publish/` 와 공개 주소 확인 한 곳에만 있고, `socket`·`requests`·AI SDK 는 0건입니다.
- **격차 1 — 정책**: CLI `publish-pages --yes` 는 승인된 Chance 글을 **저장소 main 에 직접 commit·push** 합니다(`publish/pages.py:389`). 운영자 기준(Chance 는 `publish_flow: pr` 만, 사람 병합 전 공개 금지)과 다르고, `PIPELINE_PAUSE` 와 `publish_flow` 를 모릅니다. 블로그 `pages.yml` 도 `PIPELINE_PAUSE` 를 읽지 않아 이 push 는 정지 중에도 배포됩니다. 다만 GUI·자동·예약 경로는 없고 사람의 `approve` 와 `--yes` 가 필요해 '사람 승인 없는 공개 경로'는 아닙니다.
- **격차 2 — 구조**: 로컬 서비스가 import 사슬로 발행 코드를 끌어옵니다(`service.context`→`publish.gitrepo`, `service.projects`→`gate`·`journal`→`publish.pages`). `settings.json` 한 파일에 발행 연결(`repo_path`)과 네이버 프로필이 같이 있어, 이 파일이 깨지면 후보 계획과 초안이 막힙니다(목록 보기는 됨).
- **격차 3 — 범위**: 운영자 사용 범위 중 없거나 CLI 뿐인 것 — 초안 로컬 저장(D-281 이 일부러 안 함)·AI 초안 보조(코드 없음)·로컬 이미지 관리(화면 연결 없음)·출처 단독 복사·GUI 백업·복원·GUI 로 네이버 글쓰기 주소 정하기.
- **완료 조건 대조**: P4e 14개는 모두 충족(추천 카테고리·출처 표시는 조건·제한 있음). P4d 8개는 구현자 자체 보고로는 모두 충족이지만 독립 분석은 ⑥ 부분 완료 상태 이름·⑦ 다른 PC 복원(주제 엔진 4파일 한정, 화면 없음, 진짜 다른 PC 미확인)을 '부분'으로 봅니다. **AI 호출·프롬프트 조립 코드가 아예 없어 AI 입력 금지 목록이 넘어갈 길은 0** 입니다(허용 목록과 자동 보류 규칙은 AI 연결 묶음이 조립부와 함께 만들어야 함).
- **설치·개인 PC**: 설치 파일·업데이트 코드는 아직 없고 설계 문서뿐입니다. 설치 뒤 로컬 작성은 네트워크가 필요 없습니다. 키는 Windows 자격 증명 관리자에만 있고 백업에 없습니다(운영자 기준과 일치). 새 PC 이전 절차 문서와 `settings.json` 백업 포함 여부가 비어 있습니다.

## 8. 외부 Publication Service 분리 여부

- **하나의 서비스로 분리돼 있지는 않지만 모양은 이미 그렇습니다**: `publish/` 는 Chance(GitHub Pages) 전용(`gitrepo.py`·`pages.py`·`deploy.py`)이고 네이버 복사·Blogger 초안·PR 생성 코드는 없습니다. 정책 게이트(`PublicationPolicy.check(ctx, channel, action)`)만 이름으로 더하면 됩니다(채널·행동별로 허용·사람 승인 필요·금지).
- **채널별 정책(운영자 결정)을 이 게이트가 담습니다**: Naver A/B = 복사 후 사람이 직접 게시(허용) · Chance = `publish_flow: pr` 만(지금 직접 push 는 기본 잠금) · Blogger = 초안 생성까지만(Desktop 코드 없음) · 기존 공개 글 = 읽기 전용.
- **egress·Registry 의 자리**: 외부 호출이 생길 때(네이버 검색 트렌드 등) `S/topics/trend.py` 의 `TrendProvider`·`QuotaGuard`·`connections.PURPOSES` 를 재료로, `service/` 밖 새 패키지(`egress/gateway.py`·`registry.py`)에 호출을 한곳으로 모으고 호출자가 주입합니다 — 조건이 안 맞으면 `NoTrend()` 라 로컬 후보·초안 코드는 한 줄도 안 바뀝니다. 이는 5절 `AI_PROCESSOR_POLICY`·허용 목록 설계와 같은 자리입니다(R-217).
