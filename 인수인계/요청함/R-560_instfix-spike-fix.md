# 병합 요청 M136 — 설치 도구 시험 정정 (앱, T2)

> **병합 방식**: 지금은 AI 병합 기능이 **꺼져 있어** 운영자께서 직접 병합해 주세요. (`M136 승인` 이라고 답하셔도 아직 AI 가 병합하지 않습니다.) 이 요청은 앱 저장소 `chanceblog-desktop` 의 것이고, PR 제목 맨 앞이 `[M136]` 인 것 하나만 병합합니다. 검사는 이미 끝나 초록입니다. 급하지 않습니다(보통).

## 1. 무엇을 바꾸는지
운영자께서 설치 도구 시험(GitHub 의 일회용 Windows 컴퓨터에서 설치 도구 세 후보를 재 보는 **Run workflow**)을 처음 돌려 주셨고, 그 결과를 읽어 **측정 도구가 틀리게 판정하거나 멈추던 곳**을 고쳤습니다. 앱 자체의 코드는 한 줄도 바뀌지 않습니다.
- **1차 결과에서 나온 결함**: 앱의 점검 열세 개가 '12개가 아니라서 실패' 로 적히던 것·설치 도구 Inno 의 판을 파일 버전 하나로만 읽다 0.0.0.0 에서 후보 하나를 멈추던 것·'일반 사용자로 설치해 보기' 가 '종료 0 인데 흔적 없음' 을 실패로 적던 것·결과 상자 머리의 '러너: ? ?' 와 읽기 어려운 모양을 고쳤습니다.
- **독립 검증이 남긴 권고 15개를 모두 반영**: '일반 사용자로 띄우기 실패' 의 이유를 형식 이름 하나(InvalidOperationException)가 아니라 **윈도 오류 문장**으로 남깁니다(비밀번호를 가린 뒤 200자로 자름) — 그래서 2차 결과에서 진짜 원인을 가릴 수 있습니다. 관리자 권한을 요구하는 경우는 실패로 가르고, 설치본 점검의 근거에 종료 코드·시간 초과 같은 이유를 덧붙이고, 원인 후보를 다섯으로 정정했습니다.
- 바뀐 곳: `packaging/spike/measure.py`·`run_spike.py`·시험 도우미 둘과 시험 셋(설치 도구 시험 모듈)·문서(`docs/INSTALLER_SPIKE_RUN.md`·`docs/DECISIONS.md` 의 D-810 한 행·`CHANGELOG.md`·결정 색인 재생성).

## 2. 왜 필요한지
1차 결과의 '일반 사용자 시험' 이 원인을 알려 주지 못한 채 '종료 0 인데 흔적 없음' 으로 끝났습니다. 그대로 두 번째 실행을 하면 같은 모호한 결과가 나옵니다. 오류 문장을 남기게 해 두면 2차 한 번으로 후보를 가릴 수 있습니다.

## 3. 사용자가 체감하는 변화
**앱에는 없습니다.** 달라지는 것은 운영자께서 병합 뒤 설치 도구 시험을 **한 번 더** 돌리실 때의 결과 상자뿐입니다(같은 단추, 같은 방법 — `docs/INSTALLER_SPIKE_RUN.md`). 그 부탁은 병합이 확인된 뒤 따로 보냅니다.

## 4. 위험과 알려 둔 한계
- 이 도구는 GitHub 의 일회용 Windows 컴퓨터 안에서만 돌도록 막혀 있고(아니면 종료 코드 2 로 멈춤), 이 PC·운영자 PC 에서는 진짜 측정을 돌리지 않았습니다. 독립 검증도 같은 이유로 진짜 측정은 돌리지 않고 가짜 Host 와 진짜 PowerShell 한 시험(다른 계정 인자만 뺀 사본)으로 확인했습니다.
- 윈도 오류 문장의 **실제 모양은 일회용 컴퓨터가 처음 보여 줍니다**(영어 윈도 전제). 낱말(elevation·권한 상승·740)로 실패를 가르는 것이 새 규칙이라 거짓 양성이 있으면 후보 하나가 탈락할 수 있어, 2차 결과 상자의 오류 문장을 사람이 한 번 읽어 확인합니다.
- 독립 검증의 마지막 권고(후속): 상자 칸 이유와 관리자 권한 요구 실패 기록의 '가린 뒤 자르기' 순서를 시험이 아직 묶어 두지 않았습니다(지금 코드는 안전하고, 시험 보강은 시험 묶음 후속으로 합니다).
- 앱 검사(CI)는 윈도 러너가 있어 진짜 PowerShell 시험도 돕니다.
- 운영자께 여쭐 것은 없습니다.
