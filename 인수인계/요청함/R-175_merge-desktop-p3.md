## 왜 필요한가 (쉬운 설명)
지금까지(P0~P2b) 만든 5채널 주제 선정 규칙은 '계산 부품'이라 어디에서도 쓰이지 않았습니다. 이번 단계(P3)가 그 부품을 **후보를 저장하고, 보여 주고, 백업하는 쪽**에 처음 잇습니다. 화면(P4)이 곧 이 서비스를 부를 수 있게 하는 바탕입니다.

| 부품 | 하는 일 |
|---|---|
| 남은 자리 계산(`slots`) | '목표 개수 − 이미 있는 활성 후보 − 검토 대기'로 새로 만들 개수를 정하고, 센 상태·안 센 상태와 '같은 후보' 판정 규칙을 한 곳에 모았습니다 |
| 관심도 연결 틀(`trend`) | 관심도(Search Trend) 공급자 규약과 '없음'·'가짜'(시험용) 구현 — **실제 호출은 만들지 않았습니다(P5)** |
| 후보 보관함 `topic_engine.db` | 글 보관함과 **따로 둔** 새 보관함(새 패키지 `topicdb/`) — 후보·보류함·점수 기록·관심도 캐시 틀·연결·출처·발행 이력 장부. 자기 이름표·판 번호가 있고, 낯선·더 새로운·깨진 파일은 한 바이트도 안 바꾸고 거절합니다 |

## 눈에 보이는 변화 (꼭 알아 두실 것)
1. **앱 화면·기존 명령은 그대로입니다.** 기존 명령 45개의 도움말 해시가 같고, 기존 명령 시나리오 출력도 같습니다(차이는 임시 경로 글자와 `topics` 가 선택지 목록에 더해진 것뿐).
2. **새 명령줄 `topics`**(AI 가 쓰는 도구입니다 — 운영자가 직접 칠 필요는 없습니다): `status`(상태 보기)·`init`(처음 설정)·`check`(씨앗·캘린더·프로필 검사)·`plan`(새 후보 미리 보기)·`generate`(후보 저장)·`top`(채널별 우수 후보 5개)·`list`·`show`(후보 목록·상세)·`review`(보류함 기한 보기)·`backup`·`restore`. **저장·처음 설정·복원은 끝에 `--yes` 가 있을 때만** 하고, 나머지는 읽기만 합니다.
3. **새 폴더**: `topics init --yes`·`topics generate --yes`·`topics backup` 을 처음 실행할 때만 사용자 데이터 폴더 아래 `topic_engine\`(설정 JSON 셋과 후보 보관함)와 `backups\topic_engine\` 이 생깁니다. 실행하지 않으면 아무것도 생기지 않습니다.
4. **`topics backup` 은 기존 `backup` 처럼 `--yes` 없이 새 폴더만 만듭니다**(기존 데이터는 안 바꾸고 최근 10개만 보관) — '읽기 전용이 기본'의 유일한 예외입니다(결정 D-73, 아래 확인 항목).
5. **새 오류 코드 9개**(87 → 96개) — 모두 쉬운 한국어 이유·조치가 있고 개발자용 영문·예외 이름은 `--verbose` 에서만 보입니다.
6. **모든 명령의 '예상 못 한 운영체제 오류' 상세에서 파일 이름이 빠집니다**(`--verbose` 에서도 오류 번호와 종류만 — 사용자가 친 글이 오류 문구로 되풀이되지 않게 하는 보안 조치, 결정 D-80). 이 한 곳만 기존 명령의 오류 상세 글이 달라집니다.

## 우분투 검사 실패와 그 수정 (투명하게)
첫 병합 가지의 자동 검사에서 **Ubuntu 두 칸만 빨갰습니다**(윈도 두 칸은 초록 — 제 PC 가 윈도라 미리 못 본 것). 로그를 로그인 없이 읽을 수 없어 **임시 진단 가지**(지금은 지웠습니다)로 우분투에서 돌려 실패한 시험 이름을 읽었고, 5,476개 중 **딱 1개**였습니다: 번호 자리에 넣은 아주 긴 글이 `topics restore <백업파일> --verbose` 의 표준 오류에 되풀이되는지 보는 기존 시험. 원인은 리눅스가 이름 한 마디 255바이트가 넘는 글에 `File name too long` 오류를 내고 그 문구(친 글 포함)가 `--verbose` 상세에 실린 것입니다(윈도는 다르게 돌려줘 안 보였음). **수정 5차**에서 고쳤습니다 — 친 글은 파일 시스템에 묻기 전에 모양부터 보고(제어 문자·이름 한 마디 255바이트 초과·전체 260자 초과면 묻지 않고 '백업을 찾을 수 없음'), 운영체제 오류 문구에는 파일 이름을 싣지 않으며(위 '눈에 보이는 변화' 6), 같은 갈래로 `--data-dir`·`--repo` 의 긴 글이 새던 22곳도 함께 막혔습니다. 윈도에서도 리눅스의 이름 길이 한계를 흉내 내 같은 표를 돌리는 시험을 더해 앞으로 같은 일이 나면 윈도에서도 빨개집니다.

고친 뒤 **한 번 더** 같은 방식으로 우분투에서 돌려 보니(5,495개) 이번에는 **제가 수정 5차에서 새로 더한 시험 1개**만 빨갰습니다 — 윈도 경로(`C:\…\topic-…`)를 주고 '파일 시스템에 물었다'를 기대하는 시험인데, 리눅스에서는 `\` 가 파일 이름의 글자라 같은 입력이 다르게 흘러가기 때문입니다(프로그램 동작은 두 OS 에서 각자 맞고 **시험의 기대만 윈도 전용**이었습니다). **수정 6차**에서 시험만 고쳤습니다(모든 OS 에서 도는 `/` 경로 판·윈도 전용 판·모양 판정 함수 직접 시험, 프로그램 코드 변경 0줄). 이 병합 가지의 검사 4칸이 그 결과입니다.
