# 확인 요청 045 — 매니저 세션이 기다리는 세 가지와 위임 (결정은 한 가지)

> 이 글은 **질문**입니다. 이슈 양식 '[답변] AI 확인 요청에 답하기' 에 **대상번호 045**(앞의 0 을 빼고 써도 됩니다)와 고른 보기(1·2·3)를 적어 주세요. **답이 없으면 3(보류)** 입니다 — 아무것도 바뀌지 않고 매니저 세션은 해당 일을 하지 않고 기다립니다.
> 매니저 세션은 '운영자님이 매니저 채팅에 직접 쓴 말'만 승인으로 인정하는 규칙을 스스로 정했습니다. 지금 PC 에 접속하실 수 없어서, 보기 1 은 **이 답을 승인으로 받아들이도록 위임**하는 보기입니다(받아들일지는 그 세션이 마지막으로 판단합니다).

## 세 가지 (금액·종목 같은 값은 없는 중립 질문입니다)
- **PM_001 — 제품 코드를 저장소에 올리는 PR 순서.** 제품 코드(260여 파일)를 매니저 저장소에 올리는 순서입니다. 추천: 운영 체계 PR 두 개(부트스트랩)를 병합한 뒤 모듈 묶음별로 나눠 PR 을 올리고 매번 운영자님이 병합합니다. 기본값: 요청하시기 전까지 올리지 않습니다.
- **PM_002 — 블로그 공개 저장소 파일 읽기 전용 복사.** 설계서가 가리키는 블로그 저장소의 알림·검증 도구 파일(큰 것은 1,500줄·3,000줄)을 임시 폴더에 읽기 전용으로 받아 필요한 것만 복사해도 되는지입니다. 블로그 쪽에는 아무것도 쓰지 않습니다. 추천: 허락. 기본값(허락 없음): 이 세션이 파일 글을 메시지로 나눠 보냅니다(느리고 번거롭습니다).
- **PM_003 — 원격 연결·첫 커밋 시점.** 운영자님의 단계 1(봇·저장소 설정·열쇠 준비, 저장소가 비어 있으면 GitHub 화면에서 README 한 줄로 main 만들기)을 마친 뒤에 연결하고 첫 커밋을 올립니다. 추천: 단계 1 이 끝나고 운영자님이 요청하실 때. 기본값: 요청 전까지 연결·커밋·푸시를 하지 않습니다.

## 보기 1 에서 함께 위임하는 것 (PM_004)
- 위 세 건(PM_001–PM_003)에 한해, 이 세션이 전하는 **소유자 `[답변]`(작성자 소유자·대상번호·선택이 봇 접수로 확인된 것)** 을 매니저 세션이 운영자님의 승인으로 인정합니다. 다른 사안(실제 공급원 연결·자격증명·텔레그램·연동 활성화·알고리즘 상수 확정·병합 등)은 위임에 들어 있지 않고 계속 매니저 채팅에서 직접 확인합니다.
