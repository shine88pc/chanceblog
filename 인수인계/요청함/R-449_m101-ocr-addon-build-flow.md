# 병합 요청 M101 — 글자 읽기 추가 도구 빌드 흐름 초안 (앱, T3)

> **병합 방식**: 지금은 AI 병합 기능이 **꺼져 있어** 운영자께서 직접 병합해 주세요. (`M101 승인` 이라고 답하셔도 아직 AI 가 병합하지 않습니다.) 이 요청은 앱 저장소 `chanceblog-desktop` 의 것이고, PR 제목 맨 앞이 `[M101]` 인 것 하나만 병합합니다. 검사는 이미 끝나 초록입니다. 급하지 않습니다(보통). **새 워크플로 파일이 들어 있어 운영자만 병합하는 종류(T3)이고, 이 워크플로를 실행하는 것도 운영자만 합니다 — AI 는 실행하지 않습니다.**

## 1. 무엇을 바꾸는지
승인해 주신 '사진 속 글자 읽기'(확인 026 앱 연동 승인 · 030 ② GEOS 고지문만 넣고 소스 압축 파일은 없음)의 **빌드 단계**입니다. 이미 병합된 추가 도구 소스(몸통, M098)를 사람이 한 번 눌러 GitHub 의 윈도 러너에서 만드는 흐름과, 만든 묶음을 점검하는 두 겹의 문입니다.
① **워크플로 초안(`.github/workflows/package-ocr.yml`, 새 파일 하나)**: **수동 실행만**(입력칸 없음)·권한은 `contents: read` 하나·비밀 0·액션 셋은 전체 커밋 SHA 로 고정(이미 병합된 `ci.yml`·`package.yml` 과 같은 값, 새 액션 0)·서명·릴리스 게시 단계 없음. 잠금 파일은 해시 고정(`--require-hashes --only-binary=:all:`)으로 설치하고, 점검을 통과한 묶음 하나만 올립니다.
② **빌드 정리**: 저장소 기준 경로·`--require-clean`·재현 빌드(시각 고정·해시 시드 고정)이고 점검을 끄는 옵션 여섯은 없앴습니다. 모델 받기는 빌드 전용 코드(커밋 고정 주소·허용 호스트·https 만·크기 상한·SHA-256 대조·실패하면 파일을 남기지 않음)이며 앱 본체에는 내려받는 코드가 없습니다. 글자 사전(47,451바이트, 출처·라이선스 근거 파일 포함)을 저장소에 더했고 줄바꿈 변환을 막았습니다.
③ **점검 두 겹**: 빌드 점검(네트워크 DLL 가져오기·금지 부품·모델 해시를 보고 걸리면 산출물 0, 종료 코드 1)과, 만든 압축 파일을 빌드와 독립으로 다시 판정하는 산출물 점검(없어야 할 것·있어야 할 것·GEOS 라이선스 전문). 몸통에서 병합된 고지 만들기(licenses·THIRD_PARTY_NOTICES·GEOS 전문)는 점검 앞 단계로 합쳤고 못 만들면 산출물이 없습니다.
④ **워크플로 규칙 검사 강화**: 표준 라이브러리만의 작은 YAML 읽개로 글을 구조로 읽는 허용 목록 방식입니다(숨은 단계·줄 나눔처럼 읽히는 보이지 않는 글자까지 거절).

## 2. 왜 필요한지
승인된 단계 계획의 셋째(몸통 → 화면 → 빌드 흐름 → 켜기)입니다. 추가 도구가 실제로 만들어져야 운영자 PC 에서 글자 읽기를 켜 볼 수 있습니다. 빌드는 정해진 입력에서 같은 결과가 나오고, 한 가지라도 어긋나면 산출물이 없도록 만들었습니다.

## 3. 사용자가 체감하는 변화
없습니다. 앱 본체(`src/`·`packaging/`·잠금 파일·본체 워크플로)는 한 줄도 바뀌지 않았고 `LOCAL_OCR` 는 꺼진 채입니다. 이 워크플로는 운영자가 직접 실행하기 전에는 돌지 않습니다(`push` 로는 돌지 않음).

## 4. 위험과 기존 기능에 미치는 영향
- **운영자께서 병합 전에 봐 주실 곳(T3)**: ① **액션 SHA 세 개를 공식 릴리스 값과 대조**(checkout v4.4.0 `11d5960a…`·setup-python v5.6.0 `a26af69b…`·upload-artifact v4.6.2 `ea165f8d…` — 이 PC 는 네트워크가 막혀 AI 가 못 했습니다. 이미 병합된 `ci.yml`·`package.yml` 과 같은 값이라 대조하시면 그 둘도 함께 확인됩니다) ② 워크플로가 닿는 외부 두 곳(파이썬 패키지 저장소의 잠금 파일 해시 고정 설치·모델 저장소의 커밋 고정 내려받기)이 괜찮은지 ③ 권한 `contents: read` 하나·비밀 0·수동 실행만이라는 점.
- **알려 둔 한계**: 이 흐름은 GitHub 러너에서 **한 번도 돌려 보지 못했습니다**(AI 는 워크플로를 실행하지 않습니다). 처음 실행에서 막히는 곳이 나오면 결과를 알려 주시면 고치겠습니다. 이 PC 에는 `pefile` 이 없어 일부 시험이 건너뛰어졌고 빌드 가상환경에서 따로 통과를 확인했습니다. 이 PC 에서 저장소 배치 그대로 진짜 빌드를 세 번 돌려 점검 통과·같은 입력 두 번은 바이트까지 같음을 확인했습니다(러너가 아님).
- **운영자께 여쭐 것(급하지 않음, 이번 병합과 별개)**: ① 병합 뒤 처음 한 번 Actions 탭에서 이 워크플로를 수동 실행해 결과를 알려 주세요 — **추천: 병합한 뒤 바로 한 번**. ② 추가 도구에 든 GEOS(LGPL) 때문에 앱 이용 약관이 '디버깅을 위한 역설계'까지 금지하지 않는지 도구를 배포하기 전에 한 번 봐 주세요 — **추천: 배포 전 확인**.

## 5. 시험·독립 검증 결과
- 새 시험 207개(빌드 흐름 196 + 합친 흐름 11), 변이 244개를 동등 변이 몇 개 말고 모두 시험이 잡았습니다. 워크플로 규칙 검사는 옛 검사기가 놓치던 우회 변형 65개 가운데 60개를 지금은 모두 막습니다.
- 독립 검증(구현자와 다른 AI 둘 — 안전·시험): 1차 필수 둘과 중간 재확인의 필수 하나(유니코드 줄 나눔 글자로 숨긴 워크플로 단계)를 모두 고친 뒤, 이미 병합된 몸통 위로 얹은 합친 모양의 충돌 풀이까지 **둘 다 pass(필수 0·권고 0)**.
- 검사(CI) 앱 12칸 초록. 이 병합은 Qt 화면 코드를 바꾸지 않아 Qt 시험은 따로 돌리지 않았습니다.
