# [R-075] 병합 부탁 — 자동 검사를 미리 끝내 두기

> **이번 PR 은 검사를 기다리지 않으셔도 됩니다.** 제가 브랜치를 올린 때 검사 4칸이 이미 돌아 끝났고, PR 을 만들면 그 초록 결과가 화면에 바로 보입니다.

## 병합할 제목 (이것 하나만)
> **[R-075] 자동 검사를 미리 끝내 두기 — PR 을 만들 때 다시 돌지 않음 [대상: 데스크톱]**

- 맨 앞이 `[R-075]` 인 이 제목 하나만 병합합니다. 다른 번호나 다른 제목은 병합하지 않습니다.
- **데스크톱 프로그램 저장소 `chanceblog-desktop`** 입니다(병합 화면 맨 위 저장소 이름 확인).
- 첫 화면에 노란 배너가 여러 개 보여도(작업 중인 다른 브랜치) 위 제목 하나만 고릅니다.

## 무엇이 바뀌나 (쉬운 설명)
**말씀하신 불편:** 병합 전에 검사가 끝나기를 계속 지켜봐야 하고, 검사가 빨갛게 나오면 이슈로 다시 확인을 요청해야 했습니다.

**원인(실측):** 검사가 길어서입니다(Windows 칸 약 13분). 게다가 R-071 때 저는 병합 부탁을 보내기 전에 같은 검사를 먼저 돌려 초록(16분)을 확인해 두었는데도, 운영자님이 PR 을 만드는 순간 GitHub 가 **같은 내용을 처음부터 다시 검사**(13분)해서 그동안 기다리셔야 했습니다.

**고치는 법:**
1. 검사 설정 파일(`ci.yml`)에서 'PR 을 만들 때 다시 검사' 한 줄을 뺍니다. 이제 검사는 **제가 브랜치를 올릴 때 한 번만** 돌고, PR 화면에는 그 **이미 끝난 결과**가 그대로 보입니다.
2. 앞으로 저는 **검사 4칸이 모두 초록인 것을 확인한 뒤에만** 병합 부탁을 보냅니다. 빨간 칸이 나오면 제가 먼저 고치고(운영자님께 묻지 않습니다) 초록이 된 뒤에 요청합니다 — 이슈로 '문제' 답을 쓰실 일이 없어집니다.
3. 병합 부탁의 '하실 일'이 **PR 만들기 → 초록 4칸 확인 → Merge → Confirm** 으로 짧아집니다(기다림 없음).
4. 검사 시간 제한을 20분에서 30분으로 늘렸습니다(Windows 칸이 14~15분까지 늘어, 느린 날 중간에 끊겨 빨갛게 되는 일을 막습니다).

**바뀌지 않는 것:** 프로그램 동작·블로그·네이버·발행은 그대로입니다. 검사 자체의 시간(Windows 칸 약 13분)과 내용도 그대로이고, 기다리는 쪽이 운영자님에서 저로 바뀝니다. 블로그 저장소의 PR 검사는 2분 정도라 지금은 그대로 두고, 같은 방식을 뒤따라 제안드립니다.

## 확인한 것
- 독립 검증 1회(구현자와 다른 AI 가 새 복사본에서): **'병합 가능'**(높음 0·중간 1·낮음 7). 설정 변경이 'PR 때 다시 검사' 한 줄 삭제뿐임을 코드로 확인했고, 새 시험이 그 한 줄을 되살리는 변경 8가지를 모두 잡았으며, GitHub 공식 문서와 이 저장소의 공개 기록(R-071 PR #10 의 머리 커밋에 미리 돌린 검사와 PR 검사가 따로 달려 있었음)으로 'PR 화면에 미리 돌린 검사 결과가 그대로 보인다'를 확인했습니다. 지적 중 중간 1건(규칙 문서에 '부탁은 한 번에 하나만·보내기 직전 main 확인' 보강)과 낮음 5건(시험이 빈 줄 뒤의 다른 트리거를 못 잡음·실패 문구·시간 제한·수동 실행 충돌·확인 방법 적기)을 고쳐 반영했고, 그래서 브랜치를 다시 올려 검사를 한 번 더 돌렸습니다(이 요청의 브랜치가 그 최종본입니다). 남은 낮음 2건은 운영 방식으로 대응합니다('Update branch' 단추의 검사 여부는 확인할 수 없어 누르지 말라고 적었고, 다른 브랜치와의 문서 충돌은 병합 순서를 지켜 피합니다).
- 이 브랜치의 자동 검사: 4칸(Windows·Ubuntu × 파이썬 3.10·3.12) 모두 초록 — 15:54 에 시작해 16:13 에 끝났고 18분 37초 걸렸습니다(그래서 검사 시간 제한도 20분에서 30분으로 늘렸습니다). PR 화면의 검사도 이 결과를 그대로 보여 줍니다.
- 변경 범위: 파일 5개(검사 설정 1개·시험 2개 추가·규칙 문서 3곳 한 줄씩). 설정 파일은 설명 주석을 더하고 'PR 때 다시 검사' 한 줄을 지우고 시간 제한(20→30분)과 수동 실행이 서로 취소하지 않게 하는 이름 한 줄을 바꾼 것이 전부입니다(읽기 전용 권한·시험 명령·파이썬 3.10/3.12·Windows/Ubuntu 는 그대로).

## 솔직한 한계 (병합을 막지 않음)
- PR 을 만들 때 '합친 결과'를 다시 검사하지 않습니다. 한 번에 한 요청만 보내고 main 은 운영자님의 병합으로만 움직이므로 같은 내용이며, 병합 직후 main 검사는 제가 직접 확인합니다.
- 다른 사람이 포크로 보낸 PR 은 검사가 돌지 않습니다(혼자 쓰는 저장소라 해당 없음).

## 위험과 대비
- 이 PR 은 검사 설정만 건드리므로 병합해도 프로그램·블로그·발행에는 아무 일도 일어나지 않습니다. 되돌려야 하면 병합 한 건을 되돌리는 요청을 드립니다.
- 병합 뒤 제가 직접 확인합니다(병합 상태·내용 일치·main 검사). 병합하신 시각을 알려 주실 필요는 없습니다.
- **결정하실 것은 없습니다.**
