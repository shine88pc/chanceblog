# 병합 요청 M116 — 발행 안전 넷 (T3)

> **병합 방식**: 지금은 AI 병합 기능이 **꺼져 있어** 운영자께서 직접 병합해 주세요. (`M116 승인` 이라고 답하셔도 아직 AI 가 병합하지 않습니다.) 이 요청은 블로그 저장소 `chanceblog` 의 것이고, PR 제목 맨 앞이 `[M116]` 인 것 하나만 병합합니다. 검사는 이미 끝나 초록입니다. 급하지 않습니다(보통). **병합 전에 아래 3절의 확인 한 가지를 부탁드립니다.**

## 1. 무엇을 바꾸는지 — 확인 032 ①(이슈 #254)로 승인하신 1–4번
**T3 — `.github/workflows/` 두 파일(`chanceblog.yml`·`chance-shadow.yml`)의 키 줄 한 줄씩, 잠금 규칙, 프로필 값 셋, 워치독**입니다.
① **잠금 규칙 L9·L10**: 발행 정지를 풀 때 품질 관문은 보류형(`hold`), 글감 방식은 사실 기반(`facts`)이고 국문 단독(`["ko"]`)이어야 한다는 재개 조건 3·4 를 코드가 지킵니다(지금 레지스트리 값은 이미 맞아 오류 0 — 값이 바뀌면 잠금이 막습니다).
② **쓰지 않는 사진 키 거르기**: 두 워크플로의 `UNSPLASH_ACCESS_KEY` 줄이 글감 방식이 `feed` 일 때만 키를 싣습니다(사실 기반 실행에는 비밀이 실려 가지 않습니다). 기존 글 사진 교체 워크플로(`chance-fix-images.yml`)는 키를 쓰므로 그대로입니다.
③ **프로필 정규식 값 묶기**: 한국어 프로필 셋의 이메일·퍼센트·가격·용량 패턴 앞에 경계를 둬서 같은 숫자 열 한가운데에서 다시 시작하는 제곱 시간 틈(6,400자 글에 5초대)을 닫았습니다(병적 입력 6,399자가 0.02초 안, 점검 한 번 5.4초→0.02초).
④ **오타로 걸린 발행 정지도 워치독이 알림**: 알 수 없는 `PIPELINE_PAUSE` 값은 점검을 이어 가며 '발행 정지 변수 값을 알 수 없다' 는 심각 알림(`PAUSE_UNKNOWN`) 한 건을 더합니다 — 고정 문장(받은 값을 싣지 않음), 같은 알림이 열려 있는 동안 새로 만들지 않고 48시간에 한 번 이하. 알려진 켜짐 값(`true`·`1`·`yes`·`on`)은 지금처럼 조용합니다.
**권한·시크릿·다른 트리거·광고·레지스트리 값(`blogs.json`)·영문 프로필·발행 정지 변수는 바꾸지 않았습니다.**

## 2. 승인안과 달라진 한 곳 — 용량 패턴의 자릿수 상한
승인안(BP2 보고서)의 숫자 단위 패턴 중 **용량(`mg`·`mcg`·`μg`·`iu`) 패턴은 정수부 상한 9자를 두기로 했었는데, 상한 없이 앞 경계만 두는 것으로 달라졌습니다.** 이유: 상한이 있으면 기존 `test_quality_shadow` 시험 셋(숫자를 줄여도 안 줄여도 같은 규칙이 걸려야 함)이 깨졌고, 시험을 상한에 맞춰 고치면 기존 시험의 보장이 줄어 약화가 됩니다(그 시험 파일은 기준과 글자 그대로 같습니다). 앞 경계가 속도를 이미 지킵니다(독립 확인이 길이 열 배에 10.4배, 64,000자 0.012초로 선형임을 직접 재었고, 옛 패턴은 제곱). 상한이 없으면 옛 패턴과 같은 판정이 되어 **검사가 더 엄격해지는 쪽**이라 안전을 줄이지 않습니다. 퍼센트(9)·가격(20)·이메일(64·63) 한도는 승인안 그대로입니다. 이 한 곳이 마음에 안 드시면 병합하지 말고 알려 주세요.

## 3. 병합 전 한 가지 확인 부탁 — 저장소 변수 `PIPELINE_PAUSE`
GitHub 저장소 설정의 `PIPELINE_PAUSE` 변수의 **현재 값이 `true`·`1`·`yes`·`on` 중 하나이거나 비어 있는지** 한 번 봐 주세요(AI 는 변수를 읽을 수 없습니다). 그 밖의 말이면 병합 뒤 첫 워치독이 위 ④ 의 오타 알림(빨간 실행과 폰 알림)을 한 번 보냅니다 — 오타를 잡은 것이니 값을 고치시면 알림 이슈가 닫힙니다. 값이 `true` 라면 아무 일도 없습니다.

## 4. 사용자가 체감하는 변화
**지금 발행이 정지돼 있어 글·사이트·알림은 그대로입니다.** 발행을 다시 켜는 날 ①이 잘못된 설정으로의 해제를 막고 ④가 오타를 알립니다.

## 5. 위험과 알려 둔 한계
- **옛 패턴과 의미가 달라지는 입력**(저장소 텍스트 파일 672개에서 옛·새 매치가 다른 것은 4건뿐이고 모두 새 시험이 일부러 만든 입력이며, 합성 입력 28,584건·무작위 12만 문장에서 다른 것은 모두 아래 알려진 좁아짐 — 설명 안 되는 차이 0): 퍼센트 정수부 10자리 이상, 가격 숫자 열 21자 이상, 이메일 로컬파트 65자 이상·도메인 칸 64자 이상, 소수부 한가운데에서 숫자가 다시 시작하는 꼴(`5.5.5%` 등). 용량은 상한이 없어 옛 패턴과 같습니다.
- **승인 밖이라 묶지 않은 것**: `body_safe_veto_patterns` 둘(면제 취소)은 숫자 N자 + `x` 에서 4,000자 1.18초·0.279초로 여전히 제곱입니다(상담 구절이 든 긴 숫자 절에서만 닿는 낮은 위험 — 후속 T3 제안, 결함 D-431 에 적음).
- **워치독 알림**: 사람이 `PAUSE_UNKNOWN` 이슈를 닫아도 변수 값이 그대로면 다음 점검에 새로 만들어져 한 번 더 알립니다(값을 고치거나 지우면 이슈가 자동으로 닫힘).
- **AI 쪽 실수 하나(이미 알림 P116 에 공개)**: 구현자의 시험 한 번이 접속 차단 러너 도입 전에 돌아 글감 사실 수집 경로(NOAA 공개 자료 읽기)로 가려다 중단됐습니다. 실제 접속은 기록이 없고 영향은 공개 자료 읽기 시도뿐(비밀·사진·쓰기 없음). 이후 모든 시험은 루프백만 허용하는 러너로 돌렸습니다.
