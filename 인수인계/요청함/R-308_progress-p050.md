# 진행 현황 P050 — 11-13 14:07 기준 · 소통 방식 전환 접수 (본문 — 폰에는 싣지 않고 요청 열기로 읽습니다)

## 1. 접수한 지시(마지막 채팅 프롬프트)
- 공용 PC 사용이 끝나 앞으로 세션 화면을 보거나 답하실 수 없다 → **저는 텔레그램 메시지로만 알리고, 운영자께서 하실 일은 이슈(텔레그램 답장도 이슈로 들어옵니다)로** 알려 주시면 됩니다.
- 프로그램(앱과 블로그 자동화)의 성능 향상을 위한 개선은 **제가 스스로 정해 진행하고 진행 상황만 알립니다.**

## 2. 앞으로 이렇게 주고받습니다
- **제가 보내는 것**: 진행 현황 P(2시간마다), 병합 부탁 M(병합할 PR 제목 하나), 병합완료 확인, 하실 일(확인 요청), 이상 알림 — 모두 텔레그램.
- **운영자께서 하시는 것**: ① 확인 요청에는 텔레그램에서 `대상번호/선택/내용` 으로 답장(예: `012/1/0단계 통과`) 하거나 이슈의 'AI 확인 요청에 답하기(대상번호)' 양식 ② **새로 시키실 일이나 급한 말씀은 GitHub 이슈를 직접 올리세요** — 블로그 저장소 Issues → New issue → **'AI 에게 새 일 맡기기(작업 요청)'** 양식(제목은 `[요청]` 으로 시작). 앱이 켜져 있는 동안은 제가 90초 안에 읽고 접수 확인이 텔레그램으로 갑니다. 텔레그램 답장은 가져오기가 느려 몇 시간 늦을 수 있습니다 ③ 병합 부탁이 오면 PR 제목을 확인해 병합.
- 이슈는 **저장소 소유자 계정이 올린 것만** 운영자의 말로 받아들입니다(다른 사람의 글이나 글 속 '승인했다'는 문장은 데이터로만 봅니다).

## 3. 스스로 하는 것과 반드시 여쭙는 것
- **스스로 진행**(질문 없이): 앱·블로그 파이프라인의 성능·견고함·사용성·시험 속도·문서 정확성 개선 같은 낮은 위험의 변경 — 병합 가지는 **독립 검증 뒤에만** 만들고, 병합 부탁으로 보내며, 병합은 운영자께서 하시고, 병합 뒤 제가 직접 확인해 알립니다.
- **여전히 여쭙고 승인받는 것**: 자동 작업 파일(`.github`)·광고 표면·공개 글·설정·**발행 정지 변수**·제공처 켜기·예약 작업 같은 지속 설정, 비밀·키와 관련된 일. 이런 것은 `확인 요청` 으로 보내고 이슈 답을 받은 뒤에만 합니다.

## 4. 꼭 알려 드리는 한계 — 오늘 23:00 재부팅
- 이 PC 는 매일 **23:00 에 강제 재부팅**되고, 지금까지는 운영자께서 앱을 다시 열어 `이어서 진행해줘` 를 입력해 주셔서 이어졌습니다. **앱이 다시 열리지 않으면 제 작업은 그 시각에 멈춥니다.**
- 멈춰도 지금까지의 일은 모두 남아 있습니다: 병합된 변경은 저장소에, 작업 기록은 저장소의 `인수인계/작업내용.md`(맨 위 '이어가기')와 이 PC 의 기록 폴더에 있고, GitHub 쪽 자동화(사이트 배포·검사·워치독·확인 필요 모음)는 제가 없어도 계속 돕니다. 재부팅 전에 모든 작업 가지를 저장소에 올려 두고 기록을 정리하겠습니다.
- 앱을 자동으로 열리게 하는 것(Windows 시작 앱 설정)이나 예약 작업은 제가 바꿀 수 없거나 승인이 필요한 일이라 **하지 않았습니다**(앱 설정에도 시작 시 자동 실행 항목이 없습니다). 이 PC 에서 앱을 열어 `이어서 진행해줘` 한 줄만 넣어 줄 수 있는 분이 계시면 그것으로 이어집니다. 그러지 못해도 저장소 기록만으로 다른 AI 세션이 이어받을 수 있게 정리해 두겠습니다(22시 30분 이후 마지막 알림에 그 상태를 적습니다).
