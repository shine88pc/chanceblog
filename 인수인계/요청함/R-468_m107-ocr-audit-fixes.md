# 병합 요청 M107 — 글자 읽기 안전 감사 권고 처리 (앱)

> **병합 방식**: 지금은 AI 병합 기능이 **꺼져 있어** 운영자께서 직접 병합해 주세요. (`M107 승인` 이라고 답하셔도 아직 AI 가 병합하지 않습니다.) 이 요청은 앱 저장소 `chanceblog-desktop` 의 것이고, PR 제목 맨 앞이 `[M107]` 인 것 하나만 병합합니다. 검사는 이미 끝나 초록입니다. 급하지 않습니다(보통).

## 1. 무엇을 바꾸는지
합쳐진 앱의 글자 읽기를 독립 감사자가 적대적으로 읽은 결과(**불변 조건 일곱 가지는 깨지지 않음** — 사진·글자가 PC 밖으로 나가지 않음·클라우드 0·결과 보존 기본 꺼짐·꺼짐 상태 부작용 0 등)의 권고 중 지금 고치기로 한 것입니다. **글자 읽기는 꺼진 채이고 앱 화면·기능은 바뀌지 않습니다.**
① **프로세스를 끄는 명령을 절대 경로로**: 시간 초과·취소·종료 때 작업자를 끄는 `taskkill` 을 이름만으로 부르면 현재 폴더에 둔 가짜 파일이 실행될 수 있어서, 윈도에 직접 물은 시스템 폴더의 절대 경로로 부릅니다(환경 변수 값은 그 폴더와 같을 때만 믿음).
② **작업 제한 장치를 못 만들면 작업자를 띄우지 않음**: 작업자의 메모리 한도(1GB)와 '앱이 죽으면 작업자도 종료' 를 맡는 윈도 장치(Job 개체)에 못 넣으면, 한도 없이 도는 것보다 쓰지 않는 쪽(안전한 기본값)으로 끝냅니다.
③ **소켓 가드 위 감사 훅 한 겹**: 추가 도구의 네트워크 차단(소켓 가드)이 못 보던 `_socket` 직접 호출도 같은 규칙으로 막고 세는 층을 더했습니다(켜짐 표시로만 일함 — 훅을 못 걸면 작업자가 시작하지 않음).
④ **작은 보강**: 추가 도구 폴더 확인이 정보 파일의 이상한 값에서 예외를 새지 않고, 폴더 안(중첩 포함) 디렉터리 링크를 문제로 셉니다.
⑤ **안내 문구·문서 정정**: 읽은 글 안내가 실제 입구 검사 범위(주민·카드 번호·키 모양·태그·긴 줄·눈에 보이지 않는 글자)와 저장 동작('확인해 초안에 넣은 글은 초안과 함께 저장돼요')에 맞게 바뀌었고, `docs/SECURITY.md` 에 켜기 전 한계와 할 일을 적었습니다.

## 2. 왜 필요한지
운영자께서 글자 읽기를 켜기 전에 안전 쪽 약한 고리를 미리 줄이는 단계입니다. 이 병합은 켜는 것이 아니라(켜기는 별도 번호 요청) 켜도 되는 상태에 더 가깝게 만드는 것입니다.

## 3. 사용자가 체감하는 변화
**없습니다.** 글자 읽기가 꺼진 채라 화면·기능은 그대로입니다(켜졌을 때의 안내 문구만 더 정확해짐).

## 4. 위험과 기존 기능에 미치는 영향
- **기존 기능**: `.github/`·잠금 파일·모델 잠금·`EMBEDDED_FILES`·고지문 빌드 코드·`LOCAL_OCR` 는 바뀌지 않았습니다. 앱 쪽은 작업자 실행 코드(`ocr_adapter`)·추가 도구 확인·문구·새 작은 파일(`ui/winroot.py`)입니다. 이 PC 의 진짜 `--selftest` 를 새·옛 가드 모두에서 6회 돌려 `ok`·정상 읽기 시도 0 이었습니다.
- **알려 둔 한계**: ① **리눅스 칸**은 이 PC(윈도)에서 못 돌려 앱 검사(CI)로 확인합니다(윈도 전용 시험은 다른 칸에서 건너뜀). ② 켜기 전에 남은 일 — 작업자 실행 파일 해시를 앱 소스에 고정하는 일은 **켜기 변경 때** 같이 합니다(진짜 값은 운영자 첫 수동 실행 결과로 정해짐). ③ 윈도 오류 보고·운영체제 수준 격리(낮은 무결성·AppContainer)·윈도 asyncio 한계는 문서에 한계로 적었습니다.
- **운영자께 여쭐 것(급하지 않음, 이번 병합과 별개)**: ① 전화번호·이메일·주소 모양 줄을 가리지 않고 '맞아요' 를 누를 때 **한 번 더 경고**만 할지 — **추천: 경고만**(켜기 요청 때 함께 여쭙겠습니다) ② 켜기 변경에 작업자 실행 파일 해시 고정을 같이 넣을지 — **추천: 같이 넣기** ③ AppContainer 별도 설계를 할지 — **추천: 지금은 안 함**.
