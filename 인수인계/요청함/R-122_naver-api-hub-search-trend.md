# [R-122] NAVER API HUB 검색어 트렌드 연동 — 점검 결과와 결정 7가지

> **지금 하실 일은 없습니다.** 문서(§14)가 요청한 대로 **코드는 아직 바꾸지 않고** 현재 상태와 영향 범위부터 점검했습니다. 데스크톱 GUI·초안 작업은 멈추지 않았습니다. 결정 7가지는 모두 기본값이 있어 답이 없으면 기본값으로 진행합니다.
> 답하는 방법: 텔레그램의 **[답하기]** → 요청 번호 `r122` → 답변 **승인** → **선택** 칸에 `A=1 B=0 C=1 D=1 E=1 F=1 G=0` 처럼 적기(안 적은 항목은 기본값). 채팅으로 말씀해 주셔도 됩니다. 문서 원문은 저장소에 올리지 않았고 이 글은 제 말로 요약한 것입니다.

## 한눈에
1. **네이버를 부르는 코드는 아직 한 줄도 없습니다.** 다만 '연결 설정'에 네이버 오픈 API 자리가 **옛 방식 가정**(하루 25,000회·예비 키로 넘어가기 허용·'제3자 문서 기준' 한도)으로 비어 있어, 문서의 기준(월 한도·키 돌려쓰기 금지)에 맞게 **고쳐야** 합니다.
2. **이미 있는 안전장치**: 키는 윈도 자격 증명 관리자에만 저장, 한도 안전장치(우선순위별 절약·잠금/쓰기 실패 시 호출 안 함), '연결됨·연결 확인 필요·요청 한도 도달·인증 정보 오류·연결 안 됨' 5가지 상태 문구(문서의 5가지와 뜻이 같음), 키 없이도 후보 만들기. **모자란 것**: 월 단위 한도, 시도/성공을 나눈 기록, 사용량 파일이 깨졌을 때 '막힘'(지금은 절반 썼다고 보고 계속함), 시계가 되돌려진 것 감지, 설정 화면(화면 자체가 아직 없음).
3. **공식 문서 확인(11-04)**: 주소·헤더·요청 항목은 문서와 같습니다. 문서와 다르거나 문서가 모르는 점 4가지 — ① **무료는 '한시적'**(종료일 공지 없음, 유료 전환은 사전 공지, 단가 미공시) ② 검색어 트렌드 월 한도는 **최대 50,000회**(운영자님 30,000회는 범위 안), 한도 도달 시 호출 차단, 한도 상향은 무료 기간에 불가, 알림은 공식 안내상 50·80·100% ③ `ratio` 는 **한 번의 조회 결과 안에서 가장 큰 값을 100으로 한 상대값** — 호출이 다르면 값끼리 비교할 수 없음 ④ **저장·캐시·AI 입력 약관은 확인하지 못했습니다**(이 PC 의 조직 정책이 해당 사이트의 브라우저 접속을 막고, 정적 수집은 약관 목차만 줍니다).

## 문서와 현재 코드가 어긋나는 곳 (제가 고칠 것)
- **키 돌려쓰기**: 지금 네이버 자리는 한도·일시 오류 때 허용된 다음 키로 넘어갈 수 있는 설정이고 용도마다 키 3개까지 받습니다 → 문서는 금지. **이 용도는 키 1개·다른 키로 넘어가기 끔**(Unsplash 와 같은 방식).
- **한도**: 하루 25,000회(제3자 문서 기준)는 옛 오픈 API 가정 → **월 단위(내부 월 27,000·일 100)** 로 교체.
- **상대 지수**: 후보 모델의 '월간 검색 수요(회)' 칸은 실제 횟수를 담는 칸입니다. 검색어 트렌드 값은 **그 칸에 넣지 않습니다**(문서도 금지). 채울 수 있는 칸은 '최근 관심도 변화'(상승·보합·하락)와 '계절성'(관심이 몰리는 달)뿐입니다.
- **비교 한계**: 한 번에 5개 그룹(그룹당 키워드 20개)까지라 후보가 5개를 넘으면 매번 같은 기준 키워드 하나를 넣어 나눠 부르는 방식이 필요하고, 그만큼 호출이 늘어납니다(하루 20개 후보여도 5~6회 — 내부 일 100회에 한참 못 미침).
- **인터넷 호출**: 이 앱에는 공개 페이지 확인용 호출 코드(키 없음)만 있습니다. 키가 들어가는 호출은 시간 제한·크기 상한·주소 이동 거부를 갖춘 **전용 클라이언트를 새로 만들어야** 합니다.
- **보조 저장소(DPAPI)**: 문서의 2순위 항목 — 지금은 없고 만들지 않는 쪽을 권합니다(결정 E).
- **설정 화면**: 'NAVER API HUB' 카드는 GUI 의 설정 화면이 만들어질 때 함께 들어갑니다(명령줄 `keys` 는 지금도 있음).
- **알림 비율**: 공식 안내는 50·80·100% 입니다. 문서의 '50%부터 10% 단위'는 콘솔 화면에서 보신 설정이라면 그대로 두세요(차이만 알려 드립니다).

## 영향 범위(제안, 코드는 아직 안 바꿈)
- **1단계 '안전 틀'(인터넷 호출 없음)**: `service/connections.py`(용도 정정·키 1개·월 창 선언), `service/quota.py`(월 창·시도/성공 계수·막힘 규칙·시계 되돌림·장부), `service/format.py`·`service/cli.py`(사용량 표: 오늘·이번 달·내부 한도·콘솔 한도·마지막 성공·마지막 오류·중지 사유), `security/shape.py`(키 모양), 문서(`SECURITY.md` §7·`ARCHITECTURE.md` 표·`DECISIONS.md` 새 결정), 시험(월 창·막힘·시계·가림·키 순환 금지·안 부르는 것).
- **2단계 '실제 호출'**: 새 `service/` 모듈(요청 만들기·검사·응답 읽기·표현 변환 — '월간 검색량·실제 횟수' 같은 표현 금지 검사 포함), 전용 클라이언트(맨 값 정확 가림 장치 포함), 후보 제안 뒤의 선택적 보정 단계, 가짜 서버 시험(진짜 네이버 호출 없음), 1단계 병합 + 약관 확인 뒤.
- **시험**: 문서 §15 의 16개 완료 기준을 시험 이름으로 하나씩 대응시키고, 일부러 어겨 보는 변이 점검과 독립 검증을 거칩니다.

## 결정해 주세요 (기본값 있음)
- **A 구현 순서**: `1` **2단계로 나눠 진행**(기본 — 1단계 '안전 틀'을 먼저 독립 검증 뒤 병합 부탁, 실제 호출은 약관 확인 뒤) / `2` 한 번에 / `0` 지금은 하지 않음(GUI·초안 작업 먼저)
- **B 약관(결과 저장·캐시·AI 입력·수익형 활용)**: **운영자님이 'AI·Naver API 서비스 이용약관'(및 데이터랩 이용 조건) 본문에서 확인해 알려 주세요** — 저장해도 되는 기간, 파생 분석·AI 입력 허용 여부. `1` **확인 전까지 저장·캐시 끔, AI 입력 안 함, 화면에만 표시**(기본) / `2` 확인했고 허용 범위를 채팅으로 알려 드림
- **C 무료 기간 종료 대비**: `1` **콘솔 월 한도 30,000 유지**(비용 상한 역할)하고 유료 전환 공지는 제가 정기 점검에서 읽어 알려 드림(기본, 읽을 수 있는 범위에서) / `2` 월 한도를 더 낮춤(콘솔에서 직접)
- **D 한도 단계의 기준**: `1` **콘솔 30,000 기준**(70%=21,000 안내·80%=24,000 자동 중지·90%=27,000 = 내부 월 한도에서 신규 호출 중지, 일 100회)(기본) / `2` 내부 27,000 기준(70%=18,900…)
- **E 키 보관**: `1` **자격 증명 관리자만**(기본 — 비밀이 파일에 놓이는 길을 열지 않음, 못 쓰면 키 없이 계속) / `2` DPAPI 보조 저장소도 만듦
- **F 기존 네이버 오픈 API 자리**: `1` **교체**(기본 — 이름을 'NAVER API HUB 검색어 트렌드'로, 키 1개·키 넘어가기 끔, 하루 25,000회 가정 삭제) / `0` 그대로 두고 새 용도를 따로 추가
- **G 키 모양(선택)**: 발급된 Client ID·Client Secret 의 **글자 수와 문자 종류만**(값은 절대 쓰지 마세요) 알려 주시면 입력 검사를 정확히 합니다. `0` 기본: 느슨한 검사(영숫자·`-`·`_` 8~128자) / `1` 알려 드림

## 알아 두실 한계와 투명성
- 공식 문서는 11-04 에 이 PC 의 도구로 읽었습니다. 요금 단가·실패 호출의 사용량 반영·월 초기화 시각(시간대)·오류 코드·약관은 공개 페이지에 없었습니다 — 그래서 월 경계는 안전하게(내부 월 한도가 콘솔보다 10% 낮음) 잡고, 실패 호출도 시도로 세어 보수적으로 막습니다.
- 콘솔 설정(가입·결제수단·Application·월 한도 30,000·알림)은 운영자님이 직접 하신 것이라 제가 확인할 수 없습니다.
- 지금은 어떤 코드·설정·실행도 바뀌지 않았습니다.
