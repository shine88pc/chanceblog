# 확인 요청 037 — 설치 파일 준비 (결정은 한 가지)

> 이 글은 **질문**입니다. 이슈 양식 '[답변] AI 확인 요청에 답하기' 에 **대상번호 037**(`37` 처럼 써도 됩니다)과 고른 보기(1·2)를 적어 주세요. **답이 없으면 2(보류)** 입니다. 승인하셔도 이 요청은 **`NO-MERGE-` 가지에 준비하는 것**까지이고, 병합 부탁과 워크플로 실행 부탁은 각각 따로 보냅니다(병합·실행은 운영자님만).

## 왜 필요한가
- 앱 v1.0(확인 035 ③)의 완료 기준 9·11·12번(업데이트 전 백업과 복구·설치형과 휴대용 실행·버전과 변경 이력 일치)에는 **정식 설치 파일**이 필요한데 지금은 코드가 0줄입니다.
- 설치 도구는 후보가 둘입니다 — Velopack(앱 결정 D-04 의 1순위)과 Inno Setup. 문서만으로는 이 앱에 무엇이 맞는지 정할 수 없어서, **같은 프로그램을 두 도구로 실제로 설치·업데이트·제거해 크기·시간·바이러스 검사 오탐·한국어·관리자 권한 요구를 재 보는 시험**이 먼저입니다. 문서 점수는 Inno 81·Velopack 66 이지만 D-04 는 측정으로만 뒤집고, 점수 차가 5점 이하면 D-04 를 따릅니다.

## 승인받으려는 것 (이것이 전부)
| 항목 | 무엇을 | 어디서·무엇을 받나 | 비밀·권한 |
|---|---|---|---|
| **a** 설치 도구 시험 | 수동 워크플로 **한 개**(운영자님이 'Run workflow' 를 눌러야만 돎): 일회용 GitHub 윈도 컴퓨터에서 같은 프로그램을 Velopack·Inno Setup 으로 설치·업데이트·제거해 보고 결과표를 올림 | **GitHub 일회용 컴퓨터에서만** 받음 — Velopack 도구 `vpk` 1.2.161(GitHub 의 Velopack 릴리스, 146,884,263바이트 ≈ 147MB, MIT, 비용 0)과 Velopack 파이썬 부품 1.2.161(PyPI, 1,363,140바이트 ≈ 1.4MB, MIT, 비용 0). **이번에 승인받지 않는 것**: 릴리스 워크플로(초안 릴리스·서명 키 시크릿 — 설치 도구 시험 결과가 나온 뒤 따로 여쭙니다)·서명·태그·공개·업데이트 확인 접속. 이 PC 와 운영자님 PC 에는 아무것도 받지 않습니다.

## 진행 방식과 운영자님 몫
1. 승인되면 AI 가 가지에 준비 → 독립 검증(안전·시험) → **병합 부탁**(T3) → 운영자님이 병합(새 워크플로 파일은 main 에 병합돼야 'Run workflow' 단추가 보임) → **실행 부탁** → 결과표를 읽고 도구를 정함.
2. 운영자님이 하실 일: 병합 한 번·'Run workflow' 누르기 한 번·(나중에) 운영자님 PC 에서 설치·제거 실기 시험(비개발자용 단계표를 따로 드립니다).
3. 되돌리기: 병합 전에는 가지만 지우면 끝이고, 병합 뒤에는 병합 한 번을 되돌리면 이전 상태입니다.

## 같이 알려 드릴 것
- 설치 도구용 패키지 ID 를 `ChanceBlogDesktop` 으로 하면 데이터 폴더 `ChanceblogDesktop` 과 윈도에서 같은 폴더가 되어, 제거할 때 **글이 지워질 수 있습니다**. 그래서 ID 는 `ChanceBlogDesktopApp`(제안)으로 하고 제품·실행 파일·키 저장 이름은 지금 그대로 둡니다 — 나중에 이름·라이선스 등을 묻는 확인에서 다시 확인받습니다.

## 1 을 추천하는 이유
- 설치 파일은 앱 v1.0 의 가장 긴 줄(크리티컬 패스)이라 도구 시험을 먼저 시작해야 나머지(업데이트·릴리스)가 이어집니다. 시험은 일회용 컴퓨터에서만 돌고 시크릿이 없으며 병합 전에는 main 에 아무 영향이 없습니다.
- 이 알림에는 운영자님 사진의 이름이나 읽은 글을 쓰지 않았습니다.
