## 무엇이 들어 있나 — 코드 묶음 여섯 개를 한 번에
병합해도 **프로그램 화면이나 설치 파일은 아직 생기지 않습니다.** 코드와 시험이 저장소에 들어올 뿐이고, 프로그램이 실행되지 않으니 블로그에 글이 올라가는 일도 없습니다. 지금까지 여섯 묶음을 따로 만들어 두었는데, 한 건씩 병합 부탁을 드리면 번거로우실 것 같아 하나로 합쳤습니다.
1. **글 만들기** — 원고를 Chance 블로그와 똑같은 글 파일로 계산합니다. 실제 한글·영어 글 두 편을 **글자 하나까지 똑같이** 만들어 내는 시험으로 고정했습니다.
2. **마크다운↔웹 글 변환** — 원고를 안전한 웹 글로 바꾸고, 이미 있는 글을 원고로 불러옵니다. 원고에 섞인 HTML·위험한 링크(`javascript:` 등)는 글자로만 보이게 막습니다.
3. **원고 보관함(SQLite)** — 이 PC 안에 원고를 저장·불러오기·판 기록·자동 저장 초안·백업·복구합니다. 깨졌거나 낯선 파일은 한 바이트도 바꾸지 않고 거절합니다.
4. **네이버 A/B 복사 꾸러미** — 제목 줄이기·태그 정리·이미지 자리 표시·고지문·체크리스트·금지 표현·글 길이 점검을 하고, 두 블로그 글이 너무 비슷하면 직접 승인을 요구합니다. 글을 AI 로 다시 쓰지 않습니다.
5. **안전 고치기** — 독립 검토 4번의 지적을 반영했습니다. git 이 멈추거나 내 파일을 덮어쓰지 않게 하고, 로그에서 키·비밀번호 모양을 가립니다.
6. **Pages 발행 + 배포 확인** — 승인된 글을 연결해 둔 chanceblog 사본에 쓰고 commit·push 하며, 올린 글이 공개 주소에서 열리는지 chanceblog 의 확인 도구로 봅니다. **블로그에 실제로 글을 올리는 코드라 가장 조심한 부분**입니다(봇이 먼저 올린 경우·main 이 아닌 경우·연결이 끊긴 경우도 시험으로 확인합니다).

## 확인한 것
- 전체 시험 680개가 모두 통과했습니다. 일부러 코드를 망가뜨려 보는 점검(변이 시험)도 했습니다 — 안전 고치기 217곳·마크다운 103곳·보관함 119곳·네이버 152곳·발행 122곳·배포 확인 56곳을 시험이 **모두** 잡아냈습니다.
- 발행(블로그에 올리는 코드)과 안전 고치기는 코드를 쓰지 않은 별도 AI 가 새로 받은 사본에서 읽고 돌려 보는 독립 검증을 각각 네 번 받았고 지적은 모두 고쳤습니다. 여섯 묶음을 하나로 합치는 작업은 제가 했고, 합친 결과를 위 시험과 자동 검사로 다시 확인했습니다.
- 자동 검사(Windows·Ubuntu × 파이썬 3.10·3.12, 4칸)가 이 브랜치에서도 모두 초록입니다. 이 브랜치의 내용은 합친 묶음과 같고, 결정 기록(D-20)과 이관 문서 한 줄만 더했습니다.
- 솔직한 한계: 발행 코드는 시험용 임시 저장소로만 돌려 보았고, 실제 chanceblog 에 대한 첫 발행은 프로그램 화면이 생긴 뒤 승인 절차를 거쳐 진행합니다.
