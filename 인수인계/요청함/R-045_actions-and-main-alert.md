## 이슈 #91 — "GitHub Actions 플랫폼 경고 4종, 업데이트 진행해줘"
- **무엇인가:** 모든 자동 실행(글 쓰기·Blogger·네이버·확인 필요 모음·사이트 배포…)은 GitHub 가 만든 공용 도구(`actions/checkout` 등)를 가져다 씁니다. 그 도구의 옛 판이 "곧 지원이 끝나는 Node.js 20"으로 돌아서 GitHub 가 모든 실행에 경고를 붙이고 있었습니다.

## 이슈 #90 — "알림이 적용이 안 되고 있다"
**확인한 사실:** 10-31 00:00~10:08 에는 알림이 갈 일이 없었습니다(알림이 가는 일: Chance 새 글, Blogger 초안 업로드·게시, '확인 필요 모음'의 새 해야 할 일, 제가 보내는 요청). 10-31 14:07 부터는 갈 일이 있었는데 못 갔습니다(발행 프로그램이 망가져 Blogger·네이버가 아무것도 만들지 않았고 — R-043 에서 되돌림). 더 큰 구멍은 **"문제가 생겼다"는 알림**이었습니다: 저장소 규칙·시험 검사는 그 변경에서 두 번 빨갛게 떨어졌지만 GitHub 알림과 '확인 필요 모음'(2~6시간 지연)으로만 갔고, 텔레그램 요청만 보시는 운영자는 이틀 동안 몰랐습니다.

**고친 것:** main 에 올라간 변경(직접 올린 것이든 PR 병합이든)이 규칙·시험 검사에 떨어지면 **곧바로 텔레그램 한 통**이 갑니다.
> 🚨 main 검사 실패 — 방금 main 에 올라간 변경(커밋 7자리, 올린 사람)이 저장소 규칙·시험을 통과하지 못했습니다. Blogger·네이버 발행이 멈췄을 수 있습니다. GitHub 에서 직접 고치지 마시고, AI 에게 [요청]으로 '확인해 달라'고 맡겨 주세요. [실행 열기] [AI 에게 요청하기]
- 알림이 오면 **하실 일은 [AI 에게 요청하기] 버튼으로 "main 검사 실패 알림이 왔어요, 확인해 주세요"라고 맡기시는 것**뿐입니다. 직접 고치지 않으셔도 됩니다.
- PR 검사(병합 전)가 떨어진 것과 자동 글 올리기(봇 커밋)는 알리지 않습니다. 알림은 보조라 알림 단계가 실패해도 검사 결과·글 발행에는 영향이 없습니다. 비밀 값은 화면에 나오지 않습니다.
- **한계(솔직하게):** ① 검사가 우연히 한 번 실패한 경우에도(예: 네트워크) 알림이 갈 수 있습니다 — 그때는 "지나가도 됩니다"라고 안내드립니다. ② 망가진 변경이 알림 프로그램이 쓰는 파일 다섯 개를 망가뜨리면 이 알림도 못 갑니다(그 경우 기존 '확인 필요 모음'이 2~6시간 뒤 알립니다). ③ 실제 GitHub 에서 처음 한 번은 아직 돌려 보지 못했습니다 — 실제로 검사가 떨어지는 일이 생겨야 확인됩니다.

## 위험과 대비 (솔직하게)
- **#91 은 모든 워크플로에 닿는 변경입니다.** 제가 쓰지 않은 AI 가 새 버전의 공식 설명서·입력 이름·동작을 따로 확인했고(Node 24, 기존 입력·출력 그대로, `git push` 그대로 동작) 전체 시험 4443개(629초)·문법 검사·규칙 검사를 통과했습니다. 판정: #91(액션 버전)과 #90(알림) 모두 '병합 가능(메모 있음)' — 지적 사항은 모두 반영했고 알림 쪽은 고친 뒤 다시 검토받았습니다. 다만 **글을 올리는 `git push` 와 사이트 배포는 병합 전에 실제로 돌려 볼 수 없습니다.**
- 그래서 **병합 뒤 제가 직접 지켜봅니다**: ① 병합 직후 사이트 배포(빌드·배포·반영 확인) ② 다음 Chance 글 실행이 글을 올리는지(매시 예약) ③ 다음 Blogger·네이버 실행. 이상이 보이면 이 변경 한 건을 되돌리는 병합 부탁을 바로 드립니다(되돌리면 원래대로입니다).
- 급하지 않으니 **병합은 저녁에 하셔도 됩니다.** 병합하신 시각을 알릴 필요는 없습니다 — 제가 직접 확인합니다.
- 결정할 것은 아직 없습니다. 참고: main 에 직접 올리지 못하게 잠그는 GitHub 설정은 자동 글 올리기까지 막을 수 있어 **지금은 하지 않기로** 하고(기본값), 이번 알림으로 보완합니다.
