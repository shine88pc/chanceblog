## 이번 묶음이 하는 일
운영자 개인 PC 필수 시험('Profile·Seed·초안 저장 → 재실행 후 복원')의 핵심이고 개인 PC 제한 사용 Package 의 Gate 항목(초안 저장·Secret 저장 방지·Backup 에 초안 포함)을 닫습니다.
- **초안 저장**: 초안 작성 화면의 `저장`(Ctrl+S)으로 만든 초안을 기존 글 보관함(`chanceblog.db`)에 저장하고(보관함 구조 변경 없음 — 백업·되돌리기에 자동으로 따라감), `저장한 초안` 목록(제목·후보·저장 시각·글자 수)에서 다시 열어 이어서 고치거나 확인창 뒤에 지웁니다. 저장 상태 줄('저장됨/저장 안 됨' — 색만으로 전하지 않음)이 있고, 초안 화면을 떠나거나 후보를 바꾸거나 앱을 끝낼 때 세 갈래 확인창(저장 / 저장 안 하고 나가기 / 계속 고치기)이 뜹니다. 홈의 '작성 중 초안' 수와 연결됩니다. 앱을 다시 켜도 바이트까지 같게 복원됩니다.
- **저장 직전 비밀 모양 검사**: 앞서 병합한 보안 수정(M052)의 스캐너(Google API Key·GitHub Token·Bearer·OAuth·AWS 키·PEM 개인 키 여섯 종류)로 제목·본문·키워드·태그·요약과 만든 초안 칸·후보 번호·분야를 훑고, 키 모양이 있으면 **보관함 파일을 열기 전에 저장을 멈추며** 위치(칸·줄)와 유형만 알립니다(자동 삭제·'무시하고 저장' 없음). 확인과 쓰기는 한 번에 처리해 두 창이 동시에 저장해도 한도(300편)를 넘지 않습니다.
- **백업과 맞물림**: 저장한 초안은 앞서 병합한 전체 백업·복원(M054)에 함께 담기고, 백업 전 비밀 모양 검사가 저장한 초안까지 풀어서 훑어 옛 데이터에 키 모양이 있으면 백업을 거절하고 위치만 알립니다.
- **네이버 글쓰기 열기 폴백**: 옛 네이버 프로필이 있으면 지금과 같은 동작이고, 옛 프로필에 주소가 없을 때만 채널 프로필의 블로그 주소로 열기 단추를 켭니다(허용 호스트 `blog.naver.com` 만 — 다른 호스트·유사 호스트·`@`·포트·스킴 변조 주소는 거절).
- **main 에 숨어 있던 빨간 시험 1건도 고쳤습니다**: 보안 수정(M052)이 후보 쓰기에서 키 모양을 거절하게 한 뒤, 화면 보안 시험 하나가 키가 든 옛 후보를 쓰기 길로 만들다 멈췄습니다(검사에는 화면 시험 도구가 없어 드러나지 않았음). 옛 데이터를 흉내 내도록 보관함에 직접 넣게 고쳤고 '화면에 도달하지 않는다' 단언은 그대로입니다. 이 PC 에서 화면 시험 41모듈 2,107개를 전부 돌려 빨간 것이 이 1건뿐임을 확인했습니다.
- **앱 안의 로컬 동작만**입니다. 새 외부 호출·키·네트워크·AI·글 올리기는 없습니다(소스와 시험으로 확인).

## 눈에 보이는 변화
- **운영자 PC 의 블로그·자동 실행은 그대로입니다.** 이 변경은 데스크톱 앱 안의 동작이라 개인 PC 로 옮길 시험용 Package 에 들어가야 보입니다. 보이게 되는 것: 초안 화면의 `저장` 단추·저장 상태 줄·`저장한 초안` 목록·떠날 때 확인창, 홈의 작성 중 초안 수.

## 솔직한 한계 (문서에 적음)
- **저장한 초안은 암호화되지 않은 평문 보관함**입니다(같은 PC·같은 계정의 보호에 기댐 — 그래서 키·키 모양 글은 저장 자체를 멈춥니다). 실제 Windows 125·150% 배율·글자 입력기(IME)·화면 읽기·전원 차단은 시험에서 모의까지만 했습니다.
- 독립 검증이 남긴 **정보 수준 후속 둘**: 이유 칸의 글자 가림을 못박는 시험 하나, 저널이 남지 않는 환경에서 자동 복구 길을 지키는 결정적 시험 하나(둘 다 지금 동작은 맞고 시험 보강입니다).
- 화면 시험은 검사(CI)에 PySide6 가 없어 건너뛰어집니다 — 그래서 병합 전에 이 PC 에서 화면 시험을 직접 돌려 확인했습니다(검사 12칸이 보는 것은 화면 없는 시험 전부입니다).
