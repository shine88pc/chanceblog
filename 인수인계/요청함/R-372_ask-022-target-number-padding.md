# 확인 요청 022 — 이슈 #216: 대상번호에 19 만 써도 되게 고쳐도 될까요 (결정은 한 가지)

> 이 글은 **질문**입니다. **이번에는 꼭** 새 양식 'AI 확인 요청에 답하기(대상번호)'(대상번호 **022**·선택 ②)나 이 세션 채팅의 `022/2` 로 답해 주세요. 지금 코드는 대상번호를 세 자리로만 읽으니 `22` 가 아니라 `022` 로 쓰셔야 합니다. **답이 없으면 1(하지 않음)** 입니다.

## 이슈 #216 두 가지에 대한 답
**① 병합완료 알림이 M076 뒤로 안 왔다**: 맞습니다. M077(보관함) 병합완료 확인은 병합(19:28) 뒤 앱 main 의 자동 검사가 12분 28초 걸려 끝나길 기다렸다가 19:43 에 `R-371` 로 나갔습니다(M076 도 같은 방식으로 병합 11분 뒤에 나갔습니다). 이 대기가 운영자님께는 '알림이 안 온다'로 느껴졌고 제가 미리 알리지 않았습니다. **앞으로는 이렇게 하겠습니다**: 병합이 보이면 2분 안에, 병합 내용이 검증한 가지와 같은지(트리)와 변경 파일이 맞는지를 확인한 뒤 '병합완료 확인 - 정상' 을 먼저 보내고, 병합 뒤 main 검사는 따로 지켜보다 빨갛게 되면 그때 이상을 알립니다. 지금처럼 검사까지 기다린 뒤 보내는 쪽을 원하시면 알려 주세요(이 부분은 코드가 아니라 제 작업 순서라 승인 없이 바꿉니다).
**② 019 를 19 만 써도 되게**: 아래 질문입니다.

## 지금은 어떻게 읽나
새 양식의 `대상번호` 는 접수 코드가 숫자 **세 자리**(001…999, 1000번부터는 네 자리)로만 읽고, `19` 처럼 짧으면 '`대상번호`는 숫자 3자리로 써 주세요(예: 001)'로 거절합니다. 앞에 0 을 더 붙인 것(`0019`)도 거절합니다. 승인은 이 번호가 AI 가 보낸 요청의 번호와 같고, 선택이 그 요청의 승인 보기와 같을 때만 인정합니다.

## 선택지
1. **하지 않음(기본)** — 지금처럼 세 자리(019)로 씁니다.
2. **고침** — 숫자만 쓴 대상번호의 앞을 0 으로 채워 세 자리로 맞춰 읽습니다(1→001, 19→019, 135→135, 1000 이상은 그대로). 접수 답글에 '019 로 읽었습니다'를 적어 잘못 읽었으면 바로 알 수 있게 합니다. 숫자가 아니거나 P·M 으로 시작하는 번호, 번호가 둘인 글, 숫자 사이에 문자가 낀 글은 지금처럼 거절합니다.

## 2 를 고르시면
- 바뀌는 곳(어림 10개 파일): 접수 코드 `pipeline/operator_loop.py`(대상번호 읽기·거절 문장)·접수 확인 답글 문구(`pipeline/notify.py`)·양식 안내 문장 `.github/ISSUE_TEMPLATE/ai-answer.yml`('숫자 3자리' → '19 만 써도 됩니다')·`scripts/validate_repo.py`(양식 검사)·시험과 문서. 입력 칸·승인 규칙·소유자 확인은 바꾸지 않습니다.
- **승인을 읽는 코드와 `.github` 아래 양식을 고치는 일이라 변경 등급 T3** — 구현자와 다른 AI 의 독립 검증을 거쳐 병합 부탁을 보내고 **운영자께서 직접 병합**합니다. 확인 021(옛 양식 없애기)을 승인하시면 같은 묶음으로 한 번에 검증·병합하겠습니다. 시작은 보관함·블로그 관리 병합 부탁이 정리된 뒤, 내일 오전을 예상합니다.
- 위험은 낮습니다: 번호는 양의 정수 하나이고 앞의 0 은 자리 채움뿐이라 같은 번호를 두 가지로 읽을 길이 없고, 달라지는 것은 지금 거절되던 짧은 입력이 받아들여진다는 점뿐입니다. 접수 답글에 읽은 번호를 적어 오독을 즉시 알 수 있게 하고, 승인은 여전히 그 요청의 승인 보기를 직접 골라야 합니다.
