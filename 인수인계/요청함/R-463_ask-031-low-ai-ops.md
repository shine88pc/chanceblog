# 확인 요청 031 — 감시·알림 운영을 어떻게 바꿀까요 (결정은 한 가지)

> 이 글은 **질문**입니다. 이슈 양식 '[답변] AI 확인 요청에 답하기' 에 **대상번호 031**(`31` 처럼 써도 됩니다)과 고른 보기(1·2·3)를 적어 주세요. **답이 없으면 3(AI 쪽만 바꿈)** 입니다.

## 무슨 일인가 (AI 의 사실 정리)
- **지금 방식**: AI 세션이 감시기 둘(저장소 main 머리·운영자 이슈)과 2시간 알림 크론으로 계속 켜져 있고, 병합·검사 대기마다 알림을 받아 일합니다. AI 는 알림이 올 때마다 쌓인 대화(약 62만 토큰 분량)를 다시 읽고 반응합니다.
- **숫자(이 PC 기록 기준)**: 오늘 07–13시 알림 이벤트 약 115건 중 93%(107건)가 감시기 시작·만료·명령 끝남 같은 **기계적 알림**이고, 어제(11-22)는 하루 1,600건 넘게 왔습니다. 에이전트(구현·검증) 한 번도 40–85만 토큰이라 하루 수십 번이면 매우 큽니다. 이 방식은 회사 계정의 추가 사용량으로 돌고 있고 이미 한도의 상당 부분을 썼습니다(수치는 채팅으로 알려 드렸습니다).
- **개인 PC·무료 AI 한도**: 무료 플랜은 메시지·시간 한도가 훨씬 작고, PC 가 꺼지거나 잠들면 감시기도 멈춥니다. 그래서 지금 방식은 **사실상 지속이 어렵다**고 봅니다(AI 의 판단).
- **이미 AI 없이 도는 것**: 요청 파일→텔레그램 알림(저장소에 올리는 즉시)·운영자 이슈 접수와 봇 응답·병합 부탁 PR 자동 만들기·확인 필요 모음(2시간마다)·발행 중단 감시·병합 뒤 사이트 배포. 모두 GitHub 이 대신 돌려 **PC 가 꺼져도 되고 무료**입니다.

## 제안 (추천 = 2)
- **AI 쪽 변경(승인 없이 바로 적용 — 이미 일부 적용함)**: 감시기를 하나로 합치고 시작·만료 알림을 없앰(AI 가 깨어나는 횟수 4분의 1)·AI 는 '일이 있을 때만' 켜서 짧게 일하고 닫음·검증 에이전트는 갈래당 1명(안전+시험 겸임)·문서만 바꾸는 묶음은 에이전트 없이 검사(CI)와 자동 점검만.
- **GitHub 쪽 새 알림 둘(`.github` 변경 = 운영자 승인 필요)**: ① **병합 부탁 자동** — AI 가 올린 병합 가지의 검사가 모두 초록이 되면 PR 본문의 요약으로 병합 부탁 알림을 자동으로 보냄 ② **병합완료 확인 자동** — main 에 병합이 들어오고 main 검사가 끝나면 '병합완료 확인 - 정상/이상' 을 자동으로 보냄(병합 커밋이 부모 하나·변경 파일이 PR 과 같은지도 함께 봄). 둘 다 비밀·새 외부 접속·새 키 없이 기존 텔레그램 알림 길을 그대로 씁니다.
- **그 밖**: 진행 현황(P)은 AI 가 켜져 있는 동안만, 변화가 있을 때만 보냅니다. AI 가 꺼져 있으면 '확인 필요 모음'과 발행 중단 감시 알림만 계속 옵니다.

## 선택지
1. **지금처럼 유지** — AI 상주 감시·알림. 이 PC(회사 계정)에서만 가능하고 개인 PC·무료 한도에서는 어렵다고 봅니다.
2. **추천** — 위 AI 쪽 변경 + GitHub 쪽 자동 알림 둘 추가. 새 워크플로 두 개와 시험을 만들고 독립 검증 뒤 각각 병합 부탁으로 올립니다(병합은 운영자님).
3. **AI 쪽만 변경(기본)** — GitHub 자동 알림은 하지 않음. 병합 알림은 AI 가 켜져 있을 때만 갑니다.

## 2 를 추천하는 이유 / 알려 드릴 점
- AI 가 없어도 '병합 부탁·병합 확인' 알림이 오고, AI 사용량이 알림 개수에 비례해 늘지 않습니다. 만들어 올리는 일은 새 워크플로 둘뿐이라 작습니다.
- 2 를 고르셔도 지금은 아무 워크플로도 바뀌지 않았고, 만들어 올릴 때 병합 부탁으로 따로 여쭙니다. 3 의 AI 쪽 변경은 지금 바로 적용합니다.
- 이 알림에는 운영자님 사진의 이름이나 읽은 글을 쓰지 않았습니다.
