# 확인 요청 026 — 글자 읽기를 앱에 붙여도 되는지 (결정은 한 가지)
> 이 글은 **질문**입니다. 이슈 양식 '[답변] AI 확인 요청에 답하기' 에 **대상번호 026**(`26` 처럼 써도 됩니다)과 고른 보기(1·2·3)를 적어 주세요. 답이 없으면 1(하지 않음)입니다. 2 를 고르시면서 범위를 줄이시려면(예: '0단계만') 같이 적어 주세요.

## 한눈에
- 시제품에서 고른 RapidOCR(합성 사진에서 글자 정확도는 PaddleOCR 와 같고 설치는 약 3배·메모리는 3배 이상 작음)를 '따로 설치하는 추가 도구'로 붙이는 안입니다. 앱 본체의 의존성은 늘지 않고, 도구 폴더를 지우면 꺼집니다.
- 사진은 PC 밖으로 안 나가고 네트워크·AI 를 쓰지 않습니다. 읽은 글은 '확인 전' 이고 줄마다 확인한 글자만 초안에 쓰이며, 읽은 글은 저장하지 않습니다.
- 추가 도구는 압축 약 105-120MB·풀면 약 270MB(추정, 지금 본체는 압축 43MB·풀면 104MB)이고 비용은 0원입니다. 병합과 기능 켜기는 따로 번호 있는 요청으로 여쭙습니다.
- 앱 안전 규칙(하위 프로세스 허용 목록 한 곳)·빌드 흐름(.github 새 파일 하나)·새 의존성 21개·모델 2파일이 들어가므로 T3 입니다.
- 만들기 전에 실사진 평가와 '네트워크를 끊고 같은 시험'(약 2분)을 먼저 하고 싶습니다(0단계). 결과가 나쁘면 거기서 멈춥니다.

## 선택지
1. **하지 않음(기본)** - 아무것도 만들거나 받지 않습니다. 지금 병합된 수동 사진 기능(종류·순서·메모·부가설명)은 그대로 씁니다.
2. **허락(아래 범위·조건 안에서만, 단계마다 알림)** - 0단계 -> a -> b -> c -> d 단계를 NO-MERGE 가지와 저장소 밖 폴더에서 진행하고, 병합과 켜기는 따로 여쭙습니다.
3. **보류** - 지금은 정하지 않습니다(1 과 같이 두고 다시 묻지 않고 기다립니다).

## 2 를 고르시면 하는 일과 받는 것
- 0단계(앱 변경 0): 이미 받아 둔 시제품 환경으로 ONNX 모델이 Paddle 원본과 같은 가중치인지 수치 비교, 모델 카드·라이선스 본문 확인, 같은 시험을 비행기 모드로 한 번, 운영자 사진 폴더를 읽어 속도·메모리 숫자와 사진별 '읽은 줄 목록' 글 파일(그 폴더 안에만 만들고 보신 뒤 지움)을 만들어 드리면 운영자가 사진과 견주어 사진마다 쓸 만함·애매·못 씀을 알려 주심(약 15-30분).
  - 필요한 것: (가) 본인 사진 10-20장을 한 폴더에 복사해 알려 주기(본인 사진만, 읽기만 하고 보고는 숫자만, 읽은 줄 목록은 그 폴더 안에만 잠깐) (나) 비행기 모드 약 2분 조작 (다) 모델 카드를 열어 주시거나 파일로 전달
- a 단계: 이미 받아 둔 휠 21개·모델 2파일로 '추가 도구' 묶음 시제품을 저장소 밖에서 만들어 크기·동작을 잰다. 새로 내려받는 것은 빌드 도구뿐(PyInstaller 등 - 본체 Package 와 같은 핀, PyPI 두 호스트, 약 20MB 안팎 추정).
- b-c 단계: 앱 저장소 NO-MERGE 가지에서 작업자 프로세스·규칙·화면·초안 연결(확정한 글자를 본문에 넣는 새 연결)·시험을 만들고 독립 검증(S·Q)을 받는다. 새 설정 칸·저장 형식 변경·백업 변경은 없습니다.
- d 단계: 추가 도구를 만드는 새 빌드 흐름 파일(.github/workflows 새 파일 1개 - 지금 Package 흐름과 같은 조건: 수동 실행만·읽기 권한만·비밀 0·액션 SHA 고정)을 NO-MERGE 가지에 준비합니다. 병합은 운영자만 합니다(AI 는 하지 않습니다). 모델 2파일(18.2MB)은 빌드 때 Hugging Face 에서 커밋 고정·해시 대조로 받습니다(앱은 어떤 경우에도 내려받지 않음).
- 결과: 압축 파일·해시·정보 파일(21개 패키지 목록·라이선스)을 만들고, 운영자가 본인 사진으로 직접 시험해 보시는 절차(약 30-60분, 비행기 모드)를 알려 드립니다.

## 받는 것과 접속하는 곳(확인한 값은 바이트까지, 어림은 어림이라고 적었습니다)
- 접속하는 곳(받을 때만, 시험·실행 중에는 0): pypi.org·files.pythonhosted.org(패키지·빌드 도구) · huggingface.co 와 그 CDN(모델 2파일, 빌드 흐름에서만). 그 밖의 호스트(modelscope.cn·Paddle 자체 인덱스·유료·구독 서비스)는 넣지 않았습니다.
- 파이썬 패키지 21개 합 109,521,868바이트: rapidocr 3.10.0(27,288,134)·onnxruntime 1.31.1(14,888,466)·opencv-python-headless 5.0.0.93(43,825,962) 포함, 전부 휠(소스 빌드 0)·SHA-256 고정. numpy 2.5.5 는 14일 이상 된 판으로 낮춰 핀할 수 있습니다.
- 모델 2파일 합 18,245,305바이트(인식 13,418,787·검출 4,826,518): 이미 받아 둔 것과 같은 파일이고 저장소 이름·커밋·SHA-256 이 고정돼 있습니다.
- 빌드 도구(PyInstaller 6.22.3 등, 본체 Package 와 같은 핀)는 약 20MB 안팎(어림). a 단계에서만 새로 받습니다.

## 추천값(2 를 고르실 때만 해당 - 다르게 하려면 번호와 함께 적어 주세요. 적지 않으면 추천대로 진행합니다)
- O2 배포 형태: 따로 설치하는 추가 도구(본체에 합치지 않음) · O3 모델 받기: 빌드 때 Hugging Face 커밋 고정+해시 대조 · O5 안전 규칙: 하위 프로세스 허용 목록 +1(글자 읽기 작업자)과 시험 단언 수정, 소스 관문 LOCAL_OCR(기본 꺼짐)
- O6 읽은 글 저장: 저장하지 않음(다시 열면 다시 읽어야 함) · O7 'Telemetry 0': 끄는 호출·환경 변수·가져오기 표 검사·비행기 모드 시험을 '0' 으로 보고 한계를 문서에 그대로 적음 · O8 평가 사진: 운영자 본인 사진 폴더
- 세부(O9·O10 등)는 추천안으로 진행하고 알림으로만 알립니다.

## 조건
- 일반 사용자 권한(관리자 요구 없음)·앱 네트워크 0·사진 외부 전송 0·원본 사진 변경 0·분석 결과 저장 기본 끔·새 설정 칸 없음·저장 형식 변경 없음·비용 0원.
- 시험·평가 단계는 네트워크 차단 상태에서 합니다(소켓 가드·연결 표본·비행기 모드 증명).
- 평가 사진은 운영자가 정한 본인 사진만이고 보고에는 숫자만 씁니다. 외부 작성자 사진은 쓰지 않습니다.
- 병합(LOCAL_OCR 꺼진 채)과 기능 켜기는 각각 따로 번호 있는 요청으로 여쭙습니다. main 에는 직접 push 하지 않습니다.

## 멈춤 조건 (하나라도 걸리면 멈추고 다시 여쭙니다)
- 0단계: 가중치가 설명 못 할 만큼 다름·모델 카드나 원본 라이선스가 재배포를 막음·네트워크를 끊으면 읽은 글이 달라짐·운영자 실사진 판정이 제안 기준(고치지 않고 쓰는 줄 70% 미만)에 못 미침.
- a 단계: 동결과 대안(내장 파이썬 방식)이 모두 실패·소스 빌드가 필요한 패키지·목록에 없는 호스트·크기나 해시 불일치·FFmpeg DLL 을 빼면 동작하지 않음·가져오기 표에 네트워크 라이브러리가 남음.
- b-d 단계: 소켓 가드 시도 1건 이상·관리자 권한이 필요한 동작·사용자 데이터나 사진 원본의 변화·묶음 점검의 규칙을 풀어야 하는 경우·독립 검증의 필수 지적을 같은 가지에서 못 고침.

## 알려 드릴 위험과 못 정한 것 (숨기지 않습니다)
- 실사진 성능은 모릅니다. 합성 27장에서도 글자 오류율 16%·줄 재현 70% 이고 확신도 0.9 대의 오독이 있어 줄마다 확인이 필수이고, 확인에 걸리는 시간이 직접 적는 시간보다 짧은지는 사람이 해 봐야 압니다(짧은 글은 직접 입력이 더 빠를 수 있고, 거친 계산은 설계서 1-6).
- 'Telemetry 0' 은 소켓 시험으로 증명되지 않습니다. onnxruntime 윈도 이진에는 윈도 이벤트 추적(ETW) 텔레메트리 코드가 있어 끄는 호출만 하며, 그 효과는 OS 쪽에서 증명하지 못합니다. 같은 패키지의 문서는 웹 서버로의 전송을 말하나 이진에서는 그 흔적을 못 찾았습니다.
- 앱의 안전 시험은 지금 '바깥과 닿는 코드(하위 프로세스 포함)는 세 곳뿐' 이라고 못박습니다. 작업자 프로세스는 이 규칙을 바꿔야 하는 보안 정책 변경이며, 이 PC 안의 계산이라는 구분을 받아들이실지 여쭙는 것입니다.
- 읽은 글은 저장하지 않아서 초안을 다시 열어 '다시 만들기' 를 하면 확인한 글자가 본문에 안 들어갑니다(이미 만든 본문은 그대로). 불편이 크면 '확인한 글자만 저장' 스위치를 따로 여쭙겠습니다.
- 지금 앱의 초안 만들기 코드는 확정한 글자를 본문에 넣지 않습니다. 글자 읽기를 붙이려면 그 연결을 새로 만들어야 하고(변경 등급 T2) 독립 검증을 받습니다.
- 추가 도구가 본체의 약 2.5배입니다(압축 약 105-120MB 추정 대 지금 43MB). OpenCV 의 FFmpeg DLL(LGPL 계열·네트워크 부품)과 쓰지 않는 기본 모델 31.7MB 는 도구에서 뺍니다. 핀 21개를 계속 관리해야 하고, numpy 2.5.5 는 2일 된 판이라 낮춰 핀합니다.
- 스마트 앱 컨트롤·백신이 두 번째 미서명 실행 파일을 막을 수 있는지는 시험하지 못했습니다. PyInstaller 로 묶은 동작도 아직 시험하지 못했습니다(a 단계).
