**결론: 지금 개인 PC 에서 '블로그 등록 → Seed → 후보 → 규칙 기반 초안 → 고치기 → 글 모양 점검 → 복사 → 저장·백업·복원'까지는 써도 안전해요(진짜 키·외부 게시·AI 없이, 네이버에는 사람이 직접 붙여 넣기). 자동 게시·AI·외부 지표와 이미지·문체 숫자의 초안 반영(N-3b)·정식 설치 파일은 아직 안 돼요. 화면 배율·한글 입력·실제 붙여넣기는 아직 확인 전이라 처음 몇 번은 결과를 눈으로 확인하며 쓰세요. 이 글이 요청하신 '제한 사용 시작 보고'예요.**

## 1. 지금 사용 가능한 기능
모두 화면에서 되고, 키·AI 없이 돌아요.
- 블로그 등록: 왼쪽 '블로그 관리' → 네이버 A 또는 B 카드 → 이름·블로그 ID(또는 주소)·언어 → '저장'. 고치기·A→B 복제·삭제도 돼요.
- Seed 등록·수정: 'Seed 관리' → 새로 등록하면 '승인 전'이고, '승인하기'를 눌러야 후보에 쓰여요. 앱에는 처음부터 든 Seed 가 없어요.
- 후보 만들기: '주제 후보' → '후보 만들기' → 확인창 '만들기'. 규칙으로 계산하고, 네이버 A·B 용만 만들어져요.
- 규칙 기반 초안: 후보에서 '이 주제로 만들기' → 제목 3개·본문(소제목 4–6개)·키워드·태그·요약. 입력하지 않은 경험·가격·수치는 지어내지 않아요.
- 초안 고치기·저장: 제목·본문을 직접 고치고 '저장'(Ctrl+S). 저장한 초안은 다시 열어 이어 써요.
- 글 모양 점검(N-2): '검사하기'를 누르면 깨진 글자·안 보이는 글자·반복·HTML·자리표시를 찾아 위치를 알려 줘요. 경고만 하고 글은 안 고쳐요.
- 내 글 문체 참고값(N-3a): 설정 맨 아래 카드. 보기만 해요(3번).
- 복사: 제목·본문·전체·태그·키워드·요약. 제목·본문 복사 전에 키 모양 글과 건강 효과 단정 표현은 막고, 확인이 필요하면 확인창이 먼저 떠요.
- 백업·복원: 설정의 '백업·복원' 카드. 키는 담지 않고, 복원 직전 데이터는 자동 사본으로 남아요.
- 네이버 수동 게시: '네이버 글쓰기 열기'가 기본 브라우저로 글쓰기 주소만 열어요. 로그인·붙여넣기·발행은 사람이 해요.
- 알아 둘 점: 저장은 '저장'을 눌렀을 때만 되고 이전 저장본을 덮어써요(자동 저장 없음). Windows 종료·로그오프 때 저장 안 한 내용은 확인 없이 사라져요. 백업은 이 PC 안에만 만들어지고 최근 10개만 남으니 USB 등에는 직접 복사하세요. 글쓰기 열기 단추는 블로그 ID(영문·숫자·밑줄·하이픈, 40자까지)나 blog.naver.com 주소일 때만 켜져요.
- 개인 PC 에서 직접 확인된 범위는 시험지 0–6단계(등록·후보·초안·저장·껐다 켜기·백업·키·계정 격리) 보고까지예요. 글 모양 점검과 문체 참고값은 시험지에 없어 써 본 기록이 없고, 복사·글쓰기 열기는 '선택' 칸이라 결과를 몰라요.

## 2. 아직 불가
- 외부 쓰기 전부 꺼짐: GitHub Pages 올리기·공개 확인·Blogger 초안·네이버 자동 게시·PR 자동 병합·예약 게시. 운영자 결정으로 일부러 꺼 둔 안전장치예요. 소스에 박혀 있어 설정·화면·명령줄로 못 켜고, 시험용 Package 는 명령줄 입력을 모두 거절해요.
- AI 호출 없음. 설정의 'AI 보조'·NAVER 키 카드는 키를 보관만 하고 쓰는 기능이 없어요. 진짜 키는 넣지 마세요.
- 외부 데이터 없음: NAVER API HUB 관심도·검색광고·이미지 검색·웹 읽기. 앱이 직접 인터넷으로 보내는 코드는 없고, 유일한 바깥 길은 '네이버 글쓰기 열기'예요. 블로그 주소를 기본 브라우저에 넘겨 여는 것이고 요청은 브라우저가 보내요.
- 화면이 없는 것: 발행 기록(올린 뒤 주소·상태 남기기), 후보 상태 바꾸기, 계절 일정·실시간 이슈·협찬 캠페인·지역 값 입력, 옛 네이버 프로필 항목(금지 표현·기본 태그 등). 그래서 후속·계절·실시간 후보는 재료가 없어 비어 있을 거예요. 후보 수가 목표보다 적을 수 있어요(코드 읽기 결과, 실제 개수는 못 세어 봄).
- '주제 설정' 세 칸(우선·제외 키워드·선호 글 유형)은 저장만 되고 후보·초안에 아직 안 쓰여요.
- 블로그 저장소 연결·발행 이력 읽기는 화면에서 정할 수 없어요(8번). 올리기·공개 확인은 막혀 있어요.
- 문체 숫자의 프로필 저장·초안 반영(N-3b), AI 문체 모방: 없어요.
- 정식 설치 파일·자동 업데이트·서명: 없어요(6번). 창 한 개만 뜨게 하는 보호도 진행 중이라 기준 빌드에는 없어요. 지금은 앱을 두 번 열면 창이 둘 떠요.

## 5. N-3b 선행
N-3b 는 아직 시작 전이에요. 먼저 필요한 것은 이래요.
- 프로필 둘(옛 네이버 프로필·채널 프로필)을 어떻게 합칠지 결정. 지금은 화면에서 채널 프로필만 고칠 수 있고 옛 프로필은 명령줄로만 고치는데, 시험용 Package 는 명령줄을 막아요.
- 어떤 숫자를 어느 칸에 저장할지. 여섯 숫자 중 프로필에 칸이 이미 있는 것은 소제목 수 하나뿐이에요.
- 새 칸을 안전하게 넣는 순서(읽기 호환 먼저, 쓰기 나중).
- 승인 방법(체크 칸 기본 해제·확인창·되돌리는 법).
- 초안 생성기가 문체 숫자를 받는 칸(지금은 없음)과, 원문이 새지 않는지 보는 시험.
- 저장 화면·쓰기 서비스·독립 검증.
- AI 제안(결정 아님): 합치기 전에 채널 프로필 한쪽에만 저장하는 축소안. 다만 '통합 먼저'라는 기존 전제를 바꾸는 일이라 운영자 결정이 필요해요. 작업 기간은 문서에 추정이 없어 몰라요.

## 6. Installer 준비 상태
- 지금은 개인 PC 시험용 휴대용 zip(0.1.0-preview.1, 서명 없음)까지예요. 압축을 풀어 실행하고, GitHub Actions 수동 실행으로 만들어요(산출물은 Actions 에 14일 보관). 운영자가 83722d6 빌드로 개인 PC 시험을 통과했어요(Windows 10 Pro 22H2). 크기는 개발 PC 에서 이전 커밋으로 잰 값이 약 40MB 이고, 시험한 빌드의 크기는 확인 못 했어요.
- 첫 실행에 SmartScreen 경고가 떠요('추가 정보 → 실행'). 앞서 운영자 보고에서도 그랬고 스마트 앱 컨트롤 차단은 없었어요. 서명이 없어서 새 빌드마다 떠요.
- 없는 것: Setup.exe·시작 메뉴·제거 프로그램·자동 업데이트·롤백·코드 서명·아이콘·릴리스 워크플로. 지우려면 수동 세 곳이에요(압축 푼 폴더·%LOCALAPPDATA%/ChanceblogDesktop·자격 증명 관리자의 앱 항목).
- 새 버전은 새 폴더에 풀어 쓰고 데이터 폴더는 그대로 이어져요. 옛 버전으로 되돌리면 새 버전이 만든 데이터를 옛 앱이 거절할 수 있어요.
- 나중에 운영자 결정이 필요한 것: 서명 도입 시점·앱 라이선스·아이콘·이름 표기 통일. Setup.exe 는 11-11 조사의 어림으로 5일 이상이에요(다시 재 보지 않음). Windows 11 PC 로 옮기면 서명 없는 파일이 스마트 앱 컨트롤에 막힐 수 있어요(일반 지식, 이 자료에 근거 없음).
- README 첫머리('설치할 수 있는 버전이 없습니다') 같은 낡은 문장이 몇 곳 남아 있어요. 사용에는 영향이 없고 정리가 필요해요.

## 7. 일반 사용자 권한 시험 상태

- 아직 증명 안 된 것: 화면 배율 125·150%, 한글 입력기, 실제 클립보드·네이버 편집기 붙여넣기, 실제 브라우저로 글쓰기 열기, Windows 종료·로그오프, OneDrive 폴더·네트워크 드라이브, 관리자 계정의 접근(표준 계정 사이만 시험).
- 한계: 환경 변수로 데이터 폴더를 사용자 프로필 밖에 두면 계정 격리가 보장되지 않고, 화면에는 경고가 없어요. 평소엔 기본 위치를 쓰세요.

- 11-11 조사가 찾은 빈틈: 블로그 쪽 pages.yml 은 main 에 올라오면 반응하고 이 변수를 안 봐서, 앱 명령줄의 올리기가 일시정지 중에도 사이트를 배포할 수 있었어요. 지금은 앱 쪽에서 막혀요(외부 쓰기가 소스에서 꺼져 있고, Package 는 명령줄 입력을 모두 거절).
- 블로그 저장소 연결은 화면에서 정할 수 없어요. 다만 환경 변수나 복원된 설정 파일에 폴더가 적혀 있으면 연결되고(일반 PC 에서는 기본 연결 없음), 연결돼도 후보 만들기가 발행 이력 파일을 읽기만 해요. 쓰기·git·네트워크는 막혀 있어요.
- 확인 못 한 것: 블로그 저장소의 현재 pages.yml(이 자료에 없음), Package 안에 명령줄 부품이 빠졌는지.

## 10. 가장 빠른 안전 사용 시점
날짜는 추정하지 않았어요. 시험 통과가 기준이에요.
- 이미 통과(운영자 보고): 표준 사용자 실행·계정 격리·저장 복원·백업 복원·키 격리. 외부 쓰기 0 은 코드로 확인했어요.
- 옛 시험 G1–G9: 통과 G3·G4·G6·G8·G9, 현재 값 확인 전 G1, 개발 PC 화면 시험만 있음 G2, 미확인 G5(복사→붙여넣기)·G7(글쓰기 열기→실제 브라우저).
- AI 쪽 확인은 끝났어요: 운영자 요약으로 Package Gate 세 항목을 기록했고(R-312), 83722d6 의 main 검사 12칸이 초록임을 확인했어요.
- 운영자가 해 보면 좋은 일은 맨 아래 '해 볼 일'이에요(진짜 프로필로 초안 한 편·배율 화면 확인).
- 권장: 창 한 개 수정이 병합되기 전에는 앱을 한 번만 여세요. 네이버 글쓰기 열기도 진짜 블로그로 한 번 해 보세요(안 되면 주소를 직접 열면 돼요).
- 판단: 데이터가 새거나 외부로 나갈 위험은 코드·시험·운영자 시험 보고 기준으로 막혀 있어 보안·데이터 안전은 충족으로 보여요. 그래서 지금부터 개인 PC 제한 사용을 시작하셔도 돼요. 다만 '쓸 만함'은 보증하지 못하고, 쓰시다 이상한 점은 이슈로 알려 주세요.
- 쓰는 규칙: 진짜 키는 넣지 않기·닫기 전에 '저장'·백업은 USB 로 직접 복사·새 빌드는 SHA-256 대조 뒤 새 폴더에 풀기·복사가 막히면 문구를 고쳐 다시 복사.
