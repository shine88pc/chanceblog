# R-008 · 연결 안 된 블로그별 하실 일 (이슈 #65)

## 전체 그림
| 채널 | 지금 상태 | 막혀 있는 곳(사용자님 몫) | 손이 가는 정도 |
|---|---|---|---|
| Chance(GitHub 사이트, 한·영) | **연결됨** — 하루 최대 2편 자동 발행 | 없음 | — |
| 영문 Blogger(macat0722) | 코드·가드레일 완료, 정지(`mode: off`), 시크릿 4종은 등록됨 | 구글이 refresh token 을 거부함(R-002·R-005 진행 중) | 중 — 이미 하는 중 |
| 한글 Blogger(kcyoon) | 코드·프롬프트·워크플로 등록 완료, 정지 | 블로그·구글 계정·시크릿이 없음 | 큼 |
| 티스토리 | 초안 패키지 기계 완료, 블로그 항목 없음 | 블로그 주소·주제 | 작음(입력) + 시험 글 1건 |
| 네이버 | 초안 패키지 기계 완료, 블로그 항목 없음(블로그는 개설만, 글 없음) | 블로그 주소·주제 | 작음(입력) |

**추천 순서**: ① 영문 Blogger 마무리 → ② 티스토리·네이버 정보 입력(5분) → ③ 한글 Blogger. 영문은 거의 다 와 있고, 티스토리·네이버는 입력만 주시면 제가 레지스트리·프로필·프롬프트를 만들 수 있고, 한글은 다른 구글 계정까지 필요해 가장 손이 많이 갑니다.
**서두르지 않으셔도 됩니다.** 어느 것도 하지 않아도 Chance 는 계속 발행됩니다. 광고는 어느 채널에서도 품질 게이트를 통과하기 전까지 플랫폼 화면에서도 켜지 않습니다.

## 1. 영문 Blogger (macat0722) — 이미 진행 중
1. 구글 클라우드에서 **앱 게시(In production)** — R-005 에서 "했어요"로 접수됐습니다.
2. **refresh token 새로 받기**: `.github/editorial/BLOGGER_API_SETUP.md` §2(로컬 스크립트) 또는 §2-B(브라우저 OAuth Playground, 웹 애플리케이션 유형 클라이언트가 필요). 새 프로젝트·새 클라이언트를 만드셨다면 같은 클라이언트로 받습니다.
3. 저장소 Settings → Secrets and variables → Actions → **Secrets** 에서 `BLOGGER_CLIENT_ID`·`BLOGGER_CLIENT_SECRET`·`BLOGGER_REFRESH_TOKEN` **세 개를 함께** 덮어씁니다(값은 이슈·채팅에 쓰지 않습니다).
4. Actions → `[Blogger 영문] 글 자동 작성`(병합 뒤 이름) → Run workflow → **`인증 점검만 실행`** 만 체크 → 결과는 제가 자동으로 읽습니다.
5. 점검이 통과하면 제가 **`mode: draft` 켜기 승인(T3)**을 번호 있는 요청으로 묻습니다. 켜도 글은 Blogger **초안함**에만 올라가고 공개는 사용자님이 직접 합니다.
- 한 줄 질문: **이 구글 계정이 Chance 의 AdSense 계정과 같은가요?** 같으면 Blogger 자동 글의 정책 위반이 광고 계정에 영향을 줄 수 있어 알아야 합니다(`[요청]` 양식에 한 줄이면 됩니다).

## 2. 한글 Blogger (kcyoon) — 가장 손이 많이 갑니다
영문과 **다른 구글 계정**을 쓰는 것이 원칙입니다(한 블로그의 정책 문제가 다른 블로그로 번지지 않게). 영문 값을 한글에 쓰면 안 됩니다.
1. 그 계정으로 Blogger 블로그를 만듭니다. 주소가 정확히 **`https://kcyoon.blogspot.com/`** 이어야 합니다(레지스트리의 주소와 같아야 글이 올라갑니다).
2. 같은 계정으로 구글 클라우드에서 **프로젝트를 새로 만들고** Blogger API 사용 설정 → Google Auth Platform 에서 **앱 게시(In production)**(R-005 와 같은 방법: 브랜딩에 홈페이지 `https://shine88pc.github.io/chanceblog/`·개인정보처리방침 `https://shine88pc.github.io/chanceblog/privacy/`·승인된 도메인 `shine88pc.github.io`) → OAuth 클라이언트 생성 → refresh token 발급(가이드 §7).
3. GitHub Secrets 에 **4종을 한꺼번에** 등록: `BLOGGER_KO_BLOG_ID`(Blogger 관리 화면 주소의 숫자)·`BLOGGER_KO_CLIENT_ID`·`BLOGGER_KO_CLIENT_SECRET`·`BLOGGER_KO_REFRESH_TOKEN`.
4. Actions → `[Blogger 한글] 글 자동 작성` → Run workflow → **`인증 점검만 실행`**.
5. 그다음은 제 몫입니다: 켜기 전 `_config.yml` 에 이력 파일 제외를 먼저 더하고(광고 표면이라 별도 승인), 주제 방향·톤·금지 범위·AI 고지 문구를 정리해 보내 드리니 읽고 승인해 주세요(`mode: draft`).

## 3. 티스토리
티스토리는 글을 자동으로 올릴 수단이 없어서(오픈 API 2024-02 종료) **제가 초안 패키지를 만들면 사용자님이 복사해서 발행**하는 반자동입니다.
1. 블로그가 없으면 만드시고, **주소**(`이름.tistory.com`)·**주제**(어떤 글을 올릴지)·**카테고리 이름**들을 알려 주세요 — `새 일 맡기기`(`[요청]`) 양식에 적으시면 됩니다. 그러면 제가 블로그 항목·프로필·프롬프트를 만들고 `mode: package` 로 켜는 승인을 번호 있는 요청으로 묻습니다.
2. **비공개 시험 글 1건**을 직접 써서 확인해 알려 주세요: 태그 입력 방식, HTML 모드에 붙여넣은 뒤 서식, 외부 이미지의 목록 썸네일, 예약 발행 화면, **회사 PC 에서 이미지 파일 업로드가 되는지**(막혀 있으면 대표 이미지 단계가 병목입니다).
3. 광고(애드센스 연동)는 켜지 않습니다.

## 4. 네이버 블로그
네이버도 글쓰기 API 가 없어 같은 **초안 패키지 + 복사 발행** 방식입니다.
1. 블로그 **주소**와 **주제·카테고리**를 알려 주세요(`[요청]` 양식, 티스토리와 같은 방식). 네이버 글감은 Chance 와 어떻게 다르게 할지(같은 공공 자료 요약인지 다른 주제인지)도 한 줄 주시면 좋습니다.
2. 광고(애드포스트)는 켜지 않습니다.

## 알려 주는 법과 알아 둘 것
- 정보를 주실 때는 `새 일 맡기기`(`[요청]`) 양식의 "해 주었으면 하는 일"에 위 항목을 적고, **진행 범위는 `구현·시험까지(T3 제외)`** 를 고르시면 제가 이어서 준비합니다. 끝낸 일을 알릴 때는 `AI 요청에 답하기` 양식에서 요청 번호 `R-008`(대문자), 답변 **했어요**를 쓰셔도 됩니다. 알리지 않아도 인증 점검 실행·새 이슈는 제가 읽습니다.
- 값(토큰·키·비밀번호)은 어디에도 쓰지 말고 GitHub Secrets 화면에만 입력합니다. `[요청]` 양식은 **승인이 아닙니다** — 켜는 일(T3)은 제가 번호 있는 확인 요청으로 다시 묻고, 그 요청에 `[답변]` 으로 승인하셔야 켜집니다.
- 계정 만들기·동의 화면·토큰 발급·시크릿 입력은 AI 가 대신 하지 않습니다.
