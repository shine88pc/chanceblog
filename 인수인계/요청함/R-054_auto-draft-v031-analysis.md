# [R-054] 요구사항 v0.3.1 차이 분석과 개발 계획

> 운영자님이 알려 주신 `chanceblog_desktop_auto_draft_requirements_v0.3.1.md`(원문은 공개 저장소에 올리지 않고 분석만 남깁니다)를 요구서가 요청한 12항목 형식으로 정리했습니다. **하실 일은 없습니다.** 정하실 것은 10번에 기본값과 함께 적었습니다. 요구서의 핵심 원칙(입력이 없어도 작업이 멈추지 않고 기본값만으로 복사 가능한 초안이 완성된다)에 모두 동의하며, 기존 개발을 처음부터 다시 하지 않고 독립 모듈로 단계적으로 쌓습니다.

## 한 줄 결론
요구서가 요구하는 "후보 선택 → 초안 만들기 → 결과 확인 → 복사"에서 **지금 데스크톱에 있는 것은 '복사 꾸러미 만들기'와 '유사도 검사'뿐**이고, 후보 선정·초안 만들기·화면은 모두 새로 만들어야 합니다. 기존 GitHub Pages·Blogger 기능은 건드리지 않습니다.

## 1~12 (요구서 16장 형식)
1. **현재 후보 선정 구현 상태**
   - 데스크톱: 없음(후보 데이터 모델·네이버 데이터 수집·키워드 기회도·후보 목록과 상태 관리 모두 미구현). 있는 것은 네이버 A·B 블로그 프로필(표시명·주소·주제·대상 독자·말투·카테고리 매핑·기본 태그·금지 표현·이미지 규격·글 길이·제목 길이·문단 길이·태그 수·AI 고지문·발행 주기).
   - 클라우드(블로그 저장소): 자동 발행용 주제 선정은 있습니다 — 블로그 프로필의 시드 주제에서 철(월)에 맞는 것을 고르고 AI 로 넓혀 중복을 거릅니다. 검색 수요·경쟁 데이터는 쓰지 않습니다. 이 엔진은 데스크톱이 선택 기능으로 가져다 쓸 수 있습니다.
2. **현재 초안 생성 구현 상태**
   - 데스크톱: 문장을 만드는 기능은 없습니다. 이미 있는 원고를 네이버 복사 꾸러미(제목 줄이기·태그 정리·짧은 문단·이미지 자리·고지문·점검표·금지 표현/길이 점검)로 바꾸는 기능, 네이버 A·B 유사도 검사, 그리고 진행 중인 서비스 계층(명령줄)이 있습니다.
   - 클라우드: 네이버 초안을 매일 자동으로 만들어 이슈로 올리는 기능이 이미 돌고 있습니다(사용자 입력 없음). 요구서의 "기존 사용 가능한 생성 방식"이 이것입니다.
3. **필수 사용자 입력으로 처리된 항목(데스크톱 현재)**: 원고 본문(직접 쓰거나 불러오기)·제목·분류·대상 블로그, 그리고 주제 선택 자체. 올리기 전 '승인'은 일부러 둔 확인 단계라 유지합니다(복사 단계에는 승인 같은 필수 단계를 더하지 않습니다).
4. **선택 입력으로 바꿀 항목**: 위 필수 입력 전부를 "생성 결과가 기본값으로 채우고 사용자가 고치는" 방식으로 바꿉니다. 새 선택 입력(접힌 패널): 꼭 넣을 내용·제외할 내용·실제 경험/의견·참고 주소(우선 노출), 글 길이·제목 방향·독자층·가격/날짜·결론(고급). 비어 있어도 절대 멈추지 않습니다.
5. **새로 추가할 기본값**: 공통 기본값(정보형·쉬운 존댓말 설명체·처음 접하는 일반 독자·프로필 글 길이·도입→핵심→기준→주의→정리·제목 후보 3개·프로필 범위 태그). 프로필에 없는 항목 추가: 도입부 스타일·소제목 수·설명 난이도·마무리 방식·제외 주제·같은 주제 재사용 기준(기존 프로필 파일과 호환되게 기본값을 둠). 값 적용 우선순위(사용자 입력 > 블로그 프로필 > 글 유형 틀 > 키워드 분석 > 공통 기본값)를 코드와 시험으로 고정합니다.
6. **정보 부족 시 안전한 대체 규칙**: 후기형은 정보형으로 바꾸는 표(경험 후기→정보 안내, 사용 후기→기능·선택 기준, 방문 후기→이용 정보·방문 전 확인, 제품 체험→공개 정보·구매 전 확인)와 금지 자동 생성 10종(직접 사용·방문·구매·수익·체감 주장, 실제 대화·댓글, 확인 안 된 가격·날짜·통계, 없는 사례)을 **두 겹**으로 지킵니다. ① 작성 규칙 ② 생성 뒤 검사기(사용자 입력·참고 자료에 근거 없는 1인칭 경험 표현은 막고, 가격·시간·통계는 '확인 권장'으로 표시). 확인 권장이 있어도 초안은 완성 상태로 냅니다.
7. **변경할 화면과 파일**: 화면은 아직 하나도 없습니다(명령줄만 있음). 새 독립 모듈: 후보 모델·상태(`content/candidates`)와 보관함 표, 후보 소스(`candidates/` — 프로필 시드·수동 추가·클라우드 주제 엔진, 키를 받은 뒤 네이버 수집기·캐시·조회일), 초안 구성(`draft/` — 기본값·선택 입력·우선순위·글 유형 틀 5종·안전 대체·작성기 인터페이스), 경험·수치 주장 검사(`check/claims`), 네이버 꾸러미 확장(제목 3후보·한 줄 요약·확인 권장), 서비스 계층 명령, 화면(`app/`). 기존 파일은 프로필 항목 추가와 보관함 표 추가 정도만 바꿉니다.
8. **기존 기능에 미치는 영향**: GitHub Pages·Blogger 발행 경로는 바꾸지 않습니다(새 모듈은 독립, 기존 시험 전부 유지). 보관함은 새 표만 더하고 버전을 올리며 사전 백업·실패 시 원복을 둡니다. 프로필 항목 추가는 기본값이 있어 기존 설정과 호환됩니다.
9. **구현 순서**(요구서 14장을 현재 상태에 맞춰 조정): ⓪ 서비스 계층 독립 검증·병합(진행 중) → ① 프로필 확장·후보 데이터 모델·상태·보관함 표·명령줄 → ② 후보 소스(키 없이: 프로필 시드·수동 추가·클라우드 주제 엔진) + 키워드 기회도 틀(데이터가 없으면 숨김, 요구서의 허용 표현만 사용) → ③ 기본값·선택 입력·우선순위·글 유형 틀·안전 대체 규칙·경험 주장 검사기 → ④ 초안 작성기(기본은 틀 작성기, 완성 문장은 클라우드 초안 가져오기 또는 선택 AI)·제목 3후보·요약·확인 권장·항목별 복사·네이버 글쓰기 열기 → ⑤ 초안·발행 상태 기록·발행 주소·A/B 유사도·중복 경고 → ⑥ 화면(5개 메뉴). 묶음마다 독립 검증을 거치며 한 묶음은 반나절~하루(추정). 네이버 데이터 수집 API 연결은 키 승인 뒤입니다.
10. **사용자 확인이 필요한 사항**(모두 기본값으로 진행, 바꾸려면 알려 주세요)
    - ① 초안 문장을 누가 쓰나: 기본은 **키 없이** 틀 작성기 + 클라우드가 만든 초안 가져오기. 앱에 Gemini 키를 넣어 직접 쓰는 안은 키 결정(승인 사항)이 있을 때만.
    - ② 네이버 데이터 수집(공식 오픈 API·검색광고 API)은 키 발급과 약관 확인이 필요한 **승인 사항**: 기본은 키 없이 시작하고, 필요해지면 번호 있는 요청으로 여쭙니다. 비공식 긁어오기·자동 로그인·자동 입력은 만들지 않습니다.
    - ③ 네이버 블로그 B 정보(주소·주제·대상 독자·말투·하루 편수): 받을 때까지 틀만.
    - ④ 화면 틀(PySide6 와 pywebview): 작은 시제품으로 비교해 정합니다.
    - ⑤ 후보 갱신 주기: 기본은 앱을 열 때와 '새로 고침' 눌렀을 때(정기 자동 수집은 앱이 켜져 있을 때만; 클라우드 정기 수집은 따로 검토).
    - ⑥ 같은 주제 재사용 경고 기준: 기본은 같은 핵심 키워드를 90일 안에 다시 고르면 경고(프로필에서 바꿈).
11. **현재 UI 구조와 단순화가 필요한 화면**: 사용자용 화면이 없고 명령줄은 개발·시험용입니다. 요구서 11장을 **첫 화면 설계로 채택**합니다: 메뉴 5개(홈·주제 후보·초안·발행 기록·설정), 한 화면의 주요 버튼 3개 안팎, 선택 입력은 접힘, 오류는 '해야 할 일'을 먼저. 서비스 계층의 "올리기는 확인이 있어야 한다" 규칙은 화면에서도 '위험한 작업만 확인 창'으로 유지합니다(네이버는 복사만이라 확인 창이 필요 없음).
12. **기본 화면에서 숨길 고급 기능**: API 연결·캐시·가중치·호출량 제한·로그·데이터 내보내기·진단 정보(점검 명령), 보관함 백업·복원·삭제, 내부 번호·영문 상태 코드·Git 해시·점수 수식·오류 상세는 모두 '설정 > 고급'으로.

## 요구서와 지금 규칙을 맞춘 것 (정합 메모)
- 후보 상태 9개(NEW·REVIEW·SELECTED·DRAFTING·DRAFT_READY·COPIED·HOLD·REJECTED·PUBLISHED)와 지금의 네이버 발행 상태(초안 생성·검토 필요·복사 준비·복사 완료·수동 발행)는 **둘로 나눠 연결**합니다: 후보(NEW·REVIEW·SELECTED·HOLD·REJECTED)는 새 후보 표, 초안 이후(DRAFTING·DRAFT_READY·COPIED·PUBLISHED)는 기존 네이버 흐름에 대응시킵니다. 화면에는 한국어 이름만 보입니다.
- 요구서의 금지 표현(상위노출 보장·노출 확률·검색 1위·수익 보장)과 허용 표현(키워드 기회도·콘텐츠 작성 우선도·블로그 프로필 적합도·최근 관심도 변화·관련 블로그 검색 결과 수)은 시험으로 고정합니다.
- 요구서의 보류 항목(사진 자동 처리·네이버 자동 로그인·입력·발행·AI 자동 전환·상위노출 점수)은 기존 결정(D-01·D-15)과 같아 그대로 보류입니다.
- 요구서 13장(AI 없이 동작, AI 실패가 전체 오류로 번지지 않음)은 기존 결정(D-16·D-18)과 일치합니다.
