## 이번 묶음이 하는 일
1. **설정 화면의 연결 카드에 '키 구역'**이 생깁니다(새 메뉴는 없습니다). 키 행(별칭·`사용`/`예비`/`꺼짐` 배지·우선순위·마지막 성공 시각·마지막 오류의 쉬운 문장)과 단추: **키 등록**(입력 → 확인 두 단계)·**삭제**(확인창이 먼저)·**연결 시험**·사용/예비/끄기·**별칭 바꾸기**·**우선순위 올리기/내리기**.
2. **키는 Windows 자격 증명 관리자에만 저장됩니다.** 앱의 파일·화면·로그·진단·클립보드·예외 어디에도 키 원문·끝 글자·길이가 남지 않고, 저장한 키는 다시 보여 주지 않습니다. 입력 칸은 점으로만 보이며 저장·취소·닫기 어느 길로든 비워집니다. 키가 지나가는 길은 '마스킹 칸 → 서비스 → 자격 증명 관리자' 하나뿐입니다.
3. **서비스별 키 개수가 운영자 정책 표대로** 바뀝니다: NAVER API HUB·Unsplash·Pexels·Pixabay·네이버 검색광고 **1개**, Gemini(AI 보조) **3개**, Blogger **2개**(채널별 1개의 근사 — 채널 칸은 Blogger 호출 묶음에서). 전에는 NAVER API HUB 를 뺀 모두 3개였습니다. **이미 저장된 옛 키는 그대로 읽히고 지울 수 있고, 새로 더하는 것만 상한을 따릅니다.** 같은 서비스의 둘째 키부터만 약관 확인을 묻습니다. **자동 키 순환 규칙은 바뀌지 않았습니다**(NAVER API HUB·Unsplash 는 순환 없음 그대로).
4. **연결 시험 단추는 지금 모두 '준비 중' 으로 꺼져 있습니다**(아직 실제 호출 코드가 없습니다). 이용 약관 확인 전의 NAVER API HUB 는 시험 함수를 건네도 호출하지 않습니다 — 이 묶음은 **외부 서비스를 부르지 않습니다.**
5. **쓰기는 단추를 누를 때만**: 설정 화면을 열고 다시 읽는 것은 여전히 읽기만 합니다(데이터 폴더·보관소가 바이트까지 그대로). 쓰는 동안은 모든 단추가 꺼져 두 번 눌려도 한 번만 일합니다.
6. 키 저장 직후 파일 쓰기가 윈도의 일시적 파일 잠금으로 가끔 실패하던 것을 짧게(0.45초 안) 다시 시도하도록 했습니다. 키 저장소를 못 쓰는 PC 에서는 카드가 '이 컴퓨터에서는 키 저장소를 쓸 수 없어요' 를 상태로 보이고 등록 단추를 끕니다.
7. 점검 사진 17장을 새로 올렸습니다(키는 한 장에도 나오지 않고 이름은 모두 가짜).
