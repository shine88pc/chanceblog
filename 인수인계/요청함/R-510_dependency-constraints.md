# 병합 요청 M120 — 의존성 설치 버전 묶기 (T3, 확인 034 ① 승인)

> **병합 방식**: 지금은 AI 병합 기능이 **꺼져 있어** 운영자께서 직접 병합해 주세요. (`M120 승인` 이라고 답하셔도 아직 AI 가 병합하지 않습니다.) 이 요청은 블로그 저장소 `chanceblog` 의 것이고, PR 제목 맨 앞이 `[M120]` 인 것 하나만 병합합니다. 검사는 이미 끝나 초록입니다. 급하지 않습니다(보통).

## 1. 무엇을 바꾸는지 — 운영자님이 승인하신 변경안 A(확인 034 ①, 이슈 #258)
**T3 — `.github/workflows/` 열 파일의 설치 줄과 검증기를 건드립니다.** 요구 파일 셋(`requirements-dev.txt`·`requirements-edits.txt`·`requirements-pipeline.txt`)은 **한 글자도 안 바꿨습니다**(범위 표기 유지 — 지시하신 대로).
① **새 파일 둘** `constraints-py310.txt`(37줄)·`constraints-py312.txt`(36줄): 격리 환경에서 범위 그대로 설치해 전체 시험을 통과한 실제 버전을 `이름==버전` 으로 묶었습니다(3.10 은 google-genai 2.33.0, 3.12 는 2.34.0 — 서로 다릅니다). GitHub 리눅스 러너(파이썬 3.10.22·3.12.16)에서 같은 버전으로 설치되는 것을 병합 전 임시 가지에서 확인했습니다(요구 파일 셋·인라인 설치 모두 설치 버전 = 목록, `pip check` 통과).
② **설치 줄 열 곳**: 요구 파일이나 `google-genai` 를 설치하는 줄에 그 파이썬용 `-c constraints-pyNN.txt` 만 더했습니다 — 3.12: `blogger`·`naver`·`tistory`·`issue-edit`·`pr-scope-check`·`sync-issue-form`, 3.10: `chanceblog`·`chance-fix-images`·`chance-shadow`, 두 파이썬 칸: `guardrails`(단계 환경 변수 한 칸으로 번호를 고름 — `run:` 안에 식을 끼우지 않음). **권한·시크릿·트리거·`if`·`uses`·다른 줄은 그대로**입니다.
③ **검증기 새 규칙 DEP-3(오류)**: 설치 줄에 `-c` 가 없거나 파이썬 번호가 틀리거나, constraints 파일의 줄 모양이 틀리거나 요구 파일의 직접 요구와 어긋나면 막습니다(읽지 못하는 모양은 통과가 아니라 오류). DEP-1(경고)은 따옴표 친 `"$CONSTRAINTS"` 를 범위 없는 패키지로 읽어 경고가 3 → 4 가 되는 것을 막으려 **바깥 따옴표만 벗기는 한 줄**을 고쳤습니다.
④ 시험 105개(새 모듈 — 구현자 104개 + 병합 가지에서 제가 더한 안전 장치 문서 문장 시험 1개)와 기존 시험 둘의 강화, 문서(`docs/DEPENDENCY_PINNING.md` 새로 — 만드는 법·갱신 절차(월 1회와 보안 공지 때, 외부 접속은 번호 있는 확인 뒤)·검증 방법). 안전 장치 문서(`docs/SECURITY_GUARDRAILS.md` G-A5·DEP-3 매핑, `docs/ARCHITECTURE.md`, 결함 D-10 '해결')는 제가 맞췄습니다.

## 2. 사용자가 체감하는 변화
**지금 글·사이트·알림은 그대로입니다.** 달라지는 것은 예약 실행(블로그 발행·네이버·티스토리·이슈 처리)과 검사(CI)가 매번 같은 버전으로 설치된다는 점입니다 — 패키지가 범위 안에서 새 버전을 내도 어느 날 갑자기 다른 버전을 받아 깨지는 일이 없습니다. 갱신은 월 1회와 보안 공지 때 같은 방법(격리 설치·전체 시험)으로 constraints 만 바꾸는 작은 병합 부탁으로 합니다.

## 3. 알려 둘 것(승인안과 다른 곳·한계)
- **새 루트 파일 둘이 사이트에 정적 파일로 공개됩니다.** 내용은 공개 저장소에 이미 있는 패키지 이름·버전뿐이라 새 노출은 아닙니다. 사이트에서 빼려면 `_config.yml`(광고 표면 — 운영자 승인 필요)과 병합 정책 목록을 함께 바꾸는 **별도 T3** 가 필요해서, 이 변경에서는 `tests/test_site_cleanup.py` 의 '일부러 열어 두는 파일' 목록에 적었습니다. 사이트 정리를 원하시면 알려 주세요(후속 제안).
- **후속 제안 둘(이 병합 밖)**: ① `.github/CODEOWNERS` 에 `/constraints*.txt` 한 줄 ② `requirements-pipeline.txt` 3행 주석('3.10/3.12 모두에서 같은 버전으로 풀림')은 이번 실측과 어긋난 옛 문장 — 요구 파일을 한 글자도 바꾸지 말라는 지시라 그대로 뒀습니다.
- `actionlint-py` 와 `pip install --upgrade pip` 는 이번 묶음 밖입니다(확인 032 #9 와 함께 다룸). pip 는 요구·제약 파일을 시스템 인코딩으로 읽으므로 한글 윈도에서 로컬로 `-c` 를 쓸 때는 `PYTHONUTF8=1` 을 둡니다(문서에 안내, 리눅스 러너는 영향 없음).
- 다른 갈래가 요구 파일에 패키지를 더하거나 워크플로에 `pip install` 을 더하면 DEP-3 이 오류를 냅니다 — 두 constraints 목록에도 더하고 `-c` 를 붙입니다(`docs/DEPENDENCY_PINNING.md`).
- `pr-scope-check.yml`·`issue-edit.yml`·`sync-issue-form.yml` 은 기본 가지를 체크아웃해 설치하므로 constraints 파일이 main 에 들어간 **병합 순간부터** 맞습니다(병합 PR 자신은 AI 가지라 범위 검사가 건너뛰고, 이슈 처리는 이슈 이벤트라 병합 뒤 실행 — 문제 없음으로 읽었습니다).
