# 병합 요청 M099 — 글자 읽기 b 단계 2 (앱)

> **병합 방식**: 지금은 AI 병합 기능이 **꺼져 있어** 운영자께서 직접 병합해 주세요. (`M099 승인` 이라고 답하셔도 아직 AI 가 병합하지 않습니다.) 이 요청은 앱 저장소 `chanceblog-desktop` 의 것이고, PR 제목 맨 앞이 `[M099]` 인 것 하나만 병합합니다. 검사는 이미 끝나 초록입니다. 급하지 않습니다(보통).

## 1. 무엇을 바꾸는지
승인해 주신 '사진 속 글자 읽기'(확인 026)의 **화면 단계**입니다. 앞서 병합된 몸통(M098) 위에 사용자가 보는 칸을 붙입니다.
① **사진 한 줄의 글자 읽기 칸**: 읽기 단추·상태 줄·읽은 글 목록(키보드로 위아래·Home·End, Space 로 '맞아요', Enter 나 F2 로 고치기, Delete 로 빼기와 한 번 되돌리기, 합치기)과 '읽은 글 모두 맞아요' 질문(질문을 띄운 뒤 줄이 달라지면 낡은 '네' 는 거절).
② **사진을 읽는 입구와 진행자**: 사진 한 장을 메모리에서 읽고 줄이는 부분(회전 적용·투명 사진은 흰 바탕·너무 큰 사진은 읽기 전 거절·디스크 쓰기 0·사진 경로는 밖으로 안 나감)과, 한 장씩 맡기고 시간 초과·취소·유휴 종료를 감시하는 진행자, 이것들을 몸통의 읽기 어댑터에 잇는 조립(켜짐 관문과 추가 도구 확인을 통과할 때만 만들어짐).
③ **문구 69개**와 화면 규칙, 창 연결.
④ 저장해 둔 초안을 '다시 만들기' 할 때 **확정한 사진 일부만 다시 읽어도 확인창이 뜹니다**(이전에는 나머지 사진의 글자 문단이 소리 없이 빠질 수 있었음).
⑤ **켜짐 관문은 그대로 꺼짐**(`LOCAL_OCR` False)이라 이 화면은 어떤 빌드에서도 나타나지 않고, 켜는 일은 따로 번호를 붙여 여쭙습니다.

## 2. 왜 필요한지
승인된 단계 계획의 둘째(몸통 → 화면 → 빌드 흐름 → 켜기)입니다. 화면까지 들어가야 운영자 PC 에서 켜 보기 전에 글자 읽기를 실제로 확인할 수 있습니다.

## 3. 사용자가 체감하는 변화
없습니다. 켜짐 관문이 꺼져 있고, 읽기 컨트롤러가 없으면 글자 읽기 위젯은 만들어지지도 않아 사진 정리 창은 지금과 한 글자도 다르지 않음을 창 지문(827줄) 비교로 확인했습니다.

## 4. 위험과 기존 기능에 미치는 영향
- **기존 기능**: 저장 형식·서비스 쓰기·백업·설정·네트워크는 안 바뀌었습니다. 새 네트워크·하위 프로세스·파일 쓰기 길은 없고(몸통의 어댑터를 그대로 씀) 안전 시험의 허용 목록 변경도 없습니다(소스 규칙 등록부에 새 화면 파일을 이유와 함께 더한 것뿐). 앞서 병합된 L2(닫기 질문·복원 중 저장 막기)·L3(진단 정보 복사)와 겹친 곳 네 군데(앱 상태 한 블록·창 생성자 서명 한 줄·문서 두 곳)는 두 쪽을 모두 남기는 방식으로 풀었고, 그 풀이는 안전 검증자가 따로 확인했습니다. 합치다 생긴 낡은 결정 행 하나를 지웠고, 새 Qt 시험 파일 둘은 PySide6 가 없는 검사 환경에서 불러오다 실패하던 것을 건너뛰게 고쳤습니다.
- **Qt 시험이 잡아 고친 결함 다섯**: 단추 줄이 별도 창으로 잠깐 떠 앱 창의 포커스를 빼앗던 것·읽은 글 목록 높이가 0 으로 보이던 것·합치기 단추가 방향키로 고른 줄을 안 따라가던 것·읽는 중 사진을 지워도 취소가 1초 기다리던 것·상태 글이 두 줄이 돼도 창 키를 안 맞추던 것.
- **알려 둔 한계**: 읽는 프로그램(화면 읽기) 알림·윈도 125%·150% 실제 렌더·한글 입력기는 개발 PC 에서 확인하지 못했습니다(켜기 전에 운영자 PC 에서 볼 목록이 `docs/UI_VISUAL_QA.md` 21절에 있습니다). 코드 양이 목표를 크게 넘었습니다(화면 규칙·위젯·진행자·조립·입력이 모두 있어야 켤 수 있는 한 묶음). 저장해 둔 초안 다시 만들기 확인은 문단이 없던 글에도 한 번 묻는 헛걸음이 있을 수 있습니다. 일부 사진만 확인한 초안의 안내 문장이 '확인한 글자가 없어요' 라고 말하는 작은 어색함이 있습니다(검증자 참고, 동작 영향 없음).
- **운영자께 여쭐 것(급하지 않음, 이번 병합과 별개)**: 켜기(별도 요청) 전에 운영자 PC 에서 실제 윈도 125%·150% 화면·한글 입력·화면 읽기 프로그램으로 글자 읽기 칸을 한 번 봐 주세요. **추천: 켜기 요청 때 목록을 같이 드림.**

## 5. 시험·독립 검증 결과
- 새 시험 185개(순수 82·Qt 103): 고치기 전 코드에서 순수 5개·Qt 14개 이상이 빨강이고, 변이 106개(순수 56·Qt 50)를 시험이 잡았습니다(동치로 살아남는 몇 개는 이유를 적음). 바뀐 기존 시험은 강화뿐이고 시간 여유만 둔 둘은 단정을 그대로 둡니다.
- 독립 검증(구현자와 다른 AI 둘 — 안전·화면 시험): 1차 필수 둘(낡은 '모두 맞아요' 질문·일부만 다시 읽은 때 확인창 누락)을 모두 고친 뒤 몸통 위의 합친 트리로 변경분 재확인 **둘 다 pass(필수 0)**, 병합될 최종 모양(L2·L3 와 겹침 풀이 포함)도 안전 검증자가 확인했습니다(그 뒤 더해진 것은 문서 중복 줄 정리와 시험 파일 두 곳 보정뿐).
- 검사(CI) 앱 12칸 초록. 앱 검사에는 PySide6 가 없어 Qt 시험은 건너뛰므로, 이 병합 가지의 Qt 시험은 GitHub 윈도 러너에서 따로 돌렸습니다(네 조각 모두 통과).
