# 작업 요청서 5: 채널별 구분 관리 · 티스토리·신규 Blogger 추가 · AdSense 정책 대응

> 먼저 `작업 내용`(인수인계 현황 문서)을 읽고, 이 요청의 진행·결정은 **그 문서 한 곳에만** 기록할 것(새 현황 문서 만들지 않기).
> 등급 T3(광고 표면·공개 콘텐츠·사이트 설정)은 사용자 채팅 승인 없이 진행하지 않는다.
> 확인하지 못한 것은 추측하지 말고 "미확인"으로 표시한다.

## 1. 배경 (운영자 요청, 2026-10-26)
- 운영자는 Actions에서 **초안 작성 상태를 사이트(채널)별로 구분해서** 보고 싶다. 예: Blogger / 블로그(Chance) / 티스토리를 각각 별도 분류로.
- 채널을 **티스토리**와 **신규 한글 Blogger(`kcyoon.blogspot.com`, 별도 구글 계정)**까지 추가할 수 있게 해 달라.
- **AdSense는 하나의 계정에 여러 사이트 주소를 연동**해 둔 상태다.

## 2. 사실 정리 (조사·확인된 것)
1. **AdSense는 반복·중대한 위반이 있으면 개별 사이트가 아니라 계정 수준 조치로 넘어갈 수 있다**(구글 AdSense 도움말). 따라서 한 사이트의 위반이 연동된 모든 사이트의 광고 수익에 영향을 줄 수 있다.
2. **구글 게시자 정책은 "사람의 검토나 큐레이션 없이 자동 생성된 콘텐츠에는 광고를 두지 말라"고 안내한다.** 현재 Chance_Blog는 자동 발행이 사람 검토 없이 공개되고, 홈에 광고 스크립트가 있다(작업 내용 §5 기록 기준). → 아래 4장의 결정 항목.
3. **티스토리 오픈 API는 종료됐다**(관련 자료 다수에서 확인, 정확한 종료 공지 원문은 미확인). 현재 가능한 자동 발행 도구는 비공식 세션·브라우저 자동화 방식이라 정책 변경 위험이 있다. → 티스토리는 **초안 패키지 + 운영자 복사 발행**으로 간다(네이버와 동일 방식). 계정 로그인 자동화는 구현하지 않는다.
4. **GitHub Actions에는 폴더·카테고리 기능이 없다**(알고 있는 바, 미확인). 워크플로 목록은 이름순 평면 목록이므로 **이름 접두사 규칙**으로 묶는다.

## 3. 요구사항

### 3-1. 채널 구분 체계
다음 6개 구분으로 통일한다(이름은 제안, 사용자가 바꿀 수 있음).

| 구분 | 대상 | 발행 방식 |
|------|------|-----------|
| Chance | GitHub Pages 한/영 | 기존 자동 발행(4장 결정 대기) |
| Blogger 영문 | macat0722 | 초안함 업로드(승인 대기, 현재 정지) |
| Blogger 한글 | kcyoon (신규, 별도 구글 계정) | 초안함 업로드(처음엔 `off`) |
| 티스토리 | 신규 | 초안 패키지(복사 발행) |
| 네이버 | 개설만 됨, 글 없음 | 초안 패키지(복사 발행) |
| 공통 | 배포·워치독·점검·동기화 | — |

### 3-2. Actions 이름 규칙
- 워크플로 `name`과 `run-name`에 **`[구분]` 접두사**를 붙인다. 예: `[Blogger 영문] 초안 업로드`, `[티스토리] 초안 패키지 만들기`, `[공통] 워치독`.
- 현재 워크플로를 위 표로 재분류해 목록과 이름 변경안을 **먼저 보고**한다(기존 한글 이름 규칙·`docs/ACTIONS_GUIDE.md`와 맞출 것).
- 채널별로 독립 실행·예약이 가능하도록 채널별 얇은 워크플로 + 공용 로직(재사용 워크플로 또는 공용 스크립트) 구조를 검토한다. 구현 방식은 현재 구조를 보고 제안.

### 3-3. 초안 확인 위치 (인박스)
- **Blogger 영문·한글**: 초안은 Blogger 초안함에서 확인·게시한다. Actions 요약에 채널·블로그 이름·초안 링크·제목을 남긴다.
- **티스토리·네이버 패키지**: 초안 1건 = **GitHub 이슈 1개**로 만든다. 라벨 `채널:티스토리` / `채널:네이버` + `초안`. 본문에 복사용 제목·본문·해시태그, 이미지(첨부 또는 링크), 출처, **AI 생성 이미지 여부**, 체크리스트("복사 발행 완료")를 넣는다. 발행하면 운영자가 이슈를 닫는다.
- **Chance**: 4장 결정에 따라 PR 또는 기존 방식.
- **초안 현황판**: 고정 이슈 1개(기존 `#22 확인 필요 모음`과 별개 또는 통합 여부는 제안)에 **채널별 대기 초안 수와 최신 초안 링크**를 표로 자동 갱신한다. 모바일 GitHub 앱에서 라벨 필터로도 볼 수 있어야 한다.

### 3-4. 신규 채널 등록 (`pipeline/blogs.json` 구조에 맞춰)
1. **Blogger 한글 `kcyoon`**: 주제는 A(일상 속 AI·디지털 도구 활용기, 주력) + B(집·살림 실사용 기록, 보조 30% 이내). `mode: off`로 등록하고 영문 Blogger와 **계정·Cloud 프로젝트·OAuth 클라이언트·Secrets를 분리**한다(예: `BLOGGER_KO_*`). 영문과 번역 복제 금지, 서로 링크 금지. 활성화는 사용자 승인과 게이트 통과 후.
2. **티스토리**: `mode: package`. 블로그 주소·주제는 사용자 결정 대기(5장). 티스토리 에디터 서식(HTML/마크다운)과 이미지 처리 방식은 **확인 과제**로 보고. 티스토리의 robots.txt가 AI 검색 크롤러를 막는지도 확인해 보고한다(우리 글의 AI 노출 가능성에 영향).
3. **네이버**: `mode: package`(이미 계획됨). 주소는 사용자가 알려줄 예정.
- 새 채널의 기본값은 `draft`/`package`/`off`처럼 **공개되지 않는 쪽**이어야 한다(defaults.mode가 draft인 현재 설정 유지).

### 3-5. 보안
- 채널별 시크릿 분리, 최소 권한. 레지스트리·로그·이슈 본문에 시크릿 값을 쓰지 않는다.
- 이슈 본문으로 만든 초안에도 **사용자·외부 입력을 신뢰하지 않는 원칙**(셸 보간 금지, 멘션 무력화)을 적용한다.
- 티스토리·네이버 계정 정보(아이디·비밀번호·쿠키·세션)는 저장·처리하지 않는다.

## 4. 사용자 결정이 필요한 항목 (Claude Code는 선택지와 추천을 제시하고 기다릴 것)
**AdSense와 자동 발행 (T3)** — 위 2장의 2번과 관련된 결정이다. 선택지를 비교해 추천을 제시한다.
- (a) Chance도 **초안 → 사람 승인 후 공개**(PR 병합 등)로 전환. 하루 승인 건수가 부담이면 발행 빈도를 승인 가능한 수준으로 낮춘다.
- (b) 현행 자동 발행을 유지하되, **자동 생성 글이 나가는 페이지에서는 광고 표시를 끈다**(광고 표면 변경이므로 T3).
- (c) 현행 유지(위험 감수). 계정 수준 조치 가능성을 문서에 명시.
- 어느 쪽이든 **신규 한글 Blogger·티스토리·네이버에는 품질 게이트를 통과하기 전까지 광고를 붙이지 않는다**는 원칙을 레지스트리에 반영하는 방안을 제안한다.

## 5. 사용자만 할 수 있는 일 (작업 내용 §4에 반영)
1. 티스토리 블로그 개설과 주소·주제 결정, 네이버 블로그 주소 전달.
2. 신규 한글 Blogger 전용 구글 계정에서 Cloud 프로젝트·OAuth 클라이언트 생성, 동의 화면 게시 상태 확인, 토큰 발급, Secrets 등록(값은 채팅·저장소에 쓰지 않음).
3. 신규 한글 Blogger의 Blogger ID(관리 화면 주소의 숫자) 전달.

## 6. 검증과 보고
1. **계획 보고(승인 대기)**: 현재 워크플로 재분류표·이름 변경안, 인박스·현황판 구조, 레지스트리 변경안, AdSense 선택지 비교.
2. 구현 후: 연습(dry-run) 실행으로 채널별 이름·요약·초안 이슈 생성을 확인(가짜 AI 응답 사용), 이슈 라벨·현황판 표 갱신 확인, 시험 추가.
3. Actions나 외부 화면에서만 확인되는 항목은 "푸시 후 관측 필요" 목록으로 남긴다.
4. 완료·결정 내용은 `작업 내용` §2·§3·§5에 갱신한다.

## 7. 제약
- 기존 Chance 자동 발행을 승인 없이 끄거나 바꾸지 않는다(4장 결정 전까지 현행 유지).
- 광고 표면(`_config.yml`·`index.html`·광고 관련)은 T3 승인 후에만 수정.
- 티스토리·네이버 로그인 자동화, 블로그·계정 자동 개설, 채널 간 상호 링크, 원고 변형 복제는 만들지 않는다.
