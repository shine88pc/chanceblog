## 항목 1 — AP15 · F029: 안내·결과 문장의 흐린 글 색(가장 작음, 먼저)
- 승인 범위: 흰 바탕의 흐린 안내·결과 문장(대비 약 3.2:1)을 **기존의 진한 보조색(약 5.4:1) 토큰**으로 바꾼다. **입력 칸 테두리에 새 진한 색을 더하지 않는다**(승인한 목업의 색을 바꾸지 않음) · 새 색 값을 만들지 않는다(기존 색 토큰만).
- 먼저 확인: 흐린 글 토큰(muted)과 진한 보조 토큰의 실제 값·대비(WCAG 상대 휘도 공식으로 직접 계산)가 백로그의 3.2:1·5.4:1 과 맞는지, muted 가 쓰이는 곳 중 '안내·결과 문장'이 정확히 어디인지(토큰 전체를 바꾸면 다른 곳이 바뀐다 — **문장 용도에만** 바꾼다). 화면 문서(`docs/UI_DESIGN_SPEC.md`·`UI_VISUAL_QA.md`·`docs/images/ui/*` 캡처)가 이 색을 값으로 못박았는지 확인하고, 영향이 있으면 갱신 범위·방법을 보고(캡처 이미지를 다시 만들어야 하면 **오프스크린 렌더 도구가 있는지** 확인하되 이미지 대량 재생성이 필요하면 하지 말고 보고).
- 시험: 대비 시험(바꾼 문장 색이 흰 바탕 대비 4.5:1 이상, 입력 칸 테두리 색은 그대로), 변이(문장 색을 다시 muted 로·테두리 색을 바꿈·토큰 값을 틀리게 — 시험이 빨개지는지).

## 항목 2 — AP13 · F024: 홈 추천 줄 서랍의 막다른 길
- 승인 범위: 홈에서 추천 줄을 눌러 열리는 서랍의 **모양은 그대로 두고**, 주 단추를 '주제 후보에서 열기'로 하고 눌렀을 때 **그 후보가 골라진 주제 후보 화면으로 가게** 한다. 지금은 단추가 모두 '다음 단계에서 열려요' 안내만 띄운다. 결정 D-201 의 '기존 서랍 유지'와 달라지는 점을 **새 결정으로 기록**한다.
- 먼저 확인: 서랍 코드와 '다음 단계에서 열려요' 안내가 정말 모든 단추에 걸려 있는지, **이동할 '주제 후보' 화면이 실제로 있고 Navigation 이 그 화면으로 후보를 골라 보내는 길이 있는지**(사이드바는 완성된 화면만 연결돼 있을 수 있다). 이동 대상 화면이나 후보 선택 전달 장치가 아직 없으면 **새 화면·큰 구조 변경을 만들지 말고 이 항목은 하지 않고 보고**한다.
- 시험: 서랍 단추를 누르면 후보 id 가 담긴 이동 요청이 나가는지(화면은 가짜 서비스로), 안내만 띄우던 옛 동작이 사라졌는지, 서랍 모양(위젯 구성)이 안 바뀌었는지, 후보가 없을 때(빈 상태) 단추가 안전한지. 변이 3개 이상.

## 항목 3 — AP14 · F034: 작은 로그 파일(가장 조심할 것)
- 승인 범위: 앱이 처리 못 한 오류가 나도 남는 기록이 없어 알리기 어렵다 → **데이터 폴더 안에 오류 이름과 코드 위치만 가려서 남기는 작은 로그**를 허용한다: **256 KB 짜리 3개 돌려쓰기**(예: `RotatingFileHandler(maxBytes=256*1024, backupCount=2)`), **첫 오류가 날 때 처음 만든다**(앱을 켜기만 해서는 파일을 만들지 않는다). 지금 문서는 앱이 파일에 쓰지 않는다·읽기 전용이라고 적혀 있어 **문서를 사실에 맞게 고친다**(어디에 어떻게 적혔는지 `grep` — SECURITY·ARCHITECTURE·README 등).
- 반드시 지킬 것: (a) 로그에는 **오류 클래스 이름과 코드 위치(파일 이름:줄)만** — 오류 메시지 글·값·경로·키·토큰·글 본문을 남기지 않는다(메시지 글 자체를 남기지 않는 것이 가장 안전하다) (b) 앱에 이미 있는 공통 가림(Redaction) 경로를 그대로 거친다(새 가림 규칙을 만들지 않는다) (c) **가림을 걸 수 없는 충돌 덤프(faulthandler·미니덤프)는 만들지 않는다** (d) **백업에 넣지 않는다**(기존 백업 제외 규칙에 로그 이름을 더하고 시험으로 못박는다) (e) 로그 쓰기가 실패해도(디스크 가득·권한) 앱 동작은 그대로(예외를 삼킨다) (f) 네트워크·외부 쓰기 0 — 외부 호출 금지 시험이 그대로 통과해야 한다 (g) 로그 위치는 기존 데이터 폴더 해석 함수를 쓴다(새 경로 계산 금지), 사용자 이름이 든 절대경로를 로그에 남기지 않는다.
- 먼저 확인: 앱에서 '처리 못 한 오류'가 지나는 곳(진입점·예외 훅·Qt 메시지 핸들러)과 기존 `logging` 사용, 창 없는 실행 파일(PyInstaller 창 없음) 모양에서 stderr 가 어디로 가는지, 백업 코드의 제외 목록. 백로그가 '일부 맞음'이라 했으니 어디가 틀렸는지 먼저 정리한다.
- 시험: 첫 오류 때 파일이 처음 생기고 시작만으로는 안 생김 · 256 KB 넘으면 돌려쓰고 파일이 3개를 넘지 않음 · **CANARY_ 가짜 비밀·가짜 경로·가짜 글이 든 오류 메시지가 로그에 한 글자도 안 남음** · 클래스 이름과 위치만 남음 · 백업에 안 들어감 · 쓰기 실패해도 앱 안 죽음 · 네트워크 0. 변이 5개 이상(메시지를 그대로 기록·가림 경로 우회·돌려쓰기 크기 제거·백업 제외 목록에서 이름 삭제·첫 오류 전에 파일 만들기).
