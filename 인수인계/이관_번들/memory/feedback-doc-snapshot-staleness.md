현황 문서(`인수인계/작업내용.md`·`WORKLOG.md`) 현행화 때 독립 사실 점검(읽기 전용 에이전트)이 **같은 부류의 오류를 세 번 연속 잡아냈다** (2026-11-13 M070 — 1차 필수 3·2차 필수 1·3차 권고 3).

**Why:** 이 문서는 새 AI 세션과 운영자가 읽는 단일 진실이고, 병합·알림이 계속 일어나는 동안 쓰기 때문에 쓰는 도중에도 상태 문장이 낡는다. 감시기(Monitor)가 알려 준 시각·내 추정 시각을 쓰면 틀린다(M069 병합을 21:40 이라 적었으나 PR merged_at 은 21:39:36).

**How to apply:**
- 병합 시각 = PR `merged_at`(또는 병합 커밋 시각) 분 단위 **버림**, 감시기 시각 금지. '부탁 뒤 N분' = 요청 파일 커밋 시각 → 병합 시각(M069 은 42초 → '1분 안').
- 상태 문장('병합 부탁 중'·'독립 검증 중'·'점검 중')은 쓰는 사이에도 낡는다 → **병합 가지를 만들기(커밋하기) 직전에 `git ls-remote`·`next_notice_no.py`·요청 가지 로그로 다시 대조**하고, 낡았으면 생성 스크립트(`scratch/make_worklog13_facts.py` 방식 — 원본으로 되돌린 뒤 한 번에 다시 적용)의 문장을 고쳐 재생성한다.
- 한 줄만 고치지 말고 **같은 부류의 줄**(§0-3 블로그 행·§2 표·§6 Chance 행·확인 번호 '지금 `015`' 같은 숫자 문구)을 `grep` 으로 모두 찾는다 — 점검자가 매번 새 곳을 찾아냈다.
- 번호는 도구 값을 믿되 `no:` 를 손으로 적어 순서를 바꿀 수 있다(요청함에 없는 표준 번호만, PR 제목이 `[M번호] ` 로 시작해야 함) — 이번에 S2c-1b 가 먼저 검사를 마쳐 M071 을 손으로 적고 문서는 M070 을 비워 뒀다.
- 점검 순서: 구현자(나) 스크립트 생성 → 문서 시험 15모듈 → **독립 사실 점검(읽기 전용, 작업 트리를 점검 도중 바꾸지 않기)** → 지적 반영 → 바뀐 줄만 재점검 → 커밋. 점검자는 같은 에이전트를 SendMessage 로 재호출하면 맥락이 남아 빠르다.
