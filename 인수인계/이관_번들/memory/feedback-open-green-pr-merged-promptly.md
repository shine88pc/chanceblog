운영자가 병합 부탁(R-nnn)을 보내기 전에 열려 있던 초록 PR `[M038]`(PR 166)을 2026-11-10 11:24:44 에 직접 병합했다(PR 은 09:35 에 봇이 만들었고 CI 는 10:27 에 초록, 독립 검증은 11:5x 에 통과). 이어 M039 는 요청 파일을 푸시한 지 44초 만에 병합됐다.

**Why:** 병합 가지(`ai/claude/M###-…`)를 푸시하면 봇이 PR 을 자동으로 만들고, 운영자는 PR 목록에서 `[M###]` 제목의 초록 PR 을 병합한다(알림 번호 체계·'병합만 하면 되게' 지시 — 기억 [[feedback-merge-ready-no-wait]]). 그래서 푸시한 순간 '병합 부탁을 보낸 것'과 같은 위험이 생긴다 — 독립 검증이 지적한 문제를 고치기 전에 병합될 수 있고, 병합 뒤에 고친 가지를 다시 올리면 충돌한다(M038 의 문서 보정이 그렇게 되어 M039 로 옮겼다).

**How to apply:** ① 병합 가지는 **독립 검증이 끝난 뒤에만** `ai/claude/M###-슬러그` 로 푸시한다. ② 미리 검사(CI)만 보고 싶으면 이름에 `NO-MERGE` 를 붙인다(봇이 PR 을 만들지 않음) — 검증 뒤 같은 내용을 M### 이름으로 다시 올리면 CI 가 한 번 더 돈다(약 5분). ③ 병합 부탁(R-nnn)은 CI 초록 + 독립 검증 통과 뒤에 보낸다(기존 규칙). ④ 운영자가 부탁 없이 병합한 번호는 요청 파일이 없으므로 다음 병합 요청의 `no:` 를 손으로 맞춘다(자동 번호가 건너뛴 번호를 다시 줌). ⑤ 병합 확인은 늘 하던 대로(한 커밋 앞·트리 일치·main 검사와 배포·글 수) — [[telegram-notification-standard-2026-11-06]].
