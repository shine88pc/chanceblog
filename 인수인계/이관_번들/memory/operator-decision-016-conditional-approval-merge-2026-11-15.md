**운영자 답(2026-11-15 ~08:0x, 채팅 — 이슈 #198 '직접 병합' 요청에 대한 확인 016 답, 선택 3 을 아래처럼 수정해 승인):**

1. **방식**: AI 가 독자 판단으로 자동 병합하는 것이 **아니다**. AI 가 변경을 쉬운 말로 설명 → 운영자가 **병합 번호를 명시해 `M075 승인`** 처럼 답 → AI 가 그 PR 을 병합. 병합 전 설명은 비개발자도 이해하게 **6항목**: ① 무엇을 바꾸는지 ② 왜 필요한지 ③ 사용할 때 무엇이 달라지는지(체감 변화 중심) ④ 기존 기능 영향과 위험 ⑤ 검사와 독립 검증 결과 ⑥ 문제 때 되돌리는 방법. 예시 형식(병합 요청 M075 / 무엇을 바꾸나요? / 왜 필요한가요? / 사용할 때 무엇이 달라지나요? / 위험은 무엇인가요? / 검사 결과 / 되돌리기)과 '승인 예: M075 승인' 한 줄.
2. **승인 문구**: 반드시 병합 번호와 함께. 아래만으로는 승인 아님 — '확인했습니다'·'진행하세요'·'좋아 보입니다'·'기본값대로'·'다음 단계 진행'. 승인은 그 PR **한 건**에만 유효(다른 PR·이후 변경 재사용 불가). 승인 이후 커밋 추가·변경 범위 변경이면 **승인 무효 → 새 설명·새 승인**. AI 는 승인한 병합 번호와 **현재 열린 PR 번호가 일치할 때만** 병합.
3. **병합 직전 재확인 8조건**: 승인된 병합 번호와 PR 일치 · 승인 이후 커밋 추가 없음 · 검사 전체 통과 · 독립 검증 통과 · 충돌 없음 · 변경 범위가 승인 설명과 일치 · 비밀 정보 노출 없음 · 되돌리는 방법 확인.
4. **AI 병합 가능 범위**: 일반 프로그램 코드·일반 UI·시험·문서·로컬 저장·조회·오류 수정·접근성·성능 개선. **운영자가 승인해도 AI 가 직접 병합하지 않고 운영자 직접 병합 유지**: GitHub Actions 워크플로 · 광고·AdSense·ads.txt · 공개 게시물과 고정 페이지 · PIPELINE_PAUSE · 발행 모드와 발행 재개 · Provider 활성화 · API 키·시크릿·자격 증명 · 의존성 추가 · 데이터 삭제·마이그레이션 · 자동 게시 활성화 · 외부 비용 발생 기능 · main 브랜치 보호 설정.
5. **병합 방식 제한**: **운영자 PC 의 Git 자격 증명으로 main 에 직접 push 하는 방식 금지.** 흐름은 반드시 AI 가 PR 작성 → 검사·독립 검증 → 쉬운 병합 설명 발송 → 운영자가 번호 명시 승인 → AI 가 승인된 PR 병합 → main 사후 검사 → 병합 완료 알림. 사후 검사에서 문제가 나오면 추가 변경을 자동 병합하지 말고 **되돌리기 요청과 쉬운 원인 설명을 먼저** 보낸다.
6. **병합 완료 알림 필수 항목**: 병합 번호·PR 번호·병합된 커밋·실제 반영된 변화·main 검사 결과·이상 유무·원복 커밋 또는 방법.
7. **순서**: 이 정책을 **먼저 문서화하고 시험**. 실제 AI 병합 기능을 켜는 변경은 **별도 병합 요청**으로 보내고 그 변경은 **운영자가 직접 병합**. 첫 운영은 일반 코드 또는 문서 PR **3건** 시험 — 3건 모두 ① 승인받은 PR 만 병합 ② 승인 후 변경 없음 ③ main 검사 전체 통과 ④ 원복 0건 ⑤ 다른 PR 오병합 0건 ⑥ 운영자 전용 경로 변경 0건 이면 승인형 AI 병합 계속 사용. **한 건이라도 문제가 나면 AI 병합 즉시 중지, 운영자 직접 병합으로 복귀.**

**Why:** 운영자는 자동 병합이 아니라 '쉬운 설명을 읽고 번호로 승인'하는 통제권을 원한다. 병합 안내를 잘못 읽어 M070 이 부탁 알림 전에 병합된 일(2026-11-14)도 배경.

(b) 작업 순서: HANDOFF1 문서에 결정 반영(작업내용 §0-2 19번·AGENTS 불변 규칙) → **MERGEPOL1**(정책 정본 `docs/AI_MERGE_POLICY.md`·순수 함수 `pipeline/merge_policy.py`·시험 — 꺼진 상태) → 별도 병합 요청으로 **켜는 변경**(Actions 워크플로 방식 권장: 운영자 PC 자격 증명 불사용, GITHUB_TOKEN 병합은 후속 워크플로를 못 깨우므로 workflow_dispatch 로 배포·사후 검사를 따로 호출, 병합 호출에 승인 시점 머리 SHA 지정으로 '승인 후 커밋 없음' 보장, 승인 전달은 텔레그램 답→이슈 또는 소유자 이슈 댓글) → 첫 운영 3건.
