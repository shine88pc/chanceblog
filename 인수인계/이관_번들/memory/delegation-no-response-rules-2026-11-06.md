운영자가 **"이번 답변 이후에는 추가 확인 요청에 답하지 못할 수 있다"** 며 상시 위임 규칙을 줬다(원문 `C:\work\ai\operator_delegation_rules.md`, 이 PC 에만).

**규칙 요약**
- 판단 우선순위: ① 최신 운영자 결정 ② 확정 전략 문서·C-Type UI 문서 ③ 기존 결정 기록 ④ 현재 정상 동작·회귀시험 ⑤ 데이터 보존·복구 가능성 ⑥ 보안·약관·라이선스 ⑦ 변경 최소화 ⑧ 되돌릴 수 있는 안전한 기본값. 충돌하면 가장 최근의 명시적 운영자 결정. 시점이 같거나 불명확하면: 삭제보다 보존·자동보다 수동·실제 호출보다 Mock/비활성·쓰기보다 읽기·교체보다 병렬 추가·자동 승인보다 승인 대기·외부 공개보다 로컬·하드코딩보다 사용자 설정·큰 변경보다 작은 독립 변경·추정값보다 `UNKNOWN`/`데이터 부족`/`확인 필요`.
- 확인 없이 진행: 이름 붙이기·동작 불변 리팩터링·시험 추가·문서 정정·접근성 개선·명백한 오류 수정·로그/오류 메시지 개선·기존 토큰 안의 간격 조정·읽기 전용 조회·Mock Provider·비활성 확장 지점·기존 흐름으로 돌아가는 Fallback·데이터에 영향 없는 성능 개선·확정된 C-Type 토큰 적용·1366×768·125% 대응·미완성 기능 메뉴에서 숨기기.
- 안전 기본값(UI·데이터·외부 API·AI 각각)은 원문 참조 — 핵심: 완성된 화면만 Navigation·0으로 추정 말고 '연결 전/집계 전/데이터 부족'·삭제 대신 보존·ID 재사용 금지·파괴 작업 전 미리보기·Migration 과 삭제 동시 금지·키는 Credential Manager 만(백업 제외)·여러 키로 한도 우회 금지·약관 미확인이면 호출·저장·캐시·AI 입력 비활성·AI 는 선택(없어도 규칙 기반 초안)·건강·의료·법률·재무 효과 단정 금지.
- **멈춤 예외 10가지**(해당 작업만 `BLOCKED` → 차단 이유 기록 → 안전한 Mock·Interface·시험까지만 → 다른 독립 작업 계속, 프로젝트 전체는 중단 금지): ① 기존 사용자 데이터 손실 가능성 ② 자격 증명·키 노출 가능성 ③ 외부 약관·라이선스 위반 가능성 ④ 결제·구매·유료 전환 ⑤ 외부에 실제 게시·배포·전송 ⑥ 기존 GitHub Pages·Blogger 운영 변경 ⑦ 네이버 자동 로그인·쿠키 저장·자동 발행 구현 ⑧ 원복 방법 없는 데이터 Migration ⑨ 기존 정상 기능 전면 교체 ⑩ 두 최신 운영자 결정이 직접 충돌해 안전하게 해석 불가.

**Why:** 운영자가 앞으로 확인 요청에 답할 수 없는 시간이 있다 — 새 결정 때마다 멈추면 풀오토가 서기 때문([[blog-project-principles]]·[[quiet-mode-defaults]] 의 연장).
**How to apply:** 새 확인 요청(`kind: decision`)은 위 10가지 예외에 해당할 때만 보낸다. 그 밖의 새 결정은 우선순위로 스스로 정하고 **결정 기록(D-번호)에 '위임 규칙 n 근거'와 함께 적고** 병합 요청의 '정해 둔 것'에 한 줄로 알린다(되돌리고 싶으면 한 줄로 알려 달라는 문구는 유지). 구현·검증 에이전트 지시서에는 '멈춰서 묻지 않기 + 이 우선순위' 를 넣는다. 병합 자체(AI 불가)·T3 변경의 운영자 병합·저장소 설정 켜기는 여전히 운영자 몫이다([[approval-scope-and-site-checks]] 는 유효). 이전 운영자 지시 중 '충돌하면 바로 바꾸지 말고 결정 항목으로'(P3b-1 계절 점수 — [[p3b1-round2-operator-decisions-2026-11-06]])는 그대로 지키되 답이 없어도 안전 기본값(승인된 점수 표 유지)으로 병합 가능하게 올린다.
