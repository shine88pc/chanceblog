## 만들 것(각각 시험과 함께, **다른 용도(Unsplash·Gemini·Blogger 등)의 동작은 바이트 단위로 그대로**)
1. **용도 정정**: 레지스트리의 `naver_openapi`('네이버 오픈 API(검색·데이터랩)', 하루 25,000회 '제3자 문서 기준', 키 돌려쓰기 허용)를 **`naver_apihub` — 'NAVER API HUB 검색어 트렌드'** 로 바꾼다. 칸은 `client_id`(비밀 아님)·`client_secret`(비밀) 그대로, 제공자 하나, **`rotation: never`**, **이 용도만 항목 최대 1개**(`Purpose` 에 `max_entries` 를 더하되 기본은 지금의 3 — 기존 용도는 안 바뀐다. 둘째 항목을 더하려 하면 쉬운 한국어로 거절), 한도 등급 한 개(`day` 100·`month` 27,000), 콘솔 한도 30,000·최대 50,000 같은 참고 값은 제공자 메모·새 칸(`console_limit`)에 둔다. `implemented` 는 **False 그대로**(호출 코드가 없다 — `keys test` 는 '준비 중'). `naver_searchad`(검색광고)는 **건드리지 않는다**. 옛 `naver_openapi` 이름으로 이미 저장된 항목이 있는 `connections.json` 이 **깨지지 않고** 읽혀야 한다(자동 삭제 금지 — 안전한 처리를 설계하고 시험으로 못박는다: 예) 옛 용도는 읽기 전용 '옛 항목'으로 보이되 새 용도로 옮기는 안내를 준다. 비밀은 지우지 않는다). 레지스트리를 바꾸는 시험(용도 목록·표)은 약화하지 말고 새 기대로 갱신한다.
2. **월 창**: `Window.kind == "month"`(한국 시간 달력 월, 초기화 = 다음 달 1일 00:00 KST, 라벨 `YYYY-MM`)를 `_used_of`·`_record`·`_next_reset`·`_frees_at`·`_valid_window`·상태 구조에 더한다. `quota_state.json` 구조 판이 올라가면 **옛 판을 안전하게 읽는 이전(migration)** 과 시험을 넣는다(옛 파일이 깨졌다고 보지 않는다). 일 창 100·월 창 27,000 이 **둘 다** 지켜진다(먼저 닿는 쪽이 막는다).
3. **시도/성공 분리와 장부**: 이 제공자(플래그 `ledger=True`)에 한해 창마다 `attempts`·`successes` 를 따로 세고(실패도 시도로 센다 — 429·타임아웃 포함), 최근 N건(예: 200) 호출 장부(`ledger`)에 **비밀·응답 본문·요청 본문 없이** 호출 종류·시작/완료 시각·조건 해시(정규화한 요청의 해시 앞부분 — 값에서 키를 유도하지 않는다)·성공/실패·HTTP 상태·재시도 횟수·응답 사용 여부·캐시 적중 여부를 적는다. `usage()` 가 설정 화면용 값(오늘·이번 달 시도/성공, 내부 일/월 한도, 콘솔 월 한도, 마지막 성공·마지막 오류·호출 중지 사유)을 돌려준다. 다른 제공자의 상태 파일 모양은 그대로(장부 칸은 이 제공자에만).
4. **Fail-Closed**(플래그 `fail_closed=True` 인 제공자에 한해, 다른 제공자는 지금 동작 유지): ① 상태 파일이 깨졌거나 읽을 수 없으면 '절반 썼다고 보고 계속'(`_assume_half`)이 아니라 **`Denied`(사용량 확인 불가)** — 안내 문구 포함 ② 월 계수가 한도·과거 값과 모순(음수·한도 초과·장부와 불일치)이면 차단 ③ **시계 되돌림 감지**: 마지막으로 본 시각(`last_seen`)을 상태에 두고 `now < last_seen − 허용 오차(예 5분)` 면 차단('시계 이상') — 고치는 길은 시계가 돌아오거나 운영자가 명시 명령으로 확인하는 것뿐(자동 해제 금지) ④ 연결 설정 파일이 깨졌으면(이미 `CONNECTIONS_FILE_INVALID`) 호출 안 함 ⑤ 인증 상태가 불명확(시험 성공 기록 없음·`needs_check`·`auth_failed`)이면 신규 호출 차단 — 단 `implemented=False` 인 동안은 어차피 호출이 없으니 **틀(함수·시험)만** 만든다. 잠금을 못 잡거나 쓰기가 실패하면 이미 호출을 허용하지 않는다(그대로 시험).
5. **한도 단계**: 단계 비율은 **콘솔 월 한도(30,000) 기준**: 70%(21,000) 사용량 안내(`notice`) · 80%(24,000) `bulk_refresh`(자동 새로고침·배치) 거절·`new_candidate`(수동 분석)는 제한적 허용 · 90%(27,000 = 내부 월 한도) 모든 신규 호출 거절(`critical` 포함 — 이 제공자는 '마지막 10% 예약'을 쓰지 않는다). 기존 `FLOOR_PERCENT`·`RESERVE_PERCENT` 의 다른 제공자 동작은 그대로 두고 **제공자별 단계표**로 풀어 쓴다. 안내·거절 문구는 쉬운 한국어, 영문 코드를 화면에 보이지 않는다.
6. **명령줄·표시**: `keys usage naver_apihub`·`keys policy naver_apihub` 가 위 값(오늘·이번 달·내부/콘솔 한도·마지막 성공·마지막 오류·중지 사유)을 보이고, 호출 중지 때 고정 문구('NAVER API HUB의 새로운 데이터 조회를 사용할 수 없습니다…')를 쓴다. 상태 5종 문구(`STATUS_TEXT`)는 그대로 쓴다.
7. **키 모양**: `security/shape.py` 는 NCP Client ID/Secret 의 실제 모양을 모른다(공식 문서에도 없음) → **느슨한 검사**(영숫자·`-`·`_`, 8~128자)로 시작하고 값을 입력·로그·오류에 넣지 않는 규칙은 그대로. 시험은 **가짜 값**만 쓴다.
8. **문서**: `docs/SECURITY.md` §7·`docs/ARCHITECTURE.md`(용도 표·월 창·장부·Fail-Closed·알려 둔 한계)·`docs/DECISIONS.md` 새 결정(번호는 끝 번호 확인 — 내용: NAVER API HUB 검색어 트렌드 안전 틀, 키 1개·돌려쓰기 금지, 월 창, 시도/성공 분리, Fail-Closed 범위, 단계 기준, 모르는 것(실패 호출 반영·월 초기화 시각·약관)과 그에 따른 보수적 선택)·`CHANGELOG.md`·`README.md` 의 해당 줄. 숫자(시험 개수 등)는 정확히.
