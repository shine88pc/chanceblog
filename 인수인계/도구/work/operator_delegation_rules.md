# 운영자 지시 원문 — 향후 의사결정 위임 및 무응답 진행 규칙 (2026-11-06 22:05 무렵, 채팅) — 옛 PC 의 W 에 있던 원문 사본을 2026-11-23 저장소로 옮겼다(요지는 작업내용 §0-2 11번)

이번 답변 이후에는 운영자가 추가 확인 요청에 답하지 못할 수 있습니다.

따라서 새로운 결정사항이 발생하면 작업을 멈추거나 반복 확인을 요청하지 말고, 아래 기준에 따라 스스로 판단하여 계속 진행해 주세요.

## 1. 기본 원칙

다음 우선순위로 판단합니다.

1. 이미 확정된 최신 운영자 결정
2. 확정 전략 문서와 C-Type UI 문서
3. 기존 결정 기록
4. 현재 정상 동작과 회귀시험
5. 데이터 보존과 복구 가능성
6. 보안·약관·라이선스 준수
7. 변경 최소화
8. 되돌릴 수 있는 안전한 기본값

문서나 결정이 충돌하면 가장 최근의 명시적 운영자 결정을 우선합니다.

결정 시점이 같거나 우선순위가 불명확하면 다음 순서로 선택합니다.

- 데이터 삭제보다 보존
- 자동 실행보다 수동 실행
- 실제 호출보다 Mock 또는 비활성
- 쓰기보다 읽기 전용
- 기존 기능 교체보다 병렬 추가
- 자동 승인보다 사용자 승인 대기 상태
- 외부 공개보다 로컬 저장
- 하드코딩보다 사용자 설정
- 큰 변경보다 작은 독립 변경
- 추정값보다 `UNKNOWN`, `데이터 부족`, `확인 필요`

## 2. 추가 확인 없이 계속 진행 가능한 사항

아래 항목은 별도 확인 없이 권장 기본값으로 진행해 주세요.

- 내부 변수명, 함수명, 파일명
- 기존 규칙을 변경하지 않는 Refactoring
- 시험 추가
- 문서 정정
- 접근성 개선
- 명백한 오류 수정
- Log와 오류 메시지 개선
- 기존 Token을 사용하는 UI 간격·정렬 조정
- 읽기 전용 데이터 조회
- Mock Provider 구현
- 비활성 상태의 확장 지점 마련
- 실패 시 기존 흐름으로 돌아가는 Fallback
- 사용자 데이터에 영향을 주지 않는 성능 개선
- 현재 확정된 C-Type 디자인 Token 적용
- 1366×768과 Windows 125% 대응
- 미완성 기능을 메뉴에서 숨기는 처리

## 3. 안전한 기본값으로 진행할 사항

### UI

- 완성된 화면만 실제 Navigation으로 활성화
- 미완성 화면으로 이동하는 경로는 만들지 않음
- 화면당 Primary Action은 1개
- 데이터가 없으면 0으로 추정하지 않고 `연결 전`, `집계 전`, `데이터 부족` 표시
- 실제 기능이 없는 검색·알림·사용자·날씨 Widget은 만들지 않음
- 점수 링에는 숫자를 중심으로 표시하고 구간 이름은 별도 Label 사용
- 색상만으로 상태를 표현하지 않음
- 글자 대비는 WCAG AA 4.5:1 이상을 우선
- Windows 시스템 기본 글꼴 사용
- 실제 사용 권한이 확인되지 않은 사진·Logo는 사용하지 않음

### 데이터

- 삭제 대신 보존
- ID 재사용 금지
- 파괴 작업 전 미리보기
- Migration과 삭제를 한 실행에서 동시에 하지 않음
- Backup 실패 시 원본 유지
- Credential과 API Key는 Backup 제외
- 데이터 구조 변경 전 자동 사본 생성
- 일부 항목 실패가 전체 목록을 막지 않게 함
- 후보·초안·발행 이력의 연결 ID 유지

### 외부 API

- 이용약관이 확인되지 않으면 실제 호출·저장·캐시·AI 입력 비활성
- Mock Provider로 먼저 검증
- API Key는 Windows Credential Manager에만 저장
- 저장한 Key 원문은 다시 표시하지 않음
- 여러 Key로 무료 호출 한도를 우회하지 않음
- 호출량 확인 불가 시 신규 호출 중지
- API 실패 시 Seed·캘린더·기존 이력으로 계속
- 공식 데이터와 내부 파생 Signal을 별도 필드로 저장

### AI

- AI는 선택 기능
- AI가 없어도 규칙 기반 초안 생성
- 실제 사용·방문·구매·가격·협찬 관계를 임의 생성하지 않음
- 건강·의료·법률·재무 효과를 단정하지 않음
- 공공데이터 원문은 허용 확인 전 AI에 전달하지 않음
- 내부 Signal과 최소 사실만 사용

## 4. 작업을 멈춰야 하는 예외

아래 상황에서만 해당 작업을 중지하고, 다른 독립 작업을 계속 진행해 주세요.

1. 기존 사용자 데이터가 손실될 가능성
2. Credential·API Key가 노출될 가능성
3. 외부 서비스의 약관·라이선스 위반 가능성
4. 결제·구매·유료 전환이 필요한 경우
5. 외부에 실제 게시·배포·전송하는 작업
6. 기존 GitHub Pages·Blogger 운영을 변경하는 작업
7. 네이버 자동 로그인·쿠키 저장·자동 발행 구현
8. 데이터 Migration의 원복 방법이 없는 경우
9. 기존 정상 기능을 전면 교체해야 하는 경우
10. 두 최신 운영자 결정이 직접 충돌해 안전하게 해석할 수 없는 경우

이 경우에도 전체 프로젝트를 중단하지 마세요.

```text
해당 작업만 BLOCKED
→ 차단 이유 기록
→ 안전한 Mock·Interface·시험까지만 진행
→ 다른 독립 작업 계속
```
