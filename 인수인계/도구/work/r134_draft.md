## 무엇이 바뀌나 (쉬운 설명)
운영자님이 NAVER API HUB 에서 만들어 두신 '검색어 트렌드' 연결을 프로그램이 나중에 안전하게 쓰기 위한 **안전 장치만** 먼저 만든 것입니다(R-122 의 1단계, 결정 A=1). **인터넷으로 NAVER 를 부르는 코드는 이 묶음에 없습니다** — 키를 넣는 자리와 사용량을 세어 막는 규칙만 들어갑니다. 눈에 보이는 화면 변화도 없습니다(명령줄 `keys` 표시만 늘어납니다).

| 항목 | 내용 |
|---|---|

## 솔직한 한계 (병합을 막지 않음)
- **호출 코드가 없습니다.** 인증이 불명확하면 막는 검사는 호출이 생기기 전까지 아무도 부르지 않는 틀입니다. 실제 조회·후보 보정은 다음 단계(R-122 의 2단계, 약관 확인과 키 등록 안내 뒤)입니다.
- 멈춤을 푸는 '확인' 함수는 아직 명령줄에 이어 두지 않았습니다. 프로그램 안 한도(100·27,000)와 직접 분석 5회 상한을 설정으로 낮추는 길도 아직 없습니다.
- 사용량 파일을 **통째로 지우면** 사용량 0 으로 다시 시작합니다(깨진 파일과 달리 알아내지 못함). 월·일 숫자가 서로 맞지 않아 멈춘 것은 그 달·그 날 초기화 때 풀립니다.
- 새 사용량 파일 모양(판 2)은 옛 프로그램이 읽으면 깨진 파일로 봅니다(되돌릴 때만 해당).
- 윈도에서 설정·사용량 파일을 바꿔 넣을 때 가끔 막혀 시험이 드물게 한 번 실패한 적이 있습니다(재시도가 없는 기존 저장 방식의 성질, 후속).
- 실패한 호출의 사용량 반영·월 초기화 시각·약관은 NAVER 공개 문서에 없어 **실패도 시도로 세고 월은 한국 달력 월로** 안전하게 잡았습니다(문서 SECURITY §7 '모르는 것').
